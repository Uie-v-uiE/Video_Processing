## 一、被砍的那一族：`clkout0_1`（20 ns 周期，50 MHz 像素时钟）
改前（r108）：最差 8 条**同族** = `u_pl/u_split_ctrl/prod/CLK`（乘法的 DSP PREG）→ `u_pl/u_osd/{r,g,b}_reg[*]/D`
  1.130 ns slack / **23 级**（CARRY4=2 LUT6=12 MUXF7=1）/ logic 4.147 ns(22.5 %) **route 14.298 ns(77.5 %)**
  ⇒ 相对余量 1.130/20 = **5.65 %**，是全设计**相对最紧**的一格（绝对最紧是 eth_rxc 0.721/9.0 %）。
改后（r109）：最差 = `u_pl/x_d_reg[20][7]/C` → `u_pl/u_osd/ch_r_reg/ADDRARDADDR[7]`
  **4.094 ns** slack / **21 级**（CARRY4=8 LUT6=5）/ logic 5.740 ns(37.2 %) route 9.700 ns(**62.8 %**)
  同族还有 4.128 / 4.318 / 4.476 ns（`ch_r_reg` 的其它地址位），全部 > 4 ns。
⇒ **原来那条"值→拆位→160 格装配→选中格→字模→颜色"的 23 级单链不见了**：`prod → u_osd/{r,g,b}_reg`
   这一条端点对已经不在该时钟的最差名单里；新的最差是"选中格"这一拍的**前半段**（装配 → `ch_r` 寄存器），
   它的 slack 是 4.094 ns —— 也就是这一刀把该时钟的相对余量从 **5.65 % 推到 20.5 %**（4.094/20），
   代价只有 **+2 LUT / −6 FF**（`ch_r` 落在分布式 RAM 里，没有另占 8 个触发器），BRAM +0.5 格（95 → 95.5）。

## 二、全局与逐时钟（同一份 build/timing_summary.rpt，Design Timing Summary + Intra Clock Table）
WNS/TNS/失败端点：**0.605 / 0.000 / 0**（51029 个端点全判），WHS 0.049、hold 失败 0。
`clk_fpga_0` setup 1.238 ns（占 10 ns 的 12.4 %）、`clkout0_1` 4.094（20.5 %）、`sys_clk` 见同表。
`eth_rxc`（8 ns）仍是**绝对**最差的那一格，而它现在拿到的标本换人了：
  最差 = `u_eth/u_reasm/off_reg[11]_rep/C → u_eth/u_reasm/rows_hit_reg[2..4]/CE`，0.605 ns
  ⇒ 全局瓶颈回到 **r107 那一族**（`rows_hit` 位图的使能广播），不是 OSD 也不是校验和锥。
  这一条是 #105/#121 早就量过的"route 主导 + 高扇出使能"形状 ⇒ 下一刀的形状也照 r107 那把抄：
  分组/降扇出，而不是改算术（#179 的 icmp_rx 累加锥是同类否决过的候选）。

## 三、为什么这里**不能**写"时序提升了 0.4 秒/若干 ns"
全局 WNS 从 0.721 → 0.605 是**持有者换了**（u_reasm 那一族本来就在 0.6x 附近排队），
按规矩 35 绝对差值既不算收益也不算损失；本文件的收益口径只有一句：
**同一条 `clkout0_1` 最差路径的 slack 与级数在它自己的两端夹逼下动了**（1.130/23 → 4.094/21，
route 占比 77.5 % → 62.8 %），而这条改善来自一个 8 位的寄存器插入。
