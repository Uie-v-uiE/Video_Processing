# 先确认再动手：什么该问、怎么问

## 适用场景

- 即将刷写或擦写板上非易失存储、覆盖既有交付件、删除文件、改演示脚本的顺序或口径。
- 你正打算替用户做一个"讲不出对错但一眼看得出不同"的决定：配色、字体字号、动画节奏、界面文案。
- 涉及许可证、引用他人材料、对外发布或署名。
- 反面征兆：整轮时间被"这个也要确认"吃掉，连能读出来的事实都在等人回答。

## 使用方法

### 三类必问（其余尽量不问）

1. **不可逆或代价高的**：刷写/擦写板载非易失存储、覆盖既有位流或交付件、删除文件、
   改变演示顺序或口径、更换时钟源与板载外设归属。判据：错了要花时间，且可能伤硬件或丢别人的东西。
2. **影响主观观感的**：画面观感、颜色、字体、时序表演、上位机界面文案。你没有判据，用户有。
3. **有权属或合规含义的**：参考设计与例程的许可证边界、引用他人材料的范围、对外发布与公开渠道。

### 先查什么（问之前把可只读消解的疑问消解掉）

跑只读命令或读一手文档就能确定的事不要问：位宽、例化关系、资源用量、管脚表、某条路径的延迟、
当前构建产物是否存在。检索规范与出处记录用 research-before-code；上板动作的前置与禁区用
before-touching-hardware。

### 问法（低自由度，逐字可套）

- 一次不超过 3 个，每个只问一个事实，能被"是/否/选甲或乙"回答；不许一句里塞两个未知量。
- 每条自带推荐默认值和生效说明："若不回答，就按某方案走，因为某理由。"
- 把"我打算这样做"压成一行动词句 + 一个后果，让人能一句话否决。

```
打算（不超过三条）：
1. 向板载非易失存储写入镜像（会擦掉现有内容）｜建议：先只做易失加载，除非要求断电自启｜不回答则：只易失加载。
2. 演示顺序改为先结论后细节｜建议：保持现有顺序｜不回答则：不改。
3. 保留第三方参考目录（许可证未明确）｜建议：不落盘，仅纸面参考｜不回答则：移出仓库并记一行已移出。
否决方式：回一句"2 否"即可，其余按默认执行。
```

### 问了但用户不在时怎么安全继续

- 只做只读准备工作：读文档、读报告、跑不改源码也不碰板台的检查、把台架和判据搭好。
- 把需要签字的动作显式挂起：写成一件"挂起清单"（项 + 影响 + 默认值 + 否决入口），挂在交付可见处。
- 本轮不进的动作：改板载存储、删他人文件、走对外渠道、改外观口径。
- 挂起不是停工：把两条分支都搭到只差一步，回答后一次跑完；等待期间别让在飞的构建和改口撞车
  （见 pitfalls/build-artifact-races）。

### 能自己定的别问

- 可由代码或报告读出的事实——跑一条只读命令就有答案。
- 纯机械的改名、格式化、补注释、内部信号命名。
- 判据自问两句：问一句的成本是多少，自己查一句的成本是多少；后者更低就闭嘴去查。

## 失效条件

- **把用户的一句随口话当永久授权**："你看着办"只覆盖当时那件事那个范围，不覆盖后续同类动作，
  更不覆盖擦写类动作。征兆：拿早期的一句同意去解释一个本轮新增的高风险动作。要复确认的三个信号：
  动作对象变了、代价等级变了、距上次表态已经隔了一轮。
- **用确认代替测量**：用户说"应该没问题"不是报告读数。观感类可以问，时序、资源、正确性类不可以问。
- **一次问太多、或一句里含两个未知量**：用户只答其中一条，你靠猜测处理其余，事故从这里开始。
- **默认值没写生效范围**：用户以为自己在否决甲，实际连带否决了乙。
- **反向失效**：把可只读消解的疑问拿去问人。征兆是"等待回答"成为一轮里最大的耗时项。
- 无人可问且硬截止临近：不可逆与权属类只能挂起；必须在两条可行动作里选时，选可逆的那条，
  并在交付文档里写明这是临时假设及其后果。

## 已验证效果

未量过，属建议。依据的观察类别：自作主张改外观、口径与演示顺序被打回，返工成本至少一次完整构建；
以及一味确认把能自己定的事拖掉整整一轮。想变硬：在轮次记录里给每个决策标"问过/没问 + 事后是否被打回"，
比较两类错误率——未问而被打回的数除以未问动作数、等待回答耗时除以轮次总耗时；两边都不该接近 0。
