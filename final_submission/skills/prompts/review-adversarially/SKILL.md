# 对抗式审计（提示词模板）

## 适用场景

- 自己写的结论、文档或代码要出货前过一遍第二双眼睛。
- 前一次委托回来是一团好评与几条风格建议——即"为改而改"的征兆。
- 一批产出里数字很多（计数、占比、次数），需要有人独立复跑而不是转抄。

## 使用方法

先查什么：被审产出的当前位置与版本标识（哪个提交、哪份产物），以及审计者可读的只读命令清单——
先把"允许查什么"说清楚，否则它会猜位置。先跟用户确认什么：审计者能否读整个目录、
是否允许它跑只读命令、以及"审计结论是否会导致已交付内容改口"（改口要走确认，不由审计者直接动手）。

模板（整块粘贴，一批一次）：

```
角色：你是审计者，不是作者。本次只输出判定表，不修改任何文件。
零修改是合格的交付结果：若全部成立，直接写"无需修改"，不要为改而改提风格建议。

【规则】
R1 逐条给结论，只用三个词：成立 / 不成立 / 未核实。禁止出现"看起来合理、整体没问题、应该、基本符合"。
R2 每条结论点名依据位置：文件名 + 行号，或表号/章节号。允许你只读查询（读文件、跑只读命令），
   禁止猜位置；拿不到位置就写"未核实"，并补一句"还差什么才能核到"。
R3 凡出现数字（计数、占比、阈值、次数），写出复跑方式（一条命令，或"数哪份产物的哪一项"）；
   并复核我自己的计数：不符时如实写"作者值=<X>，复跑值=<Y>"，禁止把任一侧改成与对方一致。
R4 禁止改动：不编辑文件、不写产物、不跑有副作用的命令（清理、生成、格式化、刷写均在内）。
   如果你认为必须改，只写"建议动作"，由我来做。
R5 每条"不成立/未核实"配一条最小反驳：<看到什么读数或哪一行能推翻你的结论>。
R6 射程：只审下面清单内的文件与结论，清单外一律不看也不评，也不要因为看到旁证就扩大范围。

【本批次】
不变量（本批唯一判据）：【填入：一句话，例如"同一信号在跨域处只有一个同步器实例"】
文件清单（4–5 个）：【填入：本批文件名列表，只放支持该不变量的文件】
作者已下的结论：【填入：逐条粘贴，一条一行，含其中的数字】

【输出格式】
| 结论(成立/不成立/未核实) | 依据位置(文件+行/表) | 数字复跑方式 | 最小反驳 |
最后附：本批判定条数、其中未核实条数、以及对上面"作者计数"的复核结果一行。
```

### 使用说明

喂什么：一批文件清单（4–5 个）+ 一个不变量 + 你的结论原文。
期望回什么：一张判定表，每行有位置；未核实是允许且常见的结果；末尾有计数复核。
怎么验收这次回答：（a）表里出现无件词（R1 禁止项）⇒ 退回只补位置，别让它重写整表；
（b）随机抽 2 行按它给的位置去看，内容对不上 ⇒ 整批判未核实（位置编出来的审计没有价值）；
（c）它给的复跑方式自己跑一遍，跑不出同一数字 ⇒ 该行降级。

派工纪律：**分批，每批 4–5 个文件、一批一个不变量**。一次丢几十个文件会得到部分完成，
既不完整又破坏一致性（前后批用了不同标准）。跨批共用的文件放进它所属的那一批，不要一次全给。
**派了活不等于干了活**：用版本库状态核对——先看工作区是否干净，再比对审计前后
`git status --porcelain` 与 `git diff --stat` 的输出：审计者应造成 0 个文件改动；
而你自己声称"已按审计改掉"的文件必须出现在 diff 里，只有对话里的"我改好了"不算数。

## 失效条件

- **审计者与你共享同一份上下文**（同一会话的续问、同一份摘要）：它只能证明"没互相抄"，
  不能证明正确；结论会复现你的盲区。要独立会话、只给产出与清单。
- **批量改口后行号漂移**：位置全部指向已移动的行，看起来条条有件其实全错。改完重新跑一轮，
  不要手工挪行号。
- **不变量横跨多批**：每批各自"成立"而整体不成立。征兆是批与批之间存在引用关系——合并成一批，
  或改成一次只审接口。
- 审计者给的行号精确但内容与结论无关（常见于它只读了文件头）：靠抽 2 行复核拦住，别靠它自陈。
- 把审计者当作者用（"顺手改一下吧"）：会引入未审的改动，且破坏"零改动可核对"这一条判据。

## 已验证效果

未量过，属建议。可复跑的三个计数：判定行数与带依据位置的行数（比应为 1）、
抽查 2 行的命中率（<1 即整批作废）、审计前后 `git diff --stat` 的文件数（应为 0）。
