# 证据台账：把"这一轮的结论挂在哪个件上"变成可核对的文本件

## 适用场景

症状级触发，任一条都算：

- **量了没落件**：读数只在终端里活过这一轮，下一轮开头第一件事是重跑或"上次那个数是多少"。
- **下一轮找不到件**：结论说的是某份报告，但没人说得出它的路径、当轮字节数与摘要。
- **交付被指"点名的东西不在包里"**：复核人按文档去找件，盘上没有——这就是死引用。
- **件被事后改过**：同一件在两处给出不同数字，说不清是谁在哪一步动的。
- **台账只有一句"已通过"**：判定、命令、件三者对不上，声明与证据之间没有可逐行核对的东西。

不适用：不产生读数的轮次（纯查资料，记出处即可）；件大到不该随包（先按下面口径跟用户确认）。

## 使用方法

台账是 `<root>/evidence/ledger.tsv`：制表符分隔、带表头的**文本件**，11 列 =
`ts round claim cmd artifact bytes cbytes digest tool verdict note`。`add` 追加一行并**现算盖章**：
UTC 时间、盘上字节数 `bytes`、内容口径字节数 `cbytes`、内容摘要 `digest`（形如 `mode:16 位十六进制`，
行尾与 BOM 不参与；二进制件自动退回按字节口径并把 mode 标在前缀里）、件里声明的工具版本 `tool`
（读不到就写 `NOT_MEASURED`，不许编一个版本）。判定语言与本包尺子一致（见 `three-state-verdicts`）：
三态、结论行最后一个字段才是判定词、`判 N 项` 的 N 是**做了多少次比较**、空集/读不到/解析失败判
`NOT_MEASURED`、有 FAIL 走退出码 1、只有未测走 2。

一轮的节拍：立案 → 跑出件 → `add` → `check` → `render`（命令在本条目目录下跑）：

```bash
# 1) 立案：一句话结论 + 产生它的命令 + 件路径（相对 root）
# 2) 先把读数落盘成文本件（这里假设上一步已写出 reports/metrics.txt）
node scripts/ledger.mjs add --root . --round w07 \
  --claim "最差余量 0.310，在阈值内" \
  --cmd "node demo.mjs --report reports/metrics.txt" \
  --artifact reports/metrics.txt --verdict PASS
# 3) 收尾核对；--require-round 判"这一轮到底有没有立案"，缺行判未测而不是通过
node scripts/ledger.mjs check --root . --require-round w07
# 4) 渲染成能进交付的表
node scripts/ledger.mjs render --root . --out evidence/ledger.md
```

跑完应看到（这些都是上面那三条命令的实跑读数）：

- `add`：8 行判定 + `判 8 项：扫描行数 rows=1 比较次数 cmp=8 写入行数 added=1 … PASS`，退出码 0。
- `check`：每行 7 条判定（字段完整性 F / 路径相对 P / 件在盘上 D / 件非空 N / 内容一致 I / 判定词 V /
  盖章可读 T），再加同轮多行 U、判定分布 A、（给了才有的）轮次覆盖 R。一轮一行时末行是
  `判 11 项：扫描行数 rows=1 比较次数 cmp=11 死引用 dead_ref=0 摘要不符 digest_mismatch=0 缺判定 missing_verdict=0 同轮多行 dup_rounds=0 require_round=w07 PASS`；
  夹具那种两轮各一行的台账末行是 `判 17 项：… rows=2 … require_round=none PASS`。
- `render`：`判 4 项：比较次数 cmp=4 渲染行数 rendered=1 台账行数 ledger_rows=1 等式 equality=ok … PASS`；
  表列为 轮次 / 结论 / 命令 / 件 / 判定 / 摘要。等式两端对不上就是渲染件在骗人（有行没进表）。
- 自测：`node scripts/ledger.mjs --self` 末行 `判 37 项：红=0 未测=0 夹具 pkg=7 件 沙箱=已清理 PASS`。

**先查什么**（一手资料优先：工具与流程的实际输出格式 ＞ 应用笔记 ＞ 教程 ＞ 模型记忆）：
① 件是不是**文本**——二进制件按字节口径哈希，"行尾不参与"对它不成立；
② 件路径必须**相对 `--root`**，绝对路径与越出 root 的写法一律拒收；
③ **摘要口径要与交付包一致**：这里按内容算（统一行尾、去 BOM），若复核方按整文件原始字节哈希，
两边的数对不上，先对齐口径再立案，否则合法的行尾差异会被读成"件被改写过"；
④ 件里到底有没有版本声明字段（`tool_version` 一类），别把记忆里的版本号写进台账。

**先跟用户确认什么**（工具替你决定不了，属高自由度判断）：
① 哪些件属于隐私或受保密限制**不能随包**——这种件不该被 `--artifact` 点名（点名却不在包里就是死引用），
要么换成脱敏样例件、要么以"清单形式缺席"写进 `note`，替代口径由用户认可；
② 台账与渲染件允许落在哪：默认进 `<root>/evidence/`，要放到被核对树之外用 `--ledger`；
③ 同轮重跑留下的多行里哪一行代表该轮当前判定（工具按 `ts` 最新取，但仍把该轮判成未测，要人确认）；
④ 是否允许 `--force` 落"未盖章"的行（件当时不可读时的权宜，摘要只记 `NOT_MEASURED`，绝不填假数）。

## 失效条件

- **自指**：台账或渲染件被写进被核对的树，下一轮又把它当证据件引用。征兆：`check` 的 rows 每轮都在涨
  却没人立案，或"摘要不符"的红来自上一轮自己写出的件。修法：一轮一行；渲染件只进交付说明，不进 `--artifact`。
- **同轮重跑留多行**：取最新的规则是该轮 `ts` 最大的那一行代表当前判定（`check` 的 U 行会打印"取最新=第 k 行"），
  旧行仍逐条核对但不再当结论；因为"哪行算数"没被人确认，`check` 把这种轮判 `NOT_MEASURED`（不许当通过）。
  要么删旧行，要么换轮次标识。
- **跨机器不可移植**：台账里出现绝对路径或 `..`，换台机器整片死引用；`check` 只点名路径问题，救不回件本身。
- **把 `--self` 绿当真实可用**：自测只证明提取层与比较在干活；夹具是合成的，真件的形状（列名、编码、
  版本字段位置）与夹具不同就会假绿。收紧判据后必须重跑一次真件（做法见 `checker-selftest`）。
- **工具只判台账自洽，不判结论对不对**：`verdict=PASS` 的行完全可能量错了对象；`missing_verdict=0`
  只说明判定列合法，不等于每条结论都有据。`check` 绿 ≠ 设计对。
- **件被合法更新**（重跑同名覆盖）⇒ 摘要不符而红：这是有意的，重新 `add` 一行新盖章，别去改旧行。
- **台账 0 行**时 `check`/`render` 判 `NOT_MEASURED`：这一轮是"没东西可核"，不是"核过没问题"。

## 已验证效果

实跑过的 `--self` 输出行（同一命令可复跑）：

```text
$ node scripts/ledger.mjs --self
S 变异 死引用 ⇒ 红=1 且红在 D 期望={"token":"FAIL","dead":1,"cmp":17,"redLines":1,"redAt":"E1-D"} 实得={"token":"FAIL","dead":1,"cmp":17,"redLines":1,"redAt":"E1-D"} PASS
S 变异 追加一个字节 ⇒ 红=1 且红在 I 期望={"token":"FAIL","dig":1,"cmp":17,"redLines":1,"redAt":"E1-I"} 实得={"token":"FAIL","dig":1,"cmp":17,"redLines":1,"redAt":"E1-I"} PASS
S 二进制件被追加字节 ⇒ 只红一条且红在 I 期望={"token":"FAIL","redLines":1,"redAt":"E1-I","dig":1} 实得={"token":"FAIL","redLines":1,"redAt":"E1-I","dig":1} PASS
判 37 项：红=0 未测=0 夹具 pkg=7 件 沙箱=已清理 PASS
```

夹具是 8 份合成输入：4 份台账形状（完整 / `verdict` 留空 / 行被截断 / 空文件）与 4 份读数件
（完整 / 缺版本字段 / 0 字节 / 二进制）。37 项比较里四类必断言各自**只红一条且红点正确**：完整读数 ⇒ `PASS`
（rows=2 cmp=17）；缺字段 ⇒ 红在 `E2-V` 并点名 `verdict`（截断行 ⇒ 红在 `E2-F` 并点名缺的列名）；
死引用（件路径改成不存在的）⇒ 红在 `E1-D`；追加一个字节 ⇒ 红在 `E1-I` 并报出 `digest_mismatch=1`。
另外四条口径同样量到读数：只改行尾（整件换 CRLF）⇒ 一条都不红；二进制件 ⇒ 摘要前缀换成 `raw`
且版本字段记 `NOT_MEASURED` 而不是编一个；同轮两行 ⇒ `dup_rounds=1 NOT_MEASURED` 并打印
`取最新=第 2 行（ts=…）`；空台账 ⇒ `cmp=3` 判 `NOT_MEASURED` 且没有一行判 PASS。
带/不带这条的 A/B 增益未量过，属建议。

## 来源

长自"量了没落件、落件找不到、交付被指点名的东西不在包里"这一类反复断链：节拍上的缺件与缺口见
`one-round-work-loop`，交付侧的死引用、绝对路径泄漏、指纹口径见 `package-integrity`，
自带 `--self` 与"一个变异只该红一条"的纪律见 `checker-selftest`，判定词与计数地板照 `three-state-verdicts`。
