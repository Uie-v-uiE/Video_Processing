### 1.2 第 1 站：视口换算 —— 一次 >>1

```
wire        left_pane = (x < PANE_W);      // 只留给调试位；内容选择从此不看它
wire [11:0] cx = x >> 1;                   // 视口内的源列（0..511），左右两半同一个数
wire [11:0] cy = (y >> 1) < IMG_H ? (y >> 1) : (IMG_H - 1);
```
（`pl_video_top.v:241`–`:243`）整个 1024×600 屏对应 512×300 的片源，所以两方向都是除 2：
`1024 个显示列对应 512 个源列 ⇒ 每个源列在屏上占两列；行方向 600 对应 300，还是那一次 >>1`（`:238`）。
这一站的意义在 `:239`–`:240`：`原图抽头与处理抽头从此共用同一份源坐标，缝只是逐像素二选一`——旧的「两屏各画一整幅」几何被删掉（`:336`–`:338`）。
`left_pane` 只剩调试用途，这一位就是那句「内容选择从此不看它」（`:241`）。
注意 `cy` 里那个钳制：`(y>>1) < IMG_H ? (y>>1) : (IMG_H-1)`（`:243`），600 行 >>1 得 300，已经越出 [0,300)，所以最后一行重复源行 299。
`cy` 走的是**打拍链 + 效果链**那一路（`:367` 把它锁进 `cy_d[0]`，`:807` 交 `.y_in(cy_d[3])`），**不是**给 mapper 的那一个。

### 1.3 第 2 站：行提前量与 `cy_r`（逐位解释）

```
localparam integer BILIN_ROWS = 2;
wire [12:0] y_right_adv = {1'b0, y} + {5'b0, pipe_off_rows} + BILIN_ROWS[12:0];
wire [11:0] y_req_row = y_right_adv[11:0] >> 1;
wire [11:0] cy_r = (y_req_row >= IMG_H) ? (y_req_row - IMG_H) : y_req_row;
```
（`pl_video_top.v:250`、`:276`–`:277`、`:284`）逐位拆：

- `{1'b0, y}`：12 bit 无符号的显示行 `y`（0..624）零扩展成 13 bit 有符号位宽，因为加完提前量可能超过 600。
- `{5'b0, pipe_off_rows}`：`pipe_off_rows` 是 8 bit（`:236`，注释 `// 效果链自己声明的"内容滞后几行"（u_pipe 的输出口）`），补 5 个 0 凑成 13 bit ⇒ **提前量由链子自己报，顶层不抄字面量**（`:244`：`= 效果链的内容滞后，实测 −4 行且逐像素一致`）。
- `+ BILIN_ROWS[12:0]`：双线性读口在行方向晚一整对显示行（`:250` 定义、`:724`–`:725` 解释「唯一额外的代价是行方向晚一整对显示行」）。`BILIN_ROWS` 的偶数性是硬约束：`⚠ BILIN_ROWS 必须**偶数**（`row0 = ~y[0]` 定成对奇偶，奇数会让一对分属两个源行 ⇒ A/B 错行）`（`:249`）。
- `y_right_adv[11:0] >> 1`：先加再截 12 bit 再除 2 ⇒ 得「请求行」（0..302；`:282` 写明 `y_req_row 最大 302 ⇒ 不需要除法器/取模（#58）`）。
- `cy_r`：`y_req_row >= IMG_H` 就减一次 `IMG_H` ⇒ **绕回**到下一帧头几行的位置。注释给了为什么是减而不是取模：`:279`–`:280`「钳到 `IMG_H-1` 就让屏顶画"这张图自己的末行"」，`:281`–`:283` 又钉了口径：「**取模的对象是"请求行"，窗也必须按"写进环的那一拍"来开**」「**减一次就够**」。
  所以 `cy_r` 的语义是：**喂给 mapper 的显示行号（已提前、已绕回）**；而 `cy` 的语义是：**喂给效果链/打拍链的行号（已钳、未提前）**。两者故意不同级，改错一个就会出现帧头 6 行与主体不同角（`:288`–`:291` 那一刀）。

绕回窗同时被换角拍点复用：`wire [11:0] img_h_12 = IMG_H;`（`:298`）、`wrap_row_now = (y_req_row >= img_h_12)`（`:299`）、
`adv_row_next = y_right_adv + 13'd1`（`:300`）、`req_row_next = adv_row_next[12:1]`（`:301`）、`wrap_row_next = (req_row_next >= img_h_12)`（`:302`），
翻角条件是 `if (fs_de_d && !de && wrap_row_next && !wrap_row_now) rot_fs_tog <= ~rot_fs_tog;`（`:312`）——
即「在最后一个不绕回的行（今天=593）的行尾消隐里换角」（`:293`–`:295`）。

**数据形状与屏上表现**

  读口相位接错一级 → 四分之一格子错列（`:742`–`:743`）。

### 2.1 定点表示：Q8 倒数，不是 Q8 倍率

全链路只有一种缩放数表示：**Q8 的倒数** `inv`，`256 = 1.0x`（原始大小），数值越大画面越小。
出处三处一致：`zoom_mapper.v:3`（`// inv_scale Q8: 256=1.0x（原始，最大），512=0.5x（缩小）。3 级流水，可与旋转叠加。`）、
`zoom_ctrl.v:3`（`// inv_scale Q8: 256=1.0x（最大），512=0.5x（最小，画面更小、四周黑边）。`）、`zoom_fit.v:16`。
小数位数 = 8（分母 256），整数部分 2 位（10 bit 里剩 8÷256…1023÷256 ≈ 3.996），所以能表到的最大显示倍率是 1.0x、
最小约 0.2502x；**放大**（>1.0x）在倒数尺度上表现为 `inv < 256`，128 = 2.00x（`zoom_ctrl.v:53` `default: tbl = 10'd128; // 2.00x`）。
为什么用倒数：mapper 是**逆**映射，屏→源本来就是「乘一个大于等于 1 的步长」，用倒数就把缩放变成一次乘法，
`呼吸仍然只在 [INV_LO, INV_HI]（默认 1.0x…0.5x）里走；手动档允许到 2.0x/0.25x：`zoom_mapper` 是**逆**映射，
inv 变小只是采样窗收进画面内部（不越界），inv 变大则四周填黑 —— 两种都不需要动 mapper`（`zoom_ctrl.v:38`–`:39`）。
方向语义也一句话讲完：`// inv 越大 → 逆映射采样越"散"→ 显示画面越小。`（`zoom_ctrl.v:4`）、
`// 0: 向缩小走(inv增) 1: 回到1.0x(inv减)`（`:30` 的 `dir`）。

### 2.2 八档怎么编码成寄存器值

档号约定在 `zoom_ctrl.v:35`：`// 档号与下面 OSD 那张表**同一个约定**：0=0.25 1=0.33 2=0.50 3=0.75 4=1.00 5=1.33 6=1.50 7=2.00。`
落点就是那张 `function [9:0] tbl; input [2:0] i;`（`:40`–`:41`）的 case 表（`:43`–`:54`），全部是编译期常数、不做除法（`:34` 的 `纯常数，不做除法，#58`）：

| 档号 | 名义倍率 | `inv` 值 | 反算倍率 256/inv | 源行 |
|---|---|---|---|---|
| 0 | 0.25x | `10'd1023` | 0.25024x | `zoom_ctrl.v:44` |
| 1 | 0.33x | `10'd776` | 0.32989x | `:47` |
| 2 | 0.50x | `10'd512` | 0.50000x | `:48` |
| 3 | 0.75x | `10'd341` | 0.75073x | `:49` |
| 4 | 1.00x | `10'd256` | 1.00000x | `:50` |
| 5 | 1.33x | `10'd192` | 1.33333x | `:51` |
| 6 | 1.50x | `10'd171` | 1.49708x | `:52` |
| 7 | 2.00x | `10'd128` | 2.00000x | `:53` |

（表中「反算倍率」是按 `scale = 256/inv` 由本卷算的算术结果，不是文件里的测量数字。）
0 档为什么是 1023 不是 1024，文件里给了完整理由：`// 0.25x —— **不是 1024**：inv_scale 只有 10 bit（Q8 的天花板就是 1023 ⇒ 1024 会回绕成 0，画面上变成"无限大"而不是 0.25x）。1023 对应 0.2502x，与档名差 0.02 %，台架按 10 bit 的边界钉住。`（`:44`–`:46`）。
`zfit` 的钳位上界也是同一个 1023（`zoom_fit.v:51`），两处的天花板是同一个理由。

### 2.3 `zoom_code`：OSD 的「最近一档」用中点比大小

`output reg  [2:0]  zoom_code,     // V8-5：OSD 的"最近一档"编号（见下面的表）`（`zoom_ctrl.v:29`）。
本来要显示 "0.75x" 就得算 `25600/inv`，`那是一条运行时非 2 幂除法 —— 在快域里就是 #58 那个 −5.014 ns 的组合除法器`（`:61`–`:62`），
所以改成「与相邻两档的中点比大小」（`:61`），7 个常数比较、优先级链（`:76`–`:83`）：
`>= 10'd900` → 0、`>= 10'd644` → 1、`>= 10'd427` → 2、`>= 10'd299` → 3、`>= 10'd224` → 4、`>= 10'd182` → 5、`>= 10'd150` → 6、否则 → 7。
这些数就是相邻表值的算术中点（900≈(1023+776)/2、644≈(776+512)/2、427≈(512+341)/2、299≈(341+256)/2、224≈(256+192)/2、182≈(192+171)/2、150≈(171+128)/2，本卷算的）。
两张表能互相对上的原因写在 `:36`–`:37`：`zoom_code` 是拿 inv 与相邻两档的中点比大小得到的 ⇒ 表值代回自己那一档必然落在自己的区间里，
并且这条不是巧合而是台架判据（`tb_v94_zoom_sel 逐档验 `code(TBL[i]) == i`，改哪边都会红`，`:37`）。
比较对象必须是真在用的那一个：`⚠ 比较的对象是 `inv_used`（真正喂给 mapper 的那一个），不是 `inv_scale``（`:58`–`:59`），
否则 `拿它分区就会"屏上写 1.00x、画面上是 0.52x"`（`:59`）。寄存一拍再给 OSD（`:62`–`:63`、`zoom_code <= code_nxt;`（`:95`）），
理由：`档位号只跟着**上一拍**的 inv_scale ⇒ 这一段不进 OSD 那条组合链（V7.9.4 的教训）`（`:93`）。

### 2.4 自动呼吸档与 Fit 档

呼吸（自动）：每帧一步，步长 `STEP = 10'd2`（`:8`；顶层实参 `pl_video_top.v:325` 同一个值），
在 [256, 512] 之间来回；`dir` 决定方向（`:120`–`:136`，上升支 `if (inv_scale + STEP >= INV_HI)`（`:122`）、下降支 `if (inv_scale <= INV_LO + STEP)`（`:130`））。
带外恢复是这条链最讲究的一段：手动档可以把画面停在呼吸带之外，`原来 `!dir` 那一支在 inv 已经大于 INV_HI 时会写成 `inv <= INV_HI`，于是 1023 → 512 一帧跳掉半幅 —— 用户看到的就是"画面弹一下"`（`:114`–`:115`），
现在改成 `if (inv_scale > INV_HI) begin inv_scale <= inv_scale - STEP; dir <= 1'b1; end`（`:117`–`:119`）—— 每帧一步朝带回里走（`:116`）。
节拍：`手动档：**与呼吸同一个节拍，只在帧首换** ⇒ 一帧之内不会半屏新一档半屏旧一档`（`:106`），实现在 `else if (manual && frame_start)`（`:105`）与 `else if (frame_start)`（`:112`）。
Fit 档（第三种来源）：`// V9-2：第三种缩放来源 —— 由**角度**定出来的"刚好装得下"那一档（见 zoom_fit.v）。`（`:15`）；
生效式 `wire [9:0] inv_raw = fit_en ? inv_fit : inv_scale;`（`:64`）+ `wire rot_clamp = rotate_en && (inv_raw < inv_fit);`（`:72`）+ `assign inv_used = rot_clamp ? inv_fit : inv_raw;`（`:73`）。
旋转态「不许放大到画外」的实现就是取 inv 较大者（`:65`–`:66`），代价写进口径：`① 旋转态因此**不提供放大**，1.33x/1.5x/2.0x 三档在旋转时被拉回 fit；② **0° 不在钳之内**`（`:67`–`:68`），
原先「0° 也在钳」那句注释是错的，`那是把 `zoom_fit` 的**输出**当成了生效条件，实测口径见 #162`（`:69`–`:70`），两条口径都由 `tb_v94_zoom_sel` 的 T8 钉住（`:71`）。
开拟合时整条 `inv_scale` 链被旁路（不写它）：`整条 inv_scale 链**旁路**（这里不写 inv_scale ⇒ 关掉拟合时，呼吸/手动从它原来的位置接着走，不会跳档）`（`:97`–`:98`），
但 `zoom_active` 仍按 `inv_used` 报（`:100`），否则 `会出现"lane23 说没在缩放、屏上画面缩了一半"`（`:101` 前一句 `:99`）。

模块：`src/rtl/process/zoom/zoom_fit.v`（61 行），顶层实例名 `u_zfit`（`build/report/power.rpt:210` 按这一行列它的功耗 0.003 W）。
它的职责只有一句话：把「当前角度下整幅画面刚好还在屏内」那个倍率算出来，输出成一个 Q8 倒数。

### 3.1 它在解哪道题

视口就是图像未旋转时的外框 `IMAGE_W × IMAGE_H`，默认 512×300（`zoom_fit.v:9` `parameter integer IMAGE_W = 512,`、`:10` `parameter integer IMAGE_H = 300,`）。
文件头把几何推了一遍：图像以显示倍率 s 旋转 θ 之后的外框是 `W' = s·(W|cosθ| + H|sinθ|)`、`H' = s·(W|sinθ| + H|cosθ|)`，
要求 `W'≤W 且 H'≤H`，写开就是两条 `inv_x = (W·C + H·S)/W`、`inv_y = (W·S + H·C)/H`，取较大者即「刚好装得下」（`zoom_fit.v:3`–`:7`）。
输出端口 `output reg  [9:0]  inv_fit`，注释直接写明约定：`// Q8：256 = 1.0x，越大画面越小`（`zoom_fit.v:16`）。

### 3.2 三角项：查表，不算

```
wire signed [9:0] sin_v, cos_v;
sin_rom u_sin (.angle(angle), .value(sin_v));
cos_rom u_cos (.angle(angle), .value(cos_v));
```
（`zoom_fit.v:19`–`:21`）不是 CORDIC，是两张自动生成的三角表（`rotate/sin_rom.v`、`rotate/cos_rom.v`，各 372 行），索引是整数度 0..359（`sin_rom.v:4`），
值域里 256 表示 1.0，即 Q8 有符号 10 bit（`sin_rom.v:2`，详见 §5.2）。取绝对值用 10 bit 无符号，文件里说明了为什么不会溢出：`// |·|：表里最大幅度是 256（=1.0），10 bit 无符号放得下，取反不会溢出。`（`zoom_fit.v:22`），
实现就是 `wire [9:0] C = cos_v[9] ? (~cos_v + 10'd1) : cos_v;`（`zoom_fit.v:23`），S 同构（`:24`）。
关键约束在注释里点名：`// 与 zoom_mapper 用的是**同一张**三角表 ⇒ 这里算出来的"装得下"判的就是那条链真正画出来的框。`（`zoom_fit.v:18`）——
`zfit` 与 `zmap`（`zoom_mapper.v:22`–`:23`）例化的是同一对 ROM，所以判据和画出来的框不会各说各话。

### 3.3 除法折成乘常数

`NSHIFT = 20`（`zoom_fit.v:11`，注释 `// 倒数常数的定点位数`）。运行时没有除法器：

```
localparam [NSHIFT-1:0] REC_W = ((1 << NSHIFT) + (IMAGE_W >> 1)) / IMAGE_W;
localparam [NSHIFT-1:0] REC_H = ((1 << NSHIFT) + (IMAGE_H >> 1)) / IMAGE_H;
```
（`zoom_fit.v:29`–`:30`）elaboration 阶段算好，综合折成常量乘法。文件解释了为什么非这么做不可：
`⚠ 运行时**没有除法器**（#58 那一课：100 MHz 域的组合除法器把 WNS 打到 −5.014）`（`zoom_fit.v:26`），误差 ≤ 0.03 %，比 Q8 表本身 ±0.5 LSB 的量化误差还小（`:27`）。

分子是两条定点内积：

```
wire [17:0] nx_c = IMAGE_W * C + IMAGE_H * S;     // ≤ (512+300)·256 = 207872 < 2^18
wire [17:0] ny_c = IMAGE_W * S + IMAGE_H * C;
```
（`zoom_fit.v:32`–`:33`）18 bit 的位宽上限直接在行尾算给你看。随后 `wire [31:0] ix = (nx * REC_W) >> NSHIFT;`（`:44`，注释 `// 18×11 → 29 bit，一段乘法器就够`）、
`iy` 同构（`:45`），`wire [9:0]  imax = (ix > iy) ? ix[9:0] : iy[9:0];`（`:46`）就是「取较大者」。

### 3.4 边界钳制与余量

```
wire [10:0] fit_raw = {1'b0, imax} + (imax >> 8) + 11'd2;
wire [10:0] fit_c   = (fit_raw > 11'd1023) ? 11'd1023 : fit_raw;
```
（`zoom_fit.v:50`–`:51`）截断就在 `:51` 这一行，上界 1023。为什么是 1023 而不是 1024：`inv_scale/inv_fit` 都只有 10 bit，
`zoom_ctrl.v:44` 的 0.25x 档同样因此被钉成 `10'd1023`，注释说 `1024 会回绕成 0，画面上变成"无限大"而不是 0.25x`（`zoom_ctrl.v:44`–`:46`）。
余量 `(imax>>8)+2` 的来源是量化误差而不是几何：`余量：Q8 三角表每一项最多差 0.5 LSB ⇒ inv 最大差 (W+H)/2/H ≈ 1.35，取 (imax>>8)+2 稳过它`（`zoom_fit.v:48`–`:49`），
并且在 0°/90° 只多缩 `3/256 ≈ 1.2 %（屏上 6 个源列，看不见）`（`:49`）。
这就是「0.5–1.0 那一段特殊」的原因：`fit_raw` 的位宽给到 11 bit（`:50` 的 `{1'b0, imax}`）正是为了在 `imax` 接近 1023 时先加完余量再夹，
避免在 10 bit 里加出回绕后又被误判成「没超界」；夹完之后才是 10 bit 的 `fit_c[9:0]`。

### 3.5 为什么分两拍、用掉几颗 DSP

```
reg [17:0] nx, ny;
always @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin nx <= 18'd0; ny <= 18'd0; end
    else        begin nx <= nx_c;  ny <= ny_c;  end
end
```
（`zoom_fit.v:39`–`:43`）文件里给的是实测口径，不是估计：
`r60 实测 `angle → inv_fit` 一拍做完是 15 级、含两个 DSP48，slack 只剩 +1.843 ns（全设计第三差）`（`zoom_fit.v:35`–`:36`）——
也就是说 **`zfit` 这一站吃掉 2 颗 DSP48E1**，全设计合计 19 颗（`build/report/utilization.rpt:121` 行 `| DSPs           |   19 |     0 |          0 |       220 |  8.64 |`，
`:212` 行 `| DSP48E1    |   19 |     Block Arithmetic |`）。逐实例的 DSP 数目这几份 rpt 里没有单独列出（`build/report` 下只有 cdc / clock_util / methodology / power / route_status / timing_summary / utilization 七份），
除 `:35` 那句实测注释之外无第二处点名 ⇒ 其余实例各占几颗：未证。
多一拍换来的余量是划算的，因为 `这条链的输入一帧才变一次（自动旋转的步进钉在帧首）`（`zoom_fit.v:36`–`:37`）。
输出寄存器在 `:57`–`:60`：复位给 `inv_fit <= 10'd256;`（`:58`，注释 `// 上电角度就是 0 ⇒ 1.0x，与未开拟合时一致`），常态 `inv_fit <= fit_c[9:0];`（`:59`）。
装载策略值得单独记一句：`:52`–`:56` 说明它是**每拍都跟**而不是「角度变了才装载」，否则 `zoom fit 1` 在 30° 按下去屏幕会先不动（`:55`）。

### 3.6 与 `zoom_ctrl` 的接缝

`zfit` 的输出只是候选值，真正生效的是 `zoom_ctrl.v:73` 的 `assign inv_used   = rot_clamp ? inv_fit : inv_raw;`，
其中 `inv_raw = fit_en ? inv_fit : inv_scale`（`zoom_ctrl.v:64`）。mux 为什么不在顶层：
`这里已经是"倍率的唯一出处"`（`zoom_ctrl.v:16`–`:18`），顶层再 mux 一次就会出现「屏上那一格与真正在用的 inv 不是一回事」。

**数据形状与屏上表现**
- 输入：`angle`，9 bit 无符号（`zoom_fit.v:15`），0–255 对应 0–359°（表 256 项，见 §5）。
- 输出：`inv_fit`，10 bit 无符号 Q8 倒数，256 = 1.0x，上界 1023（`:16`、`:51`）。中间量 `nx/ny` 18 bit 无符号、`ix/iy` 31 bit、`fit_raw/fit_c` 11 bit。
- 出错表现：这一站算错（例如换了一张不同的三角表、或余量给小了）表现为旋转时画面边缘出屏后被裁掉，或整幅比应有的角度多缩一点；
  由于两拍延迟是设计内定的，误把它改成一拍会在时序上复发 `+1.843 ns` 那一档（`:35`）。屏上具体形态未做逐档截图 ⇒ 未证。

模块：`src/rtl/process/zoom/zoom_mapper.v`（117 行），顶层实例名 `u_zmap`（`build/report/power.rpt:211` `|     u_zmap                 |     0.006 |`）。
文件头一行就把职责说完了：`// 右屏无极缩放逆映射：屏幕 (x,y) → 源图 (sx,sy)。`（`zoom_mapper.v:2`），
约定与流水深度：`// inv_scale Q8: 256=1.0x（原始，最大），512=0.5x（缩小）。3 级流水，可与旋转叠加。`（`zoom_mapper.v:3`）。

### 4.1 端口与位宽

`input  wire [9:0]  inv_scale,   // Q8, 256=1.0, up to 512=0.5x`（`zoom_mapper.v:10`）；
屏幕坐标进 `x_in`/`y_in` 各 12 bit 无符号（`:13`–`:14`），出 `x_out`/`y_out` 各 12 bit + `oob` 1 bit + 小数 `frac_x`/`frac_y` 各 8 bit（`:15`–`:19`）。
`rotate_en` 是第 12 行，角度 `input  wire [8:0]  angle`（`:11`）。
倒数要先拓宽成有符号：`// 512 需 11-bit 有符号才为正`（`:25`），`wire signed [10:0] inv = $signed({1'b0, inv_scale});`（`:26`）——
这一句是本模块最容易踩的坑：10 bit 有符号在 inv=512 时是负数，所以必须先补一个 0。

### 4.2 s0：中心偏移，两条 Y 轴同时算

```
xp      <= $signed({1'b0, x_in}) - $signed(IMAGE_W / 2);
yp_math <= $signed(IMAGE_H / 2) - $signed({1'b0, y_in});
yp_disp <= $signed({1'b0, y_in}) - $signed(IMAGE_H / 2);
```
（`zoom_mapper.v:32`–`:34`，寄存器声明 `reg signed [12:0] xp, yp_math, yp_disp;` 在 `:29`）
注释给的口诀是 `// s0: 中心偏移。旋转用数学坐标 yp_math=H/2-y`（`:28`）。
也就是说：**显示系 y 向下、数学系 y 向上**，两者只差一次翻转，所以 s0 把两个版本都算出来，s1 里按 `rotate_en` 二选一
（`yp_s1  <= rot_s0 ? yp_math : yp_disp;`，`:44`）。三位都是 13 bit 有符号，够装 ±2048 的屏宽偏移。

### 4.3 s1：旋转（只有 rotate_en 时才乘）

```
xr_m <= $signed({{11{xp[12]}}, xp}) * cos_v
      + $signed({{11{yp_math[12]}}, yp_math}) * sin_v;
yr_m <= -($signed({{11{xp[12]}}, xp}) * sin_v)
      +  $signed({{11{yp_math[12]}}, yp_math}) * cos_v;
```
（`zoom_mapper.v:47`–`:50`）这是标准的逆旋转 `[cos sin; -sin cos]`：13 bit 的中心偏移先符号扩展成 24 bit
（`{11{xp[12]}}` 复制 11 位符号 + 原 13 位 = 24 位），再乘 Q8 的 sin/cos，两路乘积相加后落在 24 bit 有符号里，
结果寄存器 `reg signed [23:0] xr_m, yr_m;`（`:39`）。非旋转态这两路清零：`xr_m <= 24'sd0;`（`:52`），省功率、也让 s2 只有一套乘法器。
`rot_s0`/`rot_s1`（`:30`、`:41`）是把 `rotate_en` 跟着流水走的对齐位。

### 4.4 s2：乘 inv_scale 与两种移位

```
wire signed [31:0] rot_xs = xr_m * inv;
wire signed [31:0] rot_ys = yr_m * inv;
wire signed [31:0] raw_xs = xp_s1 * inv;
wire signed [31:0] raw_ys = yp_s1 * inv;
wire signed [31:0] xr_pix = rot_xs >>> 16;
wire signed [31:0] yr_pix = rot_ys >>> 16;
wire signed [31:0] xs_pix = raw_xs >>> 8;
wire signed [31:0] ys_pix = raw_ys >>> 8;
```
（`zoom_mapper.v:58`–`:66`）乘加结构就是「一次 24×11 或 13×11 的乘法 + 一次算术右移」：
旋转支里 Q8 的 sin/cos 与 Q8 的 inv 叠成 Q16 ⇒ 右移 16；非旋转支只有 Q8 ⇒ 右移 8。
`s2: * inv_scale；inv>256 时边缘 OOB 填黑（缩小后四周空边）`（`:57`）说明了这一拍唯一的语义差别。
回到图像坐标系：`sx_c = rot_s1 ? (xr_pix + (IMAGE_W / 2)) : (xs_pix + (IMAGE_W / 2))`（`:68`–`:69`），
纵支 `sy_c` 在 `:87`–`:88`，旋转态是 `((IMAGE_H / 2) - yr_pix - (rot_y_has_frac ? 32'sd1 : 32'sd0))`——注意那次翻转连着减一格，见 §6.4。
`>>> 8` 的取整方向是设计的一部分：`floor 与 frac 必须自洽：`>>> 8` 是**朝 −∞** 取整，余下的低 8 位正好是 [0,1) 的小数`（`:90`–`:91`）。

### 4.5 越界两向判定 `oob`

写法是「一条 if 把两端同时夹住」，而不是先判上界再判下界：

```
end else if (sx_c < 0 || sx_c >= IMAGE_W || sy_c < 0 || sy_c >= IMAGE_H) begin
```
（`zoom_mapper.v:103`）四个条件、两条边界：下界用有符号比较 `< 0`，上界用 `>= IMAGE_W` / `>= IMAGE_H`（半开区间 [0, W)）。
命中时**四个输出一起清**：`x_out <= 12'd0;`（`:104`）、`y_out <= 12'd0;`（`:105`）、`oob <= 1'b1;`（`:106`）、`frac_x <= 8'd0;`（`:107`）、`frac_y <= 8'd0;`（`:108`）。
小数一起清零是必须的：如果留着旧小数，下游双线性会在越界点外插出一个「不该存在的邻接像素」，屏上表现为黑边内侧一条 1 像素的杂色线。
正常支把 12 bit 截出来：`x_out  <= sx_c[11:0];`（`:110`）——`sx_c` 是 32 bit，能被这条 if 保证在 [0,512) 内，所以截 12 bit 无损。
复位态是 `oob    <= 1'b1;`（`:100`），即「未算出来之前一律当越界」，保守填黑。

### 4.6 DSP

`s2` 那四条乘法是全设计里最贵的一段。`build/report/timing_summary.rpt:934` 点名的正是这一站的寄存器：
`Min Period        n/a     DSP48E1/CLK         n/a            3.272         20.000      16.728     DSP48_X2Y30      u_pl/u_zmap/yr_m_reg/CLK`——
`yr_m_reg` 直接被综合成 DSP48 的 CLK 脚，说明 s1→s2 的乘累加落在 DSP 里；全设计 DSP48E1 合计 19 颗（`build/report/utilization.rpt:121`、`:212`）。
`zmap` 独占几颗：这几份 rpt 没有逐实例计数 ⇒ 未证。

**数据形状与屏上表现**
- 输入：12 bit 屏幕 (x,y) + 10 bit Q8 倒数 + 9 bit 角度 + `rotate_en`。
- 输出：12 bit 源 (sx,sy) + 8 bit 小数 (frac_x, frac_y) + 1 bit `oob`。小数是 Q8（每格 1/256），位宽与源坐标不同，别混用。
- 出错表现：`oob` 判松了（该越界没判出来）→ 从帧缓冲里读到隔壁行的像素，屏上是随机彩噪；判紧了 → 有效画面四周多出黑边。
  符号扩展写错（`:26` 那一处）在 0.5x 时会让整幅画面上下翻转，是本模块注释专门留警告的原因。

独立模块 `src/rtl/process/rotate/rotate_mapper.v`（66 行）是它的早期形态／台架参照，参数默认 640×360（`rotate_mapper.v:6`–`:7`），
现役 `zoom_mapper` 默认 512×300（`zoom_mapper.v:5`–`:6`）。两者的数学完全一致。

### 5.1 为什么必须是逆映射

`rotate_mapper.v:2`：`// Inverse map display/canvas (x,y) -> source (sx,sy) for angle 0..359.`
`rotate_mapper.v:3`：`// Math: center image, flip Y, rotate by -angle (matches reference matlab).`
原因是扫描的节拍：显示控制器是按屏像素 (x,y) 一个个往前走的，能作为「每拍一次」索引的只有屏坐标；
若改正向映射（源 → 屏），每拍要写出的目标地址是散落的，还得解决空洞填充，帧缓冲写端口要按屏序排好。
逆映射把两件事一起解决：屏坐标天然连续，空洞（源坐标出界）天然落在「读」这一侧，用一个 `oob` 标志就能填黑。
所以旋转方向取 **−angle**（`:3`），把「屏上的这一点」转回「它在原图里是哪一点」。

### 5.2 sin/cos 来自表，不是 CORDIC

`src/rtl/process/rotate/sin_rom.v`（372 行）与 `cos_rom.v`（372 行）：

```
// Auto-generated sin_rom: round(fn(angle_deg)*256), signed 10-bit
module sin_rom (
    input  wire [8:0] angle, // 0..359
    output reg signed [9:0] value
```
（`sin_rom.v:2`–`:5`）索引是**整数度** 0–359，不是 256 分；值是 Q8 有符号 10 bit（`sin_rom.v:1` 文件头 `timescale`、`:2` 生成说明）。
所以量化单位是 1°/0.5 LSB：`9'd0: value = 10'sd0;`（`:9`）、`9'd1: value = 10'sd4;`（`:10`，sin1°≈0.0175 → 4/256）、
`9'd30: value = 10'sd128;`（`:39`，正是 0.5 的 Q8 表示）。纯组合 `case`（`:7`–`:8`），综合成 LUT 逻辑，不占 DSP，也不占 BRAM。
`zfit` 与 `zmap` 例化的是同一对表（`zoom_fit.v:20`–`:21`、`zoom_mapper.v:22`–`:23`、`rotate_mapper.v:20`–`:21`），
这条「同一张表」的约束写在 `zoom_fit.v:6`：`C/S 来自**与 zoom_mapper 同一张** Q8 三角表（256 = 1.0）`。

### 5.3 角度累加与 ±1° 按键通路

`src/rtl/process/rotate/angle_ctrl.v`（46 行）：文件头 `// Angle control: KEY1 +1°, KEY2 -1°, wrap 0..359。`（`angle_ctrl.v:2`）。
按键是组合级的两条独立通路，优先于自动走：

```
else if (key_inc)
    angle <= (angle == 9'd359) ? 9'd0 : (angle + 9'd1);
else if (key_dec)
    angle <= (angle == 9'd0) ? 9'd359 : (angle - 9'd1);
```
（`angle_ctrl.v:39`–`:42`）——359→0 与 0→359 两个方向手工回绕，所以按键不受「一帧最多 7°」那条约束。
自动档的累加用「先加再减 360」而不是「到 359 就归 0」：

```
wire [9:0] up        = {1'b0, angle} + {7'd0, speed};
wire [8:0] wrap_up   = (up >= 10'd360) ? (up - 10'd360) : up[8:0];
```
（`angle_ctrl.v:33`–`:34`）注释给的理由是算术的：`// 一帧最多走 7°：360 = 7·51 + 3，所以取模要用"减 360"而不是"到 359 就回 0"`（`:31`），
否则每圈在回绕处丢几度，`转速快的时候肉眼看得出那一顿`（`:32`）。`speed` 是 3 bit，`// 度/帧；0 = 自动开着但不走`（`:14`）。
步进必须钉在帧边界：`else if (auto_en && fs_edge && (speed != 3'd0))`（`:43`）。
`fs_edge` 不是脉冲而是翻转位同步后的边沿：`(* ASYNC_REG = "TRUE" *) reg [2:0] fs_s;`（`:24`）、`fs_s <= {fs_s[1:0], frame_tgl};`（`:27`）、
`wire fs_edge = fs_s[1] ^ fs_s[2];          // 每次帧首恰好一拍（sys_clk 域）`（`:29`）。
两条 ⚠ 都在文件头/段首：帧中间换角度会让「这一帧上半与下半用两个不同的角，画面在换的那一行错开一下」（`:4`–`:6`）；
脉冲跨域「会被整个吃掉（#36）」，同步器放在拥有时基的这一侧，「顶层不许再自己采一遍」（`:20`–`:22`），
并且顶层为它单起一个翻转触发器，否则 `cdc.rpt` 判 CDC-11 Critical（`:22`–`:23`）。
对外只有一个门：`assign rotate_active = (angle != 9'd0);`（`:18`）——这就是 §2 里 `zoom_ctrl` 的 `rotate_en` 来源（`zoom_ctrl.v:68` 明写 `顶层递进来的 `rotate_en` 就是 `angle_ctrl.v:18` 的 `rotate_active = (angle != 0)``）。

### 5.4 包围盒与钳制

旋转后的外接框（也就是「四角会不会出屏」）在 `zoom_fit` 那两条式子里被显式解出来：`W' = s·(W|cosθ| + H|sinθ|)`、
`H' = s·(W|sinθ| + H|cosθ|)`，要求两者都不超过原框（`zoom_fit.v:4`–`:5`）。取较大者后，
`zmap` 每像素侧仍逐点判定：`if (xs < 0 || xs >= IMAGE_W || ys < 0 || ys >= IMAGE_H)`（`rotate_mapper.v:55`）——
四角出屏不需要专门的状态机，它们各自作为「屏上某一点的源坐标落到框外」被这一行逮住，走同一条填黑分支
（`x_out <= 12'd0;` / `y_out <= 12'd0;` / `oob   <= 1'b1;`，`rotate_mapper.v:56`–`:58`）。
位宽上这里比 `zmap` 多留一位余量：`wire signed [24:0] xs = xr + (IMAGE_W / 2);`（`:42`）、
`wire signed [24:0] ys = (IMAGE_H / 2) - yr;`（`:43`）——512/640 级坐标在 25 bit 有符号里绝不回绕，钳制才可信。
`!enable` 时这一站整体旁路，但 `oob` 仍然算：`oob   <= (x_in >= IMAGE_W) || (y_in >= IMAGE_H);`（`:53`），
注意这一支只判上界不判 `<0`，因为输入 `x_in`/`y_in` 是无符号的 12 bit（`:13`–`:14`），下界恒真。
「旋转态四角出屏」如果指另一条显式的角点判据（例如台架里逐角点比对），本轮未在几何 RTL 中检索到，只有上面这条逐点判据 ⇒ 未证。

**数据形状与屏上表现**
- 输入：`angle` 9 bit 整数度 0–359（`angle_ctrl.v:15`），`key_inc`/`key_dec`/`auto_en`/`speed[2:0]`/`frame_tgl`；屏坐标 12 bit×2。
- 中间量：`xp`/`yp` 13 bit 有符号（`rotate_mapper.v:24`）→ `xr_m`/`yr_m` 24 bit 有符号（`:31`）→ `xr`/`yr` 24 bit（`:40`–`:41`）→ `xs`/`ys` 25 bit 有符号（`:42`–`:43`）。
- 输出：`x_out`/`y_out` 12 bit + `oob`；`zmap` 那一版还多带 `frac_x`/`frac_y` 两个 Q8 小数（`zoom_mapper.v:18`–`:19`）。
- 出错表现：换表 / 忘了一次 `flip Y` ⇒ 画面上下镜像；角度在帧中变化 ⇒ 换的那一行错开一条（`:5` 描述的现象）；
  `#189` 那一族「沿角度方向的稀疏错一行鬼影」实测发生率 ≈ 0.27 %（`zoom_mapper.v:80`），根因在纵轴翻转与 floor 没连着改，见 §6.4。

### 6.1 四邻取样地址怎么来

时间复用是这个模块的前提：`// 每个源像素用满它天然的 4 个 50 MHz 拍（2 显示列 × 2 显示行），一个读口每拍一次读，全程不进快域。`（`fb_bilin.v:4`）。
四个相位由 `col0 = ~x[0]`、`row0 = ~y[0]`（`:25`–`:26`）组合决定，文件里把分配写成了表：
`(row0,col0) = (1,1)→发 A ｜ (1,0)→发 A+1 ｜ (0,1)→发 B ｜ (0,0)→发 B+1（一个读口、每拍一次）`（`:37`–`:38`）。
地址算式（全在慢域）：

```
localparam [16:0] ROW_WORDS = IMG_W / 4;   // 一行几个 64bit 字（IMG_W 是 4 的倍数）
wire [18:0] pxl  = sy * IMG_W + sx;
wire [16:0] w_a  = pxl[18:2];
wire [1:0]  lane = pxl[1:0];
wire [16:0] w_b  = w_a + ROW_WORDS;
```
（`:34`、`:42`–`:45`）`sy * IMG_W` 因为 IMG_W 是 2 的幂而综合成连线（`:41`）。
**为什么一次取两个 64 bit 字**：一块 `frame_buffer_w64` 里 4 个 RGB565 挤在一个 64 bit 字里，
横向邻接（x 与 x+1）通常还在同一个字内（只需 `lane+1`），但纵向邻接（y 与 y+1）一定差整整一行 ⇒ 必须再取一个字，
地址就是 `w_b = w_a + ROW_WORDS`（`:45`）。于是「四邻」= 字 A（上边两个）+ 字 B（下边两个），每拍读一个、四拍读齐；
`a_hold`/`b_hold` 就是这两个字的暂存（`reg [63:0] a_hold, b_hold;`，`:125`，写 enable 是 `if (ph_a0) a_hold <= fb_word;` / `if (ph_b0)`，`:129`–`:130`）。
字内选道由组合函数 `pick` 完成（`:70`–`:81`，四个 case：`pick = w[15:0];` … `pick = w[63:48];`）。
右邻跨字的那一格单独处理：`wire [15:0] p10_y0 = (lane_d2 == 2'd3) ? fb_word[15:0] : pick(a_hold, lane_d2 + 2'd1);`（`:140`–`:141`）——
lane==3 时右邻已经不在 A 字里，当拍刚到达的 `fb_word`（即 A+1）才是它。

### 6.2 边界折回与 `bilin_en=0`

```
wire [7:0]  fx_use = (!bilin_en || sx >= IMG_W-1) ? 8'd0 : fx;
wire [7:0]  fy_use = (!bilin_en || sy >= IMG_H-1) ? 8'd0 : fy;
wire        kx_use = !bilin_en || sx >= IMG_W-1;   // 横向抽头折回
wire        ky_use = !bilin_en || sy >= IMG_H-1;   // 纵向抽头折回
```
（`:51`–`:54`）钉子与折回是两件事一起做：`末列/末行的 +1 抽头落在图外 ⇒ 两件事一起做：① 小数钉 0（lerp 恒等于 p00/p01）；② 抽头**折回图内**`（`:46`–`:47`）。
只做①是不够的，理由写得很硬：`末行那次 `w_b = w_a + ROW_WORDS` 会读到帧缓存的**填充区** —— 硬件里是 BRAM 上电的 0、xsim 里是 X，而 X×0=X ⇒ 整行被污染`（`:49`–`:50`）。
折回的落点在 `p10_y0c = kx_d2 ? p00_y0 : p10_y0;`（`:144`）与 `p01 = ky_d2 ? tap_r[15:0] : p01_raw;` / `p11 = ky_d2 ? tap_r[31:16] : (kx_d2 ? p01_raw : p11_raw);`（`:161`–`:162`）。
`bilin_en` 走同一道钉子（`:48`），所以 on/off 逐位等于最近邻、切换不需要重新构建。

### 6.3 行抽头 RAM 与索引的坑

```
(* ram_style = "block" *) reg [31:0] tap_hold [0:IMG_W-1];
tap_r <= tap_hold[j_d1];
if (ph_a1) tap_hold[j_d2] <= {p10_y0c, p00_y0};
```
（`:142`–`:143`、`:152`–`:153`）512×32 的 1W1R 块，把上边的两个抽头打包成一个 32 bit 字。
索引必须是**显示**列对号而不是源列：`⚠ 索引必须是 `jd` = **显示**列对号 x[9:1]，不能是源列 `sx`：旋转时一条源图线在 x 方向会**停滞甚至倒退** ⇒ 同一个 sx 在这一行里被**另一个源行**重写`（`:136`–`:138`）；
`jd` 的定义就在端口上：`input  wire [8:0]  jd,             // **显示**列对号 = x[9:1]`（`:22`）。
读写地址差两拍是刻意的：`读地址 `j_d1`：读出的正是"两拍前那个请求"的 j（= 当拍的 j_d2），与 B+1 同拍到位`（`:150`），
并且 `写只发生在 y0 行、读只用在 y0+1 行 ⇒ 同一拍同地址不会读写相撞`（`:151`）。
另一条硬约束是综合层面的：`这块 RAM 的读写必须放在**只关心时钟**的 always 里（不带 async reset）`（`:145`–`:146`），
否则 Vivado 报 `ERROR: [Synth 8-91] ambiguous clock in event control`（`:146`），xsim 完全看不出来。

### 6.4 两次线性插值的算式、权重位宽与舍入

小数权重是 Q8 8 bit：`input  wire [7:0]  fx, fy,         // Q8 小数（zoom_mapper 的 frac_x / frac_y）`（`fb_bilin.v:23`），
`bilin_lerp.v:15`–`:16` 同样注为 `sx 的小数部分，Q8`。核的接口是 `4 个 RGB565 抽头 + Q8 小数位 → 1 个 RGB565`（`bilin_lerp.v:2`）。
展开到 8 bit 通道用的是位复制而不是补零：`function [7:0] rep5; input [4:0] v; begin rep5 = {v, v[2:0]}; end endfunction`（`bilin_lerp.v:20`）、
`rep6` 是 `{v, v[1:0]}`（`:21`）；理由在 `:4`–`:5`：`全 1 展开正好 255 ⇒ 纯白不会因展开变灰（补零的话 0x1F→0xF8）`。

第一级横向（`bilin_lerp.v:29`–`:44`）：权重 `wx0 = 9'd256 - {1'b0, fx}`、`wx1 = {1'b0, fx}`，六个内积一次做完，例如 `tr <= r00 * wx0 + r10 * wx1;`（`:39`），
`tr/tg/tb` 是上边行、`br/bg/bb` 是下边行（`:31`–`:32` 注释 `上边（源行 sy）`/`下边（源行 sy+1）`），寄存 1 拍。
第二级纵向 + 舍入（`:51`–`:55`）：`wy0 = 9'd256 - {1'b0, fy1}`、`wy1 = {1'b0, fy1}`，
`wire [25:0] or_r = tr * wy0 + br * wy1 + 26'd32768;`（`:53`）——`+26'd32768` 再取 `[24:16]` 就是「一次 +2^15 再 >>16 四舍五入」（`:7`）。
**没有饱和级**：`两两权重之和恒为 256 ⇒ 横向 ≤ 255×256 = 65280（17bit 封顶）、纵向 ≤ 255×65536 + 舍入 = 25bit ⇒ 不需要饱和`（`:5`–`:7`），
`:57` 再钉一次：`>>16 之后必然 ≤255（权重和恒为 256），所以不夹取。`
这条不是口头保证，`这点由 TB 判据 2「四角同色 ⇒ 输出恒等」强制检验`（`:7`）。
截回 565 在 `pix <= {vr[7:3], vg[7:2], vb[7:3]};`（`:67`）；`:58` 提醒语法坑：`不能写 or_r[24:16][7:3] —— Verilog-2001 不允许对位选结果再位选`。
流水级数：`两级流水：横向一次、纵向一次`（`:3`），且数据寄存器有意不复位：`只复位 valid：数据寄存器带异步复位会挡住它们被打进 DSP48 流水级`（`:37`）——
这就是 `bilin_lerp` 与 DSP48 硬化寄存级绑在一起的说明。

### 6.5 结果缓冲（行环的另一半）

```
(* ram_style = "block" *) reg [16:0] res [0:2*IMG_W-1];
if (asm_d2) res[{h_d4, j_d4}] <= {oob_d4, lerp_pix};
```

而且 `这里不许再开第二个逻辑读口：实测 BRAM 从 80 块顶到 160 块 RAMB36，全片才 140`（`:180`）。

**数据形状与屏上表现**
