# ARCH：把这套工程拆开讲清楚（十卷，本地件，不入库）

这一套的定位与 `LEARNING/`（九卷，从零讲起）不同：这里假定你已经知道 Zynq 上 PL/PS 各是什么、
Verilog 与 C 都读得动，要的是**每一级数据怎么流、每个数落在哪一行**。所以每一卷都按同一形状写：
先给"这一卷回答什么"，再给逐信号的台账表，然后按数据走的顺序讲实现，最后单独列"未证清单"——
读不到证据的东西明写读不到，不编。

## 怎么读

- 只想拿一条链路的全貌：A1 → A2 → A3 → A4 → A5 → A6，然后 A7 与 A8（控制面与观测面），最后 A9。
- 要复现某一次"为什么没这么做"：直接看 A10 的 §7，每条都点名凭据文件。
- 要与仓库里的交付文档对照：`report/technical-document.md`（设计说明）、`report/interface-table.md`
  （端口与寄存器表）、`report/src-map.md`（模块清单）、`report/40-optimization.md`（逐批次优化账）。

## 已知边界

- 这一套只描述**当前这一棵树**。`src/rtl` 的注释里有四处指向已经不存在的凭据件/工具名
  （清单见 `../REVIEW-20261007.md` §3），改注释会动 rtl 指纹、破掉"位流↔RTL"的等式，
  所以本轮只登记不修。

  所以凡"屏上/串口实际读数"的条目都写着未量，不冒充验过。
