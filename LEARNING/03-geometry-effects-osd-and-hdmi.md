# 03 · 显示通路：几何、效果链、OSD 与同帧对比、HDMI 输出

本卷只讲一件事：DDR 里躺着的一帧 512×300 RGB565，怎么变成屏上 1024×600 的那幅画，以及这条路上能插进去的所有东西（读口调度、缩放、旋转、双线性、六级效果、同帧 A/B 缝、五
行状态字、TMDS 串化）。

口径三条：① 不碰硬件、不跑工具，数字只有两类来源——代码里的字面量与表达式，或`build/`、`report/`、`data/`里已被跟踪的报告；自己算的写明算式与两个操作数各在哪一行。② 引用
写`文件:行号`，这些行号是本轮逐条 Grep/Read 落到的那一行，同时给关键词，行号漂了就按关键词重找。③ 报告与 RTL 冲突时按 RTL 写，并把冲突本身指出（§5、§10.2、§13 各一处）。

相关的时钟域只有两个：`axi_clk`= PS `clk_fpga_0`100 MHz（`src/rtl/top/system_top.v:214` `DST_HZ`写
`100_000_000`，`:258-259` `fclk0`递成`axi_clk`）；`clk_pix`= MMCM `clkout0`50 MHz（`src/rtl/clocks/clk_gen.v:21`）。
显示通路整体活在 50 MHz 这一域，100 MHz 只负责把帧从 DDR 搬进显示缓存。

## 1 一条时间轴：从一帧到一颗像素

数据流在顶层文件头三行就写死了（`src/rtl/top/pl_video_top.v:2-4`）：`video_timing_1024x600`出时序 →
`axi_frame_writer_gated`/`64`把刚提交的一帧搬进显示帧缓存→`fb_bilin`读口 →`proc_pipeline`效果链 →`split_display`
逐像素混合 →`osd_overlay`叠字→ 同一份 RGB888+同步同时走面板`u_dvi`。

按"站在屏幕前的一拍"排开，每站贡献几拍数得出来：光`u_t`1 拍（`x <= h_cnt`寄存输出，`src/rtl/video/video_timing.v:63`）；视口换算与行提前是
组合、0 拍（`pl_video_top.v:242-243`、`:276-284`）；几何映`u_zmap`3 拍（`src/rtl/process/zoom/zoom_mapper.v:31/42/96`
三个 always）；读口 2 拍（地址寄存 1 + BRAM 1，`src/rtl/process/bilin/fb_bilin.v:39-40`）；效果链 15 拍（`src/rtl/process/proc_pipeline.v:22`）
；OSD 2 拍（`src/rtl/video/osd_overlay.v:4`）。

"内容站在第几拍"不是推出来的，是**量**出来的：顶层把混色级要的列标签深度写成`localparam MIX_D = 3 + 1 + 1 + u_pipe.LATENCY`（`pl_video_top.v:354`），三
个加数是 mapper 的 3 拍、读口地址寄存 1 拍、BRAM 读出 1 拍，代入 15 得 **MIX_D = 20**（本卷按该式子算）；标签桶宽
`SB = (MIX_D > 16) ? (MIX_D + 1) : 16`⇒ 21（`:355`）。`cx`到混色级差一拍，屏上就少一列——第 6 节给出这几处各被哪条判据钉住。

面板档：H 1024+44+88+188 = **1344**、V 600+3+6+16 = **625**（`src/rtl/video/video_timing_1024x600.v:3-4`与
`:17-21`的参数表）。由此场频 50 MHz ÷ (1344×625) = **59.52 Hz**、一帧 **16.8 ms**（本卷自算；`data/metrics.csv`"显示像素时钟"
那行念 59.5 Hz、`sim/tb_v98_top_seam.v`文件头念"一帧 1344×625 拍 = 16.8 ms "，是同一件事的两份记法）。

## 2 读出口调度：一台搬运机、一个读口、两条行环

### 2.1 100 MHz 侧：整帧只在消隐里搬

显示帧缓存是一块 512×300 的 BRAM，不是 DDR。DDR 里那一帧`u_row`（`axi_frame_writer_gated`）`axi_clk`域拉回来，只在"消隐且允许"
那几拍落 BRAM（`src/rtl/axi/axi_frame_writer_gated.v:3-5`）。窗口`frame_commit_lock`给（`pl_video_top.v:430-440`），消
隐判据是顶层那一条`disp_quiet = (y >= 600) && ((y < 624) || (x <= 1279))`（`:397-401`）——
`VB_X_GUARD = 1279 = 1344−65`，早关 64 个消隐像点，因`allow_copy_axi`过 CDC 要晚这个窗口约 5 个像素拍。

这一档塞得下，是可以当场核的算术（式子`pl_video_top.v:392-396`，数字本卷重算）：竖直消隐 625−600 = 25 行 × 1344 = **33 600 个像素拍**；像
素 50 MHz、AXI 100 MHz ⇒同一段时间是 **67 200 个 axi 拍**，正是诊断门`VBLANK_AXI_CYC = 32'd67200`（`:446`）；一帧 512×
300 = 153 600 像素 ÷ 每字 4 像素 = **38 400 个 64 bit 字**（`axi_frame_writer_gated.v:42-43`）；一拍一个字 ⇒ 38 400
< 67 200，余量约 1.75 倍。

搬运节拍：`arlen`固定 15（16 拍 burst）、`arsize = 3'b011`（8 字节）、`arburst = INCR`（`:37-38/:105`），`PIX_PER_BEAT = 4`⇒
一个 burst 交付 16×4 = 64 个像素；最多 4 个 burst 在途（`MAX_OUT = 3'd4`，`:40-47`）；
`TOTAL_BURSTS = 38400/16 = 2400`（本卷`:44`的式子算）。超窗就粘住报警：`copy_overrun`在
`row_done && copy_cycles > 67200`上置位，LED[0] 从心跳`hb[24]`切成快`hb[22]`（`:447-452`、`:1034-1039`；注释念的
1.5 Hz / 6 Hz 就是这两个抽头，本卷按 50 MHz ÷ 2^25 = 1.49 Hz、÷ 2^23 = 5.96 Hz 复算，亮灭各需两次翻转）。

DDR 侧一共三个 bank、全靠地址分开而不是仲裁：ETH 乒`BANK0 = 32'h1000_0000`/`BANK1 = 32'h1008_0000`（`src/rtl/eth/ddr_bank_commit.v:10-11`，间
隔 512 KB）、PS 片源`PS_BASE_ADDR = 32'h1010_0000`（`pl_video_top.v:16`、`system_top.v:144`）；理由写在
`pl_video_top.v:13-15`：仲裁只管"谁用 DDR→帧缓存这台搬运机"、管不到"谁写 DDR "（SD 的 DMA 走 PS 的 HP0、不经过 PL）。

### 2.2 50 MHz 侧：一个读口、一拍一次、每源像素用满 4 拍

读口`fb_bilin`（`pl_video_top.v:732-750`），地址级只有一条线（`fb_bilin.v:34/42-45/56`）：`pxl = sy*IMG_W + sx`⇒
`w_a = pxl[18:2]`（64 bit 字下标）、`lane = pxl[1:0]`、`w_b = w_a + ROW_WORDS`（`ROW_WORDS = IMG_W/4 = 128`）、`addr_nxt = (row0 ? w_a : w_b) + (col0 ? 17'd0 : 17'd1)`。
四个槽位`(row0,col0)`决定：(1,1)→A、(1,0)→A+1、(0,1)→B、(0,0)→B+1（`:37-38`）。

这两个相位量在顶层**必须`sx/sy`同一级**，接的是`~x_d[2][0]`/`~y_d[2][0]`/`y_d[2][1]`（`pl_video_top.v:744`）——那个" 2 "
`tb_v98`自带的级数标定量出来（样本 822 555，k = 0 全错｜k = 1 错 412 166｜**k = 2 错 0**｜k = 3 错 410 389，`:739-743`）；第一版接
的`[3]`，代价是屏上四分之一格子错列。

"一次读几列"的答案：**一拍读一个 64 bit 字（= 4 个源像素挤在一个字里），一次只用其中一个`lane`**。不浪费是因为 ×2 展开让一个源像素天然占 2 显示列 × 2 显示行 = 4
个 50 MHz 拍（`fb_bilin.v:4`），四条读命令刚好把一个读口排满，全程不进 250 MHz 快域。`lane == 3`是唯一特殊情形——右邻抽头跨到下一个字，所以每个请求都多发一
`A+1`（`:140-141`、`tap_sched.v:18`）。

资源账。帧缓存 **80 块 RAMB36**（`build/util_hier_probe.rpt:59`）：`frame_buffer_w64`把非 2 幂深度的 38 400 字拆成 32
768 + 8 192 两块（`src/rtl/video/frame_buffer_w64.v:32-35`），每块 64 bit 宽按 32 bit 分两个 plane 落进 1024 深的
RAMB36 ⇒ 32768/1024×2 = 64、8192/1024×2 = 16，合计 **80**（本卷自算）；深度为什么必须 2 的幂写在`frame_buffer_w64.v:4-7`（直
接声明 38 400 深会被向上填充成 2^16，实测吃 128 块而全片只有 140）。原图那条环 **4 块**（本卷自算：8192×17 bit ÷ (2048×18) = 4；参数
`RLOG`/`CWID`/`DEPTH` 三行 localparam 的原文 `CWID = clog2(W)`、`DEPTH = (1 << RLOG) * W`（`src/rtl/video/raw_line_delay.v:42-43`）；该文件 :39 写明 LINES=4 ⇒ RLOG=3，代上顶层传的 1024 列即得 CWID=10，那两参数是 `W = 2*IMG_W = 1024`、`DW = 17`
`pl_video_top.v:781/788`）。全片合计 95.5 tile = 93 RAMB36 + 5 RAMB18 折半（`build/utilization.rpt:106-110`）。
`fb_bilin`自己那 2 块 RAMB18（`util_hier_probe.rpt:57`）也对得上：`tap_hold`512×32 ⇒ 512×36 模式一块，`res`1024×
17 ⇒ 1024×18 模式一块（`fb_bilin.v:142/184`）。

### 2.3 两条行环，和 lane23 那条"读回来"的路

行环解决的是"内容不能提前，只有地址能提前"。这里**有两条**，别混。①`u_bilin`里的乒乓结果缓`res[0:2*IMG_W-1]`，半号 =`pair_odd = y[1]`，写
"本对"读"上一对"（`fb_bilin.v:179/184-191`），代价是内容整体晚 1 对显示行 = 2 显示行 = 2×1344/50 MHz =**53.76 µs**（`:182-183`）。
②`u_raw`=`raw_line_delay`，把**原图抽头**整体延后`RAW_LINES = u_pipe.OFF_LINES`= 4 个显示行（`pl_video_top.v:781/788-792`），写
槽 =`y`的低 3 位、读槽 =`(y−LINES) mod 8`（`raw_line_delay.v:55-56`）⇒ 延迟恰好 4 行 + 1 拍、**列不偏**。

第 2 条为什么必须有：右窗读地址带`cy_r = (y+OFF+2)>>1`的提前量（`pl_video_top.v:276-284`），那笔账是替效果链的行滞后付的；原图抽头不欠这笔账，所以
要么另开一个读口、要么把它延回来。另开读口的代价实测过：第二个逻辑读口把帧缓存从 80 块顶到**160 块 RAMB36，而全片只有 140**（`fb_bilin.v:180`、`tap_sched.v:10`
各写了一次同一个数）。于是选了延后。

环不`line_cache`串起来的：第一版就是串级，`sim/tb_v100_raw_delay.v`当场打掉——串 N 个 = 延后 N 行**又**多花 N 拍 ⇒ 列偏 N 格，而这
种错在模块级台架看不见（`raw_line_delay.v:6-7`）；环深`2^RLOG ≥ LINES+1`⇒`mod`就是切位，不留运行时除法（`:37-41`）。还有一处只属于环的坑
（#102）：多出的那 1 拍在行首会越过消隐——一行 1344 拍而有效列只 1024，尾部 320 拍`x[9:0]`从 0 数到 319，而 RAM 读出的是**上一拍发出去的那个地址**⇒ 下一行第一个有效列摆的恰好是消隐期最后那个格子（台架读数源列 160 = 显示列 320 那一格，定义要源列 0），一帧 600 行、行行有一格。做法是`de`刚掉下去那一拍做一次预读、锁进
`head_q`，输出只`de && x== 0`选它（`:58-76/95`）；两种"看起来更简单"的办法被点名否决（读出再打一拍 ⇒ 每列推后一格；消隐期地址钳 0 ⇒ 帧头那一行仍错一行，因
`V_TOTAL = 625`不是环深 8 的整数倍，`:77-79`）。

**`lane`这个词在本工程有两个意思**，读代码必须分清。其一是帧缓存字内的车道：`lane = pxl[1:0]`，一个 64 bit 字里四个 RGB565 之一（`fb_bilin.v:44`、`frame_buffer_w64.v:66/72-79`）。
其二是可读回状态的通道号：PS 先`gpio_o[31:27]`选 lane，再`GPIO_1`读那一条 32 bit（`system_top.v:206-208/219/237-247`）。
lane0..9 是链路健康快照（`src/rtl/eth/link_monitor.v:186-196`：lane0 丢字总数、lane1 {坏包,作废帧}、lane8 包数、lane9 字节数），lane24..29
是链路内时延，lane30 是片源仲裁，lane31 是时基生死。

**lane23 就是"当前倍率与来源"那一条**：`system_top.v:241` `lm_lane == 5'd23`接到`dbg_zoom`，位序的唯一出处在
`pl_video_top.v:679-688`——bit31 像素时基活着、**bit19 = 拟合生效**（`split_ctl[18] | z_bus_axi[19]`）、bit18 手动旗标、bit[17:15]
档号、bit[14:12] OSD 的"最近一档"、bit11 是否在缩放、bit10 呼吸方向、bit[9:0] **`inv_used`**（真正喂给 mapper 的那一个，不是
`inv_scale`，`:1044-1049`）。为什么要这条口：GPIO 读回来`zsel/zman`只能证明" PS 写了那一位"，证明不了 13 级同步链把它送到了像素域、更证明不了据此
算出的倍率是对的（`:646-649`）。于是有两条可机器判定的等式：`zsel = i`⇒ 像素`inv_scale == TBL[i]`；屏`Zoom:`那一格与同一帧在用的
`inv`同档。打包走准静态总线 + 帧首发布（`zoom_snap.v:5-7/36-44`：总线只`frame_start`整拍换、发沿再往后推 8 个像素周期），两条不变量由
`sim/tb_v95_zoom_snap.v`逐周期验。`bit19`必须有，否则一次正常拟合会被上位机读成"档位错乱"——那是尺子先错（`:683-687`）。

## 3 缩放：三颗 DSP48 定档，八颗 DSP48 逐像素映射

### 3.1 八档定点倍率，尺度是 Q8 倒数

约定：`inv_scale`是 **Q8 倒数**、`256 = 1.00x`、**inv 越大画面越小**（`zoom_ctrl.v:3-4`），倍率 = 256/inv。八档表（`zoom_ctrl.v:40-56`）
与倍率（末列本卷算）：档 0 = 0.25x/inv**1023**/0.2502、档 1 = 0.33x/776/0.3299、档 2 = 0.50x/512/0.5000、档 3 = 0.75x/341/0.7507、档 4 = 1.00x/256/1.0000、档 5 = 1.33x/192/1.3333、档 6 = 1.50x/171/1.4971、档 7 = 2.00x/128/2.0000。
`0.25x`写 **1023 而不是 1024**：`inv_scale`只有 10 bit，1024 会回绕成 0，画面上变成"无限大"而不是 0.25x（`:44-46`）。档位名的整数写法
`25 33 50 75 100 133 150 200`（`ZOOM_X100`）记`data/metrics.csv`"缩放范围"那一行。

呼吸只`[INV_LO, INV_HI] = [256, 512]`即 1.00…0.50 里走，手动档允许到 2.00x/0.25x：mapper 是**逆**映射，inv 变小只是采样窗收进
画面内部（不越界）、inv 变大四周填黑，两种都不动 mapper（`zoom_ctrl.v:38-39`）。

### 3.2 三种来源与判据

`inv_used`只有一个表达式（`zoom_ctrl.v:64-74`）：`inv_raw = fit_en ? inv_fit : inv_scale`；
`rot_clamp = rotate_en && (inv_raw < inv_fit)`；`inv_used = rot_clamp ? inv_fit : inv_raw`；
`rot_forced = rot_clamp`。四条路径各自是：

- **自动呼吸**：`enable`（=`zoom_run`，`pl_video_top.v:222`）为 1 且非手动时，每帧首`STEP = 2`地在 [256, 512] 之间走三角波、方向位
`dir`记账（`zoom_ctrl.v:112-137`；参数在`pl_video_top.v:325`）。手动档可能把画面停在呼吸带之外，切回自动时**朝带回里走**、不许瞬移（`:114-119`；
 原来 1023 → 512 一帧跳掉半幅，用户看到的就是"画面弹一下"）。
- **手动**：`manual`来`gpio_cfg1_o[29]`、档`[28:26]`（`system_top.v:268`），与呼吸同一个节拍、**只在帧首换**，一帧之内不会半屏新一档
 （`zoom_ctrl.v:105-111`）。
- **Fit（`zoom fit`）**：倍率由角度定，整`inv_scale`链被旁路但**不写它** ⇒ 关掉拟合时呼吸/手动从原位接着走、不跳档（`:96-100`）。
- **旋转钳（#93）**：旋转态不许放大到画外，取"用户那一档"与"这个角度刚好装得下那一档"里画面较小的那个（inv 大 ⇒ 画面小 ⇒ 取较大 inv）。代价两条写进口径：① 旋转态不提供放大，1.33/1.5/2.0
 三档被拉回 fit；② **0° 不在钳之内**，因为顶层递`rotate_en`就是`angle_ctrl.v:18` `rotate_active = (angle != 0)`（`zoom_ctrl.v:65-72`）。
 mux 必须在`zoom_ctrl`里做而不在顶层再 mux 一次，否则会出现"屏上那一格与真正在用的 inv 不是一回事"（`:15-21`）；这一位同时参与 OSD `(Fit)`（`pl_video_top.v:1011`）。

`zoom_code`（OSD 的"最近一档"）不查倍率、只比大小：`inv_used`与**相邻两档的中点**比，7 个常数 900/644/427/299/224/182/150（`zoom_ctrl.v:76-83`）。
这七个数本卷能复算：(1023+776)/2 = 899.5→900、(776+512)/2 = 644、(512+341)/2 = 426.5→427、(341+256)/2 = 298.5→299、(256+192)/2 = 224、(192+171)/2 = 181.5→182、(171+128)/2 = 149.5→150（表值取自`:44-53`）。表值代回自己那一档必然落在自己区间里——这不是巧合，是台架判据
`sim/tb_v94_zoom_sel.v`逐档`code(TBL[i]) == i`（`:36-37`）。

### 3.3 `zfit`：3 颗 DSP48 算"刚好装得下"

几何式`src/rtl/process/zoom/zoom_fit.v:3-7`：视口 = 未旋转外`IMAGE_W × IMAGE_H`，转 θ、倍率 s 之后
`W' = s·(W|cosθ| + H|sinθ|)`、`H' = s·(W|sinθ| + H|cosθ|)`；要`W' ≤ W`且`H' ≤ H`，`inv = 256/s`写开就是
`inv_x = (W·C + H·S)/W`、`inv_y = (W·S + H·C)/H`，取**较大者**。RTL 里没有除法器（#58 那一课：100 MHz 域的组合除法器把 WNS 打到
−5.014，`:26`），`/W`、`/H`折成"乘一个 elaboration 常数 + 定长移位"（`zoom_fit.v:11/29-33/44-50`）：`REC_W = ((1<<20) + (512>>1))/512`= 1048832/512 = 2048.5 → **2048**、`REC_H = ((1<<20) + (300>>1))/300`= 1048726/300 = 3495.75 →
**3495**、`nx_c = 512*C + 300*S`≤ (512+300)·256 = 207 872 < 2^18、`ix = (nx*REC_W) >> 20`、`fit_raw = imax + (imax>>8) + 2`。

**代两个角度自算**（本卷算，操作数全在上面那几行与三角表里）。θ = 0°：C = 256、S = 0 ⇒nx = 131 072、ny = 76 800 ⇒ ix = 131072×
2048/2^20 = 256、iy = 76800×3495/2^20 = 255.98→255⇒ imax = 256 ⇒`inv_fit`= 256+0+2 = **258**，正好落进
`sim/tb_v100_fit_rot.v`的 T2b 窗口" 0° 要求 256 ≤ inv_fit ≤ 259 "。θ = 45°：C = S = 181（`src/rtl/process/rotate/sin_rom.v:54`、`cos_rom.v:54`）⇒
nx = ny = 512×181 + 300×181 = 146 972 ⇒ ix = 287.06→287、iy = 489.87→489 ⇒ imax = 489 ⇒`inv_fit`= 489+1+2 = **492** ⇒ 倍率 256/492 = 0.5203，而理论界是 300/(0.7071×812) = 0.5225，多缩的 0.4 % 就是那口余量。

余量为什么是这么大：Q8 三角表每项最多差 0.5 LSB ⇒ inv 最大`(W+H)/2/H ≈ 1.35`，`(imax>>8)+2`稳过它，而在 0°/90°（表精确）只多缩 3/256
≈ 1.2 %、屏上 6 个源列，看不见（`:48-50`）。输`inv_fit`是寄存器、**比角度晚两拍**：第一拍只算分子，第二拍做乘常数+移位+取大+余量（`:34-43`）——r60
实测一拍做完是 15 级、含两个 DSP48、slack 只剩 +1.843 ns（全设计第三差）。资源：`u_zfit`占 **3 颗 DSP48**（`build/util_hier_probe.rpt:80`）。

## 4 旋转：为什么只能走逆映射

### 4.1 为什么不是前向散布

前向散布（把源像素画到目标位置）在硬件里三件事同时坏：目标栅格会留洞（补洞就得再遍历一遍）、同一目标像素会被多个源像素写（要么写冲突要么做 atomics）、而且**目标侧永远不知道当前这一拍该出什么**
。本工程的显示通路是**光栅驱动**的：`u_t`每拍给`(x,y)`，混色级必须在**同一拍**交出一颗像素，晚一拍就是错列，所以只能问"这个显示格该取哪个源格"，也就是逆映射——
`zoom_mapper.v:2`的标题就是"右屏无极缩放逆映射：屏幕 (x,y) → 源图 (sx,sy) "。代价换来的是：源图越界的格子天然回答"没有" ⇒`oob`一位填黑（`:103-106`）。

同一个理由决定窗滤取窗的位置：四个窗口级在**目标域**建行缓存，所以旋转开着时模糊/Sobel 算的是屏上那张图而不是源图（`proc_pipeline.v:37`的
`rotate_active`只作状态用；`report/rotation_and_effects.md`§2 把这条写成四步流程）。这条纪律有台架：`sim/tb_rotate_window.v`
判"旋转不许把效果链强制旁路"。

### 4.2 角度从哪里来、量化单位是多少

`angle`是一个 9 bit 的**十进制度数**、0..359，不是 Q 格式的角度编码（`angle_ctrl.v:15`；`osd_overlay.v:32`明写"度（0..359：angle_ctrl
里就是十进制度数，不用换算）"），所以**角度量化单位 = 1° 一档**；三角表的量化是另一件事（§4.3）。

- KEY1 短按 +1°、KEY2 −1°、到界回绕（`angle_ctrl.v:39-42`）；短按改在**松手时**发，否则每次长按必先进 1°（`pl_video_top.v:144-150`；
`key_long` `HOLD_CYC = 30_000_000`、`ARM_CYC = 10_000_000`⇒ 50 MHz 下 0.6 s / 0.2 s，`:148`）。串口
`rot ...`走几何控制字（`system_top.v:274-275`的拼字）。
- 自动旋转：`gp[14] = rot_auto`开、`gp[17:15] = rot_speed`是**度/帧**、0 = 开着但不走（`pl_video_top.v:176-177`、`angle_ctrl.v:43-44`）。
 一帧最多走 7°，360 = 7·51 + 3，所以取模用"减 360 "而不是"到 359 就回 0 "，否则每圈在回绕处丢几度（转速快时肉眼看得出那一顿，`:31-34`）。
- 跨域与拍点：`angle_ctrl` `sys_clk`（50 MHz 输入钟），换角事件`clk_pix`用**翻转位**跨过来（`angle_ctrl.v:20-29`）。拍点在
 r109 挪过：不`frame_start`，而在"最后一个不绕回的行（今天 = 593）的行尾消隐"（`pl_video_top.v:286-314`）。为什么：屏上最上面 6 个显示行（`OFF_LINES 4 + BILIN_ROWS 2`）
 的内容是在上一帧的绕回请求行取回来的，挂帧首换角 = "帧头 6 行吃上一帧的角度、其余吃这一帧的"。行尾那一拍之后到第 594 行第一个像素之间是整段行消隐 1344 − 1024 = **320 拍**
（本卷自算，操作数`video_timing_1024x600.v:17-21`），那三级同步赶得上。眼睛那一半已`board/ACCEPTANCE.md`的 **E4r** 对上（动起
 来才有顶部分散细线、角度停住就干净），量大小的`sim/tb_head_rot_displace.v`。

### 4.3 坐标变换的式子与位宽

三角表是 Q8：`round(sin(θ°)·256)`、10 bit 有符号、360 项组`case`（`sin_rom.v:2-5`；抽查 sin45 = 181`:54`、sin90 = 256`:99`、sin270 = −256`:279`）⇒ 量化误差是 ±0.5 LSB = ±1/512 ≈0.002 的函数值误差，`zoom_fit.v:27`把它写成" Q8 三角表本
身 ±0.5 LSB 的量化误差"。

`s0`中心偏移 + Y 翻转（`zoom_mapper.v:31-36`）：`xp <= {1'b0,x_in} − IMAGE_W/2`（即 x − 256，13 bit 有符号）、`yp_math <= IMAGE_H/2 − {1'b0,y_in}`（150
− y，数学系）、`yp_disp <= y − 150`（不旋转时用这条）。`s1`只有旋转支需要乘加（`:46-51`，符号位复制到高 11 位后相乘）：

```
xr_m = xp·cos_v + yp_math·sin_v
yr_m = −xp·sin_v + yp_math·cos_v
```

这就是"把目标点反向转 θ"（等价于图像正向转 θ）。位宽账（本卷算）：|xp| ≤ 256、
|yp_math| ≤ 150、|C|、|S| ≤ 256 ⇒ |xr_m| ≤ 256×256 + 150×256 = 103 936，`xr_m`声明 25 bit
有符号，宽裕。`s2`缩放 + 定点回位（`:58-66`）：`rot_xs = xr_m*inv; xr_pix = rot_xs >>> 16`，`raw_xs = xp_s1*inv; xs_pix = raw_xs >>> 8`。
两个移位量不是随手写的：旋转支是"转一次（×256）+ 缩一次（×256）" = ÷2^16，非旋转支只缩一次 = ÷2^8。取整方向必须`>>>`（朝 −∞），因为低 8 位要被当小数用："
`>>> 8`是朝 −∞ 取整，余下的低 8 位正好是 [0,1) 的小数 ⇒`x_out`与`frac_x`指的是同一条数轴上的同一格（换`/256`+ 取余就会在负数上错一格）"（`:90-92`）。
最后加回中心、判越界（`:68-69/87-88/103-115`），越界`x_out/y_out`清 0、`oob`置 1、小数清 0。

旋转支的小数要连着翻符号一起改（`:70-88`，#104/#189）：`Y_disp = C − Y_math`而`Y_math = yr_pix + f/256`，所以
`Y_disp = (C − yr_pix − 1) + (256 − f)/256`（`f ≠ 0`时）。
#189 的修正是判"有没有小数"必须看**完整的 16 位**小数：真小`f = rot_ys[15:0]/65536`，显示侧
权`256 − ceil(f·256)`，`f ∈ (0,1/256)`时 ceil 恰为 1 ⇒ 权重 255 且**必须**减那一格；原来两半都错，症状是沿角度方向的稀疏"错一行"鬼影，实测
发生率 ≈ 0.27 %（台架扫 3726 个像素命中 10 个，全错，`:76-80`）。

独立模`rotate_mapper`**今天没有例化者**（第 13 节），它保留的算式是`xs = ((xp·C + yp·S) >>> 8) + W/2`、`ys = H/2 − ((−xp·S + yp·C) >>> 8)`（`src/rtl/process/rotate/rotate_mapper.v:40-43`），即
"只转不缩"，`zoom_mapper`的旋转支同族。

## 5 双线性插值：四个抽头、两级 lerp、一次折回

`(sx,sy)`是整数部分、`(fx,fy)`是 Q8 小数（都来`zoom_mapper` `x_out/y_out/frac_x/frac_y`）。四点是
`p00= (sx,sy)`、`p10= (sx+1,sy)`、`p01= (sx,sy+1)`、`p11= (sx+1,sy+1)`（`bilin_lerp.v:11-14`）。取这四个字用的还是**同一个
读口、四条读命令**（`fb_bilin.v:56`：`w_a`/`w_a+1`/`w_b`/`w_b+1`）。A 行凑齐那一拍写进抽头暂`tap_hold`（512×32，地址是**显示列对号**
`jd = x[9:1]`而不是源`sx`：旋转时一条源图线在 x 方向会停滞甚至倒退 ⇒ 同一`sx`在这一行里被**另一个源行**重写 ⇒ 满屏噪点；`:136-153`、`pl_video_top.v:745-747`）。
B 行凑齐那一拍`u_lerp`。

权重就`wx0 = 256 − fx`、`wx1 = fx`，`wy0/wy1`同形（`bilin_lerp.v:29-30/51-52`）。RGB565 展到 8 bit 用**位复制**不是
左移补零：`rep5 = {v, v[2:0]}`、`rep6 = {v, v[1:0]}`⇒ 全 1 展开正好 255，纯白不会因展开变灰（补零的话 0x1F→0xF8）（`:20-26`）。

位宽账（本卷`:39-61`的表达式算）：横向最`255×256 = 65 280`⇒ 17 bit（`tr/tg/tb/br/bg/bb`声`[16:0]`）；纵向
`65 280×256 = 16 711 680`，加舍`+32768`⇒ 16 744 448 < 2^25 = 33 554 432 ⇒ 25 bit，与文件头"纵向 ≤ 255×65536 + 舍入 = 25 bit "一致（`:6-7`）。右移 16 后≤ 255.5 ⇒`vr = or_r[24:16]`，`[7:3]`回 5 bit（`:59-67`）。舍入只做一次，就在纵向合
并后。**为什么不需要饱和**：两两权重之和恒为 256（`wx0 + wx1 = 256`），这条恒等式同时是台架判据 2 的内容——四角同色 ⇒ 输出恒等，`sim/tb_bilin_lerp.v`
强制检验它（`:6-7`）。

算术核里的乘加表达式一共 9 条（横向 6 条 + 纵向 3 条，形式都`a*w0 + b*w1`，展开 18 次乘法）；
`src/rtl/process/bilin/fb_rd5x.v:7-8`自述"插值的 12 个乘法留在慢域（`bilin_lerp`两级流水），快域 4 ns 塞不下"。**工具把它折成几颗**
有唯一答案：`u_lerp`在实现报告里是 **6 颗 DSP48**（`build/util_hier_probe.rpt:60`），逐颗映射关系报告里没有、本卷不猜。`bilin_lerp`自己
声明两级 ⇒ 输出在输入那拍之后第 2 拍，`fb_bilin`因此`assemble`也延两拍（`:164-169`）；模块级不声明 LATENCY，由
`sim/tb_v101_fb_bilin.v`用唯一平移量搜索量出来并钉住（`:194-195`）。

边界两类，处理不同。**画面外**（缩小后四周空边、旋转切角）`zoom_mapper` `oob`决定，随像素一起过乒乓缓冲，最后在混色级填黑（`pl_video_top.v:772`、`split_display.v:48`）
；标签与像素"同一次写、同一拍读 ⇒ 天生同级"（`fb_bilin.v:197-198`）——这一句很重要，#92 第三笔就是标签绕开环只走等长 skid，到混色级差 (4 行, 1 列)，于是画面
右沿最后一列被"别的格子"的越界位按黑（`pl_video_top.v:782-785`、`raw_line_delay.v:11-16`）。**末行/末列** `+1`抽头落在图外：只做"把小数
钉 0 "是**不够**的，末行那`w_b = w_a + ROW_WORDS`会读到帧缓存的**填充区**——硬件里是 BRAM 上电的 0、xsim 里是 X，而 X×0 = X ⇒ 整行被
污染；所以抽头本身要**折回图内**（`fb_bilin.v:46-54`）：`kx_use = !bilin_en || sx >= IMG_W-1`，折回`p10→p00`、`p11→p01`、`p01→tap_r[15:0]`。
`bilin_en = 0`走同一道钉子 ⇒ 本模块逐位等于最近邻，板上 on/off 来回切不需要重新构建（`:48`）。

**「某一级有没有真的生效」是怎么被检查的**：这是本工程一个反复出现的动作：**不信任"接口上写了这一位"**。双线性开关`gpio_o[19]`→ 3 级同步 →`bilin_en_pix`，复位默认取 **1** ⇒ 上电画面与它是
`localparam`常量那一版逐位相同，"加了口子但观感不变"可查（`pl_video_top.v:251-262`）。旋转支的小数位：#104 之前`frac_x/frac_y`在旋转那一支
被钉 0，于`bilin on`在旋转态是**空头支票**（`zoom_mapper.v:70-72`），尺`sim/tb_zoom_frac.v`的覆盖点就直接写成"旋转态到底有没有非零
小数"。效果链某级到底有没有算：`tb_v86_pipe_sel`的 T5 逐档实测拍数、`tb_v89_align`判"旁路下像素里带的坐标与台架数出来的输出位置之差是否恒为一个固定值"。还有一
条更狠的：`split_ctrl`文件头写着"本模块目前没有被任何顶层例化"（`src/rtl/video/split_ctrl.v:3-6`），而`pl_video_top.v:885`现在确实
例化了`u_split_ctrl`——那句注释是 ISSUES #62 时期的话、已被 r59 那一轮推翻。**注释会说谎，例化不会**，这条口径本卷全程照用。

## 6 几何正确性的判据：两端夹逼与"缝两侧当场可见"

`sim/tb_zoom_fit_corners.v`（161 行）是 E4/#93 的机器替身，判据只有两条、必须成对。**A 装得下**：`zoom_fit`给`inv_fit`，把整个
显示窗 512×300 = 153 600 格喂给`zoom_mapper`，源图四个`(0,0) (W-1,0) (0,H-1) (W-1,H-1)`每一个都必须被某`oob = 0`的
显示格取到，判"离角点 ≤ 1 格"。**B 正对照（这条必须能红）**：倍率放大一档（`inv = inv_fit − 1`）⇒ 旋转框溢出视口 ⇒ 至少一个源角**不再**被任`oob= 0`
的格取到；B 不成立就说明 A 是恒真的摆设（"空判据恒绿"那一族）。覆盖地板同样印出来：`swept == W*H`、`live > 0`、A 每角命中几个、B 每角掉几个（`FAIL floor_swept angle=<a> swept=<n>expect= 153600`）。

为什么强调"只用 DUT 自己的输出"：2026-10-01 23:15 有人在 RTL **外面**用 node 建模判"角点出屏"，报了个假阳性——错在用的格心/格角约定与 RTL 不一致（差半格
到一格），所以这台架只用`x_out/y_out/oob` `inv_fit`，不重算映射、不抄第二份真值。同一套规矩在`sim/tb_head_rot_displace.v`的
D1/D2/D3 上复用（D1 同角度扫两遍必须逐位相同、D2 k ≥ 1 必须至少一格移 ≥ 1 个源像素、D3 地板不许空判）；`sim/tb_v100_fit_rot.v`则是"尺子与 DUT
不共用算式"——`zoom_fit`用乘常数 + 移位，台架用交叉相乘（`hav*IW >= 512*bC + 300*bS`）判同一件事、一次除法都不做。

### 6.1 为什么几何错误在缝两侧当场可见

同帧 A/B 缝把原图与处理图并排放在**同一帧的同一时刻**（`pl_video_top.v:911-928`、`report/technical-document.md`§3.5）⇒ 任何"只错
一点点、而且是系统性错位"的几何问题，都会在缝的两侧留下**同一行同一列的两种答案**，眼睛不必比较两帧。三类典型表现，每条在本仓库里真实红过。

1. **整列错位（差 N 拍）**：原图那一路 = 行环（4 行 + 1 拍）+`orig_skid`（15 拍）= 16 拍，而链子只`PROC_LAT = 15`拍 ⇒ 处理抽头比原图抽头
**早一整拍 = 早一整列**。1.00x 时画面铺满整屏看不出来；一缩小，左边界就把"画面自己最左那一列"甩进背景带、右边界少一列（`pl_video_top.v:819-824`）。凭据
`tb_v98`的 C1c（原图抽头`x_d[MIX_D]`同级）与 C2——在`inv = 512` `inv = 1023`两档都量到"内容左右沿 = 定义左右沿 − 1 "，**恒
 为一列、不随倍率变** ⇒ 是整拍之差，不是取整偏差。
2. **标签比内容旧（暗带）**：`split_display`曾用第 11 级`x`判左右窗，而两个像素抽头是第 20 级的内容 ⇒ 判定比内容旧 9 列（20 − 11 = 9，本卷按
`split_display.v:9-14`给的分解算）。结果：缝左边约 9 列里"标签说左窗、内容其实是右窗那一路（被强制清 0）"⇒ 选中的是 0 ⇒ 一条近黑的竖带。今`x_sel`与
`x`都`MIX_D`那一级（`pl_video_top.v:919-921`），而"只有一个流"之后这一族结构上消失（`:769-771`）。凭据 C1i 与 C9a/C9b/C9c/C9e
 ——C9a 判"没有整列近黑"、C9b 判"确实有整列是亮的"，没有 C9b 则 C9a 的那个 0 可能只是探测器瞎了（`sim/tb_v98_top_seam.v:1212-1213`）。
3. **少一列 / 边缘条带**：行缓存式 3×3 的中心抽头`p11 <= p12 <= 行缓存读`⇒ 当拍读到的那一格要再跳一拍才成为中心，而移位整个`de_in`钉住 ⇒ 行内最后一个有
 效像素读完、下一拍就是消隐，那一跳永远不来 ⇒ 每行少发一个样本，而输出流仍`de_out`数够格子 ⇒ 最后一格只能重复前一列（`src/rtl/process/proc_box_blur.v:25-28`）。
 这是 #92 第四笔，凭`tb_v89_align`的 ID 判据（四级 + 整链全中，`first col= 31 dc=-1`）。同族另两条：拍 k 武装的边界旗标落在**槽位 k+1**、行
 尾补跳那一拍武装的旗标落在**下一行第 0 槽** ⇒ 第 0 列被旁路成原图直出 = 左边一条带；中心行 = 输入行 − 1 ⇒ 每帧第一个输出槽吃的中心是上一帧的末行 = 上边缘那条带（`proc_box_blur.v:54-59`，这
 一段是四个窗口级的正本，其余三处指回来）。

一条与生俱来的纪律（#54/#56）：**任何拿每拍计数器与"第 0 列/末列"比的判据，换一种消隐宽度或占空比就会挡住不同的列** ⇒ 台架与板子给出两个不一样的答案。所以
`split_ctrl`的扫描计数按`de`走不按拍走（`split_ctrl.v:64-72`），四个窗口级的行尾判据"只数连续有效像素"（`run == H_ACTIVE`），既不用
`>=`也不用第二拍（`proc_box_blur.v:29-37`）。

## 7 效果链：六级、九位控制字、逐段位宽

`stage_sel`是 **9 bit，一位一个算法**（端`proc_pipeline.v:31`，位定义在文件`:5-6`）：`[0]灰度 [1]反色 [2]3×3 模糊 [3]3×3 锐化 [4]Sobel [5]二值化 [6]判决反相（仅 [5]= 1 有意义）[7]腐蚀 [8]膨胀`。
级序 gamma → 颜色 → 滤波 → 边缘 → 阈值 → 形态学，**九位逐位直连、不留第二条兜底口径**（`:50-61`；两套口径并存时同一个设置就有两种答案）。九位对六级不是 1:1：级 0
只有 gamma（使能是独立一`gamma_en`），级 1/2 各两个互斥选项但物理串联，级 3/4 各一个（级 4 多一个反相位），级 5 是腐蚀/膨胀两位。

**腐蚀与膨胀同属最后一级、且互斥**，代码里核到（`proc_pipeline.v:59-61`）：

```verilog
wire w_erode = stage_sel[7] & ~stage_sel[8];
wire w_dilate = stage_sel[8] & ~stage_sel[7]; // 两位同时为 1 时两个都不做
wire [1:0] morph_mode = w_erode ? 2'd1 : (w_dilate ? 2'd2 : 2'd0);
```

为什么两位都置 1 要显式旁路：开/闭运算要**两遍** 3×3 窗口，这里只有一遍，所`mode == 3`也当旁路，代价写`proc_morph.v:22-24`而不是藏在 mux 里。
OSD 那一格必须跟着这个语义：两位同时为 1 `Pipe`的第五位给 **0** 而不是 3——"给 3 就是屏上写着两个都开、画面上什么都没发生"（`osd_overlay.v:139-142`）。
`report/technical-document.md`§3.4 念的是同一条（并把出处写成`proc_pipeline.v:59-60`）。

- **灰度**：`r8 = {r5,r5[4:2]}`等三路展到 8 bit，`y16 = r8*77 + g8*150 + b8*29`，取`y16[15:8]`，写回
`{y8[7:3], y8[7:2], y8[7:3]}`（`proc_gray.v:14-24`）。系数和 77+150+29 = **256**（本卷加）⇒`>>8`就是归一化、最大
`255×256 = 65 280`装进 16 bit 不需饱和；这是 BT.601 的 0.299/0.587/0.114 的定点化。
- **模糊**：三通道各自九点和，`rs`最`31×9 = 279`（10 bit）、`gs`最`63×9 = 567`（11 bit），`×57 >>9`：57/512 = 0.111
 328 对 1/9 = 0.111 111，相对误差 +0.195 %（本卷自算，式子`proc_box_blur.v:103-120`）。平场自校验：九点`279×57 = 15 903`，取
`rp[13:9]`即 15903/512 = 31.06 → 31 ✓ 恒等。这也`u_blur`在整链里唯一带 DSP 的原因（`util_hier_probe.rpt:69`，DSP = 1）。
- **锐化**：Verilog 的无符号减法会回绕，所以**先比较再相减**：`r_c = 5·中心`、`r_n = 四邻和`、`r_d = (r_c > r_n) ? r_c − r_n : 0`，再
 夹`[0,31]`（`proc_sharpen.v:88-108`）。直`a-b`再判负的表现是"暗边变成一圈亮边"。
- **Sobel**：`Gx = −p00 − 2p10 − p20 + p02 + 2p12 + p22`、`Gy`同形纵向（`proc_sobel.v:111-114`）；范围 ±1020（本卷算：4
 ×255）⇒ 11 bit 有符号刚好；`mag = |Gx|+|Gy| ≤ 2040`⇒ 12 bit，夹到 255 写回 565（`:115-119`）。输出是白边黑底。旁路必须取"窗口中心抽头
 的**原色**"而不`din`（`:145-150`）——以前`dout <= din`，本级自己是对的，但整链里它一个人不跟随行约定，代价是开 Sobel 时画面跳一行 + 2 列。
- **阈值 / 形态学**：级 4 与级 5 用**同一个亮度式子、同一对白/黑** ⇒ 级 4→级 5 视觉上只有形状在变（`proc_binary.v:16-25`、`proc_morph.v:26-34`）。
`pol`（`stage_sel[6]`，`src/rtl/process/proc_pipeline.v:58`）是判决反相位，"同一级的第二个算法，不额外占硬件"（`proc_binary.v:4`）。形态学的掩码只存 1 bit/像素，两条掩码行缓存 = 512
 bit×2，另加**一条** 16 bit 行缓存只为旁路能还原原色（`proc_morph.v:5-7`）。

两个必须记住的写法陷阱。其一（`proc_morph.v:36-39`）：存储器**必须**写成`reg mb0 [0:H_ACTIVE-1]`（每元素一格），写成
`reg [0:H_ACTIVE-1] mb0`（一根 1024 位向量，`mb0[x_in]`变成按位取值）就推断不出 RAM，综合报
`Synth 8-7186 ... using registers`⇒ 两条掩码行缓存变成 2×H_ACTIVE 个触发器、两个异步读口各变成一棵 1024:1 的 LUT 树（r83 之前它就是这个
状态，凭据是该注释点名那份 r80 的构建日志没随包留下）。其二：`mc1`的读是**异步**（组合读出），BRAM 做不到 ⇒ `ram_style="block"`只会被判
`Synth 8-6849 infeasible`再退回 LUTRAM（`:42-44`）。此外四个窗口级都把"复位只能写在这**一个**块里"写在旗标旁边（`proc_box_blur.v:66`）：同
一根寄存器分给两个进程 =`Synth 8-6859/8-6858 multi-driven net`，综合把逻辑那一侧**忽略**（恒 0）而仿真看不出来（xsim 按进程后写覆盖，ISSUES #61）。

## 8 固定延迟不变量：15 拍、−4 行、一个出处

**结论先说**：整链延迟恒为 **15 拍**，与哪一级开、同级选哪个算法都无关；内容偏移恒为**−4 行、0 列**。两个数都写在模块参数上：`LATENCY = 15`、`OFF_LINES = 4`（`proc_pipeline.v:22/27`）。
15 拍逐拍账（`:17-18`，本卷把加法式子写全）：灰度 1 + 反色 1 +模糊 3 + 锐化 3 + Sobel 3 + 阈值 1 + 形态学 3 = **15**。两条易被忽略的口径：窗口级
是**三拍**不是两拍（`de_in → de_d1 → de_d2 → de_out`，`proc_box_blur.v:144-146`）；同级两个选项是**串联**的，所以两个都占自己的拍数（`proc_pipeline.v:17`）。
级 0 的 gamma 是分布式 RAM 的**组合**读出 ⇒ 不占拍（`:20-21`），谁改成寄存读出（BRAM 风格）LATENCY 必须同时改成 16。

−4 行的因果：四个窗口级各贡献 −1 行、点运算级不贡献；行缓存式 3×3 滤波在收到第 y 行时才算得出第 y−1 行的窗口，因果性决定它必然滞后一行（`:23-26`）。顶层能补，因为帧缓存在
DDR 侧是随机地址的：**把地址提前，不是把数据提前**，而且提前量必须加在 mapper 的**显示行输入**上而不是输出的源行上——链子的滞后发生在显示栅格上，缩放/旋转之后"源行差 4 "≠"
显示行差 4 "（`:244-249`）。实现就是三行（`:276-284`）：

```verilog
wire [12:0] y_right_adv = {1'b0,y} + {5'b0,pipe_off_rows} + BILIN_ROWS[12:0];
wire [11:0] y_req_row = y_right_adv[11:0] >> 1;
wire [11:0] cy_r = (y_req_row >= IMG_H) ? (y_req_row - IMG_H) : y_req_row;
```

`pipe_off_rows` `u_pipe`自己输出`OFF_LINES`（`:48/808`）；`BILIN_ROWS = 2`是双线性读口那对乒乓缓冲的 2 行（`:250`），必
须**偶数**——`row0 = ~y[0]`定成对奇偶，奇数会让一对分属两个源行 ⇒ A/B 错行。`cy_r`的取模只减一次就够：`y_req_row`最大 302 ⇒ 不需要除法器/取模（#58，`:281-284`）。
帧头越界请求喂的是**下一帧的头几行**，钳`IMG_H-1`会让屏顶画"这张图自己的末行"（位置与段数都不变 ⇒ 十二格判据看不见这一格），绕回后仍走一遍逆缩放 ⇒ 小于 1.00x 不多出一
条顶带（`:278-280`）。

坐标按每级自己的节拍打标：四个窗口级不能共用顶层那一`x_in/y_in`——第 k 级拿到像素那一刻，顶`x_in`已经在说"第 (n+累积延迟) 个像素"，行缓存按列号写 ⇒
**写进去的列号与数据差着累积延迟**，且消隐越长差得越多。修法：给坐标装一条`de`同节奏的自由运行延迟线`xd[1:12]/yd[1:12]`，每级取自己那一拍，抽头号 = 该`de_in`之前
累积的拍数：**2→blur、5→sharp、8→sobel、12→morph**（`proc_pipeline.v:70-98`）；这条链是纯寄存器、每拍一跳、不参与任何运算，注释自算代价 = 2×
12×12 = **288 个触发器**（`:82`）。

口径"`xd[k]`必须恰好 k 拍"就是 #103 的根因那一刀：以前第一跳`xd[0] <= x_in`，于`xd[k]`其实是 k+1 拍 ⇒ 四个窗口级的列标签比它自己的数据
**晚一整拍**，后果两条都在硬件上——每行最后一个有效拍`x_in`只到 H_ACTIVE−2 ⇒ 槽位 H_ACTIVE−1 永远没人写（上电读 0）；每行第一个有效拍`x_in`还停在消隐
末尾（顶层一屏数到 1343）⇒ **写地址越界**，xsim 丢掉这一笔、硬件按地址位截断`1343 mod 1024 = 319`（本卷按该注释复算这个模）⇒ 每行往 319 号槽写进消隐期的
0x0000，读回它的是真实列 320 那一拍 ⇒ 板上一根钉死在显示列 320（源列 160）的 1 像素纯黑竖线（`proc_pipeline.v:75-81`）。判据：`sim/tb_v103_pipe_bypass.v`
的 **C10d**（槽位完整性）与**C10f**（越界写），改前两条都红；C10dpre 还要求九个行缓存数组在喂任何像素前 unwr 计数逐条== 1024。

这个不变量买到的是**读口调度不用重算**。顶层所有跟"内容站在第几拍"有关的地方都只取`u_pipe.LATENCY`：`MIX_D = 3 + 1 + 1 + u_pipe.LATENCY`（`:354`）、`PROC_LAT = u_pipe.LATENCY`
与`LEFT_TAIL = PROC_LAT`（`:816-817`，`orig_skid`的级数）、`RAW_LINES = u_pipe.OFF_LINES`（`:781`）、`SEAM_TAPS = MIX_D + 1 − 3`（`:902`，代
进去 = 18，`seam_src.v:9`的默认参数一致）。对外只有一个数。以前这里是字面量 7，于是"链上加一级"必须同时记得改它——忘了**不是编译错**，而是左窗与右窗错开 N 个像素（`:812-815`）。

钉住它的是实测而不是静态检查：`tb_v86_pipe_sel`的 **T2** 实`de_in→de_out` `up.LATENCY`比、**T3** 要求
`up.LATENCY == 15`、**T5** `sel = 001/004/008/010/020/080`六种档位下`first_lat`都 == 15（该文件头 T1..T16 段）⇒
RTL 改了拍数没改参数、或参数改了没改顶层，都有测试可红。一对差分判据`tb_v84_morph.v`：morph 的旁路与 blur 的旁路必须**逐位相同**——这就是 §7 里 Sobel
改成"取中心抽头原色"的原因。真加一级的话：`LATENCY`改 16 ⇒`MIX_D`/`PROC_LAT`/`LEFT_TAIL`/`SEAM_TAPS`都是 elaboration 期表达式
会自动跟，`OFF_LINES`若变`RAW_LINES` `y_right_adv`一起跟；会红的顺序大致是 T2/T3/T5（拍数）→ C1c/C2/C8c（两抽头不同深）→ C1i（相
位）→ C5c（帧头那 6 行）。

## 9 gamma 与量化：表在 LUTRAM 里，截断不做四舍五入

**表放在哪**：三张 256×8 bit `(* ram_style = "distributed" *)`数`tr/tg/tb`（`src/rtl/video/gamma_lut.v:27-29`）⇒
落在 **LUTRAM**，不是 BRAM。凭据两条互印：`build/util_hier_probe.rpt:70`那`u_gamma` `LUTRAMs = 96`、`RAMB36 = RAMB18 = 0`、`DSP = 0`；
而 96 正好 =`3×256×8/64`（本卷自算，一个分布式 RAM 单元 64 bit）。三通道**共用一张内容、复制三份 RAM**而不是"一份三读"：三读要额外读口，复制三份则内容永远由同
一个写口保证一致（`gamma_lut.v:3-4`）。为什么用表不用幂函数：PL 里`in^(1/γ)`要么堆 DSP 要么做对数/指数近似（`:4`）。曲线本体在 PS 侧算（`src/ps/main.c`
`gamma_curve`，`pow(i/255, 100/g100)*255 + 0.5`），PL 只照画，所以屏上写的数与串口打印的数必然同源（`effect_ctrl.v:63-65`）。
**gamma 那一级不占拍**（组合读出）⇒ LATENCY 常数不动（`gamma_lut.v:7`、`proc_pipeline.v:20-21`）；它挂在第 0 级是"左窗原图/右窗处理图"一
贯的半屏对比语义；`gamma_en = 0`时逐位等于输入，`tb_v88_gamma` `tb_v86`的 T1 钉住。

**写入协议**：`wr`是**翻转位**而不是脉冲（脉冲跨不到本域，#36）；先`idx`+`data`、下一次写`wr`翻转 ⇒ PL 看边沿才写一项，地址与数据不必同时对齐（`gamma_lut.v:5-7`）。
边沿检测在本地：`do_wr = rst_n && (wr !== prev)`；**复位`prev` `wr`一起置 0**，否则上电本身会被当成一次写事件（ISSUES #52 的根，`:31-39`）。
`en/wr/data/idx/disp[5:0]/temp[7:0]`六个字段过**同一对** ASYNC_REG 同步器（`effect_ctrl.v:39/54-56`，位序
`[31] en、[30] wr、[29:22] data、[21:14] idx、[13:8] disp、[7:0] temp`）。

**value 量化那级的实际做法**：链上每一处"从 8 bit 回到 5/6 bit "都是**截断、不加舍入**——
`y16 = {tr[r8][7:3], tg[g8][7:2], tb[b8][7:3]}`（`gamma_lut.v:51`）、`gray = {y8[7:3], y8[7:2], y8[7:3]}`（`proc_gray.v:24`）、`pix <= {vr[7:3], vg[7:2], vb[7:3]}`（`bilin_lerp.v:67`）。
而正向展开是位复制（`gamma_lut.v:20-25`），所以**每拍真正被读到的表项只有 32/64/32 格**：`r8 = {r5,r5[4:2]}`只有 2^5 = 32 个不同取值、`g8`
有 64 个（本卷按该式子的取值集合数出来）⇒ 表虽然 256 项，红/蓝通道实际只被索引到其中 32 个位置。截断的最大误差：丢掉低 3 bit ⇒ 8 bit 域里最多 7/255 ≈2.75 %
（本卷自算）。`bilin_lerp`那一处的舍入不是没有，而是**提前**做完了（纵向合并后`+2^15 >>16`，`:53-55`）。同一链上别的"取整还是截断、夹不夹位"各有决定：模糊
`>>9`截断（`proc_box_blur.v:118-120`）、锐化**夹到满量程**（`proc_sharpen.v:105-107`）、Sobel 夹到 255（`proc_sobel.v:118`）、双
线性靠权重和恒等**不夹**（`bilin_lerp.v:57`）、`zoom_fit`夹到 10 bit 上界 1023（`zoom_fit.v:51`）。

" 0–100 %"要说精确：端点用 **1/16 宽度**作单位（`lo16/hi16`，0..16），换算成像素就是一位移位`像素 = (u*W) >> 4`，`W`是 2 的幂（1024
或 512）⇒ 综合出来是 2:1 选线，既不是除法器也不是桶形移位器（`split_ctrl.v:29-42`）；百分`PCT = 100·16384/W`是 elaboration 常数（1024⇒1600、512⇒3200
精确）⇒`pct = (eff*pct_c) >> 14`（`src/rtl/video/split_ctrl.v:115-117`）。手工位置只有 10 bit（`gp[9:0]`，`pl_video_top.v:887`）⇒ 最大可给
1023 列，百分`1023×1600 >> 14 = 99`（本卷自算）⇒ **100 % 只有自动扫描能到**（`hi16 = 16`时
`hi_px = 16×1024>>4 = 1024`）。缝位夹到`[0, W]`而不`[0, W−1]`，因为"缝推到最右" = 整屏都是缝左侧那一半（`:93-99`）。`hi < lo`
是合法输入（`split range 80 20`），这里把两个端点折`[min,max]`，台架 T3 单独判（`:43-47`）。百分比那条链上有一级单独寄存`pct_q`、**别删**：r60
全设计最差路径是`u_split_ctrl/swp_reg[7] → u_osd/r_reg[1]`、28 级、里面有一个 DSP48（`:118-124`；
`util_hier_probe.rpt:75`那个 DSP = 1 就是这里`eff × PCT`）。

那条 2 列宽的标记蓝线：`split_display` `sep`那一拍把颜色钉成`r = 8'h40, g = 8'h40, b = 8'hFF`（`split_display.v:63-64`），`sep`
是`marker && (seam−1 或 seam 这两列)`（`:52-53`）；`follow`模式下换`src_mark`，宽度是 2 个**图像列**（`seam_src.v:26`）。
`gp[13] = 1`才是"关" ⇒ 复位/PS 没写过时屏上仍有这条线（`pl_video_top.v:892-894`）。它是故意的、不是缺陷；但关掉之后"缝在哪一列"就只能靠内容切换看出来，所
以存在"串`split <n>`之后 marker 位不变"这条判据（`report/technical-document.md`§3.5 末句）。

## 11 HDMI 输出：×2 复制、TMDS、OSERDESE2、这一档为什么不纳检

**结论：×2 展开是复制，不是插值**，而且展开发生在**坐标**上、不在像素值上：`cx = x >> 1`、`cy = (y >> 1)`夹`IMG_H−1`（`pl_video_top.v:242-243`）⇒
相邻两列算出`cx`相同、相邻两行算出`cy`相同，同一个源像素被取 4 次、屏上占 2×2。这条"复制"在链子上留下的痕迹就是 §2.2 那句"每个源像素天然占 4 个 50 MHz 拍
"，以及一句代价声明：`proc_pipeline`的一行现在是 **1024 个有效拍**（`#(.H_ACTIVE(2*IMG_W))`，`:800`），于是 3×3 窗口的空间尺度按 1024
列算、同级相邻两列在源上只差半格，横向模糊/锐化/Sobel 的半径因此是**半个源像素**；代价还包括行缓存宽度翻倍（`:9-15` `:796-799`两处都写了这笔账，并明说想回到"一行
512 拍 = 源尺度"的喂法`de_in = de_d[3] && !x_d[3][0]`，动它之前要把 #103 那一族的账重算一遍——观感与正确性一起动，不是免费优化）。真正的插值是**几何**
插值、发生在源侧：非整数倍率/旋转角`(sx,sy)`带小数，读口对源图做 2×2 采样 + 两级 lerp（§5）。所以"×2 展开"与"双线性"是两件不同的事，只在 1.00x、0° 时两
者重合：`fx = fy = 0`，`bilin_lerp` `fx = fy = 0`时恒等`p00`（这条性质由`tb_bilin_lerp`判据 2 保证，`fb_bilin.v:47-48`）。

三`tmds_encoder`各编一个通道，通道映射是 DVI 口径：**ch0 = Blue + HS/VS、ch1 = Green、ch2 = Red**（`src/rtl/hdmi/rgb2dvi.v:21-33`）。
消隐期的三条码字（`tmds_encoder.v:48-53`）：`{c1,c0} = 00 → 1101010100`、`01 → 0010101011`、`10 → 0101010100`、`11 → 1010101011`，其
中 ch0 `c0 = hs`、`c1 = vs`（`rgb2dvi.v:22-25`），绿/红两条`c0/c1`钉 0；钟道更直接，一个常数`10b_1111100000`每拍送进同一条串
化器（`:48-52`）。编码本体两步（`tmds_encoder.v:13-36`）：① 8→9 的异或/同或选择
`use_xnor = (n1 > 4) || (n1 == 4 && din[0] == 0)`，`q_m[0] = din[0]`，其余 XOR 路径
`q_m[i] = q_m[i-1] ^ din[i]`、XNOR 路径取反，`q_m[8]`在 XOR 是 1、XNOR 是 0（"本拍加还是减不平衡度"的标记位）；② 9→10 的直流平衡：游标
计数`cnt`是 6 bit 有符号，`cnt == 0 || n1q == n0q`时`q_m[8]`决定是否取反，否则只有"会把 cnt 拉回 0 "的那一侧才被允许（`:55-73`），`!de`
`cnt`清零（`:46-47`）。

10:1 串化用**主从两颗 OSERDESE2 级联**（UG471 的标准形状，`src/rtl/hdmi/tmds_serializer.v:2-3`）：`DATA_WIDTH = 10`要求
`DATA_RATE_OQ = "DDR"`（`:16-17`）；MASTER `D1..D8 = din[0..7]`（`:33-40`），SLAVE 只吃
`D3/D4 = din[8]/din[9]`（`:73-77`），SLAVE `SHIFTOUT1/2`回接 MASTER `SHIFTIN1/2`（`:64-65`），两颗的
`CLK = clk_pix5x`、`CLKDIV = clk_pix`，输`OQ`过一颗`OBUFDS`出差分（`:91`）。250 与 50 的关系可算：**一个 10 bit 码字 = 5 个 250 MHz 周期 × 2 边沿** ⇒ 字符率 = 250/5 = 50 MHz = 像素率，正是 TMDS 要求的" TMDS 钟 = 像素钟、10 bit/character "（这一
条在本仓库里被写成约束取证依据：`src/constraints/r119_hdmi_source_window.xdc:23-26`）。两个钟同源同相：`MMCME2_BASE`，`CLKFBOUT_MULT_F = 20`⇒
VCO = 50×20 = 1000 MHz，`CLKOUT0_DIVIDE_F = 20`⇒ 50 MHz 像素钟，`CLKOUT1_DIVIDE = 4`⇒ 250 MHz 5 倍钟，`CLKOUT2_DIVIDE = 5`⇒
200 MHz IDELAY 参考（`clk_gen.v:15-29`，三路各过一个 BUFG，`:53-56`）。`pl_video_top`里 250 MHz 这一路只`u_dvi`（`:126-131`、`:1026-1032`）
——`fb_rd5x`/`tap_sched`那一族"每像素 5 次读"的方案在 r63 起被全程慢域`fb_bilin`取代，只剩台架在驱动（`fb_rd5x.v:4-6`）。

### 11.1 为什么这一档不纳检（工具/约束层面的四条事实）

1. **工具明说了没查。**`build/check_timing_verbose.rpt:69-77`有一节标题`6. checking no_output_delay (12)`，第一条是 "
 There are 6 ports with no output delay specified. (HIGH) "，点名列`led[0]`、`led[1]`、`tmds_clk_p`、`tmds_data_p[0..2]`（`_n`
 那一半在 OBUFDS 内部、所以不点名）。没`set_output_delay`参考对象 ⇒ 工具对这些引脚对外**一条时序都不查**。同类口径`data/metrics.csv`"全局
 setup 失败端点"那行自己就写着："收口 I/O 的 5 个端点当前无输入窗 = 未检查（H5：未检查不等于满足）"。

 册数**，本机当时取不到规范原文（试过 TI/DVI 页都不能解析），所以按纪律留到下一笔并写明缺出处，"不许把 UI 的 0.26/0.28 当成已按规范写进来"。
3. **后来补到了数，但它是候选件、默认不加载。**`src/constraints/r119_hdmi_source_window.xdc:51-52`给
`tmds_data_p[*]/tmds_data_n[*]`写了`set_output_delay -clock clkout1_1 -max 4.000 / -min -4.000`；数字是
**算出来的**：HDMI 1.4§4.2.4 Table 4-24 `Inter-Pair Skew at Source Connector, max = 0.20 Tcharacter`，本档
`Tcharacter = 像素周期 = 20.000 ns`⇒ 半窗 = 0.20×20.000 = **4.000 ns**（`:19-27`）。参考钟为什么`clkout1_1`：四条串行器

 约束**，会改变实现看出去的边界，必须先用一轮构建量它对逐时钟名册的影响，量完之前塞进去就等于"用声明代替测量"（`:36-38`，开`VP_R119_TMDS_WINDOW= 1`）；该文件还留了
 一把只读尺子`build/r119_window_check.mjs`判"那两个数与 4.000 是否一致"（`:27`）。
4. **就算加载了，它也覆盖不了 TP1 的本体判据。** 同文件"仍然如实保留的三条"：① TP1 真正的判据是**眼图掩模 + 抖动/占空比/上升下降**，这些不在 SDC 的语义里（`set_output_delay`
 只约束沿的到达时刻），只能靠仿真与示波器，本文件不代表"过 CTS "（`:41-44`）；②`led[0]/led[1]`是`LVCMOS33`直驱 LED（`src/constraints/rk_zynq7020.xdc:10-11`），HDMI
 连接器引脚表里没有这类信号 ⇒ **没有可引用的对外窗**，给它们"不查"的定性属一次放宽、本文件不替它们写窗（`:45-47`）；③ 本窗只挂在数据道（相对钟道的对齐），钟道自身不挂输出窗：源端的钟
 就是参考，对它要求的是占空比/抖动/沿/对内偏斜（`:48-49`）。

引脚侧事实附在最后：`tmds_clk_p/_n`、`tmds_data_p[i]/_n[i]`全部`TMDS_33`电平，引脚
W16/Y16/AA17/AB17/U17/V17/U15/U16（`rk_zynq7020.xdc:12-19`）。
