# 03 缩放、旋转与双线性：原理 → 实现 → 取舍

这一级是整台机器的门面：显示器是 1024×600 的固定时序，源是 512×300，中间要能**任意倍率缩放**、
**任意角度旋转**、并且在斜边上**不出现硬台阶**。三件事共用一套定点坐标链。

## 1. 原理：屏幕坐标 → 源坐标，只能靠乘

显示侧每拍要一个像素，就必须在**一拍之内**回答："这个显示格该取源图的哪个位置？"
除法是回答不了这个问题的（见第 4 节那笔账），所以整条链只做两件事：**乘一个定点数**、**移位取整**。

约定（`src/rtl/process/zoom/zoom_mapper.v:3`）：

```
inv_scale 是 Q8 的"倒数"：256 = 1.0×（原始大小），512 = 0.5×（把画面缩小一半显示）
⇒ 倍率 s = 256 / inv_scale，inv_scale 越大画面越小
```

- 显示坐标 `(xp, yp)` 减去视口中心，得到以中心为原点的坐标；
- 旋转变换：`xr_m = xp·cosθ + yp_math·sinθ`、`yr_m = −xp·sinθ + yp_math·cosθ`（`:47-50`）；
  `yp_math` 是"显示 y 翻转成数学 y"的那一支，后面第 3 节它还会回来咬一口；
- 缩放：`rot_xs = xr_m * inv`（`:58-61`）；
- 取整：旋转路 `>>> 16`、未旋转路 `>>> 8`（`:63-66`）。
  为什么移位量不同？三角表也是 Q8（256 = 1.0），所以旋转过一次已经带了 8 位小数，
  再乘 `inv` 是 16 位小数；不旋转时只有 `inv` 贡献的 8 位。**同一个"取整到源像素"的动作，
  两条路的移位量必须不一样**，这是这类坐标链最容易写错的一处。
- 越界：`oob` 置位、四周填黑（`:57` 的注释就是这条：`inv > 256` 时缩小后四周必然有空边）。

流水级数：3 级（`:3`），并且缩放与旋转**可以叠加**——因为角度只是两张表的索引，
不额外增加一级。

## 2. 三角表是 Q8，不是 Q15：精度是"选"出来的

`angle_ctrl` 输出的 `angle` 是 0…359 的 9 位整数（`src/rtl/process/rotate/angle_ctrl.v:15`），
直接当 `cos_rom`/`sin_rom` 的索引，表的幅度是 **256 = 1.0**（Q8）。

为什么不用更宽的 Q15？因为工程侧的账是"够不够看"而不是"够不够精"：
Q8 的量化误差是 ±0.5 LSB，即倍率上约 ±0.2 %；而显示侧本来就只有 512 列源、1024 列显示，
再高的精度会被取整吃掉。反倒是 **`zoom_fit` 与 `zoom_mapper` 必须用同一张表**——
`src/rtl/process/zoom/zoom_fit.v:5-6` 明写："C/S 来自与 `zoom_mapper` 同一张 Q8 三角表 ⇒
这里判的'装得下'就是那条链真正画出来的框"。**两处用两张表，就会一个说装得下、另一个画出去。**

## 3. 旋转 + 双线性：一次"小数被丢掉"的修法（`#104`）

双线性插值要用源坐标的**小数部分**当权重。旋转那一路过去在 `:70` 的位置把 `frac_x/frac_y` 钉 0，
于是屏幕上 `bilin on` 在旋转态是空头支票。接回小数时踩到的不是乘法，而是**取整方向**
（`:71-79` 的注释块，逐字读过才写得出来）：

```
Y_disp = C − Y_math，而 Y_math = yr_pix + f/256，`>>>16` 是朝 −∞ 取整 ⇒ f ∈ [0,256)
```

翻转一次，floor 就落在另一侧：小数不为 0 时纵向必须**多减一格**，同时权重要取 `256 − f`。
原来两处各错一半（`:79`：`rot_y_has_frac` 用了高字节、`~rot_fy+1` 也用了高字节 ⇒ 一族不减格、
权重给成 0）。对照台架是 `sim/tb_zoom_frac.v`：改前 298 行 FAIL，改后读数在
`build/r94_zoomfrac_after.txt`。

**教训的一般形式**：只要坐标链里有"翻转 + 取整"同时存在，就要单独问一句
"这一支的 floor 是朝哪边的"，并把小数与整数**一起**改。

## 4. 为什么运行时不许有除法器（`#58`）

自动缩放要算 `inv_x = (W·C + H·S)/W`、`inv_y = (W·S + H·C)/H`（几何见
`src/rtl/process/zoom/zoom_fit.v:3-5``：旋转后外框 `W' = s·(W|cosθ| + H|sinθ|)`，要求 `W' ≤ W` 且 `H' ≤ H`，
取**较大者**就是"刚好装得下"）。听起来一个除法而已——实测：
**100 MHz 域放一个组合除法器，把 WNS 打到 −5.014 ns**（`src/rtl/process/zoom/zoom_fit.v:26-27``）。

修法是把除法折成"乘一个 elaboration 阶段就算好的倒数常数 + 定长移位"：

```verilog
parameter integer NSHIFT = 20          // 倒数常数的定点位数（:11）
// round(2^NSHIFT / 边长)，elaboration 阶段算好 ⇒ 综合折成常量乘法（:28）
```

误差 ≤ 0.03 %，比 Q8 三角表本身的量化误差还小。**这条纪律后来推广到整条快域链**：
快域（像素时钟的高倍频）一律不做算术，只做取数与搬运。

## 5. 双线性读口：一个源像素用满它天然的 4 拍

`src/rtl/process/bilin/fb_bilin.v:1-6`——显示侧**唯一**的帧缓存读口：

| 事项 | 实际做法 | 出处 |
|---|---|---|
| 每拍读几个字 | 一个：每源像素用满它天然的 4 个 50 MHz 拍（2 显示列 × 2 显示行） | `:4` |
| 时钟域 | `clk_pix` 50 MHz 单域，**不进快域** | `:5`、`:13` |
| 延迟 | 地址寄存 1 拍 + BRAM 1 拍 ⇒ 请求到数据 2 拍；结果缓冲使内容整体晚 1 对显示行（= 2 显示行） | `:5-6` |
| 何时换的 | r63 / `#52`，顶层 `src/rtl/top/pl_video_top.v:721-729``，旧信号名 `fb_rd`/`oob_fb_d1` 沿用不动 | 同处 |

算术核完全解耦在 `src/rtl/process/bilin_lerp.v`（4 个 RGB565 抽头 + Q8 小数 → 1 个 RGB565，两级流水：
横向一次、纵向一次）。它文件头（`:3-7`）记的三个精度决定，每个都有代价：

1. **565 展开 8 位用位复制**：`R8 = {r5, r5[2:0]}`、`G8 = {g6, g6[1:0]}`，不是左移补零。
   全 1 展开正好 255 ⇒ 纯白不会因为展开变灰（补零的话 `0x1F → 0xF8`）。
2. **权重 Q8 且两两之和恒为 256** ⇒ 横向 ≤ 255×256 = 65280（17 bit 封顶）、
   纵向 ≤ 255×65536 + 舍入 = 25 bit ⇒ **不需要饱和**。这一点不是"我以为不溢出"，
   由台架判据 2「四角同色 ⇒ 输出恒等」强制检验。
3. 纵向合并后一次 `+2^15` 再 `>>16` 做四舍五入。

## 6. 那一版"每像素 5 次读"为什么还留在仓库里

`fb_rd5x.v` + `tap_sched.v` 是 r63 之前的方案：50 MHz 像素域 + 同源 250 MHz 的 5 倍时钟，
每个像素周期发 5 次读（左窗 1 次最近邻 + 右窗 4 次双线性抽头）。顶层已经不用它们了，
但两个台架（`sim/tb_fb_rd5x.v`、`sim/tb_tap_sched.v`）还在驱动，形状与延迟由它们钉着——
文件头明写"**别当死代码删**"（`src/rtl/process/bilin/fb_rd5x.v:5-7``、`src/rtl/process/bilin/tap_sched.v:5-6``）。

这一族里最有价值的两条实测结论：

- **快域→慢域最坏有 16 ns**，所以抽头与左窗字都要在快域先落一次触发器再交给慢域；
  插值的 12 个乘法留在慢域（`bilin_lerp` 两级流水），因为快域 4 ns 塞不下（`src/rtl/process/bilin/fb_rd5x.v:7-9``）。
- **帧缓存不许再加一个逻辑读口**：每像素 5 个快槽 = 右窗 4 + 左窗 1 恰好占满 ⇒ 不新增任何 BRAM；
  实测在同一组阵列上再加一个读口会把帧缓存从 **80 块 RAMB36 顶到 160 块，而全片只有 140**
  （`src/rtl/process/bilin/tap_sched.v:10-12``）。这是"资源账要量、不要估"的最硬一例。
- `LAT=5` 这个延迟数也不是纸上推的，是 `tb_fb_rd5x` 用"唯一平移量搜索"量出来的
  （`src/rtl/process/bilin/fb_rd5x.v:8-9``）。

## 7. 怎么验，以及什么表现是**正确的**而不是坏

```bash
VP_VIVADO_BIN=<Vivado>/bin bash build/sim/run_one.sh tb_zoom_frac    # 旋转支小数与 floor（#104）
VP_VIVADO_BIN=<Vivado>/bin bash build/sim/run_one.sh tb_fb_rd5x      # 5 槽形状与 LAT
VP_VIVADO_BIN=<Vivado>/bin bash build/sim/run_one.sh tb_v101_fb_bilin
```

板上要记住的一条反直觉事实：**在 1.00× 与 2.00× 下 `bilin off` 和 `bilin on` 看不出差别是正确行为**
——每个源像素占整数个显示像素 ⇒ 小数权重为 0 ⇒ 插值逐位等于最近邻
（`sim/tb_v101_fb_bilin.v` 的 L5 用 4088 格钉住这件事）。
要看出差别必须用**非整数倍率**（如 1.5×）或**旋转态**。把它说成"功能坏了"是误读。

小结：这一级的全部要点是——只用乘和移位；缩放与判"装得下"必须共用同一张表；
翻转与取整要一起改；快域不做算术；读口数量由 BRAM 总量决定而不是由"想要几个口"决定。
