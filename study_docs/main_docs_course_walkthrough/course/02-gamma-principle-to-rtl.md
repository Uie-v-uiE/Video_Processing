# 02 Gamma：原理 → 实现 → 取舍

## 1. 原理：为什么亮度不能线性给

三个事实叠在一起，才需要 gamma 这一步：

1. **人眼对暗部更敏感**。同样差 8 个灰阶，在暗区看得出来、亮区看不出来。要让"码值均匀变化"对应
   "看上去均匀变化"，就需要一个**幂律映射**而不是线性映射。
2. **显示器件本身就是非线性的**。LCD/OLED 的亮度大致随驱动值走 `V^2.2` 这条曲线，
   所以信号端要预先给它一个 `V^(1/2.2)` 的逆函数，屏幕上出来的才是想给的亮度。
3. **工程上不做浮点**。像素流水线每拍要处理一个像素，映射只能是**查表**：把
   `out = round(255 · (in/255)^(1/γ))` 预先算成 256 项 8-bit 表，运行时只做一次表查询。
   γ 要能改，就得能把表**换掉**——这正是本模块"表在 PL、内容由 PS 灌"的由来。

RGB565 的一个像素是 16 bit：`R[15:11] G[10:5] B[4:0]`（5/6/5 位）。
逐通道校正 ⇒ 需要三张表，而且**绿通道是 6 位、红蓝是 5 位**，这个不对称直接决定了实现里的位选取。

## 2. 实现：53 行的 `src/rtl/video/gamma_lut.v`

### 2.1 端口与存储

```verilog
module gamma_lut (
    input  wire        clk,      // 像素域：读写都在这里
    input  wire        rst_n,
    input  wire        en,       // 0 = 旁路，逐位等于输入
    input  wire        wr,       // **翻转位**，不是脉冲
    input  wire [7:0]  idx,
    input  wire [7:0]  data,
    input  wire [15:0] din,      // RGB565
    output wire [15:0] dout);

    (* ram_style = "distributed" *) reg [7:0] tr [0:255];   // :27
    (* ram_style = "distributed" *) reg [7:0] tg [0:255];   // :28
    (* ram_style = "distributed" *) reg [7:0] tb [0:255];   // :29
```

三张 256×8 的表，`ram_style = "distributed"` 是**明确指定用 LUTRAM**（分布式 RAM，由查找表本身构成）
而不是块 RAM。读口是异步的：一拍之内 `idx` 一给就写、`din` 一到就读，不占流水级。

### 2.2 写口：为什么是"翻转位"而不是脉冲

```verilog
    reg prev;
    always @(posedge clk or negedge rst_n)
        if (!rst_n) prev <= 1'b0; else prev <= wr;      // :35
    wire do_wr = rst_n && (wr !== prev);                 // :39
    always @(posedge clk) if (do_wr) begin
        tr[idx] <= data; tg[idx] <= data; tb[idx] <= data;   // :41-46
    end
```

写请求来自 PS 通过 AXI GPIO 拨的一个控制位。PS 与像素时钟**不是一个域**，
所以这里不能传"脉冲"：脉冲宽度只有一两个 PS 侧周期，像素域采样时**可能整拍都看不到**，
写就丢了。传**翻转位**（值变化 = 一次事件）就不怕采样：只要两边各采到一次电平变化，事件就不会漏。
RTL 里那句注释写得很直白——"`wr`：**翻转位**，不是脉冲（脉冲跨不到本域）"（`:12`）。

另一半的坑在复位：`prev` 必须和 `wr` 一起在复位时清成 0。否则上电瞬间 `prev` 是 X、`wr` 是 1，
边沿检测会把"上电"本身当成一次写事件，把 `data` 那个不确定值灌进表里 —— 这就是
`main.c` 与台架一起钉住的那类"看起来随机坏一格"的问题（源码注释直接指向 `ISSUES #52`）。
`prev` 用 `always` 复位而不是 `reg prev = 1'b0;` 那种声明初值，是因为后者是 SystemVerilog 写法，
本工程按 Verilog-2001 编（`:33-34` 的注释）。

### 2.3 读口：5/6/5 的位选取不对称

```verilog
    wire [15:0] y16 = {tr[r8][7:3], tg[g8][7:2], tb[b8][7:3]};   // :51
    assign dout = en ? y16 : din;                                // :52
```

表是 8 位精度，而像素里红蓝只有 5 位、绿有 6 位 ⇒ 校正完取高位放回：**红蓝丢低 3 位、绿丢低 2 位**。
这一行是整个模块里最容易被"我以为对称"坑到的地方，也是台架会去数的位。
`en` 为 0 时 `dout` 就是 `din`，逐位不变——这是台架第一条判据（下面第 4 节）。

## 3. 数据通路的位置与可见性

| 问题 | 答案（出处） |
|---|---|
| 它在效果链的第几级？ | 级 0，`src/rtl/process/proc_pipeline.v:104` |
| 屏上两半都能看到 gamma 吗？ | **不**。只改"处理图"那一侧（`report/command_precedence.md:68`）；缝的左边给原图、右边给处理图，所以 gamma 只在右半可见（`report/commands.md:232`） |
| 控制字在哪？ | `axi_gpio_2` 通道 2，地址 `0x41220000 + 0x08`，位序 `{en, wr, data[29:22], idx[21:14]}`；同一个寄存器里还住着 `[13:8] gamma_disp`（只给 OSD 显示"1.8"这一格，PL 不参与运算）与 `[7:0] temp_disp`（屏上温度两位 BCD）——见 `report/architecture.md:105` 与 `src/ps/main.c:79-96` |
| γ 的值怎么表示？ | `cur_gamma = γ×100`，`0` 表示关（`en=0`，PL 逐位旁路），见 `src/ps/main.c:291` |

**关键约束**：这组位与 gamma 写在**同一个寄存器**里，所以任何写通道 2 的代码都必须从
`gm_w` 那个基值出发改位，不能整字覆盖——否则会把 OSD 的显示位和温度一起抹掉
（`src/ps/main.c:94` 就专门写了这条警告）。

## 4. PS 侧：一次换表是 256 次写

`gamma_set()` 循环 256 项，每项两次 `usleep(5)` ⇒ 全程约 **2.6 ms 不回主循环**
（`src/ps/main.c:286`）。这带来一个真实故障：115200 波特下 Zynq 的 RX FIFO 只有 16 字节
（约 1.4 ms 的量），人在 gamma 执行中途粘进来的下一行字节就从 FIFO 漏掉了——
症状是"命令要发好几次才有反应"。修法是把**收字节**和**切分派发**拆开：
`rx_fill()` 只搬运不派发，长流程里反复调它，主循环再按顺序派发整行
（`src/ps/main.c:303-310` 的注释块；同一段还处理"残包"——半行搁置超过 3 s 就丢掉并明说丢了）。

这个例子值得单独看一眼：**问题不在协议、不在硬件，而在"一段不回主循环的耗时操作"**。
把它写进文档是因为同类操作（一次写满一张表、一次擦一整片 Flash）在固件里反复出现。

## 5. 为什么用 LUTRAM，也为什么不"不动 BD"就完事

| 选法 | 好处 | 代价 | 本工程为什么这么选 |
|---|---|---|---|
| LUTRAM（distributed） | **异步读**，不占流水级；单块极小（3×256×8 ≈ 6 Kbit），布线域内就近 | 占用查找表资源；表变大就不可行 | 像素链路已经是一条深度固定的流水线，多插一级同步 BRAM 读会把延迟和边界条件全改一遍 |
| BRAM（block） | 不吃 LUT，容量大 | 读是**同步**的，必须多加一级；工程 BRAM 使用率本来就贴着上限 | 收益为负，且改动面比这一级本身大得多 |
| 表存在 PL 里（综合时常量） | 不需要写口 | γ 不能运行时改，演示时只能"看起来固定" | 不行：串口要能 `gamma 1.8`、还要能 Auto 呼吸（`src/ps/main.c:293-301`） |
| 加一个 AXI GPIO 通道 | 位够用、干净 | **要重生成 BD**，连带引脚/时钟配置都要重新核对 | 不划算：现有通道 2 里塞得下 `{en,wr,idx,data}` 加上显示位，"不动 BD"是当初定的取舍（`report/commands.md:310`） |

## 6. 怎么验（照着跑就能复现）

```bash
# 1) 台架：八条判据，含"关着就必须一动不动"那条反例（src/ps/main.c:283 点名的就是它）
VP_VIVADO_BIN=<Vivado>/bin bash build/sim/run_one.sh tb_v88_gamma
# 2) 板上：打开 gamma，看右半（处理图）变化、左半（原图）不动
echo "gamma 1.8"   | <串口发送工具>
echo "bilin off"   | <串口发送工具>   # 避免和缩放对照混起来
# 3) 关掉必须逐位复原：gamma 0 之后右半应与开表前的右半一模一样
```

台架的红怎么读：`RESULT tb_v88_gamma PASS` 之外，脚本 `build/sim/run_one.sh` 约定
**退出码 3 = 台架自己判红**（不是编译失败），判据行按"最后一个非空字段"读结论。

小结：gamma 这一级把"人眼/器件非线性 → 幂律表 → 运行时可换表 → 跨域怎么把表送进去 →
送表时别把串口收字节饿死"串成了一条完整链，每一环的实现都能在 `:行号` 上找到落点。
