## 第 1 节 本目录是什么、不是什么

- **是**：教你**读懂这个工程**的一套文档 —— 结构、时间顺序、接口契约、通用原理与辨认方法。
- **不是**：设计说明书（那是 `report/architecture.md`、`report/modules.md`）、
  不是可复用方法论（那是 `skills/`）、不是数字表（那是 `data/metrics.csv` 与 `report/perf_report.md`）。
  重复处按 P11 质量判据第 3 条删本目录那份，不复制过来。
- **本目录刻意不进 GitHub**：它是本地学习件，交付文档里**不许**出现指向 `docs/walkthrough/` 的链接；
  本目录反过来引用交付件是允许且必需的。这条约定写在这里，是为了让后面任何一批续写都不小心破坏它。
- **口径纪律**（全套文档共用，写在这里一次）：
  ① 每个数字后面必须点名它出自哪个文件，或标 `【未实测】`；
  ② 每条关于工具行为的说法，必须由我本次真的打开过的文件或真的抓到的网页支撑，登记在 `_sources.md`；
  ③ 查不到的写 `【未核实】`，不许写成事实；
  ④ 不写"通常/一般来说/理论上"，也不写"显然/众所周知/很简单/容易理解"。

小结 1：本目录的价值判据只有一条 —— 你不跟我们说话，也能靠它回答"这东西怎么把 A 变成 B、为什么这么搭、
换我自己的题目该动哪几处"。
小结 2：本目录的一切结论都可以被第 2 节那两条命令复核；复核不过就是文档错了。下一步：第 2 节。

## 第 2 节 15 分钟走到第一条可执行命令

前置：一个 Git Bash（或任何能跑 `bash` 与 `node` 的 POSIX shell），仓库根目录。
**不需要** Vivado、不需要 Vitis、不需要板子。

```bash
# 第 0 步（10 秒）：确认你在仓库根，且看得到这三样
ls build/gates.sh build/sim/run_one.sh src/rtl/top/system_top.v

# 第 1 步（约 30 秒，只读）：读一份冻结的门禁清单
bash build/gates.sh build/evidence_r75
```

**这一条命令做完，你已经看到了这个工程的"交付判据长什么样"**：22 项判据、四域分组时序、
以及末行那句 `GATES: PARTIAL … 有 2 项因缺凭据未判`。为什么传目录而不是裸跑、看到别的说明什么，
全部写在 `hands-on.md` 实验 1（含逐条分叉）。

想再花 30 秒验证"文档里的行号是真的"：

```bash
node src/host/line_cite_check.mjs
```

需要跑台架或上板时才要设环境变量，**只认名字**：`VP_VIVADO_BIN`（指到 `<Vivado>/bin`）、
`VP_XSDB`（指到 `<Vitis>/bin/xsdb.bat`）。两者缺一律先 REFUSE 而不是硬跑
（判据原文：`build/sim/run_one.sh:46-47`、`src/host/health_read.mjs:32`）。

小结 1：第 2 步那条命令是全套文档的"复核入口"，它不写仓库里任何东西（原因见 `hands-on.md` 实验 1 那段）。
小结 2：15 分钟的预算 = 第 0 步 10 秒 + 第 1 步 30 秒 + 读它打印的 22 行。下一步：第 3 节挑你的路径。

## 第 3 节 三条阅读路径

三条路径都以 `prerequisites.md` 的自查表为**第一步**（先判自己缺哪块、那块会卡在哪一节，再走）。

### 路径 A · 完全新手（只学过数字逻辑与 Verilog 语法，没碰过 SoC、总线、嵌入式）

1. `prerequisites.md` —— 做第 2、3 节两张表，标出你要补到第 3 层的三项
2. `system-overview.md` —— 它把什么变成什么、为什么不是纯软件
3. `glossary.md` —— **先读第 1 节**（五层阶梯的读法），后面当字典随手查
4. `myths.md` —— 先划清"看着像其实不是"的那几对边界，后面少绕路
5. `subsystem-map.md` —— 51 只实例逐只点名，建立"能 grep 到"的地图
6. `one-pass-walk.md` —— 一帧数据走过 16 站，这是全套文档的样板篇
7. `code-reading.md` —— 八段逐行片段，练"拿到一段代码先问哪六问"
8. `mechanics.md` —— 第一次只读每节的第 ①② 层（零术语版与不用它会看到的现状），第 ③ 层的规范出处等网络通了再补
9. `interface-contract.md` —— 你以后要改的东西几乎都在这四页里
10. `clocking-and-reset.md` —— 把第 6、7、8 篇里所有"跨域"落到一张表上

13. `next-layer.md` —— 读完前十二篇再开这一篇，它是"下一步去哪"的地图，不是本页的必修

### 路径 B · 会写软件（C/Python），完全没做过硬件

1. `prerequisites.md`（第 2 节是你的主战场，三项要到第 3 层）

## 第 4 节 阅读单元规则（每篇的固定形状）

本目录**不限制篇幅**（详细优先），改用四条可核对的形状约束每一篇：

1. 篇开头写"读完这篇你能回答哪三个问题"。
2. 每节结尾两行小结（"小结 1 / 小结 2"）+ 下一步去哪。
3. 超过 100 行的篇必须带节目录（本目录 8 篇全部带目录）。
4. 每篇 ≥1 道自测题，且**答案的形式是"去某个文件查"**，不许在文档里直接给结论。
5. 技术名词首次出现：要么就地解释，要么写成"（→ 术语表）"；二者必居其一。

数字与出处的纪律在第 1 节；模块级说明另有六件要求（为什么存在 / 取值范围 / 时序要求 / 失败暴露 /
共享状态 / 怎么确认它活着），本目录目前对 6 个模块做满（`subsystem-map.md` 第 7 节）。

小结 1：这四条是"够详细"的替代指标 —— 我们不看字数，看结构与落点。
小结 2：任何一篇被改短时，先看这四条有没有断。下一步：第 5 节。
