**1. 输入变输出，中间阶段**
输入是上位机经千兆网 UDP 发来的一帧 512×300 RGB565（另有 SD 卡裸帧、片内自绘图卡两路）；输出是 HDMI 屏上
1024×600、左半原图右半处理结果的对照画面，加串口回显与一组寄存器回读。阶段：采样（4 位双沿→8 位）→自算校验→
剥头与端口过滤→按偏移重组并逐行验收→跨域缓冲→打包 64 位写片外内存（乒乓两块）→提交→只在消隐窗口把整帧搬进
片上帧缓存→逆映射取源坐标→效果链（固定 15 拍、滞后 4 行）→逐像素二选一对比→叠字→并串编码上屏，另有计量段。
依据：`system-overview.md` 第 1~4 节；`one-pass-walk.md` 第 0 节、第 1~16 站、第 19 节。

**2. 一份数据怎么知道硬件算完**
没有中断（三只 GPIO 都关中断），全是轮询＋翻转位：链上有四个不同的"完成"，各有各的通知对象；"算完"在硬件里表现为
一个被拧反的位，对面打三拍取相邻两拍的差才得到一次脉冲；搬运机自己出 `done`，再翻给像素域。超时由看门狗兜
（20 ms 拷贝、500 ms 心跳）。
依据：`one-pass-walk.md` 第 16 节；`interface-contract.md` 第 7 节；`clocking-and-reset.md` 第 3 节表第 2、7、8 行、第 4.2 节。

**3. 为什么跨时钟域同步，去掉会怎样**
六个节拍互不相干的域，采样沿可能撞上数据沿。文档给的去掉后果分四类：一整排数读到"半新一半旧"；只亮一拍的脉冲被
三级电平链整个吃掉（对面当作没发生，提交/发布根本不存在）；组合逻辑的毛刺被采成假事件；二进制指针打两拍会读出一个
值域里没出现过的数。
依据：`clocking-and-reset.md` 第 3、4 节；`mechanics.md` 第 3 节第 ②③ 层；`myths.md` 第 3 节。

**6. 一句无专有名的话**
两条各按自己节拍走的电路之间要传一个只持续一拍的动静时，不能把线直接连过去：发的一方每发生一次就把一根线拧到反面，
收的一方把它连打三拍、再取相邻两拍相异，于是必然得到一个对面来得及看的单拍——代价是两次事件若挤在对面看一眼的
间隙里会被并成零次。
依据：`clocking-and-reset.md` 第 4.2 节第 ①③ 层（自述为"我自己复述"）。

**7. 零术语简化说法可能带偏处**
`clocking-and-reset.md` 第 4.1 节第 ① 层："让一个开关先被新时钟连续看三次，看完才用。"它自己写的误导提示是：
*简化说法，会在"这个开关其实只是一拍亮一下"的情形下误导你——那一拍会被整个吃掉，精确版见 4.2*。
同族还有第 4.3 节第 ① 层（"这排数还在变就抄到半新一半旧"）。（备选：`myths.md` 第 7 节第 ① 层"不用发命令"
会被读成"不用等"。）

**8. 与 build/ 报告数字对不上先怀疑什么**
先怀疑"我念的不是同一份件、不是同一轮、甚至不是同一个量纲"，再怀疑硬件：文档明说冻结门禁件的端点总数 39915 与
当前位流的 51135 是两个读数，且两份同名报告内容不同；余量(ns)与时长(ms/拍)永不相减；"没判"与"判红"是两个不同退出码；
行号本身会漂，要跑那把引用尺子。
依据：`hands-on.md` 实验 1（"看到别的说明什么"）与第 8 节、实验 3；`myths.md` 第 4 节第 ⑤ 层、第 12 节；`mechanics.md` 第 0 节③。
