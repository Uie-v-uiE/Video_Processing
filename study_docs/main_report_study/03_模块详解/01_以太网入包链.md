# 模块详解 01 · 以太网入包链（RGMII → 协议解析 → 拼帧 → CDC → AXI 写 DDR）

> 本篇是全套文档最长的一篇，因为本工程一半的难点都在这条链上。
> 所有 `文件:行` 都相对仓库根 `Video_Processing/`。
> 标注「**推断**」的条目是代码里没有注释、由逻辑推出来的解释，不要当结论引用。

---

## 0. 先建立两个全局事实

### 事实一：整个协议栈其实只有**一个时钟域**

```verilog
// src/rtl/eth/gmii_to_rgmii.v:39
assign gmii_tx_clk = gmii_rx_clk;
// src/rtl/eth/rgmii_rx.v:42
assign gmii_rx_clk = rgmii_rxc_bufg;      // = BUFG(rgmii_rxc)
```

所以 `arp / icmp / udp_rx / eth_ctrl / frame_reasm` 全部跑在 PHY 恢复出来的那根 125 MHz 上，
**协议栈内部没有任何真正的跨时钟域**。全链只有两个异步 crossing 点：`u_cdc`（数据）与
`u_commit`（`frame_done` 事件）。这解释了两件事：
- 为什么协议栈的路径都在 `eth_rxc` 这个时钟组里；
- 为什么 `eth_rxc` 域一旦时序紧张，全链一起紧（它承载了最多的逻辑）。

### 事实二：显示侧**不是**由 ETH 直写 BRAM 的

`pl_video_top.v:45-48` 有一组 `eth_wr_en/eth_wr_addr/eth_wr_data/eth_wr_clk` 输入，
但**全文件没有任何地方使用它们**（遗留自第二版"ETH 直写显示 BRAM"的结构）。
现在的数据路径是：`frame_reasm → dc_fifo → axi_frame_saver64 → HP0 → DDR bank`，
显示侧再由 `axi_frame_writer_gated` 在消隐窗口把整帧读回 BRAM。
读代码时如果以为"网线来的数据直接进显示 BRAM"，就会完全误解拖影与帧尾这两个问题。

## 1. 链路总览与逐段信号

```
[PHY RTL8211]
   │ RGMII: eth_rxc(125M) + eth_rx_ctl + eth_rxd[3:0]   （DDR，4bit）
   ▼
① rgmii_rx      IDELAYE2×5 + IDDR×5 → gmii_rx_clk / gmii_rx_dv / gmii_rxd[7:0]
   │             （采样用 BUFIO，逻辑用 BUFG，同一根时钟两张网络）
   ▼
② gmii_to_rgmii 只是把 rx/tx 两个子模块包在一起，并 assign gmii_tx_clk = gmii_rx_clk
   │
   ├─► ③ arp_rx    ──► arp_tx        （ARP 请求→应答）
   ├─► ④ icmp_rx   ──► icmp_tx       （ping→echo reply，数据过 sync_fifo）
   └─► ⑤ udp_rx    ──► udp_tx(常闭)  （视频入口）
                                        │
                                        ▼
                              ⑥ frame_reasm   4 字节小端 offset → 半字写流
                                        │  fb_wr_en / fb_wr_addr[18:0] / fb_wr_data[15:0]
                                        │  + reasm_flush（每包一根标记）
                                        ▼
                              ⑦ dc_fifo (u_cdc)  36bit × 8192，格雷码异步 FIFO   ← 跨域点 A
                                        │ axi_clk = 100 MHz
                                        ▼
                              ⑧ axi_frame_saver64 (u_saver)  4×16bit → 64bit + keep/WSTRB
                                        │
                                        ▼
                              ⑨ AXI HP0 → DDR 0x1000_0000 / 0x1008_0000
                              ⑩ ddr_bank_commit (u_commit) 决定何时提交/换 bank  ← 跨域点 B
```

三个解析器（ARP/ICMP/UDP）**并行**吃同一份 `gmii_rxd`，各自重数前导码与以太头
（`eth_udp_video_top.v:121/134/148`）。好处是零仲裁、互不影响；代价是同一段字节流被解析三遍。

## 2. ① `rgmii_rx.v`：把 4bit 双沿还原成 8bit

| 关键点 | 位置 | 说明 |
|--------|------|------|
| 时钟两路 | `:42,:46-55` | `BUFG` 给 fabric（`gmii_rx_clk`），`BUFIO` 给 IDDR（IO 专用低延迟网络）。IDDR 必须用 BUFIO，这是 7 系列 DDR 输入的硬性要求 |
| 半字节拼接 | `:137-138` | `IDDR.Q1 → gmii_rxd[i]`（上升沿，低半字节）、`Q2 → gmii_rxd[4+i]`（下降沿，高半字节）。顺序符合 RGMII"低 nibble 先" |
| 控制位 | `:43` | `gmii_rx_dv = dv_t[0] & dv_t[1]`：上升沿采 DV、下降沿采 ERR，两者与 ⇒ 任一无效即视为无数据 |
| 输入延迟 | `:69-71` | `IDELAY_TYPE="FIXED"`、`IDELAY_VALUE=15`、`REFCLK_FREQUENCY=200.0` ⇒ 约 `15×78 ps ≈ 1.17 ns` |
| 原语分组 | `:59,:67,:109` | 全部打 `IODELAY_GROUP="rgmii_rx_delay"`，`:60-64` 唯一一份 `IDELAYCTRL`（`.RDY()` 悬空、`.RST(1'b0)`） |
| IDDR 配置 | `:89,:131` | `SAME_EDGE_PIPELINED`、`SRTYPE="SYNC"`，所有动态控制引脚接地 |

**为什么要 IDELAY？** RGMII 是源同步，PHY 已内部加约 2 ns 延时，但 PCB 走线 + 时钟树延迟会把
采样点推出数据眼。`IDELAY_VALUE` 就是"把采样沿往哪个方向挪多少"的旋钮——
**它是"能 ping 通但丢包"这类现象的第一顺位调节量**（**推断**：代码没有注释解释 15 的来历）。

**一个值得注意的缺口**：`IDELAYCTRL.RDY` 悬空 ⇒ 逻辑不等 IDELAY 校准完成。
实际靠 `system_top.v:98-102` 的 24 bit 计数器（50 MHz 下约 168 ms）延后 `eth_rst_n` 释放来间接保证（**推断**）。

**没有 TB**：Xilinx IO 原语需要 unisim 库，而 `sim/run_sim.tcl` 只编译 `src/rtl/**/*.v` ⇒
这一层只能在板上验证（判据：`ping` 通 + 逐字命中率）。这也是为什么本工程把大量精力放在
"不看屏幕的判据"上——**最外面那一层根本无法仿真**。

## 3. ③④ ARP 与 ICMP：硬件协议栈的"最小可用实现"

### ARP（`arp_rx.v` / `arp_tx.v` / `arp.v`）

- 状态机是 **1-hot 5 bit**（`arp_rx.v:32-36`），且**输出用 `case(next_state)`**（`:113`）
  ⇒ 少一个流水线气泡：`skip_en` 生效那一拍就按新状态解析当前字节。
- 字段抓取按字节计数移位拼接：目的 MAC `:134-137`、EtherType `:140-146`（低字节直接读
  `gmii_rxd` 而不读刚写的寄存器，避开同拍竞争，`:142-145`）、
  opcode `:154`、发送方 MAC `:156`、发送方 IP `:158`、目标 IP `:160`，判决在 `:164-177`。
- **MAC 过滤接受"本机 或 广播"**（`:137`）——必须接受广播，否则收不到 ARP 请求本身。
- 学到对端地址后**不清零**（`:168-173` 只清暂存器）⇒ `src_mac/src_ip` 始终锁着
  "最后一个问过板卡的站点"，并被回灌给 `u_arp/u_icmp/u_udp` 当发送目的地址
  （`eth_udp_video_top.v:126/140/153`）。**上位机换 IP 后必须先重新 ARP 一次**。
- 发送侧 `arp_tx.v:198` 只在 `des_mac/des_ip` 非零时才覆盖模板 ⇒ 没学到地址时退回参数默认值。
- **ARP 永远是"应答"**：`arp_tx.v:216-217` 按 `arp_tx_type` 决定 opcode，而
  `eth_ctrl.v:68` 把 `arp_tx_type` 写死为 1。
- 错误帧处理：任一条判决不过 → `error_en → st_rx_end`，而 `st_rx_end` 要等
  `gmii_rx_dv==0` 才回 idle（`:184`）⇒ **一个坏帧会独占状态机直到它结束**，
  这是"先解析完再复位"的写法，不是 bug。

### ICMP（`icmp_rx.v` / `icmp_tx.v`）

ping 的硬件应答，两个值得学的实现技巧：

1. **校验和不在回复时重算**，而是**收的时候顺手累加**：
   ```verilog
   // icmp_rx.v:267-270  偶奇两字节拼成大端 16bit 字累加
   if (icmp_rx_cnt[0] == 1'b1)
       reply_checksum_add <= {icmp_rx_data_d0, gmii_rxd} + reply_checksum_add;
   ```
   回复时只需把 ICMP 头 + 这个累加值折叠两次（`icmp_tx.v:281-291`）。
   ⇒ **把 O(N) 的工作摊到流式接收里**，避免发送时再来一遍累加树。
2. **IP 头校验和**用 10 个 16bit 字一次求和 + 两次折叠（`icmp_tx.v:265-275`）。
3. 数据先存 `u_icmp_fifo`（`sync_fifo` 2048×8），回复时"提前两拍"发读请求
   （`icmp_tx.v:319-321`），补偿同步 RAM 的 1 拍读延迟。

**已知不严谨处（值得写进文档而不是假装没有）**：
- 不校验 IP 头校验和、不校验 ICMP 校验和、不看 code（`icmp_rx.v:228,:237`）；
- `icmp_data_length = total_length - 28`（`:200`）**隐含假设 IHL==5**，
  而 `ip_head_byte_num` 算出来了却没用到（`:195`）⇒ 带 IP options 的包会算错长度（**推断**：实际 ping 不带 options）；
- 奇数长度 payload 的补零位置与 RFC1071 不一致（`:259-260`），因为标准 ping 长度都是偶数所以从未暴露（**推断**）。

## 4. ⑤ `udp_rx.v`：视频入口，以及三个必须知道的缺口

状态机 7 态（`:34-40`），过滤链只有四关：
目的 MAC 命中（`:156`）→ EtherType=0x0800（`:157`）→ 协议号=17（`:168`）→ 目的 IP（`:178-179`）。

### 缺口 1：**没有目的端口过滤**

```verilog
// udp_rx.v:190-202  st_udp_head 里只做了这两件事：
udp_byte_num   <= {udp_byte_num[7:0], gmii_rxd};     // 收长度字段
data_byte_num  <= udp_byte_num - 16'd8;              // 载荷 = 长度 - 8
```

源端口（cnt 0/1）与**目的端口（cnt 2/3）被完全跳过**，全文件没有端口常量。
所以：**任何发到 192.168.1.10 的 UDP 包，不管什么端口，都会被当视频喂进 `frame_reasm`。**
`eth_udp_video_top.v:8` 的 `UDP_PORT=16'd5001` 参数一路传到 `system_top.v:126` 之后
**没有任何消费者**；真正做端口过滤的 `udp_rx_parser.v:120-126` 存在，但**从未被例化**
（只有 `sim/tb_udp_parser.v` 测它）。

### 缺口 2：**入包不做 CRC/FCS 校验**

`crc32_d8` 的三个实例全部挂在发送方向（`arp.v:100`、`icmp.v:117`、`udp.v:102`）。
`udp_rx` 收满 `data_byte_num` 就走（`:209`），最后 4 字节 FCS 从未被读。
能产出 `m_good`（帧结束无错且长度≥64）的 `gmii_rx_mac.v` 也**未被接入**。
⇒ 完整性唯一的判据是 `frame_reasm.v:122` 的双门限（行覆盖 + 字节数）。
**文档里绝不能写"UDP 包经过 CRC32 校验"。**

### 缺口 3：`st_udp_head` 没有 error 出口

`:93-96` 只有 `skip_en`。若某个包的 UDP 长度字段 < 8，`data_byte_num` 会下溢成一个巨大的 16bit 数
⇒ 状态机卡在 `st_rx_data` 直到被后续字节喂满或复位（**推断**）。
这也解释了"上位机随便改端口号，板子行为不变"的现象。

### 与下游的时序契约（这条很重要）

```verilog
// udp_rx.v:208-213   rec_en 是电平、贯穿整个 payload
rec_en <= 1'b1;
if (data_cnt == data_byte_num - 16'd1) rec_pkt_done <= 1'b1;   // 与最后一个 rec_en 同拍
```

`rec_pkt_done` 与最后一个 `rec_en` **同拍**成立，不是巧合，而是下游要求的：

```verilog
// frame_reasm.v:50-54 注释
// On the last byte p_valid && p_eof share a cycle and pkt_pay has not counted it yet,
// so add that byte here (and only here) to avoid an off-by-one that would reject the
// final packet forever.
wire [31:0] bytes_all = cover + pkt_pay + (p_valid ? 32'd1 : 32'd0);
```

**"包尾脉冲和数据同拍"是一个跨模块契约**。谁以后把 `rec_pkt_done` 改成"晚一拍"，
就会得到"最后一帧永远判定为不完整"这种极难查的现象。

`sof` 也不在 `udp_rx` 里产生，而是 top 用状态拼出来的：
`eth_udp_video_top.v:182` `wire udp_sof = udp_rec_en && !in_udp_pkt;`。

## 5. ⑥ `frame_reasm.v`：offset 拼帧与"提交双门限"

### 5.1 状态机

```verilog
// frame_reasm.v:29
localparam [2:0] S_OFF0=0, S_OFF1=1, S_OFF2=2, S_OFF3=3, S_DATA=4;
```
- `p_sof` 那一拍直接把 `off[7:0]` 收掉并跳 `S_OFF1`（`:72-74`）；
- `S_OFF1/2/3` 依次填 `off[15:8]/[23:16]/[31:24]`（`:77-81`），
  在 `S_OFF3` 同时锁存 `pkt_start` 并判断"这包是不是从帧头开始"（`:83-87`）；
- `S_DATA` 用 `have_lo` 两个字节拼一个 16bit 写（`:90-105`）；
- `p_eof` 回 `S_OFF0` 并拉一根 `flush`（`:113-114,:139`）。

### 5.2 `wr_addr` 的量纲（**必须记住，全链最容易错的一件事**）

```verilog
// frame_reasm.v:95
wr_addr <= off[18:1];      // 字节偏移右移 1 位
// frame_reasm.v:104
off <= off + 2;            // 每个写前进 2 字节
```
⇒ **`fb_wr_addr` 的单位是 16bit 半字（= 1 个像素），不是字节。**

下游再移 2 位得到 64bit 字索引，出 AXI 时才乘 8 换回字节地址：
```verilog
// axi_frame_saver64.v:95
wire [18:0] in_widx = wr_addr[18:2];
// axi_frame_saver64.v:117
q_addr[...] <= pack_base + {10'd0, cur_widx, 3'b000};
```

| 层 | 信号 | 单位 | 满帧值 |
|----|------|------|--------|
| UDP 载荷 | `off` / `pkt_start` | 字节 | 307200 |
| GMII 域对外 | `fb_wr_addr` / `sav_a` | **16bit 半字（=1 像素）** | 153600（18 bit） |
| axi 域打包 | `cur_widx` | **64bit 字** | 38400 |
| AXI/DDR | `m_axi_awaddr` | 字节 | `bank + widx×8` |

推论：**offset 必须是偶数**（`off[0]` 被丢掉），否则后一个字节会盖到同一半字上（**推断**：无检查）。

### 5.3 行索引为什么用除法

```verilog
// frame_reasm.v:44-48
// IMG_W=512 → ROW_STRIDE=1024 → off>>10. Must NOT use off[16:1] (16-bit
// pixel index truncates ~172/300 rows → frame_done never → SRC1 black).
localparam integer ROW_STRIDE = IMG_W * 2;
wire [31:0] row_idx = off / ROW_STRIDE;
```
注释里记的是一个真实事故：用位切片算行号会截断 ⇒ `frame_done` 永远不成立 ⇒ 屏幕全黑。
（`ROW_STRIDE` 是 1024，综合器本来就会优化成移位，用除法写法是为了**正确性优先于写法**。）

### 5.4 提交双门限

```verilog
// frame_reasm.v:116-122
// Completeness gate: every source row touched AND all
// FRAME_BYTES arrived. The row bitmap alone lets a lost
// packet through as a "complete" row, and the hole (a BRAM
// word never written = 0) shows as a black stripe that survives a stopped stream.
if (rows_hit >= IMG_H[15:0] && bytes_all >= FRAME_BYTES) frame_done <= 1;
```
**两个条件都要**：只看字节数会漏"总数对但中间有空洞"；只看行覆盖会漏"每行都碰过但行内缺一段"。

### 5.5 三个易踩的点

1. `p_good` 被 top 常闭为 `1'b1`（`eth_udp_video_top.v:188`）⇒
   `frame_reasm.v:135-138` 的坏帧分支**永不执行**，`stat_bad` 只统计"短帧"（`:132`）。
2. **越界只统计不拦截**：`:93-95` 的 `wr_en/wr_addr/wr_data` 是无条件置起的，
   `:96` 的 `if (off < FRAME_BYTES)` 只决定要不要记行覆盖，`:102` 只加 `stat_oob_off`。
   ⇒ 越界写照样发给下游（靠地址落在 bank 外才没造成破坏）。别把它描述成"越界被丢弃"。
3. `row_ok[row_idx[8:0]]`：`row_ok` 宽 300 bit（`:41`）却用 9 bit 变址 ⇒
   综合成一大片 mux；这也是 `IMG_H` 一改就要重审的地方（**推断**）。
   （顺带：这条 mux 链不在最差路径上，最差路径是 `bytes_all` 那条，见 06 篇时序专章。）

### 5.6 这个模块的测试覆盖（全仓最厚）

| TB | 测什么 |

| `tb_udp_reasm.v:17` | 正常 / 乱序 / 丢包 / 重复 / 跳帧 / 坏包 |

## 6. ⑦ `dc_fifo.v` 与 ⑧ `axi_frame_saver64.v`：跨域与打包

### CDC 写侧打包（`eth_udp_video_top.v:212-220`）

```verilog
wire cdc_wr = (fb_wr_en || reasm_flush || flush_pend) && !fifo_full;
wire [35:0] cdc_data = fb_wr_en ? {1'b0, fb_wr_addr, fb_wr_data}
                                : {1'b1, 19'd0, 16'd0};      // bit35 = flush 标记
// flush 让路给真实数据，但用 flush_pend 补投，保证标记不丢
else if (reasm_flush && fb_wr_en && !fifo_full) flush_pend <= 1'b1;
else if (flush_pend && !fb_wr_en && !fifo_full) flush_pend <= 1'b0;
```
**36 bit = 1 标记 + 19 地址 + 16 数据**。把"包尾"编码成数据流里的一个标记位，
是异步 FIFO 传递"事件+数据"混合流的标准手法（否则接收端无法知道包边界）。

### 读侧三级流水（`:239-247`）

```verilog
fifo_rd  <= !fifo_empty && !sv_full;      // 打包器满 ⇒ 停止取数（反压）
cdc_d1   <= fifo_dout;                    // BRAM 输出寄存器之后第一级
cdc_d1_v <= fifo_rd;
sav_en    <= cdc_d1_v && !cdc_d1[35];
sav_flush <= cdc_d1_v &&  cdc_d1[35];
```
`dc_fifo` 的读是**同步读**（`dc_fifo.v:60-61`，1 拍延迟），所以这里再打两级形成
"地址发出 → 数据出来 → 打上 valid"的配对。**理解这三级的对齐关系，
是理解第五版帧尾 bug 的前提**——`ddr_bank_commit` 的 `tail_drained`
判据必须把这三级全算进去（`ddr_bank_commit.v:58`）。

### `axi_frame_saver64` 的四个设计要点

1. **AW/W 同拍挂出、各自保持到被接收**（`:145-167`），B 通道永不反压（`m_axi_bready<=1`）；
2. **`OST=8` 在途**（`:65`）——吞吐由"在途深度 ÷ 往返延迟"决定，见前置知识 03 篇；
3. **`outst` 只减不回绕**（`:155`）：
   ```verilog
   else if (!have && b_ok) outst <= (outst == 4'd0) ? 4'd0 : outst - 4'd1;
   ```
   注释（`:153-154`）解释得很直白：万一上游多回一个 B，回绕成 15 会让 `have` 永远不成立
   ⇒ 整条入包链卡死（板上"冻结"类症状）。**宁可少计也不要锁死**；
4. **`WSTRB` 按 lane 生成**（`:90-91`）：
   ```verilog
   assign m_axi_wstrb = { {2{keep_r[3]}}, {2{keep_r[2]}}, {2{keep_r[1]}}, {2{keep_r[0]}} };
   ```
   历史：恒 `0xFF` 时"同一个 64bit 字被相邻两包分两次写"会把前一次覆盖成 0
   ⇒ 1396 B 分包每帧约 111 处 4 字节黑洞（`:78-81` 注释）。
5. 打包 FIFO 存储是**分布式 RAM**（`:54-56` 属性 + `:111-121` 独立无复位写块），
   这是第五版 V7.0 的成果，写法原因见前置知识 09 篇。

## 7. `eth_ctrl.v`：发送总线的仲裁，以及一个已知松口子

```verilog
// eth_ctrl.v:161-162
end if ((arp_rx_flag && (udp_tx_busy == 1'b0)) ||
        (arp_rx_flag && (icmp_tx_busy == 1'b0))) begin
```
两条以 `||` 相连 ⇒ 等价于 `arp_rx_flag && !(udp_tx_busy && icmp_tx_busy)`，
也就是**只有两路同时在忙才不发 ARP**。若 ICMP 正在发而 ARP 插进来，
`protocol_sw` 立刻切回 `2'b00`，会把 ICMP 帧的后半段截断（线上出现半帧 + ARP 头）。
这是原始例程（正点原子 eth_udp）的写法，本仓库未改 ⇒ **应当作已知限制记录**。

另外：`eth_ctrl` 的收侧合并输出（`rec_en/rec_data`）在 top 里接到
`fifo_rec_en/fifo_rec_data` 之后**没人用**（`eth_udp_video_top.v:105-106,:171`）；
视频数据绕开了它（`u_udp.rec_data → u_reasm.p_data`，`:150→:187`）。
所以它是"历史遗留的合并层"，读代码时不要以为数据经过它。

## 8. `sync_fifo.v`：一个"为了综合而写对"的样本

```verilog
// src/rtl/eth/sync_fifo.v:3-4（文件头注释）
// OPT: 存储阵列去掉异步复位，便于推断 BRAM（大深度 icmp_fifo 原先落到寄存器堆，
//      导致 eth_rxc@125MHz 域内路径 WNS 为负）。
```
**这段注释就是本工程血泪史的浓缩**：同一个坑（数组写放在带异步复位的块里）
在 125 MHz 域曾经真实地把时序打成负数，修好之后写进了文件头。
而 `axi_frame_saver64` 直到第五版才按同样方式修（它的注释 `:111-114` 记着 FF=32904 vs 85 的实测对比）。

满/空判定用"多一位的翻转位"（`:24-26`），是**单时钟** FIFO；
跨时钟必须用 `dc_fifo`（格雷码）。两者不要混用。

## 9. 本链的测试覆盖地图（以及空白）

| 模块 | TB | 备注 |
|------|----|------|
| `rgmii_rx` / `gmii_to_rgmii` / `rgmii_tx` | **无** | IO 原语无法用 `run_sim.tcl` 那套流程仿真 ⇒ 只能板上验 |
| `arp_rx/arp_tx/arp` | **无** | 板上判据 = `ping` 之前必须先 ARP 成功 |
| `icmp_rx/icmp_tx/icmp` | **无** | 板上判据 = `ping` 通 |
| `udp_rx` / `udp_tx` | `tb_eth_video.v` | GMII 级 `udp_tx→udp_rx` 回环，断言 68 字节载荷 |
| `udp_rx_parser`（未上板） | `tb_udp_parser.v` | 含"wrong port dropped"——**注意它测的是未例化的模块** |
| `crc32_d8` | `tb_crc32.v` | 测初值/改变/清零/确定性，**未与标准 CRC 向量对齐** |
| `sync_fifo` | `tb_sync_fifo.v` | 读写计数比对 |
| `frame_reasm` | 6 个 TB（见 §5.6） | 覆盖最厚 |
| 整链 | `tb_v6_ingress_integrity` / `tb_v6_pingpong` / `tb_v6_tail_bank` / `tb_v6_cover_gate` | 逐字比对 + 换页 A/B |

> 由此得出一个诚实的结论：**本工程最外面的三层（IO/ARP/ICMP）没有仿真覆盖**，
> 它们的正确性只由板级 `ping` 与逐字命中率证明。
> 想补的话，正确做法是"用 GMII 级注入 + 检查 `arp_tx` 的输出字节流"，
> 而不是去仿真 IO 原语。
