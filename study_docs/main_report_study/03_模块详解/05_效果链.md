## 0. 一句话职责与三条不变量

**职责**：对**右半窗**的像素流做 5 个可独立开关的效果，逐像素流式处理、不额外占存储帧。

| # | 不变量 | 靠什么 | 违反了会怎样 |
|---|--------|--------|--------------|
| E1 | 效果只作用于右窗 | `de_in = de_d[3] && !left_d[3]`（`pl_video_top.v:415`） | 左窗不再是「原图对照」，两窗失去可比性 |
| E2 | 每个效果**无论开关都占同样的列延迟** | 每级 `dout <= bypass ? ... : ...` 都是寄存器输出 | 打开某个效果时整幅图像横向跳动 |
| E3 | 使能位变化不产生中间态 | `effect_ctrl` 3 级捕获（`effect_ctrl.v:12-30`） | 切换瞬间出现半开半关的行 |

E2 有一个**例外**，就是 §5 里 blur 的旁路行为 —— 它违反了 E2 的精神（旁路时输出的是
上一行的像素），这也是「关掉所有效果后右窗仍与左窗差一行」的根因。

## 1. 级联结构

```verilog
// proc_pipeline.v:24-28  bypass = ~effect_en[i]
din ─► gray(bit0) ─► binary(bit1) ─► box_blur(bit2) ─► sobel(bit3) ─► invert(bit4) ─► dout
```

- 顺序是**硬编码的**：先灰度→二值（二值化作用在灰度上），再空间滤波，最后反色。
- 位序：`effect_en[0]=gray, [1]=binary, [2]=blur, [3]=sobel, [4]=invert`
  （`proc_pipeline.v:3-4`）。**左起字符 = bit0**，三处一致：串口 `main.c:74` 的
  `en |= bit << n`、OSD `EN=` 第一个字符打 `effect_en[0]`（`osd_overlay.v:102-106`）、
  `build/tcl/set_src.tcl:3`。
- 串口 `00111` ⇒ 开 blur+sobel+invert，关 gray/binary。
- `proc_pipeline.v:12` 的输入 `rotate_active` 注释自述 "retained for status"，
  **模块体内零引用**（综合器也确认 `Synth 8-7129 ... has no load`，`build/build_r05_skid.log:643`）。

## 2. 逐效果的算术

### 2.1 `proc_gray`（1 拍）

```verilog
r5=din[15:11]  g6=din[10:5]  b5=din[4:0]          // :12-14
r8={r5,r5[4:2]}  g8={g6,g6[5:4]}  b8={b5,b5[4:2]} // :16-18  MSB 复制扩位
y16 = r8*77 + g8*150 + b8*29                      // :19-21  BT.601
y8  = y16[15:8]                                   // 系数和 77+150+29 = 256 ⇒ 恰好右移 8，无溢出
gray = {y8[7:3], y8[7:2], y8[7:3]}                // :22  回包 565，纯截断无舍入
```

- 77/150/29 ÷ 256 = 0.3008 / 0.5859 / 0.1133 ≈ BT.601 的 0.299/0.587/0.114。
  注释 `:19` 自己就写了这个换算。
- **同一个「565→888 的 MSB 复制」写法在四处独立出现**：
  `proc_gray.v:16-18`、`proc_binary.v:16-18`、`proc_sobel.v:24-26`、`split_display.v:45-47`。
  改位段处理时必须同时改四处（这是一个真实的维护风险）。
- 回包用 `y8[7:3]` 给 R/B、`y8[7:2]` 给 G（5/6/5 位段），
  ⇒ **灰度图实际上把 8 bit 亮度量化回了 565**，动态范围从 256 级掉到 256→(32,64,32) 的组合。

### 2.2 `proc_binary`（1 拍）

```verilog
y16 = r8*77 + g8*150 + b8*29;  bin = (y16[15:8] >= threshold);   // :19-20
bw  = bin ? 16'hFFFF : 16'h0000;                                 // :21
```

- **它重新算了一次 y8**，不依赖上一级的输出 ⇒ gray 和 binary 同开时，
  二值化作用在「已量化回 565 的灰度」上，有效阈值有轻微偏移。〔推断〕
- `>=` ⇒ **阈值本身判白**。
- 阈值来源链：AXI GPIO `bit[15:8]` → `threshold` → `effect_ctrl` 3 级 → `th_sync` → 本模块端口
  （`system_top.v:164`、`effect_ctrl.v:8,13,26-29`、`pl_video_top.v:84-89,412`）。
- 复位默认 **80**（`effect_ctrl.v:19-22` 三处同值），PS 默认也是 80（`main.c:29`），
  UART `TH<dec>` 限幅 0..255（`main.c:102-106`）。
  ⚠️ 但 `build/tcl/set_src.tcl` 写 GPIO = `0x00010000` ⇒ **threshold 被清成 0**（全白），
  这是一条容易踩的「JTAG 直控路径与 PS 默认值不一致」。

### 2.3 `proc_box_blur`（3 拍列延迟，恒定下移 1 行）

```verilog
(* ram_style="block" *) reg [15:0] lb0 [0:511], lb1 [0:511];    // :18-19
lb0[x_in] <= lb1[x_in];  lb1[x_in] <= din;                       // :25-30，仅 de_in
r0 = lb0[x_in];  r1 = lb1[x_in];                                 // :32-33 组合（异步）读
p00<=p01; p01<=p02; p02<=r0;  ...                                // :60-64 3×3 滑窗，仅 de_in
rs = p00[4:0]+p01[4:0]+...+p22[4:0]        (10 bit)              // :36-44
rp = rs*57;  r_avg = rp[13:9]                                    // :46-52  除以 9 用乘 57>>9
avg = {r_avg, g_avg, b_avg}                                      // :53
dout <= (bypass || y_d1==0) ? p11 : avg;                         // :69-72  ★旁路输出 p11
```

- **`×57 >> 9`**：57/512 = 0.111328 > 1/9 = 0.111111 ⇒ 正偏 ≤ 1 LSB。
  用常数场（R=31,G=63）验证过结果精确等于原值 ⇒ 无饱和问题。〔推断，由位运算〕
- **按 R/G/B 三分量独立平均，不是亮度域模糊** ⇒ 彩色图模糊后色度也一起糊，
  与「先转亮度、模糊、再上色」的结果不同。本工程选择前者因为省两次转换。
- 寄存器数：9×16 + de 链 + `y_d1`(12) + dout = **175 个触发器**（`:15-16,21-23`）。
- ★ **旁路输出 `p11`（3×3 窗中心 = 上一行的像素）而不是 `din`**
  ⇒ 即使 blur 关闭，右窗图像仍恒定**下移 1 行**（`report` 里没写；代码 `:69-72` 是唯一事实）。
  模块头注释 `:2` 写的 "bypass => center pixel" 字面没错但**极易误读**成「中心 = 当前像素」。

### 2.4 `proc_sobel`（3 拍，使能时再 +1 行位移）

```verilog
lb1[x_in] <= y8;                                  // :27-34  行缓存存 8bit 亮度（不是整像素）
Gx = -p00 -2*p10 -p20 +p02 +2*p12 +p22            // :40-41  中心列不参与
Gy = -p00 -2*p01 -p02 +p20 +2*p21 +p22            // :42-43  中心行不参与
agx = gx[10] ? -gx : gx;   mag = agx + agy;       // :44-46  曼哈顿近似，无开方
m8  = (mag > 255) ? 255 : mag[7:0];               // :47     饱和
sobel_out = {m8[7:3], m8[7:2], m8[7:3]};          // :48     白边黑底
```

- 2 倍用 `{2'b0,p10,1'b0}` 移位实现；全部符号扩展到 **11 bit signed**
  （最大 |±1020| < 1024 ⇒ 不溢出）。
- `|Gx|+|Gy|` 是欧氏模的近似，误差最大约 41%（对角线方向），但**边缘检测不在乎幅值精度**。
- ⚠️ **完全没有行边界保护**：`y_in` 在本模块声明后**整条总线无负载**
  （`proc_sobel.v:12`，综合确认 `build/build_r05_skid.log:626-637`）
  ⇒ 不像 blur 那样对第 0 行做保护，首行用的是上一帧残留的行缓存内容。〔推断〕
- 寄存器数：9×8 + 2 + 16 + 1 = **91 个触发器**。

### 2.5 `proc_invert`（1 拍）

```verilog
r5=~din[15:11];  g6=~din[10:5];  b5=~din[4:0];  inv={r5,g6,b5};   // :12-15
```
按字段取反，**不是整 16 bit 取反**（两者结果相同，因为字段拼接恰好覆盖 16 bit —— 推断）。

## 3. 3×3 卷积的真实实现（以及 `line_cache.v` 是死的）

- **不是** `video/line_cache.v`。那个文件存在、有双口和越界读回黑的处理，
  但**全 `src/` 没有任何例化点**（`report/MODULES.md:79` 也确认「旧 line_cache（左扫右读）废弃」）。
- 真实实现：**每个算子两片行缓存 + 3×3 移位寄存器阵列 `p00..p22`**，
  属于**逐像素流式滑窗**，不是「取窗口」式随机访问。
  行数只需 **2 行**（`lb0`=row−2、`lb1`=row−1），第三行由 `din` 直接给。
- **窗口建在目标域（显示域）**：`x_in/y_in` 用的是画布坐标 `cx_d[3]/cy_d[3]`
  （`pl_video_top.v:415-417`），输入流是「逆映射之后的右窗光栅」。
  ⇒ 设计意图是「看到的是屏幕上的图像被模糊」而不是「源图被模糊后再旋转/缩放」。
  两者在旋转/缩放下**结果不同**，目标域的好处是核始终是正交于屏幕的 3×3、不会随旋转而歪。
- **边界处理**（三条都不完美，值得背下来）：
  1. 水平：`x_in=0` 时窗口的「左列」来自**上一行末尾**（移位只在 `de_in` 执行，
     `de` 在行尾行首之间不连续，`p*0` 保持不动）⇒ **回卷污染**；`x_in=511` 时右列来自下一行首像素。
     没有任何 clamp/复制边缘处理。
  2. 垂直：blur 用 `y_d1==0` 把第 0 行改判为旁路（`:69-70`），但旁路值本身是上一行的 `p11`，
     而且这个保护在行首有 1 拍错位（`y_d1@T = y_in@T-1` 而输出槽位对应 `y_in@T-2`）。
     sobel 完全没有该保护。
  3. 跨帧：行缓存不清零 ⇒ 首帧/换帧后头两行含上一帧数据。〔推断〕

### 3.1 一个由「2 倍行复制」引出的必然退化

`pl_video_top.v:113` 的 `cy = y>>1` 让**相邻两条显示行对应同一个源行**。
而行缓存的「上一行」是上一条**显示行**。于是：

```
偶数显示行：窗口三行 = 源 row-1, row, row      ← 上下邻居错采样
奇数显示行：窗口三行 = 源 row-1, row-1, row
⇒ 3×3 在垂直方向的实际源跨度只有 1.5 行，且逐行交替
```

**后果**：垂直方向的 Sobel 梯度与 blur 的垂直平均呈「梳齿」状退化。
这不是 bug 而是**选择的代价**：在目标域开窗 + 2× 放大 = 必然失去垂直分辨率。
如果想在源域做卷积，就得先把源行缓存接成真正的 3 个源行 ——
那需要在逆映射之后、显示行复制之前建窗，等于把卷积挪到 BRAM 读口那一侧，
代价是每源行要读 3 次（同一个读口，无法流水）。

## 4. 延迟账（本文档最实用的一节）

### 4.1 每级的列延迟与行偏移

| 阶段 | 列延迟 | 垂直行偏移 | 证据 |
|------|--------|-----------|------|
| gray | 1 | 0 | `proc_gray.v:29-30` |
| binary | 1 | 0 | `proc_binary.v:28-29` |
| box_blur | 3 | **−1 行（旁路与使能都一样）** | `proc_box_blur.v:65-68,69-72` |
| sobel | 3 | −1 行（仅使能时） | `proc_sobel.v:55-62` |
| invert | 1 | 0 | `proc_invert.v:22-23` |
| **合计** | **9 拍（与使能位无关，恒定）** | −1 行（全旁路）/ −2 行（sobel 开） | 上述 |

### 4.2 顶层声明的是 7

```verilog
// pl_video_top.v:405-406
localparam PROC_LAT = 7;  localparam LEFT_TAIL = PROC_LAT;   // 注释里没有推导
```

把「落后光栅多少拍」列成表（D 表示 `sig@T` 对应光栅槽位 `T−D`）：

| 信号 | D | 证据 |
|------|---|------|
| `de`/`cx`/`cy` | 0 | `:105-113` |
| mapper 输出（3 级） | 3 | `:125-130,147-149,154-160` |
| `rd_addr_q` | 4 | `:363` |
| `fb_rd`/`pix_left`/`pix_right` | 5 | `:372,396-403` |
| **`de_in`（进效果链）** | **4** | `:415` ← 与 `din`(5) 差 1 拍 |
| `orig_disp`（左路 7 级 skid 后） | 12 | `:441` ⇒ 与 `x_d11`(12) **精确一致** ✅ |
| **`pipe_dout`（右路）** | **14** | 5 + 9 ⇒ 比光栅基准晚 **2 列** ❌ |
| 彩条右路 `bar_r_d2` | 6 | `:383-384,388,401` ⇒ 用彩条时错 3 列 |

**结论（三条不一致，都是代码事实）**：

1. `PROC_LAT=7` 与真实 9 拍不符 ⇒ 右半窗效果像素比其几何位置**晚 2 列**显示；
   同时右半窗的 OOB 遮罩 `oob_ro`（D=12）与像素（D=14）错 2 列
   ⇒ 缩放/旋转的边界处会出现 **2 像素宽的错切黑边**。〔推断，由 `:441-454` 与延迟链常量〕
2. `de_in`(D=4) 与 `din`(D=5) 在效果链入口就差 1 拍
   ⇒ blur/sobel 行缓存的「写索引」与「像素」整体错 1 列；
   而且 `pipe_de`（D=13）与 `pipe_dout`（D=14）不自洽 —— 顺便说 `pipe_de` 无人消费。
3. 彩条左路 `bar_l_d4`(D=5)、右路 `bar_r_d2`(D=6) ⇒ **SRC0 与 SRC1 下右窗水平配准差 1 列**。

〔推断〕`PROC_LAT=7` 是**板上标出来的经验值**：因为效果链内部 de 与数据通道各有安排，
净延迟不等于各模块标称值之和。如果要修，正确做法不是把 7 改成 9，
而是**把 `pipe_de` 真正接出来做判据**（它现在没人读），
让 `split_display` 的像素选择用效果链自己的 de，而不是用固定的 11 级抽头。

## 5. 实现层事实：`ram_style="block"` 被综合器拒绝了

```
WARNING: [Synth 8-6849] Infeasible attribute ram_style = "block" set for RAM
  "u_pl/u_pipe/u_blur/lb1_reg", trying to implement using LUTRAM        （sobel 同）
                                       — build/build_r05_skid.log:999-1002
Block RAM 最终映射： u_blur/lb0_reg  = 512x16 → 1×RAMB18                :1124
                     u_sobel/lb0_reg = 512x8  → 1×RAMB18                :1125
Distributed RAM：    u_blur/lb1_reg  = 512x16 → RAM256X1S ×32（LUTRAM） :1138
                     u_sobel/lb1_reg = 512x8  → RAM256X1S ×16           :1139
                     两行的 Inference 列都写 "Implied"，不是 "User Attribute"
```

**为什么 `lb0` 保住了 BRAM、`lb1` 没有**：`lb0` 的读被寄存器化了
（`:61-62` 的 `p02 <= r0` 在时钟沿读），而 `lb1` 是**组合读**（`:32-33`）
⇒ BRAM 要求同步读，LUTRAM 才允许组合读。
〔推断，由源码 + 报告对照〕

这正是 [前置知识 09](../00_前置知识/09_BRAM_LUTRAM与综合推断.md) 讲的规则的现场版：
**属性是请求，不是命令**；决定 BRAM 可行性的永远是「读口有没有寄存器」。
想省 LUT 的话，把 `r1 = lb1[x_in]` 改成 `lb1_q <= lb1[x_in]` 的寄存读、
再把滑窗多加一级即可（代价是列延迟 +1，需要同时重算 §4 那张表）。

## 6. 使能位怎么从 PS 到这里

```
AXI GPIO（axi_gpio_0，C_GPIO_WIDTH=32）@0x41200000     build_system_axigpio.tcl:47-49
  ↓ gpio_o[4:0]  = effect_en     system_top.v:164
  ↓ gpio_o[15:8] = threshold     同
  ↓ gpio_o[16]   = src_sel       同
  ↓ gpio_o[17]   = zoom —— RTL 里没接（system_top.v:165 把 zoom_en 绑成 1'b1）
effect_ctrl：en_meta → en_sync → effect_en（3 级，:12-30）
  ⚠️ 该模块**漏标 ASYNC_REG** ⇒ build/cdc.rpt 的 clk_fpga_0→clkout0_1 行
     「No ASYNC_REG = 13」把它算进去了
  ⚠️ 它也没做格雷码/握手，只是 2FF 型同步的多一级 ⇒ 对「准静态」控制总线可接受〔推断〕
```

PS 侧打包：`v = (cur_en & 0x1F) | (cur_thr<<8) | (cur_src<<16) | (cur_zoom<<17)`
（`main.c:33-40`）。详见 [模块详解 07](../03_模块详解/07_PS控制与上位机工具链.md)。
