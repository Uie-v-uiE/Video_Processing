## 怎么用这套文档

三条阅读路线，按你的目的选：

| 路线 | 适合谁 | 顺序 |
|------|--------|------|
| **A. 从零看懂这个工程** | 第一次读它的代码 | `00_前置知识` → `02_架构` → `03_模块详解` → `04_版本演进` |
| **B. 我要改某个模块** | 已经大致知道数据通路 | 直接跳到 `03_模块详解` 对应那篇，每篇开头都有「一句话职责 + 端口表 + 不变量」 |
| **C. 我要复现/排障** | 板子拿在手上 | `05_验证与上板` → `04_版本演进/02_问题与修复全记录` 的症状速查表 |
| **D. 我要做时序** | 会写 RTL、没做过静态时序分析 | `timing/README.md` 是入口：`00-from-zero-…`（比较的是什么、报告怎么看、五域余量）→ `01-methods-and-priority.md`（五个面的方法清单与优先级决策树，每条带代价与判据）→ `02-how-this-project-did-it.md`（本项目的九次单变量对照、IDELAY 抽头怎么算出来、哪些判负退回、还欠什么），数字出处在 `timing/90-numbers-index.md` |

**这一页本身就是目录**；`02_架构/01_整体数据通路.md` 是「架构图 + 跳转入口」，
如果只想了解全貌，读它那一篇就够，里面有指向其它所有文件的链接。

## 写作时踩到的元问题（先声明，免得被当结论引用）

1. **行号会漂**。所有引用都同时给信号名；发现对不上就以信号名为准。
2. 标了「**推断**」的条目是代码里没写注释、由逻辑或算术推出来的，不是作者原话。
   例如「`frame_reasm` 的 `FRAME_BYTES` 没有被例化覆盖，改分辨率会静默失配」就是推断，
   代码事实是 `eth_udp_video_top.v:185` 只传了 `IMG_W/IMG_H`。
3. 有 **4 处仓库文档与 RTL 不一致**，我在 `04_版本演进/02_问题与修复全记录.md` 里单列了一节，
   没有偷偷按文档写。
4. 这套文档写于第五版（资源/时序专项）期间，`frame_reasm` v5.1 的时序改写
   在 [02_DDR乒乓与提交锁](03_模块详解/02_DDR乒乓与提交锁.md) §6 与
   [04_版本演进/02](04_版本演进/02_问题与修复全记录.md) 里都有记录，
   但它是否已过全部门禁以 `report/OVERNIGHT_LOG.md` 的最新一轮为准。
