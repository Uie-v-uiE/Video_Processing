> 权威版本在仓库 `report/VERSION_LINEAGE.md`（对齐了远程分支 + 三个本地快照目录）。
> 这篇补充**读代码时的差异点**：每一版的 `src/rtl` 长什么样、

## 2. 数据通路在五个阶段里的形态变化

这是读历史分支时最有用的对照表 —— **同一件事在不同版本里根本不在同一个模块里**。

| | V1（PS 网口） | V2（PL 网口） | V3（+缩放） | V4（零丢字） | V5（当前） |
|---|---|---|---|---|---|
| 收 UDP | PS + lwIP | PL `udp_rx.v` | 同 V2 | 同 | 同 |
| 数据落哪 | PS DMA 到 DDR | **ETH 直写显示 BRAM** | 直写 BRAM | 直写 BRAM→改 DDR 乒乓 | DDR 乒乓 |
| DDR 角色 | 中转 | 无（或仅 FILL） | 无 | **主存储** | 主存储（+`TAIL_GUARD`） |
| 显示源 | HP0 读 DDR | 单口 BRAM | 单口 BRAM | 单口 BRAM + 消隐拷贝 | `frame_buffer_w64`（32768+8192 分块） |
| 拼帧判据 | — | 累计字节数 | 累计字节数 | **行位图 ∧ 字节量**（`rows_hit>=300`） | 同 + `bad_frame` |
| 写 DDR 吞吐 | PS 内部 | — | — | **OST=8 流水化** | 同（打包 FIFO 改 LUTRAM） |
| 跨钟 | 无 | 直写无跨钟 | 无 | `dc_fifo` 36×8192 | 同 + `ddr_bank_commit` |
| 效果窗口 | 源域 → **旋转时强制旁路** | **目标域 3×3** | 同 | 同 | 同 |
| 缩放 | 无 | 无 | **Q8 inv_scale 256..512** | 同 | 同（`zoom_en` 硬绑 1） |
| 时序 | 未收敛（WNS −6.158） | 未收敛 | `+0.201`/收敛 | +0.675 → +0.499 | **+0.974（本夜 R06）** |

## 3. 每一版具体"动了哪根线"

### V1 → V2：把数据面从 ARM 搬进逻辑

- 删：lwIP、XEmac 收包、PS→DDR 的 DMA 描述符。
- 加：`src/rtl/eth/` 全部 20 个文件（约 2700 行）。
- 关键连接改变：`frame_reasm` 的 `wr_en/wr_addr/wr_data` **直接**接到显示 BRAM 写口。
  ⇒ 这就是 V2/V3 拖影的结构原因：**写入与扫描异步进行**。
- 顺带修掉的：旋转时 blur/sobel 被强制旁路（V1 的 `by2 = ~effect_en[2] | rotate_active`）
  ⇒ 改成目标域 3×3，`rotate_active` 降级为 status 位（今天的 `proc_pipeline.v:12`
  那句 "retained for status" 就是这次改动的化石）。

### V2 → V3：加缩放，但没碰数据面

- 加 `process/zoom/`（`zoom_ctrl` + `zoom_mapper`），右窗恒走缩放通路。
- `inv_scale` 是 Q8：`256=1.0×`、`512=0.5×`。
- 踩到的位宽坑：`inv_scale=256` 在 **9-bit 有符号**下是 −256 ⇒ 映射全错，
  改成 10-bit（`ISSUES.md:15`）。这是"定点表示范围"最典型的一课。
- **拖影没动** —— V3 的文档 `report/CHANGELOG_V6.md §0` 起点就是「第三版的状态与症状」，
  表里写着「红块移动的地方有拖影」「静止时仍然撕裂」，
  量化：frameid 判据下**最新帧仅占 42~52%**。

### V3 → V4：把根因从显示侧挪到入包侧（一次方向纠正）

- 被证伪的三个方向（V6.0–V6.2）：提交门限、读侧节流、**加深 CDC 缓冲**。
  最后一条最有教育意义：512→8192 加深后**仿真 100%、板上仍 42~52%**
  ⇒ **深度只能推迟溢出，改不了平均排空速率**。
- 真根因（V6.3 `f911527`）：`axi_frame_saver64` 每写一个 64bit 字都要等 B 响应
  ⇒ 在途深度恒 1 ⇒ 吞吐 = 1×8 B / 往返延迟 ≈ 20 MB/s 上限，
  而显示拷贝在 V-blank 抢同一条 HP0 时往返涨到上百拍 ⇒ 平均掉到 15 MB/s 以下
  ⇒ **每个包从第 48 字节起按 16bit 粒度被丢**。
- 修法：AW/W 同拍挂出、各自保持到被接收；`OST=8`；B 只回收计数且**不回绕**
  （多回一个 B 会让 `outst` 从 0 回绕成 15 而永久卡死）。
- V6.4 `a91e83b`：`WSTRB` 由恒 `0xFF` 改成按 16bit lane 生成
  ⇒ 分包长度不再影响正确性（1396 B 实测每帧 111 处 4 字节黑洞 → 0）。

### V4 → V5：资源与时序专项（本夜）

| 轮次 | 问题 | 动作 | 结果 |
|------|------|------|------|
| R02 | 打包 FIFO 被综合成 4.9 万个 FDRE（`FW=11` 时 `DRC UTLZ-1: FDRE requires 176092, only 107000`） | 数组写独占无复位块 + `ram_style="distributed"` | Reg 51.30% → 9.02% |
| R03 | 帧尾 4 字节偶发丢失 | 新增 `ddr_bank_commit`，换页判据补 `tail_drained` | 换页可见性修复 + TB 双向判据 |
| R04 | BRAM 98.93% | 帧缓存按 2 的幂分块（32768+8192） | **64.64%** |
| R05 | 显示拷贝侧 skid 同样吃寄存器 | 同 R02 手法 | Reg → 4.08%、Slice 36.05% → 18.03% |
| R06 | `eth_rxc` WNS 只有 +0.499（最差 10 条同构） | `frame_reasm` v5.1 饱和累加改写 | **WNS +0.974、功耗 2.338 → 2.176 W** |
| R07 | 综合阶段 2 条 `set_clock_groups` CRITICAL WARNING | XDC 加「时钟存在与否」保护 | 见 `report/OVERNIGHT_LOG.md` R07 |

## 5. 两处「口头叙述与仓库证据不符」

1. **「第三版修复了拖影」不成立。** 仓库自己的 `CHANGELOG_V6.md §0` 标题就是
   「起点：第三版的状态与症状」，并量化到 42~52%。
   拖影是 **V4 的 V6.3** 修掉的，且修的不是显示侧切换，而是入包链丢字。
2. **V1 的「效果保不住」不是 bug 被修，而是功能被旁路。**
   V1 的做法是旋转时强制关 blur/sobel；真正的修复（目标域窗滤）落在 V2。
   ⇒ 所以「修复滤波兼容」属于第二版 ✔。

其余三处与叙述一致 ✔：V1=PS 以太网；V2=搬到 PL + 自建 FIFO + 修窗滤；V3=无极缩放。

## 6. 怎么在版本之间跳

```bash
git fetch origin
git checkout main               # V5 当前
git checkout v4-zero-loss       # V4 零丢字
git checkout v3-seamless-zoom   # V3 无极缩放
git checkout v3-ghosting-attempts   # V3 期间三次未成功的尝试
git checkout v2-pl-ethernet     # V2 PL 协议栈
git checkout v1-ps-ethernet     # V1 PS lwIP
git log --oneline --first-parent        # main 的演进主线
```
