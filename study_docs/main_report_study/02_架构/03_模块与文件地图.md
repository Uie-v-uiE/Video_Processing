## 2. 死码为什么留着

`report/OVERNIGHT_LOG.md` 的 P09 把这类模块统一登记为「未综合 / 仅 TB 使用，
删除有回滚风险，暂不动」。真实的理由有三条，值得分开看：

1. **它们是有证据的失败方案**。`frame_buffer_db`（双缓冲）记录了 7020 资源不够这个硬约束；
   `axi_frame_saver_burst` 记录了「突发写 DDR」这条路的实测结果。删掉就丢了这个信息，
   而 `report/` 里的叙述需要它们作对照。
2. **删除会牵动 `sim/run_sim.tcl` 的文件列表**，而回归结果是门禁证据的一部分。
   在没有第二台机器可复跑全部 30 个 TB 的情况下，「不动」比「干净」风险低。
3. **它们不参与综合**。Vivado 只对顶层可达的模块做综合，所以死码不占资源、不影响时序，
   只占仓库 900 行。

但**读代码时它们是陷阱**，最典型的是 `udp_rx_parser.v`：它有 TB、TB 还断言了
「wrong port dropped」，而它根本没被例化 ⇒ 这条 PASS 与板上行为无关。
（板上路径是 `udp_rx.v:190-202`，那里**不做目的端口过滤** —— `UDP_PORT` 参数没有任何消费者。）

## 3. 端口级死线（比死文件更容易误判）

| 位置 | 现象 | 影响 |
|------|------|------|
| `pl_video_top.v:45-50` | `eth_wr_clk/en/addr/data`、`eth_frame` 五个输入体内**零引用**，而 `system_top.v:142-146,174-179` 很认真地把 `frame_reasm` 的写口送过来 | 读代码时会以为「ETH 直写显示 BRAM」——**现在不是**，这条是第二版残留 |
| `pl_video_top.v:153,159` | `zfrac_x/zfrac_y`（缩放的小数部分）接了不用 | 缩放只能是最近邻；想做双线性插值的接口其实已经留好了 |
| `pl_video_top.v:290` | `assign copy_hold = 1'b0;` → `system_top.v:121,136,185` → `eth_udp_video_top.v:18` 的输入体内零引用 | 三级死端口 |
| `pl_video_top.v:127` | `rotate_mapper .enable(1'b1)` | 模块内部的「不旋转旁路」分支永不执行（旁路在外面用 mux 做） |

## 4. 参数量「双写」清单（改一处不够的地方）

| 量 | 出现处 | 风险 |
|----|--------|------|
| `IMG_W/IMG_H = 512/300` | `system_top.v:124`（eth）**和** `:161`（pl） | 两处独立传入 |
| `BASE_ADDR = 0x1000_0000` | `system_top.v:125` 与 `:161`；另外 6 个模块各自有同名默认值 + `frame_commit_lock.v:34,99` 两个硬编码兜底 | 改基址要改 8 处 |
| `FRAME_BYTES = 307200` | `frame_reasm.v:8` 参数默认值；例化时**未覆盖**（`eth_udp_video_top.v:185`） | 改分辨率 ⇒ 完整性判据静默失配 |
| 行距 512 | `pl_video_top.v:363` 的 `{sy_fb[8:0], 9'b0}` | 写死在地址算术里，不是参数 |
| 600/624（显示行数） | `video_timing_1024x600.v:18-20` + `pl_video_top.v:207-208` | 再写一遍 |
