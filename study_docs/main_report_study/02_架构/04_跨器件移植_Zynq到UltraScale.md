## 0. 一句话结论

**"可移植"要落到"同一批文件被 `add_files` 直接引用"**，不是"我们把 RTL 重写了一遍"。
`ku5p/build/tcl/ku5p_build.tcl` 里那 19 个 `src/rtl/eth/*.v` 与 Zynq 工程是**同一批文件、
不复制不改写**；真正换掉的只有 RGMII 物理层三个文件（物理原语是器件绑死的，没法不换）。

## 1. 换的是什么：物理层三件套

| | Zynq（7 系列） | KU5P（UltraScale+） |
|---|---|---|
| RX 双沿采样 | `BUFIO + IDELAYCTRL + IDELAYE2 + IDDR`(SAME_EDGE_PIPELINED) | `BUFG + BUFIO + IDDRE1`(SAME_EDGE_PIPELINED) |
| TX 双沿驱动 | `ODDR`(SAME_EDGE) | `ODDRE1 / ODDR` |
| 输入延时 tap | 有（78 ps/档，需要 200 MHz IDELAY 参考时钟） | **本版不做**，见 §5 |

〔这条值得记〕UltraScale+ 里 **`IDELAYE2/IDELAYCTRL` 不存在**（换成了 `IDELAYE3 + IIDELAYCTRL`，
端口完全不同），而 `IDDR` 也没有 `SAME_EDGE_PIPELINED` 这一档。
另一条容易背错的：UltraScale 的 `IDDR` 端口是 `IDDR(Q1,Q2,C,CE,D,R,S)`、
`ODDR(Q,C,CE,D1,D2,R,S)` —— **单时钟、没有 CB、没有 DDR_CLK_EDGE 参数**。
所以 7 系列那份带 `#(...)` 参数的写法搬过去会直接报错。
**不要背原语，去读 Vivado 自带的 Unisim 定义**（权威来源）：

```bash
cd $VIVADO/data/verilog/src/unisims
sed -n '/^module IDDR/,/;/p' IDDR.v          # 端口顺序就是答案
sed -n '/^module IDDRE1/,/;/p' IDDRE1.v      # 有 C/CB 与 DDR_CLK_EDGE
```

## 2. 没换的部分，以及为什么它"理应"能换

协议栈（`gmii_rx_mac` / `arp*` / `icmp*` / `udp*` / `eth_ctrl`）、offset 拼帧 `frame_reasm`、
自建 FIFO（`sync_fifo` / `dc_fifo`）、健康计数 `link_monitor`、跨域 `snap_cross`、
帧缓存 `frame_buffer_w64` —— 全是行为级 Verilog + `(* ram_style = "block" *)`，
器件无关。**验证方式就是让它过综合与实现**（构建数字见 `ku5p/README.md §1`）。

有一处顺带的简化很说明问题：**KU5P 上没有像素域消费者**（这块板没有 HDMI），
所以整个入口退化成**单时钟域** —— `eth_rxc` 那根 125 MHz 从头喂到尾，
`dc_fifo` 与"消隐窗口原子提交"那一整套 CDC 在这里根本不需要。
也就是说：**当初最难对的那部分逻辑，是显示侧逼出来的，不是入包链本身要求的。**

## 3. 时钟与复位的差别（比想象的大）

| | Zynq | KU5P |
|---|---|---|
| 系统时钟 | 50 MHz 单端（MMCM 出 50/250/200） | **200 MHz 差分**（T24/U24，bank65 = 1.2 V DDR），本工程**没用** |
| 设计主时钟 | `clk_pix` 50 MHz + `eth_rxc` 125 MHz + `clk_fpga_0` 100 MHz(PS) | 只有 `eth_rxc` 125 MHz（`create_clock -period 8.000`） |
| 复位 | PS 产生 + 按键去抖 | 按键 K9 + 上电拉伸（16 位计数器，纯本地） |
| PHY 复位 | — | **没有 FPGA 引脚**：`PHYRSTB` 只被上拉到 3.3 V ⇒ 移植时不要去找这个信号 |

**没有 PS 意味着没有 AXI GPIO / HP0**：Zynq 侧"串口命令 + 寄存器"的控制面在这里必须换形态。
本版选了 LED（只有 4 个，且板子是高电平点亮），下一步该换成 **UDP 状态回包**
（`udp` 模块本来就有发送口，Zynq 侧把它 `tx_start_en` 绑 0 了）—— 有屏幕的地方用 OSD，
没屏幕的地方用网络，这条选择规则值得记。

## 4. BRAM 容量：一次算错 10 倍的复盘

第一版 `ku5p/README.md` 写"72 tile 远高于信息量下界 7~8"。**那个下界是错的**，
错因是把 RAMB36 的容量记成了 368,640 bit（那是 RAMB36 **字节数×10** 的口误），
真实容量是 **36,864 bit**（32 Kb 数据 + 4 Kb 校验）。重算：

```
帧缓存数据量 = 40960 个 64bit 字 × 64 = 2,621,440 bit        // 512×300 补齐到 4 像素/字
RAMB36E2     = 36,864 bit/块      ⇒ 2,621,440 / 36,864 = 71.1 ⇒ 72 块
实测（KU5P） = 71 × RAMB36E2 + 2 × RAMB18E2 = 71 + 1 = 72 块   // 正好等于下界
实测（Zynq） = 80 块 = 2,621,440 / 32,768                      // 64bit 宽时校验位不能当数据用
```

⇒ **两侧都不是浪费，而是各自器件的下界**：UltraScale+ 的 E2 是 72 bit 宽（64 数据 + 8 校验可
分开用），7 系列在 64 bit 宽度下每块只有 32,768 bit 可用 ⇒ 80 vs 72 的差**来自器件组织方式**。
教训两条：① 资源结论必须写"多少块 × 每块多少 bit"再除，不能凭数量级感觉；
② 一个说不出来源的数字（"下界 7~8"）写进文档，本身就是风险信号。

**同一把尺子量 UltraRAM（这处我也算错过一次，写成"约 2 块"）**：UltraScale+ 的 UltraRAM
每块 288 Kb = **294,912 bit**，XCKU5P 有 64 块。用**同一个缓冲容量**做分母才叫对比：

```
frame_buffer_w64 = 40960 字 × 64 bit = 2,621,440 bit
2,621,440 / 294,912 = 8.89  ⇒ 下界 9 块 UltraRAM（占 64 块的 14.1%）
对照：BRAM 方案 72 / 480 = 15.0%
```

⇒ **占比是同一量级**，所以"换 UltraRAM 省资源"这句话在数量上不成立；它真正可能省的是
*动态功耗*（密单元、位线结构不同）和*把 BRAM 腾出来给别人*——而这两条在这块板上都不紧迫
（BRAM 只用了 15%）。⇒ 结论：**先算，再谈换；换了要拿 `report_power` 与
`report_utilization -hierarchical` 实测说**，没实测之前它只能写成"值得量一次"。

## 5. RGMII 的时序余量问题（还没解决的那个）

RGMII 1000M 的 RX 数据与 RXC **同源于 PHY**，且 PHY 通常把时钟内部延迟 ~2 ns 以对准数据眼。
7 系列版靠 `IDELAYE2` 的 tap 补这段；本版**先不补**，理由不是"不需要"，而是：
原理图上 `RXDLY/TXDLY` 那两个 strap 只提取到"挂了 4.7 k 电阻"、**拉向哪一端没写清**。
所以正确的做法是先上板量：`ping` 通且收流零丢包 ⇒ strap 已经补好了；
丢且与距离相关 ⇒ 必须加 `IDELAYE3`。把判断留给测量，不把猜测写进 RTL。

保持余量（hold）侧目前 **WHS = +0.012 ns**（正，但极小）—— 这类"刚好为正"的数字
比"负了多少"更值得警惕：换个温度/电压就可能翻。明细见 `ku5p/build/ku5p_hold.rpt`
（构建脚本已改成会输出最坏 4 条 min/max 路径 + `write_checkpoint`，否则批处理一退出就得重跑）。

## 6. 引脚从哪儿来：两套证据的冲突

《用户手册》的中文叙述给出过一套引脚（"50 MHz 单端接 AK6"、"MDIO=AV23"、"RX 时钟 AY10/25 MHz
源同步"）。它与**原理图网表**和**厂商例程 XDC** 两套证据全部冲突，而且 `AV24/AY10` 这类球名
在网表里根本不存在。正确的取法：

1. 原理图（`pdftotext -enc UTF-8 -layout`）+ 厂商 XDC 一致 ⇒ 采信；
2. 手册叙述单独出现 ⇒ 不采信，当作待验证；
3. 最终由工具裁决：`get_package_pins` 要求**有已打开的设计**才回答，
   而错引脚在综合/实现阶段是硬错误 ⇒ **让构建当裁判最省事**，不要靠"看起来合理"。

顺带一条：这块板的 PHY 有自己的 25 MHz 晶振（Y501 XI/XTAL），**那不是给 FPGA 的 RX 时钟**；
把晶振频率误读成接口时钟，就会得出"这是 RMII"的错误结论（厂商时序约束是 8 ns = 125 MHz）。

## 7. 发送侧：移植里第二个真坑（R23 补，都是量出来的）

前面几节讲的都是"收进来"。等 KU5P 开始**主动发东西**（每秒一包统计）之后，才暴露出
入包链里从没被走过的三条路 —— 它们和器件无关，所以**不算"移植 bug"，算"共用代码的盲区"**：

1. **三选一 mux 会在帧中间换源。** 厂商 `eth_ctrl` 的仲裁条件是
   `arp_rx_flag && (udp_tx_busy==0 || icmp_tx_busy==0)`。两个独立忙标志用 `||` 连起来，
   语义是"任一空闲"，而作者想要的是"全部空闲"。⇒ 正在发的帧会被从中间切走。
   今天主线 `udp_tx_start_en` 恒 0，所以这条 OR 恒真、同样的毛病一直作用在 ping 回包上，
   只是撞车窗口窄。**周期性发送把占空比从 ~0 变成常态之后，它就从"没遇到"变成"每天几次"**。
   教训：看到"`a_busy==0 || b_busy==0`"这种条件，先问一句"我要的是不是 `&&`"。
2. **`tx_req` 提前一拍拉高。** 厂商 `udp_tx` 在 UDP 头的最后一个字节就把 `tx_req` 拉高
   （源码注释："提前读请求数据，等待数据有效时发送"）。厂商自己的数据源是 `eth_ctrl`
   后面的同步 FIFO —— **读出一拍延迟正好抵掉这个提前量**。所以这个"契约"是
   "给一个有一拍读延迟的数据源"，不是"给一个组合 mux"。
   用组合逻辑直接喂 `tx_data` 的话，第 0 个字节会被吃掉（台架 dump 里 payload 从
   `55 35 50` 开始而不是 `4B 55 35 50`，一眼看出来）。
   教训：**照搬一个模块的端口时，要把它原来配的数据源也一起看清楚**，端口名一样不代表契约一样。
3. **位宽陷阱成对出现。** `localparam [4:0] NBYTES = 5'd36` 会静默截断成 4；
   `case (idx)` 里写 `5'd32` 会先被截成 0。Verilog 不报错，工具也常常不警告。
   现象却不隐蔽：IP 总长变成 32、载荷变成"最后一个字节重复"。⇒ 判据要写成
   "头部长度字段 = 20+8+36"这种**能被算术式抓住**的形式，而不是只看"包发出去了"。

**还有一条方法论**：检查器自己也要自校。这台台架先要求自己的 CRC-32 对 `"123456789"`
给出 `0xCBF43926`，再用"整帧（含 FCS）过 CRC 得到常数余数"当 PC 收帧判据；
那个常数是从**另一份独立实现**（node）算出来的，不是从被测对象回抄的。
第一版我按记忆写了 `0xC704DD7B`（那是另一种异或约定的数），如果不做这一步，
我会以为 DUT 的 CRC 错了 —— 检查器写错比 DUT 写错难发现得多。

## 7.5 第三个方向：让 PC 能**命令**这块板（R31 补）

遥测解决"板子会说话"，但比赛谱系里那句"KU5P 做前端节点、Zynq 做显示与总控"还缺半句：
总控得能**下命令**。加的东西很小（一个 8 字节移位寄存器 + 一小段匹配逻辑），
但它踩到的全是 Verilog 字面量的暗坑 —— 三条都在台架里红过，值得单独记：

1. **拼接不够宽，会在高端补零**。`localparam [63:0] C = {"SPD999", 8'd0}` 的 RHS 只有 56 位，
   于是赋给 64 位目标时是**左边**补零 ⇒ 送出去的"第一个字节"是 `0x00`，命令短一字节。
   现象是"这一条命令死活不生效，其它都对" —— 上板几乎无法查；因为有"总账"那条判据，
   台架会让一串相关断言一起红，红得整齐反而好查。
2. **`\r` 不是 Verilog 的转义**（1364 只有 `\n \t \v \f \a \? \\` 和 `\<八进制>`），
   `"CLR\r\n"` 其实是 `'C''L''R''r'`。要多出来的控制字符就直写字节 `8'h0D`。
   这条能红，是因为 DUT **故意不过滤 0x00**（真命令里不会有 NUL；留着它，PC 侧拼错字符串
   就表现为 `cmds_bad` 增长，而不是被静默"清洗"成一条看似合法的消息）。
3. **`[base -: width]` 的 base 是最高位下标（含）**。写 `sh[(8*n) -: 24]` 会把整段右移一位，
   `"SPD"`(0x535044) 读成 0x29A822。正确写法是 `(8*n - 1)`。

设计上两条与"以后怎么改"有关：

- **`CLR` 不清计数器，只推基线**。`frame_reasm` 的那几个 `stat_*` 是两个板共用、
  并且被 R08–R10 三条板级结论引用的输出；为了一个"清零"去动它，代价是重跑别人的判据。
  基线相减放在遥测里，代价只是"字段含义变成自上次 CLR 以来"——这句话写在 RTL 文件头、
  PC 解析器和 flags2.bit1 三处，读的人不会误会。**"能不动别人的模块就不动"是一种收益**。
- **同一条规则表存在于三处**（RTL、台架、PC 工具）。所以 `tb_v80_ku5p_cmd.v` 与
  `ku5p_cmd.mjs --selftest` 用**同一批用例**（`SPD0` / `SPD1X` / `SNA` 必须三处都拒），
  再加一条总账（`cmds_ok`、`cmds_bad` 的绝对值必须等于逐条激励累加）。
  只要有人单独改了其中一处，一定有一条会红。

还有一条工程事实：`ku5p_eth_top.v` 没有任何台架例化它，所以它的端口改动**只有综合会查**。
现在有了 20 秒的预检：`bash sim/top_check_ku5p.sh`（关键是三个开关：
`-L unisims_ver -L unimacro_ver -L secureip`、把 `glbl` 当第二个 top 传进去、
以及给厂商那份没有 `timescale` 的文件补 `-timescale`）——
少了任何一个，失败信息看起来都像 RTL 错了。

## 8. 一句话结论索引

1. 移植的实质工作量集中在 **IO 物理层 + 时钟 + 复位来源 + 人机接口**四件事，行为级逻辑本身不挑器件。
2. KU5P 没有显示 ⇒ 入包链退化为单时钟域，**CDC 是显示侧的需求不是入包的需求**。
3. 不背原语：读 Unisim 定义文件。
4. 资源数字要"块数 × 每块 bit"实算，UltraScale+ RAMB36E2 = 36,864 bit。
5. 引脚/频率这类事实要两套独立证据；冲突时以原理图 + 厂商约束为准，并让构建裁决。
6. **hold 余量小不是 PVT 风险**：`WHS=+0.012` 只说明布局紧；随电压/温度恶化的是 **setup（WNS）**，
   hold 与之同向补偿。把"WHS 小"当明早的风险点，会在错误的地方花时间。
7. 端口名一样 ≠ 契约一样（`tx_data` 背后要不要那一拍读延迟，看的是原数据源，见 §7 第 2 条）。
8. 没被任何台架例化的顶层，**只有综合会检查命名端口连接是否存在** —— 台架全绿也拦不住它
   （所以有了 `sim/top_check_ku5p.sh` 这一道 20 秒预检）。
9. 同一条协议规则表如果存在于 RTL / 台架 / PC 工具三处，就让三处跑**同一批用例**，
   并加一条"总数必须等于逐条累加"的总账（§7.5）。

## 9. 自测

1. 为什么 `IDDR` 在 7 系列能写 `SAME_EDGE_PIPELINED` 而 UltraScale+ 的 `IDDR` 不能？
   正确替代是什么、它的 `CB` 从哪来？
2. 用两行算式说明：同一份 512×300 RGB565 缓存在 7 系列要 80 块、在 UltraScale+ 要 72 块，
   两边都不是浪费。
3. 本版 KU5P 顶层没有 `dc_fifo`，为什么？如果以后接 FH1159 子卡输出 HDMI，需要加回什么？
4. PHY 复位在 KU5P 上不能由 FPGA 控制，这对上电流程有什么实际影响？
5. 构建报告给出 `WHS = +0.012 ns`、`WNS = +2.081 ns`。明早上板前该不该再花一轮实现去"收"那条
   hold？说出你的判据（提示：想清楚哪一条会随电压/温度变差，以及"违例"和"余量小"的差别）。
6. 厂商例程的 RGMII 文件被逐字复制进本仓库，交付时最不能省的一件事是什么？
7. `arp_rx_flag && (udp_tx_busy==0 || icmp_tx_busy==0)` 为什么是 bug？把它改成正确写法后，
   用一句话说明"为什么今天没炸不代表不用修"。
8. 为什么 `tx_data` 用组合 mux 直接喂 `udp_tx` 会少掉第一个字节，而厂商原设计不会？
   你的修法是什么、代价是几拍？
9. `CLR` 为什么做成"推基线"而不是"把 `frame_reasm` 的计数器清零"？说出这条决定的**代价**
   （线上格式哪个字段因此变了含义、靠哪一位区分）。
10. 台架里 `SPD0`、`SPD1X`、`SNA` 三条必须判为坏命令 —— 各挡的是哪一类"看起来能工作"的错法？
9. `localparam [4:0] NBYTES = 5'd36` 与 `case (idx) 5'd32: ...` 两处写法各错在哪里？
   台架里是哪一条判据抓住它的？
