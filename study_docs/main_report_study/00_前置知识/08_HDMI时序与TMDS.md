# 08 · HDMI/DVI：像素时钟、同步时序与 TMDS 编码

> 显示侧的一切设计（为什么是 50 MHz、为什么消隐窗口有那么多拍、
> 为什么 OSD 必须叠在最后一级）都由这一篇决定。

---

## 1. 一根 HDMI 线上传的是什么

DVI/HDMI 的最小集（本工程用的"TMDS 三路 + 时钟"）：

```
TMDS_DATA0/1/2（各差分一对） + TMDS_CLK（差分一对）  = 4 对差分线
+ 5V、GND、DDC(I2C，读 EDID)、HPD（热插拔）
```

每一路数据都是 **TMDS 编码后的 10 bit 串行流**，时钟频率 = 像素时钟。
也就是说：**每个像素周期里，每路要移出 10 个 bit** ⇒ 串行器需要 10 倍像素钟。

本工程 1024×600@约 50 MHz 像素钟：
- 三色各 8 bit = 24 bit/像素，正好每路 8 bit 数据 → TMDS 10 bit → 一路一种颜色；
- 串行钟 = 5 × 像素钟（OSERDESE2 做 5:1，再靠 DDR 输出翻倍成 10:1）⇒ 250 MHz。

> 注意本工程的像素钟是 **50 MHz 而非标准的 50.25 MHz**（差 0.5%）。
> 大多数显示器/采集盒能容忍这个偏差（±0.5% 通常在同步锁定范围内），
> 但严格来说这是一个"实测可用、但不规范"的点，文档里要如实写。

## 2. 视频时序：一张图讲清

```
        ├────────────────── 一行 = HTOTAL = 1024 + 160 = 1184 拍 ───────────────┤
像素 →  │ 前肩 HFP │        有效像素 1024            │ 后肩 HBP │ 同步脉冲 HPW │
        └──────────┴─────────────────────────────────┴──────────┴───────────────┘
                                    hs（水平同步）在 HPW 期间为有效电平

垂直方向同理：VTOTAL = 600 + 若干行（前肩+后肩+同步脉冲行）
```

四个必须记住的窗口：

| 名称 | 作用 | 本工程为什么关心 |
|------|------|------------------|
| **有效区 (active)** | 屏幕真正显示像素的区间 | 只有这里读帧缓存有意义 |
| **前肩 / 后肩** | 给接收端缓冲与恢复 | 消隐期总时长 = 这两段 + 同步段 |
| **同步脉冲 (hs/vs)** | 告诉显示器"新行/新帧开始" | 极性（正/负同步）要与显示器匹配 |
| **消隐 (blanking)** | hs/vs 非有效 + 数据无效 | **本工程把整帧 DDR→BRAM 拷贝塞在这里** |

**为什么拷贝必须放在消隐期？** 因为在有效区里，显示逻辑正在逐拍读 BRAM；
这时改 BRAM 内容，屏幕上就会出现"上半是新帧、下半是旧帧"的**撕裂**。
消隐期屏幕不采样，随便改。

本工程 1024×600@50 MHz 的垂直消隐折算成 axi 周期约 **67200 拍**（100 MHz）≈ 672 µs，
这就是 `04_DDR与帧缓冲带宽` 里那个 457 MB/s 预算的分母来源。

## 3. TMDS 编码：为什么要把 8 bit 变成 10 bit

直流平衡 + 自时钟。规则：

1. **2b→3b 映射**（低位 2 bit 决定形式）：
   ```
   a=00 → 100111 / 011000      a=01 → 011110 / 100001
   a=10 → 101110 / 010001      a=11 → 101101 / 010010
   ```
   保证 3 bit 里有 2 个 1 或 2 个 0（游程受限）。
2. **8b→10b**：`d[7:0] → d[0:4]（来自 2b3b）+ d[5:8]`，后 5 bit 是前 5 bit 的**按位取反或原样**，
   选择依据是"当前 running disparity（累计 1/0 偏差）"：
   ```
   若 |disparity| 太大 → 选让偏差回弹的那支
   若 = 0 且 a=0 → 取反；a=1 → 原样
   ```
3. **disparity 累加**：每编码一个字符，把它的 1/0 数差累加进去，饱和到 ±5 附近。

对应实现：`src/rtl/hdmi/tmds_encoder.v`（8→10，含 disparity 与 count 状态机）、
`rgb2dvi.v`（把 R/G/B 三路 encoder + 控制位 + 并串化组装起来）、
`tmds_serializer.v`（OSERDESE2 做 5:1 + DDR 输出 ⇒ 等效 10:1，配 5× 时钟）。

**控制期（消隐期）走特殊编码**：TMDS 在水平/垂直消隐的特定拍上发送
`0b1100000111 / 0b1110000111 / 0b1101111000 / 0b1110111000` 这 4 个固定字符，
携带 hs/vs 电平 —— 显示器就是靠它们同步的。所以 **TMDS 编码器必须同时收到
"data valid" 与 "hs/vs"**，不能只喂 RGB。

## 4. 并串化：OSERDESE2 的用法要点

7 系列没有原生的 10:1 串行器，标准做法：

```
并行 8 bit + 2 bit 扩展 → OSERDESE2（DDR 模式，5:1）→ 输出 10 bit 宽的一个周期
需要 2 个时钟：并行钟（像素钟）+ 高速钟（5× 像素钟，本工程 250 MHz）
```

要点：
- 高速钟必须由**同一 MMCM 的另一路输出**给出，且与像素钟**同相**（否则占空比/相位会漂）；
- OSERDESE2 需要 `TSHIFT` 做相位微调（首次上电或换时钟后 shift 一次）；
- 输出用 `ODDR`/原生差分脚（`OBUFDS`）走差分对。

本工程 `tmds_serializer.v` 里能看到 `OSERDESE2` 的 `SERDES_MODE=MASTER`、
`DATA_WIDTH=5`、`TBYTE_CTL`、`SHIFTREGIN/OUT` 等端口连线 —— 学习时值得逐端口读一遍，
这是理解"高速串行输出"最便宜的样本。

## 5. 本工程显示链的完整形状

```
axi_clk(100M)                    clk_pix(50M)
   │                                 │
DDR bank ──消隐期整帧拷贝──► frame_buffer_w64（单口 BRAM，64bit 写 / 16bit 随机读）
                                 │
                    ┌─────────────────────────┐
                    ▼                          ▼
             左窗：rd_addr = f(cx,cy)     右窗：先缩放（zoom_mapper）
                （可再旋转）                 再旋转（rotate_mapper）
                    │                          │
                    │                     效果链 proc_pipeline
                    │                     （灰度/二值/模糊/Sobel/反色，目标域 3×3）
                    ▼                          ▼
                     └──── split_display（2× 垂直复制 + 双窗拼接）┘
                                      ▼
                              osd_overlay（叠 FPS/ANG/EN）
                                      ▼
                        rgb2dvi → tmds_encoder ×3 → OSERDESE2 ×3
                                      ▼
                              HDMI 1024×600
```

三个"为什么"：
1. **为什么 OSD 叠在最后？** 因为它不该被效果链处理（否则状态字也会被 Sobel 描边），
   也不该影响左右窗的像素通路 ⇒ 放在 `split_display` 之后、`rgb2dvi` 之前。
2. **为什么垂直 2× 复制？** 512×300 的画面要填满 1024×600 的双窗，
   横向靠"每像素出两拍"，纵向靠"每行读同一行两次"（`cy = y >> 1`）。
3. **为什么帧缓存要 64 bit 写口？** 因为入包侧 AXI 一拍就是 8 字节 = 4 个像素，
   一次写 4 像素才不需要 4 个写端口。
