# 60 · 这套东西凭什么说自己是对的

第 00 到 50 章回答"它是什么、怎么实现"。这一章回答另一件事：**一个说法要变成可以引用的结论，
中间必须经过什么**。它不讲硬件原理，但它决定前面所有章节里那些数字值不值得信。

写作口径与 `report/study/05_验证与上板/` 那三篇相同：每一节按"是什么 / 为什么要它 /
原理怎么推 / 代码在哪几行怎么实现 / 你可以自己验证"来写，每节末尾那条命令必须当场能跑。
所有 `文件:行` 都是写这一版时逐条 grep 过的；行号会随提交漂移，对不上就以文件名加信号名
重新 grep，**不要相信这里的行号胜过相信代码**。

先给一句结论，后面整章都在拆它：

> 这个仓库对"正确"的定义是——每条结论都能指到**一份能重跑、能变红、且带着源码指纹的产物**；
> 指不到的，就当没发生过。

三件事各自防的是不同的事故：能重跑防"只有我当时看得见"，能变红防"尺子是摆设"，
带指纹防"这个数字来自另一份代码"。

## 1. 验证是分层的，每一层只回答它那一层的问题

### 1.1 是什么

仓库里的验证链分五层，每层一个入口，每层都有自己的凭据目录：

| 层 | 入口 | 它判什么 | 它**判不到**什么 |
|---|---|---|---|
| L0 结构预检 | `python build/check_ports.py`、`bash build/orphan_rtl.sh`、`build/tcl/ooc_newmods.tcl`；门禁里的端口宽度 / 多驱动 / 顶层接线三项 | 端口名/位宽/悬空输入、多驱动、有没有模块悄悄掉出位流 | 逻辑对不对；一行像素都不看 |
| L1 全量仿真 | `vivado -mode batch -source sim/run_sim.tcl` | 63 个台架各自的断言行（今天盘上是 63 个 `sim/tb_*.v`） | 没被例化的顶层、跨台架的系统行为 |
| L2/L3 实现与门禁 | `bash build/gates.sh`（约二十项） | 时序/资源/CDC/警告数，外加两份**钉 md5** 的台架报告 | 屏上有没有那条线 |
| L4 板级机器判据 | `bash build/board_verify.sh --battery --geom`、`node src/host/health_read.mjs` | 命令回包、寄存器读回、几何 lane、心跳 | "好不好看"、"有没有那条线" |
| L4 眼睛判据 | 人手 + `board/README.md` 那张表 | 只有画面能判的归属 | 任何数值 |

### 1.2 为什么要分层

因为**每一层都会漏，而漏的地方不一样**。第 14 项"顶层接线"存在的理由就写在它的注释里：
`pl_video_top` / `system_top` 没有任何台架例化（`build/gates.sh:199-208`），
所以"改了子模块端口、顶层忘了连"这件事 **L1 全量一条都不会红**，只能等 25 分钟的构建——
今晚 `osd_overlay` 换端口就踩在这个空档上。反过来，门禁十四项全绿也不含任何"内容级"判据，
#88 那几天"gates 14/14"与"唯一例化顶层的台架红着"是**同时成立**的两件事（`build/gates.sh:249-256`）。

分层的价值不在于"多"，而在于**每条主张都要说清它属于哪一层**：把 L1 的绿念成 L4 的战果，
是本仓登记过的第二类假账（`skill/SKILL.md` 禁止段）。

### 1.3 你可以自己验证

```bash
python build/check_ports.py --quiet
```

期望看到一行 `CHECK PORTS: instances=… modules=… skipped=0 width_compared=… violations=0 PASS`。
`skipped=0` 和 `width_compared=` 那个数才是这条判据有没有牙的关键：
`violations=0` 配一个很小的 `width_compared` 意思是"它其实没比对多少根线"，
这正是第 8.1 节要讲的那种绿。

## 2. 先会写最小的 testbench

### 2.1 是什么

一个 Verilog 台架只做五件事：造时钟、放复位、喂激励、观察输出、报结论。

```verilog
`timescale 1ns/1ps            // 没有这一行，#10 是 10 秒而不是 10 ns
module tb_min;
    reg clk = 0, rst_n = 0;
    always #10 clk = ~clk;    // 20 ns 周期 = 50 MHz

    wire [7:0] q;
    dut u(.clk(clk), .rst_n(rst_n), .d(8'h5a), .q(q));   // 被测对象

    integer i, bad = 0;
    initial begin
        repeat (3) @(posedge clk);
        rst_n = 1;
        for (i = 0; i < 100; i = i + 1) begin
            @(posedge clk); #1;                            // 采样放在沿之后
            if (q !== 8'h5a) bad = bad + 1;                // !== 而不是 !=：X 也要算错
        end
        $display("RESULT %s  样本 %0d 错 %0d", (bad == 0) ? "PASS" : "FAIL", 100, bad);
        $finish;
    end
endmodule
```

### 2.2 四个新手一定会踩的点

- **`!==` 与 X**。`!=` 遇到 X 返回 X，`if (X)` 不进分支 ⇒ 一个从未被驱动的引脚会让"错"
  统计停在 0，于是"全绿"。本仓库所有判据用 `!==`，并且每条统计都带**样本数**（第 8.1 节讲为什么）。
- **`#1` 采样偏移**。同一个沿上被测寄存器还没写完，读回来的是旧值。
- **`integer` 数组默认元素是 X，标量默认是 0**。没初始化的 RAM 在仿真里是 X ⇒
  "拿 RAM 内容当期望值"的判据可能在比 X。这不是假想：`sim/tb_v98_top_seam.v:1238-1250`
  开头那一串清零循环的注释写着"这是本仓第七次撞 X 的出生地"，
  而第 1482 行 C9 那一段又单独清了一遍数组。
- **`$display` 是结论，不是证据**。证据要能落到文件里、能被别人重跑（第 8、9 节）。

### 2.3 本仓库把"报结论"收敛成一个 task

`sim/tb_v98_top_seam.v:1230-1235`：

```verilog
task line(input [8*96-1:0] tag, input ok, input [8*170-1:0] txt);
    begin
        if (!ok) nfail = nfail + 1;
        $display("%s %0s | %0s", ok ? "PASS" : "FAIL", tag, txt);
    end
endtask
```

三件事都钉死了：**结论在行首**（`PASS`/`FAIL`），**编号紧跟其后**，**期望与读数之间用 `|`**。
脚本一律取"最后一列"当判决而不是在整行里找子串（`build/tb98_gate_ce.sh:36-42`
专门写了为什么：真凭据那行的实测里本来就带着 `FAIL行=0` 这样的字样，`grep FAIL` 会把它读成红）。

### 2.4 你可以自己验证

```bash
grep -n "task line" sim/tb_v98_top_seam.v
```

期望：命中 `1168:    task line(...)` 一行。再看一眼 `sim/tb_v98_top_seam.v:3` 那行判据索引，
它就是这份台架的目录——每条 C 系列判据盯什么，都写在这一行里。

## 3. 台架在本仓库是怎么被跑起来的

### 3.1 两个入口

`sim/` 下 63 个台架，两个入口都是**通配符收全部**（`sim/README.md:9-18`）：

- `sim/run_sim.tcl` —— L1 全量批跑，一次几十分钟；
- `sim/run_one.sh <tb名>` —— 单跑一个，绕开全量那两分钟编译。

所以"某个台架忘了接进流水线"这件事在结构上不存在；反过来也意味着
**放一个坏台架在目录里，每次批跑都会被它拖住**（删台架要先看引用，见 `sim/README.md:43-50`）。

### 3.2 `run_one.sh` 做的三件与正确性有关的事

**第一件：门口那个"有活的 xsim 就拒绝启动"的守卫。**

`sim/run_one.sh:11-22`。防的不是抢占，是**污染凭据**：第二次 `run_one.sh` 并不会让第一次停下，
前一个 xsim/xsimk 还活着，继续往同一个 `/tmp/kx/<tb>.run/run.log` 里写它那一跑的行。
两次跑的行混在一份文件里，`build/tb98_report.sh` 就会把"上一跑的 C5c"与"这一跑的 C5c"
拼成一份报告——注释里记着 2026-09-27 12:45 那份就是这么废掉的，
**而它的头部 md5 全对**。认 md5 也救不了"正文来自两个进程"这件事，所以只能从源头挡：

```bash
if tasklist //FI "IMAGENAME eq xsim.exe" ... ; then
    echo "REFUSE: 已经有 xsim 在跑（它会把行写进同一份 run.log）…"
    exit 3
```

不自动杀：正在跑的那一跑可能是别人要的凭据。这条守卫在 2026-09-28 凌晨还救了一次场——
一个挂在不存在的父进程下、`taskkill` 报"没有此任务的权限"的孤儿 xsim，
让当晚的门禁第 15/16 项与 L1 全量全部没跑（`report/log/OVERNIGHT_LOG.md:5693-5708`）。
如果没有守卫，那一晚会交出一份"混了两跑"的报告。

**第二件：编译**之前**盖三枚指纹。**

`sim/run_one.sh:34-45`，写进 `$R/prov.txt`：`top_md5`（顶层源）、`tb_md5`（这份台架）、
`rtl_md5`（整个 `src/rtl` 的合指纹，算法是 `find | sort | xargs md5sum | md5sum | cut -c1-12`）。

为什么在编译前：门禁要的恰恰是"这份报告是不是**当前这份树**跑出来的"，
事后补 md5 等于把今天的指纹盖在昨天的日志上（#88 那几天的根源就是没有任何东西把报告与被测的树绑住）。
为什么要第三枚 `rtl_md5`：2026-09-26 r72 那天改的是四个窗口级
（`proc_box_blur/sharpen/sobel/morph`），`pl_video_top.v` 一个字节没动 ⇒ 顶层 md5 仍然"对得上"，
而 r71 那份旧报告可以原样冒充"当前这一版台架"（`sim/run_one.sh:38-41`）。

**第三件：过滤词表与凭据落盘。**

`sim/run_one.sh:52-56` 打印给操作者看的行必须包含 `PROBE|DIAG|NOTE|OBS |GOLDEN`，
因为台架**专门为了回答"缺口在哪"**才打这些行——2026-09-25 `tb_v98` 数"帧缓存到底被写了多少字"
那条 PROBE 就被旧过滤器挡在终端外，多绕了一趟临时目录。
注意 `run_one.sh` 自己**不**把 `run.log` 收进仓库；落盘由
`build/tb98_report.sh`（把 console 收成门禁认的那份报告）与
`build/freeze_evidence.sh`（把 `/tmp/kx/…/run.log`、`prov.txt` 一起复制进冻结目录，`:50-54`）做。
老稿子说"跑完把 run.log 复制出来当凭据"，那是把三个脚本的分工写在了一起。

### 3.3 编译清单的另外两个坑

`sim/run_one.sh:28-33`：

- 清单**必须走 `-f` 文件**，不能拼在命令行上：台架多了之后 `xvlog` 会被 Windows 命令行长度上限
  截成一句"参数太多"，而 `xv.log` 里连 ERROR 都没有 ⇒ 脚本只看 `^ERROR` 就往下走，
  最后报成一句看不懂的 "Cannot find design unit"（2026-09-25 加 `tb_v94` 时撞到）。
- `-f` 文件里必须写 **Windows 正斜杠路径**（`cygpath -m`）：命令行参数会被 MSYS 自动换算，
  文件内容不会 ⇒ 直接写 `/d/...` 会让 `xvlog` 报 "Can not find file"（同一天第二次撞到）。

这两条与 `report/study/learn/50_tcl_tutorial.md` §7（Windows / Git-Bash 下的路径与退出码坑）是同一族教训。

### 3.4 你可以自己验证

```bash
grep -n "REFUSE" sim/run_one.sh; cat /tmp/kx/tb_v100_raw_delay.run/prov.txt
```

期望：前一条命中 `19:    echo "REFUSE: 已经有 xsim 在跑…"`；后一条打出四行
`top_md5=… / tb_md5=… / rtl_md5=… / date=…`，而且 `date` 那一行**早于** `run.log` 的结束时间——
这就是"编译之前盖的章"的字面证据（临时目录会随机器重启清空，看不到就改看
`build/evidence_rNN/rNN_tb98_prov.txt`，冻结件里存着同一份）。

## 4. 全量回归与单跑必须同口径，而且这个"同"要靠人维护

### 4.1 为什么要一起改

两份脚本各自写了一遍编译清单，没有任何共享代码，于是"加一个新模块"是个两步动作。
两边都写着同一句话：`sim/run_sim.tcl:44-45` 与 `sim/run_one.sh:4-6`
——只加一边的表现是**单台架跑绿、全量回归判 ELAB_FAIL**，红的是清单不是 RTL（2026-09-23 撞到）。
同一天还撞过一次反向的：`run_one.sh` 原来是手写的一小串文件，
改 `pl_video_top` 想快点看一眼时 `xelab` 直接报 Cannot find design unit ——
顶层唯一的台架根本不在清单里。

### 4.2 `sim/prim/` 那两个占位件决定顶层台架的可行性

本机 xsim 没有 UNISIM 库，缺了它们**任何例化 `clk_gen` 的顶层都 elaboration 不起来**
（实测 `Module <MMCME2_BASE> not found`），所以 `sim/prim/MMCME2_BASE.v` 与
`sim/prim/unisims_sim.v` 必须进两个入口的清单：`sim/run_sim.tcl:46-49`、
`sim/run_one.sh:25-27` 的最后一段 `find`。

### 4.3 一个还没爆的不对称

`sim/run_sim.tcl:34-41` 的 RTL 收集是 `src/rtl/*.v` + `src/rtl/*/*.v` + `src/rtl/*/*/*.v`
（写死两级），而 `sim/run_one.sh:25` 用 `find -name '*.v'`（无限层）。
今天两者数出来一样：`src/rtl` 下 79 个 `.v`，最深是 `src/rtl/<组>/<子>/<文件>.v`，
`find src/rtl -mindepth 4 -name '*.v' | wc -l` = **0**。
一旦有人加第四层，全量回归会静默少编一个文件——红的是 ELAB_FAIL 还是"顶层没找到"取决于运气。
这是"两份清单"这件事的固有代价，不是某个 bug。

### 4.4 全量回归不许有"什么都没断言"的绿

`sim/run_sim.tcl:103-111` 的收尾是这样的：先把 `verdict` 初始化成 `FAIL`，
只有"抓到过 PASS/FAIL 行、且其中没有 FAIL"才改成 `PASS`；
一行都没抓到时打印 `(没有 PASS/FAIL 断言行 —— 判为失败)`。
注释写着改这条的理由：**NO_ASSERT 过去被计入 pass**——一个"什么都没断言"的测试台不该算过，
而跑不到最后断言的台架以前会悄悄绿。这与第 8.1 节"空集上的绿"是同一条纪律的两个入口。

### 4.5 你可以自己验证

```bash
ls sim/tb_*.v | wc -l; find src/rtl -name '*.v' | wc -l; find src/rtl -mindepth 4 -name '*.v' | wc -l
```

期望：`63`、`79`、`0`。第三个数如果不是 0，`run_sim.tcl` 的清单就必须先加深一层，
否则全量回归编的树比单跑的树少文件。

## 5. L0 结构预检：不出 bit 的那二十分钟

### 5.1 顶层接线（`build/check_ports.py`，门禁第 14 项）

它判三件"会真出错"的事（口径写在 `build/check_ports.py:10-19`）：
连了目标模块**没有**的端口名、目标模块的**输入没连**、两端**位宽不一致**。
第三条是 r52 加宽的，动机是 #57：`system_top` 里 `wire [5:0] dbg_src` 接在 8 bit 端口上，
综合只给一条 `Synth 8-689` 警告，lane30 的模式高位被静默吞掉（读出来永远 0/1），
而当时七项门禁全绿（`build/gates.sh:156-159`）。

它同时是这个仓库"判据不确定时必须闭嘴"的样板（`build/check_ports.py:28-29`）：
位宽只判"两头都数得清"的连接——纯数字、四则运算（`[6*32-1:0]` 算得出 192）、Verilog 字面量；
`[W-1:0]` 这种含参数的、拼接、部分选择一律**跳过不猜**。
理由很直白：第一次假红之后就会有人来把它关掉。
它自己带三份反例（`build/check_ports.py:21-25`，凭据 `build/ports_check_width_ce.txt`）：
两种不同的位宽形状各造一份坏文件、外加一份"整棵树必须 violations=0"的负对照。

### 5.2 孤儿 RTL（`build/orphan_rtl.sh`）：拿综合日志当 oracle

这个脚本存在的理由就是它头部那一段（`build/orphan_rtl.sh:4-14`）：
作者先用 grep 找"`模块名` 后面跟 `(`"的行，结果是**错的**——行首的直接例化整行漏掉，
注释里提到一个名字又假命中；两边都错过之后 `icmp_tx` 被判成"没人例化"，
差一点把一个在用的模块写进"可删"清单。综合器不撒这个谎：
`INFO: [Synth 8-6157] synthesizing module 'X'` 只对**从顶层可达**的模块出。

它还有一条覆盖地板（`build/orphan_rtl.sh:61-67`）：oracle 日志里 `synthesizing module`
不足 50 行就**拒绝出表**——拿空集合去比，每一个模块都会被判成"没用"。
地板旁边还记着 shell 的一个坑：`N=$(grep -c … || echo 0)` 在"没有匹配"时既打印 0 又返回非零，
两个 0 拼成 `"0\n0"` ⇒ 后面的数值比较报错并把地板**整个跳过**。

### 5.3 out-of-context 综合

`build/tcl/ooc_newmods.tcl` 在开 20 分钟全流程之前，只把新模块综合一遍，
专门抓多驱动 / 位宽 / 锁存器三类只有综合警告才会说的东西。
第 13 项（多驱动，`build/gates.sh:179-197`）的动机 #61 值得复述一遍：
一个 reg 的复位被同时写进两个 always 块 ⇒ 综合**保留常量那一侧、忽略逻辑那一侧**，
bit 里那根旗标恒为 0；而仿真按"进程后写覆盖"，台架 56 条全绿。
**这类差别不会出现在任何时序/资源报告里**，只能读综合的 CRITICAL WARNING。

### 5.4 你可以自己验证

```bash
bash build/orphan_rtl.sh --selftest
```

期望最后一行 `SELFTEST PASS 4/4：报出真孤儿、不报在用的、台架归去向、空日志拒绝出表`。
这四条正是 S21 说的"判据自己要有反例"：第 4 条测的是**地板**，不是判据本体——
少了它，一份空日志会让脚本宣布"这些模块全没用"。

## 6. 门禁：`build/gates.sh` 的二十项，以及"红"和"缺凭据"是两种红

### 6.1 项数不要背，背命令

`build/gates.sh:2-7` 明确写着**不再写死条数**，以本文件 `say` 的调用次数为准，
因为条数是随教训增长的：2026-09-23 是"七项"，r70 起 15 项，随后加 16（PS 心跳约定）、
17（手写件编码）、18（文档时效）、19（排练脚本=讲稿抽取）。今天 `say` 的调用点 26 处、
去掉分支后的项名 18 个、实际打印的行数在 20 上下——`board/README.md:1` 那张名片写的

### 6.3 三种"红"长得一样，含义完全不同

- **真红**：项跑到了、数字违例了。第 15 项会把它能说的都说出来：
  `报告里有 $NFAIL 行 FAIL`（`:284`），并且当汇总行是 `RESULT … FAIL` 时额外注明
  "台架跑完了、是它自己判红的，先读 FAIL 那几行的数"（`:273-275, :285`）——
  "跑挂了什么都没判"与"跑完了并且判红"是两件事，念成一句话就会把人支去重跑一次 75 分钟的台架。
- **过期**：md5 对不上。措辞直接点名是哪一路不符：顶层 md5 不符 / RTL 合指纹不符 / 台架 md5 不符
  （`:277-283`），并且**报告头部没有 `rtl_md5` 字段**会被明说成"那是加这枚指纹之前的旧报告"。
- **没凭据**：不是红，是**未验**。`NOLOG / 无凭据=未验`（`:170, :190`）；
  历史冻结件缺 `ports_check.txt` 或台架报告时打印 `n/a` **跳过而不是判红**（`:208-224, :292-294, :324-326`），
  理由写在注释里：这一项是拿"当前源码树"跑的，历史包没有对应的树，
  红一个没有意义的红只会让人去关门禁。

把这三样区分开，是"红了之后第一步该做什么"的答案：**先看它是不是过期，再看它读的凭据是哪份文件，
判据本身可信之后才去看被测代码**。

### 6.4 新鲜度：两个方向都要提醒

`build/gates.sh:33-48`。一次构建里 bit 与报告只差几十秒，所以相差超过 10 分钟就当不是一套（WARN）；
反过来，产物之间一致但**整批都比 RTL 旧**，那就是"改完没重跑"，念到的是上一版——
2026-09-24 真踩过：构建还在跑，先跑了一次门禁，全套报告都是 30 分钟前的、七项全绿。
第二条检查只对 `build/` 这个活目录做，冻结目录按定义就是历史产物，报出来是噪声。

`mtime` 在这里只当**提醒**，身份认定永远用 md5（`skill/artifact_freeze_and_freshness.md:36`），
因为复制会把复制件的时间统一成"现在"。

### 6.5 尺子读不懂被测对象时，必须说"我读的是哪一行"

`build/gates.sh:50-65`：2026-09-25 r60 那次红过"门禁自己没牙"——TNS 在违例时是**负数**（−6.457），
而解析式只给 WNS/WHS 留了符号位、TNS 那两列没留 ⇒ awk 不匹配 ⇒ 脚本打印
`FATAL 读不到 timing summary` 然后 `exit 2`。停下来是对的（没把自己判绿），
但它把最该看见的数字（WNS −0.482 / 19 个失败端点）换成了"读不到"这句话。
现在四列数字都允许带符号，而且读不到时**把报告里最像的三行原样打出来**。
同一精神还有一处：`:133-138` 把所有解析出来的变量逐个查空值，
空或 `NA` 一律 `exit 2`，注释写着"不要拿空值当 0 判绿"。

CDC 那一项（`:79-131`）是"与基线的**行集合**比，不与一个写死的数字比"：
原来写死"4 行以内算过"，后来给 `dbg_src` 加了一对同步器把 Critical 从 3 行变 4 行，
脚本照样打印 PASS——**门禁把自己要挡的东西漏掉了**（#26）。
现在认"新增了哪几条 src→dst 配对"，条数变少也不算改进（`:126`），
而同一条配对上 unsafe 端点变多是判红的（#65：V8-5 的 CDC-11 就是这么躲过第 6 项的）。
基线文件里只要有一行不是三列，**整个基线当坏**直接判红（`:95-103`）——
静默把缺的第三列当 0，等于"谁都能靠删一个数字让 CDC 变绿"。

### 6.6 一条纪律：不要把判据要读的凭据先毁掉

`build/gates.sh:12-18` 用一整段注释记着这件事：
`bash build/gates.sh > build/r74_gates.txt` 会在**第一项判据跑之前**就把那个文件截断，
而第 18 项恰恰要拿"盘上最新且 ALL PASS 的那一份 `rNN_gates.txt`"当基准
⇒ 它读到半空的文件，于是判"首页念 r74、最新全绿的还是 r69"红两条，第 15 项跟着白跑。
正确姿势两步：先 `bash build/gates.sh > /tmp/kx/g.txt 2>&1`，确认 ALL PASS，再 `cp` 到位。

这一类"自己把自己刚要读的凭据毁掉"的写法在本仓出现过三次（#69 的 rc 被管道吃、#88 的报告出处、
r74 这次），共同点是**判据读的与被判的是同一个对象**。加判据时先问一句：
它读的文件是谁写的、什么时候写。第三例的姊妹条目见 `:341-343`——
`SUM=$(node … | head -1); RC=$?` 拿到的是 `head` 的 0，判据红着这一项也绿。

## 7. 出处：一份报告怎么被钉在一份源码上

这一节是全章的枢纽。前面所有"绿"和"红"的可信度都押在这三枚 md5 上。

### 7.1 链条

```
run_one.sh 编译前盖 prov.txt（top_md5 / tb_md5 / rtl_md5 / date）
   → run.log 留在 /tmp/kx/<tb>.run/
   → build/tb98_report.sh 把 prov.txt 的四行**原样**抄成报告头部，再 grep 出判据行
   → build/gates.sh 第 15 / 15b 项拿报告头部与**当前树**重算的值对账
   → build/freeze_evidence.sh 再对一遍，并且要求门禁那份是 ALL PASS 才肯成套冻结
```

关键的一步是 `build/tb98_report.sh:19-29`：出处取自**跑的那天**留下的 `prov.txt`，
**不是现在树里的 md5**。事后算一遍再把指纹盖到旧日志上，正是这一项要防的那件事。

### 7.2 为什么"只认顶层"不够

三枚指纹各管一段：`top_md5` 管顶层、`tb_md5` 管台架自己、`rtl_md5` 管顶层之外那一路。
`rtl_md5` 是 r72 之后补的（`sim/run_one.sh:38-41`），而它的反例被写成了可跑的脚本：
`build/tb98_gate_ce.sh:25-31` 造了 E、F 两份文件——E 是"顶层没改、其它 RTL 改了"，
F 是"加这枚指纹之前的旧报告，头部根本没有 `rtl_md5` 字段"——**两份都必须红**，
后者尤其重要："字段缺=不判"等于给所有旧报告开了通行证。

### 7.3 门禁认指纹的两项长什么样

第 15 项（`build/gates.sh:261-294`）要求四件事同时成立：
头部三枚等于当前树、正文没有任何 `^FAIL ` 行、有一行 `^RESULT tb_v98_top_seam PASS$`、
以及报告存在。第 15b 项（`:302-326`）同形，多要一条**覆盖地板**：
`^PASS R[2-5]` 必须正好 4 条（`:311, :317`）——少一条就是那一族的判据没跑或被地板挡下。

第 15 项为什么不干脆跑台架？因为那个台架一次要跑 40+ 帧（八档缩放扫描）≈ 75 分钟，
塞进"构建完就读"的门禁里没人会等（`build/tb98_report.sh:6-9`）。
折衷的结果是"不跑，但必须认一份同一次跑的报告"，而这个折衷把 #88 那个缺口补上了。

### 7.4 成套冻结到底冻了什么

`build/freeze_evidence.sh` 的两道硬门（`:23-36`）：
`build/rNN_gates.txt` 里必须有 `^GATES: ALL PASS`，**且** `tb_v98_report.txt` 的
`top_md5` 与 `rtl_md5` 两枚都还等于当前树。任一条不成立就 `REFUSE` 并打印红项。
"红 = 没做完"，把红的东西冻结下来等于给下一轮留一个"看起来有凭据"的坑。

过关之后复制的东西（`:40-57`）值得逐条看，因为它回答"下一轮要复核需要什么"：
三件成品（bit/xsa/elf）+ 七份 Vivado 报告 + 三份静态自检 + 台架报告与门禁清单；
r77 起多带三件——边缘条带凭据、它自己的反例、以及"**修之前红成什么样**"的 C5 基线
（`:41-42`：少了后两件，冻结件里就只剩"绿"，没有"这条判据曾经红过"）；
再加构建与台架的原始 console、`prov.txt`、以及 **L1 全量回归的日志**（`:55-57`）——
最后这条是被撞出来的：门禁第 15 项只盯顶层那一份，其余台架红着门禁也能全绿。
MANIFEST 尾部（`:67-85`）写指纹、写板上跑法、写"L1 PASS=?/FAIL=?"，
还专门留一段"还欠眼睛/手的（这一版由用户签）"。

**认 md5 不认文件名**这条不是风格：现场 `build/evidence_r*` 里同名的位流有好几份
（`:4-5`），演示第 0 步的对账动作是 `md5sum build/system.bit build/ps_app.elf`
与 `board/README.md:1` 那张名片逐个字符比（`report/DEMO_SCRIPT.md:26`）。

## 8. 判据必须能变红：四种"白过"，以及各用什么读数判掉

假绿比没有检查更糟——它会让后面所有人不再检查。这一节是本仓登记最多的那一类经验，
`skill/criterion_blind_spot.md`（S21）与 `skill/bench_self_inflicted_reds.md`（S20）是它的两张清单。

### 8.1 空集上的绿

一条判据"所有被判格都必须符合形状"，如果这一格里一个样本都没有，`bad == 0` 照样成立。
所以每条结论判据前面配一条"样本够不够"的地板判据：

```verilog
line("C4a rows judged", c4_rows2[c4_a] > 200, "…");   // 这一格有没有内容行
line("C4b one run per row", c4_bad[c4_a] == 0, "…");  // 有内容行时才谈形状
```

`sim/tb_edge_rim.v:428-431` 是同一形状的四边版本：`n2/n3/n4/n5` 各自不足 20 就打印
`FAIL coverage floor: n2=… (each floor 20)`，并把它并入总失败位 `b0`。
盘上的读数解释为什么要地板：`build/tb_v98_report.txt:41` 那行
`C4 idx=8 ang=0 zoom=25% … 有画面行=300 无画面行=480`——25% 缩放下屏幕 480 行是黑的，
只判"画面行的形状对不对"的话，样本从 780 掉到 300 也不会告警。

**判掉它的读数**：结论行旁边那个**样本数本身**。所以本仓的每条 `$display` 都把数量写进正文，
而不是只写 PASS/FAIL。

### 8.2 判据根本没执行

`for (reg [1:0] i = 0; i <= 4; i = i + 1)` 里 `i` 只有 2 bit，取值被截断到 0..3，
**第 4 档从来没被测过**，而这一条照样打印 PASS。循环变量一律用 `integer`。

今天有一个更结实的签名，来自盘上那份报告：`build/tb_v98_report.txt:71` 的
`C2 row 0 … invbad=247808`，而 247808 恰好等于该档的全部采样数，紧接着 `:75` 是
`FAIL C2pre inv took`。这个形状的意思是"**门没开、倍率从没换过档**"：
C9 那几档为了量几何改过 `zoom_en` 与 `bilin_en_tb`，用完"还成台架初值"而不是还成 1，
而后面的八档扫描只自己写 `zoom_sel`，倍率到底生不生效全靠 `zoom_en`
（修法与教训写在 `sim/tb_v98_top_seam.v:1612-1620`，注释原话是这两行"**必须还成 zoom_en=1 /
bilin_en_tb=1**，不是'还成台架初值'"，并明确说
"两个都是**台架漏状态**，不是设计变了——r80 那份冻结件里这些条目都是 PASS"）。

**判掉它的读数**：`invbad == 全部样本` 或 `viol == nout` 这类"分母=分子"的等式；
以及每条新判据都要打印"我这一轮到底测了什么"（数量 + 代表样本）。

### 8.3 尺子自己错

尺子错的时候通常**不是红一条，而是整族红且每一档都红得同样齐**：今天那份报告里
C2a/C2b/C2c/C3c/C7 这一族连着 `C2pre` 一起翻红（正文 35 行 FAIL，台架注释原话
"C2a/C2b/C2c/C3c/C7 一整族因此全红"，`sim/tb_v98_top_seam.v:1617`），
且每档的 `inbad` 都几乎等于 `nin`
（第 3 档 `nin=186340 / inbad=184404`），配着 `invbad == nin + nout`——
这是"期望与实际整体站在同一个错位上"的形状，不是某处几何坏了（`build/tb_v98_report.txt:71, :122`）。
更早的一次是真·取错级数：想判"标签与内容同列"，拿第 11 级的列标签去比第 20 级的内容，
两条抽头看起来都差 9 列（#68 那一族，账记在 `sim/tb_v98_top_seam.v:1330`：
"真正错的是尺子取错级数：拿第 11 级的标签比第 20 级的内容"，而顶层那份级数账写在
`src/rtl/top/pl_video_top.v:668, :844-847`——`MIX_D` 与 `SEAM_TAPS` 要从级数推，不许抄字面量）。
读错位的"证据"会把人引去改对的代码。

**判掉它的读数**：台架里所有相位量要么从代码算出来（`src/rtl/top/pl_video_top.v:309`
的 `MIX_D = 3 + 1 + 1 + u_pipe.LATENCY`，被台架与顶层同时引用），要么实测出来，不能凭感觉；
"整族齐红"先查量具与激励，"单格偶发红"才走被测对象。
发现症状**跨两条独立通路同时出现**时，第一嫌疑是量具。

### 8.4 X 与初值

`sim/tb_v98_top_seam.v:1238-1250` 那一段清零循环旁边写着：
标量 `integer` 的初值是 0、数组元素的初值是 X ⇒ 不清零的
`c5_head_c[j5] = c5_head_c[j5] + 1` 永远是 X，而 `X > 5` 既不是真也不是假，
`line()` 就在"算术上坏了"的基础上判红。同族还有 `C0a2`：`#92` 那一轮把图案换成
`{1'b1, r[6:0], c[7:0]}` 之后**两个期望字面量一直没跟着改**，于是它红了，
而红的是尺子（`:1221-1228`）。所以判据之前先有两条**校准判据**：
`C0a` 钉"编码函数对"，`C0a3` 钉"图案里不存在黑格"（`:1199-1208`——面板级尺子用
"是不是黑"判断"在不在画面里"，只要图案里有一个黑格，那条尺子永远有假红可找），
`C0a2` 钉"数组里真的是它"（`:1226-1228`：函数对不等于数组对）。

### 8.5 你可以自己验证

期望：第一行 `C2 row 0 1023 62436 185372 … 247808 | …`，第二行 `FAIL C2pre inv took`。

## 9. C9 这一族：今天暴露的两个尺子缺陷

这一族是给 ISSUES `#103` 建的那把尺子——`sim/tb_v98_top_seam.v:1173-1213` 定义采样，
`:1479-1567` 是三档测量（C9a/C9c、C9b 对照、C9e）。用户 2026-09-27 23:3x 报的现象是
"效果开着时，处理那一侧有一条跟着分割线走的黑线"，而当时所有判据都看不见它；
台架为什么必然看不见它的两条理由写在 `:1112-1114`：**缝被钉在 0 ⇒ 屏上"缝旁"那一档结构上不存在**；
**`stage_sel` 全程 0 ⇒ 只在效果开着时才坏的列无从现形**。这两条都是台架的窗，不是设计无辜。

于是 C9 把缝挪到正中、只开灰度、只看亮度不看 tag（灰度之后 tag 不存在，而图案每格位 15 恒为 1 ⇒
红通道最低也有 0xF8，灰度后仍远不是黑 ⇒"画面内出现一整列近黑"就是缺陷本身，与颜色无关）。

今天有两个尺子缺陷被暴露出来。它们共同点是：**症状出现在对照那一侧，
而不是被测那一侧**——这正是对照判据的价值。

### 9.1 缺陷一：分母把预热帧也算进去

原来的列直方图用 `c9_rows` 当分母，而 `c9_rows` 是在**每一个** `de_o` 下降沿加的，
连 `c9_on = 0` 的那几帧预热也算（`sim/tb_v98_top_seam.v:1208-1211` 现在把两个计数器分开写：
`c9_rows = c9_rows + 1;` 之后紧跟一行 `if (c9_on) c9_burst = c9_burst + 1;`）。

盘上那份读数是它的物证
（`build/evidence/r81_tb98_partial_0942_c9_denom_bug.txt:443,447`）：

```
C9b 0.50x gray+blur: rows 3000 near-black cells 921600 || whole-dark columns 0 (border should give ~512)
C9e full-processed x 1.5x x gray: rows 3000 de-burst 1200 px 1228800 near-black 0 || darkest col -1 = 0 rows
```

一个两帧的窗，真行只有 1200（`de-burst` 那一列），分母却报 3000。
于是"某列半数以上近黑"这条阈值**永远达不到**：判红需要 >1500 行近黑，
而这一窗结构上只有 1200 行。后果是双向的——

- **C9a / C9e 的绿是分母给的**：`0 * 2 < 3000` 与"哪怕整列真黑也过"是同一个式子，
  这条判据在那个版本里是恒真式。
- **C9b 的红也是分母给的**：`:443` 那行明明数到 921600 个近黑格（0.50x 那一档左右各有
  256 列黑背景，本该有约 512 根整列黑的柱子），`whole-dark columns` 却是 0，
  于是正对照判红。

`sim/tb_v98_top_seam.v:1192-1194` 现在把这件事写成注释钉在代码旁边，
并把两个计数器都打出来（`:1498, :1527, :1562` 的 `窗内整行 %0d（de 沿 %0d）`）——
**报两个数而不是一个**，就是"先确认归因，再谈判据"的落地形式。

### 9.2 缺陷二：正对照没有权力

`report/log/OVERNIGHT_LOG.md:5618-5623` 记着 r80 那一版的对照长什么样：C9b 当时判的是
"存在一列几乎全亮"（`best*4 < rows`），而 `best` 的初值就是 0 ⇒
**探测器一个格都没数到时 C9a 与 C9b 会同时绿**。那一轮的读数正是这样
（"近黑格 0、最暗列 −1/0、最亮列 1/0，三条全绿"，`report/log/OVERNIGHT_LOG.md:5619-5620`）——
这个绿什么也没证明：`−1` 是"没有任何列入围"的哨兵值（`c9_wcol` 初值 −1，
`sim/tb_v98_top_seam.v:1185`），而"最亮列 = 0"在 `best` 没有初值保护时是必然的。
换句话说，**C9a 那一窗报 0 究竟是"这里没有黑列"还是"探测器没看"，光看 C9a 永远分不开**——
这件事只有对照能回答，所以对照必须有权力。

改法是把对照换成"这一档结构上一定有黑列"："把**同一把尺子**拿到 0.50x
（左右各 256 列黑背景）那一档，整列近黑的根数必须 ≥ 100"（`sim/tb_v98_top_seam.v:1571-1594`），
注释原话："原来这一格判的是'最亮列几乎全亮'，而 best 的初值就是 0 ⇒ 探测器全瞎也照样 PASS，
也就是说 C9a 的那个 0 从来没被证明不是瞎"。旁边还配了它自己的地板 `C9bpre`（`:1529-1530`）。

于是今天那份跑里出现了本章最有用的一对数：同一把尺子，**C9a/C9c 绿、C9b 红**
（`build/evidence/r81_tb98_partial_0942_c9_denom_bug.txt:441-442, :445`）。
两个方向不可能都在说设计——一个恒真的判据与一个被分母挡死的判据同时出现，
只能说明坏的是量具，这就把矛头直接指向了 9.1 那条分母。

这是本仓第 N 次撞"从未执行的判据照样打 PASS"，`report/log/OVERNIGHT_LOG.md:5623` 记的那句差别
值得抄下来：**这次是我自己写的对照**。

### 9.3 还有一条：列号不能靠数 de 脉冲

`:1125-1129`：第一版把列号做成"数 `de_o` 脉冲"，而 `de_o` 一行内不止一个 burst ⇒

（`:1133-1135`），越界的样本**不数但要可见**（`:1138-1140`），否则直方图又会悄悄摊到错误的格上。

### 9.4 这一族的当前结论（很重要：是"作废"，不是"没有"）

`report/log/ISSUES.md:4876-4880, :4918-4924`：
C9 采的是 `dut.r/g/b`，那是 `split_display` 的输出、**OSD 之前**，所以它对 OSD 层画的东西

真正量到 #103 的是板上那三次读数 + 一次对照（`report/log/ISSUES.md:4905-4916`）：

## 10. 变异检验：证明判据真的在看着

### 10.1 规则

**把修复改回坏的样子，必须正好红那一条，别的一条都不红。**
`skill/SKILL.md` 硬规则第 3 条把它写成流程要求：新判据第一跑就绿 ⇒ 先做一次变异，
记下哪几条红；一条都没红 = 这条判据是装饰，不许写进结论。

### 10.2 仓库里最干净的一例：T7 / T7k

`sim/tb_v100_raw_delay.v:100-104` 与 `:204-210`。ISSUES #102 修的是"每行第 0 列读到
消隐期那个地址的格子"，修法是消隐边沿做一次预读。判据分成两条：

- `T7`：行首那一格必须等于"本行第 0 列"（绝对期望，钉病灶）；
- `T7k`：行内其余列必须等于"前一列"——注意注释里那句"期望是 **k 不是 k−1**（晚的是拍不是列）：
  预读只许占'de 刚掉下去'那一拍"（`:104`）。这一条盯的是副作用"别把每一列都推后一格"。

把输出改回 `assign d_out = q;`（关掉预读）重跑，凭据是
`build/evidence/r80_ring_head_module_cred.txt`：**只有 T7 红，16/16，行内 1008 格仍 0 错**
（`report/log/ISSUES.md:4746-4748`）——红恰好落在被修的那一格，判据没有连带伤到别的列。
反过来说，**第一版 T7 是白过的**：它把检查放在"喂完之后第二拍"，那一拍量到的是 `cell k`，
行首那一格从来没被看到 ⇒ 变异也绿 = 空判；必须"驱动之后、下一个 posedge 之前"取样，
才是硬件把标签与内容配对的那半拍（`report/log/ISSUES.md:4749-4752`，同一处还记着
"行内期望是 `cell k-1` 而不是 `cell k`：RAM 读出晚的那一拍晚的是**时序**，不是列号"）。

`skill/bench_self_inflicted_reds.md:43` 还把这条推广成一句可判的量化关系：
同一个机制做两种变异，"沿翻倍"红 3 条、"只删延迟保留末态"只红 1 条 ⇒
**末态类判据永远抓不到时序错**，它会放走一个真 bug 还让人以为验过了。

## 11. 一份台架报告该有什么，以及"没写出来的那条不算发生"

### 11.1 四件必备

1. **头部：跑的是哪一份源码**。`build/tb98_report.sh:31` 那一行
   `# provenance top_md5=… tb_md5=… rtl_md5=… date=… src=<run.log 路径>`，
   值来自跑的那天留下的 `prov.txt`（`:22-29`），拿不到就明写 `UNKNOWN` +
   "这份 run 早于出处机制，或不是 run_one.sh 跑的"。
2. **每条判据一行**，形状就是 2.3 那个 `line()`：`PASS`/`FAIL` 在最前、编号紧跟其后、
   期望与读数以 `|` 分隔。脚本取结论一律按**列**而不是按子串——台架侧看首列，
   门禁侧看末列（`build/tb98_gate_ce.sh:36-42` 专门写了为什么不能在整行里 grep `FAIL`），
   所以措辞里出现冒号、竖号、甚至 `FAIL行=0` 这样的实测值都不会误判。
3. **分列/分档的原始数量**：例如 `C2SHAPE`/`C2IBAD`/`C2 row`/`C4`/`P1` 那些 `$display` 行，
   以及 `RESULT` 之前的逐档表——11.2 讲的是这一条在什么情况下会漏。
4. **一句 `RESULT`**，用来钉"跑完了"这件事（缺它 ⇒ 门禁判"台架没跑完或中途退出"）。

规矩是：**报告里没写出来的那条，就不算发生**。听起来像官僚，它防的是
"我顺手多跑了一组，结果只写好的那组"。也因此：门禁输出**不要**用重定向塞进目标文件
（第 6.6 节那三个事故之一），先跑到临时目录、确认 ALL PASS、再复制进仓库留档。

### 11.2 今天的一条新缺口：白名单把原始读数挡在凭据外

`build/tb98_report.sh:32` 是一条固定词表的 grep：

```bash
grep -a "^\(PASS \|FAIL \|RESULT \|C2 table\|C2 row\|C2BLK\|C2SHAPE\|C2IBAD\|C4 \|C4RUN \|P1 \|INFO \)" "$SRC"
```

它收了 C2/C4/P1/INFO，**没收 `C9`**。实测：

```bash
grep -c "^C9 " build/tb_v98_report.txt        # → 0
```

于是门禁第 15 项认的那份凭据里只有 `PASS/FAIL C9a…` 七行（`build/tb_v98_report.txt:59-65`），
**没有那行带着 `rows 3000 / de-burst 1200` 的分母**。今天能认出分母虚高，
靠的是把整份 run.log 另存成 `build/evidence/r81_tb98_partial_0942_c9_denom_bug.txt`；
如果没有那次另存，这条结论就只剩一个"绿"字。
`sim/run_one.sh:52-55` 的过滤词表当年为同一件事补过 `PROBE/DIAG/NOTE/OBS`——同一个坑的两侧：
一侧是终端不打印，一侧是凭据不收。

### 11.3 凭据里的字也可能已经坏了

同一份 `build/tb_v98_report.txt` 第 57、58 行（`PASS C8a…` / `PASS C8b…`）的竖号后面
**不是合法 UTF-8**：台架 `$display` 里的中文经过 Windows 控制台代码页写进 run.log，
每个汉字变成 `0xff` 打头的一串字节（`python -c` 解码这两行会直接抛
`'utf-8' codec can't decode byte 0xff`）。结论列仍可判（判决在最后一列），
但"为什么"这一半给人看的话已经不可读。

为什么第 17 项没抓到它：`src/host/doc_enc_check.mjs:10-12` 明写 `*.txt` 一律不扫，
因为那类文件放的是 Vivado / xsdb / PowerShell 的原始回显，本来就是 cp936 或 UTF-16，
"修成 UTF-8"才是破坏凭据。问题是 `tb_v98_report.txt` 不是原始回显，
它是我们自己从 run.log 抽出来的**派生件**——正好落在那条边界的缝里。
**判掉它的读数**：同一份文件里 `PASS/FAIL` 行能不能被 `python -c "open(...).read().decode('utf-8')"`
整文件解出来；解不出来就说明"这张凭据的可读部分只有判决列"。

评审照文档去翻却翻到一个不存在的目录，而这件事不改变任何行为——位流照编、台架照跑、门禁照绿
（`:107-111`）。D4 因此分两半：

- **D4a**（`:118, :127-131`）：带目录前缀、以 `.md` 结尾、且不是占位名的指路 ⇒ 目标必须在盘上。

  因为那些注释就是"下一版该去看哪一份"的指路（`:192-200`）。
  不扫的是生成物、器件库，以及**冻结件里那份文本**（它指的路就是它冻结时的那条路，
  改它等于伪造记录）和本地学习材料（`:140-145`）。
  这一章自己也在豁免名单里——所以第 0 段那句"不要相信这里的行号胜过相信代码"不是免责声明，
  而是实话：**没有判据替本目录兜底**，指路错了要靠人 grep。
- **D4b**（`:119, :132-134`）：那个已经搬走的旧顶层目录名后面**直接跟文件名字符** ⇒ 一律红；
  而"当年那个旧目录"这种**叙事**（斜杠后面是空格）不算指路，放过。
  日记也在 D4 的扫描范围内：既然指路已经全部改写，留着就是半搬（`:116-117`）。

这里有一个可以亲手体会的口径边界：D4b 的正则要求 `旧目录名/` 后面紧跟一个文件名字符，
所以第 17 项清单里那个光秃秃的目录名字符串**不会**被它咬到（见 12.1）。

覆盖面要靠人加，不能指望正则自己长全。

### 12.5 批量改文本的不变量判据：`build/trim_comments.py`

2026-09-28 凌晨那一轮把 `src/rtl` 与 `sim` 的长条注释压薄（154 个文件里改了 103 个，
注释 5003→3552 行），护栏是"**代码逐字不变**"（`report/log/OVERNIGHT_LOG.md:5674-5688`）。
尺子是 `build/trim_comments.py --check`：把**工作树**与 **HEAD** 各自 `code_of()` 剥掉注释、
`norm()` 折叠空白之后比较，任何文件不等就打印文件名并 `return 1`（`:86-102`）。

真正要说清的是**决策与比较用的是两套口径**，而且这是对的：

- **比较可以归一化**：`code_of()` 保留行结构（`"//"` 只扫到行尾，`:47-51`），
  `norm()` 再把空白折平（`:64-66`）——这样"删掉一整行注释留下的空行"不会被误判成代码变了。
- **决策必须逐行**：`--strip` 只删**整行**都是装饰的行（`:21-22` 的正则
  `^\s*//\s*[-=~*_#.\s·—─]*\s*$`），而且要求它的上下也是注释才删
  （`:112-117`："别把 `/*` 块中间的分割线删出空洞"）。

为什么不能按归一化之后的文本决策：一旦把空白折平，"整行只有装饰"这件事就没有载体了——
`assign x = y; // ───` 与一行独立的 `// ───` 在 token 流里长得一样，
而只有后者能整行删除。更硬的一条是：`code_of()` 对 `//` 的判定靠"找到下一个 `\n`"来收尾（`:48`），
归一化之后这个终止符不存在，`//` 会把后面整个文件吞掉；
同理它必须原样保留字符串字面量（`:32-45`），否则 `$display("…//…")` 里的两个斜杠会被当注释起点。
**"逐行"不是风格，是这套算法的定义域。**

一处要如实记下的落差：文件头（`:8-9`）声称 `--strip` 在写完之前还会用 `code_of()` 比一遍、
不满足就回滚，而 `do_strip()` 的实现（`:105-126`）里没有这一步——
它只靠 DECOR 的整行形状保证不碰代码。真正兜底的是**每改一批之后手动跑一次 `--check`**
（那才是与 HEAD 比的那一刀）。这一条与"注释会旧于代码"是同一族账，
本仓已经为它记过 `#106`：台架 `$display` 里硬编码的 `[tb_x.v:123]` 有 198 处，
删注释之后行号就指到别处了（`report/log/OVERNIGHT_LOG.md:5689-5691`）。
本轮只量过一件事：`build/*.sh` 里没有任何一处读这些行号，门禁不受影响。

## 13. 机器判据与眼睛判据的分工

### 13.1 什么时候才许叫人

规则先写在 `skill/eye_acceptance_loop.md:17-18`：**叫人来"看一眼"之前，
先把"台架为什么不覆盖它"那句话写下来**。写不出这句，这一眼就只是形式主义，
下一个人会拿它当免检。#103 的这一段就补上了这句话（两条结构盲，见第 9 节开头）。

### 13.2 配方，不是提问

眼睛类条目要写成**配方**：前置状态（哪一路片源、哪一档倍率、标记线开没开）→
一次一条的命令 → 每一个"不"分别指向什么病灶。例：

```
命令：src 0 → zoom 1.0 → split 100 → marker 0
前置：读回 `split show`，确认 marker 那一栏是 off
判什么：最左一列是否与它右边一列同色
每个"否"是什么意思：能看到一条竖线 ⇒ 抽头相位的行首问题（#102 的修法与 C8a/C8b）
```

`board/README.md:1` 那张表里每一条都是这个形状（第 22/29/30/32/33 项甚至把
"请分类回报①②③"写死，因为三种回报对应三种不同修法）。

### 13.3 二分杠杆

本工程的旋钮是一个 0/50/100 的分割量：`split 50` + 关掉标记线 ⇒ 一屏同时给出两份抽头，
一个现象出现在左边还是右边，就直接说明它属于哪条通路——这比任何单侧截图都可判。
同理还有 `src 2`：强制走 PL 自生图卡，不经 DDR、不经 ETH，
一条命令就能把"通路"这个维度切掉一半（`report/log/ISSUES.md:4900-4903`）。

一次问不超过三条、每条只问一个事实：①在不在？②宽度跟不跟着倍率走？③颜色跟不跟着内容走？
三个答案就把"哪一路 / 几何还是取值 / 是不是我自己造出来的"分开（`skill/eye_acceptance_loop.md:22-24`）。

### 13.4 先排除自己造出来的伪像

凡是"操作者看到的异常"与"代理刚刚动过的东西"落在同一条边上，先关自己的那个开关。
#103 走的一次弯路就在这里：那条 2 px 标记画的是**深蓝** `8'h40/40/FF`
（`src/rtl/video/split_display.v:64-65`），在黑白的边缘图里会被念成"黑线"；
`split show` 的 `marker=` 一栏没确认，两条解释就都排除不掉（`report/log/ISSUES.md:4830-4837`）。
另一条同类：只看缩放 1.00× 的左边缘不构成证据，因为卡片自己的亮边框会让那一列无法判断——
**判据所看的那条边在这一档碰不到时不算证据，换一档再看比再看一次有用**。

### 13.5 眼睛也要有状态断言的凭据

"我已经发了 X"这类话只能从捕获文件里 grep（`skill/eye_acceptance_loop.md:27-28`）。
#107 那一次的表现是"发两次同样的值看起来没反应"，
正确读法是读回 `split show` 里那个 swap 旗标，而不是凭眼睛找"交换的瞬间"
（`report/log/ISSUES.md:4805-4807`）。关闭一次眼睛验收要**两半都签**：操作者原话 + 机器判据的数字，
谁也没替谁签；操作者不在场时不许自代签。

## 14. 绿了但仍然不可信：八种情形与各自的那一把尺子

这张表是本章的用法索引。左边是情形，右边是**用什么读数把它判掉**（不是"小心一点"）。

| # | 情形 | 判掉它的读数 / 出处 |
|---|---|---|
| 1 | 报告与当前树不是同一次跑 | 头部 `top_md5/tb_md5/rtl_md5` 三枚与 `md5sum`/`find…\|md5sum` 现值逐个比（`build/gates.sh:264-283`；见 7.5 的现场不等） |
| 2 | 正文来自两个进程 | 门口守卫 `exit 3`（`sim/run_one.sh:18-22`）；已经发生过的形状是"md5 全对、行混了两跑"（`:11-17`） |
| 3 | 空集上的绿 | 每条结论旁边的**样本数**与地板行（`sim/tb_edge_rim.v:428-431`、`build/tb_v98_report.txt:41` 的 300/480） |
| 4 | 判据根本没执行 | `invbad == 全部样本`、`viol == nout` 这类分母=分子的签名（`build/tb_v98_report.txt:71,75`；`sim/tb_v98_top_seam.v:1612-1620`） |
| 5 | 正对照没有权力 | 对照组必须**数到非零**：`近黑格`、`whole-dark columns`（0.50x 那档应约 512）（`sim/tb_v98_top_seam.v:1571-1594`；`report/log/OVERNIGHT_LOG.md:5618-5623`） |
| 6 | 分母把预热帧算进去 | 同一窗报**两个数**：`窗内整行` 与 `de 沿`；两者之比应当约等于窗内帧数（`sim/tb_v98_top_seam.v:1192-1194, :1498`；`build/evidence/r81_tb98_partial_0942_c9_denom_bug.txt:447`） |
| 7 | 判据读的不是被测对象 | 取数点必须落在被判的那块上；落不到就**只报数不判**（`skill/bench_self_inflicted_reds.md:37`；本仓 `C-tap` 那条降级为 OBS 的例子） |
| 8 | 门禁读的正是它自己刚写的文件 | "它读的文件是谁写的、什么时候写"这一问（`build/gates.sh:12-18`），外加退出码不从管道取（`:341-343`） |

三条通用作法，能盖掉上面大多数：
**(a)** 每个结论后面挂一个文件与一个数字，挂不上就改口径写成假设；
**(b)** 新判据第一跑就绿 ⇒ 先做一次变异，一条都不红就不写进结论；
**(c)** 差分判据成对、正对照必须能动——"A 与 B 必须一致"要配一条"A 与 B 故意不同时该红"，
否则 A、B 一起错它就永远绿；一条历史上从没非零读数的判据其实什么也没测。

## 16. 一句话总结

这一章所有条目都在同一句话上：**"绿"不是一个状态，是一条主张**，
它必须能指回一份带源码指纹、带样本数、并且被证明过能变红的产物。
指不到的，就当没发生过——这不是苛刻，是因为**假绿会让之后所有人不再检查**，
而这一章里每一条纪律，都是有人先替所有人踩过一次才写下来的。

> `build/gates.sh:133` 与 `build/gates_cdc_test.sh:2` 的注释里把这一节叫"学习文档 §十二"，
> 那是旧编号；在本章它现在就是第 6.5、10、12 三节。

```bash

```

所以读任何一份产物，第一件事永远是看它头部那一行。
