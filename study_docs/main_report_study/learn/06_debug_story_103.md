# 一次真实的定位：从"屏上一根黑线"到"越界的数组写在硬件里走了另一条路"

这份文档不是复盘流水账，而是把**方法**拆到能被你下次自己复用的粒度。全程没有一处是"想出来的"，
每一步都有一个读数或一条命令。

## 0. 症状与最容易掉的坑

症状：屏幕上有一条竖黑线，**处理过的半边有、原图那半边没有**。

最容易掉的坑是"看图猜模块"。猜出来的修法会改错地方，而且改完你还是不知道对不对。
所以第一步不是猜，是**把"在哪里"变成可判定的实验**。

## 1. 用现成的开关做二分（不写一行代码）

板子上本来就有一批运行时开关（串口 `osd/pipe/zoom/split/bilin/src` 这些），它们就是免费的探针
（口径提醒：`bilin` 这一枚在 r94 之前只有"角度=0"才切得动——旋转支的小数被丢掉了，#104，现已修，
所以它现在在旋转态也是一枚有效探针）：

| 实验 | 观察 | 排除掉什么 |
|---|---|---|
| `split 100`（整屏原图抽头） | 线消失 | 不在共用读口（帧缓存、双线性读口、mapper）——那些两条通路共用 |
| `split 0`（整屏处理抽头） | 线还在原位 | 不是分割线本身画出来的 |
| 换 `zoom` | 位置不动 | 它按**显示列**索引，不是源坐标 ⇒ 不在缩放/旋转的算术里 |
| `pipe` 九级全关 | 还在 | 不是某一级的算法错，是"旁路"这条路径本身 |
| 只开模糊 | 还是**一条**、没摊成三条 | 黑不是模糊的输入带进来的（否则 3×3 会摊开） |
| `fill` 平色帧 + `th 8` + 只开二值 | 整屏白，线还在 | 与片源内容**完全无关**；且到二值级还是纯 0 |

到这里，嫌疑范围被压成一句话：**在效果链内部、按显示列索引、与内容无关、每个被旁路的窗口级都会自己造一次。**

## 2. 把嫌疑变成"单元台架"，并且先让尺子可信

写了个只测效果链的台架 `sim/tb_v103_pipe_bypass.v`。三个坑，每一个都会让结论作废：

1. **激励的行号必须递增**。如果把 `y_in` 钉在 0，窗口级的"整行陈旧"旗标每拍都成立，
   旁路就不走行缓存了 ⇒ 你的判据在**一条根本没执行的代码**上发绿。
2. **图案只能随列变，不能随行变**。旁路取的是窗口中心抽头，天然带 −4 行；图案随行变，
   判据就会红在"行偏移"这个正当理由上。
3. **列号不许由"我数第几个脉冲"决定**。第一版就是这么干的，量到"整行 1024 列全不符"——
   那是尺子的错：只要有一个恒定偏移，整行就都红，判据永远没有牙。
   改成**图案可逆**（把列号编进像素的 5+6+5 位里，再从输出解回来），
   才第一次把"内容错"与"位置错"分开。

还有一条通用规矩：**新加的探针必须自带正对照**。这份台架在复位后、一个像素都没喂的时候，
先扫一遍九条行缓存，要求它数到 **1024 个 X 槽**——否则"零个未写槽"那个绿，
可能只是因为分层引用没指到真数组（探测器瞎）。

## 3. 关键读数：仿真说"没有"，硬件说"有"

台架量到两件事：

- 九条行缓存里，**每一条的第 1023 号槽从来没被写过**（`CACHE after A: total=1 first=1023`）。
- 每行输出的第一格是干净的 `0x0000`，其余每格是前一列的内容。

原因在 `proc_pipeline.v` 的一行：坐标延迟线写的是 `xd[0] <= x_in`，于是抽头 `xd[k]` 实际是
**k+1 拍**延迟，而注释和四个抽头号（2/5/8/12）按的是 **k 拍**口径。差这一拍导致：

- 每行最后一个有效拍上，写地址只到 1022 ⇒ 1023 号槽没人写；
- 每行**第一个**有效拍上，写地址还停在消隐末尾的 **1343** ⇒ **越界写**。

这里是全文最重要的一课：**Verilog 仿真对越界的数组写是"静默丢掉"，硬件是把地址按位截断。**
`1343 mod 1024 = 319` ⇒ 每行往第 319 格写进消隐期的值（`pix_raw` 被越界标志钉成 0x0000，
也就是"画面外涂黑"那一条规矩；这里的"钉成 0"钉的是**越界像素的颜色**，与 #104 那条
"旋转支把小数钉成 0"不是同一件事，后者 r94 已修、见第 11 章 §2 与 §7.9），
而读回这一格的是真实列 320 那一拍。于是：

> **预测：黑线在显示列 320。**

## 4. 让眼睛去证伪这个预测

把分割标记线摆在 31%（`split 31` ⇒ pos=317，蓝线占 316/317），问一句"黑线在蓝线右边两三像素吗？"
回答是"紧贴蓝线右侧"。**预测被打脸的风险在于它真的可能被打脸**——这就是"量"和"推"的区别。

## 5. 修法与它的连带账

- 让 `xd[k]` 真的是 k 拍（`xd[1] <= x_in`，数组范围 `[1:12]`）。
- 标签对齐后，右边界旗标的武装位必须从 `H_ACTIVE-2` 改回 `H_ACTIVE-1`——
  因为那套旗标位置是在**旧的错位之下**由 `tb_edge_rim` 量出来的。
  **改一处对齐，就要把依赖这个对齐的判据全部重跑**，这不是繁琐，是这一类改动的本体。

## 6. 顺手挖出来的另一条（以及为什么不当场修）

台架还量到：链子的数据比它自己的 `de_out` 晚一拍 ⇒ 每行末列发不出去、行首凭空多一格黑。
顶层用 `pipe_dout_q` 那一拍把列对齐抵住了，所以屏上只在最左一列有一点点痕迹（#102 那一族）。
修它要同时重标顶层两处延迟账 ⇒ 单独一轮，不混进这一版。
**能识别"这是另一条病"并且忍住不顺手改，是工程能力的一部分。**

## 7. 你该带走的四条

1. 现成的运行时开关就是最好的二分工具，先做实验再做假设。
2. 判据要能红：正对照、复位对照、可逆图案，三样缺一条，绿就可能是假的。
3. **仿真与硬件在"未定义行为"上是两种机器**：越界索引、未初始化 RAM、X 传播、多驱动。
   屏上有而仿真没有 ⇒ 第一优先怀疑这一族。
4. 一个能被证伪的定量预测（"第 320 列"）值十段"我觉得可能是……"。
