# 演示视频拍摄脚本（5 分钟剪辑版 · 实物操作）

> 口径：**只用真实存在的控制面**。运行时改画面靠两样——串口控制台敲命令、板上 KEY1 长按；
> Tcl 只在构建期用，**视频里不许说"用 Tcl 实时控制"**。旁白里每一个数字都要能在 `report/PERF_REPORT.md`
> 指到一份带 md5 的报告；说不清来源的一律不念。
>
> 拍摄前一次性准备：板子已烧本版 bit + 已 `ps_app_reload`；SD 卡里有帧序列；PC 端串口终端开着
> （115200，UTF-8）；HDMI 显示器在板子右边；相机机位见下面第 2 节。

## 2. 机位与同框方案

- **主机位（A）**：45° 侧俯拍，同框进"板子 + 显示器左半 + 键盘右角"。这一路负责"操作与结果在同一张画面里"，
  评委最想看的就是**敲下回车的那一瞬间屏幕变了**。
- **副机位（B）**：手机夹在显示器边框上正拍屏幕（或 HDMI 采集卡直接录数字信号——**优先采集卡**，
  拍屏会有频闪和摩尔纹；如果只能拍屏，把快门调到 1/50 或 1/100 并关掉房间灯）。
- **特写（C）**：手持拍 KEY1 长按与拔网线/拔 SD 卡的动作，10 秒以内即可，剪辑时插进 3:50 与 4:20 两段。
- 串口终端窗口：字体 ≥ 16 px、深色背景、窗口只留命令行那一块（`stat` 那一行要能看清）。

## 3. 剪辑与倍速

- 命令回显、`stat` 输出这类"文字信息"：用 **1.5–2 倍速 + 打字幕**，不要念日志。
- 画面变化本身（缩放、旋转、split 扫过）：**原速**，且每个变化给足 2 秒静止——评委要看的是"变化前后"。
- 拔线/拔卡那两段：保留原速并加一句字幕"硬件仲裁，无软件介入"。
- 全片不加背景音乐盖旁白；片尾压一张"门禁 20 项 + 一条命令构建"的静态图 3 秒。

## 4. 失败预案（实拍时准备）

| 症状 | 现场处置 | 剪辑挽救 |
|---|---|---|
| 串口无回显 | **不要碰 JTAG**（这是踩过一次的坑：静默的串口不是重烧的理由）。先确认终端没占用 COM 口、线没松；再 `stat` 试一次 | 用之前录好的 B-roll 顶这 20 秒 |
| 屏幕全黑/冻帧 | 先看 OSD 的 `SRC:` 与 `*` 号：锁在 PS 而没新帧就是"冻在最后一帧"，属正常语义 ⇒ 敲 `src auto` | 保留这段并念解释——反而是加分（说明行为可解释） |
| 某条命令不认 | 敲 `help` 抄语法，**不要猜**（带参数的命令一条一发，别用逗号批处理） | 剪掉试错那几秒 |
| 拍屏频闪严重 | 改采集卡；没有采集卡就把显示器刷新/相机快门互调，或降机位角度 | 用采集卡补录同一段 |
| 时间超 5:00 | 先砍 2:50 双线性那段（它是"边界说明"，不是高光） | — |
