# 07 双线性：四抽头怎么在一个读口上取来，权重怎么不算出饱和

被测对象：`src/rtl/process/bilin_lerp.v`（算术核）、`src/rtl/process/bilin/fb_bilin.v`
（显示侧唯一的帧缓存读口，现行设计）、`src/rtl/process/bilin/fb_rd5x.v` 与
`src/rtl/process/bilin/tap_sched.v`（250 MHz 五槽那一版，今天只剩台架在钉，见 §5）。

读完这一章要能回答：一个源像素为什么要用满四个 50 MHz 拍；
四个抽头是怎么从一个读口里排出来的；`(!bilin_en || sx >= IMG_W-1) ? 8'd0 : fx` 这一道钉子
为什么"只钉小数"不够、必须再来一次折回；插值的位宽为什么不会溢出、这个结论是谁逼出来的；
以及暂存 RAM 的索引为什么不能是源列。

---

## 1 前置知识

### 1.1 双线性是可分离的两次线性插值

给小数坐标 `(sx + fx, sy + fy)`，`fx, fy ∈ [0,1)`：

```
row_top(x) = (1−fx)·P00 + fx·P10
row_bot(x) = (1−fx)·P01 + fx·P11
out        = (1−fy)·row_top + fy·row_bot
```

三条性质是本模块正确性的地基，全部可以只用代数验证：

* **权重和恒为 1**：`(1−fx) + fx = 1`，`(1−fy) + fy = 1`。所以四角同色时输出必等于那个色，
  不管 `fx/fy` 取什么——这不是近似，是恒等。台架把它写成判据 2
  （`sim/tb_bilin_lerp.v:121` "四角同色对全部采样 (fx,fy) 恒等（白/黑/纯红/纯绿/纯蓝/一般色）"），
  而 RTL 的"不需要饱和"这条结论就是被它逼出来的（`src/rtl/process/bilin_lerp.v:6-7`）。
* **`fx = fy = 0` ⇒ 输出逐位等于 `P00`**：判据 1（`sim/tb_bilin_lerp.v:87`）。
  这一条是整个退化机制的支点：末列/末行把小数钉 0 之后，插值就**逐位等于**最近邻。
* **结合顺序影响最低位**：先横后纵与先纵后横只允许在最后一步舍入上差 ±1 个输出码。
  黄金模型故意用另一种结合顺序算（`sim/tb_bilin_lerp.v:17-19`），
  RTL 是先横（`bilin_lerp.v:28-48`）后纵（`:50-61`）。

### 1.2 RGB565 的展开必须用位复制

一个 16 bit 像素是 `{R[4:0], G[5:0], B[4:0]}`。要在 8 bit 精度上插值就得先展开：

```
function [7:0] rep5; input [4:0] v; begin rep5 = {v, v[2:0]}; end endfunction   // bilin_lerp.v:20
function [7:0] rep6; input [5:0] v; begin rep6 = {v, v[1:0]}; end endfunction   // :21
```

**位复制而不是左移补零**：`0b11111` 复制成 `0b11111111 = 255`；
左移补零给 `0xF8 = 248`。后者会让纯白在插值后变灰，而且"四角同色恒等"这条性质直接破掉
（四角都是 `0xFFFF` 时输出只能是 `0xFFF8` 那一族）。台架为此单独写了判据 6，
红的时候说的话就是这件事（`sim/tb_bilin_lerp.v:93`：
"FAIL 判据6 纯白插值后 = %h（应仍为 ffff，说明展开通道不是位复制）"），
判据本体在 `:95`。

### 1.3 Q8 权重与"和恒为 256"

`fx/fy` 是 8 bit，代表 `[0,1)` 的小数（`bilin_lerp.v:15-16` 的端口注释）。权重取整数域：

```
wx0 = 256 − fx, wx1 = fx        // bilin_lerp.v:29-30（9 bit，永远 ≥ 1）
wy0 = 256 − fy, wy1 = fy        // :51-52
```

`wx0 + wx1 = 256` 恒成立 ⇒ 横向结果 `≤ 255·256 = 65280`（17 bit 封顶），
纵向 `≤ 255·65536 + 舍入 < 2^24`（25 bit）。这两个界写在
`src/rtl/process/bilin_lerp.v:6-7`，而"不需要饱和"是**结论**不是假设——
它由判据 2 强制检验（同一句里就是这么写的）。

### 1.4 存储布局：一个 64 bit 字 = 4 个像素

帧缓存是 `src/rtl/video/frame_buffer_w64.v`：`W×H` 像素折成 `WORDS = (W·H+3)/4 = 38400` 个
64 bit 字（`:32`），写口一次 4 个像素，读口给出整字，取哪一个像素由 2 bit "车道" `pxl[1:0]` 选。
所以一个源像素 `(sx, sy)` 的四个抽头在字与车道上是这样的（`IMG_W = 512 ⇒ ROW_WORDS = 128`）：

```
pxl   = sy·IMG_W + sx                 // fb_bilin.v:42
w_a   = pxl[18:2]                     // :43   左上所在字
lane  = pxl[1:0]                      // :44   左上车道
w_b   = w_a + ROW_WORDS               // :45   下一行同列
A+1   = w_a + 1 ；B = w_b ；B+1 = w_b + 1
```

**跨字**：`lane == 3` 时 `sx+1` 落在下一个字里，所以 `p10 = fb_word[15:0]`（`fb_bilin.v:140-141`），
`p11` 同理（`:158-159`）。这一条与 `bilin_en` 无关，最近邻也一样要读第二个字。

## 2 原理拆解：一个读口、每拍一次读、四个相位

### 2.1 为什么"每源像素四拍"是免费的

面板 1024×600 对应源 512×300 ⇒ 一个源像素在屏上占 **2 显示列 × 2 显示行 = 4 个显示像素**，
而 mapper 的源坐标来自 `cx = x >> 1`、`cy = y >> 1`（第 05 章 §2.1），
所以**同一对显示列里两拍 `sx` 相同、同一对显示行里两拍 `sy` 相同**
（`src/rtl/process/bilin/fb_bilin.v:20-21` 的端口注释把这句话写成了接口契约）。
也就是说：这四个 20 ns 的拍子本来就在，像素内容也一样，
只要把它们拿去读四个抽头，就**不需要第二个读口、不需要快时钟**。

这是 r63 那一刀的核心：整条链留在 50 MHz 慢域，快域一个字节都不进
（`src/rtl/process/bilin/fb_bilin.v:4-5`：
"每个源像素用满它天然的 4 个 50 MHz 拍（2 显示列 × 2 显示行），一个读口每拍一次读，全程不进快域"）。

### 2.2 四个相位的排法

槽位由两个相位位决定：`col0 = ~x[0]`、`row0 = ~y[0]`
（顶层递的是 `~x_d[2][0]`、`~y_d[2][0]`，见 `src/rtl/top/pl_video_top.v:744`）。

| `(row0, col0)` | 这一拍发的地址 | 读的是哪个抽头 |
|---|---|---|
| (1,1) | `w_a` | A = (sx, sy) |
| (1,0) | `w_a + 1` | A+1（给 `p10` 用） |
| (0,1) | `w_b` | B = (sx, sy+1) |
| (0,0) | `w_b + 1` | B+1（给 `p11` 用） |

表在 `src/rtl/process/bilin/fb_bilin.v:37-38`，地址式子在 `:56`：

```
wire [16:0] addr_nxt = (row0 ? w_a : w_b) + (col0 ? 17'd0 : 17'd1);
```

**先选行再加列**，不是四个候选字：`:55` 说"两个 17 bit 加器串成一级 mux 之后，而不是四个候选字"。
这是拿 mux 树换成加法器——四选一的 17 bit mux 是 4 级 2 输入 mux 或者一层 4:1 单元，
而 `17 bit + 1` 只是一条进位链，代价小得多。

### 2.3 延迟：2 拍到数据，再加一整对显示行

* 地址先打一拍（`fb_bilin.v:58-62` 的 `addr_q`）+ BRAM 内部那一级输出寄存器
  ⇒ **请求到数据 2 拍**（`:39-40`）。
  顶层的 `MIX_D = 3 + 1 + 1 + u_pipe.LATENCY`（`src/rtl/top/pl_video_top.v:354`）里那两个 `1`
  就是这两拍，所以换成 `fb_bilin` 之后混色级、skid、`SEAM_TAPS` 一个都不动
  （`:721-725`）。
* 结果缓冲是乒乓（§3.4）⇒ **内容整体晚 1 对显示行 = 2 个显示行**。
  这个数字是量出来的不是推的：`sim/tb_v101_fb_bilin.v:287` 的 L3 把
  `(行滞后, 列平移)` 当两个未知数搜索，要求**只有唯一一组成立**，实测 `(2, 2)`；
  于是同一文件 `:40` 把 `LAG = 2*H_TOT + 2 = 2690` 钉住，所有逐点判据都在这个偏移上做。
  顶层因此要在行号上再加这 2 行：`BILIN_ROWS = 2`（`src/rtl/top/pl_video_top.v:250`）。

**为什么行方向必须晚一对**：一对显示行的第二拍才读到 B+1，四抽头才凑齐；
`lerp` 又是两级（`bilin_lerp.v:3` 的"两级流水"），所以结果只能在那一对的末尾写进缓冲，
下一对被显示。这一句的完整口径在 `fb_bilin.v:182-183`。

### 2.4 位宽账（逐条界）

| 量 | 宽度 | 上界 | 出处 |
|---|---|---|---|
| `wx0/wx1` | 9 | 256（`fx = 0` 时 `wx0 = 256`） | `bilin_lerp.v:29-30` |
| `tr/tg/tb/br/bg/bb` | 17（`reg [16:0]`） | 255·256 = 65280 | `:31-32`、`:39-44` |
| `or_r/or_g/or_b` | 25 | 65280·256 + 32768 = 16,744,448 < 2^24 | `:53-55` |
| `vr/vg/vb` | 9（取 `[24:16]`） | ≤ 255 ⇒ 不夹取 | `:59-61`、`:57` |
| `pix` | 16 | `{vr[7:3], vg[7:2], vb[7:3]}` | `:67` |

四舍五入那一步是"纵向合并后一次 `+2^15` 再 `>>16`"（`:53` 的 `+ 26'd32768`，移位靠 `[24:16]` 切片）。
`>>16` 用位选而不是 `/65536`：一次除法都不要。

还有一条容易漏的写法约束，`:58` 明写：
"注意不能写 `or_r[24:16][7:3]` —— Verilog-2001 不允许对位选结果再位选"。
所以先落到 `vr` 这根线上再切。

### 2.5 每一拍的预算

| 时钟 | 周期 | 预算 | 本章谁在用 |
|---|---|---|---|
| `clk_pix` | 20 ns | 慢域算术：地址加法、车道 mux、12 个乘法 | `fb_bilin`、`bilin_lerp` |
| `clk_pix5x` | 4 ns | 快域只许落直线（无逻辑） | `tap_sched`（已退出顶层） |

`clk_gen.v:24` 那一路 `CLKOUT1_DIVIDE (4)` = 250 MHz 仍然存在（`rgb2dvi` 的串行化要用），
但读口不再碰它。§5 给这条边界的实测账。

## 3 代码逐段分析

### 3.1 `bilin_lerp`：算术核，与"抽头怎么取来"完全解耦

文件头 `src/rtl/process/bilin_lerp.v:2-3` 就把解耦说清楚了：
"4 个 RGB565 抽头 + Q8 小数位 → 1 个 RGB565。与'抽头怎么取来'完全解耦
（那部分是读口调度），所以能单独对着行为黄金模型逐位验"。

两级流水：

* **第一级（`:35-48`）**：六个乘加 + `fy1 <= fy` + `v0 <= 1'b1`。
  注意 `fy` 要跟着延一拍（`:45`），因为纵向用的是**上一拍**的横向结果。
* **第二级（`:63-70`）**：打包成 RGB565 输出，`vld <= v0`。

复位纪律只复位 valid：`:37`
"只复位 valid：数据寄存器带异步复位会挡住它们被打进 DSP48 流水级"。
这一句解释了两个 `always` 里为什么 `tr/tg/tb/br/bg/bb/fy1` 都不在 `if (!rst_n)` 里出现——
带异步复位的寄存器不能被工具塞进乘法器的原生流水级，会掉回普通 LUT 乘。

`v0/vld` 的作用是让下游知道"这两拍之后出来的不是复位期的空值"。
两个消费者都把它接成悬空（`fb_bilin.v:175` 的 `.vld()`、`fb_rd5x.v:152` 的 `.vld()`），
因为节拍是恒定的、不需要 valid；valid 留给台架（`sim/tb_bilin_lerp.v` 每改输入等 3 个上升沿再取）。

### 3.2 `fb_bilin` 的三级保护：钉小数 + 折回抽头

`src/rtl/process/bilin/fb_bilin.v:46-54`：

```
wire [7:0]  fx_use = (!bilin_en || sx >= IMG_W-1) ? 8'd0 : fx;   // :51
wire [7:0]  fy_use = (!bilin_en || sy >= IMG_H-1) ? 8'd0 : fy;   // :52
wire        kx_use = !bilin_en || sx >= IMG_W-1;                  // :53  横向抽头折回
wire        ky_use = !bilin_en || sy >= IMG_H-1;                  // :54  纵向抽头折回
```

**只做第一件事是不够的**，`:49-50` 给了具体理由：
末行那次 `w_b = w_a + ROW_WORDS` 会读到帧缓存的**填充区**——
硬件里是 BRAM 上电的 0、xsim 里是 X，而 **X × 0 = X** ⇒ 整行被污染。
"折回后对填充区零依赖"。

为什么 xsim 会是 X 而硬件是 0，这来自 `frame_buffer_w64` 的分区方式：
`:37-38` 把 38400 个字拆成 `lo[0:32767]` + `hi[0:8191]` 两块，
`hi` 那块里 `[5632:8191]` 是从不写的填充。台架还专门把这两块抹成 0 来对齐板上态
（`sim/tb_v101_fb_bilin.v` 的激励段："写前把 `dut.u_fb.lo[0:32767]/hi[0:8191]` 抹成 0"）。
顺带说一句：这个拆块本身就是被资源逼出来的——不拆（单个 38400 深阵列）时
BRAM 推断会把非 2 幂深度向上填到 2^16 ⇒ 实测吃 128 个 RAMB36（全片 140），
拆成 32768 + 8192 之后实测 80 个（`src/rtl/video/frame_buffer_w64.v:4-7`；
那句里提到的对照实验目录 `tmp_ramtest/` 今天不在树里，所以这条只能引注释，
不能引原始数据）。

折回在哪落地（`:144`、`:160-162`）：

```
wire [15:0] p10_y0c = kx_d2 ? p00_y0 : p10_y0;                    // :144 末列：右邻 = p00
wire [15:0] p01     = ky_d2 ? tap_r[15:0]  : p01_raw;              // :161 末行：下一行 = 本行
wire [15:0] p11     = ky_d2 ? tap_r[31:16] : (kx_d2 ? p01_raw : p11_raw);  // :162
```

三条合起来的性质值得自己代一遍：`kx = ky = 1` 时四个抽头全部等于 `p00`，
而 `fx_use = fy_use = 0` ⇒ `lerp` 恒等输出 `p00`。
**这就是"末列末行的双线性等于最近邻"的完整实现**，而且它不依赖 `bilin_en`——
`bilin_en = 0` 走的是同一道钉子（`:48`："本模块逐位等于最近邻，板上 on/off 来回切不需要重新构建"）。

越界本身另有出口：`oob_in` 与像素同一次写、同一拍读出 ⇒ 同一个像素、同一拍回黑
（`:47` 与 `:197-198`）。

### 3.3 标签必须跟着内容走，不许另开延迟链

`:83-85`：
"请求属性跟着数据走（数据 = 请求 + 2）。四级：d1/d2 与'当拍到达的数据'配对，
d3/d4 与'lerp 输出那一拍'配对。**不许给标签另开一条延迟链：标签与内容不同级就是错。**"

被延的标签有 8 组（`:86-93`）：`lane`、`fx/fy`（延到 `fx_d2/fy_d2`，喂 lerp）、
`j`（四拍）、`r0/c0`（相位）、`h`（乒乓半号）、`oob`（四拍）、`v`（`req_vld`，只两拍）、
`kx/ky`（两拍，"与 `fx_d2/fy_d2` 同级"）。复位值也各有讲究：
`r0_d1/r0_d2/c0_d1/c0_d2 <= 1'b1`、`oob_d1..d4 <= 1'b1`（`:99-101`）——
上电头几拍当作"越界"，宁黑不错。

四个相位就是这八个位的组合（`:119-123`）：

```
ph_a0 = v_d2 &&  r0_d2 &&  c0_d2;    // 本拍到达的是 A
ph_a1 = v_d2 &&  r0_d2 && !c0_d2;    // 到达的是 A+1 ⇒ y0 行凑齐
ph_b0 = v_d2 && !r0_d2 &&  c0_d2;    // 到达的是 B
ph_b1 = v_d2 && !r0_d2 && !c0_d2;    // 到达的是 B+1 ⇒ 可以喂 lerp
```

`v_d2` 这一项的意义在 `:28`：消隐期不许写任何 RAM，否则脏一个格子。
`req_vld` 顶层接的是 `de_d[2]`（`src/rtl/top/pl_video_top.v:748`）——
**与 `sx/sy` 同一级**，那一级是量出来的（`:739-743`：tb_v98 自带的级数标定给出
`k = 0 全错｜k = 1 412166｜k = 2 0｜k = 3 410389｜k = 4/5 全错` ⇒ `sx` 站在第 2 级），
第一版接的是 `[3]`（照 `MIX_D` 的那个 3），结果"每源像素的 4 拍"跨到相邻源像素，
屏上四分之一格子错列。

### 3.4 两块 RAM：抽头暂存与结果乒乓

**暂存 `tap_hold`（`:142-154`）**：`reg [31:0] tap_hold [0:IMG_W-1]` = 512×32，1W1R，
`(* ram_style = "block" *)`。写发生在 `ph_a1`（y0 行凑齐那一拍）：
`tap_hold[j_d2] <= {p10_y0c, p00_y0}`；读 `tap_r <= tap_hold[j_d1]`，
"`j_d1` 读出的正是'两拍前那个请求'的 j（= 当拍的 `j_d2`），与 B+1 同拍到位"（`:150-151`）。
写只在 y0 行、读只用在 y0+1 行 ⇒ 同一拍同地址不会读写相撞（`:151`）。

**索引必须是显示列对号 `jd`，不能是源列 `sx`**——`:136-138` 那段 ⚠ 讲得很硬：
旋转时一条源图线在 x 方向会**停滞甚至倒退** ⇒ 同一个 `sx` 在这一行里会被**另一个源行**重写
⇒ y1 拍读到的是别的像素的 A 行抽头。而"这个错与 `bilin_en` 无关（off 时 `p00` 也来自这块 RAM）"。
顶层因此递 `jd = x_d[2][9:1]`（`src/rtl/top/pl_video_top.v:747`，同一处注释 `:745-746`
记的是板上现象："旋转时 sx 沿一行会停滞/倒退，用 sx 当地址会让同一个格子被别的源行重写 ⇒ 满屏噪点"）。

**结果缓冲 `res`（`:184-192`）**：`reg [16:0] res [0:2*IMG_W-1]` = 1024×17，
17 bit = `{oob, lerp_pix}` ⇒ 越界位与像素**同一次写、同一拍读**，天生同级（`:197`）。

```
if (asm_d2) res[{h_d4, j_d4}] <= {oob_d4, lerp_pix};   // :188  写"本对"
res_q <= res[{~h_d1, j_d1}];                           // :191  读"上一对"
```

乒乓的半号是 `pair_odd = y[1]`（顶层 `:744`），写用当拍那半、读用另一半 ⇒
同一个 `j` 永远落在不同半 ⇒ **单口够用**。`:180` 把代价写死：
"这里不许再开第二个逻辑读口：实测 BRAM 从 80 块顶到 160 块 RAMB36，全片才 140"。
`:181` 钉深度：1024×17 正好一块 RAMB36（36 bit 宽模式），
**深度必须是 2 的幂**，非 2 幂会被推断向上填充。

**两块 RAM 都不许带异步复位**：`:145-148`
"写口带异步复位综合不出 BRAM —— Vivado 报 `ERROR: [Synth 8-91] ambiguous clock in event control`
并整个模块作废，xsim 完全看不出来。少掉的是 `tap_r` 这个输出寄存器的复位：它是数据不是控制，
复位后第一拍本来就无意义"。同一件事在 `res` 上重复一遍（`:186`：`res_q` 复位后前两拍是 X
⇒ 判据只能从那之后开始数）。全树再找 `Synth 8-91` 这句话，只有
`src/rtl/process/bilin/fb_bilin.v:146` 与 `src/rtl/process/bilin/fb_bilin.v:186` 两处，
效果链里的行缓存走的是另一条路——它们显式标 `ram_style = "distributed"`
（例如 `src/rtl/process/proc_sharpen.v:20-21` 的 `lb0/lb1`），
所以不参与这场"块 RAM 能不能带异步复位"的事。

### 3.5 读口本体

`fb_bilin` 例化 `frame_buffer_w64` 并且只用 `rd_data64`（`:65-68`，`.rd_data()` 悬空）。
这里有一个必须知道的接口细节：`frame_buffer_w64.v:63-67` 对读地址做了**掩码夹取**
（`lo[ridx & (D_LO-1)]`、`hi[r_off & (D_HI-1)]`）⇒ 越界一侧的地址不会产生 X、也不会越界寻址；
而 `:80-81` 只有 `rd_data` 走 `blank` 夹黑，**`rd_data64` 是原始字** ⇒
用 `rd_data64` 的 `fb_bilin` 得不到那条保护。
所以末行/末列的折回必须由 `fb_bilin` 自己做（§3.2），这不是重复保护，是两个口给的东西不一样。

## 5 另一条路：250 MHz 五槽读口（`fb_rd5x` + `tap_sched`）

这套东西今天**不在顶层**：`src/rtl/process/bilin/fb_rd5x.v:4-5`
"r63 起顶层改用 `fb_bilin`（全程慢域、不进快域），本模块与 `tap_sched` 只剩
`sim/tb_fb_rd5x.v` 在驱动（形状与 LAT 仍由它钉着，别当死代码删）"。
`src/rtl/process/bilin/tap_sched.v:5` 也声明了同一件事。留着的价值是：**它带着那两条被否决的账**。

### 5.1 它的形状

`tap_sched` 把一个像素周期切成 `SLOTS = 5` 个快槽（4 ns × 5 = 20 ns），
右窗 4 个抽头 + 左窗 1 个最近邻恰好占满 ⇒ **不新增任何 BRAM**
（`src/rtl/process/bilin/tap_sched.v:9-11`）。
槽位表在 `:64-74`：s0 发左窗字、s1 发 A、s2 发 A+1、s3 发 B、s4 发 B+1，
下一周期的 s1' 一次拍出 `p00/p10/p01/p11 + ofx/ofy + vld`。
`vld` 由 `acc1/acc2` 跟随"真被采纳过的请求"（`:54-56`、`:128-129`、`:149`），
因为灌水的头两拍里装的是复位值。⚠ 这对 `acc` 是**采纳跟随链**，不是坐标累加器（第 06 章 §1.4c）。

### 5.2 快域一律不做算术——这条纪律是拿门换来的

`src/rtl/process/bilin/tap_sched.v:43-47`：

> 快域里一律不做算术：`clk_pix5x` 周期 4 ns，而慢域触发器的输出最早只能在**下一个快沿**被采走
> ⇒ 跨进快域的那一拍只有 4 ns 预算，不是 20 ns。
> "快域做 `base+ROWW` 加法再进 5:1 mux"实测需要约 5.3 ns（−1.277 ns / 1400 个失败端点）⇒ 整条读口判红。

所以四个抽头字号 + 左窗字号**全部在慢域算好并各自打一拍**，进快域的是直线，快域只做一次 5 选 1。
那句收口的话值得抄下来："这条纪律比'看起来省了几级寄存器'重要：它是有门的，门就是 timing_summary"。
同族另一笔账在 `fb_rd5x.v:6-8`：快域→慢域最坏有 16 ns ⇒ 抽头与左窗字都要在快域先落一次触发器；
而插值的 12 个乘法必须留在慢域（`bilin_lerp` 两级），快域 4 ns 塞不下。

### 5.3 第二个逻辑读口：资源账

`fb_rd5x`/`tap_sched` 的动机本来是"给左窗再开一条独立的读"。实测把它写死在两个地方：
`tap_sched.v:10` 与 `fb_bilin.v:180` 同一条——
**把帧缓存从 80 块 RAMB36 顶到 160 块，全片才 140**，
而 `src/rtl/video/frame_buffer_w64.v:4-7` 记的拆块实验给出的正是那个 80
（不拆块更糟：128 块）。本轮路由后的读数是 Block RAM Tile 95.5 / 140、RAMB36 93
（`build/utilization.rpt:106-108`），也就是现在离满片只剩 47 块——
这一条决定了"要双线性就不能多要一个口"不是风格偏好，是硬约束。

### 5.4 LAT 的两处口径没对上（读代码时别当成一个数）

* `src/rtl/process/bilin/fb_rd5x.v:8` 写的是"LAT=5 由 `tb_fb_rd5x` 用唯一平移量搜索量出来，
  不是纸上推的"，而模块里那条侧带链确实是 5 位
  （`reg [4:0] sel_chain;  // 侧带：LAT 拍移位`，`fb_rd5x.v:56`）。
* `sim/tb_fb_rd5x.v:27` 钉的是 `localparam LAT_PIN = 6;  // 第一次跑出来的值钉在这儿，之后任何漂移都算回归`，
  `:215` 断言 `found == LAT_PIN`，并且要求"全对齐的候选数 `nzero == 1`"（两个平移都对 = 判据没牙）。

⇒ 注释与台架各说一个数，**我没有把它们调和**：要么注释过期（台架后来多算了一级），
要么 `LAT_PIN = 6` 里含了模块注释不计的那一级。判据的红绿以台架钉住的 6 为准，
因为它才是量出来的那一个；而这套模块今天不在顶层，不值得为改一句注释动一次构建。
这一条要留在课程里而不是悄悄抹平：**同一个模块里"延迟"有两个数，就说明没有任何东西在钉注释**。

## 6 为什么这样选

**慢域 4 拍，不快域 5 槽。** 两条路的差别不在吞吐（都是每像素一次结果），在**时序预算的所有权**。
快域方案要维护"跨进快域只有 4 ns"这条纪律，一次加法就算红（§5.2 的 −1.277 ns）；
慢域方案把每个源像素天然的 4 拍拿来用，20 ns 的预算够放地址加法、车道 mux 与 12 个乘法。
代价是行方向晚一对显示行——用一个常数 `BILIN_ROWS = 2` 补掉（第 05 章 §3.5、第 06 章 §2.3）。

**单口 + 乒乓，不开第二读口。** §5.3 的资源账。

**位复制，不左移补零。** §1.2，判据 6 是它的守门人。

**先横后纵，而黄金模型先纵后横。** 结合顺序不同会差 ±1 个输出码；
让台架用**另一种**顺序算期望值，才能把"抄实现式子"这种假绿排除掉
（`sim/tb_bilin_lerp.v:17-19` 的原话是"黄金模型故意用另一种结合顺序（先纵后横）算，
而 RTL 是先横后纵——不是把实现式子抄一遍"）。

**折回而不只是钉小数。** §3.2：钉小数只能让 lerp 恒等，
但那次越界读在仿真里是 X，而 X × 0 = X ⇒ 整行仍然坏。
这条是"修一半"最典型的形状，档案把它写进了源码头而不是只写在提交信息里。

**索引取显示列对号。** §3.4：旋转态源列不单调，这是被板上"满屏噪点"量出来的，
不是先想到的。

**`bilin_en` 做成运行时口子而不是编译参数。** `fb_bilin.v:48`
"板上 on/off 来回切不需要重新构建"；跨域形状走 `gpio_o[19]` 的独立三级同步
（`src/rtl/top/pl_video_top.v:251-262`），复位默认 1 = 与常量那一版逐位相同，
所以"加了口子但观感不变"是可查的。

## 7 怎么验

### 7.1 `sim/tb_bilin_lerp.v` —— 算术核的六条判据

只例化 `bilin_lerp`，时钟 `always #10 clk`（20 ns），每改一次输入等 3 个上升沿再取 `pix`。

| 判据 | 代码位置 | 测什么 / 红于哪一种实现错误 |
|---|---|---|
| 1 恒等端点 | `sim/tb_bilin_lerp.v:87` | `fx = fy = 0` 逐位等于 `p00`（8 组取值）；退化机制的支点 |
| 2 四角同色恒等 | `:121` | 六色 × 步长 15 的 (fx,fy) 全部恒等 ⇒ **"不需要饱和"这条结论的守门人** |
| 3 单调 | `:134` | `fx: 0→255` 时 `pix[15:11]` 不许回退 |
| 4 左右镜像 | `:158` | 交换左右抽头 + `fx → 255−fx`，两次 R 码差 ≤ 1 |
| 5 随机对照 | `:193` | 400 组随机抽头，与**先纵后横**的黄金模型逐通道差 ≤ 1 个输出码 |
| 6 白黑端点 | `:95` | 纯白 `0xFFFF` 在 `fx=91 fy=173` 下仍 `0xFFFF` ⇒ 位复制 |

判据 5 的 PASS 行只在 `errors == 0` 时打印并带最差偏差值（`:193`），这是刻意的：
一条"允许差 1"的判据如果逐条打 PASS，日志里就分不清"差 0"和"差 1"。

### 7.2 `sim/tb_v101_fb_bilin.v` —— 读口本体的十条判据

真光栅激励（`NROW = 24` 行 × `H_TOT = 1344` 拍，`req_vld` 只在 `x ≥ H_FP = 160` 且
`< 160+1024` 时为 1），四段激励里第四段是旋转式映射 `sy = (200 + jd) % 290`。
`fx = ((sx*7)+13) & 0xFF`、`fy = ((sy*11)+5) & 0xFF` 是**故意取非平凡小数**，
好让判据 3/4 的恒等性质不掩盖真错。

| 判据 | 位置 | 测什么 |
|---|---|---|
| L1 preload | `sim/tb_v101_fb_bilin.v:259` | 图真的灌进去了（首末字逐位对） |
| **L3 unique shift** | `:287` | `(行滞后, 列平移)` 搜索，要求**恰有一组**成立且必须是 `(2, 2)`；延迟不靠声明 |
| L4 / L4b | `:338` / `:340` | 逐点等于黄金双线性；`oob_out` 标签与像素同字同拍 |
| L5 | `:342` | `bilin_en = 0` 时逐位等于最近邻 |
| L6 | `:361` | 一个源像素的 4 个槽位上内容相同（`slotbad == 0`） |
| L7 | `:344` | 被检槽位不许有 X——"X 会让上面每一条计数成为假绿" |
| L8 | `:367` | 四段激励各自真被量过（`nckA/B/C/D > 4000`、`nslot > 3000`、`guard_bad == 0`） |
| **L9 / L10** | `:378` / `:380` | **成对判**：L9 要越界读的机会 `bil_oob_opp > 0`（尺子真的走到了末行/末列），L10 要伤害 `bil_oob_harm == 0`（折回真的挡住了）。只判 L10 会绿在"根本没发生"上 |

L9/L10 这一对是本仓"空判据恒绿"那一族的正面解法：机会计数与伤害计数分开、
机会 > 0 是伤害 == 0 的**前提**，两条都不许省。
L10 红的时候打的诊断行也起了名字（`L10 first offender: t=… tap=vertical-B|horizontal+1 sy_then=… ky_d2=…`）。

### 7.3 已经存在的变异对照

`build/sim/mut_control.sh:82-87` 有 **`bilin_ky_fold`** 这一条真 case：

```
sed -i 's/ ky_use = !bilin_en || sy >= IMG_H-1;/ ky_use = !bilin_en;/'   # 拆掉纵向折回那道门
```

判据是 L10，并且文件里把两件事写明白了：
① 这条算**正例**而不是"改判据的 mask"，因为"那个只证明计数器会动，这个证明它管的是 DUT 的那道门"；
② 预期有连带红（参考模型仍按折回算 ⇒ 末行像素比对也会红），
所以判定看"L10 在不在红名单里"，连带项写进凭据而不是删掉。
跑法：`bash build/sim/mut_control.sh tb_v101_fb_bilin L10 bilin_ky_fold`（这条**我没有跑**，
本轮不动构建；`build/sim/mut_control.sh:111` 的 case 表是它的存在证明）。

还该补而目前不在 case 表里的两条（思路）：
把 `fb_bilin.v:153` 的写索引 `j_d2` 换成 `sx` ⇒ tb_v101 的 L4 必须在旋转段红；

### 7.4 顶层那一侧

`sim/tb_v98_top_seam.v` 里与读口调度直接相关的是
**C1i "read-port phase same stage as src"**（`:1410`，要求 `c1_kn == 1` 且真级的 `pbad == 0`
——即"只有一个 k 让相位与内容同级"），加上 C1c/C1g/C1h 三条逐像素对定义的列/行判据，

### 7.5 小数是从哪儿来的

本章不验 `fx/fy` 本身的正确性，那是 `zoom_mapper` 的事：

### 7.6 §5 那套快域读口的两条尺子

它们不在顶层，但没有被删：两份文件头各自写明"只剩台架在钉、别当死代码删"
（`src/rtl/process/bilin/fb_rd5x.v:4-5`、`src/rtl/process/bilin/tap_sched.v:5`）。
最近一次全量记录里这两条都是 PASS（`sim/r29_regression.log:136-138`、`:187-189`；
同一份里 `tb_bilin_lerp` 也 PASS，`:112-120`）——
这条引用给的是"它们确实在回归里跑过"，**不是**本轮重测的读数。
它们的作用是保住那两条被否决的账：

* `sim/tb_tap_sched.v`：4 ns 时钟、5 槽 = 20 ns 像素周期，60 条请求覆盖
  `lane = 0..3` 四种车道、跨行、行首（`sx = 0`）与行尾（`sx = 508/511 ⇒ 要读下一个字`）。
  五条收尾判据：60 条请求出 60 组抽头（`:229`）、期望队列排空（`:230`）、
  **没有多余 `vld`**（`:231`，这一条管的就是 §5.1 那对 `acc1/acc2`）、
  左窗每周期都被判过（`:232`）、左窗字-车道全对（`:233`，
  "分开采会'字对车道错'，板上现象是整列颜色对、左右偏一格，而且不会报错"——
  原话在 `src/rtl/process/bilin/tap_sched.v:106-108`）。
* `sim/tb_fb_rd5x.v`：20 ns + 4 ns 双钟，判据是"平移唯一且等于钉住的 `LAT_PIN`"（`:215`）、
  右窗与实数双线性模型逐通道差 ≤ 1、左窗逐位等于最近邻、
  `bilin_en = 0` 那一档样本 `nnoff > 15` 且输出逐位等于最近邻、
  `right_out/oob_out` 不错拍（`nflag == 0`），另加两条**牙齿条件**
  （`far*2 > ncmp`、`nnear*4 < far`，头 11 行）——
  牙齿的意思是"激励自己必须够刁钻，否则判据是在量一个平凡序列"。
