# 深读这套代码：章节索引

这套文档讲的是**这个仓库自己的代码逻辑与架构**，不是 Verilog 语法、不是通用 FPGA 教程。
每一章的顺序固定为「原理（这件事在物理/协议/算术上要求什么）→ 实现（哪个文件哪一行做了哪件事）→
取舍（为什么不用另一种做法、代价是什么）→ 已量/未量」。
每一条行为断言都带 `文件:行号`，且那些行都是当次实际打开过的；量不到的地方写"未量"，不补数。

## 建议顺序

1. **00 → 01**。00 给地图与量纲纪律，01 解释后面所有读数是从哪条命令的哪个阶段落盘的。
   跳过这两章直接读实现章，会把"报告里那个数"读成一个孤立事实而不是一次测量的输出。
2. **按数据流读一次**：`02`（片源进与屏出，两头）→ `11`（收侧，网线到可提交的帧）→
   `10`（帧缓存与搬运机、仲裁）→ `12`（发侧协议栈）。
   这一段的读法与第 15 章 §2 那条箭头图可以对照，两边指向同一批例化名。
3. **想动时序或想动跨域之前先读 `03` 与 `13`**：`03` 数的是"信号换域"这一层（谁的钟、谁同步），
   `13` 数的是"工具怎么被告诉这些"这一层（约束文件、名册、量过的刀）。两章的表互为对账：
   `03` 里那条"今天没有同步器的跨域"正是 `13` 第 4 节那笔 CDC 债的来源。
4. **按显示通路读一次**：`05 → 06 → 07 → 08 → 09`；色彩与量化那一级在 `04`。
   这四章互相引用：09 明确把行环的内部交回 05，08 明确把旋转/缩放/插值的内部交回 05/06/07。
   倒着读会在"这个提前量是谁的承诺"上打转。
5. **13 与 14 一起读**。13 讲工具看见了什么、这把尺量的是哪一族；14 讲这些人怎么被证明有效、
   以及一条判据要满足什么才算它有牙。两章共用同一套纪律：改前必须红、别域不许变差、空集不算通过。
6. **15 可以第一个读，也可以最后一个读**。当作地图时先读 §1–§5；当作账本时先读 §6–§8——
   §6–§8 的每一条判定都点名 13 章那些件，没读过 13 就只能相信结论而不是复核结论。

- 本目录在**仓库之外**：`Prj/pro/delivery_review_20261005/`。仓库的工作树里只有
  `src/ sim/ build/ board/ data/ skills/ report/`（清单见 `build/deliver_spec_check.mjs:53-68` 的
  `allowDirs`，注释还写明 `docs` 已从"允许"与"必需"两张表里一并摘掉——将来谁再往仓库里加一个
  `docs/`，会被判成"多余"而红，"撤出的决定不许被悄悄撤销"）。
- 因此这套文档**不在 git 跟踪范围、也不进提交包**。同一口径先落在
  `.gitignore:173-175`（学习文档 `docs/course`、`docs/walkthrough` 按用户要求只在本地读、不随包），
  过程记录在 `开发台账` 的 #384 段。
- 仓库自己的文本尺按"git 跟踪的文件"算射程，所以这三份文档不在门禁的分母里；
  但每章的行号仍按 `src/host/line_cite_check.mjs` 的同一形状写，便于随时手工核对。

## 它不替代什么

这套文档**取代不了 `report/` 里的任何一页**。`report/` 是被交付的那一份（随包、被门禁核对、
有固定的编号与口径），本套是本机学习档：读代码时的第二视角，不是凭据。
两边若冲突，以 `report/` 与它点名的件为准——因为那一份才是别人复现时能拿到的东西。
各章末尾都有"已量 / 未量"一节，那里是本套唯一允许写"这个数我没核"的地方；
正文里的每一个数都要求指回一个打开过的文件或一段可跑的命令。

一个提醒：本套写作时有一条硬约束是**后台可能有实现在飞**，所以全套没有跑 Vivado、xsim、构建、
门禁或任何台架。凡是"这一版跑出来是几"这类数，一律从 `build/` 里那一套 r118 产物读，
不重新量；需要重新量的地方在正文里明写为未量。
