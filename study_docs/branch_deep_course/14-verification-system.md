# 14 验证体系：这个项目到底是怎么"证明"一件事的

读完这一章要能回答六个问题：一支台架的"结论"是以什么物理形式落到盘上的；为什么一支判红的台架
绝不能返回退出码 0；"改前必须红"这条规矩在仓库里有哪两个可执行的入口；`build/gates.sh` 那 24 项
各自读的是什么、申报为红的那一条 `C5c` 到底是什么；一份凭据从"跑出来"到"能被引用"要过几道章；
文本尺（行号、时效、数字对账）能看见什么、看不见什么。

本章全部结论来自直接打开这些文件；引用的每一处都是实际读过的行。

## 1 这个仓库里的"证明"分成五层，每层的产物形状不同

| 层 | 回答的问题 | 产物 | 谁读它 |
|---|---|---|---|
| L1 单元台架 | 这一支 RTL 在仿真里有没有按定义行事 | `sim/tb_*.v` 跑出的 console 与判定行 | 改代码的人，一条命令重跑 |
| L2 顶层台架 | 屏上任意一格解出的坐标与"它该来自哪里"是否一减为零 | `build/tb_v98_report.txt` | 门禁第 15 项 + 评审 |
| L3 发布门禁 | 这一版构建产物本身合不合格（24 项） | `build/rNN_gates.txt` | `GATES:` 那一行 + `freeze_evidence.sh` |
| L4 冻结与凭据链 | 这份读数是不是**这一版**跑出来的 | `build/evidence_rNN/MANIFEST.md5` 双章 | 事后复核的人 |
| L5 文本尺 | 念出去的那句话与盘上的事实是否还一致 | 各自的 `--self` 输出 + 门禁第 18/20/21 项 | 写文档的人 |

第 5 层容易被当成"文档卫生"，但它在这一套里的地位和第 1 层同构：它判的是**交付出去的那句话**。
`src/host/doc_currency_check.mjs:16-17` 写得很直白 —— 这类错"不改变任何行为：位流照编、台架照跑、
门禁照绿，坏的是念给评审听的那一句"。所以它被做成了能自己跑、能自己红的尺子，而不是提醒。

一个贯穿全章的口径：**"没数"不是"过了"**。这三件事在形状上必须分开——
判绿、判红、什么都没判。仓库里为这件事记过一整族账（`build/sim/run_one.sh:36-44`、
`build/gates.sh:205-207` 的 `naa`、`build/deliver_spec_check.mjs:9-11` 的三态判定）。

## 2 单元台架：清单、编译口径与一条命令的跑法

`sim/` 下实际有 82 支 `tb_*.v`（`ls sim/tb_*.v | wc -l` = 82，与 `sim/README.md:1` 的标题"82 支 RTL
台架"一致）。清单页不是手写的：`node build/gen_sim_readme.mjs --apply` 从每支台架文件头的
三段注释（功能 / 激励与检查 / 预期结果）生成（见 `台架变异对照`）。
这三段注释本身是竞赛交付判据 C2-3 硬要求的形状（`build/deliver_spec_check.mjs:296`），
所以"台架自己说明白它会打印什么"是被机器盯着的。

单跑一支：

```bash
bash build/sim/run_one.sh tb_writer_abort
```

`run_one.sh` 的编译口径值得注意，因为它是一次事故换来的：`build/sim/run_one.sh:4-6` 说明这份清单
现在走"`src/rtl` 整棵树 + `sim/prim` 占位件 + `sim/tb_*.v`"的通配，而**以前这里是手写的一小串文件**，
结果是改了 `pl_video_top` 想快点看一眼时 `xelab` 直接报 `Cannot find design unit`——
顶层唯一的台架根本不在清单里。今天这三路通配在 `build/sim/run_one.sh:64-66`。

清单必须走 `-f` 文件而不是拼在命令行上（`build/sim/run_one.sh:67-72`）：台架加多之后 `xvlog` 会被
Windows 命令行长度上限截成"参数太多"，而 `xv.log` 里连 `ERROR` 都没有，脚本只看 `^ERROR` 就往下走，
最后报成一句看不懂的 `Cannot find design unit`。同一行还钉了第二件事：文件里必须写
`cygpath -m` 出来的 Windows 正斜杠路径，因为命令行参数会被 MSYS 自动换算而**文件内容不会**。

第二个入口是全量批跑 `build/sim/run_sim.tcl`（`build/sim/run_sim.tcl:6-8`：编译 `src/rtl` 下全部
加 `sim/tb_*.v` 全部，逐支跑并每支补一行 `RESULT`）。这条路的含义写在 `台架变异对照`：
"某个台架忘了接进流水线"这件事不存在；反过来，放一支坏台架在目录里，每次批跑都会被它拖住。

还有一个反直觉但很重要的规矩：同一时刻只能有一个 `xsim` 在写那个目录。
`build/sim/run_one.sh:50-61` 在门口用 `tasklist` 检查，有活的 `xsim.exe` 就**拒绝启动**（退出码 3 那一支），
而且**不自动杀**——正在跑的那一跑可能是别人要的凭据。原因写在同一行上面：第二次 `run_one.sh`
并不会让第一次停下，前一个 `xsimk` 还活着，继续往同一份 `run.log` 里写它那一跑的行，
两跑的行混在一份文件里，报告脚本就会把"上一跑的 C5c"与"这一跑的 C5c"拼成一份——
而它的头部 md5 全对（`build/sim/run_one.sh:52-54`）。**认 md5 也救不了"正文来自两个进程"这件事。**

## 3 六支代表台架：每支实际在判什么

### 3.1 `tb_icmp_rx_len`：把"最后一个字节判在哪一拍"变成可判红的数

被测是 `icmp_rx`（`sim/tb_icmp_rx_len.v:63-78`），时钟 `always #4 clk`（`:50`，8 ns = 125 MHz，
与硬件上的 `gmii_rx_clk` 同频）。这支台架存在的理由写在 `:26-31`：r90 那一轮要把最坏 setup 路径上的
`icmp_rx_cnt == icmp_data_length - 1`（16 位减法 + 比较，实测 9 级）换成"把 len−1 提前寄存"加一根
数据窗旗标——这是"资源换时序"——而这类"看起来等价的改写"动的正是收包链的边界：差一个字节就让应答
少/多一个字节、校验和加错一对。顶层台架不看 ICMP，`build/board_verify.sh` 的 ping 只说"通没通"，
两者都不足以证明"逐字节仍然一样"。

它的主循环是 14 轮换长度（`:211-217`：1,2,3,4,5,6,7,8,15,16,55,56,63,64），每轮发一整包
（前导 7×`55` + `D5`、以太网头 14、IP 头 20、ICMP 头 8、载荷 N 字节），然后判七条（`:226-239`）：
`A` `rec_byte_num === N`、`B` `rec_en` 脉冲数 === N、`C` 第 k 个 `rec_data` 必须 === `pay[k]`、
`D` `reply_checksum === exp_sum(N)`、`E` `rec_pkt_done` 恰好一次、`F` 状态机回 `S_IDLE` 且等待
<60 拍、`G` `icmp_id/icmp_seq` 仍锁得住。

`D` 那条的期望值由一个台架自己写的函数算出来（`:159-167`）：成对 `{pay[2k],pay[2k+1]}` 相加、
奇数尾字节放低半 `{8'h00,pay[N-1]}`、32 位不折叠。**关键设计在这里**：这套语义是按"现有 RTL 的语义"
写死的（`:33-35`），所以第一次跑必须在**未修改的树上全绿**——这就是等价性的锚；改完仍全绿才算改对了。
如果期望值是从"当时的现象"抄来的，那条判据就把 bug 当成了期望（同一课见 3.3 的 `B2`）。

第二族（`:242-284`）经历过一次方向反转。原来 `H3/H4/I/J` 四条钉的是**读出来的楔死行为**
（问题台账 #151：那时只登记、不修）。2026-10-01 板上量到它的真实代价：一条 `ping -l 0` 之后
**所有**后续包都不再应答，直到重配 PL（逐轮曲线 `build/r101_216_deathpoint.txt`）。于是期望值改成
由**定义**推出：声明的数据字节数 = IP 总长 − 28 = 0 ⇒ 这一包没有数据段 ⇒ 必须照样收尾、必须回
`st_idle`、并且不许影响下一个包（`:246-248`）。新判据 `K1/K2/K3/K4`（`:254-267`）与截断包那一半
`L1/L2/L3`（`:274-284`）都源于同一个根因，红话写得很清楚：`K4` 那句
"a 0-byte request must not poison the FOLLOWING 32-byte request (board: all later pings went silent)"。

判定行的形状是 `[tb_icmp_rx_len.v] PASS <标签> | <说明>`（`:81-89` 的 `line` 任务），
收尾 `RESULT tb_icmp_rx_len PASS errors=0`（`:286-287`），看门狗 600 µs 到点打 `FAIL timeout`
（`:291-295`）。判据标签一律 ASCII（`:81` 注释）：xsim 会截 CJK 的 bit7。

### 3.2 `tb_link_monitor`：参考计数器 + 判据自己的反例

这支 635 行的台架例化了**三个** `link_monitor` 和一台 `frame_reasm`、一台 `snap_cross`：
`u_lm` 用 `CLK_HZ(1000)` 一拍当 1 ms 的测试时基（`sim/tb_link_monitor.v:104`）、
`u_lm_prod` 用生产 `CLK_HZ(125_000_000)` 只问 `ms_tick`（`:179`）、
`u_lm_syn` 输入全手摆、专打 `gapclr` 与记账拍相撞（`:224`）。时基为什么要换成 1000：
`:45-46` 算过——否则等 200 ms 断流要跑 2500 万拍。

它最有价值的两个手法值得单独学。

**手法一：参考计数器（`:83-93`）。** 注释直接说出动机："判据要问的不是 `drop_words` 非 0，
而是它数的次数对不对。差别很要命：板上零丢包那句话说的是 `drop_words == 0`，而这个寄存器以前只被
'非 0 就行 / 不动就行'级别的判据看过 ⇒ 任何一次把事件挪一拍、少记一次边沿的改动都能全绿。"
于是台架用与 `link_monitor` 同样的两个式子在 Verilog 侧**独立数一遍**（`:89-93`），收尾逐字比对：
`E1` 比 `P_DROP === ref_drop` 与 `P_CDC_EP === ref_ep[15:0]`（`:374-380`），
`E2` 再用 `flip_en` 把"满只高一拍"的边界事件造出来（`:94-95`、`:100`、`:391-397`）。
同一段还留了一条 `FALSIFIER`（`:359`）：把 CDC 写口挡住一整帧，`drop_words` 必须非 0——
这条不是判功能，是判"这把尺子在这一跑里真的被测到过"。

**手法二：判据自己的反例（`:297-302`）。** `B2` 那条统计寄存器自洽判据被写成
`reg + always @*` 而不是 `wire`，理由写在 `:243`：**`wire` 表达式不随 `force` 重算**，
那种写法测不出"判据根本没看 sum"。于是 `:298` 在仿真期 `force u_lm.gap_sum = u_lm.gap_max + 32'd1`，
要求 `b2_ok` 必须变假；`:301` 那条红话是
`FAIL B2-mut force 过的 gap_sum 仍然让判据说绿 ⇒ b2_ok 没有真的在看 sum`。
**这里不碰 RTL**——因为构建正在读 `src/rtl`（`:297`）。

另一条"永远不会红"的坑也在这支台架上被修掉（`:96-99`）：原来判"最后一张快照在源钟停之后还在"
写的是 `d_bus !== 0`，而目的侧那一路本来就会被 `xdomain` 循环灌成非 0 ⇒ 那条判据**永远不会红**。
现在先把停钟前一刻的读数钉进 `d_bus_hold`，再比"停钟之后有没有变"。

`B`/`B2` 的**分家**是第三个手法（`:288-295`、判据索引见 `:39`）：发布与统计寄存器分开判之后
"B2 红 = 算术坏了；B 红而 B2 绿 = 发布路径/节拍坏了"。合在一起判就只能整体回退，说不出红的是哪一半。

### 3.3 `tb_writer_abort`：尺子的可信度取决于响应器是否照协议办事

被测 `axi_frame_writer_gated`（顶层里那个 `u_row`，`sim/tb_writer_abort.v:54-61`）。
缺陷形状（#170）写在 `:22-28`：`abort` 那一拍把 `active` 清 0，而 `m_axi_rready = active && !sk_full`
⇒ 从下一拍起不再接收任何 R 拍。按 AXI 的规矩 master 必须把 `rvalid` 举到 `rvalid && rready` 为止，
所以已在途的拍不会消失，它们会**等在新帧门口**：下一帧 `start` 之后第一批被接收的拍其实属于上一帧，
而写地址是按"本帧第几个字"推进的 ⇒ 症状是"整帧平移 + 顶部花"；`outstanding` 在 abort 时被清 0、
随后又按这些旧拍的 `rlast` 递减 ⇒ 计数从此与真相不符。

`:30-32` 是这支台架全部意义所在的一句话：**"这支台架的全部意义在响应器照协议办事：`rvalid` 一旦
举起来就 held 住，被接收才推进。如果这里写成 `rready=0` 就把那拍丢掉，症状根本不会出现 ⇒ 尺子在
被测物上做假绿。"** 于是 `B1/B2` 两条（`:159-165`）是响应器自己的对照：abort 的时机必须真的有在途
（`B1`），而且那一拍确实还举着没人收。

`B2` 还记了一次方向错误（`:161-163`）：第一版写成"必须看到 `rvalid=1` 且 `rready=0`"——那是**改之前的
症状**，修好之后反而红，判据写成这样等于把 bug 当成期望。改成讲机制：
`(!inflight) || (rready === 1'b1)`，红话说的是 "in-flight beats must keep being accepted;
blocking them is what makes #170 leak"。**期望值要从语义推，不能从当时的现象抄。**

`:83-91` 记了第二件：`rvalid_r/rlast_r/rdata_r` 现在是**队列状态的组合函数**。第一版把它们也寄存了，
于是 `rlast` 那一拍在 burst 边界被重复呈现一次——症状是 `A4/B6` 报 17 次"乱序"（= 16 个 burst 边界 + 1）
而 `A2` 的字数照样对得上。注释那句是全章的方法论：**"那是台架自己的响应器在骗人，不是 DUT 的问题。
台架先自证清白，才有资格说别人。"**（原文写作第一人称，指的是那支台架的建模代码。）

第三件在 `:113-117`：期望值这次是**逐行从编码算出来的**——数据低 16 位 = `araddr[15:0] + beat`，
而 `araddr = base + burst_idx*(BEATS*8)`，所以第 w 个字落在 burst `k=w/16`、拍 `b=w%16`，
其编码值 = `k*128 + b`。第一版按 `prev+1` 判 ⇒ **干净跑**也被报出 15 次"乱序"，那是尺子自己错。

三段结构：`A` 无 abort 的对照（`:144-152`，必须在当前树上也是绿的）、`B` 在途时 abort 再重启下一帧
（`:154-178`）、`C` 消隐期与 abort 后 60 拍都不许写（`:180-190`，"现在就该绿；留着防修的时候顺手改了
`allow_wr` 的语义"）。每段 `while` 都带 600/3000/8000 拍上界（`:148`、`:158`、`:170`、`:174`）。
判定走 `chk` 任务（`:98-108`，**非 ANSI** 声明风格，理由见 `:94-95`：ANSI 端口写法与 `sformatf`
都不是 Verilog-2001），收尾 `checks=%0d errors=%0d` + `TB RESULT PASS|FAIL`（`:192-194`），
`#8_000_000` 看门狗另打 `TB RESULT FAIL timeout`（`:198-203`）。

### 3.4 `tb_v98_top_seam`：坐标图与"缝"式判据

唯一例化顶层 `pl_video_top` 的台架，1893 行。它的核心构造写在 `sim/tb_v98_top_seam.v:23`：
DDR 帧是**坐标图**——每个像素值就是它自己的坐标，16 bit = `{1'b1 非黑标志, 行 mod 128, 列 mod 256}`
（编码函数 `:141`，解码 `mem_row/mem_col` `:142-143`），于是"屏上任意一点解出的 (row,col) 与它该来自哪里
一减为零"这句话变成了一次整数比较。差值一律用模 256 的有符号差 `dsub`（`:145-151`，
把差折到 −128..127），判据红时先能看出量程够不够。

位 15 当"非黑"标志不是装饰：`:135-137` 解释过——黑格与"画面外的黑"在引脚上长得一模一样，
0.50×/0.75× 各有两行的左沿因此量到"晚两列"，红的是尺子的前提而不是硬件。代价是行标签从 8 位变 7 位，
所以**所有绝对行号期望都要按 mod 128 写**（`:138-139`，299→43 恰好同值、200→72）。
`C0a3`（`:1318-1326`）直接把"全帧 300×512 格没有一格编码成 `16'h0000`"做成判据——
面板级尺子只能用"是不是全黑"判断"在不在画面里"，只要图案里存在一个黑格，那条尺子就永远有假红可找。

**读数全走 `dut.` 层次引用、不读 DVI 引脚**（`:23`），理由是 `sim/prim/unisims_sim.v` 的 `OSERDESE2`
是占位件、不串行化，读它就等于信它。

判定形状与前三支都不同：`line` 任务（`:1287-1292`）只打 `PASS|FAIL <标签> | <说明>` 并累加 `nfail`，
末行 `RESULT tb_v98_top_seam PASS` 或 `RESULT tb_v98_top_seam FAIL nfail=<n>`（`:1889-1890`）。
**"缝"式判据**的意思是：每条判据钉的是屏上某一个**位置关系**（缝的左右两列、每行第 0 格、帧头那一窗），
红话里同时给两路的读数，使"红的是哪一路"可读。以 `C5` 族为例（`:1554-1566`）：

- `C5a judged rows`：`c5_judged > 500`——**覆盖地板**。红话说 "the 0deg x 100% cell must give
  >=500 judged rows, **else C5b/C5c below mean nothing**"。这是一条专门防止"判据在空集上过"的判据。
- `C5b body rows carry their own source row`：本体行的 tag 行 == 屏上行 `>>1`，`c5_bad == 0`。
- `C5c frame head is not the previous frame's tail`：`c5_head_bad == 0 && c5_head_c[0..2] > 5`——
  帧头那 `OFF+BILIN` 行在**缝的两侧各采一列**都要带自己的源行（采样列见 `:942`、`:964-993`，
  分列账打在 `:1559-1561`）。

`:1001-1004` 记了一次"红的是尺子"：行号必须在**行尾**加一，少了这一句 `c5_prow` 永远停在 0 ⇒
每一格都被当成帧头那几行，`C5a` 的 judged 会是 0（覆盖地板正确地红）、`C5c` 把整帧都算成陈旧行——
第一跑就是这么红的。注释写"这是本仓第四次撞到同一族"。

同族还有一次记在 `:1296-1300`：`integer` 标量的初值是 0，而**数组元素的初值是 X** ⇒ 不清零的
`c5_head_c[j5] = c5_head_c[j5] + 1` 永远是 X，而 `X > 5` 既不是真也不是假，于是 `line()` 就在
"算术上坏了"的基础上判红。这是本仓第七次撞"X 的出生地"。

`C0a` 尺子校准（`:1310-1315`）排在任何测量之前：编码/解码/`dsub` 三方必须自洽，含 0、小列号、
帧底帧右两个边界、以及**两个回绕方向**（`dsub(2,254)==4`、`dsub(254,2)==-4`、`dsub(0,255)==1`）。
紧随其后的是 `C0a2`（`:1339-1341`）：`ddr[0] == 64'h8003_8002_8001_8000` 且末字
`== 64'hABFF_ABFE_ABFD_ABFC`。`:1336-1338` 说明为什么验函数不够——`#92` 换了图案编码之后
这两个字面量一直没跟着改，那一轮它红了，**红的是尺子**。

`:1371-1380` 这一段是"降级为只报数"的样本：原来那条拿当拍的 `sx_l` 比当拍标签的判据被**证伪**了
——标签描述的是 17 拍之前那个地址取回的内容，两者描述的不是同一个像素。注释的结论是
"留在这里当判据只会造出一条不可能成立的判据 ⇒ 打数、不判"，能判定标签与内容同列的只剩两条路：
内容级硬判据（`C1a/C1b/C1c`）与板上的眼睛。

最后一件：`:1351-1355` 刻意**不用** `fork/join_any/disable fork`，因为那是 SystemVerilog 构造而这份
台架按 Verilog 编译；等待用"一次等一帧、最多等 16 次"做成天然有界。注释的理由值得抄进方法论：
"挂死的台架比红的台架糟，全量回归是顺序跑的。"

### 3.5 `tb_osd_lines`：整串逐字符 + 判据有牙自检

被测 `osd_overlay` 例化两份（第二份只换 `OUT_W/OUT_H`，用来钉"尺寸那一格来自参数"）。
它判的是**整串**：`expect_line`（`sim/tb_osd_lines.v:154-175`）把该行的 32 格逐格与期望比，
前 n 格必须等于期望串、其余格必须 == `8'h20`（`:324-329` 给出五行金样，
`L0 == "1024X600  FPS:30  SRC:ETH"`、`L2 == {"ROT:45", 8'hDF, "  ZOOM:0.75X(AUTO)"}`）。

为什么不用"某一格在第几列"的常数口径：`:36` 的说明是新排版按**实际位数**打数字
（`Th:80` 不是 `Th:080`），所以列位置不再是常数，而整串比对反而更狠——字段整体挪一格、少打一位、
后缀没跟上，全都会红。

`:41-43` 记了一次"判据在空集上过"的险情：`NL` 必须跟 RTL 的默认 `N_LINES=5`，
因为 `put` 有 `col < N_LINES*MAX_CHARS` 的边界保护 ⇒ 写死 4 会把第五行**整行丢出台架**
（两份 RTL 都编得过、台架全绿）。修法是例化跟默认参数一致，再让 `T1e/T13e/T15` 真去比那一行。

`T11`（`:490-498`）是这支台架最有教育意义的一条：它拿一条**错的**期望
（`"1024X600  FPS:31  SRC:ETH"`，只把 30 改成 31）比一次，要求 `errors` 必须**恰好 +1**；
不到就 `errors = errors + 1` 并记一条错。`:118` 那个 `verbose` 开关就是为它准备的——
"那条自检要故意比错，安静下来才不污染 PASS/FAIL 行"。`:24` 把这条口径写进预期结果段：
`T11/T15t 各拿一条错期望比一次，errors 必须恰好 +1（判据有牙自检，红的撤销计数）`。

其余覆盖面（`:1-34` 的三段头注释是完整清单）：边界饱和（`fps=200` 期望画 99、`ms=5000` 期望画 999，
`:339-342`）、八组控制字 `PIPE` 五位码（`:360-368`）、八档缩放（`:378-385`）、gamma 二十一档
（`:405`）、`force u_osd.ch` 逐格喂码点 + 5×7=35 个像素逐点扫字模（`T9/T10`）、
温度 256 个编码全扫且分类数必须是 `ndig==100 && ndash==156`（`T15`）、
`osd_en` 总开关正反成对（`T16`：`t13_off==0 && t13_on>0 && t13_seen>5000`）、
越界索引的机会计数（`T17 oob_opp>0`、`T18 oob_harm==0`）、样本地板（`T12 ncell>=1500`）。
注意 `T17/T18` 这一对：**机会必须出现过**（`>0`）而**危害必须没发生过**（`==0`）——
这正是 3.2 里 `FALSIFIER` 与 `B` 的同一形状。

### 3.6 判定行的四种形状，与一把统一它们的尺子

把上面五支摊开看，收尾 token 至少有四种形状：

| 形状 | 出自 | 例 |
|---|---|---|
| `RESULT <tb> PASS` | L1 批跑补的行 / `tb_link_monitor` | `sim/tb_link_monitor.v:36-37` |
| `[tb_x.v] RESULT tb_x PASS errors=0` | `tb_icmp_rx_len` | `sim/tb_icmp_rx_len.v:286` |
| `TB RESULT PASS`（行里**没有台架名**） | `tb_v94` 那一族 | `sim/tb_writer_abort.v:193` |
| `RESULT tb_v98_top_seam PASS` / `FAIL nfail=N` | 顶层台架 | `sim/tb_v98_top_seam.v:1889-1890` |

判据行的形状不统一是被允许的（每支台架自己定），但**解析器必须统一**。这就是
`build/sim/run_one.sh` 的 `--verdict` 分支存在的理由（`build/sim/run_one.sh:14`）。
它按三级兜底认（`:17-31`）：先 `RESULT <tb>`；再顶格 `PASS|FAIL <tb>[ ALL]`；
再 `^FAIL <tb> (errors=|timeout)`；最后才允许 `TB RESULT PASS|FAIL` 那一族，
而且**必须限定"这份日志里出现过本台架的名字"**——`:26-27` 说得很重：不加这个限定条件时，
一份别人的过期日志能直接替这支台架答复"通过"，"比原洞更坏"。

第 2、3 级为什么不对称地放宽：`:19-23` 解释——只有 **FAIL** 会带字段
（`FAIL tb_v90_latency errors=3`、超时那一支 `FAIL <tb> timeout`），PASS 一律顶格无后缀；
如果一视同仁地放宽到任意后缀，判据行里 `  PASS tb_x c1` 这种"名字紧跟着别的东西"的形状
会把**一条判据**当成本台架的判定。

## 4 退出码：为什么一支判红的台架绝不能 `exit 0`

`build/sim/run_one.sh` 的退出码分得很开（`:40-44`、`:117`）：

| 码 | 含义 | 出处 |
|---|---|---|
| 0 | 判定为绿 **且** FAIL 行数为 0 | `:43-44` |
| 1 | 编译或例化失败 | `:97`、`:98`、`:100` |
| 2 | 拒绝启动（没给 `VP_VIVADO_BIN`、或读不到指定日志） | `:16`、`:47` |
| 3 | **判红** | `:42`、`:43` |
| 4 | 认不出判定行（NO-VERDICT-LINE） | `:37` |

两件必须注意的事：

**第一，退出码 3 与 4 必须分开。** `:40-41` 的原话："3 与 4 必须分开：红是结论，没数不是结论。"
这正是 #166 那件事的形状。`台架变异对照` 与 `build/run_one_ce.sh:9-11` 把事故讲得很清楚：
r62 那天一支**真红**的台架被 `run_one.sh` 报成 `NO-VERDICT-LINE || FAIL 行数=0`——
两个原因叠在一起：判定形状漏了 `TB RESULT PASS|FAIL` 那一族；FAIL 计数只认顶格的 `^FAIL`，
而十二支台架打的是 `  FAIL <名字>`（两个空格）。于是"红"与"没数"长得一模一样，
**而"没数"比"红"更危险**，因为它把人支去重跑一次 75 分钟的台架，而真正该做的是读那三行 FAIL 的数
（同一句话在门禁里也写着：`build/gates.sh:353-355`）。

修好之后 FAIL 计数容错缩进：`build/sim/run_one.sh:32-34` 用 `grep -acE '^ *FAIL( |$)'`，
注释点名"一支真红的台架会被报成 FAIL 行数=0，#166 的机制就是这"。

**第二，判红与"跑挂了"要念成两件事。** `build/gates.sh:352-355` 特意数了
`RESULT … FAIL` 这一支（`RFIN`），红话按两种情况分别写：
"台架跑完了、是它自己判红的，先读 FAIL 那几行的数" 对 "台架没跑完或中途退出"。

`--verdict` 分支排在两道 `REFUSE` **之后**（`:8-9`）：判定解析是纯文本工作，不该要求现场有 Vivado，
也不该因为别人的 xsim 在跑就不许离线读一份旧日志——#166 的对照实验因此必须能离线跑。
这个顺序设计是"尺子必须能被单独试"的前提。

最后一条实现细节：`:120-123` 必须用**绝对路径**自调 `bash "$ROOT/build/sim/run_one.sh" --verdict`，
因为脚本在 `:62` 已经 `cd` 进 `/tmp/kx/<tb>.run`，此时 `$0`（相对路径）不再能解析——
第一次真跑就是这么栽的（rc=127，而仿真明明跑完了）。

## 5 出处（provenance）：报告与树必须同一次跑

门禁第 15 项判的是"这份顶层台架报告是不是**当前这份顶层**跑出来的"。它的由来写在
`build/tb98_report.sh:8-15`：`tb_v98_top_seam` 一次要跑 40+ 帧（八档缩放扫描）≈ 75 分钟，
塞进"构建完就读"的门禁里没有人会等 ⇒ 于是门禁第 1~14 项从来不含顶层台架，
而 #88 的真实教训正是 **"gates 14/14 与唯一例化顶层的台架红了几天同时成立"**。
把这个缺口叫"跳过"还不够——一份**上一版顶层**跑出来的 PASS 报告会伪装成今天的凭据。

机制是四步：

1. **编译之前**盖三枚指纹（`build/sim/run_one.sh:91-95`）：`top_md5`（`pl_video_top.v`）、
   `tb_md5`（本台架）、`rtl_md5`（整个 `src/rtl` 的合指纹），写进 `prov.tmp`。
2. 只有 `xvlog`/`xelab` 两步都过了，才 `mv prov.tmp prov.txt` 并**删掉旧 `run.log`**
   （`build/sim/run_one.sh:101`，理由见 `:85-90`）。否则一次编译失败会留下"新树指纹 + 旧正文"，
   报告脚本会把这对指纹原样盖到旧正文上，第 15 项就此作废。
   编译失败时盘上留下的还是**成对旧**的 `prov.txt + run.log`，自洽，冒充不了当前树。
3. `build/tb98_report.sh:24-29` 从 `prov.txt` 读出处，而不是从现在树里现算——
   "事后算一遍再把指纹盖在旧日志上，正是这一项要防的那件事"。
4. `build/gates.sh:347-360` 的 `mcheck` 逐枚对账，只认 `fresh`/`bridge` 两种答案，
   空串/`ERR`/`no` 一律红（`:356-358`）——"尺子没答"不等于"答了且过了"。

三枚而不是两枚（`:77-79`）：只有 `top_md5` 是不够的。r72 那一轮改的是四个窗口级
（`proc_box_blur/sharpen/sobel/morph`），`pl_video_top.v` 一个字节没动 ⇒ 顶层 md5 仍然"对得上"，
而 r71 那份旧报告可以原样冒充"当前这一版台架"。这条后来被做成反例 `E`
（`build/tb98_gate_ce.sh:34-37`）与反例 `F`（旧头部没有 `rtl_md5` 字段也必须红，
"字段缺 = 不判"不允许）。

指纹定义只有一处（`build/rtl_fingerprint.sh`）：`build/sim/run_one.sh:80-83` 记录 #202 那次——
原来这里按磁盘字节算，一次 `git checkout` 改换行编码就把指纹漂了而设计一字未动，
于是门禁第 15 项把自己刚还原的树念成"报告不算当前树"。现在指纹是**去 CR 的内容指纹**（`norm1`），
而 `build/gates.sh:342-345` 让这把尺子自己的对照（换行不变性、改内容必须动、扫描面、桥接表逐行复算）
成为第 15 项成立的前提。

`build/gates.sh:364-370` 还补了一条**计数地板**：三枚指纹都必须被判定过（`NJ = wc -w of MATCH_LOG`，
不等于 3 就红）。起因很具体：当天自己写的 `mcheck` 少传一个参数，`set -u` 只让命令替换那个**子 shell**
退出（`:349-352` 讲了这个坑），RTL 那一枚就这么"没查"而本项照报 PASS。
是反例 E/F 把它揪出来的，地板让它下次不必等反例。

## 6 变异对照："改前必须红"——一条不能红的判据什么也没证明

这一条在仓库里有两个入口，都不许动工作树（`台架变异对照`）。

**入口一：`build/sim/mut_control.sh <tb名> <判据名>`**（`build/sim/mut_control.sh:1-16`）。
它把整棵 `src/rtl` 拷到 `/tmp` 下，用固定的几条 `sed` 还原改前的写法，**diff 必须恰好是那几行**
否则直接退出；然后只编译"变异体 + 目标台架"，断言指定的那条判据变红。
仍然 PASS ⇒ `MUTATION FAILED`（判据没有力）。
存在的理由写在 `:9-13`：C10f（行缓存写地址越界）修好之后是绿的，而"绿"有两种可能——
根因真的没了，或者这条判据压根没被执行过。#103 第一版就栽在后一种：消隐期喂 `x=0`，
越界那一拍永远不会出现 ⇒ 判据恒绿却什么都没管。
为什么不直接改 `src/rtl`：门禁在跑、构建在跑时改源 = 静默重新综合（历史上烧掉过一整轮），
而"改回来"这一步全靠人记住。`:39-40` 又补了一条纪律：每条 mutation 都要单独写 case 分支并给出
"改动行数"上界，别再往 pipeline 那条 `sed` 里塞别的模块的旧写法——那会让一次控制跑同时测两件事。

**入口二：判据自己的反例**（`--self` 或 `*_gate_ce.sh`）。要求是
"每条故意坏掉的输入**只**红在它对应那一格"，并且**必须有一条正对照是绿的**——
不然一个"永远红"的判据会被误当成有牙（`台架变异对照`）。

这两条要求合起来把"有牙"定义成了一件可测的事。看三个实例：

- `build/run_one_ce.sh:12-20` 列了八条（全离线、不起 xsim、几秒跑完）：
  1 绿日志→rc 0；2 顶格 FAIL→rc 3；3 缩进 FAIL + `TB RESULT FAIL`（#166 原形状）→rc 3
  （**旧实现这里是 4 + 0**）；4 一条判定都没有→rc 4 且念 NO-VERDICT；
  5 别人日志里有一行 `TB RESULT PASS` 但不含本台架名字→必须 rc 4（兜底不许替陌生人答复）；
  6 收尾行带字段（`FAIL tb_demo errors=1`）→必须 rc 3；
  7 名字相近的别人的红不许替 `tb_demo` 答复→必须 rc 4（6 的反配对）；
  8 顶格的 `PASS tb_demo c1`（一条判据的形状）不许冒充判定→必须 rc 4。
  第 7、8 条是**反买通**：加了兜底之后必须证明兜底没有变成"谁都能冒充"。
- `build/tb98_gate_ce.sh:12-14` 造六份报告：一份该绿（P，合成的，只证明"合格形状会被判绿"），
  五份该红（A 顶层指纹不符 / B 没跑完 / C 有红项 / D 文件不存在 / E 顶层没改只改子模块 /
  F 旧头部没有 `rtl_md5`）。`:15-17` 明写"真凭据由 `bash build/tb98_report.sh` 从真实 run.log 生成，
  两件事不互相冒充"。
- `src/host/ps_hb_check.mjs:196-219` 的顺序是**先钉"当前树全绿"，再逐条钉"每条变异各自红在它那一判上"**；
  `:207` 还有一条常被漏掉的对照——"变异**没有改动任何字节** ⇒ 它钉不住任何东西（判据写法过期了）"。
  这条存在的原因是：判据写的正则一旦与代码形状脱钩，变异就变成空操作，
  于是那条判据看起来有反例其实恒真。

`build/make_submission.sh:263` 那句"留着随包就会撞上'未声明的红'这条门（白名单只允许 C5c）"
说的是同一件事的另一面：**红必须可归因**。

## 7 门禁 `build/gates.sh`：24 项、申报红的 `C5c`、五份 `ALL PASS` 凭据

## 8 冻结与证据链：一份读数要过几道章

`build/freeze_evidence.sh <NN>` 把第 NN 次构建的成套凭据收进 `build/evidence_rNN/`
并生成 `MANIFEST.md5`。为什么要有 MANIFEST：`:8-9` 说"现场只认 md5 不认文件名
（`build/evidence_r*` 里同名的位流有好几份），而板上跑的到底是哪一版是眼睛判据能不能算数的前提"。

两道硬门（`:11-15`、`:31-47`）：

1. `build/rNN_gates.txt` 里必须是 `GATES: ALL PASS`（`:31-35`，否则 `REFUSE … 不冻结`，
   并把 FAIL 行原样打出来）。红 = 没做完，把红的东西冻结下来等于给下一轮留一个"看起来有凭据"的坑。
2. `build/tb_v98_report.txt` 的 **两枚**指纹（`top_md5` 与 `rtl_md5`）都必须还等于当前树
   （`:41-47`）。只比顶层不够——`:13-15` 又提了 r72 那一件事。
   经 `build/fingerprint_bridge.txt` 对账上的算 `bridge`，打 NOTE 放行（`:48-49`）。

拷贝名单的设计（`:57-76`）是 #192 的产物：原来"拷哪些件"与"给哪些件算 md5"是**两份分开维护的名单**，
结果是拷进冻结目录 19+6 份而 MANIFEST 只盖章 11 份——没盖章那十四份被改动、甚至本来就没拷成，
都看不出来（每个 `cp` 后面还挂着 `2>/dev/null`，连一句抱怨都没有）。
修法不是把第二份名单补齐（补这一次，下一次加件照样漏），而是
**盖章对象 = 目录里实际存在的文件**（`:107`，`find … | xargs md5sum`）。
配套的是 `:112-117` 那条断言：`NLANDED != NSEALED` ⇒ `REFUSE … 盖章这一环没覆盖全部件`。
三件成品（`system.bit`/`system.xsa`/`ps_app.elf`）缺任一件就拒冻（`:72-76`），
其余缺项**记账不拦**——理由写在同一段：历史上有几轮的 `cdc.rpt`/benches 清单本来就没生成，
把它们变成硬门会把冻结变成"只能冻结今天"。

`:92-101` 处理了另一个形状：源 run 日志不在时，`grep` 会**写出一个空文件**（重定向先把名字建出来），
而 MANIFEST 照旧点名"逐列读数见 `rNN_c2_shape.txt`"——指路指到一个空壳，就是"没有凭证的凭证"。
现在抽不出来就删掉那个空文件，并让 MANIFEST 里那句话改成"这一版没有逐列读数"。
`:84-88` 还补了一条 `.gitignore` 的教训：那份逐列原始读数过去叫 `.log`，而仓里有 `*.log` 规则 ⇒
它从来没进过 git，冻结件里全靠它、仓库里却没有它。冻结产物一律 `.txt`。

**两枚章。** `:108-111` 记 #148：字节章管"当时盘上就是这些字节"，内容章（先 `tr -d '\r'` 再 md5）
管"内容有没有变"。一次 checkout 把 `.txt` 翻成 CRLF 只会让前者红、后者仍绿。
`build/verify_evidence.sh <NN>` 于是同时认两枚章（`:13-19`），并把"换行翻了"和"凭据被改了"分开说。
它的 `--self` 有六条对照（`:56-94`），每条都是"该红的红、该绿的绿"：
S1 原样两枚都该过；S2 换成 LF ⇒ v1 必须红、v2 必须绿（这就是 #148 那把尺子有牙）；
S3 改一个字节 ⇒ v2 也必须红；S4 章里点名、盘上没有 ⇒ 必须红；
S5 **空章**（只有一行说明、没有一枚章）必须拒绝、不许空过（`check_one` 返回 2，`:36`）；
S6 覆盖度：目录多一件没盖章的件，那行数必须从 0 变成 1，补进章里就回 0（"这把尺子能动"）。

`:41-54` 把覆盖度定成 **advisory**：只看"不符 0 件"会空过——r75 的字节章只点名 11 件而目录里有 20 件
（#192 之前那个形状），那 9 件被改动也看不出来。新冻结件由 `freeze_evidence.sh` 的
`NLANDED != NSEALED` 兜住，这里只负责**把两个数一起念出来**；历史件非 0 是已知形状，不是红。
最后 `:107-109` 的判定也是三分：至少一枚章逐份对上 ⇒ `VERIFY PASS`；
两枚都不对 ⇒ `VERIFY RED`，且红话先问"是不是 checkout 翻了换行，再问内容是否真的变了"；
没有可认的章 ⇒ `exit 2`（无从判断，不是红也不是绿）。

## 9 四把文本尺：各自能看见什么

文本尺的共性：它们都判**"念出去的那句话"与盘上的事实是否一致**，都不碰硬件，
所以每一把都必须自带能红的对照，否则恒绿。

### 9.1 `build/deliver_spec_check.mjs`——竞赛交付要求的机器判据

`:1-11` 给出三条口径：范围是 **git 跟踪的仓库树**（提交物 = 仓库本身，不是导出目录），
而"手写清单会静默变窄，所以由 `git ls-files` 现算"（`:20-30`）；
**判定词永远放在行尾**；`cmp=N` 记的是**做了多少次比较**，不是通过了多少；
读不到/没扫到一律 `NOT_MEASURED`，不许当"没毛病"。

这一条"cmp 不是通过数"的口径在整套里反复出现，是防"空集上判绿"的通用手法。
`:32-35`：`git ls-files` 读到 0 个文件时直接 `NOT_MEASURED` 并 `红=1 FAIL`、`exit 1`。

判据的**豁免也必须被核对**。`:36-48` 的 C0-3（文件名纯英文小写）豁免名单只有四个文件名
（`README.md`/`README_EN.md`/`LICENSE`/`SKILL.md`），且**只按整文件名**豁免；
命中数必须打印，名单不许超过这 4 条——"防止把整类文件放过去"。
C0-4（顶层结构固定，`:53-68`）在 2026-10-05 把 `docs` 从"允许"与"必需"两张表里都摘掉：
将来谁再往仓库里加一个 `docs/`，会被本项判成"多余"而红——"撤出的决定不许被悄悄撤销"。
这条正是本章这套文档不进 git 的机器根据（见 README）。

### 9.2 `src/host/doc_currency_check.mjs`——文档不许把旧构建念成当前

三条判据（`:20-28`，口径故意收得很窄——宽一寸就会把"历史上第 4 版得到 WNS +0.708"这种正当的
过去式念成红）：

- **D1**：一行话既说"当前/默认"又点名一个带编号的构建（`build#NN`/`frozen_rNN`）⇒ 红。
  编号的构建目录是历史凭据，只能以过去式出现。
- **D2**：文档里点名的 `build/frozen_*` / `build/evidence_*` 目录必须真的在盘上。
  冻结件被移动或改名之后，文档里的"复核一条命令"就变成一条跑不通的命令。
- **D3**：首页里"门禁全绿 = rNN"那一句必须等于 `newestGreenSet()` 算出来的那一套，
  **并且 README.md 里至少要有这么一句**（没有就等于没说）。

**射程被写进判据本身。** D1 只作用在 `SCOPE_DOCS` 那一份名单上（`:41-48`），
理由写在 `:39-41`：`夜轮记录`、`changelog_v7.md`、`issues.md`、
`version_lineage.md` 是**日记**，里面的"当前默认 #23"写的是**当时的**当前。
"拿今天的盘去判昨天的日记，红的不是文档过期，而是逼着自己回头改日记（那是销毁过程凭据，比过期更糟）。
要改的永远是现在还会被念出来的那几页。"
另有两类豁免：导出器 `build/make_submission.sh` 与两个改名工具
（`:54-58`）——"它们的整个职责就是旧名与新名之间的映射，拿'旧目录不许出现'去判它，
等于判翻译器不许提目标语言"；`:55-57` 记了第一次撞上的形状："判据没有错，被豁免的对象名单少了一类：
凡以改名字为职责的脚本，都在 MAPPER 这一族里"。

`:29-33` 列出三个入口：`--self`（三条各造一条坏输入 + 一条正当的过去式不许误报）、
`--probe`（只报数不判红，先看口径会不会咬到正当的历史句）、
`--list-adv`（把只报数那一半逐条打出来，#121："口径必须可复现，纯打印不参与退出码"）。

它实际能看见的：文档里点名的构建编号与目录、路径存在性。
看不见的：数字对不对（那是 9.4）、行号对不对（那是 9.3）。

### 9.3 `src/host/line_cite_check.mjs`——行号锚点

`D5`。为什么要有它（`:6-10`，ISSUES #122）：README/report/skill 里有 200+ 处
`pl_video_top.v:834` 这种引用，而 D4 只管**路径存在性**，**行号漂了什么都不会红**：
位流编得出来、台架全过、门禁全绿，文档却指着另一个地方。当晚给 16 个模块头补定位那一批
就实地把若干引用平移了 1~4 行（同一批里还有早就漂了一直没人核对的老错）。

**判据为什么不是"行号对不对"**：`:11-15` 说得很诚实——不存在第二份真值能给出"对的行号"。
能判的是**这句话里必然出现的标识符**（`SPLIT_SPEED`、`osd_en`、`u_pipe`…）有没有落在被引的那几行里。
锚点取不出来 ⇒ **单独列成"需人看"清单**，绝不静默通过（"空判据恒绿"那一族）。

容忍度是**判据的力度**，不是风格（`:94-98`）：区间引用（`:16-18`）0 行容忍——
因为 #122 那个真实事故的错位恰好只有 3 行（16-18 ↔ 19-21），给 ±3 就等于判不住它要判的那件事；
单点引用（`:834`）给 ±2——指"某一处"时那一两行注释上下文是正常写法。

三类硬错决定退出码（`:26-28`、`:465`）：引的文件不在树里、行号越过文件末尾、
D5b「例化者」列指错、D5d 逐字抄的固件回声与所引那几行对不上。
"锚点不在那几行里"是 **soft**，只作为排好序的候选清单输出，不决定退出码，
也不进门禁——`:176-181` 记了第一版实测：把 soft 当红报出 341 条，逐条抽读后大部分是
"文档指向那一处所在的函数开头而不是语句本身"，不是 341 个文档 bug。
`:180` 抄了 #122 自己写的警告：**"把本来就已经错的引用改成另一个错的数字，比不动更坏。"**

范围只管**代码/脚本**行号（`.v .c .h .mjs .sh .tcl .ps1`，`:34`）；`.md` 之间的行号引用故意不收
（`:31-38`）：那是追加式档案，把过去的记录改成迎合检查器等于销毁证据，
而且散文里取不出"必然出现的标识符"，判据会退化成猜。
`开发流水账`、`report/study/` 整目录跳过（`:36-38`、`:47-53`）。

锚点还得"文件认识"：`:207-211` 把锚点过滤成 `wordsByFile` 里的符号——
文件里根本不出现的词没有资格判红，只能说明这句话没给代码线索。
短词也不行（`:212-218`）：交付文档里大量引用指的是**命令名**（`show`/`auto`/`zoom`/`fill`），
它们在 `main.c` 里是字符串字面量、离被引那一行十万八千里，却"文件认识"——
第一版实测 330 条红里绝大多数是这一类。

`:301-305` 是豁免名单的反买通：豁免名单里的名字如果能在第一方树里解析到，
就是有人在拿豁免通道盖真引用 ⇒ **硬错**。它必须进硬错集合（`:457`），
否则"名单被污染"只会打印一行而退出码还是 0。

`--self` 的 15 条对照（含厂商豁免 2 条）是门禁第 21 项成立的前提，
而地板是"命中 ≥ 300"（`build/gates.sh:520`；r118 实测命中 360）。

### 9.4 `src/host/metric_recheck.mjs`——首页与指标表的数字对账

`D6`。它把 `data/metrics.csv` 里每个数对回**它自己点名的那份报告**（`:1`）。
为什么有它（`:5-11`，不是"再多一把尺子"，是同一族错误第三次发生）：
#145 表里写"128 条逐像素判定"而留档报告数出来是 138；#138/#145 凭据换过一轮表里的数还是上一轮的；
以及"50 MHz 显示域 +1.177 ns（12 %）"——**1.177 是对的，12 % 是把它按 10 ns 周期除了**
（报告里 `clkout0_1` 的 Requirement 明写 20.000 ns），真正是 5.9 %。
三次的共同点：数是从报告里抄出来的，抄完报告又变了 / 除错了分母。
`:11` 的结论是这套文本尺的设计要点：**"人去复核一个百分数不会发现除错周期，脚本会——
因为它把分母也一起从同一份报告读。"**

射程边界写在 `:14-16`：只判**点名了 timing_summary / utilization / power 这三份报告**的行；
认不出的行**算作未判并打印条数**，不静默放过，也不冒充判据——
"一条判据不许靠'没人反对'变绿"。

`:39-45` 记了 #321：r116 起首页那几行 slack 可能是**负**的（第一次给 RGMII 输入绑窗之后
`eth_rxc` 的 setup/hold 两格就是负的），而旧写法只认 `[0-9]+\.[0-9]+` ⇒ 负数一律读成 `null`，
`null` 在这把尺子里是"判红"——**于是文档写对了也红，写错了也是同样红**，
符号这一维根本没有射程。中文文档用的是 U+2212（−），英文文档可能用 ASCII hyphen，
两者都要吃进去再交给 `Number()`，否则 `Number('−0.846')` 是 NaN，会比读不到更难查。

`:364-371` 是两层地板：点名这三份报告的 csv 行必须**全部**有规则认领（`csvNamed != csvClaimed` ⇒ 红），
且这一层至少判到 8 行（`csvClaimed < 8` ⇒ 红）。理由："没有这条地板，删掉一个规则或改了一个指标名
都会让射程缩掉而没人喊。"

`:373-436` 的 `--self` 形状是这一节所有例子里最完整的：它造**假首页 + 假报告**成对测——
"正常 0 不符、改错一个能红、读不到周期能红（分母没有就不许判绿）、英文分号行正常 0 不符、
英文行改错能红"，还有"四个数都对、只把'最差那一格'指错域"这一格（`:422-429`，
那正是首页一条 stale 行的形状：它指 `eth_rxc`，而 r104 最小 WHS 在 `clk_fpga_0`）。
`:374-378` 说明为什么不能拿"恰好 1 条红"当自检期望：全树其余行本来就跟着新一轮报告走，
构建一变它们就集体变红（**那是正确的红**）。

## 10 板侧验证：机器能判的那一半

`build/board_verify.sh` 的定位写在 `:17-19`：**为什么要有这个脚本——这些判据以前是半夜手敲一串命令跑的，
别人复现不了（比赛要审"他人能否复现"）。现在把顺序、判据、以及每一项看哪一行输出固定在一个文件里，
跑完把日志留在 `build/evidence/`。**

它**不刷板子**（`:21-25`）：三件套的下载顺序会动硬件，故意留给人一条一条确认。
脚本开头只把三件 md5 打出来（`:143-147`），便于和 `build/frozen_*/MANIFEST.md` 对账。

五个可组合的开关（`:8-16`）：默认只跑不需要推流的那几项；`--stream` 加仲裁交接九条；
`--battery` 加串口命令电池 97 条（V8 的 71 + V9 的 20 + #77 的 6，会改板上控制字并复原）；
`--geom` 加 V9 几何自动化的"最后一跳"；`--round=rNN` **必给**（见下面第 3 条判据）；
`--self` 只跑判据自己的五条对照，不碰串口、不需要板子。

**退出码这件事本身是一次事故。** `:119-121` 记：这一版之前脚本**没有总判定**——不管中间红成什么样，
最后都是 `exit 0`，而且各步都挂在管道尾巴上，退出码是 `tail` 的。
2026-09-25 r59a 那次日志里明写着 `[ARB] 结论：1 条不通过 ⇒ 判红`，
而调用方看到的 `VERIFY_EXIT` 仍是 0。现在改成 `NRED` 计数（`:123`）+
`RESULT board_verify PASS（判红的步骤：0）` / `FAIL nred=N ⇒ 这一版不能采纳`（`:267-269`）。
`:224-228` 把同一个坑在仲裁那一步又讲了一遍：`node … | tee x | tail -22 | tee -a $LOG` 之后
`$?` 是最后一个 `tail` 的，arb 自己 `process.exit(1)` 的那条红在这里被吞掉——
**"这就是假绿，比假红危险"**。改法是先落盘再回放，用 `ARB_RC=$?` 拿到 node 的码
（`:228-233`），而且**两重保险**：命令自己的退出码 + stdout 里那一行"九条全过"必须出现。
电池与几何那两步同样是两重保险（`:245-251`、`:257-263`，分别认
`RESULT PASS geom_check` 与 `RESULT PASS uart_cmd_check`）。

**原始串口回显那一条（1b 段）把"凭据是谁产的"这件事讲透了。** 起因（`:37-42`）：
`[TEMP] degC=… raw=… vccint=… osd=…C` 这类只有固件周期性打出来的读数，
此前是从本机那份**不在提交包里、也不进 git** 的捕获里**手抄**进 `build/evidence/` 的。
于是"板上这一刻的温度"这条交付数字的凭据是一份**抄件**，工具自己不产它——
别人复现时拿不到同一件东西。三条判据（`:43-46`）：
① 抓到的内容必须非空——COM6 被别的终端占住时 `powershell` 照样返回 0，空捕获以前会算绿；
② `[TEMP] degC=<数字>` 的行数 ≥ `TEMP_FLOOR`（默认 2，`:46`）；
③ 落到盘上那份必须能用 UTF-8 解（固件中文回显是 GBK；GBK 原样进 git，
下一轮 `doc_enc` 就红在编码上，而那一红长得像"文档坏了"，不像"捕获没转码"）。
`--self` 就是这五种捕获：空捕获必须红、两行 `[TEMP]` 必须绿、低于地板必须红、
GBK 转码后必须绿、**没转码的那份必须红**（后两条是一对——
少了第二条就没有"转码这件事真在被判"的证据，`:19-21`、`:86-105`）。

`:76-82` 顺手记了一条 shell 层的假绿形状：不能写 `$(grep -ac … || echo 0)`——
`grep` 数出来是 0 时也照样打印 0 并且退出码 1，于是式子给出 `"0\n0"` 两个字符，
`[ 0\n0 -lt 1 ]` 报"integer expression expected"，而那**正是**空捕获该有的判红——
它变成了一条 shell 错误，然后往下走成绿。注释说这类"尺子自己报错却继续判"在本仓记过三次。

`#179` 那条也落在这里（`:15`、`:188-193`）：**没有轮号就判红而不写文件**——
脚本自带默认轮号会把今天的数写成一份名字叫旧轮的假凭据。
`:195-198` 紧接着说这份文件里**不加表头、不加时间戳、不加 md5**：
"它的身份就是板子这一刻打出来的原话。一旦加了表头，'空捕获'就会变成'有两行表头的文件'，
而非空这条判据当场失去牙。"出身信息留在 `$LOG` 里，那里有 md5 与时间。

第 2 步（`:204-217`）是读回口：`node src/host/health_read.mjs --json`。
拿不到 json 时不只判红，还说明**为什么后面都不能算数**：
"读回口拿不到 json ⇒ 后面所有'读回来对不对'的判据都不成立，这一版不能算验过"（`:216`）。

第 5 步 `--geom` 为什么要与电池**分开取证**（`:240-244`）：电池判的是**回显**（固件说了什么），
这一条判的是 lane23 里像素域自己吐出来的 `inv/zoom_code/fit` 位，以及 CFG_DATA0 的 19 个几何位。
"回显绿而硬件没动，正是本项目反复踩过的那一类（#52/#66/#68），必须分开取证。"
这句是整套板侧验证的设计核心：**固件的回显不是硬件的状态，两者必须是两条独立判据。**

`src/host/ps_hb_check.mjs` 是同一个想法用在"约定"上。它的定位（`:1-12`）：#94 那条
"AUTO 下拔掉 SD 卡 ⇒ 屏幕永久冻在最后一帧"修在两处，PL 那半有台架（`sim/tb_v102_src_life.v`），
PS 那半（`ps_hold` + 100 ms 心跳）以前只有"读代码看起来对"——
而**没有机器判据的东西在下一次改动时就是裸奔**。于是它从**源码原文**抠出那几处必须同时成立的事实逐条钉：
A1 超时值交给 `src_life`、A2 心跳/超时余量（`hb*3 <= to`，`:88`，
注释说"1 拍是掷硬币，2 拍没有余量"）、A3 publish 里置 hold 且重设时基、
A5 收心跳的调用点、A12 主循环里敲自动重挂、A13 重挂前清驱动 `IsReady`、
A14 自动重挂有闸门、A15 挂上就接回放、A16 读失败清挂载旗、A11 残包只丢尾巴且明说。
`:18-20` 明确它**不编译、不上板**："它钉的是三处源码之间的约定还成立
（节拍/超时/调用点/恢复键），行为级的凭据在 tb_v102（PL）与 `board/README.md` 的眼睛那一行（整机）。"

`:59-61` 记了反例设计里最难的一条：A16 的反例**只**把收口里"清挂载旗"那一行挖掉。
第一版反例把 `card_gone()` 换回 `ps_source_lost()`，结果同时动了 A5 的结构前提，实测红 `[A5, A16]`——
"那种一次红两条的反例不能钉住是哪一条判据在守"。这一条与 6 节里 `mut_control.sh`
"每条 mutation 单独写 case 分支"、`ps_hb_check` 的"变异必须各自红在它那一判上"是同一个纪律。

**只能由人眼判的。** `board/README.md:114-116` 第 4 节原文给了三条：
分割线两侧是同一条帧的两种处理状态、几何关系一致；缩放或旋转时不出现整行错位；
OSD 各格读数与串口读回一致。它前面那半句是这一整套的边界声明：
"机器判不了屏幕，所以这三条不预先写成通过。"
逐格签收状态与"谁点的头、什么时候、原话"记在 `board/acceptance.md` 与 `board/signoff.md`。
`build/freeze_evidence.sh:137-139` 在 MANIFEST 尾部把这份欠账**写进冻结件**：
"还欠眼睛/手的（这一版由用户签）：第 30 项 #92 边缘那条带；第 31 项 #94 拔卡/暂停不丢画/sd remount
（要一只手）；第 29 项 bilin A/B 的观感；#93 旋转大角度两条"。
r118 那一格的眼睛签也留了原话（`build/runs/decisions.md:44`：E6 由队员眼睛签，原话「0度」）。

有一条眼睛判据甚至反过来修正了机器判据的读法：`问题清单` 第 1 节记的
"碎影随 `rot speed` 变宽变乱"这个定量预测被眼睛**判掉了一半**——板上扫了 1→2→4→6→7→6→4→2→1→0
（每档约 7 秒）答"没有，跟速度看不出差"。文档接着解释这不构成对机理的否定：
角点在中心外半径约 297 源像素处，1°/帧 已经是 ≈5 个源像素（≈10 个显示像素）的位移，
早已超过可见阈，7°/帧 只让它"更散"不会"从零到有"——
**眼睛在"宽窄"这一档已经饱和；它真正分辨得开的是"有没有每帧换角"（0 与 ≥1 两档）**。
这段是全章最好的一例：眼睛判的不是"对不对"，而是"哪一档的差别人看得见"，
而这个结论又回头规定了机器判据该钉哪一档。

## 11 这套体系的边界

写清楚它证明不了什么，和写清楚它证明了什么同样重要。

1. **结构判据台架判不了。** `src/rtl/eth/eth_udp_video_top.v:378-380` 明写：
   #209 那条 `link_active` 寄存一拍（把 `|s_pkts` 的组合或缩变成触发器→触发器）的
   "判据是**结构**判据，台架判不了这一条：RTL 仿真没有门延迟，`|s_pkts` 在仿真里永不出毛刺"。
   它的凭据只能是 `build/r98_cdc_details.txt` 里那条 CDC-10 行在改后必须消失——
   一份工具报告，不是一支台架。
2. **75 分钟一次的顶层台架只能被"钉 md5"接进门禁。** `台架变异对照`：
   门禁里另两项是**钉 md5** 的（`tb_v98_top_seam` 与 `tb_edge_rim`），
   改了任何 RTL 这两份报告必须重出，否则判"报告来自另一份代码"。
   这解决的是"过期报告冒充"，不解决"这一版没跑过"——没有重跑就是没有结论。
3. **功耗那一项仍要人比。** `build/gates.sh:593` 结尾原话：
   "功耗仍要人比有没有变差"；第 8 项的判据文本就是"与前次同量级"（`build/gates.sh:204`），
   没有阈值。
4. **CDC 条数变少不算改进。** `build/gates.sh:112-113`：少了的原因没查清之前只报出来不记账。
5. **一条判据只覆盖它自己那一档。** `build/evidence/r104_c5head_band.txt:23`：
   "C5c 只在 0 度 × 100 % 那一档量过。每帧换角 × 帧头这两个维度从来没有同一条判据覆盖过（已立案）。"
   `sim/tb_head_rot_displace.v` 量的是**后果的大小**，不判"哪几行带着上一帧"——
   后者仍是 C5c 的职责（两份凭据各说各的）。
6. **文本尺不判"对"，只判"一致"。** 9.3 那句"不存在第二份真值能给出对的行号"
   对 9.4 同样成立：`metric_recheck` 判的是 csv/首页与报告一致，报告本身若来自一次错的构建，
   它只会一致地跟着错。拦住这一层的正是第 3 层（门禁读的必须是**同一套**产物，
   `build/gates.sh:53-71` 的新鲜度与身份行）。
7. **空集恒绿那一族只能靠地板压住，压不到零。** 这一族在门禁里的补丁形态是
   计数地板（`build/gates.sh:368-370` 的 `NJ=3`、`:267-272` 的 `ports_floor.sh`、
   `build/deliver_spec_check.mjs:9-11` 的 `cmp`、`:32-35` 的 `NOT_MEASURED`）。

第 6 条值得单看，因为它是这套体系与"只跑一次仿真"的真正差别：
一份 PASS 报告**本身**需要被证明属于当前这棵树，而证明它的方式不是"相信文件名里的版本号"，
是三枚在编译之前盖下的指纹 + 一份能红的反例清单 + 一把尺子自己的对照。
