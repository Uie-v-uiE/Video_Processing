**1. 输入→输出与阶段**
输入：三路 512×300 RGB565 帧（网口 UDP 包 / SD 卡裸帧 / 片内自绘图卡）。输出：HDMI 1024×600
"左原图右处理同帧对照"画面，外加串口回显与 JTAG 状态字三条出口。阶段：网口采样→自算校验→剥头过滤→按偏移重组并
逐行验收→跨域缓冲→打包写入片外内存（乒乓两块）→提交→只在消隐窗口整帧搬回片上帧缓存→显示坐标逆映射→
固定 15 拍效果链→对照混合＋叠字→并串上屏。依据：`system-overview.md` 第 1~3 节、`one-pass-walk.md` 第 19 节。

**2. 怎么知道算完**
这里没有中断：三只 GPIO 的中断属性全为 0，固件也没有异常服务程序 ⇒ 一切"完成"都是**轮询某一位＋看它翻不翻**。
链上有四个不同的"完成"（收完并验收 / 落到某块 / 搬进帧缓存 / 真的开始扫描），各自通知对象不同；跨域处用
"翻转位＋三级＋异或"把单拍事件送到对面。依据：`interface-contract.md` 第 7 节、`one-pass-walk.md` 第 16 节、
`clocking-and-reset.md` 第 4.2 节。

**3. 为什么要跨时钟域同步，去掉会怎样**
六个节奏互不同步的时钟族在同时工作（125/100/50/250 MHz 等），一位数被对面采到的时刻与它自己变化时刻无关。
去掉后本仓库登记过的后果：多位总线读到"半新一半旧"；单拍事件整件消失（对面根本没发生过）；帧尾 4 字节写进下一帧
（屏右下角少 2 像素）；组合逻辑毛刺被当事件（假"链路掉"）。且这类错**不出现在时序报告里**（结构判据）。
依据：`clocking-and-reset.md` 第 1、3 节与 4.1~4.3、`glossary.md` 词条 2/6/7/8、`myths.md` 第 3 节、
`mechanics.md` 第 3 节第 ④ 层。

**6.（必答，无专有名）**
当接收方按自己的节拍去"取"那一位时，取的那个瞬间发送方那位可能正在从旧值变到新值，于是存储元件会短暂停在既不是 0
也不是 1 的状态、最终随机落定；一次传一排时，每一位落定的早晚还互不相同，所以取到的可能是新旧拼起来的一个从未
存在过的组合，而且既不报错也不必然重现。

**7. 会被带偏的"零术语简化说法"**
`clocking-and-reset.md` 4.3 第①层"先把一整排数站住，再拧一下小旗，对面看到小旗才抄，抄到的必然是整套新值"——
最像软件里的 flag＋payload，会顺势以为"旗到了就一定是最新且一次不丢"。它自己写的误导提示是
"会在'这排数其实在对面看见小旗之前还在变'的情形下误导你"，并在第④层补"它不是握手，没有回线，不承诺每一次都到"。
同类第二处：4.1 的"连续看三次"，提示是"这个开关其实只是一拍亮一下时那一拍会被整个吃掉"。

**8. 与 `build/` 数字对不上先怀疑什么**
先怀疑"我念的是哪一份件、哪一轮构建"，而不是怀疑设计：门禁读的是**冻结证据目录**，其端点数与当前位流不同一轮；
同名报告有两份且只差头部时间行、谁正本案内未判；注释里的数字与报告不同轮（分母 7936 对 8188）；饱和值要当"至少"念；
裕量（ns）与时长（拍/ms）永不相减。依据：`hands-on.md` 实验 1、`prerequisites.md` 第 3 节"md5 与产物身份"、
`mechanics.md` 第 0 节③与第 12 节红项 2、`design-choices.md` 第 1 节／第 5 节、`myths.md` 第 4、5 节。
