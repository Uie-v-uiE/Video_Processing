### 1. 一份 .v 文本要经过哪几个阶段才变成板上跑的东西

写代码 → 综合 → 实现（布局布线）→ 生成位流 → 下载，五步；每步产出不同东西（→ 术语表 `综合`、`实现（布局布线）`、`位流 / XSA / ELF`）。

| 阶段 | 吃进去 | 吐出来 | 这一步在工程里的原文（抄件） |
|---|---|---|---|
| 写 | 人写的连接与逻辑 | 一份 .v 文本 | `module rgmii_rx (` 那一行起（下面第 2 段的抄件 A） |
| 综合 | .v 文本 + 约束 | 网表（"用哪些现成零件、怎么连"） | `launch_runs synth_1 -jobs 4` |
| 实现（布局布线） | 网表 + 约束 | 每个零件摆在哪、每根线怎么走 | `launch_runs impl_1 -to_step write_bitstream -jobs 4` |
| 出位流与报告 | 上一步的结果 | `system.bit` + 一批 `.rpt`/`.txt` | 同一条命令里的 `write_bitstream` 就是"顺带把位流写出来" |
| 下载 | `system.bit` | 板子里真的换成这套逻辑 | `program_hw_devices $dev` |

三条命令是工程脚本里的原文，出处（要开代码时再看）：
`build/tcl/build_system_axigpio.tcl:306`、`:353`；`build/tcl/program_pl.tcl:31`。

**为什么同一个数每次重建都会变**：综合只按近似模型估线长，实现才有真的位置与真的线；
而"把零件摆在哪、线怎么走"这件事本身带有工具内部的搜索顺序与随机性，
于是**同一份代码、同一套约束，重建三次可以得三个 WNS（建立时间裕量，→ 术语表）**。
本工程的实测记录（抄件，出处 `build/gates.sh:278`）：

> 同一套约束三次构建 WNS = 0.918 / 0.807 / 0.314，只抄那一个数就会误判成"某次改动拖慢了设计"

同一脚本 `:279` 补的那句是要点：分组数才是可比的量。
换句话说：拿到两个不同的数，先问"是不是同一轮、同一量纲"，再问"谁改了什么"
（这条判据在 `hands-on.md` 实验 1 与 `glossary.md` 词条 11、53 里各写了一遍）。

### 2. 五分钟看懂本工程的 Verilog（六样，全配抄件）

下面六段是本工程里真实存在的那几行，**原文照抄**，行号写在每段上方；
判断只靠抄件，不需要去开文件（开文件核对该行内容属于第 2 层动作，见最后一条）。

抄件 A —— `module` 与端口（出处 `src/rtl/eth/rgmii_rx.v:24-25`、`:28-30`）：

```verilog
module rgmii_rx (
    input idelay_clk,  //200Mhz时钟，IDELAY时钟
    input       rgmii_rxc,     //RGMII接收时钟
    input       rgmii_rx_ctl,  //RGMII接收数据控制信号
    input [3:0] rgmii_rxd,     //RGMII接收数据
```

读法：`module 名字 (…)` 就是"这一段电路有一个接口清单"；清单里每一项是一根线，
`input` 是别的模块送进来的线，`output` 是这段电路送出去的线。
`[3:0]` 表示这一项其实是 4 根线编在一起（从 3 号数到 0 号），没写宽度的是 1 根。
`//` 后面是给人看的注释，工具不执行它。

抄件 B —— 位选：从一排线里挑一根（出处同文件 `:45`、`:48`）：

```verilog
    wire [1:0] gmii_rxdv_t;  //两位GMII接收有效信号
    assign gmii_rx_dv  = gmii_rxdv_t[0] & gmii_rxdv_t[1];
```

读法：`gmii_rxdv_t[0]` 取的是那两位里的 0 号那一位；`&` 是"两个都为 1 才算 1"。
这两行合起来的意思就是本目录讲收包时反复用的那句"两沿都为 1 才算数据有效"。

抄件 C —— 寄存器写法：`always @(posedge …)`（出处 `src/rtl/top/system_top.v:108-112`）：

```verilog
    reg [23:0] phy_rst_cnt = 24'd0;
    always @(posedge sys_clk) begin
        if (!(&phy_rst_cnt)) phy_rst_cnt <= phy_rst_cnt + 1'b1;
    end
    assign eth_rst_n = phy_rst_cnt[23];
```

读法：`posedge sys_clk` = "`sys_clk` 从低变高的那一下"。这一整块**只在时钟那一下动**，
`phy_rst_cnt` 是"上一拍的数存在这里"的东西（这就是"寄存器"）；
`<=` 是"下一拍才生效"的写法。第五行 `phy_rst_cnt[23]` 是从这 24 位里挑最高那一位输出 ——
于是前 24 拍计数、计满就把复位放开，这就是板上 PHY 的上电复位发生器
（口径见 `clocking-and-reset.md` 第 2 节 那一行）。

抄件 D —— 组合写法：`always @(*)`（出处 `src/rtl/top/system_top.v:237-240`）：

```verilog
    always @(*) begin
        if      (lm_lane == 5'd31)     lm_rd = {30'd0, lm_clk_slow, lm_clk_gone};
        else if (lm_lane == 5'd30)     lm_rd = {16'd0, dbg_src};   // [10:8]=why_ps（V8-7）
        else if (lm_lane == 5'd24)     lm_rd = dbg_lat[5*32 +: 32];   // 与 q_tot 同一轮的 ms
```

读法：`@(*)` = "只要它读到的任何输入变了，这一段就重算"，它**不等时钟**。
这就是"组合"：同一拍进、同一拍出，不保存任何东西。
`{30'd0, lm_clk_slow, lm_clk_gone}` 那个花括号是"把三排线首尾接成一排 32 位"，
`5'd31` 是"5 位宽、十进制 31"这个常数的写法。
把抄件 C 与抄件 D 并排放，就是这一节真正要人记住的区别：
**带 `posedge` 的会记住、`@(*)` 的不记住**（→ 术语表第 2 节 词条 4 讲的是"记住之后要跨域"的麻烦）。

抄件 E —— 例化：把一段电路摆进另一段（出处 `src/rtl/top/system_top.v:154-156`）：

```verilog
    eth_udp_video_top #(
        .IMG_W(VIDEO_W), .IMG_H(VIDEO_H),
        .BASE_ADDR(DDR_BASE),
```

读法：`模块名 #(参数…) 实例名 (端口…) ;` 这一整句的意思是"照 `eth_udp_video_top` 那份描述，
在顶层摆一只，尺寸与地址用括号里这几个数填"。
`#(...)` 里是**建的时候就定死的数**（换一次要重新综合），端口连线是**跑起来之后每天流动的数**。
本目录说"51 只实例逐只点名"指的就是这种句子（`subsystem-map.md` 第 3~4 节）。

抄件 F —— 参数默认值（出处同文件 `src/rtl/eth/rgmii_rx.v:39`）：

```verilog
    parameter IDELAY_VALUE = 0;
```

读法：这一行给"上面 #(...) 传进来的那个数"留了一个默认值 0；
本工程实际传的是 31（`src/rtl/top/system_top.v:172`），
`glossary.md` 第 34、35 条讲的正是这个数是什么、一格多久。

### 3. 三件套与身份：bit / xsa / elf 为什么必须逐件核

三件各是什么（→ 术语表第 50 条）：
`.bit` 是 PL 的配置（下载进板子的那份）；`.xsa` 是给软件侧用的硬件描述包（本工程把它当"平台包"用）；
`.elf` 是 PS 那颗 CPU 要执行的程序。三件由**三条不同的命令**产出，所以会各跑各的。

工程里这一版的三张"来源卡"（`board/firmware/` 下，一人一件）抄件如下 —— 只看抄件就能做判断：

| 件 | 卡上给的 MD5（32 位） | 门禁件里的身份行（截到 12 位） |
|---|---|---|
| `build/system.bit` | `cd04907e1369da35d21c4090d552f5ee` | `身份：system.bit md5=cd04907e1369` |
| `build/system.xsa` | `934ebdbaa13b4ff6b63323a656453c52` | `system.xsa md5=934ebdbaa13b` |
| `build/ps_app.elf` | `d0b07f84a0683db203086fb816ac71d7` | `ps_app.elf md5=d0b07f84a068` |

出处（要开代码时才用）：三张卡 `board/firmware/system.bit.md:7`、`board/firmware/system.xsa.md:7`、
`board/firmware/ps_app.elf.md:7`；身份三行 `build/r118_gates.txt:3-5`；打点的那句在 `build/gates.sh:50-52`。

**为什么逐件核**：文件名与"最后修改时间"都不能证明三件来自同一次构建。
两张卡自己就把这件事写成了结论：
`board/firmware/ps_app.elf.md:11` 那行的口径是"文件时间晚于内容变更 ⇒ mtime 只能说明被写过一次，不能说明内容变了"；
同卡 `:13` 那一节标题直接写"它不是 r118 那一轮产的"，`:21-22` 给的原因是
"构建入口只产 bit 与 xsa，ELF 要另外一条命令 ⇒ 位流换了一版不等于 ELF 换过"。
另一件真实后果记在 `build/gates.sh:50-52`：以前只打时间不打三件的摘要，
于是导出器按"板上那一版"去挑配对的门禁件**永远挑不到**，
交付包自己在 MANIFEST 里写"这一版不作交付"而导出器还是正常退出。

板上现在跑的是哪一版，凭据也抄在这里（`build/evidence/r118_board/board_now.txt` 全文三行）：

> 板上现在 = r118（刷入 2026-10-04 04:49:50，bit_cycle rc=0 board_verify rc=0）
> B1 严格名册：B1 pairs_compared=8 losses=0 verdict=GREEN
> 刷板前那一次门禁：绿=21 红=3（其中 2 条是文档时效，改口后由最终两跑复验）

## 第 4 节 三条阅读路径各自的最低配置

- **路径 A（只学过数字逻辑与 Verilog 语法）**：第 2 节全部要到第 2 层，`定点数` 与 `总线握手` 到第 3 层；
  第 3 节只需要 `C 的地址` 与 `命令行与 shell` 两项。缺 `网络包` 不挡前四章，但挡 `one-pass-walk.md` 第 1~3 步 —— 那一步的
  读法在章内就地给了（`one-pass-walk.md` 第 2 步"数据形态"栏）。
  这一条路径里 Verilog 那半可以跳，但第 1.5 节第 1 段（阶段表）与第 3 段（三件套与身份）不建议跳 ——
  它们讲的是"文本到板子中间发生了什么"，学过 Verilog 语法并不包含这块。
- **路径 B（会写 C/Python，没做过硬件）**：**第一步是第 1.5 节，三步全做**，然后才轮到第 2 节那张表。
  排在最前是因为这一节是三段的公共前置：`构建阶段` 决定后面所有"为什么每次数字都变"能不能读明白，
  `六样 Verilog` 决定第 2 节那十行动作能不能开始做，`三件套与身份` 决定第 3 节里 `编译产物三件套`、
  `md5 与产物身份` 两行能不能对上号。2026-10-05 的 B 轮回述测试把这一点说得很直白：
  最缺的一块是"一份硬件描述文本要经过哪几个构建阶段、阶段之间同一颗器件的量为什么每次重建都会变"，
  而在 `clocking-and-reset.md` 第 5 节与 `mechanics.md` 第 8 节那里才第一次撞上它
  （`_feedback/recall-run-b.md` 第 9 题与断点清单）。第 2 节仍是主战场：
  `位宽`、`寄存器 vs 组合`、`模块与例化` 三项必须到第 3 层，
  否则 `subsystem-map.md` 第 2 节就会从第一行开始掉队。其余硬件项先按第 2 层走，遇到再补。
- **路径 C（会 FPGA、不熟本平台）**：第 2 节全部跳过；第 3 节里 `编译产物三件套` 与 `md5 与产物身份` 到第 2 层，
  然后直接进 `clocking-and-reset.md` 第 3 节（跨域点全表）与 `interface-contract.md`。
  这一条路径不必做第 1.5 节（阶段与三件套本来就是这一档读者的已有知识），
  但如果只读过别的板子、没碰过 Zynq 的 bit/xsa/elf 分工，读第 1.5 节第 3 段的抄件表就够，不必做动作。

小结 1：这张表的作用是**让你在打开下一章之前就知道自己会在哪儿掉队**，不是考试。
小结 2：任何一项自查动作做不出来，先按第 2/3 节表里标出的那一层补，再进对应的章；
**做不出来 ≠ 读不懂**：第 2、3 节的动作全部要求能打开 `src/`、`build/`，
只许读 `docs/walkthrough/` 这一目录的读者请改做第 1.5 节 —— 那里的动作靠抄件就能完成。
