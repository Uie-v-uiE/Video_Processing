PASS R3 legit frame completes | a well-formed echo request (payload 8) must give exactly one rec_pkt_done with 8 bytes; if this is red the STIMULUS is wrong, not the DUT
FAIL R1 wrapped length must not park the parser | after a bogus IP total_length=20 the 16-bit minus wraps to ~65516; leaving st_rx_data needs skip_en/error_en and st_rx_data never sets error_en
FAIL R1b only the legit frame emits payload | counted rec_en cycles across the bogus frame AND the following legit one: 8 means only the real payload shipped, >8 means the parked parser ate the next frame

RESULT tb_icmp_len_wrap FAIL nfail=3

# 三条红 + 一条绿的形状是有意配对的：
#   R3（绿）钉"我的激励本身没问题"——合法 echo request（载荷 8 字节）走完整条解析并恰好完成一次；
#   R1（红）钉"畸形包过去之后解析器仍停在 st_rx_data"；
#   R1b（红）钉"它把紧跟的**下一整帧**当本帧载荷吐出去了"（跨两帧数 rec_en，期望 8，实测 >8）；
#   R2（红）钉"跟在后面的合法 ping 得不到应答"（done_total 期望 2，实测停在 1）。
