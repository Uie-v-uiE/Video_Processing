r121 改名波（skill/ → skills/、readme.en.md → README_EN.md）与导出器结构修法
================================================================

## 为什么这一刀是必须的
仓库根目录已按赛题 §0.4 固定为 `skills/`（117 个跟踪文件），根 README 的英文版也已叫
`README_EN.md`；但树里还有 437 处 `skill/…` 与 117 处 `readme.en.md` 的指路。这些不是文字问题：
导出器的死链自检按 `(src|sim|build|board|data|skill|report|docs)/…` 抽指路，而 `skills/` 在那个
alternation 里根本不匹配 ⇒ 整个技能包层的指路**隐身**，死链数出来的不是"包干净"而是"尺子没看着"。

`--self` 判 11 项（6 条替换 + 5 条射程判定）红=0；`--check`/`--apply` 判 742 项（=射程内跟踪文件数）。

    CHECK RENAME 判 742 项 射程=742 待改=72 skill/=437 readme.en.md=117 拒写=0 冻结件不计=8 类 PASS
    WROTE RENAME 判 742 项 射程=742 待改=72 skill/=437 readme.en.md=117 拒写=0 冻结件不计=8 类 PASS

射程 = 跟踪的 .sh/.tcl/.py/.mjs/.ps1/.bat/.v/.c/.h/.xdc/.md/.csv 与 `.gitignore`；
不计的 8 类冻结件 = `report/log/**`（追加式台账，逐字记录）、`build/evidence*/**`、
`build/frozen_*/**`、`build/report*/**`、`build/runs/**`、`board/{compare,logs,captures}/**`、
`data/golden/**`、`.git*`。豁免条数打在结论行里，不静默吞掉。
改完后残留的 `skill/` 只在 8 个文件里：`report/log/{changelog_v6,contest_checklist,d4c_pointers,
issues,overnight_log}.md`、`build/evidence/r119_merge_sources.py`、
`build/frozen_r55_deadcdc/manifest.md`、`board/compare/index.md` —— 全是当日原始输出，按规矩不改。

## 我自己这两把尺子的量纲错（写下来是因为它们一开始都在骗人）
1. 第一版"反向还原必须逐字节相同"：文件里本来就有一批上一轮改过的新名，还原把它们也换回旧名，
   于是 29 个文件被误判"改的不止两个 token"。改成**归一化比对**（新旧两种拼法折成同一个 `§`），
   这才是"这一刀只动了两个 token"的正确形状。
2. 第二版的长度等式写成 `raw + skill − rmea`，因为我把 `README_EN.md` 数成 11 字符——它是 12 个，
   与 `readme.en.md` 同长。`--self` 里那条"两种写法都收"的对照因此先红后绿：**没有 --self 的话
   这条错误会直接变成 29 个"拒写"**，看起来像"文件有问题"而不是"我的算术有问题"。

## 台架取舍从手写名单改成表格现算
`sim/README.md` 那张表由 `build/gen_sim_readme.mjs` 从 81 份台架的三段头生成，表外不允许有段落（§2.4）。
导出器原来按手写 `SIM_KEEP` ∪ 脚本点名剪台架 ⇒ 剪掉的每一个都是表里的一个幻影行。现在第三个
keep 来源 = 表格第一格现算（`_table_tb.txt`），并带一条地板：数到 0 格就 REFUSE（表没生成 ⇒ 取舍没有依据）。

## 顺带修掉的三处射程/形状洞
- 死链抽取的 alternation 加 `skills?`（两处：包内自检与台账层）。
- 活文档射程的逐层地板从手写 7 个层名改成**包内实际目录现算**，且判"0"之前先数这一层到底有没有
  `.md/.csv`——否则新增长目录依然会静默掉出射程（规矩 47 的同族）。
- `^skill/` → `^skills/`（KEEP_ALWAYS_RE）；`.gitignore` 里 `skill/scripts/_out/` → `skills/…`。
