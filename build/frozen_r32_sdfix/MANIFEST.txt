# ---------------------------------------------------------------- 改了什么（src/ps/sd_play.c）
# 1) 根因修复：`dir_lookup` 返回首簇时把 FAT32 目录项偏移 20 的 **16 位小端字**按大端拼
#    （`(d[20]<<24)|(d[21]<<16)`）。首簇 < 65536 的文件看不出来（高字是 0，怎么拼都是 0），
#    而 65536 簇 × 16 KiB 恰好 = 1 GiB ⇒ 只有"起点落在数据区 1 GiB 之后"的第一个文件
#    （VIDEO007.BIN = 第 3584 帧）发作。现在抽成 `clus_of()` = `ld16(&d[20])<<16 | ld16(&d[26])`。
# 2) 失败行自己报几何量：`read_secs` 失败时打印 lba / 扇区数 / 簇号 / 分区末尾 / IN- or OUT-OF-RANGE
#    （+ data_lba、spc 让人能复核分类）。**这就是把 #50 从"并发竞态"翻案成"字节序"的那一行。**
# 3) 判据 + 反例（用户规矩：判据自己要有测试）：
#    · `dir_selftest()`：三个合成目录项，外加一条"旧写法必须给出 16778886 且与新写法不同"的断言；
#      它是挂载前的硬门 —— 把字节序改回去重下一版，板子直接拒绝挂载并报
#      `mount failed: cluster decode SELF-TEST failed (firmware bug, not the card)`（本目录 sd_selftest_red.txt）。
#    · 挂载时逐文件核对首簇是否超出分区能装的簇数：
#      `[SD] dir map ok: 9 files, first clusters within 1946818`（sd_selftest_green.txt）。
#
# ---------------------------------------------------------------- 板上凭据（本目录内，md5 在 BODY 里）
# · sd_hotspot_diag.txt  修复**前**的现场：`[SDRD!] lba=536959104 ... clus=16778886 ... OUT-OF-RANGE`
#      簇号 0x01000686 换回小端 = 0x10686 = 67206；由 `sd_stage_r29` 的文件长度算出的连续布局预测是 67205
#      （差 1 簇），再用 `clus_lba()` 反算 LBA 得 536959104 与打印值逐位相同 ⇒ 因果链完整。
#      同一份文件里还有"次生现象"的现场：之后连根目录扇区（lba=34816，IN-RANGE）都读不动
#      ⇒ 一次半途夭折的多块读会把控制器留在未完成传输里，"file not found" 是尸体不是病因。
# · sd_hotspot_fixed.txt 修复**后**：155 s 纯串口抓取，帧窗 3500→3600→…→4300 全程 29.2–30.0 fps

# · uart_sd_with_eth.txt **并发**复验：同一份 elf 在 30 fps 推流正在跑的时候连续监听 165 s，
