## 两条结构判据（这才是能写进结论的部分）

1. **`tx_data_num` 在整份 `timing_summary.rpt` 里出现 0 次**（r103 那份里它是最差那一格的起点，`tx_data_num_reg[15] → data_cnt_reg[*]/CE`，10 级）。
   ⇒ 这一族彻底离开被报告的关键路径，与上午那次一致。
2. **`check_buffer` 也出现 0 次** ⇒ **r100 那次"收益挪到隔壁 IP 首部校验和路并 −0.110、多 1 个失败端点"的失效模式，这一轮没有重演**。
   新的最差格换成了 `u_rx_par/udp_off_reg[1] → p_good_reg/D`（收侧 UDP 解析器，10 级、logic 占 43 %），仍是 `eth_rxc` 域。

## 结论与下一步（不含糊）

- 手上证据现在是：**同一刀两次隔离都好**（结构判据 + 0 失败端点 + 这次没有邻居违规），**一次正式构建（r100）把它否了**。
  r100 那次否的根因是"收益挪到隔壁"，而这次的隔离版里那条隔壁路**没有**进报告 ⇒ 值得走一次**正式 r104** 由正式构建裁决。
- 已按计划起 **r104 正式一轮**（`build/r104_chain.sh`，只带这一刀），链尾会出门禁件；
  门禁若出现任何**新的**红（尤其 `check_buffer` / IP 校验和那一族），就按本仓规矩回退这一刀，把树还原成与板上 r103 一致的 `rtl=50586c64bb87`。
- ⚠ 口径：这仍**不满足** #141 原本想要的"同一网表多滚几轮"——正式轮只跑一次。所以能写的是
  "两次隔离 + 一次正式通过"，不能写"收益确定为 +0.204 ns"；WNS 绝对差不作为收益口径。
