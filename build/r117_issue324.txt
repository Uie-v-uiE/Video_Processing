

### #324 我自己撞了老规矩：上一条提交的信息说"第 7 节补了『查过手册』"，但那次 python 的 assert 挂了 ⇒ 文件其实没改（03:39 修）

链条：脚本在 `assert s.count(anchor) == 1` 处抛错 ⇒ 后面的写文件**根本没执行**；
可同一条 shell 命令里的 `git add` / `git commit` 用 `;` 串着，照样成功，
于是**提交信息写着一件没发生的事**。这正是 #99 那条老账的翻版
（"commit claimed RTL it did not contain ⇒ 提交后要 `git show HEAD:file | grep` 一下"）。
这次是下一步我就 grep 到了（`grep -n "1\.7 ns|专用走线"` 看到原文还在 ⇒ 说明我的插入没落地），
所以只多做了一次纠正提交，没有污染门禁件。

规矩补硬（写进我自己）：**一条命令里同时"改文件 + 提交"时，改动那步必须自带成功标记
（写完立刻回读、打印命中数或 `grep -c`），而提交那步要用 `&&` 串在这个标记之后**；
`set -e` 救不了我，因为 assert 的退出码被 `;` 吞掉了。
附带一条：CJK 引号在 shell 单引号串里会截断命令（这条 #324 的正文第一次就因此没写进去 ⇒ 改用文件落地）。
