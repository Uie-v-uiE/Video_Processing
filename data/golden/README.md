# data/golden — 参考图与测试向量

这个目录放的是**软件侧算出来的参考结果**，用来跟屏上照片做人工比对。
它们**不是任何台架的输入**：全仓库对 `data/golden` 的引用只有
`docs/log/CONTEST_CHECKLIST.md` 提了一次目录名，没有任何 `.v`、`.mjs`、`.sh`
读这里面的文件（核实命令：`grep -rn "data/golden|frame_640x360" --include='*.v' --include='*.mjs' --include='*.sh' .`）。
所以这一目录的定位是"人眼比对的参照物"，不要当成黄金参考自动化比对在用。

## 文件

| 文件 | 内容 | 可信度说明 |
|---|---|---|
| `src.png` | 源图（软件渲染的输入画面） | 来历同下表说明 |
| `rot_000.png` `rot_030` `rot_045` `rot_090` `rot_180` `rot_270` | 同一源图在各旋转档下的软件渲染结果 | 用来核对"旋转后画面该长什么样"，逐像素比对没人做，靠眼看 |
| `proc_00111.png` `proc_10000.png` `proc_all.png` | 若干效果组合的软件渲染结果 | ⚠ 文件名里的**五位数字是旧的效果位口径**（现在的 `pipe` 控制字是九位、OSD 显示五位成对码）。**不要按字面把它读成当前的 `stage_sel`** |
| `dual_preview.png` | 原图/处理图左右并排的预览 | 与 `split_display` 的显示方式同类，但不是同一套算术产出 |
| `frame_640x360.mem` | 640×360 的裸帧测试向量：一行一个 16 位 RGB565 字的十六进制，行尾 CRLF；230400 行 × 6 字节 = 1,382,400 字节，与文件实际长度一致 | 目前没有任何脚本或台架读它 |

## 已知的两笔欠账

1. **PNG 无法一键重跑**。这批图是早期 host 侧预览工具的输出，那份工具现在不在树里，
   所以我不能在这里给出"重新生成"的命令。要么补一个可复现的渲染脚本（与
   `src/rtl/process/` 的定点算术一致，含同一套饱和/取整），要么在提交时把 PNG 降级为
   "历史参照图"并写清不能复核。**在补出来之前，任何"与黄金参考逐像素一致"的说法都不成立。**
2. **`frame_640x360.mem` 是孤儿测试向量**。它尺寸是 640×360，而本设计的源尺寸是 512×300，
   所以它只能当发流素材的样例，不能直接喂显示通路。二选一：接到 `src/host/video_sender.mjs`
   的输入路径上当测试数据，或者从提交包里去掉。

比对照片的实际操作步骤（哪条命令、屏上看什么、每个"否"意味着什么）在 `board/HANDS_ON.md`。
