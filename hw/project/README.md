# Board artifacts

| File | Content | Generated by |
|---|---|---|
| `system.bit` | PL bitstream | `vivado -mode batch -source scripts/build.tcl` |
| `system.xsa` | hardware description exported with the bitstream | same |
| `ps_app.elf` | PS bare-metal application | `scripts/ps/build_ps_app.py` |

The three must come from the same build. A new bitstream with an old XSA breaks the Vitis address map, and PS sources changed without recompiling the ELF leave the old firmware on the board.

## Checksums

```bash
md5sum hw/project/system.bit hw/project/system.xsa hw/project/ps_app.elf
```

The build and board scripts print the first 12 hex digits of each MD5. A log line counts as the same build only when it matches these values.

## Regeneration order

1. RTL or constraint change: run `scripts/build.tcl`, which updates `system.bit` and `system.xsa`.
2. PS source change: run `scripts/ps/build_ps_app.py`, which updates `ps_app.elf`.
3. Repackage the QSPI image: `hw/scripts/make_boot_image.sh`.
4. Verify over JTAG: `hw/scripts/board_flash.sh`.
5. Write QSPI: `hw/tcl/flash_qspi.tcl`, then power-cycle.

## Notes

`system.bit` and `system.xsa` are exported from the same implementation. The BSP behind `ps_app.elf` must match the PS7 configuration in `system.xsa`. The current ELF includes the serial `link` and `link clr` commands for frame-gap statistics.
