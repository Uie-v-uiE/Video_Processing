## 2. 没做到的（逐条给"缺什么"）

1. **第二块板没上板**。缺的不是代码而是窗口：两块板共用同一根 JTAG，且验收要有人盯屏。
   bit 已备好（`ku5p/build/` 下有 md5），验收步骤写在 `ku5p/README.md`。
2. **UltraRAM 换帧缓存这件事不成立也不宣称**。已核实的是：`ram_style` 给 `ultramark`/`ultraram`
   都被综合判为无效值（凭据 `build/uram_probe_console.txt`），以及"读口数量直接乘 BRAM"
   这条实测规律；**没核实**的是这颗器件有没有 URAM 站点（三次 TCL 问法里阳性对照没过，
   那个 0 不算结论）。下一步该查器件手册，不是继续试命令。对外只说帧缓存在 BRAM。
3. **两处屏上现象还开着**：帧头若干行的读侧绕回（`ISSUES #98`，门禁里唯一的红灯）、
   处理侧跟着分割线的那条黑线（`#103`，**尚未复现也尚未排除**——现有 C9 判据的对照没有权力）。
   另有 `#104`：角度非 0 时双线性的小数位被钉成 0，屏上 `bilin` 那一格名不副实。
   大角度旋转时画面角点出屏（`#93`）与 SD 播放中拔卡的旧现象（`#94`，已修待复验细节）也在账上。
4. **被过滤掉的包数还不是可读寄存器**（`udp_rx_parser` 的三个统计脉冲没接出去）：
   端口过滤进了顶层，计数没进。要不要接是独立决定，没有顺手塞进别的改动里。
5. **`bad` 会动这件事只有台架证据**（`tb_v795_rx_chain` 的 C2）。现场没有可靠的注错手段，
   所以板上只报"改前是死的、改后有判据"，不报"板上见过它跳"。
6. **不做 MIPI 摄像头**：两块板都没有 D-PHY 硬核，板上那个 FPC 只引出 CSI-2 差分对
   （没有并行 DVP 数据线）⇒ 接相机等于自写软 PHY，是一件独立且失败模式最难查的子工程。
   第三源位置用会动的测试图卡占住，架构、切换、回落全是真的，只有传感器是空的。
7. **仿真只有 xsim 一家**。早期可作第二意见的 ModelSim 已不在本机（许可证由新版 FlexNet 签发，
   自带客户端判 inconsistent），所以凡是"两家仿真都过"的说法今天都不可复现——仓库里可复现的
   仿真路径只有 `build/gates.sh` 与 `sim/`。
8. **`data/golden/` 的参考图没有可一键重跑的生成脚本**，只能作人工比对；
   在那之前不许说"与黄金参考逐像素一致"。详情与两条待决写在该目录的 README。

## 3. 演示时的三条口径边界

- SD 一路放的是 PC 预转换的 **512×300 RGB565 裸帧序列**（`src/host/make_sd_video.mjs` 生成），
  板上不做任何解码 ⇒ 对外说"SD 帧序列（预转换）"，不说 MJPEG/视频解码。
- 缩放 0.25×–2× 八档、旋转有限角度档、分割线 0–100 % 固定/自动扫描/贴在图像域跟随，
  都是**已实现且可当场演示**的；但小倍率与负半边会带来黑边与取样台阶（最近邻固有），
  被问到时说"对齐是修过的，台阶是最近邻"，不要说成"抖动已消除"。
- "为什么这一帧干不干净不用人眼看"是本作品的主张：同一组计数器有 OSD、JTAG 回读、
  串口三个出口，演示时先展示三方对账，再展示逐像素对照（`split 50` + `split marker 0` 一屏两条抽头）。
