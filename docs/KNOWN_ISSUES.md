# 已知未修与验证边界（对应 §3.3.5.3 的"失败分析：哪些场景仍然做不好，原因是什么"）

> 这份文件不是免责声明，是一份**带复现方法的缺陷清单**。每条都写：现象、为什么现在是这样、
> 怎么当场重现、修它要动什么、以及**为什么这一版没修**。台账原文按编号在 `docs/log/ISSUES.md`。

## 一、功能层面已确认、但这一版没修的缺陷

### 1. 帧头若干行的读侧绕回（`#98`）—— 顶层台架上唯一一条故意留红的判据

- **现象**：整屏逐像素判据里，帧头若干行会出现"读到上一帧尾巴"的绕回。判据号 `C5c`，
  红在 `build/reports/` 里那份顶层台架报告中（每一轮都红，不掩盖）。
- **为什么现在是这样**：读侧绕回原本按"发请求那一拍"开窗，正确性依赖消隐期的长度恰好盖住延迟；
  改成按"数据写进环那一拍"开窗才是与消隐无关的口径（第一刀已落在 `r78`）。
- **复现**：`bash sim/run_one.sh tb_video_pipeline_top`，看 `C5c` 那一行。
- **为什么不修**：这一刀的改动落在读口调度上，会同时动数据通路 ⇒ 必须先给它一条"改前必须红、
  改后恰好绿这一条"的变异对照（本项目的规矩），而那条对照还没建。**留红是有意选择：
  宁可交付一条知道自己在哪红的尺子，也不交付一条被调绿的尺子。**

### 2. 旋转支上的双线性小数位被钉成 0（`#104`）

- **现象**：角度非 0 时，OSD 上 `bilin` 那一格仍然显示"双线性开"，但旋转支取样的小数部分实际被丢掉，
  等效于最近邻 ⇒ **屏幕上那一格此时名不副实**。
- **复现**：`rot 30` 之后看画面台阶；或对比 `rot 0` 与 `rot 30` 在同一缩放档下的边缘锯齿。
- **修它要动什么**：旋转支的坐标定点位宽（小数位对齐到缩放支那一族的口径），并让 `bilin` 那一格
  改成"当前生效的那一路真的在用插值"才点亮。
- **为什么不修**：位宽改动会进时序关键锥，而这一版把"时序不承诺"这条边界守住了（见第二节 1 条）。

### 3. 大角度旋转的角点出屏（`#93`）

- **现象**：旋转角度大时，画面对角线长度超过窗口，角点出屏 ⇒ 出现沿对角方向的宽彩条与左缘细线。
- **为什么没修**：这是**几何选择的后果不是 bug**——当前语义是"旋转围绕视口中心、超出部分丢弃"。
  改成"旋转后仍完整可见"需要自动缩小（`zoom fit`），而那条路在 `#102`（左缘细线）上被眼睛判据否证过一次，
  队员明确要求先把已经量到的修完。**这一条按"待定的产品决定"记录，不按"缺陷已修"记录。**

### 4. `pl_demo_top` 里同一个实例被关联了两次 `stage_sel`（`#127` 第 1 条，CONFIRMED）

- **现象**：`src/rtl/top/pl_demo_top.v` 的 `u_pl` 实例上挂了两条 `.stage_sel(...)`
  端口关联（一条 `9'd1`、一条 `9'd0`）。重复输入关联在工具里是"看它选哪个"，不是"两边都成立"。
- **影响范围**：这个顶层是 PL-only 的老演示工程（被 `build_pl_full.tcl` / `create_project.tcl` 用），
  **不在交付构建的顶层链上**（交付走 `build_system_axigpio.tcl` → `system_top`）⇒ 板上跑的 bit 不含此问题。
- **为什么不顺手修**：修它要动 `src/rtl`，会让正在跑的那一轮整屏台架的 `rtl_md5` 作废。
  排进独立一轮，并且**先给 `build/check_ports.py` 加一条"同一实例不许重复关联同一输入"的门禁判据**
  —— 今天 20 项门禁里查不出它，这才是真正要修的东西。

### 5. 两处"网口/AXI 输入不可信"的钳制缺失（`#127` 第 4、5 条，CANDIDATE）

- `src/rtl/eth/frame_reasm.v`：写地址由上位机字头里的 32 位偏移直接拼出，**从未被钳制**
  （偏移越界只护住了行位图）。仿真与硬件行为一致（不是 `#103` 那一族），但一个畸形片头能把数据写进帧中间。
- `src/rtl/axi/axi_frame_writer_gated.v`：`r_pix` 每拍加一无上限，超过约 `2^19` 像素后按位回卷。
- **现状诚实说法**：这两条**没有屏上现象**，也**还没有能数出机会的探针**，所以既不升格为缺陷也不注销。
  本项目的规矩是"先加机会计数探针，有非零再谈改"，否则"没现象"和"被门住了"两种说法不可区分。

## 二、性能与资源上没有做到的

1. **WNS 没有转正，也不承诺它转正**。走势是实测的：r84/r85 全局 WNS **−0.094 ns**、失败 setup 端点 **16**；
   r86 把诊断计数器的使能改喂寄存过的事件之后，失败端点 **16 → 2**、TNS **−0.747 → −0.243**，
   但全设计 WNS 变成 **−0.135 ns**——最差的换成了同一片 `u_cdc` 邻域的兄弟路（写使能 → BRAM 的 `ENARDEN`，7 级）。
   同一条路在两次构建之间实测摆 **0.4 ns**（放置抖动），**所以任何"WNS 提升 X ns"的说法在这颗器件这个规模上都不成立**。
   当前轮的绝对值只认 `build/reports/` 里那份 `timing_summary`，不认本文。
   还能用的杠杆只有两个：把 `dc_fifo` 的写使能寄存一拍（要先在整屏逐字节判据上证，因为它动数据通路），
   或者按物理口径动邻域（Pblock）。两者都还没做。
2. **UltraRAM 换帧缓存这件事不成立也不宣称**。已核实的只有：`ram_style` 给 `ultramark`/`ultraram`
   都被综合判为无效值（`build/reports/` 里那份 uram 探针输出）；**没核实**的是这颗器件有没有 URAM 站点
   —— 三次 Tcl 问法里**阳性对照没过，那个 0 不算结论**。对外只说帧缓存在 BRAM/分布式 RAM。
3. **端口过滤掉的包数还不是可读寄存器**。过滤逻辑进了顶层，三个统计脉冲没接出去 ⇒
   能演示"过滤生效"，不能读出"滤掉了多少"。
4. **`bad`（坏包计数）会动这件事只有台架证据**（入包链台架的 C2）。现场没有可靠的注错手段，
   所以板上只报"改前这个计数是死的、改后有判据"，**不报"板上见过它跳"**。

## 三、验证手段本身的边界（评委最常问、也最容易被含糊过去的一节）

| 边界 | 具体说法 |
|---|---|
| 只有一家仿真器 | 本机只有 **xsim**。早期可作第二意见的 ModelSim 已不在（许可证由新版 FlexNet 签发，自带客户端判 inconsistent）⇒ 凡是"两家仿真都过"的说法今天都不可复现。可复现的仿真路径只有 `sim/run_one.sh` 与 `build/gates.sh`。 |
| 仿真 ≠ 硬件的一类已知分歧 | 非打包数组的越界写：xsim 丢弃、硬件按地址位宽截断。`#103` 就是这么来的 ⇒ 本项目对这类问题**只用硬件读数收口，不用仿真通过收口**，并且专门有一条门禁判据检查"台架里有没有没被门住的越界读写"。 |
| 厂商原语的仿真模型是占位件 | `sim/prim/` 里是自建的行为级占位模型（`MMCME2_BASE`、`unisims_sim`）。跑 xsim 时看到的 OSERDESE2/BUFG 相关告警**来自占位件不是设计缺陷**，这是"仿真绿色"与"板上正确"之间必须说清的一段。 |
| 参考图不是自动生成的 | `data/golden/` 的对比图没有可一键重跑的生成脚本，只能人工比对 ⇒ 不说"与黄金参考逐像素一致"。 |
| 人眼判据是外部输入 | 屏幕上"有没有那条线"由队员判，智能体没有看屏幕的能力。凡是依赖人眼的结论，本仓库都记成"待眼睛"或"用户回报"，**不混进机器判据**。 |
| 位流与固件不入库 | 板子只走 JTAG（**不写 QSPI/SPI flash**：写了会把这台机器变成唯一能启动它的东西），所以 `bitstream/` 里那一份是**当场烧的那一版的副本**，靠 md5 认身份，不靠文件名。 |

## 四、已经修好并且是"用户报→量→修→用户复验"完整闭环的例子（对照用）

- **SD 播放中拔卡画面永久冻帧、插回不恢复（`#94`）**：根因是"这一路片源还在不在"这件事没有任何计时器，
  两个 `seen` 位只置不清 ⇒ AUTO 下"帧缓存里是什么就永远显示什么"。修法是给 PS 片源补心跳与清零条件；
  队员复测原话："拔下 SD 卡已经可以重新播放画面，并且串口也回应了这个自动重挂的消息"。
- **处理侧那条钉在显示列 320 的黑线（`#103`）**：见同目录的 LLM 协作记录（`docs/LLM_COLLAB.md`）例 1，完整六轮。
- **串口"打字重复/一大串空白"（`#132`–`#135`）**：见同一份文件例 3，结论是"错在我的工具，不是固件"。
