## 1. 项目一句话与整体架构

### 1.1 在做什么

PC 通过千兆网口，用 **UDP** 把 **512×300 RGB565** 视频推到板卡；**PL** 完成收包、协议解析、拼帧、图像处理、HDMI 双窗输出；**PS** 只做串口控制（效果开关、选源等）。

显示：HDMI **1024×600@50MHz**，左窗原图、右窗处理结果；右窗额外做 **无极缩放**（原始尺寸为最大，自动缩小再回到原始，循环）。

### 1.2 数据通路（自己画一遍更好记）

```
PC 上位机
   │  UDP 5001, RGB565, [u32 offset][payload]
   ▼
PL: RGMII → ARP/ICMP/UDP → frame_reasm(offset 拼帧) → frame_buffer(BRAM)
   ▼
显示读出: video_timing(1024×600)
   ├─ 左窗: rotate_mapper → FB 读 → 原图
   └─ 右窗: zoom_mapper(自动缩放)[+rotate] → FB 读 → 效果链 → 右窗
   ▼
OSD → HDMI TMDS

PS: UART 115200 → AXI GPIO → effect_en / threshold / src_sel
```

## 2. Zynq 是什么：PS 与 PL 的分工

### 2.1 概念

Zynq-7000 = **PS（Processing System，双核 ARM Cortex-A9）+ PL（Programmable Logic，FPGA 逻辑）** 在同一颗芯片。

| 角色 | 在本项目干什么 | 为什么不放到另一边 |
|------|----------------|--------------------|
| PS | 串口收命令，写 AXI GPIO | 协议解析、字符串处理用 C 更合适 |
| PL | 网口收包、拼帧、缩放/旋转/效果、HDMI | 每秒千万级像素，软件做不动实时 |

### 2.2 为什么不让 PS 收 UDP？

**试过/考虑过的方案：**

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| A. PS lwIP 收 UDP，DMA 进 PL | 软件协议栈成熟 | 协议栈延迟大、CPU 占用高、丢包恢复复杂 | 备份路径 |
| B. **PL 硬件协议栈（本项目）** | 延迟确定、CPU 空闲只做控制 | 协议要自己写/移植，调试难 | **采用** |
| C. 摄像头直连 PL，不用网口 | 无网络问题 | 竞赛/演示要「上位机推流」故事 | 不符合本题 |

**判断依据：** 初级组考察「基本 FPGA 设计能力」，把 ARP/UDP/拼帧放在 PL，更能体现硬件设计；同时 PS 控制面保留，体现软硬件协同。

### 2.3 AXI 是什么（够用即可）

- **AXI4**：高性能总线，本项目 HP0 用于 PL 访问 DDR（PS 诊断写帧时）。
- **AXI4-Lite**：寄存器级，本项目 **AXI GPIO @ 0x41200000**，PS 写控制字。
- **HP（High Performance）口**：PL 作 master 读写 PS 侧 DDR。

**替代方案：** EMIO GPIO、自定义寄存器经 GP 口。本板 **EMIO bank2 读回恒 0**，已踩坑，故固定用 **MIO/AXI GPIO IP**。

## 3. 时钟域：为什么不止一个钟

| 时钟 | 频率 | 来源 | 用途 |
|------|------|------|------|
| sys_clk | 50 MHz | 板载晶振 W17 | MMCM 输入、按键 |
| clk_pix | 50 MHz | MMCM OUT0 | 像素、效果、HDMI |
| clk_pix5x | 250 MHz | MMCM OUT1 | TMDS 5× 串化 |
| clk_200m | 200 MHz | MMCM OUT2 | IDELAYCTRL |
| axi_clk (FCLK0) | 100 MHz | PS | AXI、GPIO、HP0 |
| eth_rxc | 125 MHz | PHY RGMII | 千兆收包 |

### 3.1 为什么像素钟是 50 而不是 50.25？

1024×600 规格点钟约 **50.25 MHz**。用 50 MHz 误差约 **0.5%**，多数显示器可同步。

| 方案 | 优 | 劣 |
|------|----|----|
| **50 MHz（本项目）** | MMCM 整数分频简单，与板载钟同源 | 有 0.5% 偏差 |
| 50.25 MHz 精确 | 更符合 VESA | MMCM 配置更绕，收益小 |

### 3.2 MMCM 怎么配（本项目）

```
VCO = 50 MHz × 20 = 1000 MHz
OUT0 ÷ 20 → 50 MHz   (clk_pix)
OUT1 ÷ 4  → 250 MHz  (clk_pix5x)
OUT2 ÷ 5  → 200 MHz  (IDELAY)
```

**知识点：** 7 系列 MMCM 输入需在一定范围；VCO 要落在 datasheet 区间；输出 = VCO / CLKOUT_DIVIDE。

### 3.3 为什么 HDMI 要 5× 钟？

TMDS 串行：每个像素时钟要打 **10 bit** 到差分线上，用 **OSERDESE2 DDR** 在 **5× 时钟** 下双沿采样 → 10 bit/像素钟。

## 4. 以太网协议栈（PL 硬件）

### 4.1 分层（对照软件里的 TCP/IP）

```
RGMII 物理接口 (IDDR/ODDR, IDELAY)
  → GMII 字节流
  → ARP 请求应答（谁是 192.168.1.10？）
  → ICMP ping 回显
  → UDP 载荷 → frame_reasm
```

### 4.2 ARP：为什么必须做

PC 第一次发 UDP 前会 **ARP who-has 192.168.1.10**。若板卡不应答，PC 没有 MAC，包发不出去（或进不了交换机表）。

**实现要点：** 解析目标 IP → 回复自己的 MAC（本项目 `00:11:22:33:44:55`）。

**替代方案：** PC 静态 ARP（`arp -s`）。可作调试手段，但演示时别人电脑未必配置，**板端必须会回 ARP**。

### 4.3 RGMII 与 IDELAY

- RGMII：4-bit 数据 + 双沿（DDR）+ 125 MHz 时钟。
- 板级走线有时序偏差，用 **IDELAYE2** 调采样沿（本项目 IDELAY_VALUE=15）。
- REFCLK = 200 MHz 给 IDELAYCTRL。

**知识点：** IDDR 用 `SAME_EDGE_PIPELINED` 把双沿数据收到同一时钟沿上。

### 4.4 ICMP

ping 通是排查网络的第一步。硬件回显 echo request → reply，**证明 PHY/时钟/MAC 通了**，再谈 UDP 视频。

### 4.5 协议栈放在哪里的其他选择

| 方案 | 说明 |
|------|------|
| 移植开源 UDP stack（如 13_UDP_STACK） | 本项目参考其结构，验证过的代码更稳 |
| 全自己从零写 ARP+UDP | 学习价值高，时间成本大 |
| 只用 lwIP（PS） | 见 §2.2 |

## 5. UDP 帧重组与帧缓

### 5.1 协议格式

```
每个 UDP 数据报： [u32 小端 byte_offset][RGB565 载荷]
一帧字节数：512 × 300 × 2 = 307200
单包载荷：≤ 1396 字节（避开 IP 分片）
一帧约：307200 / 1396 ≈ 221 包
```

### 5.2 为什么用 offset 而不是「顺序流」？

UDP **不保证顺序、不保证不丢**。

| 策略 | 优点 | 缺点 |
|------|------|------|
| **按 offset 写（本项目）** | 乱序可拼对；丢包只花局部 | 协议头 4 字节 |
| 严格顺序 + 重传 | 画面完整 | 延迟大、状态机复杂 |
| 整帧一个大 UDP | 简单 | 必须 IP 分片，丢一片全帧废 |

**结论：** 竞赛演示「实时画面」，**坏帧丢弃、下一帧自动恢复** 比可靠重传更合适。

### 5.3 frame_buffer：为什么是 BRAM 随机读

- 写：ETH 按 offset **顺序/乱序** 写入。
- 读：显示扫描 + 旋转/缩放是 **任意坐标** → 必须 **随机读**。
- 双口 BRAM：写口 axi_clk，读口 clk_pix。

**资源：** 512×300×16b ≈ **2.34 Mb**，7020 BRAM 约 4.9 Mb → **放不下双缓冲**（4.68 Mb + 其他逻辑会超）。

| 方案 | BRAM | 撕裂 | 本项目 |
|------|------|------|--------|
| 单缓冲 | 1×2.34 Mb | 可能读写同一帧 | **采用** |
| 双缓冲 | 2×2.34 Mb | 无 | 资源不够 |
| 读 DDR | 少量 BRAM | 可双缓冲 | 带宽够，但延迟/仲裁复杂 |

### 5.4 为什么源分辨率选 512×300

| 分辨率 | 帧字节 | BRAM | 评价 |
|--------|--------|------|------|
| **512×300** | 307 KB | 2.3 Mb | **当前，余量足** |
| 640×360 | 460 KB | 3.5 Mb | 可升级，效果行缓也变大 |
| 1280×720 | 1.8 MB | 13.8 Mb | 7020 远不够 |

## 6. 视频时序与双窗显示

### 6.1 1024×600 时序数字（要背）

```
H_active=1024, H_fp=44, H_sync=88, H_bp=188  → H_total=1344
V_active=600,  V_fp=3,  V_sync=6,  V_bp=16   → V_total=625
像素钟 50 MHz → 帧率 ≈ 50e6 / (1344*625) ≈ 59.5 Hz
```

### 6.2 双窗怎么切

```
x ∈ [0, 511]    左窗
x ∈ [512, 1023] 右窗
cx = x 或 x-512   （窗内坐标 0..511）
cy = y >> 1       （垂直 2×：300 行源图拉成 600 行显示）
```

### 6.3 为什么垂直 2× 而不是信箱/裁切？

| 方案 | 观感 | 实现 |
|------|------|------|
| **垂直 2×（本项目）** | 源图上下拉伸，信息完整 | `cy = y>>1` 一行代码 |
| 水平也 2× | 512×300→1024×600，比例正确 | 源水平也要插值，和缩放功能重叠 |
| 信箱黑边 | 比例对 | 浪费像素，演示不饱满 |

右窗做无极缩放后，比例问题由缩放本身解决。

### 6.4 split_display / OSD

- 中间 **蓝线** 分隔左右。
- OSD：FPS / ANG / EN，注意空格字模不要画成「0」。

## 7. 坐标映射：旋转与无极缩放

### 7.1 核心思想：逆映射（Inverse Mapping）

显示扫描得到屏幕点 `(x,y)`，反算源图 `(sx,sy)`，再去 FB 读像素。

**为什么不用正向映射？** 正向（源→屏）会有空洞，还要散射/填充；逆映射每个屏点都有定义。

### 7.2 旋转（rotate_mapper）

```
xp = x - W/2
yp = H/2 - y          // Y 翻转到数学坐标
xr = ( cos*xp + sin*yp) >> 8
yr = (-sin*xp + cos*yp) >> 8
sx = xr + W/2
sy = H/2 - yr
oob → 填黑
```

- sin/cos 为 **Q8**（256=1.0），角度 0..359° 查 ROM。
- **cos(0)=256，绝不能饱和成 255**（否则恒等映射会错）。
- angle=0 时数学上就是恒等，但实现里仍可旁路以省符号运算。

**替代方案：**

| 方案 | 优 | 劣 |
|------|----|----|
| CORDIC 算 sin/cos | 省 ROM | 流水更长 |
| **ROM 查表（本项目）** | 简单、时序好 | 占一点 LUT/ROM |
| PS 算好角度表下发 | 灵活 | 实时改角麻烦 |

### 7.3 无极缩放（zoom_ctrl + zoom_mapper）

**需求：** 右屏以 **原始尺寸为最大**，自动缩小再回到原始，循环。

```
inv_scale (Q8): 256 = 1.0×（最大）, 512 = 0.5×（最小）
每帧 STEP=2，三角波循环

无旋转时：
  sx = W/2 + ((x - W/2) * inv_scale) >> 8
  sy = H/2 + ((y - H/2) * inv_scale) >> 8

inv>256 时边缘 sx/sy 出界 → oob 黑边（画面居中变小）
```

**可与旋转叠加：** 先缩放偏移，再走旋转 Q8 公式（线性变换可交换）。

**为什么不用 Algorithm 工程的流式 bicubic？**

| 方案 | 优 | 劣 | 本项目 |
|------|----|----|--------|
| 流式 bicubic（Algorithm） | 质量高、有双三次 | 依赖 divider IP、行推流，和 FB 随机读模型不同 | 源码参考 |
| **逆映射 + 最近邻 + 连续 inv** | 与时分 FB、效果链兼容，实现清晰 | 放大时像素块状 | **采用** |
| 逆映射 + 双线性 | 更平滑 | 单口 FB 一拍读不齐 4 邻域，要行缓/多口 | 预留 frac 口 |
| PS 缩放再送板 | 软件简单 | 无硬件加速故事，实时性差 | 否 |

「无极」在本项目指 **比例连续可变**，不是插值阶数最高。

### 7.4 左右窗 FB 读如何共用一个口

左右窗扫描 **时间上不重叠**：

```
左窗扫描时: FB 地址 = rotate(cx,cy)
右窗扫描时: FB 地址 = zoom(cx,cy)
```

用延迟后的 `left_pane` 选择地址。**知识点：** 单口存储 + 时分复用；延迟线要和 mapper 流水级数对齐。

## 8. 图像效果流水线

### 8.1 五级顺序

```
gray → binary → box_blur → sobel → invert
```

每级有 `bypass`；串口 `10000` = 只开 gray（左起 bit0）。

### 8.2 各模块在算什么

| 模块 | 公式/要点 | 为什么这么写 |
|------|-----------|--------------|
| gray | Y≈0.30R+0.59G+0.11B，用 `*77+*150+*29>>8` | 避免浮点，8-bit 定点 |
| binary | Y≥threshold → 白 | 阈值可调 TH80 |
| box_blur | 3×3 均值，`*57>>9` ≈ /9 | 除法用乘移位 |
| sobel | Gx、Gy 绝对值和，白边黑底 | 经典边缘 |
| invert | 255-通道 | 简单 |

### 8.3 3×3 窗为什么需要行缓

扫描顺序是逐行的。要得到 `(x,y)` 的 3×3，必须保留 **上两行**。

```
lb0: 行 y-2
lb1: 行 y-1
din: 行 y
```

**地址用屏幕坐标（目标域）**，这样任意旋转后窗滤仍正确。

### 8.4 效果挂在左还是右？

| 方案 | 说明 |
|------|------|
| 旧：左扫描时算效果写 line_cache，右窗再读 | 左右像素一一对应 |
| **现：效果挂在右窗缩放后的数据流** | 缩放 + 效果同时可见；左窗保持原图对比 |

**取舍：** 右窗效果作用在「缩放结果」上，左窗永远是原图（可旋转），对比清晰。

### 8.5 其他效果算法（没做的，了解即可）

- 高斯模糊（可分离核）
- 中值滤波（抗椒盐）
- 直方图均衡
- Sobel + 形态学

资源与行缓都会变大，初级组优先 **功能正确 + 可演示**。

## 9. CDC 跨时钟域

### 9.1 为什么必须处理

不同时钟域直接采样可能 **亚稳态**，数据错、状态机挂死。

### 9.2 本项目用到的手段

| 手段 | 用在哪 | 原理 |
|------|--------|------|
| **2FF 同步器** | eth_frame、fs_tog、GPIO→PL、vs_tick | 两级触发器降低亚稳态概率 |
| **Gray 码 + 双钟 FIFO** | eth_rxc → axi_clk 视频数据 | 指针每次只变 1 bit |
| **ASYNC_REG** | 同步链属性 | 让工具把两级放近，利于时序 |

### 9.3 为什么异步 FIFO 指针要用 Gray 码？

二进制计数可能多位同时翻转（如 0111→1000），另一时钟域采样会读到中间态。Gray 码相邻值只差 1 bit。

### 9.4 方案对比

| 方案 | 适用 | 本项目 |
|------|------|--------|
| 握手（req/ack） | 控制信号、低速 | 控制类可用 |
| 异步 FIFO | 数据流 | **视频包流** |
| 脉冲同步 | 单脉冲跨域 | frame_start 等 |

## 10. 时序约束与优化

### 10.1 基本概念

- **Setup**：数据要在时钟沿前稳定。
- **Hold**：沿后还要保持一小段。
- **WNS**：最差负松弛（负=违例）。
- **TNS**：所有违例松弛之和。

### 10.2 本项目关键约束

```tcl
create_clock -period 20.000 -name sys_clk [get_ports sys_clk]
create_clock -period 8.000  -name eth_rxc [get_ports eth_rxc]

set_clock_groups -asynchronous \
  -group [get_clocks eth_rxc] \
  -group [get_clocks -quiet clk_fpga_0] \
  -group [get_clocks -include_generated_clocks sys_clk]
```

**为什么要 `-include_generated_clocks`？**  
MMCM 产生的 `clkout0_1` 等在 XDC 早期解析时可能还不存在；挂在 `sys_clk` 上用该选项才能把生成钟一起标成异步，避免 eth→像素钟被误分析。

### 10.3 优化做了什么（结果见 report/OPTIMIZATION_LOG.md）

| 措施 | 效果 |
|------|------|
| 跨钟 false path / async groups | 消除假跨钟违例 |
| FIFO 存储去异步复位 → BRAM | eth_rxc 域内 WNS 转正 |
| rd_addr 打拍 + 移位加法 | 缩短 clk_pix 组合路径 |
| Bitstream COMPRESS | bit 体积约减半 |
| phys_opt | 关键路径自动优化 |

**最终：全局时序 MET（WNS≥0）。**

### 10.4 功耗怎么看

`report_power` 给 Total/Dynamic/Static。无开关活动仿真时置信度 Low，**相对比较**比绝对值更有意义。

## 11. 上位机软件

### 11.1 职责

- 源图像/视频 → 缩放到 512×300 → RGB565
- 按 offset 协议切 UDP 包发出
- 定时节拍控制帧率
- 串口发控制命令

### 11.2 为什么用 UDP 不用 TCP

| | UDP | TCP |
|--|-----|-----|
| 延迟 | 低 | 重传/拥塞导致抖动 |
| 丢包 | 应用层接受 | 自动重传 |
| 视频演示 | **够用** | 过重 |

### 11.3 RGB565 打包

```
r5 = R>>3, g6 = G>>2, b5 = B>>3
pix = (r5<<11) | (g6<<5) | b5   // 小端 2 字节
```

### 11.4 替代上位机形态

| 形态 | 优 | 劣 |
|------|----|----|
| **Python 脚本（本项目）** | 改参数快 | 需装依赖 |
| C++/OpenCV | 性能好 | 开发慢 |
| 浏览器 WebRTC | 部署难 | 协议不匹配 PL |

详见 `src/host/HOST_GUIDE.md`。

## 12. 软硬件接口：AXI GPIO 与串口

### 12.1 控制字（0x41200000）

```
bit[4:0]   effect_en  gray/binary/blur/sobel/invert
bit[15:8]  threshold
bit[16]    src_sel    0=彩条 1=DDR/ETH
bit[17]    zoom_en    （PL 默认常开；预留 GPIO 控制）
```

### 12.2 为什么串口命令在 PS 做

字符串解析、格式化打印在 C 里几行搞定；PL 做 UART 解码可以，但 **控制面放 PS** 是 Zynq 的标准分工，也符合竞赛「软硬件协同」。

### 12.3 裸机 vs Linux

| | 裸机 standalone | Linux |
|--|-----------------|-------|
| 启动 | 快 | 慢 |
| 驱动 | 直接写寄存器 | 设备树/驱动 |
| 本项目 | **采用**（控制极简） | 过重 |

## 13. 方案对比与取舍总表

| 决策点 | 本项目选择 | 主要备选 | 一句话理由 |
|--------|------------|----------|------------|
| 视频入口 | PL UDP 硬件栈 | PS lwIP | 实时 + 展示硬件能力 |
| 帧存 | BRAM 单缓冲 | DDR 双缓冲 | 7020 BRAM 够单缓冲，双缓冲不够 |
| 源分辨率 | 512×300 | 640×360 | BRAM 与效果行缓余量 |
| 显示 | 1024×600 双窗 | 720p 单窗 | 对比演示效果/缩放更直观 |
| 旋转 | Q8 ROM 逆映射 | CORDIC | 简单可靠 |
| 缩放 | inv_scale 逆映射最近邻 | 流式 bicubic | 与现有 FB/效果架构兼容 |
| 效果位置 | 右窗缩放后 | 左窗 line_cache | 缩放与效果可同时演示 |
| 控制 | PS UART + GPIO | 纯 PL 按键 | 软硬件协同 + 命令丰富 |
| 约束 | 异步时钟组 + CDC | 不约束跨钟 | 时序收敛的前提 |

## 14. 踩坑记录

1. **EMIO GPIO 读回 0**：本板 bank2 不可用 → 改用 AXI GPIO。  
2. **cos(0) 饱和成 255**：旋转恒等映射出错 → ROM 必须保留 256。  
3. **XDC 未覆盖 MMCM 生成钟**：eth→clk_pix 假违例 → `-include_generated_clocks sys_clk`。  
4. **FIFO 异步复位导致 RAM 推断失败**：大深度 FIFO 落到寄存器堆，125 MHz 时序崩 → 存储阵列同步写、无复位 + `ram_style=block`。  
5. **bat 脚本路径写成 sw/host**：实际是 `src/host` → 已改。  
6. **TCL `root` 少一级 `..`**：脚本在 `build/tcl` 时应 `join dirname .. ..`。  
7. **增量综合忽略约束变更**：改 XDC 后要删 incremental checkpoint 或 reset_run。  
8. **inv_scale=256 在 9-bit 有符号下是 -256**：缩放映射全错 → 用 10-bit 有符号表示 Q8 比例。  
9. **UDP 大包 IP 分片**：载荷控制在 ≤1396。  
10. **下载 bit 后必须再 Run ELF**：bit 配置会使 PS 复位，串口才有效。
