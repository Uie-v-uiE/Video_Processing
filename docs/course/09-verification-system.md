# 09 验证体系：原理 → 实现 → 取舍

这一篇不讲某一级电路，讲**"我怎么知道它对了"这件事是怎么被工程化的**。
交付物里所有"已验证"都必须能回答一句话：**哪把尺子、判了多少项、改前会不会红。**

## 1. 原理：四条纪律

1. **判据要有牙**：一条永远不可能红的判据等于没有判据。所以每一条新增判据都要配
   一个**能红的对照**（变异测试）：故意把被测对象改坏，看**只有**该红的项红。
2. **计数要数"做了多少次比较"，不是"通过了多少次"**：只数绿色的尺子会在射程缩小时
   看起来更干净。因此每把尺子都要打印自己的**比较次数/判定项数**，并配一条**下限地板**；
   读不到输入时报 `NOT_MEASURED`，不许报 PASS。
3. **豁免要能解释、要共用一套话术**：同一件事（例如"这个名字不是指路，是原文回显"）
   在两份尺子里必须用同一份词表，否则一边放一边判红，文档就永远对不齐。
4. **尺子的输出不许住在交付树里**：机器读数写进 `build/` 下的证据件，
   交付文档只**点名**它，不复制它（复制的那份永远不会因真代码改错而变红——
   与 `05` 里 `ddr_bank_commit` 抽成独立模块是同一个理由）。

## 2. 五层尺子各管什么

| 层 | 入口 | 管什么 | 读数怎么读 |
|---|---|---|---|
| 台架 | `build/sim/run_one.sh <tb>`、`build/tb98_report.sh` | RTL 行为对不对 | 判定行取**最后一个非空字段**；退出码 `3=台架自己判红`、`1=编译失败`、`4=认不出判定`（`build/sim/run_one.sh:42``） |
| 门禁 | `bash build/gates.sh` | 构建产物、端口、CDC、编码、文档时效、讲稿抽取…一次过一遍 | 结尾一行打印 `GATES: …（判定 N 项）`，**N 由脚本自己数**（`build/gates.sh:6-14`："这里不再写死条数，以本文件里 `say` 的调用次数为准"） |
| 交付形状 | `node build/deliver_spec_check.mjs` | 章程要求的目录/章节/长度/用词是否齐 | 打印"判 18 项 红=? 未测=?"，每项一行 |
| 文本一致性 | `src/host/doc_currency_check.mjs`（D1b/D1c/D3/D4）、`line_cite_check.mjs`（D5 行号锚点）、`metric_recheck.mjs`（D6 数字对账） | 文档说的"现在是哪一版/门禁几项几绿/这个数指哪份报告"有没有过期或指错 | 每层都打印"抓到 N 句"——**N=0 就是空转**，必须回头修尺子 |
| 终审 | `node build/checks/check_repo_consistency.mjs`（C1–C12） | 声明唯一权威源、指标指得到证据、路径存活、大小写、许可、状态一致、演练清单、证据时间线、失败可见、技能包门禁 | 每项一行带**计数**；`NOT_MEASURED` 会明说缺什么 |

`run_one.sh` 的编译口径值得单独看：它用 `find` 现算清单
（`build/sim/run_one.sh:64-65`：整个 `src/rtl` + `sim/tb_*.v` + `sim/prim`），
**不是手写名单**。手写名单会随目录变深而悄悄变窄（本工程踩过：顶层唯一的台架不在清单里，
报成一句看不懂的 `Cannot find design unit`）。找不到 `xvlog` 时它第一步就 `REFUSE`
并念出变量名（`:46-47`），不会让人对着 RTL 怀疑自己。

## 3. "能红的对照"长什么样（三个真实例子）

1. **门禁里的台架项**：`build/gates.sh` 的第 15 项要求 `tb_v98` 的报告与当前顶层
   **同一次跑**——头部两枚 md5（顶层源 + 台架源）与树里现值必须对得上，并且正文
   既没有 `FAIL ` 行、又有一行 `RESULT tb_v98_top_seam PASS`（两条都要）。
   今天这一项判红，红的是**公开声明的 `C5c`**（帧头那 6 行），不是构建身份。
2. **文本尺子的反买通**：`doc_currency_check.mjs` 的 `--self` 里有一组对照，
   验证"豁免只能由**同一行**的声明词换来"：有声明 ⇒ 不红、没声明 ⇒ **必须红**、
   隔行声明 ⇒ 仍然红。少了任何一条，说明这把握尺可能空转。
3. **计数守卫自己也要被验**：导出器里"数一个可能不存在的目录"的守卫，
   在 `set -euo pipefail` 下会被 `find` 的失败直接杀掉，REFUSE 那句根本来不及打印——
   所以新加地板时必须**同时验"目标不存在"这一支**会怎么表现（过程台账 `#371` 记的就是这一条）。

## 4. 名册（roster）：跨域比较唯一的合法形式

`build/tcl/probe_timing_roster.tcl` 生成逐时钟的 setup/hold 读数，产物如
`build/roster_r118_after_eth_rxc_setup.rpt`；差分要用 `build/timing_roster_diff.sh`，
并且**两边必须是同一生成器**（混口径会 REFUSE）。三条已经付过学费的口径：

- WNS 的绝对差**既不算收益也不算损失**（规矩 35），要写就写"仍收敛、瓶颈换没换域"；
- "最差那一格换了归属"要单独判：设计级 WHS 不变而** owning 时钟域**换了，是两回事（规矩 46）；
- 告警种类的数量要**当作成本**记账（`report_methodology` 的计数必须与它自己的
  `Checks found:` 对得上，整文件 `grep -o` 会把每一类多数一次）。

## 5. 三层证据链：眼睛、机器、板上

| 结论类型 | 谁能判 | 凭据形状 |
|---|---|---|
| 几何/协议/算术对不对 | 台架 | `build/tb_v98_report.txt`、各台架的 `RESULT …` 行 |
| 这一版能不能交付 | 门禁 + 终审 + 交付形状 | `build/rNN_gates.txt`、C1–C12 读数、`DELIVER-SPEC` 行 |
| 屏上好不好看、灰线看不看得出来 | **只有人的眼睛** | `board/acceptance.md` 的 E 条目（记原话、时间与当时状态） |

最后一行不是客套：本工程有过"机器全绿但用户眼里看到两条线"的记录，也有过一次
我把用户的眼 report 归因错的教训。**推荐做法**：由我驱动串口/读数、把读数写出来，
然后向用户问不超过三条"只问一个事实"的问题（"这一格现在显示什么"、"两条线是相邻还是分开"）。
眼睛判据**不代替**机器判据，二者也不能互相顶替。

## 6. 一轮改动的最小闭环（照这个顺序做就不会漏）

1. 读现状（报告/代码），把"要改什么、改了会红谁"写清楚；
2. **先在未改动的树上把新台架跑绿**（锚定：期望值逐行从现行代码推，不要凭印象——
   本工程两次被自己写的期望值判红）；
3. 改 RTL/文档；
4. 单元台架 + 顶层台架 + `bash build/gates.sh` + 四把文本尺子 + `check_repo_consistency`；
5. 上板：`build/r116_bit_cycle.sh <标签> [位流]`（复位 → PS 初始化 → 配 PL → 载应用 → 跑流 → 两次健康读回），
   再 `build/board_verify.sh --geom --battery --round=rNN`；
6. 采纳才写文档数字（`05`/`08` 那些读数的**唯一合法来源是盘上的件**，不是记忆），
   然后冻结与提交。

规矩还有两条硬的：**构建/台架在跑的时候不许改源码**（它会静默重新综合），
**后台任务还在读的文件不许改**（边跑边改会造出"文件中途语法错但 `bash -n` 全绿"的假现象）。

小结：这套尺子的设计目标是"想蒙它，它会当场红给你看"。每条判据的存在理由都可以还原成
一句回答：**它判什么、判了多少、怎么证明它没在空转。**
