# 06 效果链九级：原理 → 实现 → 取舍

## 1. 原理：一条链要同时满足三件互相牵制的事

显示通路上的处理必须做到：

1. **延迟固定**。屏幕上要做"同帧左右对比"（左半原图、右半处理图），两半必须是**同一帧的同一时刻**；
   如果处理链的延迟随开了哪一级变化，对比就变成"这半是上一刻、那半是这一刻"，看到的差异里混着时间差。
2. **窗口级会吃掉行**。3×3 的窗口需要上一行与下一行，任何"逐行推进"的流水线因此在垂直方向
   产生固定偏移。偏移必须**可预期且可补偿**，否则叠字与坐标会错位。
3. **算法要能单独关**。演示与取证都需要"只开这一级看看"，所以每一级都得有旁路，
   而且旁路必须是**逐位等价**（关了就和没插这一级一样），不能只是"结果差不多"。

## 2. 实现：`src/rtl/process/proc_pipeline.v`

文件头（`:2-7`）就把三件事的落地写清了：

```
级 0 gamma + 级 1..5 五个可选级（八个算法位 + 一个判决反相位），每级可逐位旁路。
输入 de/x/y/din 像素流，输出 de_out/dout；固定 15 拍延迟，与哪一级开、同级选哪个算法都无关。
内容偏移固定 −4 行、0 列：四个窗口级各贡献 −1 行，点运算级不贡献。
```

`stage_sel` 的位定义（`:5-6`）——**位序就是文档**，串口/上位机/RTL 三处共用同一张表：

| 位 | 含义 | 位 | 含义 |
|---|---|---|---|
| `[0]` | 灰度 | `[5]` | 二值化 |
| `[1]` | 反色 | `[6]` | 判决反相（**只有 `[5]=1` 才有意义**） |
| `[2]` | 3×3 模糊 | `[7]` | 腐蚀 |
| `[3]` | 3×3 锐化 | `[8]` | 膨胀 |
| `[4]` | Sobel | | |

`H_ACTIVE` 的口径是这一层最容易被误读的地方（`:9-14`）：它表示**一行有多少个有效拍**，
不是显示屏有多宽。顶层现在传 `#(.H_ACTIVE(2*IMG_W))` = **1024 个有效拍**
（"整屏单地址流"，r59b 定下），于是 **3×3 窗口的空间尺度按 1024 列算**：同级相邻两列在源上只差
半格 ⇒ 横向模糊/锐化/Sobel 的半径实际上是**半个源像素**。文件头特意写明"这是既成事实、
不是待评估的新风险"（旧版曾把它写成"若哪天改成 1024 会悄悄变两倍"，`#109` 改口的就是那句）。
想回到"一行 512 拍 = 源尺度"的等价喂法是**只在偶数列进链**（`de_in = de_d[3] && !x_d[3][0]`），
但动它之前要把 `#103` 那一族（坐标抽头与 `de` 同拍、行缓存写入时刻）一起重做。

## 3. 腐蚀与膨胀为什么互斥

```verilog
wire w_erode  = stage_sel[7] & ~stage_sel[8];   // :59
wire w_dilate = stage_sel[8] & ~stage_sel[7];   // :60
```

注释直接给出理由：**开运算/闭运算要两遍 3×3 窗口，这里只有一遍**，所以两位同时为 1 时
**两个都不做**（明确旁路），而不是"优先级谁压过谁"。这是一个很好的工程判断样例——
与其让非法组合产生一个没人能解释的画面，不如让它什么都不做，并把这件事写在位定义旁边。

## 4. 各级在做什么（按数据依赖分类，而不是按名字）

| 类别 | 级 | 依赖 | 垂直偏移 | 关键实现点 |
|---|---|---|---|---|
| 点运算（查表/取反） | gamma、灰度、反色、二值化 | 只看当前像素 | 0 | gamma 走 `gamma_lut`（见 `02`）；二值化带一个反相位位 |
| 3×3 窗口 | 模糊、锐化、Sobel | 上下各一行 | 各 −1 行 | 行缓存由链统一维护，所以偏移是**结构性**的、可预先补偿 |
| 形态学 | 腐蚀、膨胀 | 上下各一行 + 互斥 | −1 行 | 单遍窗口 ⇒ 只支持开或闭之一（`:59-60`） |

四个窗口级各贡献 −1 行，所以总偏移 −4 行且**与开关组合无关**。这一句是"延迟固定"能够成立的机制：
如果每一级各自决定要不要插一级行缓存，偏移就会随开关变化，同帧对比立刻失去意义。

## 5. 控制位从哪来：跨域同步器的"同一条链"纪律

`stage_sel` 由 PS 侧经 AXI GPIO 给出，进像素域要过同步器。真正的讲究不是"每位一条链"，
而是**必须同拍生效的位要走同一条链**（`src/rtl/process/effect_ctrl.v:33-34`：
"同一条链 ⇒ 同源同深度"）：

```verilog
input  wire [8:0] stage_sel_async,   // 唯一的控制字 gpio_cfg[8:0]（九级，一位一级）  :11
input  wire [2:0] zoom_sel_async,    // 同一个字的 [28:26]                            :12
(* ASYNC_REG = "TRUE" *) reg [12:0] sel_meta, sel_sync;   // {manual, zsel[2:0], stage[8:0]}  :34
(* ASYNC_REG = "TRUE" *) reg [7:0]  th_meta,  th_sync;                                  :35
```

三个要点，每条都对应一次真踩过的坑：

1. **打包成一条链**：`stage_sel`、缩放档号、手动/自动位被拼进同一条 13 位同步链
   （`{manual, zsel[2:0], stage[8:0]}`）。若各走各的链，两级同步的深度虽然相同，
   **采样时刻仍可能错开一拍** ⇒ 出现"效果位已经是新的、缩放档还是旧的"这种组合，
   屏幕上就是一帧谁都没命令过的画面（`:33` 点名 `#58/#59` 在防的那类错拍）。
2. **`ASYNC_REG` 必须写**：跨域入口的寄存器对不标这个属性，工具会把它们优化掉
   （合并/重命名到不同列），同步就名存实亡——`ISSUES #24/#49` 踩过（`:3`、`:29`）。
3. **阈值单独一条 8 位链**（`:35`）：它不需要和上面那些位同拍，所以按"要不要同拍"分组，
   而不是按"是不是同一个 GPIO 字"分组。

`gamma_async` 是**第二个控制字**的通道 2，位序 `{en, wr, data[7:0], idx[7:0], disp[5:0], temp_bcd[7:0]}`
（`:15`）——这就是 `02` 里那张 LUTRAM 表的写口来源。

## 6. 怎么验

```bash
VP_VIVADO_BIN=<Vivado>/bin bash build/sim/run_one.sh tb_proc_gray      # 点运算级
VP_VIVADO_BIN=<Vivado>/bin bash build/sim/run_one.sh tb_edge_rim       # 边缘条带（窗口级的边界行为）
bash build/sim/run_one.sh tb_v98_top_seam                              # 顶层：缝的位置、同帧性、各级开合
```

顶层台架里 C1g/C1h 那两条钉的是"视口列/行映射在标定级上必须与定义一致"，
这也是**为什么坐标抽头必须在标定那一级取**（`sim/tb_v98_top_seam.v` 的判据名可以直接读）。
判据行的读法同 `04`：取每行最后一个非空字段作为结论，退出码 3 表示台架自己判红。

## 7. 什么表现是"对的"，容易看成 bug

- **关了某一级，画面必须逐位等于没插这一级**。如果"关了但仍有轻微差别"，那是旁路实现错，
  不是量化误差。
- **整屏只有一个视口**。所以效果只出现在"处理图"那一侧（缝的右边），左半永远是原图——
  这是设计目的，不是"效果没生效"。
- **窗口级在画面顶/底边缘必然有边界行为**（缺上一行或下一行）。边缘条带由 `tb_edge_rim` 钉住，
  四条圈的读数在 `build/tb_edge_rim_r118.txt`。

小结：这条链的全部设计约束就是"延迟固定 + 偏移可预期 + 每位可旁路 + 每级互不共享同步链"。
其中"固定 15 拍"与"−4 行"不是巧合，是把窗口级的结构性代价算进预算后定的。
