# 工程教学文档（面向设计本身）

这套文档讲的是**这台机器为什么长这样**，不是讲谁在做什麼。每一篇的顺序都是固定的三段：
先把**原理**讲清楚（这件事在物理/协议/算法上要求什么），再看**本工程的实现**（哪个文件哪一行做了哪件事），
最后讲**取舍**（为什么不用另一种做法、它的代价是什么、什么条件下该改）。

所有结论都对过代码或凭据；每处引用写成 `文件:行号`，改一行代码就可能失效的引用，
用仓库自带的两把尺子复查：

```bash
node src/host/line_cite_check.mjs     # 行号锚点：文档点名的那一行现在装的还是不是那句话
node src/host/metric_recheck.mjs      # 数字对账：文档里的数指回它点名的报告
```

## 读法建议

按 `01 → 08 → 09` 的顺序读，能拿到"怎么造出来、怎么证明它对了"这两条主干；
只关心图像质量的从 `02 → 03 → 06` 进去；要接手网络那一段的从 `04 → 05`。

小结：这套文档的验收标准只有一条——照着它说的去读代码，读到的必须和写的一致；
不一致就是文档错，改文档。下一步：`01-一条命令到位流-Tcl构建.md`。
