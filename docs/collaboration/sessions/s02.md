# S02 · 以太网接收与帧重组

## 1 负责什么

把 RGMII 上的 UDP 报文变成“完整帧”的提交脉冲：MAC、ARP/ICMP、UDP 端口过滤、按帧内偏移重组、坏包与缺行处理。模型负责列条件和写台架，人负责定“什么才算一帧”。

## 2 模型做了什么

- 从 RTL 反推接收链的时钟域和握手：IDDR 采样、异步 FIFO、125 MHz 协议逻辑、AXI HP0 写 DDR。
- 起草帧提交条件：字节数到齐、所有源行被覆盖、本帧没有坏包。
- 为乱序、缺包、重复包、越界偏移写定向激励。
- 把“上一帧丢尾、下一帧丢头、中间静默”做成 A9 混帧场景，要求两帧不混、恢复后的第 3 帧仍能干净提交。

## 3 人拍板的部分

- 提交必须是“整帧字节数 + 行覆盖位图 + 坏包门”三件事同时成立；只看字节数会把缺行帧放进显示。
- A9 用 12 位预分频的 4 ms idle timer，不用一拍超时。
- 坏包计数按帧清零，不能把上一帧的 `p_good` 带到下一帧。
- 作废计数增长是诊断信息，不是“流坏了”的唯一判据；干净流下它不应增长。

## 4 修正

模型第一版把提交条件概括成“307200 字节到齐且没有坏包”，漏了行覆盖。台架也只检查字节数，所以在缺行实现上仍然是绿的。人把行覆盖位图加回判据，台架改成“字节够、只覆盖 3/4 行”的激励；把行计数改成“每写一个字加一”的变异体后，判据变红，恢复源码后变绿。

第二处是 `p_good` 的复位时机：最初按包清零，坏包之后的整帧仍可能被提交。改成按帧维护后，坏包帧被作废，下一帧从干净状态重新累计。
