# 已知限制与没做到的事（面向读者的一页）

这页只写**已经量到、或明确做不到**的事，每条给"限制是什么 / 为什么是限制 / 现在有什么 / 还缺什么"。
未决项的集中登记在 `report/90-open-items.md`；这里不重复编号，只给指路。

## 1. HDMI 源端合规：能给的是"离散"，给不了"眼图"

- **限制**：HDMI CTS 的 Source 侧 TP1 判据是**眼图掩模 + 抖动 + 占空比 + 边沿速率**，
  而且正式表格文本只发给 HDMI Adopter（NDA）。公开能引用的是规范正文与仪器厂商应用笔记的转述。
- **为什么不能写成时序窗**：`skew ≤ 0.20 Tcharacter` 是**单边的"离散上限"**，
  `set_output_delay` 表达的是**双边捕获窗**——把前者当后者绑上去，实测直接把三条数据道判成
  `−3.48 / −3.46 / −3.47 ns` 的"违反"（那是我的量纲错，不是设计错，ISSUES #335）。
- **现在有什么**：布线后逐脚实测 互对最差 **0.065 ns**（限 4.000 ns）、对内最差 **0.001 ns**（限 0.300 ns），
  凭据 `build/evidence/r119_window_check.txt`（含 5 份输入的现算 md5 头），口径与边界见
  `report/io/hdmi_tp1_sdc_measurement.md`。候选约束件默认**不进构建**（开关 `VP_R119_TMDS_WINDOW`）。
- **还缺**：眼图、抖动、占空比、边沿速率需要示波器/探头与合规测试治具 ⇒ `【未实测】`；
  板级走线（连接器/线材）对离散的影響也未单独量过。

## 2. PS 侧固件：这台机器不能重建 ELF

- **限制**：本机没有 `arm-none-eabi-gcc`，也没有 `python3` ⇒ `src/ps/` 的任何改动都**只能算源码改动**，
  不能说"板上已修好"。
- **现在有什么**：板上跑的 ELF 与位流同源，逐轮记录在 `board/`（`board_verify` 的凭据）。
- **还缺**：一条可复现的 PS 编译路径（要么装工具链，要么换 Vitis IDE 手工构建并留步骤截图）。

## 4. 复现路径不是全绿

- `docs/repro-check.md` 的逐条实跑读数：**PASS=91 / FAIL=30 / 未测=32**（终审 C9 判红）。
- 30 条 FAIL **没有逐条归因**：里面混着三类（命令写错 / 前置缺失（需要板子、需要串口、需要工具链）/ 文档指路过期）。
  在归因做完之前，本仓库不得宣称"第三方可以照抄复现全部结果"。
- 归因需要跑构建与上板 ⇒ 属于另一轮（本轮被禁止跑构建/仿真/上板）。

## 6. 命名合规没做完

- 全仓跟踪文件 **3601 个**，其中 **308 个路径含大写字母**（末段含大写 266 + 中间段含大写 45 − 两段都含的 3 = 308），
  惯例名（README/LICENSE/NOTICE/Makefile/.git\*）点名豁免 22 个 ⇒ 判据报 **违规=286**。
  逐段核对方法与第一次对账见 ISSUES #337；计数从 230 涨到 286 的原因是**本轮交付本身**：
  最近两笔提交新增 61 条含大写段的路径、删掉 1 条（`git diff --name-status HEAD~2 HEAD` 现算）。
  也就是说这一项会随着交付继续变差，只能靠改名裁决解决（Q-P21-2）。
- §3.3.5.4 要求纯小写 ASCII，但它自己给的推荐结构里也写着 `README.md` ⇒ 惯例名已点名豁免 20 个，
  其余要改名会断 `build/frozen_r*/MANIFEST` 的 md5 配对，属不可逆连带面 ⇒ 待裁决（`docs/questions-for-team.md` Q-P21-2）。
