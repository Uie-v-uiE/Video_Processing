# 从报告定位瓶颈并索要判据（提示词模板）

## 适用场景

- 时序违例或资源超标，需要判断是逻辑深度、布线、高扇出还是时钟树，而手上只有报告。
- 模型（或人）第一次读某种报告格式，字段名与列序靠猜。
- 症状：建议一堆，但没有一条能说明"改前会红、改后应该变成什么"。

## 使用方法

先查什么（优先级：厂商工具命令参考与报告字段说明 ＞ 应用笔记 ＞ 教程 ＞ 模型记忆）：
本工具出逐路径报告的命令与字段含义、拥塞与扇出字段的定义、报告是综合前/综合后/布线后哪一阶段。
**先跟用户确认**：能不能跑只读探针命令、可以读哪些产物目录、这一轮是否允许重跑一次实现换取读数。

模板（整块粘贴）：

```
角色：你是报告判读者。顺序固定为：确认形状 → 归类 → 收益上限 → 建议与判据。不许跳步。

【第 0 步，必须先输出这一句】
"我不确定报告字段的含义，请让我用一次只读探针确认形状。"
随后只给探针：若干条只读命令或只读查看动作（禁止任何写文件、改设置、重跑构建的副作用），
每条注明要看哪几列、期望看到什么字段名。在我贴回探针输出之前，不给任何结论或方案。

【我提供】
逐路径报告片段：【填入：含时钟网络段、每级 cell/net 延迟、逻辑级数、起点与终点寄存器、两侧时钟】
汇总报告：【填入：利用率、时序汇总（最差余量/总余量/失败端点数）、布线后拥塞与扇出摘要】
口径：【填入：各时钟域周期；标明这次比较是同周期还是跨周期，跨周期禁止比绝对值】

【归类：四类各答一遍，证据不足写"无法归类：<缺哪个字段>"】
A 逻辑深度 —— 支撑字段：逻辑级数计数、cell 延迟占总延迟比例、各级延迟是否随级数近似累加
B 布线主导 —— 支撑字段：net 延迟占比、最长单段 net 延迟、线长膨胀或拥塞等级
C 高扇出 —— 支撑字段：同一驱动在多条失败路径上重复出现、net 的扇出列、该网所在层的延迟集中
D 时钟树分量 —— 支撑字段：时钟网络段延迟、skew 与不确定度行、跨域时两侧时钟路径延迟
每条写成三行：字段名 → 我贴的哪一行的值 → 因此归该类。三者缺一按"未核实"处理。

【建议：最多 5 条，每条固定四行】
1 动作：<一句话，可执行、单变量>
2 收益上限：<只由我贴的字段算出的上界与算式；算不出就写"收益不可估"并说明缺什么>
3 改前会红的判据：<一条命令或字段比较式；写出"读到什么算红"，且它在当前实现上必须为红>
4 代价：<被牵连的其它路径域、资源项、覆盖面或检查器射程>

【禁止】
- 不给第 2 行就出现改 RTL 的方案
- 把绝对 slack 差当收益（跨时钟周期、跨工具版本、失败端点数不同都不可比）
- 引用我没贴给你的字段、行或数字
```

### 使用说明

喂什么：真实的逐路径片段 + 汇总片段（先只贴文本，别贴结论）；口径行写清周期。
期望回什么：第 0 步那句声明与探针清单在前；四类归类各带"字段→行→结论"；≤5 条四行建议。
怎么验收这次回答：（a）第 0 步那句没出现 ⇒ 整批作废重来；（b）任一归类点不到具体行 ⇒ 改判未核实；
（c）每条建议必须有第 3 行"改前会红"的判据形式（命令或比较式 + 什么算红），缺就只回
"只补各条第 3 行判据，其余不要重写"；（d）第 2 行为"收益不可估"时，该条不许进入实施队列。

## 失效条件

- **只贴了汇总页**：四类里 B/D 常无字段可支撑，"全部无法归类"是正确答案；此时补逐路径片段，
  不要诱导它猜——征兆是你重问一次得到不同的归类。
- **探针命令在你这版工具里字段名不同**：以探针实际输出为准重写归类；照模板里的字段名硬找会读空。
- **改后复跑时提取脚本按旧列序解析**：静默读出 0 条记录却被打成通过，是本条最贵的失效模式。
  先确认记录条数 >0 再谈收益。
- **收益上限按当前布线乐观外推**：接近收敛的布局下实际收益常小于上界，上限只用于筛掉
  "最多也救不回多少"的改动，不能当承诺值。
- 报告与源不是同一次构建产物（改了源没重跑）⇒ 归类描述的是一个已不存在的实现。

## 已验证效果

未量过，属建议。可复跑自查：探针清单的条数、四类中给出支撑字段的类别数（/4）、
带"改前会红"判据的建议条数（/总建议数，应为 1）、按判据实测在改前确实为红的条数（/同总数）。

## 来源

长自一类观察：报告字段形状靠猜导致判读错方向；以及采纳了"局部变好别处变差"的改动、
把绝对余量差当收益。相邻条目 localise-worst-path、fix-logic-depth、reduce-fanout-and-congestion、
global-timing-roster、bench-expectations-first（改前红要先在未改树上成立）。
