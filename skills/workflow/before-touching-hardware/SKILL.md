# 上板与外设操作的前置与禁区

低自由度条目：不可逆或当场不可解释的动作必须写成"命令 + 前置条件 + 应看到的读数"。
判断类的部分（这块值不值得修、该不该现在上板）仍是高自由度，不许伪装成流程。

## 适用场景

要把东西写进板子、从板子上读出东西、或要让旁人用眼睛确认它在工作时。
症状级触发：刷了没变化；串口打不开或开了不回显；板子看起来死了；改过板侧源码但手上没有编译工具链；
现场只剩几分钟。

## 使用方法

**动手前先查**（优先级：厂商用户指南/数据手册/接口规范 ＞ 应用笔记 ＞ 教程 ＞ 模型记忆）：
**本工具的官方流程页**——调试链的启动顺序与复位顺序在不同工具、不同接口（JTAG 类、片上调试器类、
直连 USB 类）之间并不相同，别把别的工具养成的习惯顺序套上来；
板级手册里配置存储、恢复镜像、唯一标识所在部件的位置与可写性；上位机侧每条命令的返回语义。
**先跟用户确认**：任何擦除/刷写/写标识（覆盖后现场不可复原）、需要断电重上的时机、
会改变外观或演示顺序的动作、动板载存储的具体分区与失败后果。

前置（按序做，各给"读到什么算不过"）：

1. **先确认板上现在的东西是谁**。刷写之前读回身份：位流/程序的身份读数（长度、校验值、
   版本寄存器、启动状态寄存器一类），与版本库里该轮记录的件比对。
   算不过：没读回、只凭记忆、读数落不到具体某个件 ⇒ 你既证明不了刷之前是哪个版本，
   也解释不了刷之后为什么是这个行为。
2. **调试链按官方顺序起**：先上电还是先接调试器、复位的先后、是否需要先连再复位。
   没查过本工具的官方流程页就不要动手。算不过：顺序靠猜；典型表现是"连得上但读不到"或"读到旧值"。
3. **访问口先独占**。串口/终端被别的进程占用时的表现：打不开；能打开但 0 字节不回显；
   能连上但全部字节被前一个进程收走。解法顺序：查哪个进程持有该口 → 关掉重复会话/监视脚本/
   上位机后台任务 → 重新开口 → 发一行看有无回显。仍不通 ⇒ 判 `NOT_MEASURED`，
   严禁把"打不开"写成"板子没跑"。
4. **断电重上能解与不能解**。能解：状态机卡死、软件死循环、外设挂在全局状态、
   重载位流把处理侧楔死这一类。不能解：配置内容或恢复镜像本身坏了、唯一标识写坏、
   以及**访问口不可达这一类——只有断电重上（或重新刷配置）才回得来，别先折腾软件**。
   断电前先跟用户确认时机。
5. **没有固件编译工具链时**：改了板侧源码就只能写**"源码级改动"**，
   并在结论里明写"板上未修，读数不可得"。算不过：提交信息或文档里出现"已修复"却没有任何板上读数件。
6. **板载存储默认禁区**：配置字、恢复镜像、唯一标识、出厂校准一类默认不写。
   要动需用户**明确同意**，且一次一事（说清动哪个区、能否恢复、失败后果）；写前先读回留备份，
   写完立刻读回核对。算不过：没有确认记录，或写完没读回。
7. **演示现场的眼睛判据要配方**，不是"看着正常"。每条配方给：确切命令 + 前置条件
   （板上刷的是哪个件、上位机连的哪个口、要不要先跑一条准备命令）+ 应看到的读数，
   并且**每个"不达标"分别意味着什么**：完全无输出=访问口/占用问题；有输出但值不对=件不对或没加载；
   值对但画面不对=下游通路；间歇性坏=时钟或复位余量。配方落盘为文本件，现场照做，别现推。

结论一律三态 `PASS / FAIL / NOT_MEASURED`，结论行最后一个字段是判定词，`判 N 项` 记比较次数而不是通过数。

## 失效条件

- **工具在飞时改脚本**：位流生成/刷写/读回正在跑就编辑同一份脚本 ⇒ 在飞那次用的是旧文本，
  产物与源对不上；而你随后"验证"的却是新文本。征兆：日志时间戳在改动后不再增长，
  或产物内容与最后一次保存的源不一致。要么等它结束，要么在隔离拷贝里改。
- **把"命令返回 0"当状态已改变**：多数命令只表示请求已发出。必须有独立的读回状态。
  征兆：所有绿都建立在退出码上，没有一个读数来自板子本身。
- **把用户一次授权当永久授权**：同意擦一次某区不等于以后都能擦；同意今天动存储不等于整个演示期放开。
  每次禁区动作前重新确认，并把确认记在这一轮的记录里。征兆：文档里出现"上次已经同意过"。
- **身份读数在版本库里找不到对应件**（件没随包） ⇒ 第 1 步作废：仍然无法回答"板上是谁"，
  先补落件再刷。
- **眼睛判据配方在换过工具或上位机版本后未复跑** ⇒ 配方自己可能已经红，现场照做只会更慢。

## 已验证效果

未量过，属建议：本条按通用上板纪律整理，没做过带/不带的对照。
三个可自查读数：刷写前身份读回与库内件是否一致（应为"是"，否则 `NOT_MEASURED`）、
每轮结论中来自板子的独立读数条数（应大于 0）、禁区动作的用户确认记录条数（应等于禁区动作条数）。
