# 钟网改动前后的检查清单

低自由度条目：每条都给"怎么验、应看到什么"。判据一律改前改后同一支只读脚本、同一份 DCP 形状。

## 适用场景

- 把 I/O 采样钟从全局缓冲树挪到 I/O 专用短树（或反向）、加减一只 MMCM/PLL 副本、换缓冲类型、给某个钟重新源化。
- 新建一只钟或改钟名（名字会进后续所有点名约束的射程）。
- 改动之后 setup 余量"莫名"变大、`check_timing` 的未约束端口数突然变小、某一域 hold 变好而数据路径没动 ⇒ 先怀疑覆盖面丢失，不是收益。
- 需要判断这是"等价替换"（同一批消费者、同一套检查覆盖面）还是"换了一棵树顺带换了口径"。

## 使用方法

1. **改前把钟网结构落件**：`report_clock_networks`、`report_clock_utilization`、`report_utilization`（缓冲/原语计数）、时钟对象清单（`get_clocks *`）。记三类：计数、缓冲类型、**域归属**（哪批负载吃哪棵树）。改后跑同一支脚本 ⇒ **逐行差分**，不是看两个总数像不像。应看到：能指出"哪一行变了、变成什么"；指不出就是没验。
2. **机制判据先于结果判据**：结构证据要能红。副本树计数（例：某树上 mmcm/iddr/bufg 各几）必须与主树那一份**配对**读，并当场配正对照（主树侧必须能判红）。计数没动 ⇒ 写 `MECHANISM_INERT`，不许写"收益不成立"。
3. **三条点名该钟的约束逐条复查是否还生效**（重源化会静默丢覆盖面；这是本项目记过的最大一笔账）：
   - `set_clock_uncertainty`：新钟在带子覆盖之内吗？用 before/after 读数证明"写了且吃了"。
   - `set_clock_groups`：派生钟要不要 `-include_generated_clocks`。漏这一侧 ⇒ 它被当独立钟与别域做 setup（WNS≈−6.7 的假违例形状）；反过来组排除过头 ⇒ 那批跨域路从所有尺子的射程里消失。
   - `set_input_delay -clock`：参考钟的名字还指得到当初那个沿吗？另加 I/O 延时档与参考钟的关系。
   - 验证用报告而不是 grep 源文件：`report_clock_groups`、`report_exceptions`（含 ignored）、`check_timing -verbose`。一条命令一个对象，绝不并名——一个取不到的名字会让整条命令空转，现场只留一句 warning，`-quiet` 压不住命令本身。
4. **缓冲类型换了 ⇒ I/O 单元里的延时补偿要一起退回去重设**：不同树的偏斜不同，采样点位置随沿挪动；I/O 延时的档值是**与那棵树配套的**，只换一边等于沿挪了而采样点留在原地。应看到：一份"新树偏斜 + 重设后的档值"成对读数，且它算出的采样位置与报告自己的 `Clock Path Skew`／SCD−DCD 对得上。
5. **只驱动本地区域的缓冲不是全局树的等价替换**：先用 `report_clock_utilization` 的区域表数出下游负载落在几个时钟区，再确认"能不能全留在同一区"；I/O 专用短钟在很多架构里只喂 I/O 单元、喂不到 fabric ⇒ 下游流水线必须换结构（加一级同步），否则这一刀不适用而不是"不划算"。
6. **负相移≠沿提前**：两件事都要实测——工具把相移归一化成什么波形（某版把 −225° 读成 `rise@3.000`，即按周期取模后的另一个相位），以及时钟路径延迟实际把沿挪了多少（报告里的 SCD/DCD 与 `Clock Path Skew`）。挪沿在 hold 与 setup 之间是**同一恒等式里的交换**，不是白捡；不许由相移度数直接推收益。
7. **结构改动必须走正式一轮**：只重跑布局布线的捷径（同一份 `opt.dcp` 单变量滚）能验方向、能定噪声底，但**改不了综合出来的钟网**；加减缓冲原语、换源、改 I/O 结构都属于要重新综合那一类。快车道读数标明"机制证明，不是官方数"，采纳以正式构建为准。
8. 先跟用户确认：是否允许多一只时钟原语/多占一只全局缓冲、是否允许动 I/O 结构与延时档值（会挪采样点，演示可见）、是否允许新钟名（名字进后续所有点名约束）、这一刀要不要连带改约束文件。

## 失效条件

- 工具版本不同，报告字段与选项集不同 ⇒ 形状靠猜必错。先读报告头与前几十行确认列位；解析失败按 `NOT_MEASURED`，不许当 0 行通过。征兆=某行突然恒为 0 或 NA。⚠ **NA ≠ 空转**：某域在一张表里显示 NA，可能只是负载挂在别的栏目上；误判成"又一棵空转的树"要付一轮账。
- 跨构建的放置噪声掩盖真实变化：不同构建之间 0.4 ns 量级的摆动很常见（"某域 0.516→0.363"落在噪声里就不可主张）。同 DCP 重跑作对照滚（某棵树标定过空白重跑逐位复现，噪声底 0.000 ns），且对照滚必须**逐格复现上一版官方名册**，才允许把实验滚的差值归因给这一刀。
- 把覆盖面丢失当成时序收益。征兆：未被检查的端口/时钟对数减少、某域余量变大而该域数据路径未动、`report_timing_summary` 的时钟间表行数变少。
- 只读顶层控制台会把机制读成没动：实现 run 自己打印的行落在 run 目录的日志里，两个出水口都要读，且自己算闭合等式。
- 约束里点名"实现阶段才存在"的钟 ⇒ 那些命令只在实现场景加载；放进综合也加载的文件等于每次一条空约束。
- 本清单不判"这一刀该不该采纳"：它只保证你没把口径变化念成收益；采纳口径走逐域名册那套。

## 已验证效果

以下读数来自某一次具体设计，量级只用于说明形状，随设计而变，不可当普适结论引用。

- 结构刀按结构记账（不按数字）：把 I/O 采样钟从两棵不同的树收成同一棵之后，最差那族 hold 的时钟偏斜 **+1.616 ns → 同树内 0.013–0.349 ns**，`BUFIO` 用量 **1→0**（结构判据），而 WHS 数字没变好（+0.051→+0.037，最差挪到另一个域）。真正的收益是**消除了"每次重建掷 ±1 ps 硬币"这个机制**；念成"改结构没用"或念成退步都是错的。配套动作：I/O 延时档值同时从 **15 改到 26**（第 4 条的形状）。
- 覆盖面丢失那一刀的完整账（判负）：副本树机制判绿（`mmcm=1/iddr=5/bufg=1`，主树 `mmcm=0`，正对照当场红），setup 侧买到 **+0.759 ns**、未约束端口 **11→6**，但 hold 侧 WHS **−2.126**、THS −10.552、5 个失败端点 ⇒ 窗没关住；且那 +0.759 里约 **0.67 ns 是"约束作用范围被削弱"换来的**（那条 hold 不确定度带不再覆盖派生钟）。产物是一页清单：新建或改名一只钟之后逐类重查不确定度、时钟组、输入延迟参考钟、I/O 延时档与参考钟的关系。
- 相位口径的实测（第 6 条）：报告自己的时钟偏斜 主树 **5.008** vs 副本树 **5.919** ⇒ 那把"把沿提前"的刀实际把捕获沿**推迟了 0.911 ns**，相移被 MMCM 与缓冲自己的网络延迟吃掉还有余。
- 归因前提的量：同 DCP 空白两滚逐位相同（噪声底 0.000 ns）；对照滚逐格复现上一版官方名册 ⇒ 才允许把三域 +0.033／+0.187／+0.298 与第四域逐格不动写成刀的效果。
- **未量过，属建议**：改由另一只缓冲驱动某只派生钟后，其余域 hold 是否受新树偏斜影响（只在被改的那一域量过）；I/O 专用短钟的快时钟角延迟分量（慢角有数、快角没量回来，因此"换短钟也关不掉"这句话不许写）。

## 来源

- 长自五类观察：① 换钟后三条点名该钟的约束静默失效，"覆盖面丢失"被当成时序收益；② 只换了钟树、没退 I/O 延时补偿；③ 把负相移当成捕获沿提前；④ 用跨构建的差值归因（落在摆幅里）；⑤ 报告字段形状靠猜，把 NA 误判成"某棵钟树空转"。
