# 多判据门禁跑批器（三态 + 判 N 项 + 比较数地板）

## 适用场景

- 一个改动要同时过结构、位宽、覆盖、报告读数等多条判据才允许采纳，逐条手跑会漏、会记错退出码。
- 各判据自己 exit 0/1，拼在一起时分不清"红"和"没跑成"，于是把"没测到"当成通过写进结论。
- 判据越加越多，没人说得出这一轮到底做了多少次比较、哪条其实是恒绿的空转。
- 需要 `--only` 单独重跑某一条来归因，但又不希望"没匹配上"被当成过了。

## 使用方法

```bash
node scripts/run-gates.mjs --dir <判据目录> [--only <id 或文件名>] [--set key=value]...
node scripts/run-gates.mjs --self
```

判据件形状（一个文件一条判据，按文件名顺序跑）：

```js
export const ID = 'width-bound';                       // 可选；不写就用文件名当 id
export function run(ctx) {
  const ok = ctx.cmp('count ≤ 上界', value, (1 << width) - 1, '<=');   // 每调一次记一次比较
  return { id: ID, detail: `字段=${n} 全在上界内=${ok}`, verdict: ok ? 'PASS' : 'FAIL' };
}
```

跑完应看到（对夹具 `fixtures/gates` 的实测读数，故意含 1 红 3 未测）：

```
判据目录 gates：件=5 跑=5 顺序=文件名字典序
width-bound      比较数= 2 PASS          字段=2 全在上界内=true
row-overlap      比较数= 2 FAIL          A/B 不相交：实得=false 期望 == true ｜ 区间数=2
vacuous-green    比较数= 0 NOT_MEASURED  比较数=0 的"通过"不作数（真空通过防护）…
bad-verdict      比较数= 1 NOT_MEASURED  判定词「OK」不在 PASS/FAIL/NOT_MEASURED …
crash-gate       比较数= 0 NOT_MEASURED  抛异常（没跑出判定）：读输入件时炸了（合成）
判 5 项 红=1 未测=3 FAIL
```

**三态纪律（采纳门槛就按这张表写）**：

- 退出码 **0 = 全绿可采纳**；**1 = 有红，不许采纳**；**2 = 没红但有未测，不许写"通过"，只能写"未覆盖到"**。
  红优先于未测：同一次跑批里既有红又有未测 ⇒ 退出码 1，但未测数照样印在结论行里，不能被红盖掉。
- 结论行 `判 N 项 红=R 未测=M <token>` 里的 **N 是做了多少次比较**，不是通过多少条。
- 每条判据**必须打印自己的比较数**；**比较数为 0 的"PASS"自动降级为 NOT_MEASURED**（防真空通过）。
- 判据件顶层不许有副作用（跑批器会 import 整个目录）；`--only` 命中 0 条、目录里没有件 ⇒ 一律 NOT_MEASURED。
- 采纳口径要写成"判 N 项 红=0 未测=0"三个条件同时成立，而不是"退出码 0"一句话——
  退出码 2 的改动不是被否决，而是**没被证明**，得先补判据或补台架再谈采纳。

**先查什么**：判据要能在被改动对象上真取到数（报告/表格/读回的字段名与单位以一手资料为准），
先确认每条判据"从哪取数、和什么比、比不过是什么后果"，写不出这三样就不配进门禁。
**先跟用户确认**：判据目录与命名（谁有权往门禁里加件）、`--set` 传哪些工程参数、
哪些判据是硬门槛（红即否决）、哪些只做提示、失败时是否允许豁免（豁免必须留名并计入未测）。

## 失效条件

- 跑批器只管**编排**，不判"这条判据本身对不对"：比较的期望值抄错，全绿也是错的。征兆是判据的期望来自记忆而不是文档。
- `ctx.cmp` 的账只统计经它发出的比较；判据里自己 `if (a > b) return 'PASS'` 而不走 ctx ⇒ 比较数虚低，
  该条会被降级成未测（这是保护，不是 bug），但作者常误读成"判据没过"。
- `--only` 只跑你点的那条，别的没跑 ⇒ 结论只对你点的那条成立；别把 `--only` 的输出当整道门禁的结论归档。
- 判据件 import 有副作用（连板、写文件、起进程）会污染整轮 ⇒ 顺序看着对但读数不可复现。
- 目录里没有 `.mjs/.js`、或件都叫 `*.test.js` 之外的名字被过滤掉 ⇒ 报"件=0 ⇒ 未测"，别读成"门禁过了"。
- 比较数地板只挡"0 次比较的通过"，挡不住"1 次无关紧要的比较"；判据强度要另用覆盖维度核。
- 判据抛异常按 NOT_MEASURED 记，不当红：崩溃不是被测对象错，是尺子没跑成——先修尺子再谈结论。

## 已验证效果

`node scripts/run-gates.mjs --self` 实跑读数（退出码 0）：

```
S1 全量跑批：三态齐、红优先 ⇒ 退出码 1 退出码=1 判=5 红=1 未测=3 空转降级=是 PASS
S2 执行顺序=文件名字典序（跑批顺序可复算） 顺序=width-bound,row-overlap,vacuous-green,bad-verdict,crash-gate PASS
S3 --only 命中 1 条 ⇒ 判 2 项 红=0 未测=0 PASS 且退出码 0 退出码=0 判=2 结论=PASS PASS
S4 恒绿但比较数=0 ⇒ 降级 NOT_MEASURED 且退出码 2 退出码=2 判=0 未测=1 PASS
S5 --only 命中 0 条 ⇒ NOT_MEASURED（不许"没匹配上就算过"） 退出码=2 结论=NOT_MEASURED PASS
S6 空判据目录 ⇒ NOT_MEASURED（空门禁不等于绿） 退出码=2 件=0 PASS
S7 判据抛异常 ⇒ NOT_MEASURED 并带异常文本 退出码=2 未测=1 说明=有 PASS
S8 --only 也认文件名（不逼你记 ID） 退出码=1 红=1 PASS
判 21 项 红=0 未测=0 PASS
```

夹具：`fixtures/gates/01-field-width.mjs`（2 次比较的真绿）、`02-row-overlap.mjs`（真红）、
`03-vacuous-green.mjs`（恒绿但 0 次比较 ⇒ 必须被判未测）、`04-bad-verdict.mjs`（包外判定词）、
`05-crash.mjs`（抛异常）。未量过：真实门禁上"跑批器省下的漏判条数"没量过，属建议。

## 来源

长自"多条判据各自退出码打架、把没测到写成通过、门禁常绿但说不出测了什么"这一类观察；
三态与计数地板的完整口径见 verify 类的 `three-state-verdicts`；每条判据自带 `--self` 与变异对照的要求见
verify 类的 `checker-selftest`；恒绿判据与真空通过的形态见 pitfalls 类的 `ruler-fake-greens`；
覆盖维度要同现的要求见 verify 类的 `mutation-controlled-coverage`。用条目名互相引用，本条不要求先加载它们。
