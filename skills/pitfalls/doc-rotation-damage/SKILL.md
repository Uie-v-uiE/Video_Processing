# 批量改口对文档的伤害

"把口径统一改掉"是最容易把好文件改成坏文件的操作：它一次动几十处文本，而人只检查自己记得的那几处。
下面八条按改前—改中—改后排，每条给可执行的排查顺序与"读什么"。

## 适用场景

- 一次改名/换口径要落到所有文档、清单、注释、提交信息。
- 写了脚本做批量替换，或让模型"把所有 X 改成 Y"。
- 改完发现行数、表格形状、可复制的命令任一不对劲。
- 不适用：只改一处措辞、能肉眼通读全文的小改。

## 使用方法

动手前先查一件事：这批文本里哪些行**会被执行**（命令行、脚本片段、构建规则、代码围栏内），
哪些**只给人读**，哪些是**表格**——三类改法不同，混用是大部分事故的来源。
先跟用户确认：口径本身（改哪个词、是否涉及对外表述、是否影响演示顺序），以及是否允许一次动多个文件。

### ① 替换串比匹配串短，段落被截断

触发：规则形如"把带前缀的整句换成短词"，匹配串吃掉了锚点头部。
现象：段落从半句开始，前一整句消失；文件行数变少；只看命中行的 diff 看不出问题。
排查：1) 改前逐文件记下行数与字符数；2) 改后先读这两个数，任何净减都立即停下；
3) 只读每个命中行的上下各三行，确认段落首字是一句的开头；4) 把整段重读一遍（不靠 diff）。
根因分类：规则层——把"找到 A 换 B"当成无损操作，没约束长度方向。
修法：每条规则加断言"结果字符数不减少、行数不变"，断言不过整条规则回滚，不做局部修补。
预防：批量替换先 dry-run，打印每条规则的命中次数与净增/净减字符数，看过再落盘。

### ② 可运行的命令与表格被顺手改坏

触发：同一条规则既作用于正文行也作用于命令行/表格行，把注释性文字插进行中间，或在行尾加标记。
现象：命令复制到 shell 就报错（中间多了一句人话）；表格行列数对不上而散架；围栏内代码语法坏。
排查：1) 先把待改文本按行分三类（可执行/表格/正文）并打印每类行数；2) 对可执行类逐行读，
确认插入内容只出现在行尾或注释符之后；3) 对表格类数每行的分隔符个数，改前后必须相等；
4) 真跑一遍被改过的命令，看是否仍然可复制即运行。
根因分类：行类型不分——把整篇文本当同一种介质。
修法：分类处理：命令行只在行尾追加，表格行不加任何行内标记，只有正文行允许内联替换。
预防：规则表里给每条规则标注"适用行类型"，脚本按类型分派；分派不到的行宁可不改。

### ③ 行号与位置引用集体漂移

触发：文档用"见第 N 行""上面第 M 条""文件开头第三段"这类坐标式引用，而这次改动增删了行。
现象：所有位置引用一起错位，但每句读起来都通顺；只有照着去找的人才发现指错。
排查：1) 搜出全部形如"第…行/行附近/第…条"的引用并打印条数；2) 逐条读引用处的上下文，
问"目标还能只靠文字找到吗"；3) 改完重跑锚点检查器：它对每条引用检查其后是否出现指定的语义锚点串，
打印命中数与未命中清单；4) 未命中清单非空就逐条读那段文本。
根因分类：引用形式——用不稳定坐标而不是稳定文本当引用目标。
修法：把每条位置引用改成"以某短语为锚"，并保证该短语在文中唯一。
预防：文档里禁写行号；锚点检查器与改口脚本绑在同一次运行里，未命中数不为 0 就不算改完。

### ④ 被点名的文件改名或删掉了，文档还在引

触发：一次改口同时做措辞替换与剪枝（改名/删除文件），两个动作来自两份手抄清单。
现象：交付检查报死引用；或反过来把还在用的件剪掉；两处清单都对不上盘上实际。
排查：1) 先跑一次"文档点名件是否在盘上"的检查，记下红条数；2) 读代码确认剪枝清单与改口清单
是否由同一张表生成；不同源就停手；3) 逐条读被剪/被改名件的每一个引用方，确认改口侧也有对应条目；
4) 改完再跑第 1 步那次检查，红条数必须为 0。
根因分类：动作不同源——两套清单必然漏。
修法：一份清单两个动作：同一行同时产出"改名/删除"与"引用替换"，谁都不能单独执行。
预防：清单落成一个可被脚本读取的表，改口脚本与剪枝脚本都从它读；禁止出现第二份手抄。

### ⑤ 命名风格转换把正则当字面量（或反之）

触发：脚本做驼峰/下划线/大小写互换，输入里既有普通名字也有含元字符的串（点、星、方括号、美元符）。
现象：`a.b` 这种字面串被当模式解释，匹配到不该匹配的名字；含元字符的名字反过来整体不命中。
最坏的一种：初始化/默认值那一行被转错，编译与运行都不报错，只是行为变了。
排查：1) 读脚本里每个转换调用，确认入参有没有显式转义；2) 把每个含元字符的名字单独过一遍转换函数，
打印输入与输出对照；3) 专门读默认值/初始化相关行，与文档里对应描述逐轮核对是否同步改了。
根因分类：转义层级错 + 默认值路径漏改。
修法：转换函数按用途拆两个（字面量版、模式版），调用处显式选择；默认值的改动单列一张清单。
预防：给转换函数配一个含元字符的夹具用例，跑不红就算不上线。

### ⑥ 提交信息里的引号把文字当路径执行

触发：多行提交信息用内联引号交给 shell，消息里含反引号、双引号、`$`、尖括号或路径。
现象：命令报"找不到文件"；消息少了整段（被当命令替换执行掉了）；极坏情况执行了本不该执行的东西。
排查：1) 读版本库里**实际记录下来**的那条消息全文（不是你以为发出去的那串）；
2) 在消息原文里搜反引号与 `$(`，命中即怀疑被求值；3) 读你用的提交命令，判消息是内联参数还是文件参数。
根因分类：引号层级——把要原样呈现的文本当 shell 参数而不是数据。
修法：多行消息一律写进临时文件，用"从文件读消息"的接口提交；临时文件本身不进交付包。
预防：所有"要原样显示"的长文本（消息、报告片段、含引号的命令）都走文件参数，不走内联引号。

### ⑦ 改口那次本身要改的数字，同时是被别处引用的数

触发：一次改动把"判据有几条/比较几项"的定义改了，而这个数字在别处被抄进句子。
现象：定义处是新数，引用句还在念旧数；两处语法都通顺，纯文本检查查不出来。
排查：1) 搜出所有出现该数字的句子并打印条数；2) 逐条读，确认与当前定义一致；
3) 读结论行里"判 N 项"的 N，与实跑时真正做过的比较次数对齐；4) 有任何一处不一致，整轮结论退回重写。
根因分类：数字靠人抄而不是靠表生成——文本引用不是代码引用。
修法：条数与所有引用它的句子在**同一次提交**里改完；能由表生成的数字一律生成。
预防：数量词只允许出现在一处权威表里，别处用条目名/表名引用而不是复述数字。

### ⑧ 标签宽度与列名是判据的一部分

触发：改动落到表格列名、对齐宽度、结论行的字段顺序或标签拼写，而解析器就按这些定位。
现象：解析读不到字段 ⇒ 检查器输出空 ⇒ 空被念成通过；人看到的报告"没问题"，机器那侧其实没取到值。
排查：1) 读检查器源码，确认它按名字、列序还是列宽取字段；2) 用改后的样本跑一次，
看读到的字段数是否为 0；3) 跑一次变异对照：把一个已知字段名故意改错，判据若不变红，说明它本来就没在读；
4) 读检查器的退出码与末位判定词，确认空集被报成 `NOT_MEASURED` 而不是 `PASS`。
根因分类：判据耦合到格式；空集未三态化。
修法：格式与解析在同一次改动里一起改；解析失败一律 `NOT_MEASURED`。
预防：任何动表格/标签的改口都归入"会动判据的改动"，强制自带一个正例夹具与一个变异反例。

## 失效条件

- 八条都假设改动以**行为单位**落盘。若这次由工具整篇重写（格式化器、生成器、翻译脚本），
  行数与列宽断言都不成立，只能改前改后做全文结构化比对。征兆：diff 显示整文件重写。
- 对生成物与二进制件（报告快照、自动生成的头文件、位流），行数/字符数断言无意义，
  要看内容哈希与"能否由同一条命令复现"。
- 没有第二人或第二把尺子复核时，"我只改了记得的地方"这条直觉不可靠：本条只降低概率，不消灭事故；
  关键口径仍应逐文件通读一次。
- 源码看着没坏但渲染坏了：表格宽度、行内代码、锚点在另一种渲染器下形状不同。交付形态换了就要重跑一次检查。

## 已验证效果

未量过，属建议（没做过带/不带本条的 A/B）。可复跑的读数形式：
每条规则 dry-run 的命中次数与净字符增减；每文件改前后行数差（应为 0）；
锚点检查器未命中条数（应为 0）；死引用检查的红条数（应为 0）；
"判 N 项"的 N 与实跑比较次数之差（应为 0）。任一读不到记 `NOT_MEASURED`，不许念成绿。
