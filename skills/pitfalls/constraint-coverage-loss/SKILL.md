# 约束射程静默收窄

约束工具的语言是"按名字点人"。名字一改，被点的那个对象就消失了，而工具**通常不报错**——
它只是少约束了一些东西，报告于是好看起来。本条的全部内容是：把"射程"变成可打印的数。

## 适用场景

- 时钟改名、换源、把直连时钟改成派生时钟，或调整时钟树结构之后。
- 改了端口名、引脚分配、层次名，或增删了顶层端口。
- 时序/资源报告出现"没有代价的收益"，需要证明它不是覆盖面丢了。
- 不适用：完全不涉及命名与约束的纯功能改动（但改名那刀依然要走第⑤条）。

## 使用方法

动手前先查（优先级：厂商约束手册/用户指南 ＞ 应用笔记 ＞ 教程 ＞ 模型记忆）：
本工具"按名点名"的约束各自要求时钟/端口已经存在还是容许后建、派生时钟的名字与来源怎么写、
约束文件的加载顺序与忽略规则、以及有没有现成的"列出当前所有已约束对象"的报告命令。
先跟用户确认：改名是不是对外接口的一部分（端口名、引脚、上位机可见契约会影响别的队伍一侧），
以及这一轮是否允许为拿到读数而临时多跑一次报告。

核心动作只有一个：**每条按名的约束都留下"命中数"这个读数**，改前改后各打一次，差值不为 0 就必须解释。

### ① 时钟改名/重新源化后，点名该钟的约束静默失效

触发：一个时钟被改名或换了来源，而不确定度、时钟组、输入延迟这几条约束是按老名字写的。
现象：这几条约束一条都不再作用于任何对象；工具只给信息级提示甚至完全沉默；
WNS/TNS 忽然改善，被当成收益写进结论——实际是覆盖面没了。
排查：1) 把当前约束文件里所有"提到时钟名"的行抽出来，按名字分组打印条数；
2) 用工具的时钟列表报告打印实现后**实际存在**的时钟名集合；3) 逐个名字做交集检查，
打印"约束里写的名字"与"实际存在的名字"两份清单的差；4) 对每一条点名约束跑一次"它约束了几个对象"的读数，
改前改后对比，命中数从 N 变成 0 的那条就是本案；5) 再看时序报告的路径起点/终点时钟域是否还覆盖原来的域。
根因分类：命名耦合 + 工具对未知名字的宽容。
修法：约束与 RTL 的时钟名在同一次改动里一起改，改后立即重跑第 3、4 步并把命中数写进记录。
预防：把"改钟 ⇒ 逐条按名回查并打印命中数"写成钟树改动清单里不可跳的一步（见 `clock-tree-changes-checklist`）。

### ② 一条命令里一个取不到的名字，让整条命令空转

触发：一条约束命令同时点多个对象（一串时钟、一组端口、多个引脚），其中一个名字不存在。
现象：整条命令一条都不生效，而不是"少约束一个"；报错级别常常低于错误。
排查：1) 读那条命令的对象列表，数一共点了几个名字；2) 对每个名字单独跑一次"是否存在"的查询，
打印逐个命中/未命中；3) 把命令拆成一个对象一条，重跑后再看命中数是否恢复到对象数；
4) 看实现日志里那一行有没有被跳过的痕迹。
根因分类：批量命令的失败语义是"全有或全无"，而人以为它是"逐个尽力"。
修法：每条约束命令只点一个对象；对象多时在流程脚本里循环生成，逐个可追溯。
预防：把"命中数 = 应约束对象数"作为一条门禁，空转在门禁层红，而不是靠人看日志。

### ③ 派生/生成时钟不在覆盖面里

触发：源头改成 PLL/MMCM 派生，或新增倍频/分频/同相错相时钟，而约束只点名主输入时钟。
现象：穿过寄存器时钟输入的路径完全没有被约束过；报告里这些端点显示为"未约束/零窗"；
主时钟那侧的数字很漂亮。
排查：1) 打印实现后所有时钟的名字与来源，逐个标注是输入时钟还是派生时钟；
2) 对每个派生时钟查它有没有对应的不确定度、组关系与 I/O 窗约束；3) 读约束写法：派生钟是否需要
显式声明"由哪个钟、按什么关系生成"，还是工具会自动推导（自动推导不代表自动被点名）；
4) 检查器若按时钟名过滤，确认过滤清单包含派生名，而不是只有主输入名。
根因分类：覆盖模型按"输入"建模，而实际按"钟"计数。
修法：用显式声明派生时钟及其关系的写法，让每个派生钟都能被按名点名；把派生名加进所有点名约束。
预防：判据按"实际存在的时钟数"生成而不是按名字抄；数量地板不为 0，见第⑦条。

### ④ 约束写在被忽略的文件里，或文件里写了条件语句

触发：新增的约束文件没进工程加载清单；或在约束文件里用条件判断/打印这类只在交互模式下才成立的写法。
现象：文件明明存在、内容明明对，报告却说该端口/该钟未约束；条件分支静默跳过，后面的行也不再执行。
排查：1) 读工程/流程里"哪些约束文件被加载、顺序如何"的那份清单，逐条核对文件名与盘上真实路径；
2) 打开被怀疑的文件读第一处条件写法，确认该方言在这里是否被支持；
3) 在实现日志里搜该文件名，命中 0 次就是根本没被读；
4) 临时在该文件第一行放一条一定会留下痕迹的约束，跑一次看它出现在报告里吗。
根因分类：加载链路断 + 语言子集被误用（约束文件不是通用脚本）。
修法：把文件挂进加载清单并排在正确顺序之后；约束文件里只放声明式约束，条件逻辑上移到生成它的脚本。
预防：新增约束文件必须同一次改动里在"已加载文件列表"报告中出现；把该列表打印进记录。

### ⑤ 端口/引脚改名让按引脚名写的约束落空

触发：改了顶层端口名、重排了引脚分配，或把某个接口挪到另一个物理管脚。
现象：输入/输出窗约束找不到目标端口；电气属性、时钟基准管脚一类按物理名的设置没生效；
综合不报错，实现阶段的未约束检查才隐约露出。
排查：1) 打印顶层端口名清单与约束里点名端口的清单，取差；
2) 打印约束里出现的物理管脚名与分配表里的管脚名，取差；3) 对每个 I/O 约束逐条问"它绑的是端口名还是管脚名"，
改名时两侧是否都改了；4) 跑一次未约束端口/引脚检查，打印条数并与上一轮比较。
根因分类：同一实体有两个可被点名的名字，改了一个另一个还在被引用。
修法：改名一次覆盖两侧（RTL 端口与约束/分配），改后立即重跑第 1、2 步。
预防：任何改名先跑"按名点人的清单"全集扫描（约束、台架层次路径、报告提取字段、上位机常量）。

### ⑥ 未约束端口不报错，只在检查里点名

触发：新加端口忘了约束，工具只把警告/未约束清单写进报告而不终止流程。
现象：交付的时序数字覆盖不到那个接口；"报告里没有 FAIL"被读成"没问题"。
排查：1) 跑未约束端口/未约束时钟检查，读出条数；2) 逐条读该端口是否真的需要约束——
内部常量、不穿越边界的、单向扩散量、被时钟组覆盖的，各有各的理由；
3) 对确实不需要的，读交付文档里是否写了"为什么没有这条约束"；4) 对需要但没有的，补约束后重跑第 1 步。
根因分类：判定与告警分离；把"没被点名"当成"已满足"。
修法：每个未约束项要么补上，要么在交付文档里逐条给理由，形成"未检查≠满足"的可读证据。
预防：把未约束条数作为门禁项之一；条数下降必须在差分记录里给出解释。

### ⑦ 手写文件清单当射程，目录一变深就失效

触发：检查器用一份人工维护的"要扫哪些文件"清单来确定覆盖范围，而目录结构后来变深/新增子目录。
现象：新文件从未被扫，检查却全绿；扫到的文件数悄悄下降；问题不在文件里而在射程外。
排查：1) 读检查器如何取待扫文件：读清单常量还是现场遍历目录；
2) 打印本次实际扫到的文件数，并与"同条件下遍历目录应得的数"比对；3) 分层打印每层命中数
（根、每个子目录各多少），看是否与目录现状一致；4) 读该判据有没有"文件数地板"，地板为 0 时等于没判。
根因分类：射程用快照表达，而快照会过期。
修法：射程由遍历现算（含深度、忽略规则），并把每层计数与一个非 0 地板一起打印。
预防：任何"扫了多少"的判据都必须自带计数地板与逐层计数，缺一项就按 `NOT_MEASURED` 处理。

### ⑧ 用"某个搜索没命中"证明问题不存在

触发：结论是"我 grep 了 X，没有命中，所以没有 X 问题"。
现象：搜索确实为空，但那行代码所在分支根本不可达（条件恒假、开关未打开、文件未被加载、宏未定义）。
排查：1) 先证明可达：读进入该分支的条件在实现后被求成什么（常量传播结果、参数/开关实际值、生成文件里的实参）；
2) 读那段的编译/综合日志，确认相关源文件被读入、相关实例被保留而不是被优化掉；
3) 把搜索模式自身做变异对照：改用一个**已知存在**的串跑同一个搜索，必须命中；
4) 若分支不可达，则本次搜索不构成证据，结论要改写为"未测"。
根因分类：证据的否证力来自"位置被读过"，而不是"搜索跑过"。
修法：在结论旁边同时写"可达性证据"（源文件被读入、实例未被优化、分支条件的实际值）。
预防：所有以"搜不到/清单为空"为根据的判定，都要求一次正对照命中才允许写 `PASS`。

## 失效条件

- 本条假定工具按名点名、且对未知名字宽容。若你的流程把未定义对象直接当错误终止，
  ①②的症状会表现为红而不是静默，排查步骤仍适用但"命中数"读数要换成日志里的错误行。
- 命中数只能证明"被点到了"，不证明"作用得当"：约束存在但被后来的同类约束覆盖、或被工具忽略
  （属性不支持该器件、时序组与该路径无关）时命中数照样好看。此时要看报告里该对象的实际生效值。
- 时钟列表、未约束清单这类读数依赖具体报告格式；换了工具版本字段名会变，检查器先要能读到再判。
- 若一轮里同时改了名字和逻辑，命中数恢复但时序仍变化，不能只凭本条归因，要拆刀逐刀量。

## 已验证效果

未量过，属建议（本条是排查顺序，未做带/不带的对照）。判定形式统一：
每条点名约束打印命中数，改前后差值应为 0；派生时钟的"被点名数 = 实际存在钟数"；
扫描类判据打印"每层文件数 + 计数地板"；"搜不到"类结论附一次正对照命中数（应 > 0）。
结论行末位只允许 `PASS / FAIL / NOT_MEASURED`，空集与读不到一律第三种。
