# 探针自己骗你：网表查询与报告解析的七坑

## 适用场景

- 脚本查网表/读属性/解析报告，结果"该非空却空、该报错却静默"，你正要据此下结论。
- 第一次给某类报告写提取器，字段形状靠猜。
- 同一功能换工具版本后，原来查得到的名字查不到了。
- 不适用：纯写约束、纯改源的动作；那类活由改前清单管，不归本条。

## 使用方法

**先查什么**（优先级：厂商用户指南与该命令的内置帮助 ＞ 应用笔记 ＞ 教程 ＞ 模型记忆）：属性名的权威出处是该版本命令帮助与对象类文档；报告形状的第一手是盘上那份报告文件；引脚/端口名的第一手是本次综合出的网表与引脚报告。
**先跟用户确认**：改动既有脚本的名字约定、报告字段口径、输出落点前先问；只读探针可直接做。

总则——"查出来空"只有三种成因，每坑排查步骤都按此分流：
命令报异常⇒**工具报错**；命令正常返回但集合大小=0⇒**空集**；返回非空而你要的值取不到⇒**解析错**。
空集与解析错一律记 NOT_MEASURED，禁止折算成"不存在"或"通过"。

### 坑一：按名字过滤网表对象，某些工具版本读回空集

- 触发条件：用短名/正则过滤对象做查询；该版本检索域要求当前作用域或完整路径。
- 现象：不报错、返回空集。三类错误结论全从这来："对象不存在""引脚没连接""时钟没被约束"。
- 排查步骤：1) 拆两行，查询后单独打印集合大小。查询句报异常⇒工具报错，先修语法与名字形态；2) 大小=0⇒空集，先别下结论：换完整层级路径（顶层实例一路到叶）重查并打印大小，非 0⇒检索域问题，空集是查询侧的；3) 仍为 0⇒在同一时刻的网表/报告文本里搜该名：搜不到⇒对象确不存在或已被优化掉；搜到⇒解析错（转义分隔符、大小写、层次命名形态不对）；4) 修通后保留"size>0 断言+打印大小"，并用已知存在的对象做正对照复跑一次。
- 根因分类：查询语义随版本变；空集是查询的正常返回，不是"没有对象"的证明。
- 修法：一律用完整层级路径查询；每次查询紧跟集合大小打印与非空断言，断言失败非 0 退出并记 NOT_MEASURED。
- 预防：脚本模板把"查询+打印大小+断言"绑成固定三连；换工具版本第一件事跑正对照。

### 坑二：属性不存在与"值为空"混淆

- 触发条件：读某属性返回空；该属性在这个对象类上根本没有（有的对象类才有，有的实现后才生成）。
- 现象：把空当"值为空"，得出方向性错误的结论。
- 排查步骤：1) 打印返回值长度：非 0 而字段取不到⇒解析错；2) 用列属性命令单独问该对象"有哪些属性"：在册且值为空⇒值为空；不在册⇒属性不存在（记 NOT_MEASURED 并写原因）；列属性本身报错⇒工具报错，对象拿错了；3) 读命令帮助确认该属性适用的对象类与生成阶段。
- 根因分类：空有两个来源（没属性/有属性无值），返回值上不可分辨。
- 修法：读属性先问存在性再取值，两种状态分开记录。
- 预防：建"对象类×属性"的实测小抄，别假设某属性到处都有。

### 坑三：一次取不到名字的命令整条空转，但仍返回 0

- 触发条件：按名字点对象的批量命令里有一个名字不存在或阶段不对。
- 现象：退出码 0，日志里该有的创建/应用条数没出现。
- 排查步骤：1) 打印该命令的作用计数（应用/创建了几个）：0⇒空转；命令报异常⇒工具报错；2) 在日志里找"0 个匹配/skipped"字样确认；找不到计数行⇒解析错；3) 用已知存在的单个对象最小化重跑做正对照：非空⇒是名单问题。
- 根因分类：退出码只表示命令合法，不表示命中数。
- 修法：每条按名命令后加计数断言，计数 0 即非 0 退出。
- 预防：结论行强制带"判 N 项"，N=0 记 NOT_MEASURED。

### 坑四：报告字段/形状靠猜

- 触发条件：凭印象写解析器——摘要行在第几行、百分号里的数当什么量。
- 现象：解析"成功"但取值永远是同一个数，或静默取空。
- 排查步骤：1) 先跑一次短探针：打印报告前若干行原文、表头行与每行字段数——只打形状不取值；2) 报告文件不存在或为空⇒工具报错（没生成/路径错）；3) 表头有但字段数与假设不符⇒形状与猜不同；表头都在而提取仍空⇒解析错；4) 解析器改为断言表头字段名存在、按字段定位而非行号。
- 根因分类：报告形状随版本与选项变化；记忆不是现场。
- 修法：解析前先打印形状；取不到⇒NOT_MEASURED。
- 预防：每写一类新报告的解析，"形状探针"是固定第一步。

### 坑五：引脚/端口名按记忆写

- 触发条件：脚本里硬编码引脚、端口、信号名；同一功能在不同版本命名不同。
- 现象：过滤/解析取不到，结果为空。
- 排查步骤：1) 在盘上实测件里搜该名（网表文本、约束、引脚报告三处对质）：搜到异写⇒写法/解析错；搜不到⇒名字不存在或已被改名；读件命令报错⇒工具报错；2) 对比脚本字面量与实测拼写：分隔符、大小写、转义符；3) 替换后用已知存在的对象做正对照确认非空。
- 根因分类：记忆或二手模板替代一手实测件。
- 修法：名字常量从本轮实测件生成，不写字面量。
- 预防：脚本从"实测名单文件"读名字。

### 坑六：脚本里写了会被运行时控制台编码破坏的字符

- 触发条件：脚本含非 ASCII 字符（中文注释、全角引号），运行时控制台编码与文件编码不同。
- 现象：语法检查过、运行报未知 token；判定词变乱码匹配不上。
- 排查步骤：1) 读报错指向行的原文，再按字节查文件（十六进制视图）：字节与运行时显示不一致⇒编码链坏；一致⇒是语法/逻辑问题而非编码；2) 核对判定词与字段名是否全 ASCII；3) 换全 ASCII 版本复跑对照：恢复⇒坐实编码问题。
- 根因分类：文件编码→控制台码页→重定向，任一环节不一致即毁字符。
- 修法：机器可读 token（判定词/字段名/标记）只用 ASCII；中文仅出现在注释与面向人的行。
- 预防：脚本入仓前跑"关键 token 含非 ASCII"检查。

### 坑七：交互式工具的临时目录与 shell 的临时目录不是一个地方

- 触发条件：shell 在自己临时目录写中间文件，工具脚本（或反向）读同名文件。
- 现象："刚写的文件找不到"，或读到上一轮的旧件。
- 排查步骤：1) 在工具会话内打印它用的临时根，在 shell 里打印自己的：不同⇒两处为不同目录坐实；2) 对目标文件查真实路径与修改时间：读到旧件⇒路径歧义；找不到⇒写错了侧；读写命令报错⇒工具报错；3) 改显式路径复跑对照。
- 根因分类：两个"临时目录"是两个地方，同名不同件。
- 修法：跨侧传文件用显式约定的项目内路径，不靠临时目录默认值。
- 预防：脚本把读写目标的全路径打印进日志。

## 失效条件

- 本清单只管"查询/解析得到空结果"的骗术；结果非空但值错（阶段拿错、把综合期报告当实现期读）不在射程，征兆是数值方向合理却归因不了。
- "打印集合大小"只适用于返回集合形态的命令；返回标量/字符串的改用长度或存在性判断，征兆是 size 类命令本身报错。
- 非空断言证明不了"命中的就是你要的那个对象"：不同作用域同名会假过，需再对身份属性（库单元/完整路径）复核。
- 属性名、报告形状都是版本相关事实，本条只给排查法不给名单；照抄任何"别处的属性表"就违背本条精神。
- 编码问题在文件编码恰与码页一致时不复现，换台机器即复发——不复现不等于不存在。

## 已验证效果

未量过，属建议。可自查的读数：正对照对象首查的集合大小（应非 0）、带非空断言的查询占全部查询之比（应为 1）、判定 token 中非 ASCII 计数（应为 0）。
