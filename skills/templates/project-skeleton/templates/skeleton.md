# 工程目录骨架模板

> 用法：整份复制进工程根当起点。所有可变处写成形如 `【填入：…】` 的占位；
> 替换完后全文搜索一次左方括号，剩余数应为 0。目录名可以按上游要求改，
> 但"六区分职责 + 第 3 节三条约定"不要改——那是本骨架唯一被复用的部分。

---

## 1. 目录

```
【工程根】/
├── src/
│   ├── logic/          # 设计源：算法/状态机/数据通路（含生成的 IP 描述）
│   ├── constraints/    # 物理约束：引脚、电平标准、时钟、时序属性、区域
│   ├── host/           # 上位机侧：调用封装、批处理、台架脚本
│   └── board-app/      # 板侧应用：跑在处理器上的程序与其依赖清单
├── sim/
│   ├── tb/             # 测试台（一个被测对象一个）
│   ├── vectors/        # 激励与期望（成对存放，命名对齐）
│   └── run.sh          # 一键跑全部用例，产出 sim.txt
├── build/
│   ├── 【构建脚本们】  # 分步脚本：综合 / 实现 / 位流 / 打包
│   └── reports/        # 所有工具报告的落点（一律文本格式）
├── board-ops/
│   ├── 【刷写脚本】     # 把产物写进板子（含前置检查与回滚口）
│   ├── 【探活脚本】     # 板级在线判活 + 可观测量上引
│   └── 【读写脚本】     # 寄存器/存储的写后读回
├── deliverables/
│   ├── metrics/        # 指标表：资源 / 频率 / 吞吐，一张表一个口径
│   ├── golden/         # 黄金参考：比对的基准数据（同目录放生成命令）
│   └── evidence/       # 凭据件：命名带轮次标识的落盘读数
└── docs/
    ├── spec.md         # 说明：做什么、边界、接口契约
    ├── reproduce.md    # 复现：与第 2 节清单一一对应的命令序列
    └── open-issues.md  # 未决项：没量过的、需要人确认的
```

每区的三句话（照着填，填不出来就说明这个区不该存在）：

| 区 | 放什么 | 不放什么 | 谁读它 |
|---|---|---|---|
| `src/logic` | 【填入：本轮会改的设计源类型】 | 工具生成的中间件、报告 | 设计与评审 |
| `src/constraints` | 与物理相关的一切 | 与逻辑相关的默认值 | 时序复核 |
| `src/host`、`src/board-app` | 各自的源与依赖清单 | 对方的源（两边只通过接口契约相连） | 联调 |
| `sim` | 用例、激励、期望、跑批脚本 | 手工"看起来对"的截图 | 自查尺子 |
| `build/reports` | 工具直出/转存的**文本**报告 | 只有二进制日志 | 指标采集、差分 |
| `board-ops` | 可重放的板级动作脚本 | 一次性手敲的、没记下来的命令 | 现场演示、复核 |
| `deliverables` | 指标表、黄金参考、凭据件 | 与交付无关的草稿 | 评审（只看这里） |
| `docs` | 说明 / 复现 / 未决项 | 任何绝对位置 | 陌生人 |

## 2. 一条命令能重建（最小清单）

判据：**陌生人照这张表能从零重建出全部交付数据**。写不出"产出哪个报告"的行删掉。

| 命令（相对工程根） | 它做什么 | 产出哪个报告（相对位置） | 跑完应看到 |
|---|---|---|---|
| `【填入：build/clean.sh】` | 清掉上一轮的生成物，避免旧件冒充新读数 | 无（只在终端确认清单） | 报告目录为空、mtime 归零 |
| `【填入：build/synthesize.sh】` | 读入 `src/logic` + `src/constraints`，出逻辑综合结果 | `build/reports/【填入：synthesis.txt】` | 文本件存在，头部命令与本命令行一致 |
| `【填入：build/implement.sh】` | 布局布线 + 时序/占用报告 | `build/reports/【填入：implementation.txt】`、`…/utilization.txt` | 两个文本件、余量与占用可读 |
| `【填入：build/make-bitstream.sh】` | 生成可刷写的产物 | `build/reports/【填入：bitstream.txt】` + 产物本体 | 产物带版本号/时间戳，能被下一步引用 |
| 【填入：`sim/run.sh`】 | 跑全部用例 | `build/reports/【填入：sim.txt】` | 用例行数 = 用例数；三态判定齐 |
| `【填入：tools/collect-metrics.sh】` | 从上面几份文本报告抽资源/频率/吞吐 | `deliverables/metrics/【填入：metrics.md】` | 表里每行都能反查回某份报告 |
| `【填入：tools/gate.sh】` | 多判据门禁跑批（三态 + 判 N 项） | `build/reports/【填入：gate.txt】` | 红即非 0 退出，不静默 |
| `【填入：board-ops/flash.sh】` | 刷写 + 读回身份 | `deliverables/evidence/【填入：短名_轮次标识_序号.txt】` | 读回的身份与仓库产物对得上 |

约定：**任何一条命令失败都不许手工补产物**——补出来的件不在清单里，复现演练必红。

## 3. 三条约定（本骨架的硬部分）

| 约定 | 写法 | 破坏了会怎样 |
|---|---|---|
| 报告统一落文本格式 | 工具能出文本就直出；只有二进制日志的，在同一落点转存一份同名文本；件头三行自带：命令、工具版本、时间戳 | 下一轮拿不到同口径输入，只能重跑或凭记忆；差分被"我记得是…"接管 |
| 凭据件命名带轮次标识 | `<短名>_<轮次标识>_<序号>.<扩展名>`，例：`【填入：某指标余量】_【填入：轮次标识】_01.txt`；一轮的全部件按轮次标识过滤即可列齐 | 同名覆盖吃掉旧件 ⇒ 成对差分失去左半边；"改了没量"无法被揭穿 |
| 文档指路一律用相对位置 | 从工程根出发的相对路径；跨区引用写"区名 + 相对位置"，不写机器位置 | 交付包在第二台机器上必死；评审第一条命令就跑不起来 |

补充两条小规矩（成本低、省事多）：产物与源同轮提交，一次提交 = 一轮；
空集/读不到/解析失败在件里一律写 `NOT_MEASURED`，不写 0、不写"通过"。

---

## 4. 为什么这样切

- **评审只照说明书跑一遍。** 目录不是给作者整理的，是给陌生人找路用的：
  他只需要 `docs/` 读懂 + 第 2 节清单重建 + `deliverables/` 核对，其余区可以完全不进。
  三区分离意味着"讲的路径"和"给的东西"和"怎么来的"各自可被独立质疑。
- **源分四区**对应四类互不打扰的轮次：改逻辑不动约束、改约束不动上位机、改上位机不动板侧应用。
  单变量改动因此在目录层面就是可辨认的——diff 落在哪个区，这一轮赌的就是哪一类东西。
- **报告单独一区且只放文本**：报告是差分的原料，不是构建的附属品。放构建目录里会被清理动作顺手删掉。
- **交付数据与构建产物分开**：指标表/黄金参考/凭据件是"结论的证据"，位流是"结论的载体"，
  两者生命周期与复核人不同；混放必然导致交付包缺一半。
- **板级操作落成脚本**：现场演示不可重放是最大的隐性欠账；手敲一次命令等于没做这一轮。

---

## 5. 建完自查（空跑，5 分钟）

1. 干净树（或隔离拷贝）按第 2 节从上到下跑一遍：每条命令都退出 0、都产出它声称的那个报告。
2. `build/reports` 下每个件的**非可打印字符占比**接近 0（是人能读的文本），头部三行齐。
3. `deliverables/evidence` 下每个件名都能解析出轮次标识；按某一标识过滤，结果集非空。
4. 全量搜 `docs/` 与 `build/reports/` 里的盘符/用户主目录形式，命中数 = 0。
5. 任一条读不到 ⇒ 该项 `NOT_MEASURED`，记进 【填入：`docs/open-issues.md`】，不许默认成通过。
