# 外存/主存带宽预算：动手前先算账

## 适用场景

- 显示输出与采集写入同时跑；新加了一路搬运之后原本正常的画面开始撕裂或错位。
- 帧率莫名掉一档、丢样偶发且与"系统当时忙不忙"相关，逻辑侧反复自证清白却查不出。
- 要把中间结果落回外存（多趟处理、先写后读），或要在同一块内存上同时挂 DMA 与板载处理器的读写。
- 评审/答辩时被问"外存带宽够不够"，答不出可核对的数。
- 任何"一块内存被两条以上通路读写"的场合，不限厂商、不限板卡。

## 使用方法

**动手前先查**（按优先级取一手资料：数据手册与用户指南 ＞ 器件/板级应用笔记 ＞ 教程 ＞ 模型记忆）：
外存位宽与工作频率给出的峰值、存储控制器的突发长度上限、刷新开销比例、各路搬运引擎的最大事务率。
查不到出处的数字一律进表标"未核"，不许当实测。
**先跟用户确认**：是否允许改内存布局或省掉一次往返（会牵动别的功能）、是否允许临时关闭某条通路做对照
（会短时失去一个功能，演示当天禁止）、按行流式改造是否落在本次交付范围内。

1. **列全部竞争者，一条不落**（漏一条整张账就偏低）：显示读、采集写、主机↔板卡的搬运、
   板载处理器的缓存行缺失（取入与写回是两笔）、协议栈搬运（同一帧被软件复制几次）、
   刷新与行冲突开销、描述符/环形缓冲头/逐行填充的结构开销。
2. **每条给需求公式**，统一到同一个单位（建议字节/秒）再相加：
   - 像素通路：像素率 × 每像素字节数 × 往返次数（读一笔、写一笔各算，别只算一次）。
   - 突发效率：有用字节 ÷ 实际搬运字节；窄位宽、非对齐、跨行起点都会把它打到 0.6 以下。
   - 刷新开销：按一手资料的百分比留，不按 0 留。
   - 缓存行缺失：帧字节 ÷ 缓存行大小 ×（缓存行大小 × 取入 + 写回），小帧高频最吃亏。
3. **与器件上限对比并留裕量**：可用带宽 = 峰值 × 实测效率系数；预算 ≤ 可用的七到八成。
   超了先改结构再谈优化时序：省掉一次往返、中间结果放片上局部缓存或行缓冲、按行流式处理不落回外存、
   降低色度采样或位宽。提频/放宽时序是最后一步，不是第一步。
4. **把账写成一张表**：通路 / 公式 / 代入值 / 字节每秒 / 数字来源（文档名 + 位置 + 是否一手核过）。
   表进交付文档、随代码一起走版本。
   **单位是本条最容易出错的地方：不同单位的两个数相减是本包反复记过的错**（拿"百万像素/秒"去减
   "字节/秒"、拿大单位减小单位差一个量级）。每个数写下先看单位列，全表统一单位之后才允许加减。
5. **判别竞争的现场表现**（高自由度，给对照问题）：
   - 撕裂/错位、整帧慢一拍、偶发丢样且在别的负载起来时更频繁——这三类都指向带宽，不指向逻辑。
   - 定位：**把可疑通路临时关掉（或降一档分辨率/帧率），看现象是否消失**；同时用只读计数器
     （每路已传字节、事务数、重试或丢弃计数）对账，计数器合计与预算表的差就是算错的那一行。
   - 关掉一条现象消失 ≠ 一定是带宽：也可能只是把两路错峰了。把两路重新排成同时起读再验一次，
     现象复现才算坐实。
6. **同一块内存被两路读写的所有权规则**（判断类，写成原则 + 对照问题）：
   - 每个区域只有一个写者；读者只能在"写完成标记"之后读，标记与数据本体之间要有顺序保证，
     否则会出现"新标记 + 旧数据"。
   - 交接必须显式可答四问：谁分配、谁初始化、谁推进指针、谁负责缓存失效与出错回滚。
   - 禁止两路写同一区域；共享区做双缓冲或环形：写者永远写下一个缓冲，读者只读已完成缓冲。

## 失效条件

- **上限数字来自二手材料或模型记忆** ⇒ 账会自信地算错。征兆：表里"来源"列填不出文档名与位置；
  这种行必须标未核，不许进结论。
- **估算替代实测**：没有计数器件（片上只读计数器/性能计数）支撑时结论只能是"预算，未量过"，
  不许写成"带宽已验证够用"。
- 计数器合计大于预算合计 ⇒ 竞争者清单漏了；预算远大于计数器读数 ⇒ 通路其实被调度错峰了，
  此时"超预算"不代表板上会坏，但"够预算"也不代表两路同时起读的突发场景够。
- 症状其实来自缓存一致性或对齐（数据半新半旧、只有首块尾块坏）而非带宽 ⇒ 本条不适用，
  去看 `dma-and-cache-coherency`。
- 把逐帧平均带宽当峰值需求用：突发集中在几毫秒内时，平均值好看的账会漏判。

## 已验证效果

以下读数来自某一次具体设计，量级只用于说明形状，随设计而变，不可当普适结论引用。

未量过，属建议——本包没有在任何具体板卡上做过"预算表 vs 计数器实测"的成对复跑。
可复跑形式：跑一批 N 帧，读各路只读计数器的字节数求和，除以运行时长得实测字节/秒，与预算表合计比对；
差值 ≤ 15% 且计数器无丢弃/重试增量才算这条落过地，否则判 FAIL 并回到第 1 步补竞争者。
