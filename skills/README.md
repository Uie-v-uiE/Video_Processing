# 技能包：与大模型协作做 FPGA / 数字设计

把长期与编码 agent 协作过程中**沉淀下来的经验显式化**，供另一支队伍直接复用到自己的题目上。
评价指标只有一个：**可复用性**——陌生队伍拿到这个目录，能不能不问本包就用起来。

本包不含任何具体工程的事实（器件上限、板卡引脚、某一轮的读数）。
那些属于你自己的工程文档；写进来就失去了通用性（`_meta/check-skill-package.mjs` 会判红）。

## 四类内容对应赛题要求的四型

| 赛题类型 | 本包类别 | 入口 |
| --- | --- | --- |
| 提示词工作流 | `workflow/` `prompts/` | 从算法描述推软硬件划分、从综合报告定位瓶颈、一轮的标准节拍 |
| 案例模板 | `templates/` | 工程骨架、一轮记录、声明—证据对照表、验收与眼睛判据配方 |
| 校验脚本 | `scripts/` | 黄金比对、指标采集出表、契约生成主机侧代码、复现演练、门禁跑批 |
| 踩坑清单 | `pitfalls/` | 探针陷阱、尺子假绿、在飞竞态、批量改口损伤、约束射程收窄、交付包完整性 |

另有按活分的专业条目 `timing/` `rtl/` `runtime/` `verify/` 与速查表 `references/`。
**每一项都写明：适用场景 / 使用方法 / 失效条件 / 已验证效果 / 来源**（五节，逐字标题）。

## 适用范围

用于与大模型协作做 FPGA / 数字设计的任何阶段：立项、查资料、写 RTL、收时序、上板验证、
设计判据、打包交付。条目按"活"组织而不是按某一块板卡或某一个题目，因此可直接搬到别的题目上。
不适用：具体器件的资源上限、具体板卡的引脚归属、某一轮工程自己的读数——那些属于工程文档。

## 使用方法（30 秒接入）

1. 整目录放进你的工程（`skill/` 或 agent 的技能目录）。纯文本 + 零依赖 Node 件，不需安装。
2. 先读 `references/symptom-router/SKILL.md`：只有症状时用它决定读哪条、动手前先搜什么。
3. 按需加载单条；只有要细节时才打开该条目的 `references/` 或运行 `scripts/`。
   不要一次读整包——三级渐进加载（元数据 → 正文 → 资源）是这套结构的立身理由。

人工用法、新增条目的流程、改条目的规矩都在 `_meta/`：

## 失效条件

工具版本不同则报告字段与命令选项不同，按某版本写的解析正则射程会静默变窄；
`已验证效果` 标「未量过，属建议」的条目不能当已证明的结论引用；
把条目里的量级当普适数字会误导设计决策；本包不含具体器件/板卡的专有事实，
需要那些读数仍要查自己的工程文档与一手手册。

## 已验证的复用结果

本包自证可复跑：`node _meta/check-selftest.mjs` 判 16 项不符 0（含"地板可动""索引双向""变异真改到文本"），
`node _meta/check-skill-package.mjs .` 判 52 项（条目 48、索引行 49）红 0 未测 0，
六个脚本件各自 `--self` 实跑为 判 10/10/27/20/21 项红 0（见 `scripts/*/SKILL.md` 的已验证效果），
通用性判据命中 0（无工程名、板卡名、器件型号、轮次号、绝对路径）。
陌生队伍复用的判据 = 只读症状能否命中条目，见 `references/symptom-router/SKILL.md` 的自查段。
