# 演示视频拍摄脚本

> 用途：拍一条 5–6 分钟的演示片。最终成片是 16:9 左右分屏：左半边是 PC 录屏，右半边是手机拍的开发板 + HDMI 屏幕。所有命令、预期回显和字幕都按这份脚本走；拍摄时不需要临场想词。

---

## 0. 成片规格

| 项 | 建议 |
|---|---|
| 成片 | 1920×1080（或 3840×2160），16:9，30 fps |
| 时长 | 5–6 分钟；比赛限时更短时，优先删 SD 回放和遥测，保留冷启动、同帧 A/B、效果/几何、故障注入 |
| 左右分屏 | 左 50% PC 录屏，右 50% 手机画面，中间 2–4 px 深色分隔线 |
| 字幕 | 底部一条半透明黑底白字；技术名词用等宽字体；不盖 OSD 左上角 |
| 声音 | 后期配音为主；现场声压到很低或不用；不加高音量背景音乐 |
| 片头/片尾 | 各 5–8 秒，标题 + 四个亮点，不出现本机路径和日期 |

---

## 1. 拍摄前准备

### 1.1 硬件

- Zynq-7020 板卡，QSPI 已写入当前 `BOOT.bin`；
- HDMI 接 1024×600 面板，面板输入源选对；
- PL 侧 RJ45 接 PC 有线网卡，PC 地址 `192.168.1.100/24`，板卡 `192.168.1.10/24`；
- USB-C 接 JTAG/UART，串口为 `COM6`，115200 8N1；
- 手机、三脚架、补光灯；黑色背景布或干净桌面；
- 如果板卡和屏幕是左右摆的，拍摄前改成“屏幕在上、板卡在下”的竖向构图，方便手机竖拍。

### 1.2 软件与板子状态

在仓库根目录打开 PowerShell/Windows Terminal，确认：

```powershell
ping -n 4 192.168.1.10
python src/host/video_sender.py --demo --seconds 10
```

推流 10 秒，屏幕应出现渐变底 + 下移白线 + 横向红块。然后串口执行恢复默认：

```text
src 1
zoom 1.0
rot auto 0
rot speed 0
split screen
split 50
split swap 0
split marker 0
osd on
pipe 000010000
stat
```

默认状态应为：网络源、50% 竖缝、OSD 打开、约 1.0 倍、不自动旋转。`stat` 里 `src=1`、`osd=1`、`sel=` 有值。记下开场 `stat`，收尾时用它对照（`pub=` 会翻转，不算差异）。

### 1.3 PC 桌面与终端

- 关闭微信/QQ/邮件/系统更新等通知；任务栏能隐藏就隐藏；
- 桌面只留终端和必要的串口窗口，不放个人文件；
- 左半屏内部再分上下两块：
  - 上半：PowerShell/Windows Terminal，跑 `video_sender.py`、`link_selftest.py`、`telemetry_listen.py`；
  - 下半：串口助手（PuTTY、Tera Term 或 Vitis 串口终端），连 `COM6`；
- 终端字体 18–20 pt，深色底、高对比；每次开机位前清屏，避免旧命令和旧路径入镜；
- 如果终端提示符带很长的本机路径，换一个短提示符，或后期把提示符区域裁掉/模糊；
- 串口助手只开一个本地回显来源：Vitis 串口终端自带本地回显，板子保持 `echo 0`；PuTTY 默认没有本地回显，先在板子上发 `echo 1`。两者只选一种，否则一个字符会显示两遍。

### 1.4 手机

- 竖拍 4K（2160×3840），30 fps；如果用 60 fps，后期统一到 30 fps；
- 1× 主摄，不用超广角、不用数码变焦；
- 三脚架固定，镜头高度约在 HDMI 屏幕中心；
- 手机距板卡/屏幕 1.0–1.2 m，镜头稍微偏右 5–10°，避开屏幕正反射；
- 画面上部 60–65% 是 HDMI 屏幕，下部 35–40% 是板卡、电源和 USB-C 线；
- 长按屏幕锁定对焦和曝光；白平衡手动 5000–5600 K；关闭 HDR/夜景/美颜；
- 开飞行模式 + 勿扰模式，关通知；开始录制后不要再碰手机；
- 补光灯从 45° 上方打，避免直射屏幕；黑色背景布遮住杂物；线材用扎带收好；
- 先录 3 秒空画面，再开始操作；片头拍一下手或说一句“开始”，方便后期对齐。

### 1.5 预检（正式拍前必须做一遍）

- [ ] 断电重上，HDMI 有画面，OSD 五行正常；
- [ ] `ping` 5/5 或 4/4；
- [ ] 推流 10 秒，画面在动；
- [ ] 串口 `stat`、`temp`、`link` 都有回显；
- [ ] `pipe show`、`split show`、`rot show` 都能读；
- [ ] SD 卡能 `sd files`，至少有一个文件；
- [ ] `link_selftest.py` 先在没人占 UDP 1234 时跑通过一次；
- [ ] OBS 试录 10 秒，左半屏字清楚；
- [ ] 手机试拍 10 秒，屏幕没有摩尔纹、板卡对焦清楚；
- [ ] 桌面通知已关，终端历史已清。

## 2. 最终画面排版

### 2.1 16:9 左右分屏

```text
┌──────────────────────────┬──────────────────────────┐
│ 左 50%：PC 录屏           │ 右 50%：手机拍板卡+屏幕   │
│ ┌──────────────────────┐ │ ┌──────────────────────┐ │
│ │ 上：推流/自检/遥测终端 │ │ │ 上：HDMI 屏幕（OSD）  │ │
│ ├──────────────────────┤ │ ├──────────────────────┤ │
│ │ 下：串口 COM6 命令     │ │ │ 下：板卡、电源、线材   │ │
│ └──────────────────────┘ │ └──────────────────────┘ │
└──────────────────────────┴──────────────────────────┘
                    底部字幕条（不盖 OSD）
```

- 左半屏和右半屏之间加 2–4 px 深灰/黑色竖线；
- 左半屏上下两块各加一条 24–28 px 的标签条：
  - 上：`PC · 推流 / 自检 / 遥测`
  - 下：`串口 COM6 · 板卡命令`
- 右半屏加一条标签：`Zynq-7020 · 1024×600 HDMI`；
- 两块画面都做轻微暗角和 1 px 边框，避免和背景糊在一起；
- 字幕条放在画面最底部，高度 80–100 px，半透明黑底，白字 28–36 px。

### 2.2 左半屏 PC 的内部布局

- 上半 55–60%：PowerShell/Windows Terminal，显示推流脚本、`link_selftest.py`、`telemetry_listen.py` 的输出；
- 下半 40–45%：串口窗口，显示命令和板子回显；
- 两个窗口的字体一样大，行距足够；命令发出后至少留 2 秒让观众读到回显；
- 需要强调某一行时，后期做 1.2–1.5 倍局部放大 + 黄色框，不要用花哨转场；
- PC 用 OBS 录屏，不要用手机拍 PC 屏幕：手机拍屏幕会有摩尔纹、刷新条纹和对焦呼吸。

### 2.3 右半屏手机画面

- 手机竖拍，画面里屏幕在上、板卡在下；
- 屏幕要完整入镜，尤其是左上角 OSD 五行；
- 板卡要露出电源、USB-C、网线和 HDMI 线，证明“这是实板，不是录屏”；
- 手机镜头不要正对屏幕中心，偏 5–10° 可以明显减少反光；
- 画面里不要出现人手挡住 OSD；操作串口时手在 PC 键盘上，不要伸进手机画面。

### 2.4 字幕与标注

- 顶部左上角：场景编号 + 一句标题，例如 `01 · 断电冷启动`；
- 底部：一句解释，最多两行；
- 命令场景：在串口窗口下方叠一条 `发出的命令`，用等宽字体；右侧用箭头指向板子回显；
- 数字场景：把关键数字做成黄色高亮，例如 `gap_valid=1`、`0 fps`、`14.3 aborts/s`；
- 不盖 OSD 左上角，不盖串口回显最后一行；
- 字幕里不写版本号、日期、本机路径；需要指代时写“当前固件/当前镜像”。

### 2.5 声音

- 推荐后期配音：先剪画面，再按画面写旁白；旁白语速比平时慢 10%；
- 如果现场收音，用领夹麦或手机外接麦，不要用板卡风扇/PC 风扇的近场噪声；
- 背景音乐只做很低的垫底，不要压过旁白；命令回显处可以完全静音 1 秒，让观众读数字。

## 3. 分镜与命令

> 时间码是成片目标，不是拍摄顺序。每个场景先拍 PC 录屏，再拍手机画面；后期按命令和画面变化对齐。

### 3.1 0:00–0:20 开场

**左半屏（PC）**

- 上方终端显示 `ping -n 4 192.168.1.10` 的结果：4/4，0% loss；
- 下方串口窗口暂时空白或只显示一行 `stat`。

**右半屏（手机）**

- 板卡 + HDMI 屏幕全景；屏幕显示默认 50% 竖缝画面；
- 手机先录 3 秒静止画面，再开始操作。

**命令**

```powershell
ping -n 4 192.168.1.10
```

**预期回显**

```text
来自 192.168.1.10 的回复: 字节=32 时间<1ms TTL=64
... 4 个包，0% 丢失
```

**字幕**

- 主标题：`多源视频流多效果变换处理系统`
- 副标题：`Zynq-7020 · 全 PL 视频通路 · 可观测仪表`
- 底部：`一根网线进，一块屏出；像素不经过 PS`

**拍摄/剪辑**

- 开场用右半屏全景，左半屏 ping 结果做画中画；不要一上来就推流；
- 标题停留 3 秒，ping 结果停留 3 秒。

---

### 3.2 0:20–0:55 断电冷启动

**左半屏（PC）**

- 下方串口窗口保持打开；断电重上后，串口会打印启动信息；
- 启动完成后发：

```text
stat
```

**右半屏（手机）**

- 手机拍到电源开关/插头被断开再上电；
- 屏幕从黑到出现画面；板卡电源灯、DONE 灯（如果可见）入镜；
- 重点拍“断电 → 上电 → 画面自己起来”，不要剪掉中间。

**预期回显/画面**

- 串口有启动回显；
- `stat` 打印 `[STAT] ctrl thr=... src=1 ...`，帧计数开始增长；
- 屏幕 OSD 第一行显示 `512X300  FPS:30  SRC:ETH` 或 `TEST`（取决于源）；
- 无 CRC/IDCODE 错误（启动日志里不应出现）。

**字幕**

- `01 · 断电冷启动`
- `QSPI BOOT.bin：FSBL + 位流 + PS 应用`
- `上电后屏幕自己起来，不需要 JTAG`

**拍摄/剪辑**

- 手机镜头不要移动；断电/上电用一个固定机位；
- 如果启动时间较长，剪掉中间等待，但保留“黑屏 → 出现画面”的两次切换；
- 左半屏的启动日志如果滚得太快，后期做 1.2 倍慢放或只保留最后几行。

### 3.3 0:55–1:35 同帧 A/B 与默认画面

**左半屏（PC）**

- 上方终端执行：

```powershell
python src/host/video_sender.py --demo --seconds 300
```

- 推流开始后，下方串口执行：

```text
stat
pipe show
```

**右半屏（手机）**

- 屏幕出现渐变底、下移白线、横向红块；
- 中间竖缝左侧是原图，右侧是同一帧的处理图；
- 镜头慢慢推近到屏幕左上角 OSD，停 2 秒，再拉回全景。

**预期回显**

- 推流脚本打印发送帧数/包数；
- `stat` 的帧计数持续增长，`src=1`；
- `pipe show` 打印当前九位效果码对应的级名；
- OSD：
  - 第 1 行：`512X300  FPS:30  SRC:ETH`
  - 第 2 行：`Pipe:...  Th:...  Gamma:...`
  - 第 3 行：`Rot:0°  Zoom:1.00X`
  - 第 4 行：`Split:50%  Latency:...MS`
  - 第 5 行：`Temp:..C`

**字幕**

- `02 · 同一帧的原图 / 处理图`
- `左半原图，右半处理结果；共用同一套几何`
- `OSD 第 1 行：片源 512×300、30 fps、当前源`

**拍摄/剪辑**

- 这是全片最重要的画面，至少拍 20 秒可用素材；
- 推近 OSD 时不要遮挡屏幕；可以用手机的 2× 长焦拍 OSD，但不要数码变焦；
- 后期在竖缝两侧各加一个小箭头，标“原图”“处理结果”。

### 3.4 1:35–2:20 效果与几何

**左半屏（PC）**

- 下方串口逐条发，发一条等 2–3 秒，看到回显再发下一条：

```text
pipe 000010000
pipe show
zoom 1.5
rot auto 1
rot speed 2
```

**右半屏（手机）**

- `pipe 000010000`：画面效果变化（第 4 位，锐化；以 `pipe show` 打印的名称为准）；
- `zoom 1.5`：画面放大；
- `rot auto 1`：画面开始自动旋转，缩放可能同时切到 Fit；
- `rot speed 2`：旋转速度变为 2 度/帧。

**预期回显**

- `[PIPE] sel=... 生效: ...`，`pipe show` 打印各级名称；
- `[ZOOM] 1.5 → 最近档 1.50x（八档：...）`；
- `[ROT] auto=1...`，可能提示 `speed 0→2`、`缩放切到 fit`；
- `[ROT] speed=2 度/帧`。

**字幕**

- `03 · 九位效果码：一位一级`
- `000010000 = 第 4 位；具体级名以 pipe show 为准`
- `旋转时缩放切到 Fit，整幅画面保持在屏内`

**拍摄/剪辑**

- 每条命令后停 2 秒；不要连发，否则观众看不清哪条命令对应哪个画面；
- 旋转镜头至少保留 5 秒，让观众看到竖缝跟着画面转；
- 后期在命令和画面之间加 0.2 秒的硬切，不要用花哨转场。

### 3.5 2:20–2:50 竖缝对比

**左半屏（PC）**

```text
split screen
split 50
split swap 1
```

等 3 秒，再：

```text
split swap 0
```

**右半屏（手机）**

- 屏幕中间竖缝：左边原图、右边处理图；
- `swap 1` 后左右内容互换，缝位不动；
- 镜头固定全景，不要移动。

**预期回显**

- `[SPLIT] screen：缝在显示列里扫，pos=... = 50%`；
- `[SPLIT] 50% -> pos=.../1024（显示列；manual；屏上 Split 格应显示 50%）`；
- `[SPLIT] swap=1（只换内容，不换缝位）`；
- `[SPLIT] swap=0（只换内容，不换缝位）`。

**字幕**

- `04 · 缝位不动，只交换内容`
- `swap=1：原图到右、处理图到左；缝仍在 50%`
- `这不是两路各自缩放，是同一条地址流上的两个抽头`

**拍摄/剪辑**

- 这是“同帧 A/B”的最直观证据，保留完整 swap 前后各 3 秒；
- 后期在缝两侧加 `原图 →` / `← 处理` 标签，swap 后标签跟着换。

### 3.6 2:50–3:35 帧间隔读数

**左半屏（PC）**

- 推流保持运行（如果前面停了，重新执行 `video_sender.py --demo --seconds 300`）；
- 下方串口：

```text
link clr
```

等 5 秒：

```text
link
```

然后在上方终端按 `Ctrl+C` 停止推流，等 3 秒，再：

```text
link
```

**右半屏（手机）**

- 推流时屏幕在动；
- 停流后画面停在最后一帧（这是正常行为）；
- 重点拍串口窗口里的 `[LINK]` 行，屏幕保持全景即可。

**预期回显**

```text
[LINK] gap statistics cleared
[LINK] drop=0 badpkt=0 aborts=0 rows_max=0 stall=...ms gap_last≈33ms gap_min=... gap_max=... gap_sum=... gap_valid=1 live=1
```

停流后：

```text
[LINK] ... stall=...ms gap_last=... gap_max=...
```

**字幕**

- `05 · 帧间隔统计：link / link clr`
- `gap_valid=1：统计已由至少两帧校准`
- `停流后 stall 增长；gap_max 记录长间隔`

**拍摄/剪辑**

- 后期把 `[LINK]` 行放大，黄色框出 `gap_valid=1`、`gap_last`、`gap_max`；
- 停流后的画面冻结要保留 1 秒，旁白说明“这是最后一帧，不是卡死”。

### 3.7 3:35–4:15 故障注入：仪表能被打红

**左半屏（PC）**

- 先确认推流已停止（避免两个发送器抢流）；
- 上方终端执行：

```powershell
python src/host/link_selftest.py 192.168.1.10 6
```

**右半屏（手机）**

- 屏幕可能切换到自检用的测试图案，或在丢包段冻结/黑屏；
- 镜头保持全景，不要因为画面变化而移动。

**预期回显**

```text
== clean1 6s ==
   beacons=... frames=... aborts=0 ...
PASS clean1 ...
== fault 6s ==
   ... frames≈0/s aborts≈14.3/s ...
PASS fault ...
== clean2 6s ==
   ... frames=... aborts=0 ...
PASS clean2 ...
PASS link_selftest: clean→fault→clean all judged from the wire
```

具体数字以现场为准；稳定读数应接近：干净段 22.0 fps、故障段 0 fps + 14.3 次作废/秒、恢复段 18.9 fps。

**字幕**

- `06 · 仪表能被打红，也能恢复`
- `干净流 → 每 100 包丢 1 包 → 干净流`
- `故障段 0 fps + 14.3 aborts/s；恢复段回到 18.9 fps`

**拍摄/剪辑**

- 这是“自证仪表”的核心，保留完整三阶段，不要只截 PASS 一行；
- 后期把故障段的 `frames≈0` 和 `aborts` 放大；
- 旁白明确说“这不是演示动画，是每 100 包真丢 1 包”。

### 3.8 4:15–4:50 SD 回放

**左半屏（PC）**

- 下方串口：

```text
sd files
sd file 1
play
```

等 3 秒，再：

```text
stop
src 1
```

**右半屏（手机）**

- `play` 后屏幕切到 SD 卡的帧序列；
- `stop` 后画面停在最后一帧；
- `src 1` 后回到网络源（如果推流已停，画面保持，OSD 的 `SRC:` 会变）。

**预期回显**

```text
[SD] N file(s), ... frame(s) total
[SD] file #1 ... first=...
[SD] playing (stop / play 0 结束; ETH 有流时会自动让位)
[SD] stopped; next frame ...
[SRC] 已钉住 ETH（mode=1...）
```

**字幕**

- `07 · SD 回放：同一套 DDR/显示链`
- `PS 只负责把帧写进 DDR；像素仍由 PL 显示`
- `stop / src 1 回到网络源`

**拍摄/剪辑**

- 如果 SD 卡没有内容，这一场直接删，不影响主线；
- 保留 `sd files` 的文件列表，证明不是播一个固定动画。

## 4. OSD 五行怎么讲

屏幕左上角 OSD 五行是这条片子的“读数中心”。每一行都可以在推近镜头时讲一句：

| 行 | 屏上示例 | 讲解 |
|---|---|---|
| L0 | `512X300  FPS:30  SRC:ETH` | 片源 512×300、30 fps；当前源是 ETH 网络 |
| L1 | `Pipe:11000  Th:80  Gamma:1.8` | 九位效果码的屏上投影、二值化阈值、gamma |
| L2 | `Rot:45°  Zoom:0.75X(AUTO)` | 当前角度、缩放档位；`(Fit)` 表示缩放跟着角度 |
| L3 | `Split:50%  Latency:16MS` | 缝位百分比；PL 内部帧时延（不是玻璃到玻璃） |
| L4 | `Temp:62C` | 片上 XADC 温度；读不到时显示 `--` |

注意：

- L0 的尺寸是**片源** 512×300，不是面板 1024×600；面板尺寸在片头/旁白里说；
- L1 的 `Pipe:` 五位不是命令里的九位 0/1，而是“每一级选了第几个算法”；要解释当前开什么，发 `pipe show`；
- L2 的 `(Fit)` 与 `(Auto)` 互斥；
- L3 的 `Latency` 是 PL 内部时延，不包含编码/网线/面板；
- L4 的 `--` 是“还没有可信读数”，不是 0 °C。

## 6. 串口终端设置

- 端口 `COM6`，波特率 115200，8 数据位，无校验，1 停止位；
- 流控关闭；
- 行尾 `\r\n` 或 `\n` 都可以；一次发一行，等回显再发下一行；
- 本地回显只开一处：
  - Vitis 串口终端：自带本地回显，板子保持 `echo 0`；
  - PuTTY/Tera Term：默认无本地回显，先发 `echo 1`，让板子回显字符；
- 字体 18–20 pt，深色主题；关闭时间戳（如果会挡住回显）；
- 不要把命令一次粘贴一长串；观众看不清，板子也可能一次收多行；
- 如果命令没回显，先发一个空行或 `help`，确认串口还活着。

## 8. 剪辑与同步

1. 先放 PC 录屏轨，再放手机轨；两条都缩放到 960×1080，左右各占一半；
2. 找同步点：命令回显出现的那一帧，对应屏幕发生变化的那一帧；用 1–2 帧微调；
3. 每条命令后至少留 2 秒回显；数字行做 1.2–1.5 倍局部放大；
4. 章节之间硬切；只有片头/片尾用 0.3 秒淡入淡出；
5. 字幕先写“命令”，再写“它改变了什么”，最后写“读数是多少”；
6. 不盖 OSD 左上角、不盖串口最后一行；
7. 旁白按画面写，不要照着文档念；每个场景 2–4 句；
8. 输出：H.264/H.265，1080p30，音频 AAC 48 kHz；文件名不带日期/版本号。

## 9. 兜底

| 现象 | 处理 |
|---|---|
| 推流不通 | 先 `ping`；检查 PC 网卡 `192.168.1.100/24`、防火墙、网线是否在 PL 侧 RJ45 |
| 串口无回显 | 确认 COM6 没被占用、115200；断电重上；先发 `help` |
| HDMI 无画面 | 确认面板输入源、分辨率 1024×600；OSD 第一行应有 `512X300` |
| 画面停在最后一帧 | 正常：停流后保持最后一帧；重新推流或 `src 2` |
| `link_selftest` 收不到 beacon | 先 `ping` 一次板子；确认没有别的程序占 UDP 1234；停掉 sender 再跑 |
| `link_selftest` 失败 | 这是仪表在报故障，不要重拍到“绿”为止；先看是 ARP、防火墙还是板子没流 |
| `sd files` 失败 | `sd remount`；等 2–3 秒再 `sd files`；卡必须是 FAT32 |
| OSD 不见了 | `osd on` |
| 板子状态乱了 | 按 1.2 的默认命令逐条恢复，最后 `stat` 对照 |
| 手机录制失败 | 用第二台手机/备用机位；PC 录屏必须保留，它是主线 |
