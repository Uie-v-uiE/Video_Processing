# 演示视频拍摄与剪辑手册（分块执行版）

> 用途：拍一条 5–6 分钟的演示片。最终成片是 16:9 左右分屏：左半边是 PC 录屏，右半边是手机拍的开发板 + HDMI 屏幕。
>
> 读法：第 0–4 章先定成片效果、排版和区块划分；第 5 章按 A–J 十个演示区块逐块拍；第 6–9 章讲拍摄顺序、剪辑、短版和检查。每一块都按“画面区域 → 拍摄方式 → 指令顺序 → 预期回显 → 剪辑方式 → 成片效果”写，拍摄时不需要临场想词。

---

## 0. 成片最终效果

成片开始时，黑底标题淡入，右半屏是真实开发板和 1024×600 HDMI 屏幕的全景，左半屏是 PC 终端里的 `ping` 结果。标题停留三秒，观众先确认“这是实板，不是录屏”。

随后右半屏断电、上电，HDMI 自己亮起，左半屏串口打印启动信息；这是 QSPI 冷启动区。

中段进入主线：左半屏推流脚本滚动帧数/包数，右半屏画面开始运动；镜头缓慢推近到屏幕左上角 OSD，再拉回全景。屏幕中央的竖缝左侧是原图、右侧是同一帧的处理图，两侧共用几何和固定 15 拍效果链。接着逐条发送效果、缩放和旋转命令，画面在每条命令后发生变化，观众能清楚看到“命令 → 回显 → 画面”的对应关系。

后段是仪表区：串口 `link` 给出帧间隔统计，停流后 `stall` 增长、画面停在最后一帧；三阶段故障注入让帧率从正常掉到 0，再恢复，作废计数同步上升和回落。最后用 1 Hz 遥测展示同一个计数器的第二个出口，再用 SD 回放说明片源可以切换。片尾恢复默认画面，镜头拉远，四个亮点逐条出现，停在标题上。

整片不出现本机路径、日期、版本号、聊天窗口和个人文件；所有数字都来自现场回显或 OSD，不用后期伪造。

## 1. 成片规格

| 项 | 建议 |
|---|---|
| 成片 | 1920×1080（或 3840×2160），16:9，30 fps |
| 时长 | 5–6 分钟；比赛限时更短时用第 8 章的 3 分钟版 |
| 左右分屏 | 左 50% PC 录屏，右 50% 手机画面；中间 2–4 px 深色分隔线 |
| 字幕 | 底部半透明黑底白字；技术名词用等宽字体；不盖 OSD 左上角 |
| 声音 | 后期配音为主；现场声压低或不用；背景音乐只做很低的垫底 |
| 片头/片尾 | 各 5–8 秒；标题 + 四个亮点；不出现本机路径和日期 |
| 输出 | H.264/H.265，1080p30，AAC 48 kHz；文件名不带日期/版本号 |

## 2. 拍摄前准备

### 2.1 硬件

- Zynq-7020 板卡，QSPI 已写入当前 `BOOT.bin`；
- HDMI 接 1024×600 面板，面板输入源选对；
- PL 侧 RJ45 接 PC 有线网卡，PC 地址 `192.168.1.100/24`，板卡 `192.168.1.10/24`；
- USB-C 接 JTAG/UART，串口为 `COM6`，115200 8N1；
- 手机、三脚架、补光灯；黑色背景布或干净桌面；
- 屏幕在上、板卡在下的竖向构图，方便手机竖拍后裁成右半屏。

### 2.2 板子恢复默认

在仓库根目录打开 PowerShell/Windows Terminal，先推流 10 秒确认画面：

```powershell
ping -n 4 192.168.1.10
python src/host/video_sender.py --demo --seconds 10
```

然后在串口逐条执行，恢复到拍摄默认状态：

```text
src 1
zoom 1.0
rot auto 0
rot speed 0
split screen
split 50
split swap 0
split marker 0
osd on
pipe 000010000
stat
```

默认状态应为：网络源、50% 竖缝、OSD 打开、约 1.0 倍、不自动旋转。`stat` 里 `src=1`、`osd=1`、`sel=` 有值。记下开场 `stat`，收尾时用它对照；`pub=` 会翻转，不算差异。

### 2.3 PC 桌面与终端

- 关闭微信/QQ/邮件/系统更新等通知，任务栏能隐藏就隐藏；
- 桌面只留终端和必要的串口窗口，不放个人文件；
- 左半屏内部再分上下两块：
  - 上半 55–60%：PowerShell/Windows Terminal，跑 `video_sender.py`、`link_selftest.py`、`telemetry_listen.py`；
  - 下半 40–45%：串口助手（PuTTY、Tera Term 或 Vitis 串口终端），连 `COM6`；
- 终端字体 18–20 pt，深色底、高对比；每个区块开拍前清屏，避免旧命令和旧路径入镜；
- 如果提示符带很长的本机路径，换短提示符，或后期裁掉/模糊提示符区域；
- 串口本地回显只开一处：Vitis 终端自带本地回显，板子保持 `echo 0`；PuTTY 默认没有本地回显，先发 `echo 1`。否则一个字符会显示两遍。

### 2.4 手机

- 竖拍 4K（2160×3840），30 fps；如果用 60 fps，后期统一到 30 fps；
- 1× 主摄，不用超广角、不用数码变焦；
- 三脚架固定，镜头高度约在 HDMI 屏幕中心；
- 手机距板卡/屏幕 1.0–1.2 m，镜头稍微偏右 5–10°，避开屏幕正反射；
- 画面上部 60–65% 是 HDMI 屏幕，下部 35–40% 是板卡、电源和 USB-C 线；
- 长按屏幕锁定对焦和曝光；白平衡手动 5000–5600 K；关闭 HDR/夜景/美颜；
- 开飞行模式 + 勿扰模式，关通知；开始录制后不要再碰手机；
- 补光灯从 45° 上方打，避免直射屏幕；黑色背景布遮住杂物；线材用扎带收好；
- 先录 3 秒空画面，再开始操作；每个区块开拍时拍一下手或说一句“A 开始”，方便后期对齐。

### 2.5 预检

- [ ] 断电重上，HDMI 有画面，OSD 五行正常；
- [ ] `ping` 5/5 或 4/4；
- [ ] 推流 10 秒，画面在动；
- [ ] 串口 `stat`、`temp`、`link` 都有回显；
- [ ] `pipe show`、`split show`、`rot show` 都能读；
- [ ] SD 卡能 `sd files`，至少有一个文件（要拍 SD 时）；
- [ ] `link_selftest.py` 先在没人占 UDP 1234 时跑通过一次；
- [ ] OBS 试录 10 秒，左半屏字清楚；
- [ ] 手机试拍 10 秒，屏幕没有摩尔纹、板卡对焦清楚；
- [ ] 桌面通知已关，终端历史已清。

## 3. 画面排版模板

### 3.1 16:9 左右分屏

```text
┌──────────────────────────┬──────────────────────────┐
│ 左 50%：PC 录屏           │ 右 50%：手机拍板卡+屏幕   │
│ ┌──────────────────────┐ │ ┌──────────────────────┐ │
│ │ 上：推流/自检/遥测终端 │ │ │ 上：HDMI 屏幕（OSD）  │ │
│ ├──────────────────────┤ │ ├──────────────────────┤ │
│ │ 下：串口 COM6 命令     │ │ │ 下：板卡、电源、线材   │ │
│ └──────────────────────┘ │ └──────────────────────┘ │
└──────────────────────────┴──────────────────────────┘
                    底部字幕条（不盖 OSD）
```

- 左半屏和右半屏之间加 2–4 px 深灰/黑色竖线；
- 左半屏上下两块各加一条 24–28 px 的标签条：
  - 上：`PC · 推流 / 自检 / 遥测`
  - 下：`串口 COM6 · 板卡命令`
- 右半屏加一条标签：`Zynq-7020 · 1024×600 HDMI`；
- 两块画面都做轻微暗角和 1 px 边框，避免和背景糊在一起；
- 字幕条放在画面最底部，高度 80–100 px，半透明黑底，白字 28–36 px。

### 3.2 左半屏 PC 的内部布局

- 上半 55–60%：PowerShell/Windows Terminal，显示推流脚本、`link_selftest.py`、`telemetry_listen.py` 的输出；
- 下半 40–45%：串口窗口，显示命令和板子回显；
- 两个窗口字体一样大，行距足够；命令发出后至少留 2 秒让观众读到回显；
- 需要强调某一行时，后期做 1.2–1.5 倍局部放大 + 黄色框，不要用花哨转场；
- PC 用 OBS 录屏，不要用手机拍 PC 屏幕：手机拍屏幕会有摩尔纹、刷新条纹和对焦呼吸。

### 3.3 右半屏手机画面

- 手机竖拍；最终右半屏是 960×1080（约 8:9），不是完整竖屏；
- 构图时把 HDMI 屏幕和板卡放在画面中央的安全区，上下各留 10–15% 余量，后期裁切不丢 OSD 和板卡；
- 屏幕要完整入镜，尤其左上角 OSD 五行；
- 板卡要露出电源、USB-C、网线和 HDMI 线，证明“这是实板，不是录屏”；
- 镜头不要正对屏幕中心，偏 5–10° 可以明显减少反光；
- 画面里不要出现人手挡住 OSD；操作串口时手在 PC 键盘上，不要伸进手机画面。

### 3.4 字幕、标签与安全区

- 顶部左上角：场景编号 + 一句标题，例如 `01 · 断电冷启动`；
- 底部：一句解释，最多两行；
- 命令场景：在串口窗口下方叠一条“发出的命令”，等宽字体；右侧用箭头指向板子回显；
- 数字场景：关键数字用黄色高亮，例如 `gap_valid=1`、`0 fps`、`14.3 aborts/s`；
- 不盖 OSD 左上角，不盖串口回显最后一行；
- 字幕不写版本号、日期、本机路径；需要指代时写“当前固件/当前镜像”。

### 3.5 声音

- 推荐后期配音：先剪画面，再按画面写旁白；旁白语速比平时慢 10%；
- 如果现场收音，用领夹麦或手机外接麦，不要用板卡/PC 风扇近场噪声；
- 背景音乐只做很低的垫底，不要压过旁白；命令回显处可以完全静音 1 秒，让观众读数字。

## 5. 分块拍摄与剪辑

> 每块先拍 PC 录屏和手机画面，再按命令和画面变化对齐。每个区块开拍时拍手/说“X 开始”，结束说“X 完”；同一块至少留两条 take。

### 5.1 区块 A · 整机身份区（0:00–0:20）

**演示目的**：先让观众确认这是真实开发板、真实 HDMI 输出，不是软件录屏。

**画面区域**：
- 左上半：PowerShell，`ping` 结果；
- 左下半：串口窗口，暂时空白或一行 `stat`；
- 右半：板卡 + HDMI 屏幕全景，屏幕显示默认 50% 竖缝。

**拍摄方式**：
- 手机固定全景，先录 3 秒静止画面；
- OBS 先开始录 PC，再在 PowerShell 执行 `ping`；
- 不要在开场就推流；让观众先看清板子和屏幕。

**指令顺序**：

```powershell
ping -n 4 192.168.1.10
```

**预期回显/画面**：

```text
来自 192.168.1.10 的回复: 字节=32 时间<1ms TTL=64
... 4 个包，0% 丢失
```

**剪辑方式**：
- 右半屏全景打底，左半屏 ping 结果做画中画；
- 标题停留 3 秒，ping 结果停留 3 秒；
- 片头标题可用 0.3 秒淡入，之后硬切。

**成片效果（文字描述）**：
黑底白字标题淡入，右半屏是真实板卡和亮着的 HDMI 屏幕，左半屏出现 `ping` 的 4/4 回显。观众在第一眼看到“板子、屏幕、网线、终端”同时存在，知道后面所有画面都来自这台实板。

**备用/删减**：如果 ping 失败，先检查网线和 PC 网卡，不要用假回显。

---

### 5.2 区块 B · 部署/启动区（0:20–0:55）

**演示目的**：证明 QSPI 里的 `BOOT.bin` 可以断电自启，不依赖 JTAG。

**画面区域**：
- 左下半：串口启动日志 + `stat`；
- 右半：电源开关/插头、板卡电源灯、HDMI 屏幕从黑到亮。

**拍摄方式**：
- 手机固定，镜头覆盖电源、板卡和屏幕；
- 先拍 3 秒待机画面，再断电、等待、上电；
- 不要移动手机；如果启动等待较长，后期剪掉中间等待，但保留“黑屏 → 亮屏”的两次切换。

**指令顺序**：
1. 断开 12V 电源，等 5–10 秒；
2. 重新上电；
3. 等 HDMI 出现画面、串口启动信息打印完；
4. 串口发送：

```text
stat
```

**预期回显/画面**：
- 串口有启动回显；`stat` 打印 `[STAT] ctrl ... src=1 ...`，帧计数开始增长；
- 屏幕 OSD 第一行显示 `512X300  FPS:30  SRC:ETH` 或 `TEST`；
- 启动日志里不应出现 CRC/IDCODE 错误。

**剪辑方式**：
- 把断电黑屏和上电亮屏对齐到同一时间线；
- 启动日志滚太快时，只保留最后几行，或做 1.2 倍慢放；
- 字幕强调“QSPI BOOT.bin：FSBL + 位流 + PS 应用”。

**成片效果（文字描述）**：
右半屏的电源被断开，板卡和屏幕一起黑掉；几秒后重新上电，HDMI 自己亮起，左半屏串口开始打印启动信息。观众看到的是“断电 → 上电 → 画面自己起来”，没有 JTAG 下载动作。

**备用/删减**：如果冷启动失败，先修复再拍；不要用 JTAG 下载冒充冷启动。

---

### 5.3 区块 C · 视频通路区（0:55–1:35）

**演示目的**：展示从网线到屏幕的完整通路，以及同帧 A/B 竖缝。

**画面区域**：
- 左上半：推流脚本滚动发送帧数/包数；
- 左下半：串口 `stat`、`pipe show`；
- 右半：屏幕运动画面，竖缝左侧原图、右侧处理图；镜头缓慢推近 OSD 再拉回。

**拍摄方式**：
- 手机先拍全景 10 秒，再缓慢推近到屏幕左上角 OSD，停 2 秒，再拉回；
- 推近时不要遮挡屏幕，不要用手；
- 这一块是全片最重要的画面，至少拍 20 秒可用素材。

**指令顺序**：
1. 上方终端：

```powershell
python src/host/video_sender.py --demo --seconds 300
```

2. 等画面开始运动后，串口：

```text
stat
pipe show
```

**预期回显/画面**：
- 推流脚本打印发送帧数/包数；
- `stat` 帧计数持续增长，`src=1`；
- `pipe show` 打印当前九位效果码对应的级名；
- OSD 五行：
  - L0 `512X300  FPS:30  SRC:ETH`
  - L1 `Pipe:...  Th:...  Gamma:...`
  - L2 `Rot:0°  Zoom:1.00X`
  - L3 `Split:50%  Latency:...MS`
  - L4 `Temp:..C`

**剪辑方式**：
- 用推流脚本的输出和屏幕运动做同步点；
- 竖缝两侧各加一个小箭头，标“原图”“处理结果”；
- OSD 推近处做 1.2–1.3 倍放大，黄色框出 L0–L4；
- 同帧竖缝至少保留 5 秒稳定画面。

**成片效果（文字描述）**：
左半屏的终端开始滚动发送帧数，右半屏的画面开始运动；镜头缓慢推近屏幕左上角，OSD 五行清楚可见。屏幕中央的竖缝左侧是未处理原图，右侧是同一帧的处理结果，两侧的几何和行标签完全对齐。观众能同时看到“网线在收、屏幕在动、OSD 在读”。

**备用/删减**：如果推流不通，先 `ping`；不要用静态图片代替运动画面。

### 5.4 区块 D · 几何/效果区（1:35–2:20）

**演示目的**：展示九位效果码、缩放和任意角度旋转，以及竖缝跟着画面走。

**画面区域**：
- 左下半：逐条命令 + 回显；
- 右半：画面效果变化、放大、旋转。

**拍摄方式**：
- 手机固定全景，不要移动；
- 每条命令后停 2–3 秒，等回显和画面都稳定再发下一条；
- 旋转镜头至少保留 5 秒。

**指令顺序**：

```text
pipe 000010000
pipe show
zoom 1.5
rot auto 1
rot speed 2
```

**预期回显/画面**：
- `[PIPE] sel=... 生效: ...`，`pipe show` 打印级名；
- `[ZOOM] 1.5 → 最近档 1.50x（八档：...）`；

## 6. 拍摄执行顺序

### 6.1 按块拍，不按成片顺序拍

成片顺序是 A→B→C→D→E→F→G→H→I→J，但拍摄建议按设备状态分组：

1. **先拍 A 和 J**：板子默认状态，先拍开场和片尾，避免后面状态被改乱；
2. **拍 B**：断电/上电冷启动，拍完恢复默认；
3. **连续拍 C/D/E**：保持推流，按 C→D→E 顺序拍，减少反复起流；
4. **拍 F/G/I**：仪表和自检区；注意 UDP 1234 只能被一个程序占用；
5. **拍 H**：如果 SD 卡有内容，最后拍；没有就跳过；
6. **补拍 J**：如果片尾需要重新拉远，最后再拍一条。

### 6.2 每块的标准流程

1. 清屏，恢复该块需要的默认状态；
2. 手机和 OBS 同时开始录；
3. 拍手/说“X 开始”，停 2 秒；
4. 按该块“指令顺序”逐条执行，每条之间留 2–3 秒；
5. 说“X 完”，停 3 秒再停录；
6. 在拍摄记录里写：区块、take 号、是否可用、失败原因；
7. 每块至少两条 take，选回显完整、画面稳定的一条。

### 6.3 拍摄记录模板

```text
区块：C
take：2
开始/结束：00:12:30 / 00:14:10
PC 录屏文件：...
手机文件：...
命令是否完整：是
OSD 是否清楚：是
问题：推近时反光，take 1 作废
```

## 7. 剪辑流程

### 7.1 素材整理与同步

1. 按区块建文件夹：`A_开场`、`B_冷启动`……`J_收尾`；
2. 每个区块放入 PC 录屏、手机素材、拍摄记录；
3. 在剪辑软件里建 1920×1080、30 fps 序列；
4. 用拍手/“X 开始”做同步点，PC 和手机各放一条轨；
5. 以命令回显出现的那一帧，对齐屏幕发生变化的帧；必要时前后微调 1–2 帧。

### 7.2 分屏与排版

1. 左轨缩放到 960×1080，放左半；
2. 右轨（手机竖屏）按 960×1080 画幅裁切，保留屏幕 + 板卡的安全区，不要裁掉 OSD；
3. 中间加 2–4 px 深色分隔线；
4. 左半上下加标签条：`PC · 推流/自检/遥测`、`串口 COM6 · 板卡命令`；
5. 右半加标签：`Zynq-7020 · 1024×600 HDMI`；
6. 底部加字幕条；不要盖 OSD 左上角和串口最后一行。

### 7.3 局部放大与标注

- 终端/OSD 需要强调时，做 1.2–1.5 倍局部放大，持续 2–3 秒；
- 用黄色框标命令、回显和关键数字；
- 竖缝两侧加“原图/处理结果”箭头；
- 故障注入段标 `0 fps`、`14.3 aborts/s`；
- 不用花哨转场；区块之间硬切，只有片头/片尾用 0.3 秒淡入淡出。

### 7.4 字幕与旁白

- 每条字幕先写“命令”，再写“它改变了什么”，最后写“读数是多少”；
- 旁白按画面写，不照文档念；每个区块 2–4 句；
- 命令回显处可以静音 1 秒，让观众读数字；
- 不写版本号、日期、本机路径；需要指代时写“当前固件/当前镜像”。

### 7.5 音频与输出

1. 旁白降噪，音量保持稳定；
2. 背景音乐压低到不盖旁白；命令回显处可淡出；
3. 输出 H.264/H.265，1080p30，AAC 48 kHz；
4. 文件名用 `demo_full.mp4`、`demo_3min.mp4`，不带日期/版本号；
5. 导出后完整看一遍，检查左右同步、字幕遮挡和结尾。

- [ ] 终端历史已清，默认状态已恢复；

### 9.2 拍后

- [ ] 片尾保留四个亮点；
- [ ] 导出 1080p30，检查音画同步。

### 9.3 常见问题

| 现象 | 处理 |
|---|---|
| 推流不通 | 先 `ping`；检查 PC 网卡 `192.168.1.100/24`、防火墙、网线是否在 PL 侧 RJ45 |
| 串口无回显 | 确认 COM6 没被占用、115200；断电重上；先发 `help` |
| HDMI 无画面 | 确认面板输入源、分辨率 1024×600；OSD 第一行应有 `512X300` |
| 画面停在最后一帧 | 正常：停流后保持最后一帧；重新推流或 `src 2` |
| `link_selftest` 收不到 beacon | 先 `ping` 一次板子；确认没有别的程序占 UDP 1234；停掉 sender 再跑 |
| `link_selftest` 失败 | 这是仪表在报故障，不要重拍到“绿”为止；先看是 ARP、防火墙还是板子没流 |
| `sd files` 失败 | `sd remount`；等 2–3 秒再 `sd files`；卡必须是 FAT32 |
| OSD 不见了 | `osd on` |
| 板子状态乱了 | 按 2.2 的默认命令逐条恢复，最后 `stat` 对照 |
| 手机录制失败 | 用第二台手机/备用机位；PC 录屏必须保留，它是主线 |

## 11. OSD 五行怎么讲

| 行 | 屏上示例 | 讲解 |
|---|---|---|
| L0 | `512X300  FPS:30  SRC:ETH` | 片源 512×300、30 fps；当前源是 ETH 网络 |
| L1 | `Pipe:11000  Th:80  Gamma:1.8` | 九位效果码的屏上投影、二值化阈值、gamma |
| L2 | `Rot:45°  Zoom:0.75X(AUTO)` | 当前角度、缩放档位；`(Fit)` 表示缩放跟着角度 |
| L3 | `Split:50%  Latency:16MS` | 缝位百分比；PL 内部帧时延（不是玻璃到玻璃） |
| L4 | `Temp:62C` | 片上 XADC 温度；读不到时显示 `--` |

注意：

- L0 的尺寸是片源 512×300，不是面板 1024×600；面板尺寸在片头/旁白里说；
- L1 的 `Pipe:` 五位不是命令里的九位 0/1，而是“每一级选了第几个算法”；要解释当前开什么，发 `pipe show`；
- L2 的 `(Fit)` 与 `(Auto)` 互斥；
- L3 的 `Latency` 是 PL 内部时延，不包含编码/网线/面板；
- L4 的 `--` 是“还没有可信读数”，不是 0 °C。
