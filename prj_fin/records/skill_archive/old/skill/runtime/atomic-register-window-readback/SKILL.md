---

## 1. 一句话用途

多字读回必须是"一组"：撕裂读数与原子快照口。

## 2. 适用场景

- 当你有一组寄存器要**通过同一个读口逐个读回**（先写选择字段、再读数据），而这组数之间存在恒等式或包含关系（总时长 = 三段之和、计数 = 另两个字段之和、低 16 位与高 16 位同属一个量）。
- 当你读回"部分大于整体"这种物理上不可能的数。
- 当同一条恒等式**一会儿成立、一会儿不成立**。
- 当你准备把这组读数写进报告或屏上之前。
- 当你写的观测判据是"某个口应该等于某个值"，而不是"这一组数必须满足某个式子"。

## 3. 不适用 / 失效条件

- 这组数之间没有任何关系（各自独立的计数器）⇒ 撕不撕裂无所谓。
- 它们比"把整组读完一遍"慢几个数量级 ⇒ 风险可忽略（判据仍值得写下来）。
- 只有 1 个字可读，或你本来就有真正的原子广播口（一次读全组）。
- 恒等式在设计上就不成立（几段就可能来自不同轮次）⇒ "撕裂"永远为真：改口径或把字段拆开，**不许把判据改成"看起来不成立也算对"**。
- 武装必须是与数据**同域的电平**；若武装是跨域脉冲，本方法不成立，要走本包 pitfalls 类 `pulse-toggle-cdc` 那条写法，否则武装会被吃掉一半。
- 快照的新鲜度是**一个读周期**而不是当前值：别处（显示、闭环控制）当实时值用要先想清楚。
- 主机侧按"第 i 遍的 A 口配第 i 遍的 B 口"配对时，必须先确认每一口都读到了 i 个值；少读一口就错位 ⇒ 报出一个**假红**。没有对齐保证时把那条报成"不判"（null）并另给一个字段说明为什么没判 —— 假红比不判更糟，它教人去关门禁。
- 分界：本条管"一组读数的自洽"；换算式对不对在本包 pitfalls 类 `metrics-gap-sum`，"判据没判却报绿"的形状在本包 references 类 `bench-self-inflicted-reds`。

## 4. 前置条件

- 工具与版本：本包写作环境 Vivado/Vitis 2025.2.1 + Zynq-7020（本仓示例取值，需按自身工程替换）；本条与器件家族无关，只要求"索引 + 数据"型读口的存在。
- 需要的输入：这一组成员寄存器各自的可读偏移与位宽、读口的选择字段写法、能把整组逐个读回来的主机侧脚本（本仓用一条读数脚本连读若干组）。
- 需要的权限或硬件连接状态：调试器或固件能按选择字段读数据（本仓形态是 JTAG `mrd` + 一个 lane 窗口，示例取值）；台架侧要能对同一段逻辑再跑一遍以出对照。
- 判据先于修法：动手前必须已经有一条**主机侧**的恒等式判据（见 5.1），否则后面每一步都无从判读。

## 5. 使用方法

### 5.1 先写那条"撕裂"判据（它的价值在区分硬件错与读法错）

先问"这组数之间必须成立的式子是什么"，把它写成主机侧一条判据，字段名就叫"撕裂"这类。

完成后应看到：一组读数附带一个 `torn`/撕裂位；式子破了它为真、自洽它为假，且随每组读数打印。

### 5.2 判红后先怀疑读法，用最便宜的复核

连续读几组，看式子是不是**随机**破 —— 真缺陷稳定复现，撕裂随机。本仓实测形状：8 组里 3 组破，而"每轮都差不多大的那一段"最稳定，正是撕裂的指纹。

完成后应看到：一个"破的组数 / 总组数"与"哪一段最稳定"的分布，而不是单点结论。

### 5.3 读完整段 RTL 再下根因结论

如果这几个值写在同一个 always 块的同一拍，任何一次原子读必然自洽 ⇒ 违反恒等式只能是"我分几次读的"。

完成后应看到：一句明确写"同一拍写入"或"不同拍写入"的判断，并点名它来自哪段代码。

### 5.4 修在硬件里：给这一组加快照口（三条要点）

1. 武装信号取自**读法本身**（"选择字段指到这一组的第一个字"）⇒ 任何按正常顺序的读取自动得到快照，不需要新控制位、不动 BD；
2. 快照就是武装那一拍**同时**抄走全部成员（`if (arm) begin q_a <= a; q_b <= b; end`）⇒ 与抄的瞬间数据是否正在更新无关；
3. 读口导出快照，**live 值仍然留着**给台架对账 —— 台架要逐周期验"值对不对"，板级要"一组自洽"，两件事不能互相顶替。

完成后应看到：读第一个字那一拍之后，其余成员全部来自同一次抄写；台架侧仍能读到 live 值。

### 5.5 把读回顺序当成协议的一部分

武装既取自"选中这一组的第一个字"，那**任何后加入这一组的成员都必须排在那个第一个字之后**；先读它会拿到上一遍武装的那一轮，判据恒红，而且红的是脚本自己。

完成后应看到：顺序写进了表注释与顶层 mux 旁边（本仓的做法是把顺序直接写在读口注释里，示例取值）。

### 5.6 让快照自带"这一组可不可信"

组里有跨多拍算出来的成员（例如拍数换 ms 要 32 拍移位减），武装可能正好落在中间 ⇒ 连带抄一个"除法没在跑"的位；主机看见 0 就**既不判红也不判绿**。

完成后应看到：一个可信位随快照一起读出。这比多读几遍稳 —— 撞上它的概率 = 除法拍数 ÷ 一轮拍数（本仓约 2×10⁻⁵ ~ 3×10⁻⁶），靠重复采样是碰不出来的。

### 5.7 判据按读法写、不按寄存器写

在轮次进行中扫相位逐个武装并检查式子，同时打印判到的**可信样本数**。

完成后应看到：形如 `trusted=600 violated=0` 的一行（本仓例：600 个相位 ⇒ `trusted=600 violated=0`），而不是逐寄存器各打一个值。

## 6. 判读与失败分叉

| 检查 | 通过 | 失败 | 读不到输入 |
| --- | --- | --- | --- |
| 5.1 的"撕裂"字段（修后连读） | 修后连续 ≥8 组读数里撕裂字段**全为 false** ⇒ 进 §5 之后各步的收尾核对 | 仍有破的组 ⇒ 快照没生效或武装取错了对象，回 5.4 逐条对 | 脚本没读到某个成员口 ⇒ `NOT_MEASURED`；"少读一口"会伪装成撕裂，见 §3 最后第二条 |
| 反例先于结论：把判据先在"还会撕裂"的那一版上跑（同一块板、旧位流） | 它必须报红（本仓实测 5 组里 3 组红） | 旧版上也不红 ⇒ 判据是装饰，先修判据本身 | 拿不到旧版位流/旧版件 ⇒ `NOT_MEASURED`，不许跳过反例直接采纳 |
| 对照式台架判据：再跑一轮，看 live 与快照 | **live 变了而快照一动不动** ⇒ 快照有效 | 两者一起动 ⇒ 读到的还是 live，快照没生效；两者都不动 ⇒ 根本没在跑，与"快照有效"分不开 | 台架没有逐周期采样 ⇒ `NOT_MEASURED`，这一条对照必须补上 |
| 计数与可信样本数 | 判据打印可信样本数且 > 0 | 样本数为 0 ⇒ **单独判红**：忘清零的计数器初值是 X，`if (!cond)` 在 X 上两个分支都不走 ⇒ 一条什么都没判的判据会报成 PASS | 计数器没有打印出口 ⇒ `NOT_MEASURED`，先给尺子加分母 |
| 可信位（除法是否在跑） | 该位为 1 时式子才参与判定 | 该位为 0 ⇒ **既不判红也不判绿**（本条要求，不是跳过记录） | 读不到该位 ⇒ `NOT_MEASURED` |

三态只有 `PASS` / `FAIL` / `NOT_MEASURED`；"不判"不等于通过。

## 7. 已验证的效果

以下都是**旧卡登记的取证与本仓台账里的历史读数**（本条为迁移物；本轮任务禁止上板与构建，未重跑任何一次读数）：

- 撕裂的实测形状：修前同一条恒等式 8 组里 3 组破，而"每轮都差不多大的那一段"最稳定 ⇒ 判为读法错而非硬件错。出处 `report/log/ISSUES.md` `#59`（第一次读回时延就出现"分段比总长还长"）。
- 反例形状：把这条判据放在"还会撕裂"的那一版上跑，5 组里 3 组红 ⇒ 判据有牙。出处同上 `#59`。
- 修后的期望：连续 ≥8 组读数撕裂字段全为 false（本卡给出的完成判据，与修前 8 组破 3 组成对）。
- 计数为 0 的形状：`report/log/ISSUES.md` `#60` 登记"一条什么都没判的判据报成 PASS"（计数器初值 X，两个分支都不走）⇒ 本条把"样本数为 0 单独判红"写进判据。
- 本轮实际输出摘要：`【待验证】` —— 要跑的是"同一块板、同一份位流，连读 ≥8 组并打印撕裂字段与可信样本数"，并把这份输出连同反例那一跑一起存档；本轮没有采任何新数，也没有把上述历史件念成重跑结果。
- 跨多拍成员的可信位概率（2×10⁻⁵ ~ 3×10⁻⁶ 这一档）是本卡的算账，不是本轮实测：`【未实测】`，缺的是"扫相位统计撞上中间态的实际次数"。

## 8. 提炼来源与边界

- 来源证据：`report/log/ISSUES.md` `#59`（"分段比总长还长"与撕裂分布形状）、`#60`（什么都没判却报 PASS）；其余为迁移的旧卡（扁平卡 S18，退役后该文件不再存在）正文里的动作与判据文字。
- 恒成立 / 平台相关 / 版本相关：恒成立 —— "同一拍写入的多字段必然自洽，所以违反恒等式先怀疑读法"、"武装取自读法本身"、"读顺序是协议的一部分"、"样本数为 0 不能算通过"。平台相关 —— 索引窗口的位段、第一个字的编号、是否需要 BD 改动，都随目标工程的读口形状变（本仓的具体 lane 编号一律视为示例取值，需按自身工程替换）。版本相关 —— 调试器读数脚本的输出格式与 Vivado/Vitis 版本绑定。
- 不再适用的条件：数据之间没有恒等式；本来就有原子广播口；武装是跨域脉冲（改走 `pulse-toggle-cdc` 那条写法）；快照被当成实时值用于显示或闭环；设计上几段本就来自不同轮次（那时先改口径）。
- 迁移到新题目/新板卡要改的几处：① 这一组成员的名单与"第一个字"的位置；② 武装信号的取法（必须与数据同域电平）；③ 跨多拍成员那位"可信"的判据条件（本仓例是 32 拍移位减，别的换算长度要重算撞上概率）；④ 主机侧配对逻辑的"每口都读到 i 个值"保证；⑤ 台架侧 live 与快照的对照判据要在新工程里重写，不能沿用本仓字段名。
