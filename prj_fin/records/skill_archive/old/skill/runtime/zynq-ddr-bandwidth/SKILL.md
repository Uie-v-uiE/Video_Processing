## 1. 一句话用途

外部存储带宽账先算再动：突发拷贝按窗口算预算。

## 2. 适用场景

- 当你要在 SoC 的高速并行主口（HP 一类）上做 PL 整帧读写、乒乓双缓冲时。
- 当画面丢字 / 丢包，你想知道"到底是带宽不够，还是别的问题"时。
- 当有人提议"再深一层缓冲 / 再加一个读口"来治丢包时。
- 当你准备选分辨率、或决定缓冲放片上还是放外部存储时。

## 3. 不适用 / 失效条件

- 匀速、连续的数据流：那种按平均速率比就够了，"窗口预算"这一步是多余功课。
- 同一端口上还有其它主设备抢占的系统：本算法只覆盖"一条通路独占"，共享时要按最坏重叠情形另算一笔。
- 画质 / 肉眼类问题：先按分层定位排除数据面 —— 那是 `skill/zynq-video-rtl-debug/SKILL.md`（旧编号 S8）与 prompts 类 `eye-acceptance-loop`（旧编号 S23）的范围。
- 失效：任何改变往返延迟的事（别的 master 抢占、拷贝调度改动、时钟比变化）都会让这笔账整体作废，要重算 —— 在途深度是上限的来源。
- 失效：位宽 / burst 长度 / 单次传输的拍数上限必须与配置里的这条端口一致，并受协议版本限制（例：AXI3 单 burst ≤16 拍已经贴上限，换 AXI4 这条就变了，要重读协议）。
- 估算类数字（功耗、温升）在没有开关活动文件时置信度很低 ⇒ 只能做相对比较，念的时候要把置信度一起念出来。
- 算不出出处的数字就删掉、写"未验证"，不许引用。
- 相邻条目的分界：丢字率这类数**怎么量出来**（逐帧变化的图案、发完再读）见 pitfalls 类 `frameid-loss-signature`（旧编号 S9）；同一单口存储器被分时成 N 次访问、以及"再加一个读口"的真实代价探针见 pitfalls 类 `derived-clock-port-mux`（旧编号 S10）；跨域脉冲与配对基线门禁见 pitfalls 类 `pulse-toggle-cdc`（旧编号 S11）与 `cdc-pair-baseline-gate`（旧编号 S16）。

## 4. 前置条件

- 工具与版本：本包写作环境 Vivado/Vitis 2025.2.1 + Zynq-7020（本仓示例取值，需按自身工程替换；器件换代时本条的数字全部重取）。
- 需要的输入：配置里**实际**的端口时钟与位宽、每帧字节数（宽 × 高 × 每像素字节）、可用窗口的拍数、片上存储块的种类与数量。
- 需要的复算工具（两样都要有）：层次化的存储归属报告，和把突发拷贝等效成"端口被独占 N 拍"的**限速从机**台架。本仓对应物：`build/tcl/report_mem_hier.tcl` 与台架 `tb_v6_vblank_copy`（本仓示例取值，需按自身工程替换）。
- 需要的权限或硬件连接状态：本条全部是算术与台架，纸面即可开始；只有"包内相位"那一签名要板级或台架读数。

## 5. 使用方法

### 5.1 先把参数取实（"公式对、参数错"最常见）

1. 帧字节按实算（宽 × 高 × 每像素字节；例：本仓库一帧 307200 B，折成 64bit 字是 38400 个），时钟与位宽也按配置里的**实际**值取，别沿用文档里"看着眼熟"的那个数。
2. 先算上限 = 时钟 × 位宽（例：本仓库 100 MHz × 64 bit = 800 MB/s；按 50 MHz 算会得 400 MB/s，差一倍）。

完成后应看到：一行写"实钟 × 实位宽 = 上限"，并注明这两个数取自配置而不是文档。

### 5.2 突发类拷贝按窗口算预算

整帧拍数 ÷ 可用窗口拍数 = 每周期最少要交出的拍数，换算成带宽再与上限比。例：一个 67200 周期的消隐窗口里搬 38400 拍 ⇒ 下限 ≈0.571 拍/周期 ≈ 457 MB/s，即上限的 57 %。

完成后应看到：一个"窗口下限带宽 / 端口上限"的百分比。按平均速率算会把这件事完全掩盖掉。

### 5.3 吞吐 = 在途深度 ÷ 往返延迟，先数在途再谈峰值

逐字等写响应时在途恒为 1，上限就是 字长 ÷ RTT（例：RTT ≈40 拍 @100 MHz ⇒ ≈20 MB/s）。如果主机侧给的速率只剩 1.3× 余量，任何一次别的抢占都会把它压到线以下。

完成后应看到：一句"在途 = N、RTT = M 拍 ⇒ 上限 = …"，而不是一句"峰值带宽够用"。

### 5.4 提高在途深度的改法（以及它的卡死风险）

流水化写通道：地址与数据同拍挂出、各自保持到被接收；响应只回收计数、不阻塞数据通路。并且"这一轮完成"的条件要包含**在途已清零** —— 响应计数回绕会造成永久卡死。

完成后应看到：完成条件里有一项是在途计数归零，而不是只等最后一拍响应。

### 5.5 在提"加深缓冲"之前先把那道算术题做完

吸收一个窗口需要的深度 = 到达速率 × 窗口时长，换算成片上存储块数（按每块容量折）再与全片总量比。例：本仓库算出要 ≈84 个大容量 BRAM 块，而全片只有 140 ⇒ 这条路**结构上不可行**，是被算术否掉的，不是被一次失败劝退的。

完成后应看到：两个数（需要的块数 / 全片块数）与一句明确的"可行或否掉"。

### 5.6 处理器写完外部存储后必须做缓存维护

clean / flush 到一致，可编程逻辑才看得见新数据；外设直接 DMA 进存储的通路不经过处理器缓存，**别拿这条去解释那一路的现象**。缓存维护本身的写法与判据住在同包 runtime 类条目 `dma-cache-coherency`，本条只记这笔账在哪一路线上成立。

完成后应看到：结论里写清了"这一路经过处理器缓存"还是"那一路不经过"。

### 5.7 留两样复算工具

层次化的存储归属报告（谁吃掉多少块，本仓 `build/tcl/report_mem_hier.tcl`）+ 限速从机台架（把突发拷贝等效成"端口被独占 N 拍"，本仓台架名 `tb_v6_vblank_copy`）。

完成后应看到：块数归属能逐层读出来；限速从机能把速率按档扫。

## 6. 判读与失败分叉

| 检查 | 通过 | 失败 | 读不到输入 |
| --- | --- | --- | --- |
| 限速从机扫几档速率 | 最慢那一档表现成"**溢出到下一个窗口，但不写有效区、不重复、不越界、看门狗不误杀**"。本仓例：800 / 560 / 480 MB/s 都在一个窗口内完成，320 MB/s 溢出但无副作用 —— 这才叫窗口预算被钉住 | 溢出写进有效区 / 重复 / 越界 / 看门狗误杀 ⇒ 窗口预算没被钉住，先回 5.2 重算，别先加深缓冲 | 台架跑不出速率档（没有等效从机）⇒ `NOT_MEASURED`，本条判据未成立 |
| 包内相位签名 | 丢字率对包内字节偏移呈**固定台阶**（本仓例：头 48 字节约 6.7 %，其后 54~64 %），且连续丢字带很短、没有整包段 ⇒ 判"不是深度问题、是排空速率问题"，动 5.4 的流水化写通道 | 台阶形状不出现 ⇒ 别再往"加深"上花钱，改查别的层（数据面通断、对齐边界） | 拿不到逐字节偏移的丢字分布 ⇒ `NOT_MEASURED`；"肉眼看着还行"不是这一格的输入 |
| 流水化写通道之后复跑同一判据 | 同一判据回到全档 100.0 %、各相位带 0.0 %（本仓历史读数） | 仍有相位带非 0 ⇒ 在途深度还没真起来，或 RTT 变了，回 5.3 | 只跑了改后没跑改前 ⇒ `NOT_MEASURED`，缺对照不算效果 |
| 参数复核 | 引用的每个带宽数字都能说出实钟与实位宽 | 说不出 ⇒ 删掉或写"未验证"，不许引用（本仓旧文档里那句"400 MB/s"传了十几版没人复核） | 配置读不到 ⇒ `NOT_MEASURED`，先取实配置 |
| 加深缓冲的算术 | 需要的块数 ≤ 全片块数 ⇒ 才允许做 | 需要 ≈84 块而全片 140 这类"结构上不可行" ⇒ 被算术否掉，方案直接停 | 没有块数账（归属报告缺失）⇒ `NOT_MEASURED`，先跑 5.7 那份报告 |
| 缓存维护这一路 | 处理器写完外部存储后做了 clean/flush，PL 看得见新数据 | 读不到新数据 ⇒ 先分清是不是"外设直接 DMA 进存储"那一路（不经缓存，不该用这条解释） | 无法确认走的是哪一路 ⇒ `NOT_MEASURED` |

三态只有 `PASS` / `FAIL` / `NOT_MEASURED`。

- 恒成立 / 平台相关 / 版本相关：恒成立 —— "吞吐 = 在途深度 ÷ 往返延迟"、"突发拷贝按窗口算而不是按平均速率"、"加深缓冲先用块数算术否掉或肯定"、"算不出出处的数字就删掉"、"在途计数回绕会永久卡死"。平台相关 —— 307200 B/帧、38400 字、100 MHz × 64 bit = 800 MB/s、67200 周期窗口、RTT ≈40 拍、≈84/140 块、800/560/480/320 MB/s 这几档、头 48 字节的台阶位置，全部是本 SoC 本配置的数（本仓示例取值，需按自身工程替换）。版本相关 —— AXI 协议版本决定单 burst 拍数上限，端口时钟比与配置方式随工具流程变。
- 不再适用的条件：数据流匀速连续（平均速率就够）；端口被多主设备共享（本算法只覆盖一条通路独占）；器件或端口换代（位宽、块容量、burst 上限全变）；问题根本不在数据面（先按分层定位排除，见 S8）。
- 迁移到新题目/新板卡要改的几处：① 实钟与实位宽（上限的来源）；② 帧字节与折字后的拍数；③ 可用窗口的拍数与"窗口下限带宽"这一比值；④ 实测 RTT 与由此推出的单字上限；⑤ 片上存储块的种类与数量（加深缓冲那道算术题的两个数）；⑥ 限速从机台架与归属报告换成目标工程实际有的两件复算工具，档位也要重取。
