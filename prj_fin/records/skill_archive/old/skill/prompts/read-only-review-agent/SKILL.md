## 1. 一句话用途

让只读代理通读找 bug，但只有能指出行号的才算发现。

## 2. 适用场景

- 当构建或长仿真占着机器（这里是一轮 12–15 分钟的实现、一趟 75–90 分钟的顶层台架，本仓示例取值，需按自身工程替换），
  你手里有一段不能碰 `src/rtl`、也不能再开一个仿真进程的时间，而你需要的是"整批代码里还有什么坑"。
- 当你愿意接受"候选清单 + 我来复核"这种分工，而不是要代理给结论时。
- 当你要把一次 AI 评审变成台账里可核对的账（交回多少条、进正文几条、降级几条、不采信几条）时。
- 当你怀疑自己刚写的代码，但需要的是**第二双眼睛**而不是另一台台架时。

## 3. 不适用 / 失效条件

- 你要的是**结论**而不是候选（例如"这一族违例的成因"）：那需要测量，测量必须由主代理做，
  因为凭据要能被 `gates.sh` 与文档引用。
- 代码正在被构建读（`src/rtl`）：任何写入都会让 `rtl_md5` 与在跑的那一跑对不上（`report/log/ISSUES.md` #123 的机制）。
- 评审对象是你自己十分钟前刚写的东西：那需要的是台架判据，不是第二双眼睛。
- 只说"read-only"就算给了边界：不够——代理会读得很开心，然后顺手改文件、顺手跑脚本；这是最容易污染仓库的一种委托。
- 代理读不到的东西仍然读不到：它给不出**时序收敛、板级观感、上位机协议**这三类判断，那些只有测量与眼睛能给。
- 把"交回条数"当成果：结论数量不是成果（见 §6 的 8 条 → 1 条那一例）。

## 4. 前置条件

- 一段在飞构建/长仿真的窗口（示例取值，需按自身工程替换：一轮 12–15 分钟的实现、一趟 75–90 分钟的顶层台架），
  以及这段时间里**不许**发生的动作清单。
- 具体到不能解释的禁令原文：`禁止改文件、禁止跑仿真、禁止跑 src/host 下任何会碰 COM6/JTAG 的脚本`——
  本项目里 `src/host/metrics.mjs` 这类"看起来像检查器"的脚本会占串口并改写留档。
- 要查的缺陷族**列成类**（不是问"有没有 bug"）。本次五类：控制字位分配是否与 RTL 读者一致 /
  解析器的范围检查与错误路径 / 回读字段是不是硬件真值 / 会挂死或无限打印的错误路径 / 符号与位宽绕回。
- 主代理一侧的逐条回读时间（这一步是本条的全部价值，没有它整条委托就是污染）。
- 台账位置：能指出行号的那几条要进文档；指不出的写成"下一步该量什么"。

## 5. 使用方法

### 5.1 提示词正文（整段复制，先填 5.2 的槽位）

```
你是我的**只读代码评审**代理。第一段就是硬边界，不许解释、不许试探：
禁止改文件、禁止跑仿真、禁止跑【填入】下任何会碰串口/JTAG/在线硬件的脚本；
禁止执行任何"看起来像检查器"的脚本（它们会占串口并改写留档）。
你只读、只报，执行与改动由主代理做。

【本轮事实（全部由我填；我没给的数字不许补）】
- 评审范围（目录 / 文件清单）：【填入】
- 要查的缺陷族（按类列，不要问"有没有 bug"）：【填入】
- 正被构建读取、因此禁写的目录：【填入】（在飞的那一跑会把它的内容算进校验和）
- 每条发现的强制格式：file:line + 那几行原文 + 自称 CONFIRMED 还是 CANDIDATE：【已写死，不许改】
- 主代理回读的排期与台账位置：【填入】

第 0 步 · 先取证再报：输出 A"我读过哪些文件的哪些行"（路径 + 行号）与
  B"我做了哪些假设（已确认/未确认）"。打不开的文件就不许据此下结论——直接写"读不到"。

第 1 步 · 按缺陷族逐类扫，不要问"有没有 bug"。每条发现必须：
  - 带 `file:line`，并抄出那几行原文；行号不确定就写"不确定"，**不要估**；
  - 自称 CONFIRMED（能指出行号、机制说清）或 CANDIDATE（要先加探针/要先量）；
  - 一句"若成立会在什么条件下出错"，以及一句"这条我没能证伪的部分是什么"。

第 2 步 · 计数自报：交回时先给三个数——共 N 条 / 其中能指出行号 M 条 / CANDIDATE K 条。
  没给出行号的一律标 CANDIDATE，不许混进 CONFIRMED。

第 3 步 · 不许在评审轮里提议行为改动。要提的改动只许是这两类：
  一条打印格式、一条文档位表——都不改变正常路径（正温度/正路径）下的任何一个字节输出。
  需要动语义的（例如改控制字位分配 = 动上位机契约）只能写成"这条今晚不改的理由 + 缺哪一格"。

第 4 步 · 输出契约（顺序写死）：
  1) A 节读过的文件 + 行号
  2) 三个计数（N / M / K）
  3) 逐条表：`file:line` | 原文摘录 | CONFIRMED|CANDIDATE | 若成立的后果 | 建议的下一步测量
  4) 你**没查到问题**的族（按类点名，并写"这一类我只读了这些文件"）
  5) 需要用户/主代理那一格的条目（缺批准、缺测量、缺验收）
  没有数据处写【未实测】；禁止引用我不存在的报告或台账编号；
  禁止把注释里的数字当事实；禁止"通常/一般来说"式措辞。

第 5 步 · 停止条件（任一命中就停下报我）：
  你被要求改文件或跑脚本（越界，立即停）；某个族需要测量才能判（交回主代理，别猜）；
  同一条判据连续 3 次说不清——停下说明卡在哪一条，不许用"可能的隐患"凑条数。
```

### 5.2 槽位清单

| 槽位 | 该填什么值 |
|---|---|
| 评审范围 | 目录/文件清单，逐条写死；本仓示例取值，需按自身工程替换（如 RTL 目录、上位机脚本目录） |
| 缺陷族 | 五类那种写法：一类一句、可判定、不含"整体质量如何" |
| 禁写目录 | 正被构建读取的那一份源码目录（写入会作废在跑那一跑的 `rtl_md5`，见 #123 的机制） |
| 禁跑脚本目录 | 会碰串口/JTAG/在线硬件的脚本所在目录（本仓示例取值：`src/host`） |
| 回读排期与台账 | 主代理逐条回读的时间 + 台账文件；没有排期就别发这一轮 |

### 5.3 执行步骤

1. 把 §5.1 第一段（硬边界）与槽位一起发出。**完成后应看到**：代理先答 A 节"读过哪些文件的哪些行"。
2. 收三个计数（N / M / K）。**完成后应看到**：三个数字；M 就是候选进正文的上限。
3. **主代理逐条回读**（这一步是本条的全部价值）：能在盘上指出那一行的才进文档；指不出来的降级为"下一步该量什么"，不写成发现。
   **完成后应看到**：每条一个处置（进正文 / 降 CANDIDATE / 不采信），并写明不采信的理由。
4. 顺手挑一两条自己动手。**完成后应看到**：要么只改了"会说谎的那一行"（如打印的符号位），要么写清"今晚不改的理由"
   （改控制字语义 = 动上位机契约；没有能红的判据；需要用户那一格）。
5. 检查本轮落地的改动形状。**完成后应看到**：只有一条打印格式、一条文档位表这类——都不改变正温度/正路径下的任何一个字节输出。
6. 把账写进台账。**完成后应看到**：一行"16 → 8（6 CONFIRMED + 2 当场修）/ 4 CANDIDATE / 其余不采信"那种可核对的形状。

## 6. 判读与失败分叉

- **通过（一次可量化的复核收益）**：代理交回 16 条 ⇒ 主代理回读后 **8 条进正文（6 条 CONFIRMED + 2 条当场修掉）**、
  4 条降为 CANDIDATE、其余不采信（它们把注释里的数字当事实，或与我已知的债重复）。凭据在 `report/log/ISSUES.md` #125。
  这不是一句"AI 帮我找到 bug"。
- **结论数量不是成果**：第二轮把同一把尺子对准 RTL（`report/log/ISSUES.md` #127）时它交回 8 条，逐条回读后只有
  **1 条**是能指出行号的真缺陷、**3 条**是"先加探针再谈改"的候选（四条 CANDIDATE 各欠一条机会计数探针）；
  如果把 8 条全记进台账，就等于让"扫过一遍"冒充"查清楚了"。
- **降级的去处**：指不出行号的发现 ⇒ 改写成"下一步该量什么"，进债清单，不进正文。
- **越界（改了文件 / 跑了脚本）**：立即终止本轮，先核对在跑那一跑的身份读数还对不对得上（`rtl_md5` 一类，#123 的机制），
  作废的凭据重跑，不要用同名文件的旧内容补数。
- **代理读不到**：时序收敛、板级观感、上位机协议这三类它给不出判断 ⇒ 分别交给测量、`../eye-acceptance-loop/`、协议侧判据。
- **要的其实是结论**：本轮不产出（§3 第一条）；把问题改写成"能指出行号的候选"再委托，否则凭据来源不明。
- **3 次不过**：停下，列出试过什么与卡在哪一条，等人类裁决。

## 7. 已验证的效果

- 两轮同法实测（旧卡记录，逐条保留）：
  - `report/log/ISSUES.md` #125（一夜"遍历代码"的最后一轮：只读评审 + 主线程逐条复核）：交回 **16** 条 ⇒
    进正文 **8** 条（**6** 条 CONFIRMED + **2** 条当场修掉）、**4** 条 CANDIDATE、其余不采信。
  - #127（第二轮同法扫 RTL 的"越界写"那一族）：交回 **8** 条 ⇒ **1** 条能指出行号的真缺陷、
    **3** 条"先加探针再谈改"的候选、四条 CANDIDATE 各欠一条机会计数探针。
- 本轮落地的改动形状：一条打印格式 + 一条文档位表（都不改变正温度/正路径下的任何一个字节输出）——旧卡记录，
  具体文件名与 diff 行数 `【未实测】`（旧卡未抄，引用前直读 #125）。
- 基线对比（不用本模板）：`【待验证】`。需同一提示词连跑 3 次并记录"交回条数 / 能指出行号条数"之比与
  "越界（改文件、跑脚本）发生次数"；目前 0 次，**还差 3 次**。

  肉眼那一格由 `../eye-acceptance-loop/` 管；代理自己造的红与绿的签名对照见 `../../bench_self_inflicted_reds.md`（旧扁平卡路径）。
