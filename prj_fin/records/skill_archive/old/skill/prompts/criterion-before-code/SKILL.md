name: criterion-before-code
description: 给智能体的提示词模板：在动任何 RTL/固件/代码之前，先要求它把"这条缺陷要让哪一把尺子红"写出来并做出能红的对照，再改代码。当协作 agent 打算直接改源码、当一条新判据第一次跑就绿、当症状是"屏上没现象但说不清被什么门住"、"台架绿而硬件仍错"、"改动没有对应读数"、或当你要把一次修复写进正式报告却没有凭据时使用。已经有一条被反例证明能红的判据、纯文档修订、或只是复现别人已修过的同一缺陷时不要用。
---

## 1. 一句话用途

让 agent 先造出一条能红的判据，再允许它改代码。

## 2. 适用场景

- 当协作 agent 提出"我改这几行就好了"，而盘上没有任何一条读数会在改坏时变红时。
- 当一条新写的判据第一跑就绿，而它要判的缺陷确实存在（人眼已看见、或另一处已量到）时。
- 当"台架全绿 + 板上仍错"或"门禁全绿 + 文档念的是上一版"这类分裂出现时。
- 当一次修复要进正式报告，而报告里那一句需要"改前红 / 改后绿"两份凭据时。
- 当你自己（或 agent）准备把"没看见问题"写成"没有问题"时。
- 当判据的比较对象与它声称在判的对象可能不是同一个东西（自指门禁、读自己刚写的文件）时。

## 3. 不适用 / 失效条件

- 已有一条被反例证明能红的判据、且这次只是执行：直接进入改动与复跑，别再要一次判据设计（重复造尺子会掩盖真账）。
- 纯文档措辞修订且没有检查器引用这段文字：判据设计这一步不产出信息（若文档被某把尺子按文本引用，那就仍适用，并按引用它的正则重新核一遍射程）。
- 等价性/形式验证类任务：那里没有"激励维度"这件事，本模板的机会计数地板要换成覆盖域定义。
- 缺陷只能由人眼判（屏上现象、按键手感、演示动线）：本模板只造机器判据，眼睛那一格要单列成验收行，不许伪装成 PASS。
- 判据要判的本来就是恒真式（拿时序台架验纯组合译码）：要换判据类型，加维度不会让它变红。

## 4. 前置条件

- 一段对缺陷的可观察描述：什么条件下出现、看见什么算出现、看见什么算消失（三件缺一就先补齐）。
- 能跑起来的最小验证入口：一支单元级台架/测试脚本 + 工具路径探测（找不到就在第一步拒绝，不许跑出半截产物）。
- 一次"不改动"的基线跑：当前判据清单与逐条红绿（本仓库把这类读数归档成 `rNN` 一件，示例取值，需按自身工程替换）。
- 修改权限的边界声明：哪些目录这轮不许动（RTL 在构建在飞时改动会静默重新综合，把对照作废）。
- 时间预算：写清"造一条能红的对照"与"跑一轮全量回归"各要多久（两个数字），先跑耗时小的那一档、
  把耗时最大的整屏级判据留到采纳时——本仓库的实测形状写在 `skill/pitfalls/ab-revert-control-run/SKILL.md`
  的失效边界一节（单元级台架约一分钟、整屏台架 85 分钟）。

## 5. 使用方法

### 5.1 提示词正文（整段复制，先填 5.2 的槽位）

```
你是我的验证判据设计 agent。本轮规则：在你拿出"能红的判据"之前，我不允许你改被测代码。
你现在只输出文本与判据设计，不写 RTL、不改固件。

【本轮事实（全部由我填；我没给的数字不许补）】
- 缺陷的可观察描述：【填入】（触发条件 + 看见什么算出现 + 看见什么算消失）
- 被测对象与入口：【填入】（模块/文件/顶层名 + 单跑一条台架的命令）
- 现有判据清单与当前红绿：【填入】
- 工具路径与环境变量（探测不到就要拒绝）：【填入】
- 本轮不许动的目录/文件：【填入】
- 一次判据跑的耗时预算：【填入】

第 0 步 · 先取证再作答：输出 A"我读过哪些文件的哪些行"（路径 + 行号）与
  B"我做了哪些假设（已确认/未确认）"。没有任何可打开的被测文件或缺陷描述含糊 ⇒
  回答"信息不足，请提供 X"并停住。

第 1 步 · 把缺陷翻译成一个可观察谓词，写成一句可判真假的话，句式：
  "当【激励条件】时，读数【字段名】应当【期望值/区间】；现在读到【实际值或【未实测】】。"
  禁止用"正常/没问题/符合预期"这类词。

第 2 步 · 空位检查（动笔之前，五分钟）：
  - 问一句：使该谓词可观察的背景 / 对比度 / 余量，在你打算用的激励里存在吗？
  - 若被检对象铺满整个域 ⇒ 该谓词在此档位结构上恒真 ⇒ 换激励维度，不是换阈值。
  - 输出：这一格的激励里，缺陷能站身的那一格是哪一格，指得出就说，指不出就说指不出。

第 3 步 · 机会计数地板（先于结果）：判据必须**先数出一个非零的"机会"**，再谈伤害有没有发生。
  - 写一条计数行：本轮激励里"本来有可能出事"的拍数/样本数 = ?
  - 定一个下限（示例取值，需按自身工程替换：模板作者原工程用过"有画面的行数 > 200"、
    "文档锚点命中 >= 300"这类射程地板），并把下限与被检判据同生共死：
    计数不达标时那句绿不算通过，把下限调低更不算修好。
  - 若机会数 = 0 ⇒ 判据此刻没牙，必须扩激励或换维度，禁止把它列入通过项。

第 4 步 · 变异对照（这一步是本轮的交付核心）：
  - 给出一个"把修复前的写法/被门住的那道门拆掉"的最小改动，并指明它**该红哪几条判据**（列编号）。
  - 规矩：一次变异只许红它声称红的那几条；红不了 ⇒ MUTATION FAILED（判据没力），
    红多了 ⇒ 变异污染（一次测了两件事），两种都算失败。
  - 对照必须可逆：说明怎么在拷贝树上做（不要把变异写进真源），并写明"拷贝与原件的
    差异行数上界"，对不上就拒绝继续。
  - 若门有多道：明确写"拆一道门可能仍然绿（冗余门），这不是对照失败，这是发现有两道门"，
    并给出必须同时拆掉的那几道。

第 5 步 · 判定形状必须把"红"与"没数"分开：
  - 判据通过打 PASS；判红打 FAIL 并打印"首个差异位置 + 期望 / 实际 + 计数器值"；
  - 读不到输入 / 一条判定都没打 ⇒ 第三态（NOT_MEASURED / NO-VERDICT-LINE），
    绝不许与 PASS 共用同一句收尾，也不许用退出码 0 表达它。
  - 判据标签与 token 用 ASCII（编码转换会把长标签从左边截掉，让一条判据在日志里消失）。

第 6 步 · 反查自指：这条判据读的文件是谁写的、什么时候写？
  - 若判据读的对象正是它自己或它的调用者刚写的那份 ⇒ 明确写出"读的被判的是同一对象"，
    并给出不自毁的写法（先写临时文件，全绿之后再落正式件）。
  - 若一条判据第一次跑就大片红 ⇒ 先怀疑度量，再怀疑被测物（并排给出两种解释各自由哪条读数区分）。

第 7 步 · 输出契约（顺序写死）：
  1) 谓词句（第 1 步那句）
  2) 判据编号 + 每条的"该红条件"与"该绿条件"
  3) 机会计数行与下限
  4) 变异对照：改动位置、声称红哪几条、期望退出码
  5) 三态收尾的打印格式原文
  6) 还缺什么才能升格（缺一条就写出来）
  没有数据处写【未实测】；禁止引用我不存在的报告；禁止"通常/一般来说"式措辞。

第 8 步 · 停止条件：缺陷描述无法变成谓词、机会数恒为 0、或变异无法只红目标判据时，
  停下告诉我卡在哪一条，不要绕路、不要弱化判据。
```

### 5.2 槽位清单

| 槽位 | 该填什么值 |
|---|---|
| 缺陷的可观察描述 | 三件：触发条件 / 出现时看到什么 / 消失时看到什么（缺任一件先补再发） |
| 被测对象与入口 | 模块或顶层名 + **一条命令**能跑起对应台架/测试（本仓库示例取值，需按自身工程替换：`bash sim/run_one.sh <台架名>`） |
| 现有判据清单与当前红绿 | 判据编号列表 + 每条当前 PASS/FAIL/没判；从最近一次跑的输出直接抄 |
| 工具路径与环境变量 | 仿真/综合可执行文件所在目录变量名；写清"探测不到就要拒绝并念出变量名" |
| 本轮不许动的目录/文件 | 构建在飞时禁改的源码目录、需要另建的归档目录 |
| 一次判据跑的耗时预算 | 秒或分钟；超预算就先降级到单元级 |
| 机会计数下限 | 你自己那一维的非零下限（示例取值需替换：本仓库用 "有画面的行数 > 200"、"锚点命中 >= 300"） |

### 5.3 执行步骤

1. 填槽发出。**完成后应看到**：第 0 步 A 节先出现，且路径你能在盘上打开。
2. 只看第 1 步的谓词句。**完成后应看到**：一句可判真假的话，含字段名与期望区间，无"正常/符合预期"。
3. 看第 3 步机会数。**完成后应看到**：一个非零数字 + 下限；若为 0 ⇒ 退回第 2 步换维度，别进入改动。
4. 看第 4 步变异对照。**完成后应看到**：改动位置 + 声称红的判据编号 + 期望退出码三件齐全。
5. 自己在拷贝树上执行该变异（真源不动），跑判据。**完成后应看到**：`MUTATION OK`（恰好红那几条）；否则按第 6 节分叉处理。
6. 只有第 5 步过了才允许写修复。**完成后应看到**：改前红件与改后绿件**两份**同时留档，命名可配对。

## 6. 判读与失败分叉

- **通过**（变异恰好红目标判据，撤掉变异后绿）：把该判据加进回归清单，并在报告里引用改前/改后两份凭据路径。
- **MUTATION FAILED**（拆了门仍然绿）：判据没力 ⇒ 回到第 2/3 步换激励维度或补机会计数；**不要**改阈值，也不要删掉这次对照——它本身是"这里结构上红不了"的凭据。
- **红多了**（一次变异红多条）：一次测了两件事 ⇒ 拆成两条变异，或把共享的那条判据标为"跨域"并单独记账。
- **机会数 = 0**：本轮激励里没有缺陷能站身的一格 ⇒ 扩激励（补自变量维度、加高频图案/细线/反压），或在报告里明写"未覆盖"，不许写"通过"。
- **读不到输入**（工具路径错、台架文件缺）：这是第三态，退出码不许为 0；下一步修脚本的探测与拒绝，不去怀疑被测逻辑。
- **判据在日志里消失**：先查标签字节数/编码截断与"是否只有唯一一个进程在写这份日志"（残留进程会把两跑的行混进同一文件，md5 也对得上）。
- **3 次不过**：停下，列出你试过什么、卡在哪一条，等人类裁决。

- 提炼来源：`sim/mut_control.sh`（#91）、`report/LLM_COLLAB.md` 例 2 与例 6、`skill/pitfalls/criterion-blind-spot/SKILL.md`、`skill/references/bench-self-inflicted-reds/SKILL.md`、`build/gates.sh` 的 D5/D6 射程地板、`sim/run_one.sh` 的三态退出码（2026-10-01 07:40：0 绿 / 1 编译失败 / 2 REFUSE / 3 判红 / 4 认不出判定）、`report/log/ISSUES.md` #91/#103/#127/#128/#162/#163/#164/#166/#194。
- 迁移到新题目要改：机会计数的维度（这里是"越界拍数"，图像题可能是"越界索引"，网络题可能是"残包数"）、下限数值、ASCII 标签长度限制、"门有几道"的冗余判定。
- 失效边界：当缺陷只在真实硬件/真实协议栈上出现而仿真器行为不同（本仓库实测的一类差异：越界写在仿真里被丢弃、硬件按地址位宽截断），本模板造出的判据只能证明"机会有 N 拍"，不能代替板级那一格；那一格必须走人眼或板级读数，并在验收表里单列。
- 与相邻条目的分界：本页管"判据能不能红"；一次改动只测一件事由 `../single-variable-ab/` 管；真红名单归因由 `../../ab_revert_control_run.md`（既有卡片）管。
