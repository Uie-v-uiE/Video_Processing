---

## 1. 一句话用途

让 agent 从报告里定位真瓶颈，并交出逐时钟域花名册与下一刀候选。

## 2. 适用场景

- 当 `build/`（或你的报告归档目录）里存在时序汇总、资源利用率、方法学、布线状态这类报告，而你要回答"下一刀切哪里"时。
- 当有人只念一个数（全局 WNS / 最差那一条路径）就说"这版比上版好"时——本模板强制把这句话展开成逐域。
- 当时钟被改名、或由时钟向导/时钟网络重新源化之后，slack 读数发生移动时（覆盖面丢失是静默的，报告不会报错，只会让那一行消失）。
- 当 `check_timing` 报出未加输入/输出延迟的端口，或方法学报告里有 Critical 级条目时。
- 当候选是物理优化手段（高扇出复制、控制集复制、Pblock、实现指令）而工具侧机制证据还没拿到时。
- 当两次构建之间的数字移动需要判定"是真的还是波动"、而你手上有已铺好的检查点时。

## 3. 不适用 / 失效条件

- 盘上没有报告文件，只有口头描述或别人的截图：此时任何 slack 结论都是猜，走"要文件"分支，不要用本模板。
- 你要的是"这段算法放处理器还是可编程逻辑"：那是划分问题，用 `../hw-sw-partition/`。
- 报告不是同一套产物拼出来的（位流与报告不同一次构建）：先做新鲜度与身份核对，否则花名册在比两套身份。
- 单时钟、少量端口、约束全部由工具自动生成且从没被改过名字：逐域花名册与覆盖面复查这两步不产出信息，只增加一轮开销。
- 需要的是功能正确性定位（屏上现象、数据错、状态机不进）：那走现象归因类流程，时序花名册答不了这个问题。

## 4. 前置条件

- 报告清单（至少四份，缺一就在第 0 步报 `NOT_MEASURED`）：时序汇总、资源利用率、功耗、布线状态；建议再加方法学与 CDC。
- 时钟对象名册：每个时钟的名字、周期、来源（约束里 `create_clock` 还是由处理系统/时钟向导推导），以及该域端点总数。
- 约束文件清单**与加载顺序**：哪几份、每份用在综合还是只用在选择/实现阶段。
- 一个可复用的中间检查点（例：已铺好布局或已布线的 DCP 路径），用于低成本复算；没有就明确写"无检查点"。
- 上一版采纳件的逐域花名册作为基线（同一把生成器产出的，口径混用要先拒绝）。
- 噪声底：同一棵树重跑一次得到的读数抖动；没量过就写 `【未实测】` 并在结论里降级。
- 权限：只读；agent 不许动 RTL、约束或工程（改动会静默触发重新综合，把对照作废）。

## 5. 使用方法

### 5.1 提示词正文（整段复制，先填 5.2 的槽位）

```
你是我的时序 / 实现报告分析 agent。任务：读完我给你的这几份报告，产出"逐时钟域花名册 +
瓶颈定位 + 下一刀候选表"。你只输出文本，不修改任何文件，不启动任何构建。

【本轮事实（全部由我填；我没给的数字不许补）】
- 报告目录与文件清单：【填入】
- 时钟对象名册（名字 / 周期 / 来源 / 端点数）：【填入】
- 判据分母（各域周期，相对裕量 = WNS ÷ 该域周期）：【填入】
- 约束文件清单与加载顺序：【填入】
- 可复用的中间检查点路径：【填入】（没有写"无检查点"）
- 噪声底（同树重跑的读数抖动）：【填入】（没量过写【未实测】）
- 基线花名册（上一版采纳件的逐域读数 + 它的生成器）：【填入】
- 不可动项（不许放宽的约束、不许碰的存储介质）：【填入】

第 0 步 · 先取证。在任何结论之前输出两节：
  A. 我读过哪些文件：路径 + 段落/表名 + 我从那一行抄到的原文数字。
  B. 我做了哪些假设：每条一行，标"已确认/未确认"。
  四份必需报告里读不到任何一份 ⇒ 该主题写 NOT_MEASURED 并停下要文件，禁止用其余报告外推。

第 1 步 · 逐时钟域花名册。表头字段与顺序写死，不许增删列、不许只交全局一行：

| 时钟 | 周期 | 来源 | setup WNS | setup TNS | setup 失败端点 | hold WHS | hold TNS | hold 失败端点 | 相对裕量 setup | 相对裕量 hold | 未约束端点 | I/O 未点名端口 | 端点总数 | 判定 |

  - 相对裕量必须同时给分子与分母（写成 数值 ÷ 周期 = 百分比）。
  - 该域没有对应读数时填 NA，不许填 0，也不许留空。
  - 判定只允许 PASS / FAIL / NOT_MEASURED；"这一格我没读到报告"是 NOT_MEASURED，不是 PASS。
  - 禁止只报全局最差那一条路径；任何"改善"都必须同时说明其他域有无退化。

第 2 步 · 覆盖面复查（逐条按条件句执行，条件命中就必须做）：
  - 若某个时钟被改过名、或由时钟向导 / 时钟网络重新源化：先按**名字**复查不确定度、
    时钟分组、输入延迟、输出延迟是否还覆盖到该时钟，再读 slack。判据是"报告里那一行还在不在"，
    不是"约束文件里还写着"。覆盖面丢失时工具不报错，只是那一行不出现 ⇒ 读不到就写 NA 并列为债。
  - 若各域不确定度不对称（有的域带、有的域不带）：这些域的 hold 余量**不可比**，
    不许跨域挑最小那个当结论；先补平或先声明不可比。
  - 若 check_timing 报出未加输入/输出延迟的端口：这些端口被当理想时刻，工具不优化它们。
    写"未检查"，禁止写成"满足"。
  - 若方法学报告有 Critical 条目、或 CDC 报告有 unsafe 配对：它们优先于 WNS 的小数点移动。

第 3 步 · 杠杆分类（对每条最差路径给一个类别，类别只能从这几项里选）：
  读该条路径报告里的 Data Path Delay 的 logic/route 百分比与 Logic Levels：
  - 若 route 占比高（阈值由我给的实测记录定，示例取值需替换：我这条是 80 %）且级数很少 ⇒ 类别 = 物理侧（扇出复制 /
    控制集复制 / 放置 / 实现指令），拆逻辑不算对症；
  - 若 logic 占比高、级数深 ⇒ 类别 = 逻辑侧（重定时、提前一拍寄存、位宽/算术拆分）；
  - 若起点或终点是 I/O 端口且该端口无延迟约束 ⇒ 类别 = 约束债，不是时序问题。
  每条必须抄出该路的 route% 与级数原文，不许凭印象分类。

第 4 步 · 便宜的对照（必做，不许跳过）：
  - 任何跨构建的数字移动，先判定它可能是波动：若我有中间检查点，用**从同一检查点重跑
    布局/布线**这种低成本复算做对照（两跑唯一变量就是我声称的那一个），并把两跑的
    逐域读数一起列出。
  - 没有检查点 ⇒ 该结论标 NOT_MEASURED，并写"要先量噪声底：同树重跑一次，读数差的最大值就是底"。
  - WNS 的绝对变化本身既不算收益也不算损失；判据必须成对：本域一条 + 相邻域一条。

第 5 步 · 下一刀候选表。表头写死：

| 候选 | 根因类别 | 手段 | 预期收益 | 影响域 | 机制证据 | 风险 | 代价档 | 状态 |

  - 手段必须写工具真实存在的命令与选项（从我的约束/脚本或工具 help 原文里取），
    取不到就写"命令未核实"，禁止按记忆编选项。
  - 机制证据：这一刀"打到东西"的可数读数是什么（例：复制单元数从 0 变正、该网扇出下降）。
    机制证据没拿到 ⇒ 状态只能写 MECHANISM_INERT，不许写"收益不成立"。
  - 影响域必须点名第 1 步表里的时钟名；跨域改动要写清代价落在哪个域。
  - 状态只允许：fired / blocked(缺来源或批准) / rejected(measured) / declined(measured) / excluded(原因)。

第 6 步 · 反幻觉条款：没有数据处写【未实测】；禁止估算数值；禁止引用我不存在的报告或文档编号；
禁止把"工具会自己做好"当成依据。

第 7 步 · 升级/停止条件（任一命中就停下并说明卡在哪）：
  - 需要器件/工具版本行为，而我没给该版本实测过的凭据；
  - 两个候选的收益互相依赖，一次构建测两件事；
  - 基线花名册与本轮读数的生成口径不一致（列名或分母不同）；
  - 判某条路需要 PHY / 显示器 / 外部规范的时间窗口数，而我没有来源数字。
```

### 5.2 槽位清单

| 槽位 | 该填什么值 |
|---|---|
| 报告目录与文件清单 | 真实归档目录 + 每份报告文件名（本仓库示例取值，需按自身工程替换：`build/` 下的 `timing_summary.rpt` / `utilization.rpt` / `power.rpt` / `route_status.rpt` / `methodology.rpt`） |
| 时钟对象名册 | 从 Clock Summary / Intra Clock Table 抄：名字、周期、来源（约束生成 还是 IP 推导）、该域端点数 |
| 判据分母 | 每个域的周期（相对裕量的分母），逐个列，不许只给一个全局频率 |
| 约束文件清单与加载顺序 | 每份 xdc 的路径 + 是否用于综合（只用于实现阶段的文件会让综合网表与实现结果的身份要分开念） |
| 可复用的中间检查点路径 | 已铺布局或已布线的检查点文件路径；没有写"无检查点" |
| 噪声底 | 同树重跑一次的读数最大差（单位 ns）；没量过写 `【未实测】` |
| 基线花名册 | 上一版采纳件的逐域读数文件 + 生成它的脚本名（配对必须同生成器） |
| 不可动项 | 不许放宽的约束、不许写入的板载存储、不许动的源码目录 |

### 5.3 执行步骤

1. 填槽 → 发正文。**完成后应看到**：回复第一节是 A 节，含每条报告的原文数字摘录。
2. 抽查 A 节摘录是否与报告正文一致（打开该文件的对应行）。**完成后应看到**：不一致条目数（有就退回重跑，记为尺子红）。
3. 读第 1 步花名册：列数、列序、NA 与 0 是否被区分。**完成后应看到**：每域一行；无读数的格是 NA。
4. 读第 2 步覆盖面复查：对你改名/重新源化过的那个钟，明确指出"报告里那一行在/不在"。**完成后应看到**：一条明确结论，不是"应该有"。
5. 读第 4 步对照：是否给出低成本复算方案与两跑读数。**完成后应看到**：要么有对照，要么该结论被标 `NOT_MEASURED`。
6. 把第 5 步候选表按"状态"列过滤：只把 `fired` 且机制证据齐的进入构建；其余留台账。**完成后应看到**：台账行数 ≥ 候选数，且每条被拒/被否的有 reason。

## 6. 判读与失败分叉

- **通过**（花名册齐、覆盖面有明确结论、候选表带机制证据）：进入实现/RTL 改动，一次只带一个候选（见 `../single-variable-ab/`）；改完必须交"名册差分"，任何一条变差都要点名是谁。
- **失败**：agent 只念全局 WNS、把 NA 写成 0、或引用了你没给的文档 ⇒ 重贴第 1 步与第 6 步原文并点名违规句；同一判据连续 3 次不过 ⇒ 停下待裁决，不许弱化判据。
- **读不到输入**：必需报告缺一份 ⇒ `NOT_MEASURED`；下一步是补跑那一份报告（或从冻结件目录里取成套的那一组），不是用其余报告外推。
- **失败分叉：报告与位流不同套**：先按产物身份（md5）配对，重跑第 1 步；混着念的结论全部作废。
- **失败分叉：跨域出现一进一出**（本域变好、别域变差）：本轮不记收益，按成对判据写"净移动 = 0 且归属未定"，把该候选降级为待复算。
- **失败分叉：机制证据为 0**（例：要求复制但复制单元数没变）：写 `MECHANISM_INERT`，先修手段本身（命令/选项/对象名是否真实存在），不许改阈值让它"过"。
