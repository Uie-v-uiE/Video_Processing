## 1. 一句话用途

让模型的每个结论都能追溯到文件与数字，并能被直读推翻。

## 2. 适用场景

- 当你用大模型写 RTL、定位上板问题、整理交付材料，而要求每个结论能追溯到文件与数字时。
- 当你准备把模型/子代理转述的一个数字直接写进报告时。
- 当你想问模型"综合器会怎么处理这个写法"时。
- 当你准备让模型去"查资料"（数据手册、论文、同类开源）时。
- 当同一条结论要跨"模型说 / 工具印 / 人直读"三张嘴对齐，而它们可能不一样时。

## 3. 不适用 / 失效条件

- **工程里没有任何跑得出来的判据**：这套纪律靠"能红"才成立，没有判据时它只会拖慢你。
- **需要肉眼收敛的画质问题**（缩放走样、色彩、抖动）：那一半的规程在 `../eye-acceptance-loop/`；本页只覆盖能被命令判的部分。
- **跨模型 / 跨工程的可比性**：本文件只主张"这些纪律在本仓库抓出过具体缺陷"，不主张通用效果（未验证）。
- **只让模型"直接改位流 / 改管脚约束"而没有原理图或引脚表依据** ⇒ 立即停手。
- **无仿真、无日志的纯猜测循环**；把**未上板**的数据写成实测结论。
- **把 ISSUES 台账当检索索引而不先核对条目头**：编号一直在往后追加、还会漂 ⇒ 引用任何编号前先 grep 核对条目头。
  本页故意不写"现在排到第几条"，那个数每天都不一样。

## 4. 前置条件

- 上下文一次给全的材料：器件完整 part 号、工具链精确版本、架构图路径、失败日志**原文**（不是你的转述）。
  日志原文这条不能省——模型会对"只截了 20 行"的日志补出它以为在中间的那 100 行。
- 至少一条跑得出来的判据（台架 / 门禁脚本），以及它的三态收尾形状（PASS / FAIL / 读不到输入）。
- 主代理一侧"直读工具产出报告"的时间与权限（模型给的任何数字都要被直读替代）。
- 一个最小实验环境：能只改一处写法就量出一个数（例如同一存储器的几种写法变体各吃多少 RAM）。
- 交叉阅读角色的边界声明：只读、不许改文件、不许跑仿真（见 `../read-only-review-agent/`）。
- 报告归档目录与命名规矩：几分钟后单独捞出来的那份报告可能是**上一版**的。

## 5. 使用方法

### 5.1 提示词正文（整段复制，先填 5.2 的槽位）

```
你是我的 FPGA 研发协作 agent。本轮总规矩：你说的每一句结论都要挂着"文件路径 + 数字 + 命令"，
并且能被主代理的一次直读复核推翻；被推翻的那条降级为假设，不进报告。

【本轮事实（全部由我填；我没给的数字不许补）】
- 器件完整 part 号 / 工具链精确版本：【填入】
- 架构图或顶层连接说明的路径：【填入】
- 失败日志原文（整段贴，不要转述、不要只截 20 行）：【填入】
- 本轮可读的文件与不许碰的路径：【填入】
- 已有判据清单（台架/门禁脚本名 + 当前红绿）：【填入】
- 最小实验的可跑入口（一条命令）：【填入】
- 报告归档目录与本轮文件名：【填入】

第 0 步 · 先取证再作答：输出 A"我读过哪些文件的哪些行"（路径 + 行号 + 那一行原文）与
  B"我做了哪些假设（已确认/未确认）"。缺日志原文、缺路径、或缺判据清单 ⇒
  回答"信息不足，请提供 X"并停住；不许用你的记忆替我补文件内容。

第 1 步 · 交叉阅读（你在这个角色里是只读的）：给我 3 个候选根因，每个附**文件路径 + 行号 + 那几行原文**。
  行号不确定就写"不确定"，**不要估**——这条是硬要求，因为一次交叉阅读里出现过"引用了一个不存在的行号"，
  估出来的行号和读出来的一模一样，只有回原文才能分辨。
  只读角色不许改文件、不许跑仿真、不许跑任何会碰串口的脚本。

第 2 步 · 验收（主代理侧模板，由我执行，你要按这个形状交）：逐条给出
  结论 / 支撑它的文件与数字 / 你为得到它跑了什么命令。我会**直读**同一份文件复核，
  对不上的那条降级为假设、不进报告。数字不许采信转述：模型或子代理给的数字一律先当假设。

第 3 步 · 要求可证伪：每条假设写成"若假设成立应看到 X"，再把 X 变成一条能跑的判据，用它的红/绿裁决。
  判据自身要有产物：一个 PASS/FAIL 都不打印的台架**不许计为通过**；工具自报"成功"不算数，
  要检查镜像里关键符号与代码段大小（本仓库第一次"链接成功"的镜像被 `--gc-sections` 裁到只剩几十字节，
  示例取值，需按自身工程替换）。

第 4 步 · 凡"综合器才知道"的问题，用最小实验回答而不是问我/问模型：
  把同一存储器的几种写法变体做成对照探针，量出各吃多少 RAM，用实测的那两个数定架构
  （本仓先例见 `../../derived_clock_port_mux.md`）。想清楚"这一步能不能换成一次本地测量"
  再决定要不要去查资料；查回来的东西要能被我这边一次读数证伪。

第 5 步 · RTL 侧附带约束：注释只写非显然的 WHY；禁止无端加流水"以防万一"；
  禁止顺手加超时计数器当兜底。改动要唯一（一次只测一件事）。

第 6 步 · 输出契约（顺序写死）：
  1) A 节读过的文件 + 行号 + 原文摘录（行号不确定就写"不确定"）
  2) 3 个候选根因，每个带"若成立应看到 X"
  3) 把 X 落成判据：判据名 / 命令 / 期望读数 / 三态收尾
  4) 每条结论的"文件路径 + 数字 + 命令"三件（缺任一件就自己标为假设）
  5) 我给的日志之外，你没有引用过的东西——列出来（没有就写"无"）
  没有数据处写【未实测】；禁止估算数值；禁止引用我不存在的报告或台账编号；
  禁止把"工具会自己处理好"当成依据；禁止"通常/一般来说"式措辞。

第 7 步 · 停止条件（任一命中就停下报我卡在哪一条）：
  要我直接改位流或改管脚约束而没有原理图/引脚表依据；无仿真无日志只能猜；
  需要未上板的实测数字才能下结论；同一条判据连续 3 次不过——停下说明，不许弱化判据。
```

### 5.2 槽位清单

| 槽位 | 该填什么值 |
|---|---|
| 器件 part 号 / 工具版本 | 完整 part 号与精确版本号（版本行为随工具版本漂移，只写家族名不够判） |
| 架构图路径 | 顶层连接/划分说明的文件位置，模型要能自己打开 |
| 失败日志原文 | 整段原文，不是转述、不是截 20 行；截断会诱发模型补出"中间那 100 行" |
| 可读与禁改路径 | 只读角色的射程；构建在飞时禁改的源码目录另列 |
| 判据清单与红绿 | 台架/门禁脚本名 + 每条当前 PASS / FAIL / 没判 |
| 最小实验入口 | 一条命令，改一处写法就能量出一个数（RAM 块数、LUT、拍数都行） |
| 报告归档目录与文件名 | 本轮件的名字；防"几分钟后单独 awk 出来的那份是上一版" |

### 5.3 执行步骤

1. 填槽发出（日志整段贴）。**完成后应看到**：A 节先出现，且每个路径你都能在盘上打开。
2. 抽查 A 节的行号摘录是否与原文一致。**完成后应看到**：不一致条目数；有不一致就退回并点名"引用了不存在的行号"。
3. 读 3 个候选根因的"若成立应看到 X"。**完成后应看到**：每条 X 都能变成一条命令能跑的判据。
4. 直读工具产出的同一份报告（不许用模型转述的数字）。**完成后应看到**：每条结论的"路径 + 数字 + 命令"三件齐；对不上的降级为假设。
5. "综合器才知道"的那一类改走最小实验：变体做成对照探针、量出各吃多少 RAM。**完成后应看到**：两个实测数（或明确的 `【未实测】`），架构按它们定。
6. 收尾时看判据自己有没有产物。**完成后应看到**：至少一行 PASS/FAIL 或第三态；一条都不打印 ⇒ 不许计为通过。

## 6. 判读与失败分叉

- **通过**：每条结论都挂着"文件路径 + 数字 + 命令"，且能对上主代理的直读结果。
- **对不上**：那条**降级为假设、不进报告**（本条的价值就在这一步——不是让模型改口，是不采纳）。
- **转述数字未经直读复核** ⇒ 一律当假设。反面案例：拿几分钟后单独 `awk` 出来的一份报告宣布结论，那是**上一版**的文件；
  同一件事的机器版判据见 `../../cdc_pair_baseline_gate.md`。
- **引用了不存在的行号**：估出来的行号和读出来的一模一样 ⇒ 只有回原文才能分辨；命中就整批退回第 0 步重取证。
- **判据没产物**：一个 PASS/FAIL 都不打印的台架不许计为通过；工具自报"成功"不算数，要检查镜像里关键符号与代码段大小。
- **台账编号漂了**：引用任何编号前先 grep 核对条目头；核对不上就写"编号未核实"，不许沿用旧索引下结论。
- **3 次不过**：停下，列试过什么与卡在哪一条，等人类裁决；不许把"查资料"换成"猜"。

## 7. 已验证的效果

- 这套纪律要能真的**推翻过东西**，不是口号：本仓库推翻过 3 次模型与自己的结论——
  ①一条被逐条件核对否掉的"死代码"判断；②一次"断链 ⇒ PHY 停供时钟"被计数速率证伪（关键在沿够不够快，而非有没有沿）；
  ③一张自证过的收益表被换成带锚点 + 反向对照的双判据重做。三条都是旧卡记录的事实，本页未增未删。
- 出处（旧卡记录，2026-10-04 核对标题存在）：`report/log/OVERNIGHT_LOG.md` §7（条目头是"工具与子代理记录"）、
  §8（"参考与来源"），另见 `report/AI_COLLABORATION.md`。
- 未抄出的量数：上面 ②③两条的**具体读数**（计数速率的值、双判据重做后的数字）与"第一次链接成功被裁到只剩几十字节"的
  确切字节数，旧卡都没写 ⇒ `【未实测】`；引用前请直读上述两处。
- 跨模型 / 跨工程可比性：`【未实测】`——本页只主张本仓库抓出过具体缺陷，不主张通用效果。
- 基线对比（不用本模板）：`【待验证】`。需同一提示词连跑 3 次并记录"结论缺三件（路径/数字/命令）的比例"与
  "被直读推翻的条数"；目前 0 次，**还差 3 次**。

## 8. 提炼来源与边界

- 提炼来源：`report/log/OVERNIGHT_LOG.md` §7、§8，`report/AI_COLLABORATION.md`；旧扁平卡 S5 的触发 / 不适用 /

- 迁移到新题目要改：part 号与工具版本那两格（版本行为会漂，`--gc-sections` 一类链接期读数要换成你工具链的等价检查项）、
  "综合器才知道"那类问题的最小实验形态（本仓是存储器写法变体的 RAM 对照）、台账文件与编号格式。
- 失效边界：见 §3——没有判据就跑不出"能红"，这套纪律只剩开销；未上板的数据不许写成实测结论；
  没有原理图/引脚表就不许动位流与管脚。
- 与相邻条目的分界：肉眼那一格由 `../eye-acceptance-loop/` 管；只读代理怎么委托与怎么回读由
  `../read-only-review-agent/` 管；判据能不能红由 `../criterion-before-code/` 管；一次只测一件事由 `../single-variable-ab/` 管。
