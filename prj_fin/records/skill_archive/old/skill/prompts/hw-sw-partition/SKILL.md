## 1. 一句话用途

用一段提示词把算法切成有依据、有代价、有待实测项的 PS/PL 划分表。

## 2. 适用场景

- 当题目要求写"软硬件划分依据"，而你手上只有一段自然语言算法描述、还没有任何一张对比表时。
- 当协作方（人或 agent）给出的划分结论里没有数字、只有"实时性要求高所以放 PL"这类句子时。
- 当出现以下症状之一需要重开划分讨论时：处理器侧逐包/逐像素搬运、中断或协议栈抖动进入显示或采样链路、存储带宽被控制面挤占、帧率/吞吐读数与口径混在一起。
- 当已经存在两三个候选方案（例如软件协议栈 vs 硬件解析、软件缩放 vs 硬件缩放）需要在报告里并列给评审看时。
- 当要把一次划分决定交接给后续 agent，而它需要知道"哪几条结论靠哪个读数撑着、哪个读数一变就要重判"时。

## 3. 不适用 / 失效条件

- 划分已定且只验功能：用门禁/台架类工作流，不要用本模板重开架构辩论——它只会产出一张新表。
- 纯可编程逻辑内部的模块划分（例：一个滤波器拆几级、FIFO 深度）：本模板的"放置侧"只有两值，套上去会把问题压扁。
- 缺第 4 节要求的三类读数中的两类以上（数据率、算术量、存储深度）：此时任何结论都是猜，按模板第 0 步应停下要数据，别强行走完。
- 目标平台没有处理器硬核（纯 FPGA + 软核，或 CPU 在片外）：必须先把第 5 节的"器件与平台"槽换成真实边界，否则"PS/PL"两词会误导评审。
- 需要的是功耗/成本裁决而不是位置裁决：本模板不给预算表，只给放置结论与代价项。

## 4. 前置条件

- 一份算法/数据流的文字描述，按"输入从哪来 → 每步运算 → 输出到哪去"写全；缺这段描述就不要开工。
- 至少两类真实读数可引用：单位时间数据量（字节/秒、包/秒、帧/秒 × 帧字节）、单步算术量（位宽 × 乘加个数 × 邻域 × 迭代）。取不到就写 `【未实测】`，不许用估数占位。
- 器件/平台字符串与工具链版本（版本要写进结论表下方，赛题对版本口径有要求）。
- 一份可读的资源与时序基线（任一综合/实现报告，或明确的器件容量数字），用来把"代价"一栏落到 BRAM/DSP/LUT/处理器周期这类可数的东西上。
- 权限：能打开上述报告与源码目录；无硬件连接要求（本模板纯文档工作）。
- 若协作 agent 有写权限：先把权限收掉，让它只输出表格。写权限会诱发"顺手改一下代码"，把一次架构讨论变成一次未登记的改动。

## 5. 使用方法

### 5.1 提示词正文（整段复制，先填 5.2 的槽位再发出）

```
你是我的 FPGA 系统架构协作 agent。任务：把下面这段算法/数据流切成候选放置单元，
并为每个单元给出处理器侧 / 可编程逻辑侧的划分建议与依据。你只输出文本，不改任何文件。

【本轮事实（全部由我填；我没给的数字你不许补）】
- 器件与平台：【填入】
- 工具链与版本：【填入】
- 算法描述：【填入】
- 数据率与规格：【填入】（每帧字节 × 帧率 / 每秒包数 / 采样率；没测的写【未实测】）
- 单步算术：【填入】（每次运算位宽、乘加个数、邻域大小、迭代次数）
- 时延与抖动预算：【填入】（输入有效到输出可见的预算；能否容忍毫秒级抖动）
- 存储预算：【填入】（阵列总字节数；访问模式：整行流式 / 随机 / 邻域）
- 不可动项：【填入】（必须留在处理器侧的协议栈、驱动、外设、授权边界）

第 0 步 · 先取证后作答。在任何结论之前先输出两节：
  A. 我读过哪些文件：逐条给路径 + 行号或表名；没真正打开过的一律不列。
  B. 我做了哪些假设：每条一行，标"已确认"或"未确认"。
  若 A 节里没有任何可佐证的数据率或资源数字，回答"信息不足，请提供 X"并停在这里。

第 1 步 · 切候选单元，切到 5–12 个，按下列维度依次使用、不许混在一个维度里切：
  (1) 数据率台阶：哪一步之后字节率下降；
  (2) 并行度：逐元素 / 邻域 / 全局归约；
  (3) 算术密度：乘加次数 ÷ 经过的字节数；
  (4) 状态量：无状态 / 行状态 / 整帧状态；
  (5) 与外设或实时协议的耦合度。
  每个单元必须能指回我给的算法描述里的一句原话；指不回就删掉这个单元。

第 2 步 · 只输出这一张表，表头字段与顺序写死，不许增列、不许改列名：

| 候选单元 | 放置侧 | 依据 | 代价 | 风险 | 待实测项 | 判定 |

  - 放置侧只允许四个值：处理器侧 / 可编程逻辑侧 / 两侧皆可 / 【信息不足】。
  - 依据：只允许引用 (a) 我在上面填的数字，(b) 你在 A 节点名的文件，(c) 该单元自身的算术结构。
    写法示例"依据：数据率【填入】字节/秒 + 算术密度【填入】乘加/字节"；
    禁止出现"通常""一般来说""理论上""应该问题不大"。
  - 代价：写"要占用的东西 + 数字或【未实测】"，占用项限这几类：BRAM / DSP / LUT / 端口引脚 /
    处理器周期 / 软件栈维护面。
  - 风险：写成一句可判真假的话，指明"哪个读数会变就把这条结论推翻"。
  - 待实测项：必须同时给三件——跑什么命令、读哪个字段、期望值是多少；缺一件不算一条。
  - 判定：只允许 PASS / FAIL / NOT_MEASURED。读不到输入等于 NOT_MEASURED，绝不等于 PASS。

第 3 步 · 表格之后另起一节"跨域接口最小契约"，逐条列出每一处处理器↔可编程逻辑交界：
  数据方向、每单位时间字节数、控制方向、谁等待谁、边界缓存深度（无数字写【未实测】）。
  禁止只写"通过总线通信"这类没有量纲的句子。

第 4 步 · 反幻觉自查（输出在最后一节）：
  - 逐条列出你在表里写过但 A 节里没有凭据支撑的句子；有就删掉或降级为【待验证】。
  - 禁止把"厂商 IP 存在"当作"该单元放可编程逻辑更省"的证据。
  - 每条结论自问：换一个题目、换一块板卡，这句还成立吗？不成立的句子前面加"平台相关："。

第 5 步 · 升级/停止条件（任一命中就停下并说明卡在哪，等我做裁决）：
  - 数据率、算术量、存储深度这三类里缺两类；
  - 我的算法描述点名了一个你没被允许打开的文件；
  - 两个候选单元的"依据"互相冲突；
  - 你需要的资源上限（BRAM/DSP/LUT 总量）没有来源。
```

### 5.2 槽位清单（发出前逐条确认已填，未填的槽不许留空跑）

| 槽位（正文里的 `【填入】`） | 该填什么值 | 取不到时怎么写 |
|---|---|---|
| 器件与平台 | 完整 part 字符串（含封装与速度等级），或"FPGA + 片外 CPU"的真实拓扑 | `【未实测】` 并说明没有 part 字符串 |
| 工具链与版本 | 综合/实现工具主版本 + 补丁版（示例取值，需按自身工程替换；本仓库那一行写在 `data/metrics.csv` 的"器件与工具链"行） | 空着等于前置不满足 |
| 算法描述 | 输入来源 → 逐步运算 → 输出去向的原文，不写代码 | 必填，缺则不开工 |
| 数据率与规格 | 帧字节 × 帧率，或包/秒、采样率的实测或计算式 | `【未实测】`，并写"未测的原因" |
| 单步算术 | 位宽 × 乘加个数 × 邻域尺寸 × 迭代次数 | `【未实测】` |
| 时延与抖动预算 | 端到端预算毫秒数 + 可容忍抖动量级 | `【未实测】` |
| 存储预算 | 阵列字节总数 + 访问模式（流式/随机/邻域） | `【未实测】` |
| 不可动项 | 必须留在处理器侧的协议栈/驱动/授权边界清单 | 写"无"，不许空 |
| 依据列的写法示例 | 你这一题真实的数据率与算术密度数字 | 用 `【未实测】` 替代，不许编 |

### 5.3 执行步骤（做完一步就要看到对应产物）

1. 填 5.2 的九个槽位。**完成后应看到**：正文里没有残留 `【填入】` 字样（除示例那两行）。
2. 把整段发给协作 agent（它无写权限）。**完成后应看到**：回复的第一节是 `A. 我读过哪些文件`，且至少一条能对上盘上真实路径。
3. 逐条抽查 A 节：打开它点名的文件与行号。**完成后应看到**：每条都有你亲自确认过的行；抽查不通过的条目数记下来。
4. 检查结论表表头与列序是否与正文完全一致。**完成后应看到**：七列、顺序未变、`放置侧` 只有四个合法值。
5. 检查"待实测项"列三件套是否齐全。**完成后应看到**：每一条都有命令 + 字段 + 期望值；缺的标为不合格并要求重填。
6. 把表与"跨域接口最小契约"抄进你的设计文档，并把 `判定` 为 `NOT_MEASURED` 的行单独列成欠账清单。**完成后应看到**：欠账清单至少一条，或明确写"本轮无未决项 + 凭什么这么说"。

## 6. 判读与失败分叉

- **通过**（回复含 A/B 两节、七列表头一致、每行判定为三态之一）：进入实测，把"待实测项"逐条变成读数；读回的数字与"依据"列冲突时，该行的 `判定` 立刻改 `FAIL`，并回到第 1 步重切该单元。
- **失败**（表头被改、出现"通常/一般来说"、依据列只有形容词）：不要辩论，把正文第 2 步与第 4 步原样再贴一次并指出违规句子原文；连续 3 次仍违规 ⇒ 停下，说明卡在哪条判据，等裁决。
- **读不到输入**（A 节列的文件不存在，或数据率/算术量都缺）：这是 `NOT_MEASURED`，不是"划分合理"。下一步：先补第 4 节的前置读数（跑一次最小统计脚本，或在报告里点名已有数字），再重发模板。
- **失败分叉：两个候选单元结论互相冲突**：走"升级"分支——把冲突写成"哪条读数能定分晓 + 取这条读数要跑什么"，交给人做范围决定，不许让 agent 自行折中。
- **失败分叉：agent 顺手改了源码**：立刻回滚改动（本模板的前提是只输出文本），并把它的权限收回后重跑第 0 步。

## 8. 提炼来源与边界

- 提炼来源（点名文件，不讲故事）：`report/PS_VS_PL.md` 的三代对比表与第 3 节；`report/ARCHITECTURE.md` 第 3 节的通道表；`report/log/CONTEST_CHECKLIST.md`（2026-10-01 08:06）"软硬件协同"一行——落点写明"划分依据与反例写在 `report/PS_VS_PL.md`，接口在 `report/ARCHITECTURE.md` 与 `src/ps/main.c`"；`report/log/ISSUES.md` #119（口径与实测分开记账的那一类）；`report/LLM_COLLAB.md` 第 5 节"只读评审代理"与"回读门槛"（2026-10-02 02:16）——本模板第 0 步与"先取证"条款由此而来。
- 平台相关、迁移时要改的句子：
  - "处理器侧 / 可编程逻辑侧"两词 → 没有硬核处理器的平台上改成"软核（MicroBlaze 类）/ 可编程逻辑"，或两块芯片的真实芯片名。
  - "BRAM / DSP / LUT"占用项 → UltraScale+/Versal 上把 BRAM 换成分层存储（BRAM/URAM/LUTRAM 的可用性与推断口径不同），且必须重新取器件容量读数。
  - "毫秒级抖动"预算 → 与显示/采样时钟域强相关，换题目要按新域周期重写。
- 不再适用的条件：数据率与算术量都已被实测、且划分已写进约束与 RTL 时；此时本模板只会产出与既有实现脱节的表。
- 边界：本模板决定"放哪一侧"，不决定"这一侧内部怎么拆模块"，也不给时序收敛方案（后者见 `../report-to-bottleneck/`）。
