name: ab-revert-control-run
description: 把"新红了是不是我改坏的"变成一次可判定的 A/B：当一版改动后台架红了一批、而这些判据在上一份冻结报告里是绿的、分不清是"我改坏了"/"尺子今天也改过"/"它本来就红了没人说"时，用它存补丁、退回未改状态、用同一版台架再跑一遍拿到"基线红名单"，再逐条比两份红名单与台架指纹；触发物是红项与改动不同域、两份逐条判定清单、以及报告头部的 top/tb/rtl 三枚指纹。
---

## 1. 一句话用途

新红了先证明不是自己改的。

## 2. 适用场景

- 当一版改动之后台架红了一批，而这些判据在上一份冻结报告里是绿的，现在**分不清**是
  "我改坏了"、"尺子今天也改过"、还是"它本来就红了没人说"时。
- 当红项与本次改动**明显不同域**（改了插值开关，红在纯几何判据上）时。
- 当手里有一份上一版冻结报告（带台架 md5 与源码合指纹）可以当对照基线时。
- 当你正要把新红归因给硬件、工具或"尺子不准"之前——先跑本条，归因要拿差集说话。
- 当同一版台架连着两跑给出同一批红、而你不确定这份红是不是你带进来的时。

## 3. 不适用 / 失效条件

- 不适用：红项与改动明显同域（改了模糊算法、模糊判据红）——直接查代码即可。
- 失效：跑基线期间**不许再动源码**（动了报告的出处就废了）；台架文件也要冻结，两跑的台架 md5 必须一致。
- 失效：若改动本身跨域共享状态（同一版台架在不同顺序下结果不同），基线跑一次不够。
- 成本边界：台架跑一次很久时，先跑**单元级**的 A/B（本仓形状：`tb_v103` 一分钟、`tb_v98` 85 分钟；
  示例取值，需按自身工程替换）。
- 不适用：没有可复跑的台架或没有上一版冻结件——那属于"没有对照物"，本条给不出判定。

## 4. 前置条件

- 一个版本控制工作树，能对源码目录取差异并退回未改状态（本仓形状：`git diff -- src/rtl > /tmp/x.patch`）。
- 一条"合指纹"命令，把整棵源码树压成一个值：`find src/rtl -name '*.v' | sort | xargs md5sum | md5sum`
  （示例取值，需按自身工程替换目录与扩展名）。
- 上一份冻结报告在盘上，且报告头部写了 top/tb/rtl 三枚指纹（要对照的就是这三枚）。
- 能跑**同一版**台架（仿真器现场）；本条目只要求可复跑，不含任何构建脚本或 Vivado 调用。
- 一个临时目录存放补丁与两跑日志，避免第二轮把第一轮的输出覆盖掉。

## 5. 使用方法

1. `git diff -- src/rtl > /tmp/x.patch`，然后 `git checkout -- <那几个文件>` 退回未改状态；
   **记下退回后的合指纹**（`find src/rtl -name '*.v' | sort | xargs md5sum | md5sum`）。
   完成后应看到：一个补丁文件 + 退回态的合指纹值（与改动前那枚不同）。
2. 用**完全同一版台架文件**（台架的 md5 也要一致）再跑一遍，得到"基线红名单"。
   完成后应看到：一份逐条判定清单——这就是"什么都没改时也红这些"的对照物。
3. 比红名单：逐条相同 ⇒ 与本次改动无关；不同 ⇒ 差异项就是你的改动造成的，回去重推修法。
   完成后应看到：两个名单的差集（可以是空）；差集非空时逐项指名红项名与它的判定域。
4. 恢复补丁，核对合指纹回到第 1 步记录的值。
   完成后应看到：合指纹与改动前那枚逐字符相等；不等说明补丁没恢复干净，本轮结论作废。
5. 顺手查那份"绿"的冻结报告是不是**同一把尺子**：把历史报告的 `tb_md5` 与当前台架文件比一下。
   完成后应看到：两个 md5 相等或不等。本项目就是这么发现 12 条红其实来自
   "台架自己把某个准静态激励留在了上一段的状态"。

## 6. 判读与失败分叉

- 通过（本条成立的形状）= 两份报告的头部指纹（top/tb/rtl）都写下来并对照过，结论里**指名**
  哪几条是既存、哪几条是新增。
- 失败 = 结论只说"应该不是我改的"、或没记下退回态的合指纹 ⇒ `FAIL`，重来一遍，别补叙事。
- 失败 = 第 3 步有差集却没逐条归因 ⇒ 差集那几项按"你的改动造成的"处理，回去重推修法。
- 失败 = 第 4 步合指纹回不去 ⇒ `FAIL`，工作树已脏，本轮任何读数都不再能作出处。
- 读不到输入 = 上一份冻结报告不在盘上、或它的 `tb_md5` 无从比对 ⇒ `NOT_MEASURED`；
  先用当前台架自产一份基线再说，不许把"没有对照"念成"没有红"。
- 中途又动了源码（第 2 步之后）⇒ 那一次基线整条作废，重跑第 1 步起。
