## 1. 一句话用途

窗滤要挂在逆映射之后的那条流上。

## 2. 适用场景

- 当你准备让"任意角逆映射（旋转 / 缩放 / 透视这一类屏幕坐标 → 源坐标）"与"3×3 邻域滤波
  （blur / sharpen / Sobel / 形态学）"同时开时。
- 当症状是"几何变换一开、滤波就花屏或冒出中间混叠值，把几何关掉又完全正常"时。
- 当现有代码里有一条"某种几何模式下强制旁路窗滤"的捷径，你打算保留它时。
- 当你准备用"在源域行缓存上换成屏幕坐标寻址"来修它时（这条路是错的，见第 3 节）。

## 3. 不适用 / 失效条件

- 不适用：点运算（灰度 / 二值 / 反色 / gamma）与邻域无关，任何域都兼容，不用重排。
- 不适用：整行平移、整屏等比这类**邻域保持**的变换——两种顺序等价，别为此重构。
- 不适用：做**前向**映射（源 → 屏幕去散布）而不是逆映射采样的通路——那条上没有规整的目标域光栅可谈。
- 失效：行缓存深度 < 有效行宽时 3×3 的列会对不上，而且它**不报错**，只是列错 ⇒ 改分辨率必须连着改这里。
- 失效（隐蔽版本）："在源域行缓存上滤波、却改用屏幕坐标寻址"仍然是错的：
  重构成立的充分条件是行缓存挂在逆映射**之后**的那条流上，不是"坐标换了"。
- 失效：与未做几何的参考图逐像素比时，**金标也要先做同样的几何再滤波**，否则报出一堆假差异——
  那是比错的参照物，不是缺陷；而参考图本身不可一键重跑时，这条对比的证据等级只有"人工比对"，
  别写成"与参考图逐像素一致"。
- 已知未修的坑：想在几何开启态做双线性或更高档插值，先确认小数权重真的传出去了——
  本仓旋转那一支把小数位钉成 0，于是"开插值"与"关"在非零角度是同一张画，而屏上那一格写着开
  （已记录未修；通用形态是"开关的投影与硬件真的那一位不是同一位"，见 S20 第六签名）。

## 4. 前置条件

- 一条能改成"屏幕坐标 → 逆映射 → 读像素 → 建窗 → 输出"顺序的数据通路，且几何与滤波是可分别开关的两档。
- 行缓存的深度由上层传入（本仓是一个由顶层传入的行宽参数，示例取值，需按自身工程替换；
  默认值与实传值不一致时就会踩第 3 节的深度失效）。
- 一支台架同时刺激"几何开启"与"几何关闭"两档（本仓入口 `bash sim/run_one.sh tb_rotate_window`）。
- 一份能一键重跑的、同几何的金标图（没有就把对比等级降到"人工比对"，别写成逐像素一致）。
- 本条目在 Vivado/Vitis 2025.2.1（build 6403652）下写成（版本真相源见 `skill/_meta/naming-and-format.md`）。

## 5. 使用方法

1. 记住机理再排顺序：滤波若做在源图扫描序上，逆映射之后"屏幕邻域 ≠ 源图邻域"，滤的是一个根本不挨着的窗口。
   所以定死为：屏幕坐标 → 逆映射 → 读像素 → **在这条读出来的流上**建 3×3 → 输出。
   关键是承认"读出来的像素流本身就是目标图像的光栅序"——它把"滤波该挂在哪"从选择题变成事实题。
   完成后应看到：几何开启时窗口的三个来源像素在**目标域**里相邻。
2. 行缓存的列坐标用目标域（屏幕）坐标寻址，深度必须 ≥ 有效行宽，而且深度由上层传进来、别在滤波器里写死。
   完成后应看到：行宽参数只有一处定义，改分辨率时它跟着变。
3. 删掉那条"几何模式强制旁路窗滤"的捷径，然后 grep 确认它真的删干净了：
   端口/信号还留在接口上 ≠ 功能还在，看它被**读**了几次（通用版在 S1）。
   完成后应看到：那个信号在过程赋值/条件里出现的次数为 0（只剩声明就是残留）。
4. 越界填 0 放在效果链**之前**、黑边强制放在**之后**。
   完成后应看到：反色类点运算不会把越界的 0 变成白——反过来做会造出一个"看起来像丢帧"的现象。
5. 判据别只判"没花屏"，要判"滤波真的在跑"：在几何开启那一档把期望写成"**必须**出现中间混叠值"——
   不出现就说明窗滤被静默旁路了（反向判据的通用形态见 S21）。
   完成后应看到：台架里有一条"没有中间值就 FAIL"的期望（常量场判不出来，激励必须含台阶/边缘）。
6. 顺手把资源算一遍：几何重排常常是**减逻辑**而不是加逻辑。
   把同一种几何限制在一路、删掉另一路多余的映射实例，先问"哪一路能省"。
   完成后应看到：DSP / LUT / 寄存器 / 失败端点的方向一起报出来，再念最差负裕量。
7. "哪一路做几何、哪一路不做"是产品决定，会随版本变 ⇒ 任何文档里念的几何行为都要用一条命令验一遍，
   读不到就按未验证处理。

## 6. 判读与失败分叉

- 步骤 1/2（顺序与深度）：
  通过 = 两档台架都显示"滤波在跑"。
  失败 = 几何开启档出现花屏或整片中间值 ⇒ 先查滤波挂在哪个域，不要先加缓冲或改时钟。
  读不到输入 = 深度参数没传（用了默认值）⇒ `NOT_MEASURED`，列对不上是**不报错**的，必须靠判据而不是靠看。
- 步骤 3（旁路捷径）：
  通过 = 那个模式位在过程赋值里出现 0 次。
  失败 = 端口还在被别人读 ⇒ 捷径没删干净，判 `FAIL`（接口留着 ≠ 功能没了）。
- 步骤 4（越界与效果链次序）：
  失败 = 非零角度下黑边变白边/白点 ⇒ 次序反了，把填 0 挪到效果链之前、黑边强制挪到之后。
- 步骤 5（反向判据）：
  通过 = "几何开启"与"几何关闭"两档**都**要求看到"滤波在跑"，两档同时 PASS 才算；只有一档绿等于没判。
  失败 = 开启档报"没有中间值" ⇒ 窗滤被静默旁路。
  **自证**：把顺序改回"先滤波、后映射"，那条反向判据必须**变红**；改回去它不红，说明判据恒真，本次 PASS 不算证据。
  读不到输入 = 台架没打判定行 ⇒ `NOT_MEASURED`，先确认两档激励真的都跑到（少一档就是空集上过）。
- 步骤 6（资源账）：
  通过 = 资源与失败端点同向减少且最差负裕量不劣化。
  失败 = 只报"省了几颗 DSP"而不念失败端点 ⇒ 归因不完整。
  读不到输入 = 没有同一把尺子的前后两份报告 ⇒ `NOT_MEASURED`，别拿不同轮次的数直接相减。
- 判读位置：本条判的是"滤波在不在跑"；"屏上那一格写着开"不等于硬件那一位是开（见第 3 节小数位那条）。
