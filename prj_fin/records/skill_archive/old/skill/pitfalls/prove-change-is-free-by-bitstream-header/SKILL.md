description: 用位流包头而不是推理回答"这次改动到底是不是免费的"：当你改完 RTL（删掉一个没被例化的模块、换掉一个 ram_style、清掉一处综合告警）想知道会不会动到时序/资源/行为，而再滚一轮构建会把 build/system.bit 与全套报告覆盖掉时用它——先把产物写到旁边、再比报告、最后比位流本体，只有 cmp 数出的差异全部落在包头的时刻字段里才叫配置内容逐位相同。
---

## 1. 一句话用途

位流逐字节相同才算"免费"。

## 2. 适用场景

- 当你改完 RTL（或删掉一个没被例化的模块、换掉一个 `ram_style`、清掉一处综合告警），
  想知道**这次改动会不会动到时序/资源/行为**时。
- 当你打算用"再滚一轮构建然后念 WNS"来回答上一条，而那一轮会把 `build/system.bit` 与全套报告覆盖掉时
  ——覆盖之后板子上那块与你引用的那份报告不再是同一次构建，下一个人无法判断"板上是哪一版"。
- 当门禁打印"有 RTL 源比 bit 新"这类 WARN，而你要**答复**它而不是忽略它时。
- 当你想说"这一轮只改了注释/写法，不影响位流"，而这句话目前只有推理撑着时。

## 3. 不适用 / 失效条件

- 不适用：你真的改了逻辑行为 ⇒ 数字必然变，本条只教你怎么**证明它没变**。
- 不适用：只想比较两个策略的 WNS ⇒ 那是策略扫描（`build/tcl/sweep_impl_strategy.tcl`），别期待位流相同。
- 失效：如果你顺带改了约束（XDC）、器件速度等级或 IP 版本，包头以外的字节一定会动——
  那时本条只告诉你"改动不是免费的"，不告诉你贵在哪。
- 失效：**位流大小恰好相同**也不等于免费——只有 `cmp -l` 逐字节过完、并且差异全部落在包头那几格时刻字段里，
  才叫"这一版位流就是那一版"。
- 边界（不许外推）：只差时刻这 4 个字节时也**不能**推出"改动对时序零影响"：布局是确定的，但确定不等于不变；
  本条只能证"配置内容相同"，证不了"收敛余量相同"。

## 4. 前置条件

- 能写进旁边目录的一轮构建能力：本仓是 `bash build/roll_isolated.sh`（可选 `OUT=<目录>` 指定隔离目录，
  默认落在带时间戳的旁边目录；工具路径只有一个说法：`VP_VIVADO_BIN` 指到 `<Vivado>/bin`）。
- 两块位流与两套报告（本轮 vs 上一轮），以及 `cmp`、`ls -la`、`md5sum`、`diff`。
- 一个能按字节切片打印的工具（卡片原文用 `python -c`；本轮用 node 读同一区间，见第 7 节）。
- 两份报告的来源版本一致（同一器件、同一 IP 版本、同一约束集），否则第 3 节直接失效。
- 不需要连板子；但**需要**一轮真正跑完的构建才能拿到第二块位流（本轮只做了只读核对，见第 7 节）。

## 5. 使用方法

1. **把这一轮产物写到旁边**，不要动 `build/` 那套被门禁与文档引用的东西。
   仓库里的做法是 `build/roll_isolated.sh`：它**不复制**那 300 行构建脚本，
   只用一条 sed 把 `set outdir [file join $root build]` 换成隔离目录，并且**替换不生效就拒绝跑**。
   完成后应看到：一句"产物目录：…（build/ 里那套不动）"；
   若打印 `REFUSE: outdir 那一行没被改写`，说明正式脚本换了写法 ⇒ **停在这里先去看写法**
   （这条 sed 静默不匹配就会让一轮构建把 `build/` 覆盖掉——那是本条要避免的事故）。
2. 跑完先比**报告**再比**位流**：`diff <(滤掉 Date/Command 两行的 timing_summary) …`、`route_status.rpt`、
   `utilization.rpt`。
   完成后应看到：只差报告头里的 `-file` 路径（两行）⇒ 布局布线结果相同。
3. 再比位流本体：
   ```bash
   ls -la a.bit b.bit                    # 长度必须先看
   cmp -l a.bit b.bit | wc -l           # 差几个字节
   python -c 'print(repr(open("a.bit","rb").read()[100:160]))'
   ```
   Xilinx 的 `.bit` 头部是键值对：`a`设计名 / `b`部分 / `c`日期 / `d`**时刻** / `e`ID。
   完成后应看到：若 `cmp` 数出来的差异全部落在 `d` 那几个 ASCII 数字里 ⇒ **配置内容逐位相同**——
   这句话的强度远高于"两块位流的 WNS 一样"。
4. 结论要连带说出**代价**：位流相同 ⇒ 板上那块不必重烧（重烧只是再走一次 JTAG）；
   而 `rtl_md5` 变了 ⇒ 所有钉 md5 的台架报告必须重跑才算当前树的凭据（这是同一件事的另一面）。
   完成后应看到：一句"不必重烧"加一句"哪些凭据变旧了"。

## 6. 判读与失败分叉

- 步骤 1：
  通过 = 隔离目录出现且 `build/` 那套的 md5 没变。
  失败 = REFUSE（sed 没生效）⇒ 判 `FAIL`，先去读正式脚本现在的 outdir 写法，不要手改脚本凑绿。
  读不到输入 = 找不到隔离目录（构建没跑完）⇒ `NOT_MEASURED`，别说"应该没覆盖"。
- 步骤 2：
  通过 = 差异只有报告头 `-file` 那两行。
  失败 = 数据行有差 ⇒ 布局布线**变了**，"免费"这句话不成立；此时别再用位流比对去找台阶。
  读不到输入 = 某一侧报告缺失（只有旧的一份）⇒ `NOT_MEASURED`，本轮结论只能写"未证"。
- 步骤 3：
  通过 = `cmp -l` 的字节数与位置全部落在包头 `d` 字段的 ASCII 数字格内。
  失败 = 差异出现在数据段 ⇒ 配置内容不同 ⇒ 判 `FAIL`：改动不是免费的。
  分叉：长度相同但 `cmp` 没跑完 ⇒ 不算证据（第 3 节那条失效条件）。
  读不到输入 = 拿不到第二块位流 ⇒ `NOT_MEASURED`；"只改注释当然不影响位流"是推理不是测量，不许当结论念。
- 步骤 4：
  通过 = 结论里同时给出"不必重烧"和"哪些台架凭据要重跑"。
  失败 = 只念位流相同就宣布本轮全部通过 ⇒ `FAIL`，`rtl_md5` 变了这件事被漏掉。
  读不到输入 = 没有 md5 台账 ⇒ `NOT_MEASURED`，先把两侧 md5 与生成时刻记进留档件。
- 完成的口径（一条可复现的声明要**三样都留档**）：
  ① 隔离目录里的 `timing_summary.rpt` / `utilization.rpt` / `route_status.rpt` 与上一版的 diff
  （"只差两行 `-file`"）；② `cmp -l` 的**字节数**与那几个字节所在的头部字段；③ 两块位流各自的 md5 + 生成时刻。
  少任一样 ⇒ 只能写"部分证明"，不许念"改动是免费的"。

## 7. 已验证的效果

- 本轮实跑（2026-10-04，**只读**，未重跑任何构建）：读仓库内件 `build/system.bit` 的头部（node 读前 200 字节），
  打出的键值对形状正是第 5 节第 3 步说的那五个字段：本仓 `a` = `system_top;COMPRESS=TRUE;UserID=0XFFFFFFFF;Version=2025.2.1;SW_CRC=e5dd9bc8`、
  `b` = `xc7z020clg484`、`c` = `2026-10-04`、`d` = `04:36:56`、`e` = ID 段；
  同一次只读命令读到大小 2 202 122 B、md5 前缀 `cd04907e1369`。⇒ **"头部是键值对、时刻在 `d`" 这一条在当前树上是实测的**。
- 基线凭据（更早轮次的历史件，本轮**未重跑**位流对）：`report/OPTIMIZATION_LOG.md` 的 r85 一节
  （2026-09-29：同为 2 222 010 B，`cmp -l` 差 4 个字节，位置 126/128/129/132，`d 01:12:23` ↔ `d 03:06:24` ⇒ 只差构建时刻）；
  同一夜的两行台账陈述见 `report/log/OVERNIGHT_LOG.md` 的「第二轮"遍历代码"落地 + 隔离构建 r85」与
  「改动是"免费的"，而且是字节级证明」，其中"只改注释当然不影响位流"这个说法被那一轮**推掉**（用推理代替测量）。
  注意时态：那一节里"板上那块不必重烧"只对**那一对**位流成立——随后一轮是真实 RTL 改动并已重烧上板。
- 本轮没做的：没有第二块位流可比（跑一轮隔离构建属于长流程 + Vivado 现场，本轮禁止）⇒
  "现在重跑 `OUT=<目录> bash build/roll_isolated.sh` 仍能只差时刻字段"这条记 `【待验证】`。

## 8. 提炼来源与边界

- 来源证据：2026-09-29 那一夜"第二轮遍历代码"——`report/log/OVERNIGHT_LOG.md`
  里「第二轮"遍历代码"落地 + 隔离构建 r85」与「改动是"免费的"，而且是字节级证明」那两行；
  凭据形状件 `report/OPTIMIZATION_LOG.md` 的 r85 一节；做法代码 `build/roll_isolated.sh`（本轮只读打开核对）；
  被对照的产物 `build/system.bit`、策略扫描入口 `build/tcl/sweep_impl_strategy.tcl`；
  旧卡编号 S27，本包对外仍按号引用。
- 不再适用的条件：你的构建流程默认就把每轮产物写成不可变的新目录（历史可回读），
  那时本条只剩"用包头字段而不是用 WNS 说话"这一半。
- 迁移到新题目/新板卡要改的地方：
  1. 隔离产物目录的机制（本仓是一条 sed 改 outdir + 替换不生效即 REFUSE，示例取值，需按自身工程替换）；
  2. 位流头部键值对的字段名与偏移（`a`/`b`/`c`/`d`/`e` 是 Xilinx `.bit` 的形状，其他家族要重新认）；
  3. 比对的报告清单（本仓 `timing_summary` / `utilization` / `route_status`，滤掉 Date/Command 两行）；
  4. "钉 md5 的台架报告"具体是哪一批（每个工程的凭据口径不同）；
  5. 门禁里那条 mtime WARN 的措辞（本仓念的是"有 RTL 源比 bit 新"）。
- 平台相关：与 7 系列 / UltraScale+ / Versal 的**位流格式**相关（本条在 7 系列 xc7z020 上写成）；
  与工具版本相关——同版本同策略才有"布局确定"这前提。
