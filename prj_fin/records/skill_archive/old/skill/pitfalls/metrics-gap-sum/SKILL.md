## 1. 一句话用途

每个指标都说清分子与分母。

## 2. 适用场景

- 当你准备把"跑 N 秒 → 读回一组计数器 → 折算成 fps / 带宽 / 丢包率"固化成一条可复跑的命令时。
- 当你算出来的吞吐、帧率、平均间隔"好得不像话"，或反过来离谱得说不出口时。
- 当同一行里平均值落在 [最小值, 最大值] 之外时——算术上不可能，口径一定错了。
- 当你准备用"某个错误计数的增量为 0"来宣布"这一轮没丢"时。
- 当这张表要给不是你本人的人复查时。

## 3. 不适用 / 失效条件

- 不适用：需要眼睛的指标（glass-to-glass 延迟、画质主观评价）——本方法只覆盖链路内部数得出来的量。
- 不适用/失效：硬件里不是单调累计、而是"终身保持峰值"的量——它只能取 max，取差值会得到负数或一个假 0。
- 失效：采样期间被测处理器会被调试口停住的系统——墙钟里含停机时间，任何"每秒"类量都失真；
  所以**推流期间不要用调试口读寄存器**，只在前后各读一次就是为了避开它。
- 失效：链路断开或参考时钟被拉走时，"ms"类字段其实是周期数不是毫秒 ⇒ 采集器必须把这两个标志和数字
  一起打印，让读表的人当场决定信不信。
- 失效：折算里写死的几何常数（帧长、每帧字节数）与真实分辨率是两件事——换几何不同步改它，
  按字节折算的帧数直接错。
- 失效：载荷字节增量不是帧长整数倍时帧数会是小数——那是"有半帧没凑齐"的信号，不许四舍五入掉。

## 4. 前置条件

- 两个时刻的**原始读数**能存档（前 + 后），并且存档里每个念给人看的数都回得去。
- 一个只吐结构化数据（一行 JSON 之类）的出口；不要让人去解析人读的判读文案。
- 一条不打硬件、只核算式的自检命令（本仓形状：`node src/host/metrics.mjs --selftest`，示例取值，需按自身工程替换）。
- 一份计数器清单，并已把每个量分成"累计型"与"保持型（峰值/最小值）"两类。
- 每个量的"分子由谁累加、分母由谁数"这两行文字已经写下来（没有就先写，别先算）。
- 本条目在 Vivado/Vitis 2025.2.1 的裸机 + 上位机采集流程下写成（版本真相源见 `skill/_meta/naming-and-format.md`）。

## 5. 使用方法

1. 先给每个量写一行"分子由谁累加、分母由谁数"，确认两者是同一批事件。只要存在"到了但没算"的事件
   （被验收门作废、被丢弃、被截断），分母默认就是虚高的，先扣再除。
   完成后应看到：一行减法形状的口径，例如分母 = 交付帧数 − 作废帧数 − 1，而不是"交付字节 ÷ 帧长"。
2. 间隔类的分母写成**段数 N−1，不是帧数 N**（第一帧只建立基准、量不出间隔）。
   完成后应看到：平均间隔与 fps 都不带 1/N 的系统偏差——写成 N 会让误差 1/N：
   平均间隔被低估、折算的 fps 同比例偏高，几十帧量级约 3 %，个位数帧量级到 20 %。
3. 按类型取数：累计型一律取"后读 − 前读"的差值；保持型（峰值/最小值）取两次的 max，
   且可归零的那类要在测量前归零一次。
   完成后应看到：最小值不是历史值，峰值没有被当成增量。
4. "没丢"写成两条与门：丢字增量为 0 **且** 缓冲满过事件增量为 0。
   完成后应看到：两条各自独立的读数（只看前者会漏掉"满过但刚好没溢出"这种即将出事的状态）。
5. 采集与算式分家：一次测量只在开始/结束各读一次，**前后两次的原始读数**与结论一起存档，
   并走一个只吐结构化数据（一行 JSON 之类）的出口。
   完成后应看到：算式能拿存档重算，而解析器不依赖人读文案的措辞（改一句文案就崩 = 两个工具焊死了）。
6. 给算式配一条**不打硬件的自检**，其中必须有一条反面对照：故意用第 1/2 步说错的那种分母再算一遍。
   完成后应看到：反面对照给出与正确值**不同**的结果；相同就说明这条判据恒真。
7. 给表加一条自相矛盾检查：平均值必须落在 [min, max] 内，越界就当场打印
   "分子与分母不是同一总体，这张表不能用"并置一个标志位，而不是等人肉眼发现。
   完成后应看到：一个可被程序读到的标志位，不只是一句打印。

## 6. 判读与失败分叉

- 步骤 1/2（口径）：
  通过 = 自检里"分母用 N−1"与"错用 N"两条同时存在，且后者红得起来。
  失败 = 只有一条正向判据 ⇒ `FAIL`，它可能恒真；补反面对照再念结论。
  读不到输入 = 分子/分母的累加主体说不清 ⇒ `NOT_MEASURED`，先去读采集器代码，不要先算数。
- 步骤 3（取数）：
  失败 = 差值为负 ⇒ 那个量其实是保持型（或中途被归零过），按 max 重算；
  最小值等于上一轮 ⇒ 没归零，本轮的"最好成绩"是历史值。
- 步骤 4（与门）：
  通过 = 两个增量同时为 0。
  失败 = 只有丢字增量为 0 ⇒ 判 `FAIL`/降级为"未证"，因为"满过但刚好没溢出"没被排除。
  读不到输入 = 缓冲满过事件根本没有计数器 ⇒ `NOT_MEASURED`，先加计数器再谈"没丢"。
- 步骤 5（存档）：
  失败 = 表里某个数在同一次存档的原始读数（前 + 后）里找不到出处 ⇒ 这一轮没跑成，写"未验证"，
  **不许补一个看起来合理的数**。
- 步骤 6（自检）：
  通过 = 一条命令全绿且反面对照红得起来（本仓阈值：分母从 N−1 换成 N 必须算出 >0.3 fps 的差）。
  失败 = 反面对照与正确值相同 ⇒ 判据恒真，本次绿不算证据。
- 步骤 7（自相矛盾）：
  通过 = 平均值落在 [min, max] 内。
  失败 = 越界 ⇒ 算术上不可能，口径错了（多半是分子分母不同批事件），当场拒用这张表。
  读不到输入 = 只有一帧 ⇒ 段数为 0，必须是 `NaN`；表里出现"0 ms ⇒ 无限 fps"就是红的。

## 7. 已验证的效果

- 本轮实跑（2026-10-04，只算式不打硬件）：`node src/host/metrics.mjs --selftest`

  `PASS 错用 N 作分母会得到不同的 fps（证明上一条判据不是恒真）`，第 7 步那条是
  `PASS avg 落在 [min,max] 之外时必须自曝`，并在自检里真打出一行

## 8. 提炼来源与边界

- 来源证据：台账 `report/log/ISSUES.md` #34（测量工具自己会造假这一族）与 #46（任何"平均"都要说清分母）；
  本仓算式与自检的判据集合在 `src/host/metrics.mjs` 的 `--selftest` 分支里（本轮只读打开并实跑该分支）。
- 相邻条目的分界：**怎么得到**这些原始读数（逐帧变化的图案协议、发完再读）见 S9；
  读回来的一组数互相不自洽（部分大于整体）见 S18；带宽/丢包这类"先算后动"的账见 S4。
  旧卡编号 S14，本包对外仍按号引用。
- 不再适用的条件：你的采集器已经把"分子/分母主体"写成机器可读字段并强制打印段数与总体数，
  且表有自相矛盾标志位 ⇒ 本条只剩"每加一个量就补那两行文字"这一半价值。
- 迁移到新题目/新板卡要改的地方：
  1. 每个量的"分子由谁累加、分母由谁数"两行（本仓例：分母 = 交付帧数 − 作废帧数 − 1，示例取值）；
  2. 写死的几何常数（帧长、每帧字节数）必须与真实分辨率同步；
  3. 反面对照的阈值（本仓 >0.3 fps，换帧数尺度就要重定）；
  4. 计数器分类表（哪些是累计型、哪些是保持型、哪些可归零）；
  5. "ms"类字段在链路断开/参考时钟丢失时的含义（周期数 vs 毫秒）。
- 平台相关：本条只约束算式与存档，与器件家族和工具版本无直接绑定；
  但"回读会停住处理器"这一半与调试口存在与否有关，无调试口的平台改用板内时间戳。
