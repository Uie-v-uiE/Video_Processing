## 1. 一句话用途

十个"自己造的红"的签名与一眼认法。

## 2. 适用场景

- 当你新写或改动一个判据台架，**第一跑就红**，而且红得"有道理"（数值很像缺陷的症状）。
- 当你新写一个台架，**第一跑就全绿**，而你还没证明它能红。
- 当你正准备按"红了 = 被测对象错"去改 RTL/固件 —— 先证明红不是判据自己造的。
- 当一次改动里同时冒出**多种形状**的红（差常数倍 / 计数为 0 / 半数组合错在同一个位）。
- 当"查不到"被写成"不存在"，或日志里 grep 到的标记被当成执行结果（一次性探针与盯构建的看门狗是同一族）。

## 3. 不适用 / 失效条件

- **本层是查阅表，不是判据**：任何结论都不能靠本页自称成立，只能靠实测输出或台账记录。
- 红且能指到具体一格（"第 4 行第 212 列不符"）：那是真账，直接走"先量后修"，别拿这十条给被测对象开脱。
- 判据根本没跑（缺自己的执行行、缺样本计数）：十条一张都对不上，因为分子是 0 —— 先回去看它有没有打印执行行。
- 换了仿真器或宿主语言：十条的**形状**仍成立，但里面靠工具行为的写法（`integer` 初值是 X、批处理工具的命令回显、
  格式化符把后面参数对位带歪）要重新量，别照抄结论。
- 判据结构性"红不了"（取数范围里根本没有被测对象）：那是 `skill/pitfalls/criterion-blind-spot/SKILL.md`，不在本页。
- 分界：把对的判成红在这里；结构性红不了在 `skill/pitfalls/criterion-blind-spot/SKILL.md`；工具子集与格式化符造成的假象在
  `skill/references/bench-verilog-subset/SKILL.md`；"判据读的正是自己刚写的文件"这类在门禁脚本头部注释里。

## 4. 前置条件

- 一份**还没改的树**（旧设计本身就是最真的反例，比事后构造的突变可信）。
- 判据自己的执行行与样本计数（分子为 0 时十条都判不出来）。
- 变异对照入口（示例取值，需按自身工程替换：本仓是 `sim/mut_control.sh` 那类脚本，一次只改坏一处）。
- 能记录"哪几条红"的输出留档位；一份台账（本仓为 `report/log/ISSUES.md`）供出处核对。
- 时间与预算：变异法要花时间与一轮预算；预算只够一次时，先做最便宜的两条——阳性对照 + 打印样本数。

## 5. 使用方法

### 5.1 第 0 步（先于查表）：新判据先对"还没改的树"跑一遍，再动源

这一跑同时给你三样东西：判据会不会红（不用人造变异）、红在**哪一格**（期望值的形状对不对）、
以及一份免费的对照留档。顺序写死成"建台架 → 旧树跑（应当红）→ 改源 → 新树跑（应当绿）→ 变异对照（应当只红那一条）"。

本仓现例（示例取值，需按自身工程替换）：`sim/tb_cdc_capacity` 对旧 `dc_fifo` 打 `first_full_after_accepts=8191`（红两条），
改后五条全绿，`sim/mut_control.sh … cdc_full_next` 再打回旧写法 ⇒ `MUTATION OK`
（`report/log/ISSUES.md` #139，两份凭据 `build/r88_cdc_capacity*.txt`）。

⚠ 连带红要如实列：那一改同时红了 C1 与 C3（同一个根因的两个读数），**不要为了让"一次只红一条"而去削弱判据**。

### 5.2 十条签名对照表（红了先不改被测 RTL，按这张表逐条扫自己的判据与激励；顺序按代价从低到高）

| # | 症状指纹 | 一眼认法 / 修法 |
|---|---|---|
| 1 | 期望与实际差同一个常数倍，而且**每一档都差** | 是期望值的算式写错了 —— 真实缺陷一般一格不对或差 1，不会整整齐齐差一个常数倍。期望必须**从定义算**，不从被测代码抄：两条独立的路交汇才算凭据 |
| 2 | 同一份数据里"极值在动"与"变化计数 = 0"同时出现 | 采样相位与被测节拍混叠（例：节拍 40 拍、隔 2 拍比一次 ⇒ 40 是 2 的整数倍，变化永远落在两次采样中间）。改步长与周期互质，或干脆逐拍跟踪；"多采几次"修不好它 |
| 3 | 断言"停在 X"红，而 X 其实还没生效 | 等待窗口比被测节拍短（例：只等 8 拍，而这一档要等一个 40 拍的帧首才落值）。把"等固定拍数"换成**等事件**，并且等不到必须判红，不许静默通过；结果放模块级变量，别用同一个整数既当本轮结果又当累计器（那会让累计器每轮被覆盖 ⇒ 假绿） |
| 4 | 半数组合红、半数对，而且错在**同一个位** | 激励自己的位序写反了（例：拼成 `{1'b0, idx[2]}` ⇒ 硬件于是**正确地**报出反值）。把位序按端口的文档写死，别改期望去迁就它；顺手把组合扩到覆盖全部编码（含保留值）—— 红的时候判据要变**强**，不能变松 |
| 5 | "跑没跑起来"这类下界判据整片红 | 下界要按物理算（例：一趟含回程共 256 个节拍 = 10240 拍，窗口却开成 900 拍）：窗口不够长不是判据太严，是判据没跑到被测的那一步 |
| 6 | 几条问法都返回 0，看起来就是"没有" | "查不到"之前先放**阳性对照**：同一次运行里查一个明知存在的东西；对照没过，那个 0 是命令语法问题，不是事实。同一问题问不通就停手（3 次就回退），把"未答上来"写进对外清单；探针日志自己得写明"这两道问法已被对照证伪"，否则以后会被当证据引用 |
| 7 | 多版全绿、忽然红几条，且红的全是"应当变化"型、"不该变化"型全绿 | 判据在赌一个它从没检查的**起点**（现场常常是有人手动动过状态）。修两步缺一不可：给状态机一个机器可写的复位入口；复位之后**读回来验**。通用检查：每条"应当变化"的判据旁边写清它假设的初始态、谁负责摆回去、摆没摆成功怎么知道 |
| 8 | 只在仿真里出现、硅片上不可能的事（每拍都像收到事件、值变 X/z） | 新加输入端口时旧台架没人接 ⇒ 浮空成 z ⇒ 边沿检测恒真。模块侧防法：把"必须是实 0/1 才算一次事件"写进 RTL（`===` 两头判，不多花一个 LUT）；流程侧防法：新加端口的同一轮跑**全量**回归，因为受害的往往是你没想到的那份台架 |
| 9 | 没有任何一处报红，只有操作者觉得"是我打错了" | 解析器"半个接受"：静默补零 / 静默截断 / 静默取模。规则：**要么明确接受、要么明确拒绝且不产生副作用**（"拒了还写寄存器"与"收了但不改"同罪）；修法要自带一句回显，把"程序实际听成了什么"念出来；判据里除"这条要红"再配一条 `!` 反例证明**没写** |
| 10 | 绿得莫名其妙；同一份数据两条判据一个绿一个红 | 判据在 X/空集上"通过"：含 X 的比较求值为 X ⇒ `if (...)` 不成立 ⇒ 错误计数器一次都没涨。加一条 X 探测（`(v ^ v) !== 0` 即有 X/Z；`$isunknown()` 属 SystemVerilog，Verilog-2001 编不能用），并给"逐格相等"类判据显式带上 X 占比上限 + 覆盖面（样本数下限）+ 一条自洽判据 |

### 5.3 三条口径 + 两步收尾

1. **再补三条口径**：多比特字段的期望值按编码手抄成表（写成与被测式子同形的式子＝把 RTL 抄进台架）；
   行为类判据把被测函数原文抠出来现编、不要在测试里重写一份；位号与常量从规格侧抠，别从抄件抠。
2. **绿了做一次变异**：改坏被测一处 → 跑 → 改回，记下哪几条红（判读见 §6）。
3. **别把"没测到"写成"测过没问题"**：判据取数点若不是被测对象本身（例：探针数的是写通道的 enable，
   而不是被判的那块缓存的写口），就只报数、不写成判据 —— 否则红的是你的模型，报出的数字却被后人读成硬件结论。
4. **上面都过了还是红** ⇒ 那才是被测对象的，转"先量后修"。

### 5.4 查表步骤

1. 先按 §5.1 对未改的树跑一遍，拿到"会不会红、红在哪一格"。**完成后应看到**：红项 + 具体格位，或一条明确的"这条判据红不了"。
2. 用 §5.2 的"症状指纹"列逐行比对，命中就**只改判据侧**（顺序按代价从低到高）。**完成后应看到**：命中编号（1–10）或"十条都对不上"。
3. 按 §5.3 补三条口径与取数点归属。**完成后应看到**：每条"应当变化"判据旁边有初始态、谁摆回、摆没摆成功怎么知道。
4. 做一次变异并记下红项集合。**完成后应看到**：`MUTATION OK` 且红的就是它声称红的那几条；连带红按 §5.1 的 ⚠ 如实列出。
5. 十条都命中不了、且分子非 0 ⇒ 才进入被测对象的"先量后修"。**完成后应看到**：一句"红的是被测物，依据是第 X 格读数"。

## 6. 判读与失败分叉

- **一次可执行的变异对照**：改坏被测一处 → 跑 → 改回；**必须至少一条判据红**，且"哪几条红"要留在输出里。
  一条都不红 = 这条判据是装饰，第一跑的绿不作数。
- **判别力的数字关系（这才是重点）**：对同一个机制做两种变异 —— "沿翻倍"红 3 条，"只删延迟、保留末态"只红 1 条
  ⇒ 末态类判据**永远抓不到时序错**，它会放走一个真 bug 还让人以为验过了。凡机制含"先后"，就要有一条以拍/ns 为单位的断言，
  并且它单独在某次变异里红过；上下界都卡（`min == max == 期望拍数`），只卡下限时"根本没发过沿"会顶着初值假绿。
- **假红必须能被这套清单复现**：一份新台架一次就能凑齐前三种签名（例：`sim/tb_v94_zoom_sel.v`）；
  "末态类判据抓不到时序错"要用两次变异的凭据量出来，而不是讲出来
  （例：本仓示例取值，需按自身工程替换：`sim/tb_v95_zoom_snap.v` 那份台架的两次变异读数）—— 十条里没有一条是想出来的。
- **十条都对不上而分子非 0**：那是被测对象的账 ⇒ 转"先量后修"，别继续在本页找借口。
- **分子为 0（没跑 / 缺样本计数）**：十条一张都判不出来 ⇒ 先补执行行与样本计数；"计数型判据必须有非零样本"永远优先于这十条。
- **读不到输入**：台架缺件、变异脚本找不到、凭据目录空 ⇒ 记 `NOT_MEASURED`，不许把"跑不了"念成"过了"，也不许据此改阈值。
- **换工具后照抄**：靠工具行为的三条写法（`integer` 初值、批处理回显、格式化符对位）必须重新量，否则本页给的形状不成立。

## 7. 已验证的效果

- 十条全部来自实测（"十条里没有一条是想出来的"）：三种假红由同一份新台架一次凑齐（例：`sim/tb_v94_zoom_sel.v`）；
  "末态类判据抓不到时序错"由那份台架两次变异的读数量出（红 3 条 vs 红 1 条）—— 台架名 `sim/tb_v95_zoom_snap.v` 是本仓示例取值，需按自身工程替换。
- 第 0 步的顺序（旧树先跑）在本仓的凭据：`sim/tb_cdc_capacity` 对旧 `dc_fifo` 打出 `first_full_after_accepts=8191`、
  红两条，改后五条全绿，变异对照 `MUTATION OK`（`report/log/ISSUES.md` #139，凭据 `build/r88_cdc_capacity*.txt`）。
- 出处记录（2026-10-04 用 `grep -n "^## "` 核对三节标题存在）：`report/log/OVERNIGHT_LOG.md` §35（同一份新台架一次凑齐三种假红，
  硬件其实全对）、§41（"查不到"被自己的阳性对照证伪）、§43（批处理工具的源码回显被当成执行输出），
  以及 `report/log/ISSUES.md` #60（一条什么都没判的判据报成 PASS）。
- 未实测：两次变异（"沿翻倍" / "只删延迟保留末态"）的**具体红项编号清单**与 `sim/tb_v94_zoom_sel.v` 那三种签名的
  逐条读数，旧卡只给了形状没给逐条值 ⇒ `【未实测】`；本页未复跑任何台架（迁移是只读动作），
  要把第 0 步的成本数字用在自己工程上，需按 §4 的时间预算先跑一遍。
