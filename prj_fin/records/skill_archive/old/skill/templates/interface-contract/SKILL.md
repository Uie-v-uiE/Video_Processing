## 1. 一句话用途

把两侧接口的每个位域与副作用钉成一张表，让联调靠表不靠记忆。

## 2. 适用场景

- 当"命令发了没反应"或"读回来的不是写进去的"这类现象出现，而两侧代码各有一份地址/掩码字面量时。
- 当新增一个通道、一批状态窗口或一批 lane，需要同时改 RTL mux、主机访问层与文档三处时。
- 当多字读回有时自洽、有时出现"部分大于整体"这种物理上不可能的数时。
- 当上电默认档与文档/讲稿里的默认不一致（演示当场会被发现）时。
- 当某一位是反相/低有效、或"只在静止窗口生效"、或写它会把整组量锁存成快照时。
- 当交付要求"软硬件协同"必须说清接口（哪条通道、谁等谁、单位是什么）时。

## 3. 不适用 / 失效条件

- 两侧之间只有一条标准总线且无自定义位域（如纯 AXI-Lite 挂厂商 IP）：表退化成 IP 手册引用，别自造一份。
- 你要填的是性能/时序读数而不是寄存器定义：用 `../report-forms/`（`timing-readout.md` 与 `metrics-table.md`）。
- 接口还没定、正在讨论放哪一侧：先用 `../../prompts/hw-sw-partition/` 出划分表，再回来钉契约。
- 硬件定义文件/块图与 RTL 都拿不到（只有别人口头说的地址）：第 4 节 C1/C3 两条无法判 ⇒ 先要文件，别先填表。
- 只做一次性实验、不交付：可以只填偏移/位域/读写属性三列，其余三列（副作用、时钟域、量程）留空会立刻咬人，所以要么填要么显式写"未核"。

## 4. 前置条件

- 能打开硬件定义/块图对象列表（取基址、位宽、中断连接）。
- 能 grep 到 RTL 侧的读回 mux 与寄存器声明（位域、反相、快照武装）。
- 能 grep 到主机侧初始化代码里的 `static` 初值或等价默认设置（复位值列的唯一合法来源之一）。
- 有一个能执行"写图案再读回"的对象：真板、或包含该总线的仿真环境。
- 表格能导成机器可读（CSV/JSON）——否则第 4 节 C1/C2 只能靠人眼，人眼会漏。
- 权限：允许修改主机侧访问层的常量生成方式（禁止在代码里手写第二份地址）。

## 5. 使用方法（在陌生工程里实例化）

模板文件：`contract-table.md`（同目录，一层深）。
槽位计数自检（命令 `grep -o '【填入' contract-table.md | wc -l`，实跑 2026-10-04）= 10；本 `SKILL.md` = 2。
实例化到陌生工程后，目标文件里这两个数应当归 0（复位值那一格除外——取不到就写 `【未实测】`，那是允许的第三态）。

### 5.1 步骤

1. 复制并把文件名换成纯英文小写：
   ```bash
   cp <技能包>/skill/templates/interface-contract/contract-table.md <你的仓库>/report/register_contract.md # 示例
   ```
   **完成后应看到**：目标文件存在，四行元信息注释还在。
2. 先只填三列：对象、偏移/地址、位域。从硬件定义/块图里取，不取记忆：
   ```bash
   grep -nE '【填入：你的通道实例名】' <你的块图或网表导出文件>
   ```
   **完成后应看到**：每个对象一个具体地址；表里出现两个相同地址时立刻合并或拆开（C1 的预演）。
3. 填读写属性与复位值：复位值必须带依据（代码初值 / 约束初值 / 实测回读三选一），
   取不到写 `【未实测】`，**不许写 0**。
   **完成后应看到**：`grep -c '【未实测】'` 的数你愿意解释；每处都有一个补它的具体动作。
4. 填三类副作用列（写/读/时钟域）：按 `contract-table.md` 第 2 节的三类最容易漏的字段逐条对照，
   特别检查有没有窗口式读回（先写选择字段再读）与反相位。
   **完成后应看到**：窗口协议那一段有一行"新成员必须排在该组第一个字之后"，或者你确认这一族不存在并写出依据。
5. 跑四条一致性检查（C1–C4）：
   - C1/C2 用导出的 CSV/JSON 与主机侧常量比对（交集 0、不一致 0）；
   - C3 逐格回读代码行；
   - C4 对上电对象做一次"写图案再读回"：
     ```bash
     # 示例形状（把基址与图案换成你的）：写 0x1FF → 读回 → 比对
     echo "write 0x1FF; readback?"   # 【填入】你的主机侧写读命令
     ```
     **完成后应看到**：读回 == 写入；不等时把现象写进"写副作用"列而不是直接改代码。
6. 让主机侧代码从这张表生成常量（一处真值），并在文档里只指路不复制数值。
   **完成后应看到**：`grep -rn '<某个地址字面量>' src/` 命中数 = 1（生成处或表本身），不是两处手抄。

### 5.2 填完之后必做的交叉检查

- 每个 `文件:行` 出处都重新 grep 一次该行的标识符还在不在原位（改结构会漂）。
- 单位与量程列里凡"换算发生在某一侧"的，都要写清原始单位（拍/计数）与换算式；
  跨多拍算出来的成员要连带一个"计算没在跑"的可信位。

## 6. 判读与失败分叉

- **通过**（C1–C4 全过 + 副作用三列非空）：契约冻结，改接口必须同批改这张表与生成它的代码。
- **失败：偏移重复或位域重叠**：两侧只有一侧是对的；先定权威来源（硬件定义），再改另一侧，
  不要在表里给两个地址加注释共存。
- **失败：C4 读回 != 写入**：三种可能各由一个读数区分——位宽截断（看最宽输入列）、
  该位被 RTL 里别的驱动覆盖（看例化与多驱动检查）、该通道在硬件定义里根本不存在（看 C3 的依据列）。
- **失败：多字读回撕裂**：先怀疑读法而不是硬件——连续读几组看恒等式是不是**随机**破
  （真缺陷稳定复现，撕裂随机）；确认是撕裂就加快照武装口，别多读几遍碰运气。
- **读不到输入**（拿不到块图/代码初值）：该格 `【未实测】` + 一行"缺什么"；
  禁止用"通常复位为 0"填坑。
- **表与代码有两处地址字面量**：立即改成由表生成，并在门禁里加一条"文档数字必须能重算"的检查。

## 8. 提炼来源与边界

- 提炼来源：`report/ARCHITECTURE.md` 第 3 节、`report/DEFAULTS.md` 第 1 节、
  `skill/runtime/atomic-register-window-readback/SKILL.md`、`skill/pitfalls/arbiter-pending-pulse/SKILL.md`（写请求与仲裁的排队副作用）、
  `report/COMMAND_PRECEDENCE.md`（命令之间优先级与冲突裁决＝写副作用的一种）、
  `report/log/ISSUES.md` #118/#126（默认档不一致的收口）、#103（越界写两侧行为不同）、
  `src/host/line_cite_check.mjs`（`文件:行` 引用的锚点检查器）。
- 迁移要改的：地址与位域全部换成你的工程值；"中断号"列在纯轮询系统里写"无（轮询）"并给依据；
  窗口/快照那一类只在"一个读口读多字"时才需要；Zynq ↔ Intel/Altera ↔ 外挂 CPU 的差别体现在
  "时钟域"列的同步方式（硬核互连自带 CDC 的与手写 2FF 的，判据不同）。
- 失效条件：接口由厂商 IP 手册唯一决定且你从不改位域（此时表是手册的转抄，维护它只会引入第二处真值）；
  两侧之间是流式数据面而非寄存器面（那要写成协议表：帧格式、字段顺序、校验、超时，本模板的偏移列不适用）。
- 边界：本条目管"接口长什么样、有什么副作用"，不管"这个数是多少"（`../report-forms/`）
  与"这一刀值不值"（`../../prompts/single-variable-ab/`）。
