# 时序与资源读数表模板

## 1. 逐时钟域花名册（制表符分隔，第一行是列名，逐列不可省）

```
clock	period_ns	src	wns_setup	tns_setup	nfp_setup	wns_hold	tns_hold	nfp_hold	rel_margin_setup	rel_margin_hold	unconstrained_endpoints	io_unconstrained_ports	intra_endpoint_total
【填入】	【填入】	【填入】	【填入或NA】	【填入或NA】	【填入或NA】	【填入或NA】	【填入或NA】	【填入或NA】	【算式：wns/period】	【算式：whs/period】	【填入】	【填入】	【填入】
```

列名与口径的出处（示例取值，需按自身工程替换）：本仓库 `docs/timing/roster_baseline.tsv`（2026-10-03 22:45）用的就是这 13 列；它的文件头把口径写死在两行注释里（`rel_margin_* = wns_* / period_ns`、`io_unconstrained_ports = check_timing 的 HIGH 两类之和`）。

## 2. 填这张表的六条硬规矩

1. **一个时钟域一行**，不许只交"全局最差那一条路径"那一行；全局读数另起一行标 `GLOBAL` 并注明它是逐域行的汇总而不是替代。
2. **没有读数填 `NA`，不填 0**。空值、全 0、全 X 被当成通过是这类表最严重的一类错。
3. **相对裕量必须同时给分子与分母**：`rel_margin = wns ÷ period`，并在文件头写明分母是谁。
   跨域比"谁的 WNS 更小"没有意义（周期不同）；跨域比 `rel_margin` 才有可比性。
4. **不对称的约束要显式标出来再比**：若某个域带不确定度、另一个域没带（判据是"报告里那一行在不在"，
   不是"约束文件里还写着"），这两个域的 hold 余量**不可比**，在这一行旁加 `comparable=no` 列或注明。
5. **未检查不等于满足**：`unconstrained_endpoints` / `io_unconstrained_ports` 两列记的是"这些端口被当理想时刻"，
   读数非 0 时该域不许写"收敛"，要写"未检查 N 个端口"。
6. **每个数旁边放出处**：文件头两行必须写 `A=<基线件路径>`、`B=<本轮件路径>` 与生成命令；
   逐轮差值只在两端同生成器时才允许存在（混口径要拒绝比较，而不是"凑合比"）。

## 3. 判读列（差分之后再加，不要手填）

跨版本比较时另出一张差分表，列名沿用本表再加后缀：

```
clock	…（同第 1 节全部列）…	b_wns_setup	b_rel_margin_setup	rel_margin_setup_delta	rel_margin_hold_delta	unconstrained_endpoints_delta	io_unconstrained_ports_delta	verdict
```

- `verdict` 只允许 `GREEN` / `RED`（逐域判定），并另写一行整体结论；判定条件写在文件头注释里，
  例如"相对余量不许变小"（G1）+ "两列债务计数不许变大"（G2）。
- **头条绝对值只念不判**：最差路径换了主语（换到别的模块或别的域）时，绝对差不算收益也不算损失；
  这时报"族计数/归属"这类噪声做不到的量。
- 任何"改善"必须同时说明其他域有无退化；有一条变差就要点名是谁。

## 4. 资源与功耗读数（与花名册同一套产物）

| 读数 | 值 | 单位/占比 | 出处（报告文件 + 那一行的原文标签） |
|---|---|---|---|
| LUT（Logic+Memory 之和） | 【填入】 | 【填入】% | 【填入：报告路径；写清你读的是哪一行标签】 |
| 触发器（Slice Registers） | 【填入】 | 【填入】% | 【填入】 |
| BRAM（tile） | 【填入】 | 【填入】% | 【填入】 |
| DSP | 【填入】 | 【填入】% | 【填入】 |
| 实现后动态功耗 | 【填入】 | W | 【填入】；**并抄工具自报的置信度**（置信度低就在报告里如实说） |
| 结温估算 | 【填入】 | ℃ | 【填入】；注明"这是工具估算，不是板上读数"，板上量到的另起一行 |

规矩：

1. LUT 与 FF 一起念，只看一边会得出错误结论（一级寄存可能只从 LUT 搬到 FF）。
2. 资源读数要和"归属"配对：这一轮比上一轮多/少的 N 个，能不能归到某个具体改动上？归不到就写
   "净账由两份逐层件相减闭合"或"其余没有归属，不念成收益"。
3. 工具估算与板载实测要分行、不同名称，禁止混成"实测温度"。

## 5. 归档目录内还要留下的东西（一轮一件，不覆盖上一轮）

- 花名册两件（基线 A / 本轮 B）+ 差分一件；
- 逐域最差路径的分解件（含 `Data Path Delay` 的 logic/route 百分比与 Logic Levels 原文行）——
  这一件决定下一刀属于逻辑侧还是物理侧；
- `check_timing` 的原始输出件（未点名端口逐个列名，不是只留计数）；
- 门禁/判据脚本的逐条输出件（收尾必须含"判定 N 项、红 M 项、未判 K 项"）；
- 产物身份三件（位流/硬件定义/可执行文件）的 md5 与工具版本行。
