## 1. 一句话用途

用一张目录树把可交付仓库的骨架立起来，并留好目录对照表。

## 2. 适用场景

- 当仓库刚建、`src/ sim/ build/ report/` 各层职责还没写成一页纸，两个人开始把凭据放到不同目录时。
- 当出现"这一轮的报告覆盖了上一轮的报告"（没有轮次号归档目录）时。
- 当交付前自检要回答"文件名是否纯英文小写""脚本里有没有本机绝对路径"这两类硬条文问题时。
- 当评审或新队员问"你报告里这个数走哪条路径能复核"，而你只能口头指路时。
- 当队伍决定偏离推荐目录结构（例如把文档拆成三层）而需要在 README 里给出对照说明时。

## 3. 不适用 / 失效条件

- 仓库组织已稳定且这次只改内容：改 `report-forms/` 与 `interface-contract/` 那两条就够了，重排目录会让所有行号引用一起失效。
- 只需要一支脚本的模板：直接用 `../script-template/`，不要顺手重建骨架。
- 非赛题交付（内部项目、只做一次实验）：第 3 节归档命名式与第 6 节自检四条里的"交付导出"部分是为评审复核设计的，内部实验跟着做只会增加开销。
- 当你手上还没有器件/工具版本信息：骨架能建，但 `MANIFEST.md5` 的版本行会空着——那是前置不满足，别把它填成猜测值。

## 4. 前置条件

- 项目名与仓库根路径（决定 `<项目根>` 与归档目录前缀）。
- 器件 part 字符串与工具版本（要写进清单第 4 行，见 `project-skeleton.md` 第 6 节 A4）。
- 一条"能列出跟踪文件"的命令（`git ls-files` 或你用的 VCS 等价物）；没有 VCS 时 A1/A2 两条自检改用目录遍历。
- 赛题指南条文原文在手（用于第 5 节对照表左列照抄）；本模板**不**复制那张表，因为本仓库里没有它的副本文件——照抄来源必须是你的指南 PDF，不是本模板。
- 权限：能在仓库根建目录；不需要硬件连接。

## 5. 使用方法（在陌生工程里实例化）

模板文件：`project-skeleton.md`（同目录，一层深）。
槽位计数自检（命令 `grep -o '【填入' project-skeleton.md | wc -l`，实跑 2026-10-04）= 14；本 `SKILL.md` 同法 = 1。
实例化完成时这两个数应当归 0（对目标文件再跑一次同一命令即可判定）。

### 5.1 步骤

1. 复制模板正文到你的仓库根，先只改 `<项目根>` 一个值：
   ```bash
   cp <技能包路径>/skill/templates/project-skeleton/project-skeleton.md ./docs_dir_map.md
   ```
   **完成后应看到**：`docs_dir_map.md` 存在，内容里目录树的第一行是你的仓库名。
2. 按第 1 节的树建目录（不需要的整目录删掉，别留空目录）：
   ```bash
   mkdir -p src/rtl src/constraints sim build/tcl board data/golden data/measured report/log skill/prompts skill/templates skill/pitfalls skill/references
   ```
   **完成后应看到**：`ls` 出的顶层与模板树一致；差异项要么补上要么在对照表里给理由。
3. 填模板第 2 节那张表的"不放什么"列——每一行都必须由你写，不能留 `【填入】`。
   **完成后应看到**：每个顶层目录有一行实际职责；行数 = 顶层目录数（这是 A3 判据）。
4. 定归档目录前缀并写进模板第 3 节，命名式落成一条可执行的 `mkdir` 习惯（例：每采纳一键一个目录）。
   **完成后应看到**：模板第 3 节里没有 `<尖括号>` 残留。
5. 填第 5 节目录对照表（左列照抄指南原文），并把这张表贴进根 `README.md`。
   **完成后应看到**：README 里那张表的"复核路径"列每格都含一个具体文件名。
6. 跑第 6 节四条自检（当天跑，别等交付前）：
   ```bash
   git ls-files | grep -v '^[a-zA-Z0-9._/-]*$' | wc -l          # A1
   grep -rn -e '<你的盘符>:' -e '/home/' src build sim board | wc -l   # A2
   ```
   **完成后应看到**：A1 = 0；A2 在脚本与交付文档内 = 0（临时探针脚本允许留档，但要在报告里点名）。

### 5.2 实例化时的三条硬约束

- 目录名与文件名只用小写字母、数字、连字符、下划线；中文只出现在正文（模板第 7 节引的条文）。
- 不写厂商 flash/擦写板载存储的脚本进 `build/tcl/`（示例取值，需按自身工程替换：本仓库口径是"改板只走调试链路"）。
- `report/log/` 只作过程留痕：任何写进 `report/` 的结论都要能由某个脚本从盘上重算（模板第 2 节表末行）。

## 6. 判读与失败分叉

- **通过**（四条自检都过 + 对照表填满）：骨架冻结，后续只往目录里放东西，不再重排。
- **失败：A1 非 ASCII 计数 > 0**：把这些文件重命名；如果它们是自用学习件，移出跟踪集（不要为了过检而在导出时偷偷改名而不留对照——本仓库用生成 `NAMES.md` 的方式把新旧名对上，见 `report/log/CONTEST_CHECKLIST.md` 第 21 行的做法）。
- **失败：A2 绝对路径 > 0**：脚本按自身位置回算根目录，工具路径统一走环境变量；改完要跑一次"故意把变量指向不存在路径"的正对照，确认脚本在第一步就拒绝而不是跑出半截产物。
- **失败：A3 表行数 < 顶层目录数**：说明有目录没人说它放什么；补行，或删目录。
- **读不到输入**（没有指南原文、或没有 VCS 列文件能力）：A1/A2 记 `NOT_MEASURED`，不要用"看起来都是英文"代替计数。
- **偏离推荐结构但对照表空着**：这是条文要求缺项，直接补第 5 步，不要先讨论结构是否更优。

## 7. 已验证的效果

- 本仓库的真实目录树（`ls` 实测 2026-10-04 08:39，仓库根）：顶层含 `src/ sim/ build/ board/ data/ report/ skill/` 与根 `README.md`、`LICENSE`；`src/` 下是 `constraints/ host/ ps/ rtl/`；`data/` 下是 `golden/ measured/`；`report/` 下有 `log/`。模板第 1 节的树由此抽象而来，不是设想图。
- 条文口径来源（本地核对，2026-10-01）：`report/log/CONTEST_CHECKLIST.md:21`（文件名纯英文小写口径 + 大写名作为文档化例外的处理方式）、`:120`（采用其他组织方式须在 README 给出目录对照说明）；同文件"提交包结构（推荐目录）"一行写明"仓库里文档按三类放（`report/` 交付物、`report/log/` 工作记录、`report/study/` 本地学习件不入库）"，并说明导出脚本会照官方目录另出一份提交包。
- 工具路径拒绝的正对照（模板 A2 的落地形态）：`report/BUILD.md`（2026-10-02 09:23）第 1 节末尾贴出的实跑输出——把变量指向不存在路径后脚本打印 `REFUSE: 找不到 xvlog（当前 …）` 且 `rc=2`，并写明"拒绝发生在 `mkdir`/`sed` 之前"。
- 空目录演练（P03 的验收方式：把骨架 + 构建脚本复制到新目录只改槽位跑一遍）：`【待验证】`——本条目未在新目录真跑过（本次只读仓库、只写 `skill/prompts/` 与 `skill/templates/`，未被授权建第二个目录）。还差：一次完整的空目录演练记录。

## 8. 提炼来源与边界

- 提炼来源：`report/log/CONTEST_CHECKLIST.md`（2026-10-01，条文对照与未达成清单）、`report/BUILD.md`（2026-10-02，环境变量表与"脚本不许写死绝对路径"的规矩）、`build/make_submission.sh` 头部四条判据（2026-10-02 21:35：按引用留凭据 / 被否决轮次不进包 / 交付名工程化 + 生成新旧名对照 / 导出后自检不过就不落盘）、`data/metrics.csv`（2026-10-04 06:23，"一行一指标带凭据路径"的落地形态）。
- 平台相关、迁移要改的地方：目录本身与家族无关；要改的是第 3 节归档内容清单（Versal 与 7 系列的产物名不同）、`MANIFEST.md5` 里"三件套"的具体件（有的流程还有处理器侧镜像或设备树），以及第 6 节 A2 的盘符写法。
- 失效条件：仓库已经按另一套推荐结构交付过一轮（重排会让所有 `文件:行号` 引用与文档门禁一起失效）；此时把本模板当"职责口径检查表"用，不要动目录。
- 边界：本模板给目录与命名，不给构建流程（`../script-template/`）、不给读数表头（`../report-forms/`）、不给寄存器契约（`../interface-contract/`）。
