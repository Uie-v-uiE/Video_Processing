# 验证：四类检查，各答各的问题

验证分四层，互相不能替代。

| 类别 | 它回答什么 | 跑法 |
|---|---|---|
| 仿真台架 | 逐拍、逐像素的协议与几何行为对不对 | `bash build/sim/run_msim.sh <tb>` 或 xsim |
| 实现报告 | 布线后的时序和资源是多少 | Vivado 构建后读 `build/r162/*.rpt` |
| 板级复验 | 真板子上帧率、作废、时延、像素计数是多少 | 推流 + 遥测 + 串口 |
| 人眼签收 | 屏幕上的观感有没有问题 | 按 `board/acceptance.md` 逐条看 |

四层都保留第三种状态：通过、未通过、没测到。读不到输入既不算通过，也不算失败；必须写成“没测到”。

## 仿真台架

最底层是单元与集成台架。`tb_udp_telemetry` 例化真实的 `udp_tx` 和 CRC 核，从 GMII 口按帧偏移抓字节，逐字节比对以太网头、IP 目的地址、UDP 端口和载荷。它曾经在旧 RTL 上红在“首字节是 0”，修好后才转绿。`tb_eth_ctrl_arb` 在 ICMP 帧中间请求 UDP、在 UDP 帧中间请求 ARP，判据是每帧字节恒定、长度正确、顺序正确；把仲裁的空闲条件人为改成恒真，这个台架会红。

帧重组有两支台架。`tb_udp_reasm` 覆盖正序、乱序、坏包、重复包和第二次成帧；`tb_reasm_bounds` 覆盖越界偏移不许写、但必须计数。r152 又给 `tb_rows` 加了第三腿：四包共 64 字节，但只有三行，行 2 重复，要求不提交。把行计数改成“每写一个字加一”，这条会红；真实 RTL 下是绿的。

完整视频台架在 r156 上把旋转、八档缩放、双线性、六级效果、竖缝、OSD 和边界条件放在一起跑，跑满 4,569,600,090 ns，0 errors。其中 C17 系列针对 185° 场景：分割按画面列、灰度只开一级、swap 两态各跑两帧，要求处理侧非灰像素为 0；这一组在显示通路的 RTL 上通过。r160/r161 的显示侧改动由 C22/C31 分别复验；r162 只动 ETH 发送校验和，显示侧没有动。

r162 树上的一次回归覆盖十七支台架：显示侧八支、ETH/OSD/遥测/分割九支；ModelSim 汇总行是 `MSIM DONE fail=0`。同一组命令连跑两遍，两跑的 `RESULT`/`MSIM DONE` 行逐字相同（`build/msim/r162_full_regression_20261022.txt` 与 `r162_full_regression_2.txt`）。r162 的 UDP 校验和改动另跑四支 ETH 台架，全部 PASS。

## 台架能红，才算判据

一条出生以来没有红过的判据不构成证据。这个项目里能红的判据至少有四类：

- 遥测台架在旧 RTL 上红过“载荷首字节是 0”，修的是真实的两级寄存器时序。
- 发送仲裁台架在把空闲条件改成恒真之后红过，帧被从中间截断。
- 帧重组的行覆盖判据在“每字加一”的变异下红过，真实 RTL 下绿。
- 三阶段链路自检在注入丢包时必须让作废计数上升、帧率下降；如果没有反应，仪表本身就不成立。

## 实现报告

r171 候选的实现报告在 `build/r171/`。时序是 WNS 1.341 ns、WHS 0.025 ns、TNS=THS=0，失败端点 0；资源是 LUT 28.13%、FF 8.55%、BRAM 70.00%、DSP 19 颗。逐域数字和约束理由在 `report/05-timing.md`。

这些报告和位流是同一次构建的产物。报告日期、位流 md5 和 XSA md5 一起写在 `board/README.md` 的身份表里，避免拿上一版的报告配这一版的位流。

PS 源码另做了一次静态检查：`cppcheck --enable=warning,style,performance,portability` 跑 `src/ps/main.c` 与 `sd_play.c`，没有 warning/error 级问题，只有 1 条“数组下标在界判前读取”的顺序风格提示（`meta_try` 的输入是本文件内的静态样本，界内安全）和几处作用域/同名遮蔽。日志 `build/cppcheck_ps_20261022.log`。

UDP 发送校验和也补了能红的对照：`tb_udp_telemetry` 原来只比头、端口和载荷，2026-10-22 加了“IP 头 10 个 16 bit 字求和、折叠后应为 `16'hffff`”的判据；故意少加一项时 T1/T2 报 `FAIL ip checksum sum=003c`，恢复后四支 ETH 台架全过（`build/msim/r162_checksum_mutation_fail3.txt`、`r162_checksum_final4.txt`）。

PS 命令通道另有一条 2026-10-22 的 A/B：同一行 200 字节，老 ELF `d765fa1bc716` 会把前 127 字节当完整行派发（`[CMD]` 1 次），`c5be592ca30d` 整行丢弃（`[CMD]` 0 次、`[CMD!]` 2 条），随后 `STAT` 都能恢复。扩展探针 `board/cmd_overflow_probe.sh` 的 O0–O5 全过，日志 `board/measured/cmd_overflow_20261022_0141.txt`，A/B 原始捕获在同目录 `cmd_overlong_*`。
同一条路径上又发现 #502：`sd remount` 执行期间收到 `STAT` + 200 字节行，`c5be` 会把 `STAT` 和超长行一起清掉（`[STAT]` 0 条）；`172275aab352` 截掉超长行但留下 `STAT`（1 条），`th` 的前缀也没有执行。捕获 `build/serial_block_burst.txt` / `serial_block_burst_fixed.txt` 与 `serial_prefix_long.txt`；105 条电池 98.5 s PASS（`build/uart_battery_r167_20261022.log`）。

## 板级复验

r162 位流用 JTAG 装到板上，FLASH 与 HEALTH 均为 GREEN；host 侧 10 秒收到 11 包 1 Hz UDP 遥测，说明改过的 UDP 校验和能被 host 协议栈接受。r159 位流上用内置测试图连续推 8.00 秒，遥测帧数与发送端同为 240 帧，折合 30.00 fps；PL 内部时延在 2 到 16 ms 之间，只有启动时的一次作废。停流后时延自动变成无效值，不会拿旧数冒充新数。

三阶段自检在同一块板子上跑通：干净段 18.9 fps、作废不增长；每 100 包丢 1 包的故障段掉到 0.2 fps、作废每秒 13.0 次；第二段干净流恢复到 22.2 fps、作废不增长。故障段的帧率下降和作废上升都是线上读数，不靠屏幕判断。

处理窗完整性计数在 r151 上板验证过：30 fps 的 ETH 连续流、185°、split video 50%、只看灰度，遥测读到 `pane_bad=0` 且计数有效。r160/r161 的显示改动由 C22/C31 复验；这条 pane 读数在 r151 上板后仍然成立。

## 仿真答不了什么

台架不判屏上观感。模糊够不够柔、边线粗细、颜色是否顺眼，只有看屏幕的人能判；这一部分留在 `board/acceptance.md`。

台架也不判 PHY 到 FPGA 那段片外时序窗口。RGMII 收口的输入窗在当前生产约束里没有加载，所以那 5 个输入端点不在静态时序检查的射程内；这不是“通过”，是“没测到”。发送侧的 TskewT 缺口同理，属于 pinout 和 bank 类型决定的物理边界。

最后，仿真通过不等于板上通过。r162 的结论之所以能写，是因为同一版 RTL 既有台架读数，又有实现报告和上板读数；三者缺一，结论就要降级。
