# 评委问答

这一页按“问题、30 秒回答、追问时的硬答案、不要这么说”组织。数字以 r152 为准，边界以 `report/08-limits.md` 为准。

## A. 定位与必要性

### Q1 为什么一定要用 FPGA？树莓派、Jetson 或一台 PC 不行吗？

能做，但三件事很难同时说清。PC 或 SoC 路线里，画面要经过 CPU 和内存拷贝，延迟由调度决定；要做几何和滤波，还要再占一份算力；最关键的是“这一帧干不干净”通常只能看屏幕。本项目把数据面整条放在 PL，像素通路的延迟由流水线级数决定，链路健康由硬件计数器给出，PS 只做控制。

**追问**：为什么不直接用 PYNQ？同一颗 Zynq，PYNQ 用 Python 驱动 PS 侧，开发快；本项目要的是全硬件数据面和可观测性，PS 只保留控制面。两条路线的取舍写在 `report/ps_vs_pl.md`。

**别这么说**：不要说“CPU 一定做不到”或“FPGA 一定更快”。准确的说法是延迟确定性和观测方式不同。

### Q2 跟板卡厂商的例程有什么区别？

厂商例程止于“收发通了”。把它接成视频通路，还要补 UDP 端口过滤、按偏移拼帧、坏包判定、发送仲裁、DDR 提交点和显示侧的同帧对照。过程中还修掉了例程自带的两处缺陷：发送仲裁在帧中间换源，接收侧几处未验证行为。逐文件的来源标注在 `report/log/version_lineage.md`。

### Q3 能用在什么地方？

远程视频节点、广播与安防的置信度监测、工业视觉的调试与验收。共同点是现场只有一根网线，操作者需要同时看到画面和链路质量，而不是只看到“卡了一下”。

### Q4 三路片源同时来会怎样？

仲裁器只让一路拿到搬运引擎，另外两路排队或让位；显示侧只在整帧提交脉冲之后切换读口，不会出现半新半旧的帧。断流或拔卡时自动回落到还在工作的一路，插回后自动切回。演示里只演可逆的两跳：ETH 与 SD 互相让位。

## B. 时序与硬件

### Q5 时序全绿是真的收敛，还是约束出来的绿？

r162 的 WNS 是 1.378 ns，WHS 是 0.046 ns，TNS=THS=0，失败端点 0。这个绿不是把路径设成 false path 换来的：处理窗总线是一条准静态跨域总线，原来按两颗独立 MMCM 之间的 4 ns setup 去收，r152 改成显式的 10 ns 位间 skew 约束；路径仍在报告里，改后还有 8.7 ns 余量。其余跨域路由结构保证，时钟组显式声明。

**追问**：那是不是把难的路径都豁免了？不是。豁免的只有本来就靠结构保证的准静态总线和同步器；真正的同步路径仍在收；r162 拆掉 UDP 校验和之后，最差那条是 `clkout3` 上的复位恢复路径（1.378 ns）。

### Q6 0.046 ns 的 hold 余量，温度电压一抖会不会挂？

这个余量是在快速工艺角下量的，仍然是正的；它是全设计最薄的一格，在 AXI 域的时延计数器 `u_lat/c2_cyc_reg → q_c2_reg` 上。我们没有把它说成“很宽裕”。r153 试过 post-route phys_opt，WNS/WHS 与 r152 逐位相同，所以没有采纳，也没有把希望寄托在工具再优化上。板上连续流和自检都跑过，但没有做高低温循环，这一点是边界。

### Q7 跨时钟域怎么做的？

分三类。字节流用格雷码指针的异步 FIFO；帧提交、时延、处理窗计数这类慢变量用“源域整拍保持、目的域同步翻转沿再采”的快照器；单 bit 电平和复位用三级同步器，复位异步断言、本域同步释放。准静态总线额外用 max_delay 约束位间 skew。

**别这么说**：不要说“所有跨域都上了异步 FIFO”。FIFO 适合字节流，不适合慢变量；全上 FIFO 会增加资源和延迟，不解决问题。

### Q8 RGMII 是 DDR 接口，怎么保证采得准？

接收侧用 IDDR 在 PHY 恢复时钟上采样，随后立刻过异步 FIFO 搬到 125 MHz 逻辑域；恢复时钟只碰采样和 FIFO 写侧。发送侧在 HR bank 上没有 ODELAYE2，0° 转发仍有约 0.845 ns 的 TskewT 保持余量缺口；90° 和 −45° 都试过，前者断链，后者 ping 只剩 1/6，已经撤回。当前用 0°、时钟也过 ODDR，长时间 ping 稳定。这是一个物理边界，不是靠再调几行 RTL 能消掉的。

### Q9 现场试 `zoom auto` 好像不生效？

先看命令。`zoom 1` 是开关，`zoom 1.0` 才是倍率；`zoom auto` 交还呼吸。如果屏上 `Zoom:` 不动而画面在动，先确认推的是哪一版位流，再看回显里“你写的”和“我用的”是否一致。旋转态下倍率会被拟合档钳住，这是有意的，不是失效。

## C. 算法与几何

### Q10 缩放旋转用什么算法？为什么不用更高级的插值？

逆映射加双线性。八档倍率，任意角度，缩放和旋转共用一组定点算子。双线性在 50 MHz 像素时钟上用单读口就能取齐四个邻点，资源和延迟都可控；更高级的插值会需要更多邻点和更多 BRAM，而当前瓶颈已经是 BRAM。整数倍率下双线性按构造退化成最近邻，这是可解释的行为，不是 bug。

### Q11 “任意组合下延迟恒 15 拍”有什么意义？

竖缝两侧必须在同一拍对齐。如果延迟随配置变化，缝两侧就会出现固定错位，看起来像几何错了。15 拍是六级链的拍数之和，旁路路径按同样级数延迟；完整视频台架逐拍量过，不是只在文档里声明。

### Q12 左右两半是同一帧吗？几何对得上吗？

是同一帧。两侧共用同一组逆映射和同一条效果链，原图抽头用行延迟环对齐到同一拍。完整视频台架按“每行只应有一段连续画面”“每个像素带回自己的源行列号”这类形状判，不猜坐标；185° 的灰度分割臂要求处理侧非灰像素为 0，硬件计数器同样为 0。

**边界**：帧头几行的内容仍可能比同屏其余行旧一帧，这是读侧提前取行的残余，只有人眼能判断是否可接受。

### Q13 九位控制字要是有人改了位序会怎样？

会静默错位，而且不一定报错。所以位序当 ABI 管：RTL 位定义、固件写出的字、上位机掩码三处同源；新增位往高位加，不重排已有位。改一处必须同时改三处，接口表也要跟着改。

## D. 验证

### Q14 有多少台架？怎么知道它们在测东西？

仓库里有 88 支 `tb_*.v`。r152 改动后的一次快速回归覆盖九支：帧重组三支、遥测、发送仲裁、ETH 顶层、分割控制、OSD、链路监视，汇总行 `MSIM DONE fail=0`。完整视频台架跑满 4,569,600,090 ns，0 errors。

**追问**：怎么知道判据不是摆设？每条关键判据都做过变异对照：把仲裁空闲条件改成恒真、把行计数改成每字加一、把遥测首字节改错，台架都会红。一条出生以来没红过的判据，不算证据。

### Q15 什么是变异对照？为什么值得做？

故意把设计或判据破坏一处，看台架是否报红。它证明的是“判据能看见这类错误”，不是“设计没有错误”。没有这一步，绿色只说明台架跑完了，不说明它测了东西。

### Q16 之前不是有一条公开保留的红吗？现在还在吗？

那是帧头读侧绕回，r132 已经修掉，完整视频台架现在 165 条判定 0 条 FAIL。r152 的 185° 分割臂也通过，硬件计数为 0。残余是帧头几行比其余行旧一帧，只有人眼能判，这一条写在 `report/08-limits.md`。

### Q17 仿真和上板都绿，两家仿真器结果一致吗？

本机有 ModelSim 和 xsim。r152 的快速回归和完整视频台架用 ModelSim 跑；xsim 的跑法也保留。两家不是逐条对表，因为仿真原语是行为级占位件，OSERDES 和 BUFG 的告警来自占位件而不是设计。真正的外推靠上板读数，不靠“两家都过”。

### Q18 一键门禁 24 项都是什么？

那是 r132 那一轮的发布前检查，不是 r152 的。r152 的验收以台架、实现报告和上板读数为准：WNS/WHS、0 失败端点、九支台架、连续流 241 帧、三阶段自检 PASS。没有把历史门禁结果当作当前结果。

## E. 边界与诚实

### Q19 功耗和温度是测的还是估的？

功耗报告是工具估算，置信度 Low，只能当量级参考。板上温度由 PS 读 XADC，经 OSD 和串口给出，是另一个口径。两者不能混在一起念。

### Q20 端到端延迟多少？

没有测。遥测里的 2–16 ms 是 PL 内部时延：从帧提交到开始扫描，包含消隐和 DDR 搬运，不含编码、网线和交换机排队。它不是玻璃到玻璃的延迟，报告里不能那样写。

### Q21 下一步做什么？

三件事：把 BOOT.bin 固化并做冷启动复验；补一个绝对角度命令，让 185° 可重复；评估 DDR 行缓存或分块几何，看能不能把 70.00% 的 BRAM 降下来。三件都要重新跑台架和上板，不是改完就写“完成”。

### Q22 断电自启证明了吗？

没有。固件目前是 JTAG 下载，掉电回到启动介质里的旧镜像。QSPI 里仍然是更早的版本。要做断电自启，需要生成并烧写 BOOT.bin、把启动模式拨到 QSPI，再做一次冷启动复验。这是现场演示前必须对齐的边界。

## F. 现场应变

### Q23 上台后屏没亮

先看 JTAG 第三条有没有 `CON: ok`，再看屏是否通电、HDMI 输入是否切到这一路。屏上有 OSD 但 `SRC:` 为空，说明三路片源都不活，先推流或 `play`。整屏黑且没有 OSD，回到第 0 步三件套。

### Q24 评委要求“随便操作一下”

从第 2 幕开始：`src 0` 切图卡，`split 50`、`split marker 0`，`zoom 1.5`、`rot auto 1`，再 `pipe 000010000` 看 Sobel。这四步覆盖源、几何、效果和对照，不需要网络。

### Q25 没有网络环境

用 SD 回放或 PL 图卡。两款片源都不依赖网线；遥测和自检需要网络，现场没有就只演画面和串口命令，并说明遥测是另一条可选的观测路径。

### Q26 一句话给我个数

PL 内部帧时延 2–16 ms，连续流 30.00 fps，效果链恒 15 拍。端到端时延没有测，不能给数。

### Q27 功耗和结温可信吗？

功耗是估算，结温是板上 XADC 读数。前者只能当量级，后者是真实传感器读数但只代表芯片内部温度，不代表整机或环境温度。

### Q28 到底有多少支台架？

88 支 `tb_*.v`。r152 改动后的快速回归是九支，完整视频台架另算；不是每一支都在每次改动后重跑。

### Q29 电梯稿

“这是一条从网线到屏幕的全硬件视频通路，画面不经过处理器。屏幕中间的同帧对照让处理前后的差异直接可见，PL 每秒回传的遥测让帧数、作废、时延和处理窗完整性都变成可读的数。自检会故意丢包，证明这套仪表不是装饰。”
