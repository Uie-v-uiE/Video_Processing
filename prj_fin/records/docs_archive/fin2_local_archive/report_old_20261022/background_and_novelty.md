# 选题背景与创新点

## 1. 要解决的问题

嵌入式视觉设备常见一个取舍：显示通路交给处理器，还是交给可编程逻辑。

处理器路线开发快，ARM 上跑 Linux、协议栈和显示框架，生态成熟。代价是画面要经过 CPU 和内存两次以上拷贝，延迟与抖动由调度决定。很多现场要的恰恰是“网线里进来的画面立刻、稳定地出现在屏幕上，同时还能做几何与滤波处理，并且当场能判断这一帧干不干净”。处理器路线不是做不到，而是这三件事很难同时说清。

本项目把数据面整条放在 PL：接收、缓存、几何与效果、显示，PS 只做控制、状态回读和 SD 回放。代价是协议栈要自己实现，调试更依赖硬件计数器和仿真，而不是软件日志。收益是像素通路的延迟由流水线级数决定，不受 CPU 调度影响。

项目的取向可以概括成一句话：把显示方式本身做成一台测量仪器。屏幕中线以左是未处理画面，以右是同一坐标系下的处理结果，逐像素对齐。分割线可以固定、自动扫描，也可以贴在图像域里跟着旋转缩放一起走。于是“处理错了一行”“边缘少了一列”“越界被填黑”这类问题不需要探针，也不需要抓图对比，在同一条扫描线上就能看见。

## 2. 同类工程在做什么

这一节不做文献综述，只把能点开核对的公开通报摆在下面，用来说明同赛道大致有哪些做法。两页都是学校自己发的竞赛通报，内容只有题目、等级和一句话简介，没有完整技术报告。

江南大学 2024 年 12 月的校级通报里，全国一等奖是《基于高云 FPGA 的脑电分析设备》，二等奖是《智能手语识别低功耗 SoPC 设计》，三等奖是《基于深度学习的低功耗垃圾分类箱》。南京大学集成电路学院 2025 年 12 月的通报里，获奖名单出现《微视——2mm 内窥图像处理系统》《“神瞳”图像畸变校正系统》《机场动物识别与驱鸟系统》《面向 FPGA 的高效算子实现与优化》等项目名。赛事官方站点是 `https://www.socchina.net/`，本次没有从它取到完整作品集，只有上述各校通报里的题目。

按这两页能支撑的说法做定位：这个赛道近两年的常见形状是“一个具体应用对象加一个可量化的硬件能力”，也就是把一个算法做进硬件，并给出该算法的指标。本项目的起点是厂商的以太网例程，它止于“收发通了”；把它接成视频通路的过程中，发现并修掉了发送仲裁在帧中间换源、接收侧几处未验证行为等问题。逐文件的“哪些是厂商代码、哪些是自研”标在 `report/log/version_lineage.md`。

在“算法进硬件”这条轴上，本项目没有可对表的算法指标。本项目的形态差异在观测面：处理结果与原始结果同帧逐像素对照，链路健康由硬件自己计数，发布前检查项有变异对照。与 PYNQ 路线的差别也是有意选择的：同一颗 XC7Z020，官方生态用 Python/Notebook 驱动 PS 侧，本项目数据面完全在 PL，PS 只跑一份不带操作系统的裸机控制面。

这份对照的边界要说清：两页通报只给了题目与等级，本项目也没有做过系统的公开文献检索。它只能说明“同赛道大致在做什么、本项目与它的形状哪里不一样”，不是一份相关工作综述，也撑不起“别人都没做到”这类说法。

## 3. 创新点与它们的代价

### 3.1 同帧逐像素对照是仪器，不是滤镜

原图抽头用一条行延迟环与处理链对齐到同一拍、同一列；效果链固定 15 拍，混合域的延迟由常数推导，不是量出来凑的。于是左右两半来自同一帧、同一组坐标，缝上的差异只可能来自算法或几何本身。

这条设计直接产出了机器可判的结论。完整视频台架按“每行只应有一段连续画面”“每个像素应带回自己的源行号和列号”这类形状判，不猜坐标；185° 的灰度分割臂要求处理侧非灰像素为 0。它抓到过贴屏左缘的细线、缩放碰分割线时的色带和帧头读侧绕回，三类问题都修在 RTL 里。

代价是两套抽头都要养。行延迟环的级数由效果链倒推，任何一级效果改延迟都要重推对齐；帧头几行的内容仍可能比同屏其余行旧一帧，这是读侧提前取行的残余，离线没有判据能量到，只有人眼能判断是否可接受。

### 3.2 链路健康做成硬件自计数，三个出口可对账

同一组计数器有三个独立出口：OSD 直接印在屏上，AXI GPIO 可被 JTAG 读回，串口命令可清可读。于是“报告里写 0 丢包”变成“你能自己验证它是 0”。

代价是三个出口共用同一份计数和同一套字段顺序。改一个字段要同时改 OSD、JTAG 脚本和串口回显三处，接口表也要跟着改。这不是免费的，但比“每个出口各算一套数”可靠。

### 3.3 抗乱序、抗丢包的偏移拼帧

每包自带帧内偏移，比“要求按序到达”更适合尽力而为的以太网。提交有三重门限：所有源行都被覆盖、字节预算到齐、本帧没有坏包。三者同时成立才提交。这样“丢一包加一包重复偏移”这种能被累计字节数伪装成完整的帧不会上屏。

代价是门限不过就整帧不上屏，观感上是“偶发一顿”而不是“花屏”。这条路不做纠错与重传，也不假装能做。

### 3.4 消隐窗口内的原子提交

显示侧永远只读一整帧。拷贝赶不上消隐窗口就整笔作废，保留上一帧；宁可不动，不可撕裂。看门狗跨时钟域用翻转式脉冲同步器，刷新的是“这一笔还在不在动”，不是“过了多久”。

代价是偶发一帧的延迟，以及一套额外的提交状态机。它换来的是屏幕上不会出现半新半旧的帧。

### 3.5 仪表必须能被打红

三阶段自检在干净流、确定性丢包和恢复流之间切换。故障段要求作废计数上升、帧率下降；恢复段要求帧率回到干净流水平、作废冻结。如果仪表对人为破坏没有反应，这套观测就不成立。

代价是自检本身要维护一套注入逻辑和判据。它不能证明画面好看，只能证明读数对故障有反应；画面观感仍然要人看。

## 4. 明确不做的

不做 FEC 和重传。UDP 视频是尽力而为的，丢包就整帧作废，宁可掉帧也不出坏画面。

不做外部 HDMI 输入。当前 `src/rtl/hdmi/` 只有发送链；接外部信号要在输入侧另加 TMDS 接收芯片，这是下一步，不是本版已实现的功能。

不做通用协议栈。当前栈只覆盖 ARP、ICMP 和 UDP 视频/遥测需要的子集，不声称能替代成熟协议栈。
