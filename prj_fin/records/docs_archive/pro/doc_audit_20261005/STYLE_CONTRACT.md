# 文档改写契约（评委视角·2026-10-05 夜间审查轮）

## 0. 这份契约为什么存在

工程文档集在长期迭代里被改成了"给自己看的台账"：每一句结论后面挂着内部轮次号、
墙钟时间点、凭据文件名和一连串免责话。作者读得懂，第一次翻开的人读不懂，而且很像机器在自证。
赛题 §5 与 §7 要的是"设计报告 + 失败分析 + 复现说明"，不是一本施工日志。

今晚的目标：**让一个从没跟我们说过话的评委，能在 README 上 3 分钟读懂这个系统做了什么、
数字从哪来、怎么自己跑一遍**；同时不丢掉可复现性（数字必须有出处，出处必须是真的文件）。

## 1. 工作边界（硬性）

  分支 `review/20261005`，内容与主仓库 `b65a191` 逐字节相同）。
- **禁止**写主仓库 `D:/Xilinx/Prj/pro/Video_Processing/` 的任何文件；**禁止**执行任何会改动的 git 命令

  要么整篇按契约改完，要么原样不动并在清单里写明"未改，原因"。

## 2. 必须删掉或改掉的东西（红项类型，逐条编号）

- **R1 墙钟时间点叙事**：形如"从 04:18:27 到 04:37:57 共 19 分 30 秒"、"01:37 刷入、01:50 PASS"、
  "2026-10-04 08:1x" 这类**一天内的时刻**做叙述成分 ⇒ 删。耗时如果本身是信息，只留**时长**
  （"一次全流程实测约 20 分钟，其中综合约 10 分钟"）；纯取证时间戳留在凭据文件里，正文不复述。
  例外：`data/measured/`、`board/evidence_*`、`build/runs/`、`report/log/` 这类**原始记录件**里的时间戳
  是数据的一部分，不许改。
- **R2 内部轮次号当叙述主语**：`r118`、`r75`、"r87 那一跑"、"r121 实测" ⇒ 改成角色化说法
  （"当前板上这一版""最新一轮全量实测"）。**只允许保留两处** rNN：
  ① 一句话声明"板上现在跑的是哪一版 + 位流 md5 前 12 位"（这是机器要读的身份行，原样保留，不改措辞）；
  ② 凭据**文件名**本身（`build/r118_gates.txt` 这种路径字面量不许动，动了就是死链）。
- **R3 自我指涉的过程话**："这一版不作'全套门禁全绿'的说法"、"未检查不等于满足"、
  "这四个数只许两两比同域"、"本会话打开核对"、"我改过"、"本轮判负" ⇒ 要么删掉，
  要么换成对**事实**的中性描述（"本版未加 RGMII 收口输入窗，这 5 个 I/O 端点未参与检查"）。
- **R4 工具/尺子黑话**：尺子、判红、改口、定版、冻结件、快车道、台账、门禁 24 项、地板、判据——
  评委不知道这些词。交付正文里改成通用说法（检查脚本／未通过项／版本声明／基线报告／回归测试／
  记录文件／对比实验／发布前检查项）；确需保留处，就地解释一次（第一次出现时用半句话说明它是什么）。
- **R5 对赛条文的辩解**："指南推荐 2026.1，本工程……"这种逐条对表式辩解 ⇒ 改成中性事实：
  说清自己用了什么、能不能复现，不评论指南。指南条文只允许出现在 `report/submission-checklist.md`
  这类对照件里，且只写"对应条目 + 本项目落点"。
- **R6 冗余免责堆叠**：同一段里连续多个括号补充、每条数字后面三个凭据 ⇒ 一个数字最多留**一个**主凭据
  （其余合并到该节的"凭据一览"或表格里）。
- **R7 篇幅失衡**：一份文档的"怎么跑"比"是什么"还长，或开头 30 行还在讲工具版本 ⇒ 调整顺序：
  是什么 → 怎么跑 → 数字与凭据 → 限制。

## 3. 必须保留的东西（不许"整理"掉）

- **所有数值本身**：WNS/WHS/资源/功耗/fps/包数/行列数等，一个字都不许改，也不许四舍五入成另一个数。
  用 `check_docs.sh` 自检：改写后正文里出现的数字集合不能减少（新增允许，删除必须逐条给理由）。
- **所有真实路径字面量**：`build/report/*.rpt`、`data/metrics.csv`、脚本名、命令行。不许造新路径。
- **表格第一列被标注"会被机器读"的行名**：整行原样保留（那是尺子的锚点）。
- **命令块**：`bash build/board_verify.sh --geom --battery` 这类可执行命令必须与仓库里真实脚本一致，
  参数不许改。围栏代码块内容一字不动（除注释）。
- **失败与限制**：唯一未通过项、已知限制、被判负的方案，必须仍然在文档里，且说得更清楚，
  不是删掉。**诚实是本套文档的加分项，删负结果是最差的选择。**

## 4. 语言与句式（与机器门禁 C7 一致）

- 不使用第一人称与文档自指：`我们`、`本文档`、`本节将介绍`、`我`、`您` 都算红（C7 会判）。
  主语换成系统、模块、脚本、文件、报告。
- 不使用程度副词充数：`显著`、`极大地`、`完美`、`优秀`、`强大`、`TBD`、`待补充`、`待验证`、`【填入】`
  在作者自己的话里算红（C7 会判）；引号内、代码块内、表格状态格里允许。
- 不使用 emoji（⚠ ★ 😀 等）与勾叉符号（✓ ✗ ✔ ✘）；`⇒` 可以，`→` 少用（尺子按个数报数）。
- 一句话只引入一个新概念，且就地解释或指向 `docs/walkthrough/glossary.md`。
  禁用"显然、众所周知、很简单、不难理解"。
- 段落式叙述优先，不写成子弹堆叠；表格只在并列可比时用。
- 中英两份（`README.md` / `README_EN.md`）必须同构：小标题数量与顺序一致，同一组数字与同一组凭据。
