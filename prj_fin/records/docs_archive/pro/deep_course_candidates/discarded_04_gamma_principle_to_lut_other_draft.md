（5/6/5 ↔ 8 bit 的位复制扩展、查表之后的截断、亮度权重的 Q8 化）逐条落到数与 `file:line`。

## 1 前置知识

### 1.1 传递函数：器件幂律 + 人眼幂律 = 一个必须被"预失真"的量

三段事实串起来才需要 gamma：

1. **显示器件是幂律的**。LCD/LED 的亮度大致随归一化驱动值走 `L ∝ V^2.2`
   （本仓的取值口径就是这个 2.2：`src/ps/main.c:375-383` 的曲线用 `1/γ`，而 γ 的合法区间是
   1.00…3.00，见 `src/ps/main.c:400`）。
2. **人眼对亮度的感知近似是 `P ∝ L^(1/2.2)`**。把 1 与 2 乘起来，一条"存储码 → 感知"的链
   如果全程线性，需要信号端预先做 `E' = E^(1/2.2)`。这就是编码侧用 `1/γ` 而显示侧用 `γ` 的原因，
   两级指数正好互为逆。
3. **等码步要等感知步**。按上面这条设计，相邻码字的感知差是常数 `1/(N−1)`；
   如果存的是线性光，感知差在暗端极大——见 2.2 的那个 8 % 数字。

### 1.2 "8 bit 装不下曲线"是一句可以算出来的话，不是修辞

设存储域有 `N` 个码、显示是 `γ = 2.2` 的幂律。

* **线性光编码**（`L = s/(N−1)`）在最暗一格的感知跨度是 `(1/N)^(1/2.2)`（满量程的比例）。
  `N = 256` 时 `(1/256)^(1/2.2) = 0.0804` ⇒ **第一格就跨掉 8.04 % 的感知量程**。
  要让它降到与 γ 编码的最细步（`1/256 = 0.39 %`）同级，需要
  `N ≥ 256^2.2 = 198 668` ⇒ **17.6 bit**；只要"1 % 以内"也要 `N ≥ 100^2.2 = 25 119` ⇒ **14.6 bit**。
* **γ 编码**（`E' = E^(1/2.2)`）把 8 bit 用满：每个码的感知跨度都是 `1/255`。
  反过来，曲线本身在存储域是**不均匀**的：`out(i) = 255·(i/255)^(1/γ)` 的斜率
  `d(out)/d(i) = (1/γ)·(i/255)^(1/γ−1)`，在暗端远大于 1、亮端远小于 1。

第二点是"表装不下曲线"的另一半：**亮端相邻输入码会合并到同一个输出码**。
`1/γ = 0.4545` 时斜率降到 1 以下的临界点在 `i/255 = 0.4545^(1/0.5455) = 0.236`，即 `i ≈ 60`；
所以 `i > 60` 之后就开始合并。按本仓固件那条式子（含 `+0.5` 再截断，见 3.10）逐点算：

| γ | 8 bit 输出上的"相邻码合并"对数 | 第一次合并发生在 | 不同输出值个数 |
|---|---|---|---|
| 1.00 | 0 | — | 256 |
| 1.80 | 54 | i = 86 | 202 |
| 2.20 | 72 | i = 73 | 184 |
| 3.00 | 98 | i = 60 | 158 |

（这一列是把 `src/ps/main.c:375-383` 的算法逐点跑出来的算术结果，仓里没有对应的现成件 ⇒ 属推导。）
端点与暗端的两个具体数值得记住，因为固件自检就钉它们：`γ = 2.20` 时
`out(0) = 0`、`out(1) = 21`、`out(2) = 28`、`out(8) = 53`、`out(254) = out(255) = 255`；
`γ = 1.80` 时 `out(1) = 12`；`γ = 3.00` 时 `out(1) = 40`。

### 1.3 RGB565 的位不对称决定了这张表的两个"看不见的收窄"

一个像素是 `R[15:11] G[10:5] B[4:0]`（5/6/5）。本通路做两次位复制扩展与一次截断：

```
扩展：r8 = {r5, r5[4:2]}      g8 = {g6, g6[5:4]}      b8 = {b5, b5[4:2]}
截断：out5 = LUT_r[7:3]        out6 = LUT_g[7:2]        out5 = LUT_b[7:3]
```

扩展式在 `src/rtl/video/gamma_lut.v:20-25`（`src/rtl/process/proc_gray.v:14-20`、`src/rtl/process/proc_binary.v:16-21`、
`src/rtl/process/proc_morph.v:27-32` 各写了一遍同一套，`src/rtl/video/gamma_lut.v:18-19` 说明"不共用是故意的，
三处公式必须能被独立核对"），截断式在 `src/rtl/video/gamma_lut.v:51`。

代成数就得到两个关键结论：

* `r8 = r5·8 + (r5 >> 2)` ⇒ `r5 = 0..31` 时 `r8 = 0, 8, 16, 24, 33, 41, 49, 57, 66, 74, …, 255`
  （`r5` 是 4 的倍数时步长变 9），**只有 32 个取值**；`g8 = g6·4 + (g6 >> 4)` 同理只有 64 个。
  两端恰好闭合：`r5 = 31 ⇒ r8 = 255`、`g6 = 63 ⇒ g8 = 255`。
* 因此三张 256 项的表里，R/B 表**永远只有 32 个地址会被读**、G 表只有 64 个，
  而且读到的 byte 又只取其高 5 位（G 高 6 位）。
  ⇒ 这张"256 项 8 bit 表"在通路上的**有效映射是 32 → 32 与 64 → 64**。
  台架独立记着同一件事：`sim/tb_v88_gamma.v:22-23`（"R/B 只有 32 个可达索引
  （`r8={r5,r5[4:2]}`）、G 64 个 ⇒ 每张表先写满 256 槽再比"）。

那 8 bit 表还剩什么用？**买的是取整的那一次决定**：曲线必须在 8 bit 精度上算完并四舍五入，
再截到 5/6 bit，才会落在正确的格上；如果一开始就用 5 bit 算，端点与中间档会有系统性偏差。

### 1.4 为什么用表而不用幂函数：这条通路上的硬件账

`src/rtl/video/gamma_lut.v:4-5` 一句写完："用表不用幂函数：PL 里做 `in^(1/γ)` 要堆 DSP 或做对数/指数近似"。
把这句话展开成本仓能核对的量：

* 每拍要出一个像素，三个通道各一次幂；`γ` 还是运行时可变的。浮点在 PL 里不存在，定点的
  `pow` 要么用 CORDIC 级别的迭代，要么用 `exp(k·ln x)` 的两张近似表 + 一次乘 ——
  这三样都比"一次异步读表"贵。
* 表的本体很便宜：3 × 256 × 8 = **6144 bit**，写在 LUTRAM 里
  （`src/rtl/video/gamma_lut.v:27-29` 的 `(* ram_style = "distributed" *)`）。
  按 7 Series 一只 `RAMD64E` 存 64 bit 估，三张表至少 **96** 只；
  全设计有 4044 只 `RAMD64E`（`build/utilization.rpt:195`）⇒ 占比约 2.4 %（这一格是按器件容量的**推算**，
  工具给出的逐实例计数未量）。
* **异步读出 ⇒ 不占流水级**。这是这一条最硬的理由，写在两个地方并且必须一致：
  `src/rtl/video/gamma_lut.v:7`（"它不加拍数（分布式 RAM 非同步读出）⇒ LATENCY 常数不动"）与
  `src/rtl/process/proc_pipeline.v:21`（"级 0 的 gamma 是分布式 RAM 组合读出 ⇒ 不占拍；
  谁改成寄存读出（BRAM 风格）LATENCY 必须同时改成 16"）。
  链子的逐拍账 `灰度1+反色1+模糊3+锐化3+Sobel3+阈值1+形态学3 = 15`（`src/rtl/process/proc_pipeline.v:18`）
  里根本没有 gamma 那一项，就是这个意思。

### 1.5 PS↔PL 之间只有"一个 32 位窗口"，没有第二条路

这条链路的硬件形状是 BD 里的第二个 AXI GPIO：`axi_gpio_2`，
`C_IS_DUAL = 1`、两个通道各 32 bit、全部为输出（`build/tcl/build_system_axigpio.tcl:147-155`），
通道 1 引出 `GPIO_2_tri_o`、通道 2 引出 `GPIO_3_tri_o`（`:225-226`），
基址钉死 `0x41220000` 并在构建里回读校验（`:246`、`:258-270`）。
固件端 `CFG_DATA0 = +0x00`（几何/效果控制字）、`CFG_DATA1 = +0x08`（gamma 窗口），
两份地址常量在 `src/ps/main.c:77-78`、`:96`。
PL 侧 `system_top.v:51` 把这两个通道接成 `gpio_cfg1_o / gpio_cfg2_o`，
`src/rtl/top/system_top.v:276` 那一行 `.gamma_ctl(gpio_cfg2_o)` 就是"通道 2 = gamma 窗口"的唯一接线。

## 2 原理拆解（把数带进去）

### 2.1 本仓这张表的定义式与它的定点写法

```
out[i] = trunc( 255 · (i/255)^(100/g100) + 0.5 )        i = 0…255        // g100 = γ×100
```

`+0.5` 后截断 = 四舍五入（`.5` 向上）。指数由整数 `g100` 给出：`float e = 100.0f/(float)g100`
（`src/ps/main.c:378`）。这里有一个**必须自己认的口径**：γ 不是浮点数，而是"γ×100 的无符号整数"，
合法区间 `[100, 300]`（`src/ps/main.c:400`），
`γ = 1.00` 时表恒等（`src/ps/main.c:375` 的注释直接把它当台架对照的凭据）。

三个定点量分别住在不同的地方，别混：

| 量 | 格式 | 住在哪 | 出处 |
|---|---|---|---|
| γ（运算） | γ×100 整数 | PS 变量 `cur_gamma` | `src/ps/main.c:291` |
| γ（显示） | γ×10，6 bit | 控制字 `[13:8]` | `src/ps/main.c:101-102`、`src/rtl/process/effect_ctrl.v:60-61` |
| 表项 | 8 bit 无符号 | 控制字 `[29:22]` → LUTRAM | `src/ps/main.c:99`、`src/rtl/video/gamma_lut.v:27-29` |

γ×100 → γ×10 的换算也写死了：`GM_DISP((g100 + 5)/10)`（`src/ps/main.c:417`）同样是 `+5` 再截断，
所以 `g100 = 180 → 18`（屏上 1.8）、`220 → 22`、`225 → 23`。量程检查：γ 最大 3.00 ⇒ 30，
6 bit 装得下（0…63）。

### 2.2 表在通路上的真实尺寸：32 → 23

把 `γ = 2.20` 代进 1.3 的两条式子，R 通道那张表在这块板上实际发生的事是：

| `r5` | 读到的地址 `r8` | 表值 `out8` | 屏上 `out5 = out8>>3` |
|---|---|---|---|
| 0 | 0 | 0 | 0 |
| 1 | 8 | 53 | 6 |
| 2 | 16 | 72 | 9 |
| 3 | 24 | 87 | 10 |
| 4 | 33 | 101 | 12 |
| 5 | 41 | 111 | 13 |
| 8 | 66 | 138 | 17 |
| 15 | 123 | 186 | 23 |
| 24 | 195 | 227 | 28 |
| 28 | 231 | 244 | 30 |
| 29 | 239 | 248 | 31 |
| 30 | 247 | 251 | 31 |
| 31 | 255 | 255 | 31 |

（前两列是 `src/rtl/video/gamma_lut.v:23` 那条位复制式的展开，后两列是 `src/ps/main.c:375-383` 那条曲线的展开。）
32 个输入档最后只落在 **23 个不同**的输出档上：`γ = 2.2` 在 R/B 上吃掉 9 档，`γ = 1.8` 吃掉 7 档，
`γ = 3.0` 吃掉更多。这一句是本章对"8 bit 装不下曲线"在本设计里的**最终落点**——
不是曲线在 8 bit 上塌，而是曲线在 **5 bit 输出**上塌；表用 8 bit 只是把取整做对。

同时给出两个"必须自洽"的性质，台架各钉一条：

* `γ = 1.00` ⇒ 表恒等 ⇒ `out5 = floor(r8/8) = r5`（`r8 = 8·r5 + (r5>>2)`，第二项 ≤ 7 故整除不掉），
  逐位不动 ⇒ `sim/tb_v88_gamma.v:133` 的 T2"identity 表下 96 个通道值仍逐位等于输入（R/G/B 各 32 档）"。
* `out8` 序列对输入单调不降（幂律的数学性质）⇒ 固件自己数逆序次数 `bad`，
  并且钉端点 `first == 0` 且 `last == 255`（`src/ps/main.c:405-413`、`:426-427`）。
  板上实测回声：`build/evidence/r99_battery_pass_after_fix.txt:94` 那一行
  给的是 `mono_bad=0 first=0 last=255`（γ=1.80）。

### 2.3 为什么一次换表要 256 次"翻转"，而不能一次突发写

这是本章最"协议"的一节，三条理由各自独立：

1. **PL 里没有 DMA、没有第二套 AXI 从口给这张表**。表在像素域，
   像素域与 axi 域之间唯一的通道就是 `effect_ctrl` 那一对 32 位 ASYNC_REG 同步器
   （`src/rtl/process/effect_ctrl.v:39`、`:54-56`）。一次只能送 32 bit ⇒ 一次只能送一项。
2. **一次 32 bit 里要同时摆"地址 + 数据 + 事件"**，而事件只能是一个**翻转位**，
   不能是脉冲：`src/rtl/video/gamma_lut.v:5` 那句"先写 `idx`+`data`、下一次写把 `wr` **翻转**
   （不是脉冲，脉冲跨不到本域）"。原因与第 02 章的 `copy_abort` 同一课：
   axi 侧的一次写只维持几 ns，而 `clk_pix` 的周期是 20 ns ⇒ 宽度不足一拍的事件在像素域可以整拍看不见。
   翻转位不怕采样不足：只要两边各看见一次电平变化，事件就不丢（`src/rtl/util/key_long.v:4-5` 写的是同一条纪律）。
3. **边沿与数据必须同源同深度**。`gamma` 的四个字段过的是**同一对**同步器
   （`src/rtl/process/effect_ctrl.v:36-39`："`wr` 是边沿标志，协议要求 idx/data 在 wr 翻转之前已经稳定至少一次
   AXI 写，所以它们必须与 wr 同源同深度——分两组同步就会出现在本域里'边沿到了、数据还是上一次的'那种错拍"）。
   这也是为什么 `gamma_disp` 与 `temp_disp` 被塞进同一个字：
   `src/rtl/process/effect_ctrl.v:62-65` 记的是"新增的位一律走已有的那条 ASYNC_REG 链，新开一组就多一对跨域配对、
   `cdc.rpt` 基线要重画"。

协议落地成固件的两笔写（`src/ps/main.c:366-373`）：

```
Xil_Out32(CFG_DATA1, gm_w | GM_DATA(v) | GM_IDX(i));   // 第一笔：摆地址与数据，wr 不动
usleep(5);
gm_w ^= GM_WR;                                          // 第二笔：翻 wr = 写这一项
Xil_Out32(CFG_DATA1, gm_w | GM_DATA(v) | GM_IDX(i));
usleep(5);
```

`gm_w` 是这个寄存器的**影子**（`src/ps/main.c:288`），所有写都必须从它出发整字写回，
因为 `[13:8]` 的显示位与 `[7:0]` 的温度位住在**同一个寄存器**里，
读-改-写或者随手写常数都会把它们抹掉（`:94-95` 的警告，同族病见 `#55`）。

两次 `usleep(5)` 是**协议的一部分而不是礼貌**：`src/ps/main.c:285-287` 明写
"PL 看的是 `wr` 的边沿，而 AXI 连发的间隔可以短到一个像素拍都不到 ⇒ 这条约束是真实的，别删"。
定量：最小的可见间隔是一个 `clk_pix` 周期 = **20 ns**（`build/timing_summary.rpt:169`），
5 µs = 5000 ns 给了 **250 倍**余量；一次换表 256 项 × 2 次 sleep ⇒ **≥ 2.56 ms**（同一节注释给的数）。

### 2.4 一次换表的可见副作用：表在半新半旧之间停留多久

写表期间像素通路**照常读表**（同一块 LUTRAM 是 1W1R：写口在 `src/rtl/video/gamma_lut.v:41-47`、
读口在 `:51`）。于是一次 `gamma_set` 的 2.56 ms 里，
表的前段（低索引 = 暗端）已经换成新 γ、后段还是旧 γ。这件事的三个尺度：

* 2.56 ms 是**一个显示帧（16.8 ms，`src/rtl/video/video_timing_1024x600.v:4`）的 15 %** ⇒
  换表完整地落在同一帧的扫描过程中，最坏情况下屏上会有一条"新曲线/旧曲线"的水平分界；
  分界线的位置随扫描走，因为表是**按索引顺序**（0→255）写的。
* 2.56 ms 也是 672 µs 的 V-blank 拷贝窗的 3.8 倍 ⇒ 不能指望"趁消隐换"。
* 设计没有为这件事加锁：`gamma_off()` 只清使能位、表保留（`src/ps/main.c:385-393`），
  所以"开/关"来回切是瞬时的、只有"换 γ"才付这 2.56 ms。
* 屏上是否真看得见这条分界：**未量**（仓里没有针对这一瞬的拍照或台架判据）。
  自动模式把它压到不可见的办法是降低步进频率，见 2.5。

### 2.5 自动扫描：扫什么、多久一步、多久一轮、门限为什么是 200 ms

参数正本 `src/ps/main.c:323`：`gm_lo = 100, gm_hi = 300, gm_step = 20, gm_ms = 2000`
（默认 1.00..3.00、每 2 s 走 0.20），命令入口 `gamma auto [lo hi [step [ms]]]` 在
`src/ps/main.c:1226-1241`，合法性检查在 `:329`：
`100 ≤ lo < hi ≤ 300`、`0 < step ≤ hi − lo`、`ms ≥ 200`，任一不过就打印一条拒绝并**不改状态**。

往返逻辑（`src/ps/main.c:347-364`）是"碰端点即反向"：上升支 `g + step ≥ hi` 时把 `g` 钉到 `hi`
并翻方向，下降支 `g ≤ lo + step` 时钉到 `lo` 并翻回来 ⇒ 端点必被走到、不会因步长不整除而漏掉。
一轮的转换次数 = 上行 `(hi−lo)/step = 10` + 下行 `10` = **20 步**，默认 2 s/步 ⇒ **40 s 一个来回**，
每来回写表 20 次 ⇒ 累计 GPIO 流量 `20 × 2.56 ms ≈ 51 ms`。

节拍器不用中断也不睡死：主循环每圈调一次 `gamma_tick()`，没到点立刻返回
（`src/ps/main.c:346` 的注释、调用点 `:1592`）。为什么 `ms` 有 200 ms 的下限：
一次 `gamma_set` 要 256 项、约 2.6…5 ms **不回主循环**（`:299-300`、`:304`），
而 115200 波特下 Zynq UART 的 RX FIFO 只有 16 字节 ≈ 1.4 ms 的量 ⇒
人在这一段时间里粘进来的整行会从 FIFO 漏掉（症状是"命令要发好几次才有反应"）。
200 ms = 这个坏处的 **约 40 倍**余量（对 5 ms 那一档）与 **78 倍**（对 2.56 ms 那一档），
并且它是**下限**而不是默认值——默认 2 s 是给人眼看演示用的。
配套的第三条防线是把"收字节"与"切派发"拆开：`rx_fill()` 只搬不派发，
`gamma_set` 的循环里每项调一次它（`src/ps/main.c:412`），派发仍由主循环按顺序做
（`src/ps/main.c:303-310`）。

为什么扫描在 PS 侧而不是 PL 侧，`src/ps/main.c:296-298` 给的理由是硬件账：
"γ 表是 PS 通过 GPIO 的 idx/data 窗口一项一项灌进去的，PL 那边只有一张表和一个写口，
没有第二条曲线发生器 ⇒ 在 PS 扫 = 零新增硬件、零时序风险"。
这条也解释了为什么 `gamma auto` 不需要新控制位——用的还是同一个窗口。

### 2.6 γ 计算里那个浮点在哪、精度是多少

固件跑在裸机上，编译带 `-mfpu=vfpv3 -mfloat-abi=hard`（`build/ps_app.mjs:46`），
链接带 `-lm`，且注释明写这只是为了 gamma（`build/ps_app.mjs:123-124`，
`src/ps/main.c:24` 的 `#include <math.h>` 同处也写了"V8-3 的 gamma 曲线"）。
函数体 `src/ps/main.c:376-383` 的类型流值得逐行读：

* `float e = 100.0f/(float)g100;` —— 指数是**单精度**。
* `pow((float)i / 255.0f, e)` —— `pow` 是 **double** 版本，两个 float 实参被提升，
  计算在 double 里做（Cortex-A9 的 VFP 是单精度硬件，double 走软件辅助）。
* `* 255.0f + 0.5f` —— 与 float 常量相乘/相加时按 C 的规则回到 double 再存进 `float y`，
  也就是**在截成 byte 之前有一次单精度舍入**。
* `if (y<0) … if (y>255) …` 两次钳位后 `(u8)y` 截断。

这一条对结果有没有影响？把整张表按"全程 double"与"按上面的类型流（每步 fround）"两种算法逐点比，
`γ = 1.00/1.20/1.80/2.20/2.60/3.00` 六档、共 6 × 256 个点**没有一个不同**（这是算术核对，
不是仓里的判据 ⇒ 若将来出现偏差，说明曲线式或钳位被改过，那时这条对照才有意义）。
但边界值确实紧：`γ = 2.2` 时 `i = 1` 的真值是 `20.543`，加 0.5 得 `21.043` ⇒ 取 21；
再靠近整数一点的点（如 `i = 254` 落在 254.54…）说明"先加 0.5 再截断"这件事本身就在
半个 LSB 上做决定，浮点最后那次舍入并非永远无害。正确读法是：**当前 γ 集合下没有分歧，
所以这条不是活缺陷，但它没有任何东西保证下一个 γ 也不分歧**——台架也不测曲线
（`src/rtl/video/gamma_lut.v` 的表内容由 PS 灌，`sim/tb_v88_gamma.v:22`
明说"曲线的算术不在这里验（PS 算、PL 只写进去什么就查什么），
所以表是故意挑的怪表（identity / 0xFF−i / i^0x5A）用来暴露接错线"）。

顺带纠正一处指标口径：`data/metrics.csv:11` 写 DSP48 的用途是"缩放/旋转的坐标乘法与 **gamma 计算**"。
`gamma_lut.v` 里**一个乘法都没有**（只有三张 RAM、位复制扩展与一次截断）；
同链上真正用 DSP 的"与 gamma 同级的算术"是亮度加权 `y16 = r8*77 + g8*150 + b8*29`
（`src/rtl/process/proc_gray.v:22`、`src/rtl/process/proc_binary.v:22`、
`src/rtl/process/proc_morph.v:33`），它们在级 1/4/5，不在级 0。
⇒ 那一格的"gamma 计算"应当念成"与 gamma 同一条链上的亮度/阈值算术"。

### 2.7 亮度权重的定点（77/150/29）与"和必须是 256"

`src/rtl/process/proc_gray.v:21-24` 的注释给的是这条定点式的来历：ITU-R BT.601 的
`0.299R + 0.587G + 0.114B` 乘 256 取整 ⇒ `77 / 150 / 29`，然后 `>>8`（代码里写成取高 8 位 `y16[15:8]`）。

* 权重误差：`77/256 = 0.30078`（+0.6 %）、`150/256 = 0.58594`（−0.2 %）、`29/256 = 0.11328`（−0.6 %）。
* **和必须正好是 256**：`77 + 150 + 29 = 256` ⇒ 白（255,255,255）算出
  `256 × 255 = 65280`，取高 8 位 = **255**，量程不缩。
  如果各自独立取整后和不是 256（例如 76/150/29 = 255），白就变成 254 ⇒ 每次取灰度都掉一档满量程。
* 位宽账：`r8 * 77` 是 8×8 = 16 bit，两项相加仍不超过 `255×256 = 65280 < 65536` ⇒
  `y16` 取 16 bit 恰好够，不需要第 17 位（`src/rtl/process/proc_gray.v:22`、`src/rtl/process/proc_binary.v:22` 声明的都是 `[15:0]`）。
* 灰度写回 565 时用的是 `gray = {y8[7:3], y8[7:2], y8[7:3]}`（`src/rtl/process/proc_gray.v:24`）——
  同一个 8 bit 亮度被按 5/6/5 三种宽度截断，因此灰度图上蓝/红比绿少一档精度，
  这是 RGB565 的固有不对称，不是本级的选择。

## 3 代码逐段分析

### 3.1 `src/rtl/video/gamma_lut.v`：53 行的完整闭环

| 段 | 行 | 内容 | 要点 |
|---|---|---|---|
| 文件头 | `:1-7` | 定位、时钟域、协议、为什么用表、为什么挂在级 0 | 见 1.4 / 2.3 |
| 端口 | `:8-17` | `en / wr / idx / data / din / dout` | `wr` 的注释写着"翻转位，不是脉冲" |
| 位扩展 | `:20-25` | 5/6/5 → 8 bit 的三条位复制 | 与 `proc_gray/proc_binary/proc_morph` 各写一遍（故意的） |
| 存储 | `:27-29` | 三张 `(* ram_style = "distributed" *) reg [7:0] t[0:255]` | 1W1R；复制三份而不是一读三口（`:3-4` 的理由：一表三读要额外读口） |
| 写事件 | `:31-39` | `prev` + `do_wr = rst_n && (wr !== prev)` | 复位把 `prev` 与 `wr` 一起清 0 ⇒ 上电不算一次写 |
| 写数组 | `:41-47` | 一个不带复位的 `always @(posedge clk)` | 三张表同一个 `idx/data`，一次写三项 |
| 读出 | `:51-52` | `y16 = {tr[r8][7:3], tg[g8][7:2], tb[b8][7:3]}`；`dout = en ? y16 : din` | 截断在这里；`en = 0` 逐位旁路 |

两处容易被略过但很要紧：

* `always @(posedge clk) if (do_wr)` 这个块**没有复位**（`:41`）。数组是 RAM，
  带异步复位的 RAM 数组综合不出 RAM（这条经验在本仓被付了两次学费，
  另一次写在 `src/rtl/axi/axi_frame_writer_gated.v:50-54`）。
* `do_wr` 里的 `rst_n &&`（`:39`）是第二道保险：复位期间即便 `wr` 有变化也不写。
  四态比较用 `!==` 而不是 `!=`：`src/rtl/util/src_mode.v:69-74` 那一段把"台架里输入悬空成 X"
  这类事的处置讲透了（`X !== 0` 恒真 ⇒ 每拍都当事件），而 `src/rtl/video/gamma_lut.v:39` 用的是
  **`wr !== prev`** ⇒ 若 `wr` 为 X 则每拍都写。两处对 X 的取向不同，
  这里依赖的是"上电后 `prev` 有确定值、`wr` 由 `effect_ctrl` 的同步链给出"这条前提。

### 3.2 控制字的位序：一份说明、两处实现

`src/rtl/top/pl_video_top.v:32-33`（端口注释）说这个字是
`{en[31], wr[30], data[29:22], idx[21:14]}`；
`src/rtl/process/effect_ctrl.v:60-61` 补上剩下的 `[13:8] disp`、`[7:0] temp`；
固件 `src/ps/main.c:79-107` 的宏组是同一张表的第三份抄写。三处必须逐位一致，实现是：

```
gm_meta <= {gamma_async[31], gamma_async[30], gamma_async[29:22],
            gamma_async[21:14], gamma_async[13:8], gamma_async[7:0]};   // src/rtl/process/effect_ctrl.v:54-55
{gamma_en, gamma_wr, gamma_data, gamma_idx, gamma_disp, temp_disp} = gm_sync;  // :67
```

这两行的位宽拼接与拆解是**同一顺序**，所以不存在"字段错位"的空间；
`data` 与 `idx` 各 8 bit、`disp` 6 bit、`temp` 8 bit、两个标志位 ⇒ 正好 32 bit。
复位值有讲究：`gm_meta/gm_sync <= 32'h0000_00FF`（`src/rtl/process/effect_ctrl.v:48`），
低字节 `0xFF` 的两个半字节都不是十进制数字 ⇒ OSD 的温度格画 `--`（`:45-47` 的理由：
"复位成 0 会在 PS 起来之前画出 `Temp:00C`——那是一条没人测过的数"）。
这一位与 gamma 无关但共享同一个字，正是 2.3 里"所有写必须走影子 `gm_w`"的由来。

`always @(*)` 里用一个拼接做拆解（`:66-68`）而不是逐位 `assign`，
配套的那句代价说明（`:67` 行尾）也值得读："温度那一格的十进制口径由 PS 说了算、PL 只照画 ⇒
屏上写的数与 `temp` 打印的数必然同源"。

### 3.3 顶层：这一级在哪、吃谁的输入、输出给谁

```
pix_raw ─┬─► u_pipe(.din = pix_raw, .gamma_en/wr/idx/data) ──► pipe_dout_q ─┐
         └─► u_raw(行环) ─► orig_skid ─► orig_disp ──────────────────────────┴─► u_split
```

* 输入是 `pix_raw`（`src/rtl/top/pl_video_top.v:772`、`:808`）：有片源给帧缓存、没片源给图卡、越界给黑。
* gamma 的四个控制口从 `effect_ctrl` 出来直进 `u_pipe`（`:803-804`），中间没有任何再同步。
* 另一条抽头 `orig_disp` **不过链子**（`:781-792` 的行环 + `:831-849` 的 skid）。
* 于是 `split_display` 逐像素二选一（`src/rtl/video/split_display.v:47-48`）
  ⇒ **γ 只在"处理图"那一侧可见**，缝的左边是原图。
  这条既有文档口径（`report/command_precedence.md:68` 那行的"只在处理图那一侧可见"）
  在代码上就是上面那四行。
* 链子的级序是 `gamma → 颜色 → 滤波 → 边缘 → 阈值 → 形态学`（`src/rtl/process/proc_pipeline.v:51`）⇒
  灰度、Sobel、二值化吃的都是**已经校正过**的通道值。
  复合顺序是有后果的：`gray(γ(x)) ≠ γ(gray(x))`，
  所以"开 gamma 再开灰度"与"只开灰度"给出的亮度分布不同——这是设计选择（先做显示域校正再算亮度），
  念的时候别说成"等价"。

### 3.4 出屏之前的第二次位扩展

链子出来仍是 RGB565；`split_display.v:49-51` 取出 5/6/5，`:66-68` 再展开成 8 bit 送 TMDS。
用的位复制式与 1.3 那条**一模一样**。也就是说：整条通路是
`565 → 8 bit 复制 → γ 表(8 bit) → 截回 565 → 8 bit 复制 → HDMI`，
中间那次截回 565 是精度收窄点（2.2 的表），而第二次复制不会把精度找回来
（低 3 位是高位的影子，不含新信息）。

### 3.5 台架钉的是什么（八条）

`sim/tb_v88_gamma.v` 的八条判据在 `:11-14` 列出、`:126-198` 实现，覆盖的是**接线**而不是曲线：

| 判据 | 钉的事 |
|---|---|
| T1（`:126`） | `en = 0` 时 64 组像素逐位等于输入——整条链的安全网 |
| T2（`:133`） | identity 表下 96 个通道值仍逐位等于输入（R/G/B 各 32 档，正是 1.3 的可达集） |
| T3/T4（`:138`、`:143`） | 表 = `0xFF − i` 与 `i ^ 0x5A` 两种怪表下，输出等于**按自己展开后的索引**查表结果 |
| T4b（`:153`） | 反配对：`en = 1` 且表非 identity 时 R 的 32 档必须**全都不**等于输入 |
| T5（`:162`） | 只改 `idx/data` 不翻 `wr` ⇒ 整张表不变（协议是翻转，不是电平） |
| T6a/T6b（`:166`、`:172`） | 复位本身不产生一次写（`#52` 那一课的正面判据） |
| T7（`:183`） | 边界：`r5 = 0 ⇒ 索引 0x00`、`r5 = 31 ⇒ 索引 0xFF`，两端的表都查得到 |
| T8（`:198`） | 输出序列逐档不降（接反/串行会在这里露） |

期望值全部由台架自己那份 `ref[]` 算（`:23`），与被测模块"一份表两边各写一遍"⇒
接错线就分歧。曲线本身不在这里验，这一点在 `:22` 写得很明白（见 2.3）。

### 3.6 串口侧：四种写法与它们的语义边界

命令入口 `src/ps/main.c:1204-1252`，`gamma` 一词吃五种参数形状，全部**不猜**：

* `gamma off` → `gamma_off()`：清 `GM_EN`、清 `GM_DISP`、表保留（`:385-393`）。
  清显示位是必须的："不许留着旧值说谎"。
* `gamma on` → 若 `cur_gamma == 0` 则用 **220**（`:1209`）——上电默认没有 γ，
  这一句给了一个"没设过就开"的确定值。
* `gamma <数>` → `parse_gamma`（`:431-452`）后 `gamma_set`（`:1244-1250`）。
  解析器只吃 `1.8` 或 `180` 两种写法：带小数点时取**最多两位**小数、第三位数"只舍不进"（`:445`），
  不带小数点就按 γ×100 收（`:440`），出现别的字符直接返回 0 ⇒ 打印一条拒绝。
* `gamma auto [lo hi [step [ms]]]` → `gamma_auto_start`（`:1226-1241`），参数不足时用上一次的值，
  默认 `1.00..3.00`、步 0.20、2 s。
* `gamma manual` → 只把 `gm_auto` 落回 0 并打印停在哪一档（`:1219-1223`）；
  `gamma show` 报当前状态（`:1210-1217`）。

电池里对回声的机器判据在 `src/host/uart_cmd_check.mjs:251-253`：
既要求 `auto` 那一行把区间与节奏说出来（"否则用户不知道它在动"），
也要求 `manual` 之后**不许再打印** auto 那一行（反例必须钉到全角冒号那一行上，理由写在同处注释）。

### 3.7 一次 `gamma_set` 的完整时序（把代码串成事件流）

```
gamma_set(g100)                                  // src/ps/main.c:395
 ├ 参数范围检查 [100,300]                         // :400-404
 ├ for i = 0..255:                               // :405
 │    v = gamma_curve(g100, i)                   // :406  ← pow，双精度算、单精度存
 │    若 v < prev 则 bad++                        // :407  ← 单调自检
 │    记 first(i==0) / last(i==255)               // :409-410
 │    gamma_put(i, v)                            // :411  ← 两笔 32bit 写 + 两次 usleep(5)
 │    rx_fill()                                  // :412  ← 这 2.6 ms 里只搬 UART 字节不派发
 ├ gm_w |= GM_EN                                 // :414
 ├ gm_w 写 GM_DISP((g100+5)/10) 并整字下发        // :417-418  ← 屏上那一格与表同一次提交
 ├ cur_gamma = g100                              // :419
 └ 非 auto 时打印 g / mono_bad / first / last；
   自检不过额外打印一条告警，且明写"表已写入但不要用它演示"   // :423-427
```

PL 侧对应的时间线：每笔 `gamma_put` 的第二写让 `wr` 翻转 ⇒ `effect_ctrl` 的
两级同步在 2–3 个 `clk_pix` 之后把新值带到 `gm_sync` ⇒ `gamma_lut` 的 `prev` 比较发现变化 ⇒
**下一拍**写入三张表。整条链的延迟是几拍（几十 ns），相对 10 µs 的写间隔可以忽略；
要紧的不是延迟而是"别丢边沿"，那由 `usleep(5)` 保证（2.3）。

`:417-418` 那一句"OSD 那一格与表同一次提交"值得单独表扬一次它的必要性：
分开两处写会出现"表已经换成 2.2、屏上还写着 1.8"，而那一格是观众唯一能看见的证据。

### 3.8 通道 2 的存在性自证（elf/bit 不配套时的第一现场）

启动自检里对 gamma 窗口做了一次**只验地址、不动功能**的读写：
摆一个 `GM_DATA(0x5A) | GM_IDX(0x3C)` 的图案（`en = 0、wr = 0`，
所以既不开 gamma 也不往表里灌东西），写下去读回来，
不等就报"gamma 窗口不在位流上（elf/bit 不配套）"，收尾**回影子值而不是回 0**——
回 0 会把 `γ×10` 那一格抹掉（屏上变 0.0）。见 `src/ps/main.c:1552-1565`。
同一段之前还有通道 1 的 32 位宽度自检（`:1536-1550`），
理由写在那里："旧位流上没有这个从设备"，`src/ps/main.c:75-76` 的注释提前说过一次。

## 4 整体架构：这一级在系统里的位置与它欠的账

### 4.1 一张"谁算什么"的分工表

| 事情 | 在哪做 | 为什么在那做 |
|---|---|---|
| 幂曲线的算术 | PS（`src/ps/main.c:375-383`，`pow` + `-lm`） | PL 里没有浮点，做定点 `pow` 要 DSP 或 ln/exp 近似（`src/rtl/video/gamma_lut.v:4-5`） |
| 曲线的正确性判据 | PS 自检（`mono_bad / first / last`，`:407-427`） | 台架只验接线，"算错曲线"与"接错线"分开取证（`:281-283`） |
| 表的存储 | PL 像素域，3 × 256 × 8 LUTRAM（`src/rtl/video/gamma_lut.v:27-29`） | 异步读 ⇒ 不占拍 ⇒ `LATENCY` 常数不动（`src/rtl/process/proc_pipeline.v:21`） |
| 表的写入通道 | axi GPIO 通道 2 + 一对 32 位 ASYNC_REG（`src/rtl/process/effect_ctrl.v:39`） | 不新开跨域配对 = 不动 `cdc.rpt` 基线（`src/rtl/process/effect_ctrl.v:62-65`） |
| 事件（写哪一项） | 翻转位 + 像素域边沿检测（`src/rtl/video/gamma_lut.v:31-39`） | 脉冲跨不到本域（`src/rtl/video/gamma_lut.v:5`、`src/rtl/util/key_long.v:4-5`） |
| 扫描节拍 | PS 主循环（`gamma_tick`，`src/ps/main.c:347-364`，调用点 `:1592`） | 零新增硬件、零时序风险（`:296-298`） |

### 4.2 四条不变量

1. **`en = 0` 必须逐位旁路。** 这一条是"新加的一级没有改变任何已有行为"的安全网
   （`src/rtl/video/gamma_lut.v:11`、`sim/tb_v88_gamma.v:126`；纯 PL 演示顶层就是把 `gamma_ctl` 钉 0，
   `src/rtl/top/pl_demo_top.v:84`）。
2. **一次 `wr` 翻转 = 恰好写一项，电平不变不许重写，复位不算写。**
   （`src/rtl/video/gamma_lut.v:31-39`、台架 T5/T6。）这条一旦破了，症状是"表里随机坏几格"，最难查。
3. **写通道 2 的代码必须从 `gm_w` 出发整字写。**（`src/ps/main.c:94-95`、`:288`、`:417-418`。）
   任何"顺手写个常数"都会同时抹掉 γ 显示位与温度位。
4. **`gamma_disp` 与表内容同源同提交。**（`src/ps/main.c:414-418`，屏上那格的实现在
   `src/rtl/video/osd_overlay.v:282-284`：`putnum(gamma_disp / 6'd10)`、`"."`、
   `dig(gamma_disp % 6'd10)`——注意这里出现了 `/10` 与 `%10`，
   它们落在 OSD 那一整块组合逻辑里，而 `gamma_disp` 只有 6 bit，
   与温度为什么必须在 PS 侧换算（`src/ps/main.c:85-89`）不是同一条尺子，别混着念。）
