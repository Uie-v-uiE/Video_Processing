# `LEARNING/` 怎么读

这一套是**整个项目的学习文档 + 经验总结**，九卷正文共 3957 行（不含本文件）。它和仓库里另外两套学习材料的关系：

- `report/technical-document.md` 是**交付文档**，给评委看，讲"做成了什么"；
- `study_docs/` 是**已有的深读课与专题卷**（`branch_deep_course/` 15 章、`main_report_study/timing/` 时序四篇），讲"某一块怎么实现"；
- 这一套 `LEARNING/` 是**总账**：从器件和时钟周期开始，一路走到交付工程化和经验教训，每卷末尾都点名它引用的具体文件与具体读数，可以顺着往下钻。

## 四条路线

- **零基础**：01 → 02 → 03 → 04，再回头读 05a。前面四卷只要求会 Verilog 和会读 C。
- **会 Verilog、想抄架构**：01 的通路图 → 03（几何与效果链是这套系统里最值得抄的部分）→ 02 的"PL 做 AXI master"一节 → 05a 第 3 节。
- **要做时序收敛**：`study_docs/main_report_study/timing/00-from-zero-…` 打底 → 05a → 05b → 06b 的方法组四条教训。
- **要答辩或复现演示**：07（技能包 / 演示配方 / 数据面）→ 06a 的人眼判据与板级校验两节 → 06b 的数字索引（每个数当场能说出条件与出处）。

## 这套文档自己的两条规矩

1. **每个数字后面都点名来源**。写 `（来源：xxx）` 的那一句，其数字可以在括号里的文件中被读到；没写来源的句子不应该出现数字。跨构建的 WNS 绝对差在整套文档里一律不写成"收益"或"损失"。
2. **`文件:行号` 是核对过的**。落地前跑两层。第一层 `build/learning_cite_check.mjs` 判"路径存在、行号不越界、那一行非空"（同行写了"不入库/未随包/-Out/-log"这类叙述的指路算作 declared，不判红），现量 1089 条全 OK、红 0。第二层 `build/learning_anchor_spot.mjs` 判"正文反引号里抄来的那段代码，确实落在紧跟其后的那条引用所指的那一行 ±6 行内"，认基名简写（`pl_video_top.v:736`）与只写行号的续接引用（`:162`），结果分五档收口：逐字命中 / 折掉表格竖线后命中 / 只要求记号齐 / 由同行另一条引用支撑 / 可疑待读——现量 189 条判据、可疑待读 0；第四档那 27 条是"一句里并列多个来源"时抄文配到了前一条引用，每条都点开了它真正出自的那一条。第二层的输出**仍是候选队列不是判决**：它只证明"点名的东西在被点名的地方附近"，不证明那句话的意思。
