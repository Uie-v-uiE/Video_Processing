| 能力 | 说明 |
|------|------|

## 2. 目标域窗滤

窗滤（blur 与 sobel 这类邻域运算）取窗的位置决定了它算的是哪张图。早先的做法是 `angle≠0` 时
跳过 blur/sobel，原因是窗取在了源图的邻域上，而屏上显示的已经是旋转后的图。现在的做法分四步：

1. 屏幕坐标 →（缩放）→（旋转）→ 源像素  
2. 沿右窗光栅得到的数据流 = 显示域图像的扫描序  
3. blur/sobel 用 **右窗 cx/cy** 建 3×3 行缓存  
4. `rotate_active` 只作状态，不再强制 bypass  

```text
源像素(映射后) → 点运算 → 目标域 3×3 → 右窗输出
```

实现：`src/rtl/process/proc_pipeline.v`  
仿真：`sim/tb_rotate_window.v`

## 3. 无极缩放

| 项 | 值 |
|----|-----|
| inv_scale Q8 | 256=1.0× 最大，512=0.5× 最小 |
| 循环 | 每帧 STEP=2，三角波 |
| 锚点 | 图像中心 |
| 越界 | oob 黑边 |
| 默认 | PL 常开（`zoom_en=1`） |

表里 `inv_scale` 那一行是定点写法：倍率先乘一个固定的二进制比例、再存成整数，所以码值与倍率之间只差那一个比例；
inv 越大，逆映射采样得越"散"，画面上显示的原始图就越小。这一行循环的是自动呼吸那一路，手动档与拟合档
另有其表（见 `report/architecture.md` 的缩放表与 `report/defaults.md`）。

映射（无旋转）：

```
sx = W/2 + ((x - W/2) * inv) >> 8
sy = H/2 + ((y - H/2) * inv) >> 8
```

与旋转叠加时先算缩放偏移、再套 Q8 的旋转公式（inv=256 时与纯旋转一致）。旋转态真正在用的那个 inv
由 `zoom_ctrl` 收进"这个角度刚好装得下"的那一档（`report/log/issues.md` 第 93 条）⇒ 整幅永远在屏内；
代价是旋转时不提供放大，手动 1.33x/1.5x/2.0x 三档被拉回装得下的那一档（档号不丢，关掉旋转立刻回去），
缩小方向照旧。这一档在角度为零时不生效，也就是说正对屏幕时放大与缩小照常可用。

## 4. 数据通路关系（v3）

```
左窗: cx,cy → rotate → FB → 原图显示
右窗: cx,cy → zoom [→ rotate] → FB → 效果链 → 右窗显示
```

FB（帧缓存）只有一个读口，左右两窗按 `left_pane` 分时共用它，各自的地址排在同一串里轮着发。

## 5. 金标 / 仿真注意

"金标"指另一条独立实现算出来的期望值，用来和板上结果逐格比；它不是本工程的代码，所以比对前要先
把两边的定义对齐：

- 与 Python 参考实现比对：先做几何变换（缩放/旋转）再做窗滤，或者两边统一按目标域的定义算  
- `tb_zoom_mapper`：1.0× 恒等、0.5× 中心与 OOB、控制器三角波  
- 效果作用在右窗：比对时不能拿左窗 line_cache 那条路径当期望值的来源
