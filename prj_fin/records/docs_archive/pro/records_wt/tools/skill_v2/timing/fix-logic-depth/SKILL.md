# 锥太深：先算收益上限，再挑修法

## 适用场景

- 上一节的判读落在"逻辑级数深"这一类（`Logic Levels` 大、延迟集中在最深几级）。
- 一次构建要几十分钟到几小时，需要在开跑之前淘汰注定判负的候选。
- 上一轮插了拍，slack 只动了零点几，怀疑拆的位置不对或根本不该拆。

## 使用方法

**动手前先查**：厂商时序收敛章节里逻辑级数分布与关键锥的读法（`report_design_analysis -logic_level_distribution`、`report_timing` 逐级 `Incr` 差分），一手资料优先级 用户指南／数据手册 ＞ 应用笔记 ＞ 教程 ＞ 模型记忆。**先跟用户确认**：允不允许改延迟与接口协议（插一拍会改 latency，属可观察行为）、有没有面积／片内存储上限、提速目标是不是被批准过。

第一步，量四个数，再算上限：

```
从报告取: levels=<n>、逐级延迟（相邻 Path 列的逐级累计差）、当前 slack、需要的 slack
need      = 需要的 slack - 当前 slack
gain_max  = Σ(你确实能切断的那几级的延迟) - 新增寄存器的 setup/时钟网络差代价
gain_max < need  ⇒  这条路判负：写下"预测收益 + 判负理由"，不开构建
```

形状举例（是算法，不是结论数字）：若把最深的两级拆掉，上限约等于**被拆掉的这两级延迟之和**，不是整条路径延迟，也不是"少两级就按比例抬"。两级各约 0.1 ns 而 need 是 0.6 ns 时，这一步差 0.4 ns 只能来自布线或别的级——那就不该开这一刀。

修法清单，每条配一个**能红的判据**与一个**代价面读数**（判据只认同尺差分）：

1. **寄存一拍**（在锥中间切一刀）：判据 = 该族 `Logic Levels` 下降 ≥1 **且**该域相对余量变大；网表里必须数得出新寄存器，数不出打 `MECHANISM_INERT`。代价面 = 寄存器占用；**latency 变了要同步改**握手／流控／计数器对齐／缓冲深度，单元台架与端到端都要跟着改，否则红的是功能不是时序。
2. **串行算术拆并行树**（逐位进位改超前进位、累加改树形）：判据 = 同族 levels 下降**且** `route %` 没有明显升高。代价面 = 查找表／进位链占用与局部拥塞（常把①类问题做成②类）。
3. **顺序遍历改查表／片内存储**：判据 = 目标域相对余量变大**且其余域一格不掉**（名册差分）；资源代价必须同读（片内存储档位利用率、`route %`）。实测纪律：这类"资源换 setup"经常换不来多少——量到过被判负的一次（存储档位本就承重、打包缓冲已满，余量不动而占用上升）⇒ 先做小尺差分再决定，判负就进台账，不许换个口径再来一次。
4. **条件与选择前移**（把使能／比较移出最后几级，提前算选择信号）：判据 = levels 降 1 且 slack 升，且前移后的信号没在别的域成为新关键。代价面 = 面积与扇出（前移的点要驱动更多落点，可能把①类做成③类）。

换族提醒：**同一锥里最紧的一族会因你改的路径而换人**。改前改后都要点名终点族（Destination 的寄存器名前缀）；族一换，这两次读数不可比，判定只能退回逐域名册的相对余量，不许再报"这条路径抬了多少"。

## 失效条件

- **设计已零违例**：结构性改写通常被判负——收益上限算出来就是"本来就达标"，代价面（资源、latency、别的域）却是正的，还带功能风险。这种情形先问用户要不要提速，不要自己定目标频率。
- 报告里的 `Logic Levels` 与真实关键锥可能不同族：它只数这一条最差路径上的单元级数，也可能把存储读写延迟记成级；拿它当"全设计最深层级"会误导刀口。
- 跨构建比较吃放置／布线噪声：0.0x ns 的差会随机出现与消失。两端必须是同一份检查点的两个滚，或两个有指纹、同口径的正式构建，否则只念不判。
- 插的拍被工具折叠／重定时掉：机制读数为 0 时把结果写成"没有收益"是错的归因，应写 `MECHANISM_INERT` 并回到修法本身。
- 征兆：改后 slack 变好但目标族换了名字；levels 没降、`route %` 也没升（改动没落到物理上）；延迟相关的台架用例开始红。

## 已验证效果

以下读数来自某一次具体设计，量级只用于说明形状，随设计而变，不可当普适结论引用。

- 某次量到：一条算术锥拆成"两拍各 5 项"后，该族不再是关键项，判读随之改为布线／扇出主导——插拍有效，但收益必须用名册确认没有别的域被代价打到。
- 某次量到：一条 `route %` 70.5% 的姊妹路判定"逻辑修法收益上限低"，直接没开构建，省下整轮的时间。
- 某次量到：片内存储换 setup 的收益被判负（存储档位吃紧，相对余量不动而占用上升）⇒ 该候选进台账，不再重复记收益。
- 某次量到：一条 22 级（9 级在进位链）的锥，主导项确是级数，但拆它需要功能面决策，判定"不在时序这一轮的授权内"——上限算得出，动不了的原因是授权而不是工具。
- 未量过，属建议：修法 4（条件与选择前移）的单独收益没有同尺读数，只给了判据形状与代价面。
