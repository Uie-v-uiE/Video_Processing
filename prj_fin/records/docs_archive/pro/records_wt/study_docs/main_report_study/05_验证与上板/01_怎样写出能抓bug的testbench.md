# 验证与上板 01 · 怎样写出能抓 bug 的 testbench

> 这个仓库有 30 个 testbench、一次回归约 10 分钟。下面这些规则不是通用教科书，
> 而是**这 30 个 TB 里真正救过命的那几条**，以及它们各自救过什么。

## 0. 运行方式与它的漏洞

```bat
vivado -mode batch -nojournal -log sim\xsim.log -source sim\run_sim.tcl
:: 只跑某几个 / 带 plusargs：
::   set SIM_TB=tb_v6_ingress_integrity  &  set SIM_ARGS=+FULL
```

`sim/run_sim.tcl` 的机制（`:34-102`）：全量 `xvlog` 一次（`src/rtl` 含两级子目录的所有
`*.v` + `sim/tb_*.v`），每个 TB `xelab -debug typical -s <tb>` 后 `xsim -R`，
**判据是 grep TB 自己打印的 PASS/FAIL 行，取最后 10 条命中**（`:90-95`）。

三个必须知道的性质：

| 性质 | 位置 | 后果 / 对策 |
|------|------|-------------|
| **`NO_ASSERT` 被计入 pass** | `:96-102` | 一个什么都不断言的 TB 也算「通过」。当前 30 个 TB 都真打印了 PASS，但**新增 TB 时别忘了写断言**，它会静默地"绿" |
| 环境变量 `SIM_ARGS` 必须翻成 `--testplusarg key=value` | `:63` 注释 | 裸 `+key=value` 会被 xsim 拒收（打印 usage 然后退出，看起来像"跑完了"） |
| `SIM_ONLY=1` 只编译不跑 | `:55-70` | 改完 RTL 想先看编不编得过，用这个，30 秒出结果 |

另外：`xvlog`/`xelab`/`xsim` 在 `vivado -mode batch` 的 tcl 里**不是 Tcl 命令**，
必须 `exec xvlog ...` / `eval exec xsim ...`（这是环境事实，见
`report/OVERNIGHT_LOG.md` 的工具记录）。

## 1. 规则一：判据必须**能被反证**

反例（我写过）：一个 TB 断言「帧缓存读回来的数据和写进去的一致」。
它通过了。但它**永远会通过** —— 因为我把期望值也算错了，错得自洽。
把它变成能反证的做法是**再加一条会失败的断言**：

> `sim/tb_fb_roundtrip.v` 除了「38400 字写完 → 153600 次逐像素流水回读全对」，
> 还专门断言**读延迟契约**：给出地址后**下一拍**必须出数。
> 如果哪天有人把分块边界改错，这一条会立刻全红。

同理 `tb_v6_cover_gate` 的六条断言里有两条是「**不该提交的不许提交**」
（丢一包的帧被拒绝、有空洞的帧在线上被计数），
而不是只验「该提交的能提交」。**只有正向断言的 TB 等于没写。**

## 2. 规则二：TB 必须例化**上板的那份实现**，不是手抄副本

这条是被 `ddr_bank_commit` 这个模块的存在理由教育出来的。

原来那段乒乓换页逻辑写在 `eth_udp_video_top.v` 里，TB 想要它就得**照抄一份**进 TB ——
抄出来的副本和上板版本会分叉，测过了不代表板上对。
所以 R03 的第一件事就是**把这段 glue 抽成独立模块**，让 TB 例化真模块：

```verilog
// src/rtl/eth/ddr_bank_commit.v:4-6  头注释就是这个动机
// 例化处：src/rtl/eth/eth_udp_video_top.v:258-278
```

反面教材就在同一个仓库里：`udp_rx_parser.v` **没有被例化**，
但它有自己的 TB（`tb_udp_parser.v`，还断言了 "wrong port dropped"）
⇒ 这条 PASS 与板上行为**完全无关**。板上真正跑的是 `udp_rx.v:190-202`，那里不做端口过滤。

**自检问题**：你这条 PASS 对应的代码，综合器会实例化吗？
（查 `build/util_hier.rpt` 或综合日志的模块层次，比想更可靠。）

## 3. 规则三：修复类 TB 要**双向**——旧行为必须复现失败

`sim/tb_v6_tail_bank.v`（帧尾 4 字节丢失）是这套写法里我最满意的一个：

```
同一段激励，同时灌进两条并排的入包链：
  链 A：ddr_bank_commit #(.TAIL_GUARD(1'b0))   ← 旧行为
  链 B：ddr_bank_commit #(.TAIL_GUARD(1'b1))   ← 上板行为
断言（:130-175）：
  A **必须**丢掉帧尾，否则本 TB 判 FAIL（因为它没能复现已知 bug）
  B **必须**整帧完整 + commit 次数 = 2
```

为什么必须两边都跑：只断言 B 正确，无法区分「修好了」和「激励根本不触发这个 bug」。
**一个不能复现 bug 的回归测试，是在给未来的自己发假安全证。**

同一个思想的仿真版：`tb_v6_ingress_integrity` 的 `+FULL +MISALIGN`
（1396 B 分包）在 v6.4 之前是 38290/38400、first bad word=174，之后 38400/38400。
一个 plusargs 就是一条 A/B。

## 4. 规则四：把「拍数」变成可判据的对象

三条真实踩过的坑，都跟「我以为寄存了几拍」有关：

### 4.1 未位宽的延迟常量会截断（32 bit）

```verilog
#20_000_000_000;      // 期望 20 秒
```
Verilog 的数字字面量默认 **32 bit**，20e9 > 2^31 ⇒ 截断成 2.82 ms。
表现是「TB 超时退出但什么都没跑完」，看起来像 DUT 挂死。
**写法**：`#(64'd400_000_000_000)`。这条现在记在 `tb_fb_roundtrip.v` 的文件头。

### 4.2 AXI 从机用了寄存后的地址

W 数据与 AW 同拍到达时，从机若用 `awaddr_r`（寄存器版）就会把第一拍写到**上一个突发**的地址。
表现极有迷惑性：「8 个字的期望值里恰好只有 1 个对」——
因为 8 个 lane 只有 1 个恰好落在同一个 64bit 字里。

### 4.3 地址单位：字节 / 半字 / 字

```
frame_reasm 的 wr_addr[18:0]     = 16bit 半字索引   （off[18:1]）
frame_buffer_w64 的 wr_addr[18:0] = 64bit 字索引
AXI 地址                          = 字节地址
```
我给 `frame_buffer_w64` 喂字节地址写 TB ⇒ 只有 1/8 的字对。
**规则**：任何地址端口的 TB，第一行注释就写清它的单位；
模块内的注释也要写（`frame_buffer_w64.v:17,21` 就是这么写的，是后来补的）。

## 5. 规则五：仿真不能覆盖的东西，要**明确写出来**

`sim/probes/README.md:1-10` 开宗明义：`probes/` 下的文件**不是 TB、不参与 `run_sim.tcl`**，
它们回答的是「Vivado 把这段写法综合成什么」。这个区分很重要，
因为**综合推断类问题（BRAM/LUTRAM/DSP）用仿真是查不出来的**。

| 类别 | 仿真覆盖 | 靠什么 |
|------|----------|--------|
| IO 原语（`rgmii_rx` 的 IDELAYE2/IDDR、`tmds_serializer` 的 OSERDESE2） | ❌ | 板级 ping / 屏幕 |
| ARP / ICMP | ❌（无 TB） | `ping` 通 = 两者都对 |
| UDP / 拼帧 / 打包 / 提交 / 消隐拷贝 / 帧缓存 | ✅ 22 个 TB | `run_sim.tcl` |
| 真实 DDR/HP0 时序与时延 | ❌（TB 里是**可配置让步率**的 AXI 从机：`rate_num beats/10 cycles`） | 板级 JTAG 回读 |
| PS 固件（C 代码） | ❌（`tb_uart_decode_bits` 只是 `parse_bits` 的 Verilog 复刻） | 串口手测 |
| 综合推断（BRAM/DSP/LUTRAM 落点） | ❌ 本质不能 | `sim/probes/*` + `report_utilization` |
| 1024×600 实际显示、HDMI 电气 | ❌ | 屏幕 + 采集 |

**一个必须诚实的地方**：`--no-pace`（不限速）工况在仿真与板级都只做了
「允许 `net_bad` 上升但不许卡死」这一条，且记录为**未测**
（`report/V6_BOARD_MEASUREMENT.md:117`）。
写成「已验证不限速」就是造假。

## 6. 规则六：报告类判据要能落到文件上

`build_system_axigpio.tcl:138-143` 用 `catch` 包了五份额外报告
（`cdc.rpt / methodology.rpt / power.rpt / route_status.rpt / clock_util.rpt`），
注释写明动机：**门禁要求功耗与布线状态有对应文件**。
`catch` 的副作用是「报告失败不会让构建失败」⇒
所以判"构建成功"必须另外检查这些文件存在且非空，不能只看 exit code。

同理，「30/30 PASS」这个结论目前**在版本库里不可复算**：
入库的回归记录是 `sim/results/regression_v6.txt` 的 28/28（v6.4），
而 30/30 的日志（`sim/r0*.log`）被 `.gitignore:55` 排除，
只能靠 `report/OVERNIGHT_LOG.md` 的叙述核对。
**该把最新一轮回归结果也落成 `sim/results/` 下的文本**——这是我发现但还没做的一件事。

## 九、判据的**求值时机**：task 里 settle 是无效的（今晚两次踩同一处）

台架计分靠被测者的寄存器输出（例如单拍的 `wr_en`），所以"判据之前多留两拍"是必须的。
但把 `settle;` 放进判据 task 的**内部**没有用：

```verilog
chk("c01 16 pixels -> 4 words", nrec == 4);   // ✗ 实参在调用点就已经求值
task chk; input ok; begin settle; $display(...); end endtask
```

Verilog 的 task 输入在**调用时刻**取值：`nrec == 4` 在 settle 之前就算完了，
于是"每段最后一个字"那一拍永远来不及被计分 —— 而报出来的现象是"计数对不上"，
看起来完全像 DUT 少写了一次。**正确做法只有两种**：在调用点之前 `settle;`，
或者让判据做成函数、由调用方自己保证时序。

今晚这条坑的代价与收获：`tb_fb_pack` 连跑 4 轮，其中两轮的红是**台架自己的**
（判据时机 + 一个车道字面量写反），DUT 只有一个真 bug（换字时旧 lane 残留）。
如果我把"红"直接归给 DUT，就会去改一个本来正确的模块。
⇒ 判据失败时先问一句：**这个数是台架算的，还是被测者算的？**

## 十、逐条判据要能被回归脚本收集到

`sim/run_sim.tcl` 只把包含 `PASS` / `FAIL` 字样的行当证据收集。
所以台架里用 `OK` / `BAD` 做逐条标记时，不加 `SIM_VERBOSE=1` 就**一条都看不见**，
只剩最后一行 RESULT —— 排查时要么逐条标记里带 `FAIL` 字样，要么固定开 verbose。
另外中文标签在这台机器的 xsim 控制台输出里会糊成 `?` ⇒ **逐条判据的标签用 ASCII**，
中文说明留在注释里。

## 十一、跨域/时序类的判据：**必须自己制造相位差**（R23 的相位扫描）

`tb_v79_abort_toggle` 的形状值得记：一个"1 拍脉冲跨到慢时钟域"的 bug，在**默认相位下仿真永远全对**
（本工程的 100/50 MHz 就是 MMCM 同相出来的）。台架里把慢时钟的半周期临时改成 11 ns 再改回 10 ns
（`always #(PZ)` + 一次性 `PZ=11; @(posedge) PZ=10;`），就得到 1..9 ns 的**永久相对偏移**，
于是同一个判据变成一张表：

| 接法 | 10 个相位合计 | 4 ns 那一档 |
|------|--------------|------------|
| 裸采 | 27/30 | 0/3 |
| 电平型 3 级 | 27/30 | 0/3 |
| 翻转 + 3 级 + 异拍 | **30/30** | 3/3 |

三个可复用的写法：
1. **把"看起来正确的替代方案"也一起量**（这里量了电平同步）。它给我的旧结论
   "电平同步只会更糟"判了"一样糟" —— 台架否掉我的推论，正是它该干的活。
2. 判据写成**比率**而不是"有没有输出"：`看到的次数 == 真发生的次数`，多了也算错。
3. 移相这件事**只能在台架里做**。板上的相位差由布线/器件决定，是"运气变量"；
   台架里它应该是**测试维度**，不是被忽略的实现细节。

## 十二、检查器要自校，判据常数要有独立出处（R23）

`tb_ku5p_telem` 里那条"整帧过 CRC 得到常数余数"的判据，第一版我按记忆写了 `0xC704DD7B`，
跑出来 FAIL，看起来像 DUT 的 CRC 错。真实情况是我记错了异或约定。
现在这个台架有两道锁：
1. **自校检查器本身**：同一个 CRC 函数必须先对 `"123456789"` 给出 `0xCBF43926`；
2. **判据常数来自另一份实现**：`0x2144DF1C` 是在 node 里跑同一算法算出来的，
   不是从被测对象回抄的（回抄=同义反复，永远绿）。

推广一句：**任何"魔法常数"判据都要能回答"这个数是谁算的"**。
本工程里同类的还有 `fb_rd5x` 的 LAT（用唯一平移搜索量出来，再钉成常数）。

## 十三、三种"台架自己骗自己"的形态（都是今晚真踩过的）

| 形态 | 现场 | 修法 |
|------|------|------|
| **字节下标当时间用** | 用 `fstart[1]-fstart[0]` 算发包周期，得到"90"，正好等于帧长 | 抓包时同时记 `$time`，周期用时间差算 |
| **测试之间不清场** | 上一拍的模型还在发字节，下一个测试的计数从半截开始 | 每个测试前 `quiesce()`：等所有流 idle、再清零观测 |
| **靠"猜几拍够"收尾** | `repeat (LEN+10)` 差 2 拍 ⇒ 看起来像 DUT 少发 | 有界等待 `for (w=0; w<300 && 没到目标; w=w+1) @(posedge)`，到点就走、不到也不挂 |

补一条流程性的：**没有任何台架例化的顶层，回归全绿也检查不到它的端口连接**
（`ku5p_eth_top` 把 `.udp_txd` 写成 `.udp_gmii_txd`，40 个台架全过，`synth_design` 7 秒报错）。
⇒ "跑一次综合冒烟"（`KU5P_SYNTH_ONLY=1` / `build_pl_full.tcl`）和"跑台架"是两种判据，缺一不可。

## 十四、规则七：修法有**多个候选**时，让同一个台架把每个候选都跑一遍（R24）

§3 说的是"旧行为必须复现失败"（A/B 两态）。今晚 #37 遇到的是另一件事：
**候选修法 themselves 也各有 bug，而它们坏在不同方向上。**
做法：把 DUT 复制到临时目录改三个版本，用**同一个台架**、同一段激励各跑一次（仓库代码不动）：

```bash
R=/tmp/kx2/variant && mkdir -p $R/src && cd $R
# 变体来源：git show HEAD:src/rtl/eth/eth_ctrl.v 取原文；只改那一行条件
xvlog src/eth_ctrl.v <依赖…> sim/tb_ku5p_tx_arb.v && xelab tb_ku5p_tx_arb -s snap && xsim snap -R
```

| `eth_ctrl` 变体 | `midbad` | ARP 字节 | UDP 字节 | 挂在第几条断言 |
|---|---|---|---|---|
| 厂商原文 `\|\|` | 3 | 12 | **7** | 帧被截断 |
| 只改 `&&` | 0 | **0** | 12 | 请求丢了 |
| `&&` + 跨 always 块清账 | 0 | **13** | 12 | 授权脉冲高两拍 |
| 最终版（`&&` + 同块记账） | 0 | 12 | 12 | —（PASS） |

三个可复用的收获：
1. **"只跑最终版"只能证明最终版对**；三个候选一起跑，才能证明**每条断言各自抓的是哪种错**，
   也就证明了这三条断言一条都不能省。
2. 表格本身就是最好的"为什么我改两行而不是一行"的证据 —— 评审问起来不用再解释。
3. 变体要跑在**临时副本**上（配合 `git show HEAD:` 取原文），
   否则改仓库里的文件会污染同一次构建/回归的来源（今晚 build#19 正在跑，绝不改 `src/rtl`）。
