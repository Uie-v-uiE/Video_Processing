# S14 · 硬件计数器读回来变成指标：先钉"分子分母是同一批事件"，再给表加一条自相矛盾检查

## 触发
- 当你准备把"跑 N 秒 → 读回一组计数器 → 折算成 fps / 带宽 / 丢包率"固化成一条可复跑的命令时
- 当你算出来的吞吐、帧率、平均间隔"好得不像话"，或反过来离谱得说不出口时
- 当同一行里平均值落在 [最小值, 最大值] 之外时——算术上不可能，口径一定错了
- 当你准备用"某个错误计数的增量为 0"来宣布"这一轮没丢"时
- 当这张表要给不是你本人的人复查时

## 不适用
- 需要眼睛的指标（glass-to-glass 延迟、画质主观评价）：本方法只覆盖链路内部数得出来的量
- 硬件里不是单调累计、而是"终身保持峰值"的量：它只能取 max，取差值会得到负数或一个假 0
- 采样期间被测处理器会被调试口停住的系统：墙钟里含停机时间，任何"每秒"类量都失真

## 动作
1. 先给每个量写一行"分子由谁累加、分母由谁数"，确认两者是同一批事件。只要存在"到了但没算"
   的事件（被验收门作废、被丢弃、被截断），分母默认就是虚高的，先扣再除
   （例：分母 = 交付帧数 − 作废帧数 − 1，而不是"交付字节 ÷ 帧长"）。
2. 间隔类的分母是**段数 N−1，不是帧数 N**：第一帧只建立基准、量不出间隔。写成 N ⇒ 平均间隔
   被低估、折算的 fps 同比例偏高，误差 1/N（几十帧量级约 3 %，个位数帧量级到 20 %）。
3. 计数器分两类：累计型一律取"后读 − 前读"的差值；保持型（峰值/最小值）取两次的 max，
   且可归零的那类要在测量前归零一次，否则最小值还是历史值。
4. "没丢"写成两条与门：丢字增量为 0 **且** 缓冲满过事件增量为 0。只看前者会漏掉
   "满过但刚好没溢出"这种即将出事的状态。
5. 采集与算式分家，一次测量只在开始/结束各读一次；**前后两次的原始读数**要和结论一起存档，
   并且走一个只吐结构化数据（一行 JSON 之类）的出口——去解析人读的判读文案会把两个工具
   焊死，改一句文案就崩。
6. 给算式配一条**不打硬件的自检**，其中必须有一条反面对照：故意用第 1/2 步说错的那种分母
   再算一遍，必须给出与正确值不同的结果，否则这条判据是恒真的。
7. 给表加一条自相矛盾检查：平均值必须落在 [min, max] 内，越界就当场打印"分子与分母不是
   同一总体，这张表不能用"并置一个标志位，而不是等人肉眼发现。

## 完成判据
- 一条不打硬件的自检命令全绿，且里面那条反面对照**红得起来**：分母从 N−1 换成 N 必须算出
  不同的结果（本仓库阈值 >0.3 fps；命令：`node src/host/metrics.mjs --selftest`）。
- 只有一帧时段数为 0 ⇒ 必须是 `NaN`；表里出现"0 ms ⇒ 无限 fps"就是红的。
- 表里每个念给人看的数，都要能在同一次存档的原始读数（前 + 后）里找到出处；找不到就是
  这一轮没跑成，写"未验证"，不许补一个看起来合理的数。

## 失效边界
- 推流期间不要用调试口读寄存器（会停住处理器），墙钟 fps 立刻失真——只在前后各读一次就是为了避开它。
- 链路断开或参考时钟被拉走时，"ms"类字段其实是周期数不是毫秒。采集器必须把这两个标志和数字
  一起打印，让读表的人当场决定信不信。
- 折算里写死的几何常数（帧长、每帧字节数）与真实分辨率是两件事，换几何不同步改它，按字节折算的
  帧数直接错。
- 载荷字节增量不是帧长整数倍时帧数会是小数——那是"有半帧没凑齐"的信号，不许四舍五入掉。
- 相邻条目的分界：**怎么得到**这些原始读数（逐帧变化的图案协议、发完再读）见 S9；读回来的
  一组数互相不自洽（部分大于整体）见 S18；带宽/丢包这类"先算后动"的账见 S4。
