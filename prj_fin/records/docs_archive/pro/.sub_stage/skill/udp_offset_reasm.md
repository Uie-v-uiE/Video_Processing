# S1 · 上位机 bulk 推流的落位协议：分包按目标偏移写、提交要两条与门，手写 RX 链再清五处隐性假设

## 触发
- 当 PC/上位机向 PL 推**原始帧**（视频、点云、矩阵），每帧远超一个 MTU、必须切包时
- 当症状是"画面均匀黑点 / 拖影 / 最新一帧没上来"，而你手里没有一条命令能说清**丢在哪一级**时
- 当你想让数据面彻底离开处理器（ARP / ICMP / UDP 全由 RTL 应答，PS 或 MCU 只做控制面）时
- 当你准备沿用别人那句"载荷长度取 8 的倍数"的经验时
- 当你改动手写协议栈的一小段、整链就收不到包、而且它不报原因时

## 不适用
- 需要可靠、有序交付的场合：本方案丢包就是丢包，靠下一帧自愈
- 走 SoC 自带 MAC + 协议栈（lwIP 那一类）的工程——下面所有结论都建立在"不经过 CPU 缓存与协议栈"上
- 稀疏载荷（一行只写几个字节）：行覆盖门在那种形状上会误判，见失效边界

## 动作
先定协议侧的五件事（按这个顺序做）：
1. 包头带**绝对偏移**（该载荷在目标帧内的字节偏移，定长小端字段），接收侧把它换算成写地址 ⇒ **按偏移落位，绝不按到达顺序追加**。换算时先确认单位是"字节地址"还是"存储字索引"，两者差 log2(位宽 ÷ 8)；再顺手用偏移算出行号，用来记"本帧哪些源行被写过"。
2. 提交门写成**两条与门**：被写过的行数 == 总行数 **且** 帧内字节累计 == 帧长，并且本帧没有坏包。只看累计字节会把"丢一包 + 一包重复偏移"当成收满 ⇒ 空洞帧被提交。
3. 把"换页 / 切 bank"与"数据就绪"分成两件事，换页还要等跨域排空——否则屏会在半帧上翻页。
4. 坏帧策略说死（丢弃、不重传、屏上保留上一帧），但事件必须落成**可数的寄存器**（作废帧计数、缺行峰值），而不是留成屏幕上一条没人能计数的黑纹。
5. 载荷长度是**板级量出来的**，不是随手取的：包边界若落在存储字中间，同一个字会被分两次推送、后一次覆盖前一次，于是每帧留下固定数量的小宽度空洞（洞里全 0 ⇒ 屏上均匀散布的黑点）。修法只有两种：把包长取成总线字宽的整数倍，或让写侧按字节写使能生成部分字写（本仓库两条都验过：1396 B → 1392 B，以及补上写使能后仍用 1396 B 复测）。换板 / 换位宽 / 换 burst 语义都要**重量一次**这条对齐边界，别沿用别人那句"8 的倍数"。
手写 RX 链再清这五处隐性假设（每一条都会静默改变行为）：
6. 前导码 / 分界符状态机是一段隐性契约：动它的相位、计数器位宽或状态编码，整链就收不到包，而且它不会报"为什么没包"——现象与"对面没发"一模一样。
7. 邻居缓存（ARP）如果只存一个对端，同网段多主机时回复目标会漂；顺手确认它是否还接受广播目的地址。
8. "树里有这段代码 ≠ 板上有这个功能"：引用"某某检查已经做了"之前，先确认**被例化的那条链**上有它（`bash build/orphan_rtl.sh` 拿综合日志当可达性 oracle）。功能做了与它**可观测**也是两笔账——被过滤器丢掉的包若没接成可读寄存器，板上看不到"丢了多少"。
9. 任何"看起来恒真 / 恒 0"的输入都要 grep 它的驱动：本仓库的错误标志曾被硬接成常量 1，于是下游坏包计数**构造性为 0**，那一版所有关于坏包的遥测都是死数字。结论里要写清它靠哪一级证据。
10. 端口 / IP / 地址在几处各写了一份时，改一处不会报错、只会静默不通 ⇒ 集中成一处，或加一条对账脚本把它们比一遍。

## 完成判据
- 一条乱序 / 丢包 / 重复 / 帧跳变 / 坏包的激励必须证明"提交门真的在门"：丢过包的帧被拒绝、有洞的帧被计数、下一完整帧仍能提交（本仓库：`bash sim/run_one.sh tb_udp_reasm`、`bash sim/run_one.sh tb_v6_cover_gate`）。
- 对齐边界那条判据要能**自己解释数字**：修复前逐字比对 38290/38400、首个错字编号 174，而 174 正是"包长 ÷ 总线字宽"算出来的那个跨界字。数对不上机理，就说明还没抓到根因。
- 台架里"行覆盖"与"字节覆盖"必须分开写：合在一起就复现不出第 2 条那个误判。

## 失效边界
- 偏移字段本身坏了就写飞：链路层 FCS 有检查，但 UDP/IP 头里的 checksum 通常不参与判定 ⇒ "范围合法但数值错误"的偏移查不出来，只有越界那一类有计数。要防它得在应用层加 magic / CRC，别指望协议栈替你验。
- 两条提交判据都是几何相关的（行门要真实行数、字节门要帧长常数）⇒ 改分辨率时若帧长常数没被例化参数覆盖，就会静默失配。
- 不重组 IP 分片 ⇒ 上位机必须自己控制包长不超过 MTU 余量。
- 稀疏载荷（点云抽稀、稀疏矩阵）会把没写过的行也算进"覆盖" ⇒ 换成**包位图**，而不是把行门调松。
- 片外时序没约束时（位对齐靠固定输入延迟抽头、收发方向被 false path 整条豁免），时序报告全绿只说明**片内**满足，片外只有板级证据 ⇒ 换板 / 换走线要重扫抽头。
- 器件换代时收发侧的原语（串联 / 延迟校准、输出的串化器那一类）整段作废，必须改写；本仓库从 7 系列换走就会踩这条。
- 相邻条目的分界：连线 / 绑源地址 / 串口重扫见 S7；上板不亮的分层定位见 S8；"丢在哪一级"的图案协议与发完再读见 S9；跨域脉冲的写法见 S11。
