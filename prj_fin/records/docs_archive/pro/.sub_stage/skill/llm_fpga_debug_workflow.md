# S5 · 让模型的每个结论都能追溯到文件与数字，且骗不过一次直读复核

## 触发
- 当你用大模型写 RTL、定位上板问题、整理交付材料，而要求每个结论能追溯到文件与数字时。
- 当你准备把模型/子代理转述的一个数字直接写进报告时。
- 当你想问模型"综合器会怎么处理这个写法"时。
- 当你准备让模型去"查资料"（数据手册、论文、同类开源）时。

## 不适用
- 工程里没有任何跑得出来的判据：这套纪律靠"能红"才成立，没有判据时它只会拖慢你。
- 需要肉眼收敛的画质问题（缩放走样、色彩、抖动）——那一半的规程在
  [S23](eye_acceptance_loop.md)；本页只覆盖能被命令判的部分。
- 跨模型 / 跨工程的可比性：本文件只主张"这些纪律在本仓库抓出过具体缺陷"，不主张通用效果（未验证）。

## 动作
1. **上下文一次给全，之后只给增量**：器件完整 part 号、工具链精确版本、架构图路径、失败日志**原文**
   （不是你的转述）。日志原文这条不能省——模型会对"只截了 20 行"的日志补出它以为在中间的那 100 行。
2. **交叉阅读模板（只读角色，防止和构建抢同一份工作目录）**：只读，不许改文件、不许跑仿真；给我 3 个
   候选根因，每个附**文件路径 + 行号 + 那几行原文**；行号不确定就写"不确定"，**不要估**。
   （钉成硬要求，因为一次交叉阅读里出现过"引用了一个不存在的行号"——估出来的行号和读出来的一模一样，
   只有回原文才能分辨。）
3. **验收模板（主代理侧）**：逐条给出 结论 / 支撑它的文件与数字 / 你为得到它跑了什么命令；我这边**直读**
   同一份文件复核，对不上的那条降级为假设，不进报告。
4. **要求可证伪**：让模型写"若假设成立应看到 X"，再把 X 变成一条能跑的判据，用它的红/绿裁决。
5. **凡"综合器才知道"的问题，用最小实验回答而不是问模型**：同一存储器的几种写法变体做成对照探针，
   量出各吃多少 RAM（本项目靠这两个数定下架构，见 [S10](derived_clock_port_mux.md)）。想清楚"这一步
   能不能换成一次本地测量"再决定要不要去查资料。
6. **数字不许采信转述**：每轮由主代理直读工具产出的报告；模型/子代理给的数字一律先当假设。
   RTL 侧附带约束：注释只写非显然的 WHY；禁止无端加流水"以防万一"；禁止顺手加超时计数器当兜底。

## 完成判据
- 每条结论都挂着"文件路径 + 数字 + 命令"，且能对上直读结果（对不上就降级为假设、不进报告）。
- 这套纪律要能真的**推翻过东西**，不是口号（本仓库推翻过 3 次模型与自己的结论：一条被逐条件核对否掉的
  "死代码"判断、一次"断链 ⇒ PHY 停供时钟"被计数速率证伪——沿够不够快而非有没有沿、以及一张自证过的
  收益表被换成带锚点+反向对照的双判据重做）。
- 判据自身有产物：一个 PASS/FAIL 都不打印的台架**不许计为通过**；工具自报"成功"不算数，要检查镜像里
  关键符号与代码段大小（本项目第一次"链接成功"的镜像被 `--gc-sections` 裁到只剩几十字节）。

## 失效边界
- 只让模型"直接改位流 / 改管脚约束"而没有原理图或引脚表依据 ⇒ 立即停手。
- 无仿真、无日志的纯猜测循环；把**未上板**的数据写成实测结论。
- 转述数字未经直读复核 ⇒ 一律当假设。反面案例：拿几分钟后单独 `awk` 出来的一份报告宣布结论，那是
  **上一版**的文件；同一件事的机器版判据见 [S16](cdc_pair_baseline_gate.md)。
- "把 ISSUES 当检索索引"依赖编号稳定，而编号一直在往后追加、还会漂 ⇒ **引用任何编号前先 grep 核对条目
  头**。这一页故意不写"现在排到第几条"，那个数每天都不一样。
