# 项目简介（500 字以内）

**基于 Zynq-7020 的多源视频实时处理与同帧对照观测平台**

平台在一块 Zynq-7020 上完成"三路片源进、一路 HDMI 出、中间可逐级看"的链路：千兆网 UDP 推流、
SD 卡回放、PL 自绘图卡三种片源由硬件仲裁统一接管，任一路心跳消失后半秒内自动让位。画面送
1024×600 HDMI，可缩放（0.25–2.00 八档预设，另有手动倍率与随角度自适应）、可旋转、读口可选
双线性或最近邻；九级效果链固定 15 拍延迟。整屏只有一条读地址流,
原图与处理后画面**逐像素二选一**：对照线可停在 0–100% 任意位置、自动扫描、或跟随画面一起旋转，
而同一条线左右两半永远来自同一次采样。

选这个结构的动机很实际：图像处理系统最难的不是"算得出"，而是"看得出算得对不对"。同帧对照把
主观体感变成可比较的读数；片上自诊断把"这一帧干不干净"变成硬件计数器——被吞字数、作废帧数、
坏包数、帧间隔极值、帧到屏的实测时延、结温与越阈标志，全部由 PL 自己数、OSD 显示、串口回读，
三个出口互相对账，性能数字不靠外部仪表背书。

实测（数字各出自自己那一版的留档，不跨版拼数）：30 fps、限速 15 MB/s 连续 300 s 零丢包零坏帧；
不限速推到 116.7 fps 仍未丢字；最近一次门禁全绿的 r75 实现后 WNS +0.066 ns、零失败端点，
LUT 28.25%、BRAM 97.5 块、动态功耗 2.227 W。

工程侧的重点是可复现：一条 Tcl 命令从源码到位流；一条命令跑完的门禁覆盖时序、资源、CDC、端口
接线，外加逐像素判定的顶层台架与文档时效检查；关键判据都配变异对照——把修复还原回去必须恰好
红一项；每份报告按 md5 与被测源码绑定，红一项即不采纳。
