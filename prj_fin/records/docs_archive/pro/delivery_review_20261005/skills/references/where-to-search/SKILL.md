# 先查什么：资料位置、优先级与引用记法

## 适用场景

任何一个新问题的第一步。症状级触发：写出跑不通的约束；把示例工程当规格；
两个来源给出不同的数；被追问"这条结论的出处在哪一页/哪一节"时答不上来；
或者更隐蔽的一种——**用了模型的记忆而没有留下任何可核对的位置**。

## 使用方法

**四类事实，四类出处**（顺序即优先级，高优先级压倒低优先级）：

| 要定的事实 | 一手出处 | 检索位置（按本工具/板卡的官方文档体系） |
|---|---|---|
| 器件能不能放得下、硬上限 | 器件数据手册的规格表、厂商资源估算表 | 官方器件手册 + 官方在线资源估算工具 |
| 引脚/电平/时钟来源/复位与配置模式 | **开发板原理图**与手册的管脚表，用户手册的"板级资源"章 | 板卡厂商资料包；原理图要存到本地并记页码 |
| 工具的命令、选项、属性名、报告字段 | 该**版本**的官方命令参考与用户指南 | 官方文档站按版本号筛（版本不同字段不同）；本机 `help` 类只读探针作为辅证 |
| 对外接口的时序/窗/掩码/电气 | 接口规范正文与其测试规格章节 | 规范组织的公开摘要 + 已发布的第三方转述；**表格类常在会员/保密材料里** |

**三条硬规矩**

1. **每条写进文档的事实绑一个位置**：文档名 + 版本 + 章节/表号/页码 + 一条能复跑的核对动作
   （例如"读第 N 页表格第三列"或"跑某命令看到某字段"）。
2. **拿不到原文时不许当已确认**：转述要标"二手转述，未核对原始表格"，
   并把它留在"待核"清单里（`templates/claims-vs-evidence` 的状态列）。
   合规/认证类表格（眼图模板、窗口限值一类）经常只在受限材料里——
   公开二手可以引，但不能改写成"规格已确认"。
3. **区分三类数字**：实测（有件）／计算（有公式与输入）／假设（必须明写"假设"）。
   维度也要对上：单向的扩散量/抖动上限是**一侧的界**，不能当双边窗写进约束。

**提问模板（向模型要事实时）**

```
只回答【填入：要查的事实】，并按下面格式给：
1) 结论一句话；2) 出处：文档名+版本+章节/页码/表号；3) 如何自行核对（给一条命令或一个动作）；
4) 若你没有可靠出处，直接写"未知"，不要给推测。
禁止：把记忆里的页码当事实；引用不存在的选项名。
```

**先跟用户确认**：资料是否已在本地（有人手上有整套文档就不用联网猜）、
是否受保密限制（决定能否进交付包）、以及"这份转述能不能写进交付文档"。

## 失效条件

- 扫描版 PDF 检索不到文本 ⇒ 你搜不到 ≠ 文档里没有，只能判"未核"。
- 联网搜到的版本与你手上的工具/板卡不是同一代 ⇒ 字段名与属性可能已改，结论不可迁移。
- 把"探针返回空"当"不存在"：先证明查询本身能取到东西（正对照），再谈否定结论。
- 用二手材料定电气或时序参数并在板上出事 ⇒ 责任在引用规则，不在材料本身。

## 已验证效果

未量过，属建议。自查方式：随机抽交付文档里 10 条含数字的句子，
统计"能说出出处 + 能给出核对动作"的比例；不达标的那几条就是这条规则在执行层失效的征兆。

## 来源

长自两类观察：① 把教程/模型记忆当规格写出不可用的约束，返工一轮；
② 受限表格里才有的合规数值被写成"已确认"，事后只能降级为"未核"。
与 `research-before-code`（纪律）、`pitfalls/tcl-and-probe-traps`（空集与否定结论）、
`pitfalls/constraint-coverage-loss`（按名引用要回查）配套。
