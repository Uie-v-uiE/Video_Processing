# 从接口契约生成主机侧调用与测试骨架

## 适用场景

- 板载程序与上位机脚本各写一份寄存器/命令定义，改一条要改两处，长期不同步。
- 新增一个寄存器或一条命令后，只有调用改了、测试没改；漏项靠人记。
- 地址、位域、换算系数散落在业务代码里（裸偏移、硬编码魔术数）。
- 交接时对方要一份"能直接编译/直接跑"的主机侧壳子，而现在只有文档表格。

## 使用方法

**先查什么**：唯一真源是**契约文件**，它必须来自一手规范（数据手册/用户指南里的寄存器表、
接口规范里的报文与命令规格）而不是模型记忆；逐列核对偏移、复位值、方向、单位与换算式，
对不上先改契约并标红，**不许在生成物里打补丁**。契约列不齐时的处理见失效条件。
**先跟用户确认**：契约的列名与形状是否已定（改形状影响所有已有生成物）、生成物落在哪个目录、
是否允许覆盖既有文件、工程专有值（基址、系数、路径）由谁的参数文件提供。

1. **契约的形状**：机器可读（表格，或结构化文本如 JSON/YAML），**列名固定**，一列一名，
   说明写不进值里。寄存器侧至少含：名字、偏移、位域与方向（读/写/只读/读清）、复位值、
   单位与换算式、期望读回值、出处（文档 + 位置）。命令侧至少含：名字、参数与类型、响应格式、
   超时。每个数值带单位字段；每条可追到一手资料的出处。契约与生成物同一个提交走。
2. **生成物四件**：
   - 常量与位域访问辅助（偏移、掩码、移位、读改写）。
   - 按名字取地址/取字段的封装——业务代码里不许出现裸偏移。
   - 上位机脚本的命令行参数解析骨架：每条命令一个入口，含参数校验与用法串。
   - 测试骨架：**每寄存器一条、每命令一条**，含期望读回值与"读不回判 NOT_MEASURED"的分支。
3. **生成脚本的三条硬规矩**：
   1. **不许把工程专有事实写死在模板里**。基址、换算系数、器件参数、目录一律来自参数文件
      或命令行；模板里出现的专有值就是漂移的开始。
   2. **可重跑且幂等**：同一份契约两次生成必须逐字节一致。判法：生成两次，比较字节。
      不一致就无法证明"改的是契约"——你分不清变动来自契约还是生成器。
   3. **生成前后各跑一次一致性判据**：契约条目数 = 生成物条目数（常量数、测试条数、命令入口数
      分别相等）。判据必须**打印做了多少次比较**（"判 N 项"记的是比较次数，不是通过数）；
      空契约、解析失败、列读不到一律 NOT_MEASURED，不许静默通过。
4. **手工漂移检测**：把盘上的生成物按当前契约再生成一次并与之比对；不一致 ⇒ 有人改了生成物
   而没改契约 ⇒ 判红，要求把改动搬回契约再重生成。这条挂进回归门禁：改契约的提交必须在同一
   提交里带上重新生成的产物。
5. **配套条目**：可执行脚本的形状与自测见本包 scripts 类的 `contract-to-host` 条目
   （两条互相引用，本条只给范式与判据，不写路径）；三态与计数地板见 verify 类的
   `three-state-verdicts`；每条生成物声明要能指到件，写法见 templates 类的 `claims-vs-evidence`；
   生成出来的读回口上板核对走 runtime 类的 `board-liveness-readback`。

## 失效条件

- **契约缺列**（没有复位值、没有单位、没有期望读回值）⇒ 生成物对应字段只能标未核，
  **不许编默认值**。征兆：生成物里出现脚本自带的猜测常量、或同一字段每次生成值不同。
- 契约与硬件实现不一致时，生成物会**自洽地错**：条目数对账全绿，地址却是抄错的。
  一致性判据只证"同源"，不证"对硬件"——后者必须靠板上读回，不能靠生成器。
- 位域/方向的表达超出契约形状（读即清除、窗口式间接寻址、同一偏移按模式变义）⇒
  特例进了模板；特例数量一多就该改契约的列，而不是继续加分支。
- 生成物被手工打了热补丁：下次重生成会抹掉它，征兆是"改了又消失"。此时红的是流程，不是代码。

## 已验证效果

未量过，属建议——本包没有在具体工程上量过"手工维护 vs 同源生成"的漏项差。可复跑形式：
契约新增 1 条寄存器后跑重生成，看到 常量数 +1、测试条数 +1、命令入口数 +1，
且两次生成逐字节一致（比较次数按"判 N 项"打印出来），任一项不符即 FAIL。

## 来源

长自"主机侧代码与寄存器表手工双轨维护，改一处漏一处，交接时两边都对不上"这一类反复出现的观察；
专有值写死在模板里、判据只数通过不数比较，参见 pitfalls 类的 `ruler-fake-greens`；
脚本三件套（件 + 夹具 + 自测）的完整性要求参见 pitfalls 类的 `package-integrity`。
