# S24 越界的数组写与没写过的槽：xsim 给"没有"，硬件给"别的格子"

## 触发
屏上有一根**钉在固定位置**的黑线/坏线，与片源内容无关、与缩放无关、只在某一条通路上出现，
而**所有仿真都绿**。或者：某个存储型结构（行缓存、查找表、环形缓冲）的边界列行为可疑。

## 不适用
- 线会随内容/缩放移动 ⇒ 先怀疑坐标与标签同级性（S 系列里"标签与内容不同级"那一族）。
- 仿真里能复现 ⇒ 那是普通逻辑错，不需要本条。

## 动作
按这三问排，别跳步：
1. **这个数组的所有槽位都被写过吗？** 在台架里用分层引用逐槽查 X：`if (^dut.u_x.mem[i] === 1'bx) 计数`。
   必须配**复位时的对照**（一个像素都没喂时它应数到全部）——否则那个 0 只是分层引用没指到真数组。
2. **有没有越界的写？** 数"`de` 有效而写地址 ≥ 深度"的拍数。xsim 对越界数组写是**静默丢掉**，
   硬件按地址位**截断**（`addr mod 2**clog2(depth)`）⇒ 每行往同一个别的格子写一份不该在的值。
3. **越界那一拍喂进去的是什么值？** 消隐期数据通常是 0 ⇒ 硬件里就是**纯黑**；仿真里那个格子是 X 或旧值。
   这一步决定"为什么仿真看不见"。

## 完成判据
两条判据同时存在且**一条来自硬件侧的算术**：① 槽位完整性判据（改前红、改后绿）；
② 越界写计数判据（改前红、改后绿）。并且屏上位置能被公式预测出来并被人眼证实——
本项目实例：预测 `1343 mod 1024 = 319` ⇒ 读回在显示列 320，把分割标记摆在 317 后用户念回
"紧贴蓝线右侧"。**预测能被打脸的判据才算有牙**。

## 失效边界
- 器件/工具链不同，未初始化 RAM 的开机值不一定是 0（BRAM 可为 0/随机，LUTRAM 由 INIT 决定）。
- 台架若把消隐期的地址也喂成 0（而不是让它继续数），越界根本不会发生 ⇒ 判据是空转的。
  激励必须复刻真实栅格：有效列之后地址继续走到 `H_TOTAL-1`。
