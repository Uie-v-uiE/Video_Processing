# 项目整体框架大纲（主文档）

> 赛道：第八届湖南省大学生智能导航科技创新大赛 · 科技创意类  
> 定位：**应用 + 可验证方法为主，Zynq 为可选落地载体（非必要条件）**

---

## 0. 一句话

车停在停车点旁，多径把坐标拉出框 → 旧逻辑误扣调度费 → 本方案「**先判可不可信，再判围栏；不可信则不扣费**」。

---

## 1. 系统分层框架

```text
┌─────────────────────────────────────────────────────────────┐
│ L4 业务与运营                                                │
│   计费标志(OK/FEE/HOLD) · 申诉队列 · 阈值标定 · 信标复核选址   │
├─────────────────────────────────────────────────────────────┤
│ L3 围栏决策                                                  │
│   矩形/多边形包含 + 完好性门控                                 │
│   可信→判内外；不可信→HOLD 不扣费                             │
├─────────────────────────────────────────────────────────────┤
│ L2 定位与完好性                                              │
│   伪距 WLS 解算 · 残差 RMS · 剔野 · 三态(OK/可疑/拒止)         │
├─────────────────────────────────────────────────────────────┤
│ L1 观测接入 / 测试集注入                                      │
│   在线 GNSS 观测  或  数字孪生场景(多径/慢拉欺骗/拒止)         │
├─────────────────────────────────────────────────────────────┤
│ L0 部署载体（可替换）                                         │
│   量产：锁控 MCU / 模组                                       │
│   验证：PC Python · Zynq PS（本作品演示）                      │
│   扩展：路侧 RSU / 运营云                                     │
└─────────────────────────────────────────────────────────────┘
```

**原则：L2–L4 是作品本体；L0 可替换，不绑死 FPGA。**

```text

    ↓
```

## 5. 核心业务规则（必须背熟）

| 完好性 | 解算点 vs 围栏 | 动作 | 计费 |
|--------|----------------|------|------|
| 不可信（可疑/拒止） | 任意 | **HOLD** | **不扣** |
| 可信 | 框内 | OK | 不扣 |
| 可信 | 框外 | FEE | 扣 |

旧逻辑（对照）：只看解算点是否在框内 → 多径时大量误扣。

## 7. 创新点（定稿表述）

1. **应用**：把「位置是否可信」前置到扣费之前，保护用户误扣。  
2. **方法**：数字孪生测试集 + 业务指标（误扣率），而非只报坐标误差。  
3. **工程**：规则可跑在 MCU / PC / Zynq PS——**载体可替换，指标不变**。  
4. **（增强层 PLTG）可证明性**：把"可信"量化为带虚警预算的 χ² 检验与水平保护级 HPL，
   用**锁车零速先验聚窗**把 HOLD 变成可标定的"延迟定案"（实测 3 s），
   用**围栏几何作为对偶假设检验**（δ=(SSE_out−SSE_in)/σ̂²）给出"凭什么敢扣这一单"的答案，
   GNSS 不可判时**分级降级**到与卫星无关的路侧锚点测距。
   详见 `docs/创新点_PLTG_保护级感知可信围栏.md`。
5. （弱化）Zynq 作为研发验证与 RSU 原型的一种形态。

### 7.1 增强层已验证数字（10 个静止停车场景均值，`out/fence_metrics_pl.csv`）

| 策略 | 误扣 | 漏判违停 | HOLD | 自动判决 | 首次定案 | 代价/100 历元 |
|---|---|---|---|---|---|---|
| P0 旧逻辑 | 13.31% | — | 0% | 100% | 0 s | 4.84 |
| P1 三态门控（已交付） | 0.17% | 3.0% | 44.0% | 56.0% | 0 s | 1.78 |
| P2 单历元保护级（消融） | 0% | 0% | 96.5% | 3.5% | 6–22 s | 3.02 |

## 10. 演示脚本（3 分钟，含增强层）

1. 痛点 15s（误扣故事）  
2. 规则 25s（三态表：不可信就不扣费）  
3. 基线指标 30s（84%→11% / 74%→0%）  
4. **自曝短板 20s**（锁车场景 HOLD 44%、经验阈值无下界保证 → 评委必问，我们先说）  
5. **增强层 PLTG 40s**（χ² 预算门 + HPL；零速聚窗把 HOLD 变 3 s 定案；围栏作对偶假设检验；
   判不动降级到 3 个路侧锚点 → 误扣 0%、停摆 2.6%、代价 1/22）  
6. **可举证 20s**（消融：只用保护级 HOLD 96.5%；敏感性：窗口 6→40 不动；
   C 参考实现与 Python 363 历元判决 100% 一致）  
7. 边界与落地 30s（智能欺骗属射频层不承诺检出；MCU 主路径；Zynq 已验证；数字孪生非实采）
