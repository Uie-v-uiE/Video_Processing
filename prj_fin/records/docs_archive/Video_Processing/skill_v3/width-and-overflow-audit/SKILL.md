# 位宽审计：把"可枚举的边界"列全再写期望

## 适用场景

- 仿真与软件参考对不上，差异出现在最大/最小/进位那一格。
- 位宽、深度、地址步长由参数表达式推导（`clog2`、`ceil(width/2)`、`stride = w*bpp`）。
- 有人报出一个数（"偏移 0.52"、"最大 300"）要当作期望值写进台架。

## 使用方法

**先查**：接口/规范的取值范围与单位、参考实现里每一步的**舍入方向**（截断、四舍五入、向上取整三者结果不同）。
一手资料优先级＝规范表格 ＞ 参考实现源码 ＞ 教程 ＞ 记忆。**口头报出的数不是仪器读数**：
要么找到它的出处，要么标"未核"并另配一条能红的判据。
**先跟用户确认**：要不要改饱和/回绕语义（那是行为变更）、位宽加宽带来的资源代价能不能接受。

1. **列全可枚举边界**：0、1、最大值、最大值+1、进位跨界、符号位翻转、参数表达式取整的两侧。
   对每条写出"位宽/值/期望行为"三列，缺列就是没判。
2. **推导式要双向验**：写 `depth = (W+1)/2` 就同时检查 W 奇偶两侧；
   只在一侧成立而另一侧回绕，是"只在长度非对齐倍数时坏"的同一族。
3. **期望从定义来，不从现象来**：把期望写成"症状"（帧头几格必须解到第 299 行）的判据，
   会在**修好之后变红**。改写成定义式（面板像素解回源行 = 面板行 >> 1）再加覆盖地板。
4. **代理判据要先问激励能不能别名**：用"像素是黑的"判"在画面外"，而坐标标签位宽会让第 256 行标成 0 ⇒
   只在个别行/个别码上红的"缺陷"是激励自身的别名。要么让图案结构上产不出那个代理值，要么把判据窗口收到内部，
   并且**说清自己做了哪一种**——"把窗口收到绿"是失效不是修复。
5. **离线重算 RTL 算术不等于判据**：在 DUT 外复算同样的数学会造出不存在的越界（格中心 vs 索引两种口径）。
   以 RTL 自己那把双侧夹逼为准；要新判据就在台架里加，别在脚本里加。
6. **每处边界配一条能红的**：把某一位宽减 1，对应那一格必须红；不红说明它没被覆盖。

## 失效条件

- **8 位标签取模**：大分辨率下坐标回绕，测试只在某些行红。
- **X 当 0**：仿真里未写数组槽读 X，硬件读 0 ⇒ 纯黑计数器在仿真里静默漏判（要显式把 X 计成黑）。
- **舍入方向不一致**：硬件截断、参考四舍五入 ⇒ 差 1 的位置随值漂移，看起来像"偶发"。
- **把参考实现的魔数抄成规格**：参考本身若与规范不同，你固化的是 bug。
- 参数化到另一个档位（分辨率/缩放）后，原来"只测中间档"的判据一条都不覆盖边缘。

## 已验证效果

未量过，属建议：本条给的是"边界清单 + 定义式期望"的形状，具体读数属于原工程、随设计变。
可复跑的形式：任选一个参数化模块，输出边界清单表（每行 = 位宽/值/期望行为/对应判据 id）；
判据 = "清单里存在一行没有对应判据" ⇒ 红；清单为空 ⇒ `NOT_MEASURED`。

## 来源

长自三类观察：只在个别行/个别档位红的"缺陷"其实是激励别名；期望写成症状导致修好后变红；
以及离线复算造出不存在的越界。配套：`anchor-bench-before-edit`、`pynq-video-frame-pipeline`。
