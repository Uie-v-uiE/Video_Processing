# 只读探针的陷阱：空集合、错名字与自我读数

## 适用场景

- 要写一个"打开检查点读点东西"的脚本，或已经在读却读出不合理解释的数。
- 症状：命令返回 0 但什么都没发生；某类计数为 0；同一份件两次读不同；报告解析出的列整片空。
- 不适用：综合/实现本身失败的诊断（那是报告判读，见 `depth-vs-routing-cut`）。

## 使用方法

**先查**：本版本这条命令的**真实**选项与报告原文（`help` 批处理约 40 秒；报告先只读打印形状）。
一手资料优先级＝工具自身回读 ＞ 官方用户指南 ＞ 应用笔记 ＞ 教程 ＞ 记忆。
**先跟用户确认**：探针会不会打开别人正在用的检查点、会不会往交付树里写文件、能不能接受多花这 40 秒。

四条硬规矩：

1. **空集合必须有身份**：每次取对象都打印"取到几个 + 命令的 rc"。取到 0 个 ⇒ 判 `NOT_MEASURED`，
   绝不写成"没有这个问题"。属性读到空要分两种：没有这个属性、值为空——打印属性名与对象名才能分。
2. **正对照配一条**：任何"读空"的结论，都要有一条"同样的写法去读一个已知存在的对象"作对照；
   对照读空 ⇒ 是探针坏了，不是对象没有。取不到对照就明写"未配对照"。
3. **名字按路径取，取完回读核对**：过滤器写法能返回空而 `get_property NAME` 打印的正是同一串
   （详见形状表）⇒ 唯一可靠做法是按纯层次路径取，再用 `string equal` 验名字，不一致就拒绝执行下一步。
   **一个取不到的名字会让整条命令空转**，这在约束里同样成立。
4. **探针不许写进被自己扫描的树**：输出落暂存目录或包外，遍历里显式排除，并打印排除了哪些路径。
   否则报告里的字符串会被下一条判据读到，形成自指红或自指绿。

三条便宜的纪律：

5. **两次读同一份不变的件应当一致**：不一致 ⇒ 这个工具在读它自己的半初始化状态，
   据此建立的因果全部撤回（同一晚据此错过两次"根因"）。
6. **夹具要复制真实件的形状**：列数、表头、单位、分隔符、行尾、编码。手写"我以为的形状"会让
   `--self` 全绿而真实运行红——因为夹具绕过了提取层，红是断言硬编码出来的。
   做法：从真实件裁一段再脱去专有内容。
7. **报告里带单位与百分比的字段，用"原文打印 + 手工对一次"来定解析**，
   不要凭字段名猜列序（同一份报告表头与数值行的字段数可以不同）。

## 失效条件

- **`catch` 把不存在的命令变成 0**：三个不存在的查询命令被 `catch` 兜住后读出 `exc=0`，
  与"确实没有例外"无法区分 ⇒ 打印 NA 并附 rc。
- **不加 `-hier` 的全量取对象**：只返回顶层，得到"没有高扇出网"这类假干净。
- **计数对象 ≠ 计数值**：对一万个单元取某属性再去重得到"1 个"，可能只是因为该属性对每个单元都读空。
- **中文写进脚本**：工具按系统码页解码 `.tcl`，注释里的非 ASCII 也能让下一行的括号被吞 ⇒ 全文 ASCII。
- **探针写固定输出名**：会覆盖上一轮唯一的快照（先 `ls` 那个名字，问"这是谁的证据"，按 mtime 归档）。
- **把 `cmd | tail` 的退出码当 `cmd` 的**：管道后读到的是最后一个命令的状态。
- 换了工具主版本：本表每一条都要重跑才算数。

## 已验证效果

形状来自多次真实探针失败（读数随版本与设计变）：按名字过滤取网得到空集合而属性打印与之一致；
`catch` 把三条不存在的命令读成 0；同一份不变件两次读出不同数，据此撤回了两个"根因"。
可复跑的形式：任选一个探针脚本，检查它是否打印对象数、rc、属性名三件；
缺任一件 ⇒ 该探针的结论降级为 `NOT_MEASURED`。再加一条正对照：拿已知存在的对象跑同一段代码，必须非空。
