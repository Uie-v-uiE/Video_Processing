# 寄存器映射：描述符即契约，回读即凭据

## 适用场景

- 软硬件接口要定稿：哪些寄存器、什么位段、复位值多少、谁能写。
- 出现：主机侧地址常量与硬件对不上；文档写的默认档与板上默认行为不一致；读回值"看着对"但位段拼错；
  新增一个寄存器后主机侧漏改一处。
- 评审要回答"你怎么证明这个位真的写进去了"。
- 不适用：只有 AXI-Lite 手工读写、没有描述符层的工程（那只需要本条第 3、4 步）。

## 使用方法

**先查**：地址与位段以 IP 的地址映射（xsa/hwh 里的 `C_S_AXI_BASEADDR` 与 IP 数据手册）为准，**不按记忆写常量**；
描述符语法以本版本 PYNQ 的 `pynq.MMIO` / `pynq.regtools` 文档为准。
驱动寄存器地址虽有 tcl 生成器，官方原话仍要求**人工核对**——生成不等于正确。
**先跟用户确认**：谁能写这一格（PL 侧硬件写、PS 侧只读是常见形态）、复位值与"默认档"以哪份文档为准、
是否允许为了回读新增一个只读寄存器（那是 RTL 改动，要单独一轮）。

1. **先写表，再写代码**。一张 CSV/表格是唯一真源：偏移、位段、读写属性、复位值、单位、责任方、
   回读口（写完能不能读回同一个值）。没有回读口的格要显式标"不可回读"，别让它消失在表里。
2. **把表编译成描述符**，但要知道两代的描述符机制不同：
   新栈（3.x/4.0）是 `Register.create_subclass(name, fields)` / `RegisterMap.create_subclass(name, registers)`
   （普通字典：字段给 `bit_offset`/`bit_width`/`access`，寄存器给 `address_offset`/`size`）；
   旧栈教程里的 `@register_map` 加 `Scalar`/`Bits`/`Array` 类**在本包核到的新栈源码里没有**。
   重叠检查的位置也不同：新栈是在由寄存器映射生成调用签名时因重叠而报错，
   旧栈在描述符构造时 ⇒ **不要把"没报错"当成"没有重叠"**，要自己断言位段互不覆盖。
   `MMIO` 的硬性约束是实测过的：只支持 1/2/4/8 字节的读写、偏移必须是 4 的倍数、不许为负；
   8 字节读才有字节序参数。把这些当"写错就报错"的护栏，而不是当文档读。
3. **读回的形状**：`MMIO.read()` 返回按偏移/长度取到的整数或字节串，按位段取用要显式；
   IP 级 `read(offset)`/`write(offset, value)` 走的是 `mmio`，而 IP 的 `register_map` 属性
   **只在提供了 hwh 时才存在**（否则直接 `AttributeError`）——这是"换了导出方式就取不到映射"的真因。
   写代码前先打印一次可读回的键集合，与表里的名字逐条对齐，别按记忆拼。
4. **复位值不在运行时读**：本包核到的新栈寄存器模块**没有解析任何复位值字段**——
   PYNQ 不给你复位图。描述符/表里写的复位值是**你抄自 IP 文档的黄金值**，
   上电后要用回读证明它，而不是把"文档说 0x3"当成"板上是 0x3"。二者不一致是**接口缺陷**，要登记而不是解释。
5. **每一格配一次回读判别式**：写 A 读回 A（可写位）；不可写位写反值后必须不变；
   位段之间不许串（写一位，别位必须原样）。三件事一起判，才叫"这一格存在"。
   `describe()` 返回的是打印用字符串，**不能拿来程序化比对**——比对要逐字段读。
6. **两侧同源**：地址常量不许在主机代码里第二次手写。由表生成头文件/常量模块（见 `contract-to-host-bindings`），
   并加一条判据：产物里出现表里没有的地址 ⇒ 红。

## 失效条件

- **表与描述符分开维护**：改了表没改描述符，读回一切正常，判据全绿——它测的是你写错的那份。
  征兆：新增寄存器后测试数量没变。
- **把 `describe()` 当结构化读数**：字符串比对会随版本换措辞而整片红。
- **位段重叠**：`register_map` 构造时报错，但手写 `>>`/`&` 拼位的代码不报——绕开描述符就绕开了检查。
- **不可回读位被当成已验证**：只读位、硬件自增计数器的"值看着合理"不能证明写路径存在。
- **复位值口径漂移**：文档改版、IP 升级后描述符没跟着改。征兆：某一档默认值与上电实测的差，
  恰好等于文档改过的那一格。
- **拿读回当唯一判据**：读回相同不代表生效（可能是别名地址或缓存的旧值）；要结合会动的计数器/状态位。

## 已验证效果

未量过，属建议：本条按官方 `MMIO`/`regtools`/`_regmap` 文档与源码核对接口形状，未在板上实跑。
可复跑的形式（三格各跑一次）：写图案→回读→比对（可写位应等值、只读位应拒绝改变、
相邻位段应不受扰动），每条比较打印偏移/位段/期望/实得四元组；再跑一次变异对照——
故意把描述符里某一位段挪偏 1 位，三格里应恰有一格变红（若三格全绿，说明回读没有覆盖那一位段）。
