# 黄金参考比对：容差、豁免键与空集

## 适用场景

- 硬件/工具输出与软件参考逐行比；每轮都要同一把尺子。
- 症状：绿了但没人说得清比了几行；豁免加了却一条没用上；参考件其实是空的。

## 使用方法

**先查**：黄金参考是怎么产生的（谁算的、什么口径、单位是什么）——**参考错了，全绿就是错的**。
**先跟用户确认**：容差能不能放宽（那是改判据）、哪些行允许豁免（必须留名并计入读数）。

```bash
node scripts/compare.mjs <actual> <golden> [--tol N] [--exempt rules.txt]
node scripts/compare.mjs --self
```

跑完应看到四行判定 + 汇总：`C1 行数`、`C2 第 n 行`（逐条差异）、`C3 内容比对 比较=K 差异=D`、
`C4 豁免射程 键=X 命中=Y 实际挡住=Z`，最后一行 `判 N 项 红=R 未测=M <词>`。三条硬规矩：

1. **豁免按期望内容作键**（`rules.txt` 一行一条期望行子串），**不许用被测侧独有的值或信号名作键**——
   那是买通：真坏了它也不会红。
2. **豁免层要自证射程**：名单非空却一条都没用上 ⇒ `NOT_MEASURED`；用上了但一条差异都没挡住 ⇒ `FAIL`
   （它只是在旁边看着，这就是"豁免 840 条实际挡住 0 条"那一族）。
3. **任一侧为空 ⇒ `NOT_MEASURED`**，退出码 2，不许读成"一致"。行数不等是 `FAIL`，不是"少比几行"。

## 失效条件

- **数值容差按字符串比**：`1.0` 与 `1.00` 不等；本脚本只在**每行数值个数相同**时才按容差比，
  否则退回逐字——这是刻意的（防止列错位被"都在容差内"糊过去）。
- **容差用绝对值而不看量纲**：同一容差在 dB/8 与 pixel 两种单位下意思不同 ⇒ 单位写进表（见 `contract-to-host-bindings`）。
- **参考件被本轮输出覆盖**：黄金参考要有出处与只读位置，别和产物同目录同名轮换。
- **只比内容不比形状**：位段/索引判据要先证明提取层读到东西（见 `ruler-teeth-and-empty-sets` 第 3 条）。

## 已验证效果

`node scripts/compare.mjs --self` 实跑读数（退出码 0）：

```text
T1 逐字等 PASS,PASS PASS
T2 容差内 PASS,PASS PASS
T3 超容差该红 2 PASS
T4 空侧判未测 NOT_MEASURED PASS
T5 行数不等该红 FAIL PASS
T6 豁免名单没用上 NOT_MEASURED PASS
T7 豁免挡住了一条差异 PASS PASS
判 7 项 红=0 未测=0 PASS
```

夹具由脚本自己在临时目录里生成（含一条"故意超容差"、一条"豁免名单没吃到东西"、一条"空侧"），
所以这不是一次只测绿的路径。它不判"参考对不对"——那是第 0 步的出处问题。
