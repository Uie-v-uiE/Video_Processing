# 提示词：从算法描述推到软硬件划分

先给账，再给划分。模型直接给划分，就会给一个听起来合理、无法反驳也无法继承的答案。

## 适用场景

- 新题目要做软硬件划分；或评审追问"这块为什么非得进硬件"。
- 症状：结论是"通常这类算法放硬件"；片上存储与带宽没算过；延迟预算没有数字。

## 使用方法

**先查**：目标平台的可用片上存储与带宽量级（器件手册/板卡资料）、算法每一步的**数据量与访问模式**
（逐像素、可分离、需要邻域、需要全局归约）、以及接口的实时约束来自哪份规范。
**先跟用户确认**：延迟/吞吐里哪个可以让步、能不能接受多周期复用一颗算子、资源上限是硬约束还是软目标。

粘贴这段（把【】填掉；填不出来的格子就写"未知，需要先测"，不许留空当作已知）：

```text
角色：你是数字系统设计者，帮我做软硬件划分。不要直接给结论，先按下面顺序把账算完。

输入描述：【算法做什么，一步一句】
实时约束：帧率/采样率【】、每帧数据量【】、端到端延迟预算【】、抖动容忍【】
平台事实：可用片上存储【】、外部存储带宽【】、时钟与位宽【】（每条注明出处，无出处写"未核"）

要求依次输出：
1 步长表：每个运算的 输入元素数 / 输出元素数 / 访问模式（逐元素、邻域半径 r、可分离、全局归约）/ 是否含分支。
2 数据搬运账：每帧每步的字节数（含 stride 与格式对齐造成的放大），以及最坏档位的数字。
3 三类候选划分：A 全部软件；B 全部硬件；C 混合（逐步标注进硬件的理由是"带宽/延迟/并行度/确定性"里的哪一个）。
4 每个候选给出：需要的片上存储、外部带宽占用、关键路径级数下界、以及"它被什么单点失败否掉"。
5 只输出一个建议，并列出它成立所依赖的三条假设——任何一条被我否掉，结论必须重算。
禁止：没有数字的形容词（"较快""开销较小"）；引用你没取到的文档；把"通常做法"当依据。
```

## 失效条件

- 模型跳过第 1–2 步直接给划分 ⇒ 它在猜，退回重跑并把"必须先出账"写进同一句提示。
- **实时约束来源缺失**：整张表就失去意义；这类划分只能写成"该窗模型下的结论"。
- 把"可分离"当成"必然省资源"：省的是乘法次数，花的是中间缓冲——两笔账都要列。
- 三条假设一条都没被否证过 ⇒ 这张表没被用过，下一轮它会被当成事实引用。

## 已验证效果

未量过，属建议：这段提示词的"先算账再下结论"结构来自一次真实评审问答（当时答不出"这条通路每秒搬多少"），
没有做过带/不带的 A/B。可自查的形式：拿它跑一次，检查输出里有没有第 2 步的**带单位**数字表——
没有数字表就是没执行，判 `NOT_MEASURED`。

## 来源

长自两类观察：划分结论没有账支撑被评审一句话问倒；以及模型给的答案里形容词代替了数字。
配套：`external-memory-bandwidth-account`、`prompt-report-to-bottleneck`。
