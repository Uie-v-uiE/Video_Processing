# 件与树的绑定：谁 produced 谁，怎么证明

## 适用场景

- 一份报告被引用为"当前这一版的读数"，但它可能是上一轮的产物。
- 长跑构建/台架在飞，同一批源或脚本被改动。
- 交付导出器拒绝落盘时，目标目录里还留着上一版，看起来像本轮交付。
- 要把"这个位流 ↔ 这份报告 ↔ 这个提交"三者钉成一件事。

## 使用方法

**先查**：本工程有没有**自带的指纹工具**（仓库里那个脚本才是权威），以及每份报告头部写的
指纹版本号；一手资料优先级＝仓库脚本自身 ＞ 交付文档写的命令 ＞ 记忆里的命令。
**先跟用户确认**：是否允许为了绑定重跑一次长跑构建（那是整轮时间）、是否允许把中间产物改名归档（会动引用它的文档）。

1. **指纹在运行前打，不在读取时补**。让 runner 在**编译之前**把源集哈希写进旁证文件，
   门禁比对旁证与活树。"报告包装器顺手哈希当前源"是最坏的一种做法：
   昨天的日志能盖上今天的指纹，伪装成新证据。
2. **用仓库自己的指纹工具，别凭记忆抄一行命令**。一条手抄的 `find | xargs md5sum` 对行尾敏感，
   曾经据此**误判一次合法采纳需要重跑整轮**（真实差异只是 CRLF/LF）。
   报告里写的 `fpver` 决定该用哪个函数；读不到就用 ⇒ 判 `NOT_MEASURED`。
3. **产物身份由 md5 反查，不由文件名新旧**。"取最新那份 gates 报告"用 glob 排序＝按**文本序**取，
   曾让交付包带上了旧一轮的身份行。做法：按内容过滤（哪个报告点了这份产物的哈希）、
   再按 mtime 选、并把候选打印出来。
4. **构建在飞时禁改同一批源与脚本**。要么等它结束，要么在隔离拷贝树里做。
   被后台任务杀掉的进程会留下**看似挂起的日志**——先读退出码再下判断；
   停掉一个包装脚本往往**留下它自己的子进程**，要按命令行找到并确认它的工作目录 mtime 已冻结，
   否则你正在改一个活进程在读的文件。
5. **导出器拒绝落盘 ⇒ 目标目录不是本轮交付**。启动时打印"这个目录里是谁的版本（导出时间＋来源提交）"，
   任何交接语句都要引用那行头，而不是"目录存在"。空目录比"看着像的旧目录"安全。
6. **一轮记录的最小绑定**：件路径＋件时间戳＋被测对象的哈希＋产生它的命令与工具版本。
   缺任一项，下一轮就无法区分"设计变了"与"尺子换了"。
7. **资源/时序差要按模块归因再打印**，归不到就别说。扁平化的叶子模块在层次报告里**没有行** ⇒
   归到外层实例并标注"已折叠"；给出闭合式（各分项之和＝设计级差值），部分归因不算凭据。

## 失效条件

- **探针写固定输出路径**：它会覆盖上一轮唯一的快照。跑任何硬编码输出名的工具前先 `ls` 那个名字，
  问"这是谁的证据"，并先按 mtime 归档。
- **代理量取自激励**：用"像素是黑的"判"在画面外"，而坐标标签位宽会让第 256 行标成 0 ⇒
  只在个别行/个别码上红的"缺陷"其实是激励自身别名。
- **判据的原始数字没进被采纳的报告**：报告过滤器漏了那一行，则任何人都无法复核，包括你自己。
  加判据的**同一次提交**里把它的原始行加进过滤器，并回读确认那几行真在报告里。
- **把 `NOT_MEASURED` 当红**：绑定读不到时（缺指纹工具、缺旁证）应阻塞结论但不阻塞交付；
  分不清这两者会导致"为了变绿而放宽绑定"。
- **同一目录混两份版本被同时读**：产物目录要有版本子目录或身份头，不能靠 mtime 猜。

## 已验证效果

形状已在真实工程中反复生效，具体读数属于那一版工程、随设计变，不在此引用（本包不装工程专有读数）：
一次"重跑指纹工具后哈希相等"的核对**推翻**了凭记忆命令行得出的"需要重跑整轮"结论；
一次按内容而非文本序选报告，避免交付包带上旧一轮的身份行；一次固定路径探针差点覆盖上一轮唯一快照。
可复跑的形式：任选一份报告，用仓库指纹工具重算当前树哈希，与报告头对比 ⇒ 应等值；
变异对照：改一行源后重算 ⇒ 必须不等值（若仍等值，说明指纹工具没把你改的东西算进去）。

## 来源

长自四类观察：昨天的日志盖今天的指纹；按文本序"取最新"取到旧一轮；导出器拒绝后旧目录冒充交付；
固定输出路径的探针覆盖唯一快照。配套见 `build-in-flight-races`、`delivery-package-integrity`、
`board-liveness-readback`。
