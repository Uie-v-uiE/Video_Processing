# 交付包完整性：以"陌生机器上的克隆"为被测对象

## 适用场景

- 要把工程导出成一个目录/压缩包交出去，并保证别人能照着文档跑起来。
- 症状：交付文档引用了从未入库的件；剪枝名单漏了后来新增的层；包根出现中间件被算进清单。

## 使用方法

**先查**：赛事/接收方对**目录与文件命名**的硬性要求（常见为"小写字母、数字、下划线或连字符，中文只进正文"），
以及推荐目录结构——先按它落，不吻合再在 README 给目录对照说明。
**先跟用户确认**：哪些件不随包（要同行声明词）、哪些是本地留档、允许删到什么程度、
清理动作是否要先把旧包留一份镜像（防中途失败变成连环删除）。

1. **在干净检出上跑尺子**（`git worktree` 一份 HEAD）。工作树里"存在"的件，克隆后可能不存在：
   真实教训是同一把尺子在两个树上读出 688/死引用 0 与 686/死引用 7，那 7 条全是只在本机存在的证据件。
2. **剪枝与引用改写必须来自同一张表**：剪了没改口就是死链；由"被剪件清单"现生成改写规则，
   并打印"剪枝件 N 条 ⇒ 生成规则 M 条"，两个数共享来源才不会不对称。
3. **清理按形状不按名字**：中间件用 `_*` 之类的形状扫，别维护 12 个手写名字（新增的漏在外面，
   最后被算进 MANIFEST）。打印"清=N 保留=M"，保留的那个不见了要中止。
4. **受保护的目录用 KEEP 规则守**：赛题要求的层（报告目录、技能包目录）一旦进了"一次性文件"清理名单，
   就会出现"首页每一条凭据都指向不存在的目录"。
5. **脚本与产物的对应要从被调方读**：`grep` 字面路径去问"这个脚本真会产出这些件吗"会得假阴性——
   路径常是 `[file join $dir x]` 拼出来的 ⇒ 解析 `-file` 参数再与目录实际内容做集合差。
6. **导出器拒绝落盘时打印"这个目录里是谁的版本"**：旧目录比空目录更容易被误当交付。
   任何交接语句都要引用那行头，而不是"目录在那儿"。
7. **包内不许有本机绝对路径**：可执行文件与复现入口文档硬 0；叙述性文档里的绝对路径要**只剥前缀保留文件名**，
   个人目录路径既是不可复现也是隐私泄漏 ⇒ 让读者用 `git rev-parse --show-toplevel` 现取。
8. **派生件（PDF/PNG）没有尺子**：它只认源文件的话就会带着已修正的旧句出门 ⇒
   包源≤件的时间戳配对，或重跑导出并对**件的内容**复测。

## 失效条件

- 判据只数"文件里有没有提到"：条目被删光读数不动 ⇒ 数条目/带读数的行。
- 按文本序取"最新"报告（glob 顺序）：交付包带上旧一轮的身份行。按内容过滤 + mtime，并打印候选。
- 把 `!include` 写进已被整目录排除的路径：git 无法在被排除目录里再包含，声明是空的 ⇒ `git check-ignore -v` 验。
- 用一次 HTTP 抓取失败就下"文档取不到"的结论（文档站是 JS 单页，抓到的是"请启用 JavaScript"）。
- 在导出脚本正在运行时改它（后台实例读的是你刚改过的那份）⇒ 中止这一跑，别交付中途改过的脚本产出的包。

## 已验证效果

形状已在一轮真实交付里生效（计数随本轮变，不作通用结论）：干净 worktree 与主树同跑一把尺子，
差出 7 条只在本机存在的引用；按内容而非文本序选报告，避免带旧身份行。
可复跑的形式：本包自带的 `node _meta/check-package.mjs .` 会判
"每条引用的资源真在盘上""目录名纯 ASCII 小写""索引与条目现算一致"三项；
交付前把它当**其中一层**（它判包内自洽，不判整个工程的可复现性）。

## 来源

长自四类观察：交付包"点名的件不在盘上"、剪枝与改口两张表并行漂移、按名字清理漏新增中间件、
导出器拒绝后旧目录冒充交付。配套：`artifact-provenance-binding`、`doc-rotation-damage`。
