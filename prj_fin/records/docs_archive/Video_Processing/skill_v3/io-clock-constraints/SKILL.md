# I/O 与时钟约束：顺序就是判据

**未覆盖 ≠ 满足**。报告数字漂亮而约束里没有一条输入/输出窗，那笔欠账必须书面挂着，不能算收益。

## 适用场景

- 第一次为某个对外接口（源同步、并行总线、DDR）建约束；或接手一版"报告好看、约束是空的"的设计。
- `check_timing`／`report_methodology` 点名未约束端口。
- 违例数呈"差一个整周期"的镜像红绿 ⇒ 方向或沿的口径错了。
- 要声明异步时钟关系、给不确定度定口径。

## 使用方法

**先查**：外部器件的时序表（**读的是发射端还是接收端那两行；"已含内部延时"与"未含"两种行不要混**）、
板上延时/相位开关的实测档位、本版本每条命令**实际存在的选项**（用 `help` 探针量，别按记忆写）。
一手资料优先级：器件数据手册与接口规范 ＞ 应用笔记 ＞ 教程 ＞ 记忆。**取不到原文就不写数**。
**先跟用户确认**：哪些端口允许"不检查"（那是放宽，要进欠账表并在交付文档书面挂着）、
外部时序取自保密表格时是否允许引公开转述并标"未核"。

1. **只读地把现状读出来**：约束文件在综合/实现各加载了几次、时钟对象实测清单、未约束端口权威名单。
   后续每个名字都从这里抄，不从记忆里写。
2. **`create_clock` 的位置与命名**：板载振荡器从引脚进来 ⇒ 打在端口上并给 `-name`；
   综合出来的缓冲/门输出上的钟才打在内部对象上。名字决定**后续所有按名约束的射程**，改名＝一起漂移
   （见 `clock-change-constraint-reach`）。由 IP 或处理系统创建的钟**只在实现阶段存在** ⇒
   点名它们的约束要绑到不参与综合的那份约束文件。
3. **先补齐时钟检查覆盖面再谈 I/O 窗**：派生/生成时钟要么显式声明，要么用"含生成时钟"的取对象方式抓进组；
   漏了它会被当独立钟与别的域做 setup 分析，产生**假违例**。
4. **窗的数值必须与器件外部真实时序一致**（见第 0 步的两行陷阱）。建完看工具实际做的检查形状：
   setup/hold 的 Requirement 各行是从哪个沿量起的 ⇒ 据此决定 offset 挂哪条边。
5. **方向与沿语义（低自由度）**：输出窗的参考沿是**捕获端**那一只；
   **方向写反就是空约束**——把由上电计数器驱动的输出端口写成"起点"方向的例外，
   每次综合报一条 CRITICAL WARNING，不约束任何东西、只制造噪声。
   输出侧的数要来自接收端器件或接口规范的窗口条款；拿不到就**让工具继续点名那几个端口**并把这笔挂进欠账表，
   比抄一个没来历的数更负责。
6. **`-min` 与 `-max` 必须各写一条命令**（合在一条会被解析成参数过多，而报错信息**指向端口列表**，
   很容易让人去改端口名——本条曾在两条探针跑 / 12 分钟之后才定位到真因）。
7. **单向扩散量不能当双边窗**：规范里"数据与时钟对齐误差 ±X"（以及只讲 PCB 时钟走线的 skew 行）是
   **单向上限**，不是 setup/hold 窗的两个边界。把 skew 上限当窗写会造出假违例——这是**量纲错误，不是设计问题**。
   核对法：窗的上下界要来自同一对"发射端→捕获端"的界，且相加能对上规范给的半周期预算。
8. **不确定度全域统一口径**：同一检查类型（setup 或 hold）用同一条带子覆盖全部时钟；
   **一条命令一个对象，绝不并名**。口径不一致时逐域余量不是同一把尺，任何"几个域都差不多/都很紧"都不许写。
9. **异步关系用组声明**，但要知道代价：组排除把跨组路径从时序分析里拿走，CDC 报告也就不念它们 ⇒
   "CDC 报告干净"这句话的射程只剩组内。同步器那几条要另配一条有出处界值的 `set_max_delay`，
   两半齐了才叫"到达差有界"。注意：**界值叠在被排除的时钟对上通常不产生例外行**（要收窄排除范围，不是加命令）。
10. **每条命令都用报告验证它生效**（不许凭"我写了"）：组、例外、未约束名单、方法学报告各读一次。
    一个取不到的名字会让**整条命令空转**，现场只留一句 warning。

## 失效条件

- **单位口径没验时，任何"覆盖缺口 = N 个"都不可信**：工具按端口计数、方法学按检查计数、RTL 表按位计数，
  三个真实数字三个单位 ⇒ 拿一种减另一种就得到一条永远绿的假判据。必须存在**一种单位让各桶同时对上**，
  否则这一格写"我还不认识工具的计数口径"。
- 外部时序来自保密表格 ⇒ 只能引公开转述并标"未核"；此时窗数字只代表"该窗模型下的读数"。
- 新加窗让一批端点**第一次**被检查，发布门变红：那是"开始被检查"，不是"设计变差"。
  征兆＝红全集中在这几个端口、其余域逐格不动。
- 版本差异：上一版有的写法这一版可能没有 ⇒ 照抄文章示例会得到一条被拒/空转的命令。
- 组声明漏生成时钟 ⇒ 同源派生钟被当独立钟分析，出现假违例；反向漏了则跨域路径没人看。

## 已验证效果

未量过，属建议（本包不装工程专有读数）。本条里三类形状是从**多次真实失效**里抽出来的，
具体数字随设计变：窗写成 skew 上限后出现的假违例、方向反了的空约束、`-min/-max` 合并命令的报错指向错处。
可复跑的形式：建窗前后的同名检查各落一份件，**逐端口按四桶比名单而非比条数**
（裸输入／裸输出／已有例外的输入／已有例外的输出）；条数地板 ≥1，空集或解析失败判 `NOT_MEASURED`。

## 来源

长自五类观察：出货流程里没有输入/输出窗却报出好看的 hold；把单向扩散量当窗（同族两次抄错行）；
一条命令里并名一个取不到的对象导致整条组声明空转；不确定度只给一域使逐域不可比；
判据拿两种单位相减并把差值钉成常量。同族条目：改钟后覆盖面复查见 `clock-change-constraint-reach`，
命令实测差异见 `vivado-tcl-probe-traps`。
