# 哪些事先问人：授权矩阵

## 适用场景

- 即将执行：刷写板载存储、改时钟拓扑（会动别的域）、放宽或摘掉一条判据、动演示画面与讲解顺序、
  选许可证、推送到公开仓库、删除或大改工程结构。
- 症状：agent 已经把"建议"当成"授权"写进了执行计划；或反过来，把可逆的小修也拿去问，浪费一轮。

## 使用方法

**先查**：题目/需求文档与用户历史指示里**已表态**的部分（先把已授权的边界读出来，别重复问）。
**先跟用户确认**：下面矩阵里"必须问"的三列，一次问清、给选项、给代价（以用户能比较的单位：分钟、内存、风险）。

| 动作类别 | 默认 | 为什么 | 问的时候带什么 |
| --- | --- | --- | --- |
| 读硬件状态、跑只读探针 | 直接做 | 无副作用 | 结果与读数 |
| 改源码/脚本/文档并跑本地判据 | 直接做 | 可逆 | 差分与判据读数 |
| 刷写板载存储 / 上电断电操作 | **先问** | 影响板子状态、耗时、可能锁死 | 要刷哪一份、耗时、失败后果、回滚办法 |
| 为验证临时插桩（动源码） | **先问** | 容易留下一时措辞造成的失实 | 一键复原的路径 |
| 摘掉/降级一条判据、扩豁免、调阈值 | **先问** | 改的是"什么叫通过" | 影响面 + 替代方案 |
| 改演示画面、讲解顺序、外观 | **先问** | 人要直接看到 | 画面/位置的改动与理由 |
| 许可证、对外发布、推送到远端 | **先问** | 有权属含义 | 选项差异与不可撤销点 |
| 重构目录结构、批量重命名 | **先问** | 会牵动所有引用者 | 受影响的引用面清单 |
| 花钱买硬件/外设 | **先问**（而且先列现有资源） | 忽略板子已有的东西就白花钱 | 已有能力 + 候选 + 各自代价 |

**问的形状**：一句话说明要做什么、代价（时间/资源/风险）、回滚办法，然后给 2–3 个选项。
用户要的是**决定权**，不是进度报告。"可行吗/要不要照别人的开源工程重构/亮点你选几个我来选"
这类问题**只要答案，不要动手**。

## 失效条件

- **把沉默当同意**：用户没回就往下做不可逆那一步。
- **把可逆的小修也拿去问**：一轮里问 5 次会消耗信任；只问矩阵里"先问"那几行。
- **问了但没给代价**：用户无法比较，只能凭直觉点头，事后翻盘。
- **越界扩大范围**：用户问"这招管不管用"，agent 顺手改了别的层 ⇒ 窄问题就答窄问题，停止扩张审计。
- 停表纪律：夜间/截止前设了"某时刻后不再开新的长跑"的，那是**硬**边界；
  到点就把目标登记为受阻并汇报，不要重复 hold 到明早。

## 已验证效果

未量过，属建议：矩阵本身是从真实协作里被纠正出来的（刷板预授权、判据放宽要先问、
"临时插桩"造成过一处失实）。可自查的形式：任选 5 次 agent 发起的动作，
逐条判"该问的问了没 / 不该问的问了几次"，两个计数一起落件。

## 来源

长自四类被纠正的瞬间：未经确认刷板、未经确认摘判据、未经确认改演示内容、以及"顺手重构"。
配套：`round-work-loop`（第 1 步立案时就写清边界）、`doc-rotation-damage`（批量改口的风险面）。
