# 提示词：把实现报告读成"下一步做什么"

## 适用场景

- 有一堆报告文本，要回答"该动哪里"。
- 症状：每次建议都是"插寄存器"；改善与回退同时出现却只报了改善；报告被解析成整片空值而计数仍绿。

## 使用方法

**先查**：报告原文的形状（用只读探针打印一次，不靠记忆写正则，见 `depth-vs-routing-cut` 的形状表）。
**先跟用户确认**：本轮授权动哪一层（约束/RTL/流程脚本），因为有些刀动不了。

粘贴这段（连同报告原文一起给它）：

```text
任务：只做判读，不要改任何文件。按下面四问输出，每问都要引用报告里的**原文片段**（不许改写数字）。
1 分类：每条违例的主导项是什么——逻辑级数 / 布线占比 / 扇出与拥塞 / 时钟与 I/O 窗缺失 / 不确定度口径不一致？
  布线占比要从原文括号里的百分比取；取不到就写 NA，不许按 0 处理。
2 覆盖：这轮的未约束端口/未检查路径数与上一轮比是升是降？降了是因为修好了还是因为不再被检查？
  两种解释都要写，给出可区分它们的下一步读数。
3 上限：若按分类 1 的结论插拍，本条路径最多能抬多少？给出你用的数字与来源；算不出就明写"算不出"。
4 成对：改动可能伤到哪些别的域/别的资源？列"预期变好"与"可能变差"两列，缺后一列视为没做分析。
禁止：把绝对 WNS 差当收益；用"应该/预计"代替读数；引用你没看到的段落。
```

## 失效条件

- **模型没拿到原文形状**：它会把"route 81.275%"读成不存在的字段，然后整列空值仍自称绿。
  ⇒ 先跑"打印原文"这一步。
- **只做第 1 问**：没有第 2 问，约束射程丢失会被记成设计收益（本包见过表观改善的大部分来自此）。
- **第 3 问被跳过**：没有上限就开始插拍，等于没有预算就花钱。
- **把第 4 问写成"无明显回退"**：那不是成对差分，是没做。

## 已验证效果

未量过，属建议：这段提示词的形状来自真实判读失误（把射程丢失读成收益、把空值读成 0），
未做 A/B。可自查的形式：拿它跑一次，检查输出是否四问齐、第 1 问是否引用了原文百分比、
第 2 问是否给出可区分的下一步读数——三项缺任一 ⇒ 该轮判读降级为 `NOT_MEASURED`。

## 来源

长自三类观察：判读结论永远是"改 RTL"；未约束计数下降被当成改善；解析空值被当 0。
配套：`depth-vs-routing-cut`、`global-timing-roster`、`clock-change-constraint-reach`、
`vivado-tcl-probe-traps`。
