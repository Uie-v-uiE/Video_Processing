# 先分主导项：逻辑深度、布线/扇出，还是约束射程

## 适用场景

- 拿到一族违例，要在"拆锥插拍 / 复制与放置 / 改约束 / 不动"之间选一刀。
- 症状级：插了拍子 WNS 不动；复制了驱动数字不变；同一族违例的起点终点重复。
- 不适用：还没跑过任何构建（先 `start-to-first-bitstream`）；违例来自时钟/窗缺失（先 `io-clock-constraints`）。

## 使用方法

**先查**：本版本这些命令/开关**到底存不存在**——用不开设计的 `help` 批处理实测（一次约 40 秒），
比按记忆写命令便宜；报告字段用只读探针先打印**原文形状**再写解析（见 `references/command-shapes.md`）。
**先跟用户确认**：这一刀的授权范围（改结构需要功能面决策）、愿不愿意为验证开一次完整构建、
"算出上限但动不了"要不要进台账。

1. **先分主导项**。从 `report_timing` 的 `Data Path Delay` 行取逻辑/布线占比
   （占比在**括号内**，按"`route <n>ns <p>%`"写解析会永远读空而计数地板仍绿），
   再看起点终点之间的级数与进位链级数。三类结论与刀口：
   - **级数主导** ⇒ 拆锥/插拍/重定时；先算这条锥最多能抬多少（第 2 步）。
   - **布线主导**（占比很高、单条广播网占大头）⇒ 复制驱动、改放置/区域约束、降负载；改逻辑无用。
   - **约束/射程主导**（表观数字突然变好）⇒ 先走 `clock-change-constraint-reach`，那多半不是设计变好。
2. **先算收益上限，再决定要不要开构建**：上限 = 需要省下的延迟 ÷ 可插入的寄存器级数，
   并受探针能取到的最深路径限制（取到的层数受 `-max_paths` 约束，别把"只看到 4 层"当成"只有 4 层"）。
   **上限只对这一把杠杆成立**，不对整个域成立。
3. **证明机制真的动了**，再谈收益：复制出来的对象带可识别的后缀、扇出报告的行数变了、
   放置确实落进了目标区域。**机制没动就不许报"无收益"**——那叫"没测"，写 `NOT_MEASURED`。
   本版本没有把扇出当约束命令的东西，扇出清单与复制都走实现阶段的可选项（表在 `references/command-shapes.md`）。
4. **便宜的对照车道**：从已布线的检查点重跑 place+route 只要几分钟量级，
   而顶层构建是小时量级 ⇒ 用它做反事实对照（这一刀值不值得开整轮），只在采纳时才付整轮的钱。
5. **常量折叠会把逻辑压进它折进去的那一拍**：面积少了，级数可能更深。字节级一致的台架**不能**为
   "时序没变差"背书——那是两件事，要用名册量（见 `global-timing-roster`）。
6. **资源换时序要成对报**：占用与余量一起列；只带来部分收益却写成全部收益，下一轮就在假基线上加刀。

## 失效条件

- **只按绝对 slack 差决定开不开刀**：跨构建的 slack 差里混着射程与种子。
- **把"最差那条修好"当成"这一族修好"**：一族里各条的主导项可能不同，逐条分主导再逐条配刀。
- **探针归档深度当真实深度**：上限算小了，于是把一个本来能收敛的候选判死。
- **用固定延时/循环等来"验"时序**：负载变了症状就回来（与搬运侧同一条纪律）。
- **复制驱动后没读回后缀**：选项名写错时命令会**静默空转**，"无收益"其实是打字错误。
- **pblock/区域约束切断进位链**：放置器会把单元留在块外，实验从单变量变成多变量。
  要包进块就把共享进位链的模块一起包，否则别画那条边界。

## 已验证效果

形状已在真实对照中生效（数字随设计变，不在此引用）：一条占比极高、单网独占大段延迟的路被判为布线主导，
据此**没有开构建**就否掉了拆锥方案；一条多级含进位链的锥判为级数主导。两条都靠"先算上限 + 机制回读"落地。
可复跑的形式：任选一族违例，打印三条——每条的占比、级数、以及按第 2 步算出的上限；
判据 = "存在一条被归为逻辑主导但占比明显偏高的路" ⇒ 红（归类与数据矛盾）。

## 来源

长自三类观察：插拍后不动（其实是布线主导）、复制驱动后不动（选项名写错导致空转）、
以及"省了面积"被当成"时序变好"（常量折叠加深了那一级）。
配套：`references/command-shapes.md`（命令与报告形状的实测表）、`global-timing-roster`、
`vivado-tcl-probe-traps`。
