# 先在未改动的树上把判据钉住

一句话：**改之前先让新判据跑一次，跑出一个可解释的红，再动源**。
最便宜的证伪对照不是"我想象的旧代码"，而是**当前这棵树**。

## 适用场景

- 准备改一处逻辑/约束/脚本，而手上没有任何能红的判据。
- 症状：改后报告长什么样都无法区分"DUT 变了"与"期望本来就是我猜错的"；
  一条判据从来没红过；新加的台架第一次跑就绿。

## 使用方法

**先查**：被测对象的**当前**行为从代码逐行推出来（不要凭功能直觉），以及上一轮同一把尺子的位置与口径。
**先跟用户确认**：为"配一条能红的尺子"要不要多花一轮台架时间；是否允许为了变异在真件里临时插桩（须一键复原）。

1. **期望逐行从现码推**：每个判据写清"从哪个信号取、和什么比、比不过是什么后果"。
   推不出这三样就不配进门禁。历史里两次"我以为的语义"被现码否掉——那正是这条存在的理由。
2. **在**未改动**的树上跑**，把红落盘当凭据（两件一起归档：台架文件 + 那份红色读数）。
   这个红同时回答"改动前的行为是什么"和"这条判据真的能红"。
3. **第一次就跑绿的判据一律可疑**：要么激励没到达那个分支，要么期望恒真（见 `width-and-overflow-audit` 第 4 步）。
4. **改后差分用同一把尺子**：改了期望、容差或提取口径 ⇒ 与上一轮不可比，这一轮结论只能写"新基线，无对比"。
5. **一条变异只该红一条**；若一个根因合理连带红 N 条（共用提取层很常见），
   把连带写下来而不是削弱判据。
6. **长跑台架不进采纳循环**：一轮 70 分钟以上的台架只在采纳时付；
   迭代用只读探针 + 十几分钟量级的单元台架，或从检查点重跑（见 `depth-vs-routing-cut` 第 4 步）。

## 失效条件

- **"改前就红"被当成设计坏了**：先看红的落点是否与新判据无关（多半是期望推错或激励别名）。
- **打印探针当判据**：`$display`/`puts` 出来的数不会红，"它在打印"不等于"它被覆盖"。
- **判据的期望编码了症状**：修好后变红（这是同一族的第二次）。
- **零样本分支**：某个分支的样本数为 0 却判通过 ⇒ 把判断挪到一个构造上必然有样本的激励上，
  而不是降低地板。
- **控制判据初始值恒满足**：`best*4 < rows` 而 `best` 从 0 起——一个什么都没看到的检测器
  能让两条判据同时绿。写"控制必须能红"时先问：**零样本能满足它吗？**
- 长夜批次里"跑完没落件"：读数只在终端活过一轮，下一轮第一件事是重跑。

## 已验证效果

形状已被真实读数支持：一次未改动树上的红直接给出了边界值（不是人造旧码），
据此才去改那一行；同一次里一个变异合理连带红两条，按第 5 步登记而没有削弱判据。
可复跑的形式：任选一轮改动，检查盘上有没有"改前红"件、它的时间戳是否早于 diff、
判据里是否至少有 1 条本轮红过；三件齐了才算这条在被执行。
