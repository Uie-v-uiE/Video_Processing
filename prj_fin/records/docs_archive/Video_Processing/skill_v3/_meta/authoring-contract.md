# 写作契约（新增/修改条目必读，机器判据逐条对应）

## 文件形状（只有这一种，一层目录）

```
<条目名>/SKILL.md              # 目录名 == frontmatter 的 name
<条目名>/references/<一层>.md   # 超过 ~100 行的表放这里，正文只留"去哪查、什么时候查"
<条目名>/scripts/<工具>.mjs     # 必须实现 --self（能红的对照），不许有本机绝对路径
<条目名>/assets/<模板>          # kind=案例模板 必备
```

frontmatter 四个字段：`name`（≤64，hyphen-case）、`description`（≤600 字符，
以「用于」开头、含触发词、**只写什么时候用不写做法**）、`compatibility`（工具/版本/依赖）、
`metadata.kind`（赛题四型之一）与 `metadata.topic`（闭合词表：流程纪律 / 时序与约束 / RTL /
片上运行时 / PYNQ / 判据与尺子 / 验证与台架 / 速查）。

正文五节，标题**逐字**这样写（机器按标题抓节）：`适用场景`、`使用方法`、`失效条件`、`已验证效果`、`来源`。

## 硬要求（每条都对应一个能红的判据）

1. `使用方法` 必须写明**动手前先查什么**与**先跟用户确认什么**（缺任一 ⇒ 红）。
2. `失效条件` 不许空话：要写"什么情况下这条会误导你、失效前有什么征兆"。
3. `已验证效果`：**带单位的读数所在的那一行，必须同一行带普适性声明**
   （某次/量级/随设计变/不可当普适/同一设计里…）。按节判会被一句无关的话买通——上一版就是这么漏的。
   没有可复跑读数就明写「未量过，属建议」，含糊句子视为没写。
4. 通用性：不许出现绝对路径、轮次号 `rNN`、台账 `#NN`、具体器件型号、本工程专有名。
   工程专有读数属于交付文档，不属于技能包。
5. 三级加载要真被使用：`references/` 里的文件必须被正文点名，引用只允许一层，
   超 100 行的表顶部要有 `## 目录`；正文点了但不存在的件 = 红。
6. 黑话（见 README 术语表）用了就必须先在术语表里定义。
7. 每条新条目要同时做两件事：给 `symptom-router` 加一行症状，并因此自动获得一条评测用例
   （`V1` 会检查每条是否"有用例或显式登记未配"）。
