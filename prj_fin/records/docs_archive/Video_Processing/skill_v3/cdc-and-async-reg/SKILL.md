# 跨域：结构、属性与"这条判据到底看了什么"

## 适用场景

- 多时钟域、异步复位/输入进来；静态检查报出一串跨域警告，没人逐条判。
- 上板偶发单拍错值、假满假空、只在负载或温度变化时出现。
- 加了同步器却仍被方法学报告点名；或加了属性结果时序变了。

## 使用方法

**先查**：本工具的跨域检查到底读什么（属性、还是结构）、同步器需要几级与什么属性、
异步关系声明把哪些路径从分析里拿走（见 `io-clock-constraints` 第 9 步）。
一手资料优先级＝工具用户指南的方法学/属性章节 ＞ 应用笔记 ＞ 教程 ＞ 记忆。
**先跟用户确认**：能不能为了同步加一级寄存器（改延迟）、能不能新增一个只读回读口、
"某一格暂时不加同步"能不能接受并写进欠账表。

1. **先把"是否跨域"判成事实**，不要靠网名的直觉：以**驱动端与捕获端的时钟**为准，
   把每根可疑网的两端时钟打印出来；同名不同源、生成钟与原钟不同域都会被骗到。
2. **两级同步只保护单bit**：多bit 状态用格雷码/握手/异步 FIFO，别把"两级同步"套在总线上。
3. **同步属性是布局指令，不是注释**。给格雷码向量加属性之后，资源与警告计数可以完全不变，
   而设计级 WNS/WHS 一起动——"只改属性是时序中性的"是**错的**（中性的是面积与警告）。
4. **属性有没有落地要单独证**：不要用方法学计数当代理。做法是重新出一份跨域明细（读当前网表），
   并核对携带该属性的单元数从几变到几；**归档件可能是几个月前的**，必须现跑。
5. **异步声明是有代价的**：把两个域声明为异步后，跨域路径不再被时序分析，
   跨域检查也不再念它们 ⇒ "报告干净"这句话的射程只剩域内。要另配一条界值有出处的 max-delay，
   两半齐了才叫"到达差有界"。
6. **每处同步配一条能红的判据**：把同步级数抽掉一级，判据必须红；抽掉仍绿说明这条看不见它。

## 失效条件

- **只看警告条数下降**：条数取决于射程与归档新鲜度，不取决于你的改动。
- **把复位当数据同步**：异步复位释放需要同步撤除，否则恢复/撤除时间违例表现为"偶发整块错"。
- **格雷码只有一位宽**：位宽推导见 `width-and-overflow-audit`；格雷码跨域前必须先确认单调性与位序。
- **上电初值当状态用**：想靠"上电就是 0"修 bug，换实现方式（如把行缓存搬进存储块）就破。
  ⇒ 显式复位，不依赖初值。
- **同步器插在被优化掉的路径上**：综合可以把"看起来无用"的同步级合并/删除 ⇒ 要用属性或禁止优化的手段，
  并回读网表确认它们还在。
- 没有可回读状态口的工程：本条第 4 步只能写成"未验证"。

## 已验证效果

形状已核到具体机制（读数随设计变，本包不引用）：给格雷码向量加属性后，Slice LUT/寄存器/BRAM 逐字节不变、
警告清单不变，而设计级 setup/hold 都移动了 ⇒ 证实"属性=布局指令"。
可复跑的形式：任选一处同步器，做三件对照——现跑跨域明细、统计带属性的单元数、
把属性删掉再跑一次；三件都读到才算这一格有凭据，任一读不到 ⇒ `NOT_MEASURED`。

## 来源

长自三类观察：上板偶发单拍错值最后落在异步复位释放；"加了同步器"被报告计数误判为没生效；
以及把异步组声明当成"CDC 已清"。配套：`io-clock-constraints`、`clock-change-constraint-reach`、
`width-and-overflow-audit`。
