# 批量改口：一次改到位的规矩与它自带的坑

## 适用场景

- 一个术语/口径/路径要在几十上百个文件里统一。
- 症状：替换后出现半句话、表格列数变了、两个文件各挂一个数字、机械读者从此读空。

## 使用方法

**先查**：谁在**机器读**这段文本——检查器的正则、导出器的名单、按行号引用的地方。
先把这些"锚点"列出来（读它们的正则源码，不读注释）。一手资料＝尺子自己的源码 ＞ 交付文档描述 ＞ 记忆。
**先跟用户确认**：批量改写是否允许（会动到交付文档）、旧数字要不要保留在证据件里、
改写后出现的新红能不能接受。

1. **一条规则配一条断言行数/长度变化**：批量替换最容易的不是没换到，而是**多换/少换**。
   每条规则自己报告：命中数、已改口数、不命中数，三者相加要等于规则数；
   行数变化不在预期内就拒绝写盘。
2. **"已应用"分支要能数旧文**：判断"这条规则是否已经改过"要数**新文恰出现一次**；
   用"≥1 次"会让重复应用悄悄通过（本包见过同一句被写两遍留在首页）。
3. **改完回到产出件里 grep 原始 token**：残留应为 0，非 0 逐条解释（规则发出不等于规则生效）。
4. **机械读者先保住形状**：被正则读的短语要么原样保留、要么把它降级成**引用块**，
   然后同轮 grep 那条正则还能不能抓到 N≥1；抓到 0 就是这层瞎了（症状是"绿"，其实是空转）。
5. **行号引用是负债**：往文档里插 N 行会平移所有 `file.md:NN` 引用，而"范围检查"往往仍判在内 ⇒
   改写前先 grep 入站引用范围，改后要跑**产生那个数字的生成器**，别手抄派生数。
6. **被引原文不许改**：工具回显里的路径/数字是证据；只改作者自己的句子，且只剥前缀（保留文件名）。
7. **改名要扫脚本**：help 文本、错误信息、注释里的旧路径不会被文档检查器看到 ⇒
   改完要说清"我扫了哪些面"。
8. **存在性断言逐条 `test -e`**：文档写"这些件都在包里"必须逐条核；一条没中就是失实。

## 失效条件

- **把负面结果"整理"掉**：删失败项/对比表比留难看。数字、路径、失败项一个都不许被整理掉。
- **软化成模糊话**：没量过的整句承诺要拆成"每格各自带凭据"的表，不是改成"大致没问题"。
- **首页的机制句没人管**：没有任何尺子判"谁拥有这条总线""这个数在数什么" ⇒
  首页每一句架构描述要**从端口/模块头现推**，并全文扫同一主张（同一处错误常在接口表里也有一份）。
- **表格列↔行的配对**：数字全对而用途列整列错位，所有计数尺子都绿 ⇒ 配对要用第二个件独立核。
- **修好一个错就收尾**：同一主题的兄弟句要一起扫（grep 该主题的词汇表），否则下一节还有第二个同类错。
- 索引行是对目标文件的**主张**：改完任何文档要回读描述它的那几行索引，确认承诺的小标题真存在。

## 已验证效果

形状已在一轮真实批量改写中生效（计数随本轮文件变，不作通用结论）：
"命中/已改口/不命中相加＝规则数"这条挡住了重复应用；把"改前红"计数交给生成器现算，
避免了手抄派生数导致的失实。可复跑的形式：任选一次批量改写，跑
`node _meta/check-package.mjs .`（同文件重复句判据 X1）+ 第 3 步的残留 grep，两者读数一起落件。

## 来源

长自四类观察：批量替换把 README 留下重复句；改写带走了判据能读的形状；插入行平移了引用而尺子仍绿；
首页机制句在全文多处同错。配套：`ruler-teeth-and-empty-sets`、`delivery-package-integrity`。
