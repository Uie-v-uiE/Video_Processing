# 改钟之后，约束的射程会静默变窄

改时钟拓扑时，**每一条按旧钟名取对象的约束会一起停止生效**——`set_clock_uncertainty`、
`set_clock_groups`、`set_input_delay -clock`、IDELAY 参考关系——不报错、不警告、不需要你敲任何放宽命令。
于是"时序变好了"。这是本包里最容易骗过评审、也最容易骗过自己的一类失效。

## 适用场景

- 插了一个 MMCM/PLL 在原来直接吃 BUFG 的域前面；把某个钟换了源；时钟改名或重新派生。
- 症状级触发：改完 WNS/WHS 明显上移；某域的 hold 违例数突然掉了；`check_timing` 的端口欠账数变了而
  `report_methodology` 的对应类没变（**两者单位不同，不许相减**）。
- 不适用：纯逻辑改动（那走 `global-timing-roster` 的全域名册差分）。

## 使用方法

**先查**：本版本按名取对象的选项与"含生成时钟"的写法（用 `help` 探针实测，别按记忆写）；
被改对象在原约束文件里的**全部**点名处（全文按名检索，不靠记忆列）。
**先跟用户确认**：是否允许为了恢复覆盖面重跑一次完整实现（那是整轮时间）；
"这一版不作收敛说法"能不能接受。

1. **改钟的当轮，读任何 slack 之前先做覆盖名册**：把每一条按名约束（不确定度、时钟组、输入窗、
   false path、max_delay）逐条按**新对象名**重新取一次，打印取到的对象数。取到 0 个 ⇒ 该条已失效。
2. **一条命令一个对象**，绝不并名：一个取不到的名字会让**整条命令空转**，只留一句 warning。
   这也是为什么"改了钟名之后违例少了"经常是假的。
3. **派生钟要显式纳入**：用"含生成时钟"的取对象方式或逐条点名派生钟，否则派生钟被当独立钟参与分析。
4. **把"表观收益"拆成两笔账**：
   物理的（逻辑/布局/布线真的变了）与射程的（约束不再生效）。做法是**同一份已布线检查点上只改约束**
   做一次对照读数——那一步量到的差就是射程贡献。一次真实改动里，表观 +0.759 ns 中约 0.67 ns 是射程丢失
   （该数来自某一次具体改动，量级随设计变，不可当普适结论引用；但"大头往往是射程而不是物理"这件事普适）。
5. **相位归一化是另一个陷阱**：负相位的 MMCM 输出**不等于**沿提前；STA 里看到的可能是
   "换了被比较的那一对沿"。要按报告里打印的实际沿读，不要按 `phase` 数字推断。
6. **改完要留三件套**：改前的约束覆盖名册、改后的名册、两者逐条对照表（谁从"覆盖 N 个对象"变成 0）。
   缺一件，下一轮无法区分"设计变好"与"没人检查了"。

## 失效条件

- **只读 WNS 不读覆盖**：这是本条存在的全部理由。征兆＝改善集中在被重新源化的那一域，其余域逐格不动。
- **把两种端口计数相减**：一个按端口、一个按检查/引脚，得到一条永远绿的假判据。
- **用"违例条数掉了"当收敛证据**：条数取决于检查覆盖面，覆盖面掉得比违例快。
- **只改一处 XDC 却假设另一处还生效**：综合阶段与实现阶段各加载一份约束文件，
  按名约束要跟着走；只绑到其中一个阶段时，另一个阶段的读数不含它。
- **恢复覆盖后不敢看红**：重新纳入检查会让发布门变红，那是"开始被检查"而不是"设计变差"；
  此时放宽判据就是把射程第二次弄丢。

## 已验证效果

形状已在真实改动中量到（具体数字随设计变，见上面第 4 步那句的标注）：一次插入 MMCM 的改动让同一条
I/O hold 路径的不确定度项从"有"变成"没有"，表观收益的大部分由约束失效贡献；同一轮里端口欠账的
两个来源给出不同数值（单位不同），以及一个新警告类出现。
可复跑的形式：同一份已布线检查点，跑 A（当前约束）与 B（把失效的那几条按新名重新生效），
逐域打印 setup/hold 相对余量的成对差；若 B 比 A 差 ⇒ 之前的"收益"就是射程丢失，结论必须改写。

## 来源

长自一次夜间改钟的真实误判：把约束射程丢失读成设计收益，且两种端口计数被相减过一次；
同族观察是"改了 XDC 之后违例数掉了但没人解释为什么"。配套：`io-clock-constraints`（第 2、8、9 步的口径）、
`ruler-teeth-and-empty-sets`（取到 0 个对象要判 `NOT_MEASURED` 而不是"没有违例"）。
