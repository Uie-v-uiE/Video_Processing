# 与大模型协作的提示词工作流

## 适用范围

指南 3.3.3.1 允许使用大模型与智能体，3.3.5.3 要求提交“提示词、模型回答、自我纠错轨迹、
智能体工作流设计”，3.3.5.2 要求把协作经验提炼成技能包。本条目给出四段可直接粘贴的模板，
并且每段都绑定一个机器校验点：没有校验的提示词无法证明有效。

换题目、换板卡都能用：模板描述的是输入契约与输出形状，不含本队作品的模块名。

## 使用方法

### P1 算法 → 软硬件划分

```text
输入：算法描述、每秒数据量（含单位）、延迟上界、器件型号、可用端口清单（来自 .hwh）。
要求输出，按此顺序，不要复述输入：
1) 三段论：进 PL 的理由（实时性/并行/带宽/接口扩展/控制可靠性，五选一或多）、
   留在 PS 的理由、边界契约（基址、偏移、缓冲格式、完成判定、错误处理）。
2) 带宽账：需求 = 字节/帧 × 帧率 × 方向数；供给 = 端口位宽 × 时钟；写明假设与
   “这是理论峰值”。
3) 被放弃的候选方案与放弃原因。
禁止：编造端口名、地址、寄存器名；不确定就写“需要由 .hwh 取证”。
```

校验点：把输出里的数字逐条落成 `metrics.csv` 行（`spec` 用 `min:`/`max:`/`declare`），
`python3 scripts/measure_report.py metrics.csv` 会把没有来源的数字点名；地址与端口必须能
在 `python3 scripts/hwh_inspect.py design.hwh` 的输出里找到。

### P2 报告 → 瓶颈定位

```text
输入：hwh_inspect 的 JSON、综合/实现报告片段（资源、WNS、时钟）、板上实测 fps。
要求：给出至多 3 个候选瓶颈，按“最可能先修”排序，每个候选必须附一条可执行的验证命令
（tclsh/Vivado/板上 python 任一）与预期观察到的现象；无法验证的候选要写“未测”。
```

校验点：候选里出现的任何 PYNQ API 名字先过 `python3 scripts/api_lint.py draft.py`；
出现 `pynq.lib.i2c`、`pl_device_transfer`、`PartialBitstream`、`buffer.length` 这类
不存在的名字，检查器会红（见 `scripts/api_surface.json` 的 10 条否定项）。

### P3 失败诊断与一次只改一个变量

```text
输入：完整报错文本（逐字）、最后一步操作、`references/pitfall-triage.md` 表格中你怀疑的行号。
要求：症状→假设→最小实验→判定标准（何为红、何为未测），并声明这次实验只改变哪个变量。
输出末尾必须列出“本次不能证明的部分”。
```

校验点：实验结论要能被 `scripts/run_offline.py --script <复现脚本>` 或板上命令重跑；
结论写进 `evals/results/` 留痕。

提问时必须把“键名来自谁”交给模型，否则它会混用两套名字：`overlay.ip_dict[...]` 的键是
**上游**给的（`phys_addr`、`addr_range`、`registers` 以寄存器名为键，值里是
`address_offset`/`size`/`fields`），而 `scripts/hwh_inspect.py` 报告里的
`address_blocks`/`base`/列表形 `registers` 是**本工具自己的输出格式**，不是框架 API。
本包踩过的真实坑就是把工具输出当成框架字段写进板侧代码，离线全绿、上板 `KeyError`。
同理要求模型区分错误来自哪一层：属性不存在（`AttributeError`，名字是幻觉）、
驱动主动拒绝（`RuntimeError`/`MemoryError`，用法不对）、还是核内部不返回
（软件栈之外，要在 PL 侧查）。

### P4 对抗自审

```text
你是评审。请找出这段代码里最可能让它在真板上失败的三处，并按“最致命”排序；
对每处给出：触发条件、你能引用的官方文档或源码位置、修不修得起的判断。
最后单独一段回答：你不确定但怀疑的点（不许为了凑数编造引用）。
```

校验点：模型给的引用 URL 必须是 v3.1 路径（`en/v3.1/...`）；本包里
`references/sources.md` 列了已核实清单，可逐条对照。

## 失效条件

- 模型没有你的 `.hwh` 与地址表时，P1/P2 的输出只是猜测：先跑 `hwh_inspect.py` 再把
  JSON 贴进上下文。
- PYNQ 版本不同则 API 面不同（4.0 移除 Z2、删了 `pynq.lib.arduino/rpi/logictools`），
  模板里要让模型明确“按 v3.1 回答”。
- 四段模板不覆盖 Vivado 约束收敛与静态时序问题，那属于 UG901/UG904/UG949 的范围。
- 把“模型说确认无误”当作验证：本条目所有校验点都是脚本，不接受自然语言结论。

## 已验证效果

P2/P3 的形状在本包生产阶段真被使用过：错误样本集与检查规则由两个彼此看不到对方内容的
会话产生，检查器在该样本集上静态召回 9/10（唯一漏检为 TLAST，属行为层，见
`references/pitfall-triage.md`）。这批独立提问还推翻了本包的两条前提
（`recvchannel.wait()` 自身会做 invalidate；`Overlay.pr_download` 在 v3.1 仍存在），
两处已回写对应条目——这正是 P4 对抗提问要的效果。
