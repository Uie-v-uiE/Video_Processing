# .hwh fixture provenance and schema evidence

Directory: `assets/fixtures/hwh/`
Records made: **2026-10-10** (all fetches below were attempted/loaded on this date).

Files in this directory:

| File | Role |
|---|---|
| `gen_fixtures.py` | deterministic generator; run `python gen_fixtures.py` to reproduce the fixtures byte-for-byte |
| `z2_video.hwh` | PYNQ-Z2-flavoured video overlay (PS7 + `axi_dma` + `axi_gpio` + `axi_intc` + `xlconcat` + custom `video_kernel`) |
| `z2_minimal.hwh` | PYNQ-Z2, different overlay, deliberately different DMA limits (portability test) |

| `hwh_fixture_check.py` | stdlib-only contract check, prints `hwh_fixture_check: 判 <N> 项 红=<R> PASS\|FAIL` |

## 1. BOLD STATEMENT — these fixtures are SYNTHETIC

**The three `.hwh` files in this directory were NOT produced by Vivado. They are
hand-generated XML emitted by `gen_fixtures.py`. They are SYNTHETIC-BUT-
SCHEMA-FAITHFUL: every element and attribute that the skill's parser is expected
to read was taken from the official PYNQ v3.1 `.hwh` parser source (quoted
verbatim below), and the remaining names are listed in section 4 as UNCONFIRMED.
No file here may be described, in a report or a slide, as real Vivado output.
Claiming otherwise would be a fatal review finding.**

Machine-checkable honesty markers: the checker asserts each fixture's first 600
bytes contain the word `SYNTHETIC`, and the generator writes an XML comment
`<!-- SYNTHETIC fixture generated by gen_fixtures.py - not Vivado output. -->`.

## 3. Adopted vocabulary, with the evidence for each name

### 3.1 `MODULE` (the IP instance record) — CONFIRMED

`hwh_parser.py` (verbatim):

```python
self.instance2attr = {
    i.get("INSTANCE"): (i.get("FULLNAME").lstrip("/"), i.get("VLNV"),
                        i.findall("./PARAMETERS/*[@NAME][@VALUE]"),
                        i.findall(".//REGISTERS/*[@NAME]"), i.get("BDTYPE"))
    for i in self.root.iter("MODULE")}
...
for mod in self.root.iter("MODULE"):
    mod_type = mod.get("MODTYPE")
    full_path = mod.get("FULLNAME").lstrip("/")
```

Adopted attribute set on `<MODULE>`: `INSTANCE`, `FULLNAME` (leading `/`),
`VLNV`, `MODTYPE`, `BDTYPE`. Confirmed `MODTYPE` string values:
`processing_system7`, `zynq_ultra_ps_e`, `versal_cips`, `axi_intc`, `xlconcat`.
`BDTYPE` values seen in code: `BLOCK_CONTAINER`, `RBD` (fixtures omit `BDTYPE`,
which the parser tolerates: `bdtype != "BLOCK_CONTAINER"` holds for `None`).

### 3.2 `PARAMETERS` / clock parameters — CONFIRMED

`findall("./PARAMETERS/*[@NAME][@VALUE]")` — child tag name is a **wildcard**, so
the fixtures use `PARAM` (see UNCONFIRMED U1). Confirmed `NAME` values:
`PCW_FPGA_FCLK{0-3}_ENABLE`, `PCW_FCLK{n}_PERIPHERAL_DIVISOR{0,1}`,
`PSU__FPGA_PL{n}_ENABLE`, `PSU__CRL_APB__PL{n}_REF_CTRL__DIVISOR{0,1}`,
`NUM_PORTS` (xlconcat), `DIN_FROM` (GPIO), `ENABLE_DFX`.

### 3.3 `MEMRANGE` — CONFIRMED (and this, not SEGMENT, is what PYNQ reads)

```python
for i in mod.iter("MEMRANGE"):
    if i.get("INSTANCE") in self.instance2attr:
        intf_id = i.get(mem_intf_id)          # "SLAVEBUSINTERFACE" / "MASTERBUSINTERFACE"
        high_addr = int(i.get("HIGHVALUE"), 16)
        base_addr = int(i.get("BASEVALUE"), 16)
        addr_range = high_addr - base_addr + 1
        self.ip_dict[...]["memtype"] = i.get("MEMTYPE", None)
```

Confirmed: `INSTANCE`, `BASEVALUE`, `HIGHVALUE` (absolute, `0x` hex, base <= high),
`SLAVEBUSINTERFACE`, `MASTERBUSINTERFACE`, `MEMTYPE` in {`REGISTER`, `MEMORY`}.
`MEMRANGE`s are placed **inside the PS `MODULE`** for full designs and additionally
at top level inside `MEMINST` for partial designs
(`init_partial_ip_dict()` → `_parse_ip_dict(self.root, "MASTERBUSINTERFACE")`).

From `hwh_frontend.py` (verbatim): `port.baseaddr = int(i.get("BASEVALUE"), 16)`,
`port.range = (int(i.get("HIGHVALUE"), 16) - port.baseaddr) + 1`,
`for addrblock in i.iter("ADDRESSBLOCK")`, `_memrange_bounds(mem)`.

### 3.4 registers / fields — CONFIRMED (`PROPERTY` children, not attributes)

```python
j.findall(".//REGISTERS/*[@NAME]")
j.find('./PROPERTY/[@NAME="ADDRESS_OFFSET"]').get("VALUE")
j.find('./PROPERTY/[@NAME="SIZE"]')
j.find('./PROPERTY/[@NAME="ACCESS"]')
j.find('./PROPERTY/[@NAME="DESCRIPTION"]')
{k.get("NAME"): {...} for k in j.findall("./FIELDS/FIELD/[@NAME]")}
k.find('./PROPERTY/[@NAME="BIT_OFFSET"]')
k.find('./PROPERTY/[@NAME="BIT_WIDTH"]')
```

`hwh_frontend.py` adds `IS_ENABLED` to the same property list. So the fixtures
emit `<REGISTERS><REGISTER NAME=..><PROPERTY NAME="ADDRESS_OFFSET|SIZE|ACCESS|IS_ENABLED|DESCRIPTION"/><FIELDS><FIELD NAME=..><PROPERTY NAME="BIT_OFFSET|BIT_WIDTH|ACCESS|DESCRIPTION"/>`,
nested inside `ADDRESSBLOCK` (per `hwh_frontend`: `addrblock.iter("REGISTER")`).

### 3.5 DMA limits — CONFIRMED, and they fix the fixture constants

`pynq/lib/dma.py` v3.1, verbatim:

```python
if "c_sg_length_width" in description["parameters"]:
    self.buffer_max_size = 1 << int(
        description["parameters"]["c_sg_length_width"]
    )
else:
    self.buffer_max_size = 1 << MAX_C_SG_LENGTH_WIDTH

self.buffer_max_size -= 1
...
data_width = (
    int(self.description["parameters"]["c_m_axi_mm2s_data_width"]) >> 3
```

* `max transfer = (1 << C_SG_LENGTH_WIDTH) - 1` → `z2_video` 14 → **16383**,
  `z2_minimal` 23 → **8388607**, `alt_board` 26 → **67108863**.
* `alignment bytes = C_M_AXI_*_DATA_WIDTH >> 3` → 32→**4**, 64→**8**, 128→**16**.
* other confirmed DMA parameter names: `c_include_sg`, `c_include_mm2s`,
  `c_include_s2mm`, `c_micro_dma`, `c_mm2s_burst_size`, `c_addr_width`,
  `c_s_axi_lite_addr_width`. `bindto = ["xilinx.com:ip:axi_dma:7.1"]` (VLNV).
* `xilinx.com:ip:axi_dma:7.1` also appears in the real-parsed golden dict.

### 3.6 nets / ports / GPIO / interrupts — CONFIRMED

`PORT` with `NAME`, `SIGNAME`, `DIR` (`'I'`/`'O'`); `root.find("./EXTERNALPORTS")`
with `PORT` children; `CONNECTION` carrying `INSTANCE`, `PORT` (plus `NAME`,
`LOGICAL`, `PHYSICAL`, `CONNTYPE` from `hwh_frontend`); nested `PARAMETERS` with
`DIN_FROM`; PS port names `IRQ_F2P` (Zynq), `pl_ps_irq0`/`pl_ps_irq1` (ZynqMP),
`GPIO_O`, `emio_gpio_o`, `GPIO_0`; IP port names `irq`, `dout`, `In0..InN`.
`SIGIS` appears in the `hwh_frontend` attribute list; its values (`CLK`, `RST`,
`INTR`, `UINT`) are conventional (see U6).

## 4. UNCONFIRMED list (used anyway, kept self-consistent)
- **U14** `PORT@FREQ` / `PORT@PORTTYPE="CLK"` / `PORT@HAS_CLOCK` as a clock-frequency
  source: not present in `hwh_parser.py@v3.1`; kept only as a fallback and listed here as
  unconfirmed.
- **U15** `PCW_ACT_FPGA<n>_PERIPHERAL_FREQMHZ` as the FCLK frequency key: this name is seen
  in real Vivado-generated `base.tcl`/preset output, not in `hwh_parser.py`, so treat it as
  conventionally-named rather than parser-confirmed.

Because no real Vivado `.hwh` text could be loaded (section 2), the following
names are **not evidence-backed**. Each is either ignored by the official PYNQ
parser or mirrored from a confirmed name, so the fixtures stay self-consistent:

- **U1 `PARAM`** as the element name inside `PARAMETERS`. The parser uses the
  wildcard `*[@NAME][@VALUE]`, so any name parses; `PARAM` is Vivado convention, unverified.
- **U2 `SEGMENT` and its `BASEADDR` / `HIGHADDR` / `HIGHADDRNAME` / `ISVALID` /
  `OFFSET` / `RANGE` / `STARTVALUE` / `BASEVALUE` / `HIGHVALUE` / `NAME`
  attributes.** Neither official parser reads them. They are emitted because
  the skill's own tool contract requires `SEGMENT@BASEADDR/@HIGHADDR`, and each
  SEGMENT's base/high is **byte-identical to the corresponding confirmed
  `MEMRANGE@BASEVALUE/@HIGHVALUE`** so no contradiction exists in the file.
- **U3 `MEMINST`, `MODELS`/`MODEL`, `MODELPORTS`/`MODELPORT`, `NETS`/`NET`,
  `MODINST`, `MODELPORT`, `MEMINTERFACE(S)`** — structural dressing requested by
  the brief or implied by it; not read by `hwh_parser.py` (nets come from
  `PORT@SIGNAME`, not from `NET` elements).
- **U4 the root element name `ROOT` and its attributes** (`Design`, `ARCH`,
  `DEVICE`, `PKG`, `SPEEDGRADE`) and `SYSTEMINFO` attributes — the parser only
  does `root.find("./EXTERNALPORTS")`, never checks the tag.
- **U5 `MODULE` extra attributes** `HWNAME`, `NAME`, `TYPE="IP"`, `TAG`, `DESC`,
  `PARAMETERS="TRUE"`; and `ADDRESSBLOCK` attributes `INTERFACE`, `NAME`; and the
  `MEMRANGE@ADDRESSBLOCK` attribute.
- **U6 `PORT` attributes** `CLK="TRUE|FALSE"`, `CLKRATE` (deliberately **not**
  emitted — the 100 MHz is expressed the official way, through PS clock
  `PARAMETERS`), `WIDTH`, `LEFT`, `RIGHT`, `TRISTEDGE`, `PHYSICAL`, `MODE`, and
  `SIGIS` values.
- **U7 `MODTYPE` values `axi_dma`, `axi_gpio`, `axis_switch`, `proc_sys_reset`,
  and the custom `video_kernel` / `pixel_stats` / `scaler`** — only
  `processing_system7`, `axi_intc`, `xlconcat`, `zynq_ultra_ps_e`, `versal_cips`
  are confirmed. `axi_gpio`/`axis_switch` VLNV version suffixes
  (`:2.0`, `:1.1`), `processing_system7:5.5`, `axi_intc:4.1`,
  `zynq_ultra_ps_e:3.4`, `xlconcat:2.1` are plausible, unverified.
- **U8 `C_S_AXIS_DATA_WIDTH` / `C_M_AXIS_DATA_WIDTH`** as parameter names — the
  brief asks for them; PYNQ's own alignment code actually reads
  `c_m_axi_mm2s_data_width` / `c_m_axi_s2mm_data_width`, so the fixtures carry
  **both spellings with the same value** (4/8/16-byte alignment agrees either way).
- **U9 custom-IP VLNV prefix** `user.com:pynq_video:video_kernel:1.0` (and
  `user.com:hls:scaler:1.0`, `user.com:pynq_video:pixel_stats:1.0`).
- **U10 `ACCESS` value spelling** `read-write` / `read-only`; PYNQ copies the
  string verbatim, so the exact Vivado token is unverified.
- **U11 memory ranges**: `MEMRANGE@INSTANCE` for the PS DDR controller
  (`processing_system7_0_ddr_nmemic`, `ddr4_0`) does not resolve to a `MODULE`;
  tolerated by the checker because `hwh_parser` skips unresolved instances.
- **U12 parameter key case**: `dma.py` looks up lowercase keys
  (`c_sg_length_width`) while the real-parsed golden dict shows uppercase
  (`C_S_AXI_LITE_ADDR_WIDTH`). The lower-casing site could not be read (no
  `xsa.py` at that ref). The fixtures keep **uppercase**, matching the observed
  real `.hwh` output; the skill's parser must case-fold, and `hwh_fixture_check.py`
  does exactly that, which doubles as the reminder.
- **U13 the FCLK frequency formula** (`1000 MHz / (DIVISOR0 * DIVISOR1)`) used by
  the checker to call `z2_video` a 100 MHz design — plausible but not verified
  against PYNQ's `Clocks` class.

## 5. Reproduce and verify

```sh
cd assets/fixtures/hwh
python gen_fixtures.py        # 3 well-formed fixtures, byte-stable across runs
python hwh_fixture_check.py   # 判 87 项 红=0 PASS, exit 0
```

`hwh_fixture_check.py` (stdlib only) asserts, per file: (a) `ElementTree` parses
and re-parses to the same root; (b) an `ADDRESSBLOCK`/`SEGMENT` with both
`BASEADDR` and `HIGHADDR`, whose values match a `MEMRANGE`; (c) an instance with
`REGISTERS` → `REGISTER@ADDRESS_OFFSET` and a `FIELD` with `BIT_OFFSET` +
`BIT_WIDTH`; (d) the `axi_dma` `PARAM` constants and the PYNQ-derived max size /
alignment; (e) the two Z2 files disagree on `C_SG_LENGTH_WIDTH` **and**
`C_S_AXIS_DATA_WIDTH` while sharing the same board family; (f) `alt_board.hwh`
contains no `0x40000000` anywhere, keeps every register window at
`>= 0x80000000`, and shares no address segment with the Z2 fixtures. It also
re-checks the official `hwh_parser` expressions (`MODULE@INSTANCE` ↔
`MEMRANGE@INSTANCE`, `PARAMETERS/*[@NAME][@VALUE]`, `EXTERNALPORTS`) so the
fixtures are exercised through the same XML paths a real overlay would use.
