# S05 · 验证、观测与故障注入

## 1 负责什么

把“功能看起来对”变成“判据能红、红了能定位、绿了能复现”。模型写台架、故障注入和遥测解析；人定判据和验收口径。

## 2 模型做了什么

- 为接收链、显示链、几何、效果级、OSD、CDC 写单元与集成台架。
- 把帧提交、竖缝、行标签、校验和、帧间隔做成可打印判定行的专项。
- 写三阶段自检：干净流 → 每 100 包丢 1 包 → 干净流，用每秒变化量判，不用绝对值。
- 写 `link` / `link clr` 的串口读数和遥测解析。

## 3 人拍板的部分

- 每条判据必须先有能红的反例；第一次跑就绿要查激励是否为空集。
- 三态判定：PASS、FAIL、NOT_MEASURED；读不到输入不等于通过。
- 板上自检只认每秒变化量，避免把启动时的作废算进故障段。
- 仪表要能被人为破坏打红，不能只会显示好看的数。

## 4 修正

- 台架曾出现“判据全绿但设计没被覆盖”的假绿：激励只跑了单个窗口或空样本。后来给每条判据加覆盖计数和反例，C22/C31 都保留改前红、改后绿的读数。
- 模型的初版自检用绝对帧率，启动瞬态会把故障段判成通过。改成每秒 `frames`/`aborts` 的 delta 后，故障段读到 0 fps、14.3 次作废每秒。
- `cmd_link` 函数存在但没有接进 `dispatch`，板上敲 `link` 回“不认”。接回分派和帮助行后，`[LINK]` 能读 `stall`、`gap_last/min/max/sum`、`gap_valid`、`live`。

## 5 结果

19 支标准回归 `fail=0`；完整视频台架 C17/C25/C26 专项 PASS。板上 8 秒推流 241 帧、29.95 fps；三阶段自检 22.0 / 0 / 18.9 fps；105 条串口命令电池 PASS；`gap_max=22 061 ms`。
