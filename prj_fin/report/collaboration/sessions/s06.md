# S06 · 上板、固化与交付

## 1 负责什么

把工程从“功能可用”推进到“可提交”：QSPI 启动、冷启动复验、目录重构、文档与海报、GitHub 主分支。模型做装配和检查，人做上电、断电和人眼验收。

## 2 模型做了什么

- 用 TCL 重建 `board/vivado` 工程，把源文件路径改成 `$PPRDIR/../../src/...`，检查缺失文件和绝对路径。
- 把 Vitis 平台描述放进 `board/vitis`，把构建脚本集中到 `build/`。
- 重写 README、设计报告、验证、优化、复现、局限和技能包索引；技术文档与海报留在本地 `deliverables/`。
- 打包 QSPI 镜像，检查 bootgen 日志里的 `[ERROR]` 和成功行，生成三件套哈希。

## 3 人拍板的部分

- 断电重上是唯一可信的启动验收；JTAG 下载只影响当前上电周期。
- 串口、网络、遥测、自检、温度和串口电池分开记录，不把“台架绿”写成“板上也绿”。
- 技术文档和海报不随 GitHub 提交；评委拿到的是本地交付件和 FIN 包。
- 最终包只保留源码、台架、报告、工程和一手证据，旧构建物不进提交面。

## 4 修正

- bootgen 在输入缺失时也可能返回 0，旧 `BOOT.bin` 会让“成功”变成假绿。打包脚本改成生成前删旧镜像，并检查日志里的 `[ERROR]` 和成功行。
- `board/vivado` 曾缺 BD wrapper：工程能打开，综合时找不到 `design_1_wrapper`。现在 wrapper 随工程放在 `.srcs` 内，干净副本的综合已验证到 100%。
- `BOOT.bin` 的 BIF 曾指向包外的旧 Vitis 工作区。现在 FSBL 随包放在 `board/flash/fsbl.elf`，BIF 用同目录相对路径，重打后的镜像 MD5 与原镜像一致。
- 复现脚本的 BSP/PS_OUT 路径曾因目录移动而错位；现在脚本先找 `board/vitis_ws`，再退回旧工作区，并把相对 `PS_OUT` 规范成绝对路径。

## 5 结果

QSPI 冷启动 `DONE=1`、`EOS=1`、无 CRC/IDCODE 错误，串口 `stat`/`link` 有回显，ping 5/5；健康快照 `HEALTH: GREEN`；8 秒推流 241 帧、29.95 fps。
