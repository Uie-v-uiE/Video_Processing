name: failing-read-prints-geometry
description: 让失败分支自己报出几何量，从而把"定点的数据缺陷"从"偶发/环境"里分出来：当一个操作在固定位置反复失败（同一帧号、同一行号、同一序号、同一通道）而错误信息只有"读失败 / 超时 / 不工作"一句、或当你正准备把它解释成时间方向的因头（并发挤的、控制器忙、时钟被拉慢、时序不稳）时用它。打印要一次给足四类量——访问的位置、这位置怎么来的、合法边界、当场算出的分类（`IN-RANGE` / `OUT-OF-RANGE`）；RTL 台架里同一招是让被测对象报出它那一拍的坐标。
---

## 1. 一句话用途

失败时先让它报出自己的位置。

## 2. 适用场景

- 当一个操作**在固定位置**反复失败（同一帧号、同一行号、同一序号、同一通道），而错误信息只有一句"读失败 / 超时 / 不工作"时。
- 当你正准备把这种失败解释成**时间方向**的因头（并发挤的、控制器忙、时钟被拉慢、时序不稳）时——这类解释不需要任何新证据就能自圆其说，正是本条要拦的。
- 当一个判据涉及"第几拍 / 第几格"，而你能推出好几套都说得通的解释时。
- 当几个模块各自猜同一个对齐量、已经猜出好几版结论时。

## 3. 不适用 / 失效条件

- 不适用：失败**不定点**（同一操作在不同位置随机失败）——打印几何量仍然有用，但结论方向要换回时间 / 电源 / 时序。
- 不适用：打印本身要走那条已经坏掉的通路（例如打印前要先读同一个设备）——这时只能打到主机侧日志，或预先攒在内存里事后导出。
- 不适用：现象本身能被一条命令判（那不是"看一眼"的活，也不是本条）——先去补判据，见 `skill/pitfalls/criterion-blind-spot/SKILL.md`（旧编号 S21）。
- 失效：现场量太多会被串口缓冲截断——乱码输出不算输出，**判据文件要整份读完**再下结论。
- 失效：边界值算错会让分类骗人（边界要从分区/固件参数读，不要假设容量）——所以第 2 步要把来源量一起打。
- 失效：判据的**输出本身坏掉**时（例如打印用了不支持的格式符，糊成一串），它的红与绿都不算证据（同族在 `skill/references/bench-self-inflicted-reds/SKILL.md`，旧编号 S20）。
- 分界：本条管"失败时打什么"；"整条流丢没丢字"的取证图案在 `skill/pitfalls/frameid-loss-signature/SKILL.md`（旧编号 S9）。

## 4. 前置条件

- 一条能复现的失败（同一位置至少两次），且你有办法做**定点跳帧**式的探测（指名要第 N 格 / 第 N 帧 / 第 N 行）。
- 打印通路：主机侧日志或串口；知道该通路的缓冲上限，超出就会截断。
- 合法边界的**来源**（分区末尾、缓冲区容量、数组长度）能从参数或结构里读到，而不是从手册里抄。
- RTL 侧要能用**分层引用**读各模块内部那个对齐量（本仓写法 `^dut.<路径>.<寄存器>`，示例取值，需按自身工程替换）。
- 允许"把缺陷改回去重下一版"来做反例；本条目不替你构建或上板。

## 5. 使用方法

1. **在失败分支上至少打四类量，一条就够判**：① 它试图访问的位置（LBA / 指针 / 数组下标 / 寄存器地址）；② 这个位置**怎么来的**（上游中间量，如簇号、偏移、行号）；③ 合法边界（分区末尾、缓冲区容量、数组长度）—— 别让人去查手册；④ 一个当场算出的分类（`IN-RANGE` / `OUT-OF-RANGE`）。
   完成后应看到：失败时一行里四个量齐全，且分类与前面三个数自洽。
2. **写成一行、只在失败时才打**（成功路径零开销）。把边界**和它的来源量**一起打出来，让人能复核那个分类，而不是只能信它。
   完成后应看到：正常路径不打印；失败行里能同时读出"边界值 + 算出它的那个数"。
3. **给判据自己配一个反例**：加了检查就要证明它能红——把缺陷改回去重下一版，看它是否报警（本仓库是一次真实的"字节序改回去 → 挂载被拒"）。
   完成后应看到：缺陷态必报警、修复态必安静，两个方向都看过。
4. **定点性先确认再归因**：同一位置复现两次以上 + 一次定点跳帧（N 好 / N+1 坏）之后，才允许写"偶发"或"竞态"。
   完成后应看到：两份独立长跑落在同一位置，以及一对相邻位置的成败对照。
5. **RTL 台架里的同一招**：只要判据涉及"第几拍 / 第几格"，就让**被测对象自己报出它那一拍的坐标**——分层引用各模块内部那个对齐量、打印出来（本项目四处引用把"三个模块猜了三版"一句话裁决成"滞后 = 3 个有效像素"）。
   完成后应看到：一行按模块列出的坐标读数，替代一整段关于"到底谁晚了几拍"的争论。有多套合理解释时，打印一次的代价远低于再猜一轮，而且打印结果能被下一个人复核，推断不行。

## 6. 判读与失败分叉

- 第 1 步：通过 = 那一行能**同时锁死因果链**：位置、来历、边界、分类四者自洽，且把打印值套回换算式能精确复现出访问位置。
  失败 = 四者不自洽（分类说越界而换算回来其实在界内）⇒ 分类算错了，先修第 3 步的边界来源，别急着定因头。
  读不到输入 = 那一行被截断/糊成一串 ⇒ `NOT_MEASURED`：乱码不算输出，先确认串口缓冲与格式符，再重打一次；这条判据的输出坏掉时，它的红与绿都不算证据。
- 第 2 步：通过 = 成功路径零开销、失败路径一行给全。
  失败 = 只在失败时打但缺"边界来源量"⇒ 别人只能信你的分类，复核不了；判 `FAIL`，补一个数。
- 第 3 步：通过 = 改回缺陷必报警、改回来必安静。
  失败 = 缺陷态它不响 ⇒ 这条检查是摆设（没牙），判 `FAIL`；先修检查再谈"修好了没有"。
  读不到输入 = 没有第二版件可比 ⇒ `NOT_MEASURED`，不许把"没测到异常"写成"已验证"。
- 第 4 步：通过 = 至少两次同位置复现 + 一次 N/N+1 定点对照。
  失败 = 只复现一次就写"偶发/竞态"⇒ 归因无效，判 `FAIL`，回到第 1 步补打印。
  次生现象要认出来：一次读失败之后驱动/控制器留在那次未完成的传输里，后面每一次操作都会失败并报成另一种错（例如"文件找不到"）——那是尸体，不是病因。
- 第 5 步：通过 = 各模块报出的坐标彼此一致、并与几何算式对得上 ⇒ 一句话裁决"差几格"。
  失败 = 各模块报不同值 ⇒ 找到的是分歧而不是错，按模块归属继续拆；不许用平均值糊过去。
  读不到输入 = 分层引用指不到那个量 ⇒ `NOT_MEASURED`，先确认名字与层级还在原位。

## 7. 已验证的效果

以下都是历史轮次的台账读数（`report/log/ISSUES.md` #50 与 #54 两节）。本轮（技能包重构轮）**没有重下固件、没有上板、没有跑台架** ⇒ "现在重跑仍得同一组数"记 `【待验证】`；台账里点名的那些串口原始件本条目不重复列路径（本轮未逐一打开确认它们还在）。

- 定点性（#50）：两次独立长跑都停在**同一帧号 3584**，而 `3584 = 7 × 512`（每个文件 512 帧 ⇒ 第 8 个文件的第一帧）；定点跳帧探测 `FRAME3583` 成功、`FRAME3584` 失败，之后的全都报成"找不到文件"（次生现象）。⇒ 这一步把结论从"并发偶发超时"改成"可定点复现的坏点"。
- 那一行几何打印（#50，加上四类量之后一次 `FRAME3584` 就出结论）：
  `[SDRD!] lba=536959104 n=32 clus=16778886 part_end=62332928 OUT-OF-RANGE (data_lba=34816 spc=32 ...)`
- 四者自洽的复算（#50）：读到的簇号 `16778886 = 0x01000686`（高字是 `0x0100`），把高字两个字节换回来是 `0x00010686 = 67206`，而按连续布局预测的首簇是 67205 ⇒ **只差 1 个簇**；用错簇号算出的 LBA `34816 + (16778886−2)×32 = 536959104` 与打印值**逐位相同** ⇒ 从目录项到 LBA 这条链被完整证实；分区末尾 62332928（32 GB 卡）⇒ 这个 LBA 根本不存在，卡拒绝命令是**正确行为**。根因是目录项里那个 16 位小端字被按大端拼了。
- 位置选择性（#50，本条反例的理论支点）：首簇 < 65536 时高字是 0，**怎么拼都是 0** ⇒ 前 7 个文件全对；65536 簇 × 16 KiB 恰好 1 GiB，所以第一个"起点落在数据区 1 GiB 之后"的文件才发作。这种只在某个数据位置之后才发作的选择性，任何基于时间（并发/控制器/时序）的假设都解释不了 ⇒ 是数据缺陷的签名。
- 判据能红也能绿（#50 第四步，用户定的规矩）：固件内一条合成目录项自检 + "旧写法必须给出 16778886 且与新写法不同"的断言（否则判据只是把实现照抄一遍），挂载前硬门；把字节序改回去重下一份 ⇒ 挂载直接失败并明说 `autoplay: mount failed: cluster decode SELF-TEST failed (firmware bug, not the card)`，改回来 ⇒ 打印 `dir map ok: 9 files, first clusters within 1946818`（每个片源文件的首簇都量一遍并对分区上界核对）。
- 修复后的板上读数（#50）：一次纯串口长跑里帧窗 3500 → 3600 → … → 4300 一路 29.2–30.0 fps，**跨过 3584 没有任何失败行**，播到 4398 帧后自动回绕 ⇒ 这张卡第一次整卡播完；同一份件在 30 fps 推流并发下连续监听 165 s 也全程 29.2–30.0 fps、跨 3584 零失败（旧固件在这条工况下必停——也正是最初让人误判成"并发挤的"的那条工况）。口径注意：这只证明**读取路径**在并发下不再停，"屏幕上此刻显示哪一路"是另一把尺子。
- "整份读完"这条纪律的来源（#50 自记的三次误判之一）：看到 shell 乱码输出就当成那份抓取里有停止行，于是引用了一条**根本不存在的证据**（frame 2736）；发现方式很简单——用读工具把那份 25 行的文件整份读一遍。
- RTL 台架那一招（#54）：让台架回读四个模块"发出槽位 0 那一拍"的列号，**四个都报 3** ⇒ 正确深度 = 行缓存读 + 窗口移位 + 输出寄存 = **3 个有效像素**；同一改动让六个台架同时全绿——两个互相矛盾的判据被同一个解释同时安抚，说明找到的不是"让某个测试过关的补丁"，而是对齐本身。

## 8. 提炼来源与边界

- 台账出处（逐字保留）：`report/log/ISSUES.md` #50 与 #54。
- 相关条目：判据"结构性红不了"（本条第 3 步的反例思路）在 `skill/pitfalls/criterion-blind-spot/SKILL.md`；假红/输出本身坏掉在 `skill/references/bench-self-inflicted-reds/SKILL.md`；丢字取证在 `skill/pitfalls/frameid-loss-signature/SKILL.md`。
- 不再适用的条件：失败已经被一条现成命令判死（不需要打印几何量）；或打印通路就是坏掉的那条（先解决"打到哪儿"）。
- 迁移到新题目/新工程要改的地方：① 四类量的具体名字（本仓是 LBA / 簇号 / 分区末尾 / 分类；换设备就换成指针、容量、边界、分类）；② 定点跳帧的探测手段（要能指名第 N 格）；③ 反例那一版怎么下（换固件要能重下一版，换 RTL 要能机械复原缺陷态）；④ 串口/日志缓冲的截断上限（决定一次能打几个量）。
- 工具行为断言与来源行另见 `skill/pitfalls/_proposed-sources.md`（本目录不写 `_meta/`）。
- 平台相关：本条与器件/工具版本无关，只与"失败分支能不能打印"有关；裸机侧注意格式化输出对不支持的格式符会糊（属 §3 最后一条失效）。
