## 1. 一句话用途

分时读口先算两道算术题。

## 2. 适用场景

- 当你想在不加 RAM 的前提下，把一个 1 读/1 写存储器的读口供多个消费者用，而片上有一个 N 倍于工作时钟、同一个 PLL/MMCM 出来且**同相**的快时钟。
- 当违例集中出现在"跨进快域"的那几条路径上。
- 当你准备把地址/偏移算术放进快域时。
- 当你打算用 `set_multicycle_path` 把这一组时钟间的红色关掉时。
- 当你改了读口、下游所有配准抽位（彩条链、进链子的 `de/x/y` 抽位、分割显示抽位、越界/窗口标志）都要跟着挪时。
- 当同一份读需要两个以上描述量（本仓形状："字号"与"字内选道"），你打算分两拍打进去时。

## 3. 不适用 / 失效条件

- 不适用：两个时钟**不同源或不同相** —— 那是异步握手（FIFO / 格雷码 / 翻转位）的场合，硬套分时只会把错误推到硅片上（跨域脉冲与握手在 `skill/pitfalls/pulse-toggle-cdc/SKILL.md`，旧编号 S11）。
- 不适用：器件有真正双口 RAM、或换了原语不同的家族 —— 分时这一整套的动机消失，先量 RAM 代价再决定。
- 不适用：需求本来就有余量（N 次读里还有空槽），不必为它重排节拍。本仓就有一次这种动机消失的实例：几何改成"每源像素 4 个慢拍供 4 个字"之后，250 MHz、5 选 1 mux、第二个读口一起都不需要了（见 §7 末条）。
- 失效：改了像素/快钟比例（分频参数一动）⇒ 整张槽位表与所有推导抽位一起作废，必须重新量，不许沿用推导常数。
- 失效：需求里有任何一次读要加法 ⇒ 快域那一个周期塞不下，算术必须搬回慢域。
- 失效：把整组 `set_multicycle_path` 当豁免用 ⇒ 换来的是一条时序全绿、显示随机花屏的位流（理由见 §5 第 5 步）。

## 4. 前置条件

- 两个时钟必须**同源同相、整数倍**（本仓形状：`clk_pix` 50 MHz 与它的 5 倍快钟出自同一个 MMCM）；先拿时钟报告确认相位关系，别信画图库。
- 一份实现后的资源层级表与一份 `report_timing`：前者用来数 RAM tile（示例取值，需按自身工程替换），后者用来做逻辑/布线分诊。
- 端到端台架：能喂一张已知图进真实存储器、逐拍记录输出、并在候选平移量里搜索的那一种。
- 允许你改抽位常数并全量回归；回退要求把实验版整份留档（含槽位表与失败现象）。
- 需要综合与实现（本包在 Vivado/Vitis 2025.2.1 下写成，版本真相源见 `skill/_meta/naming-and-format.md`）；本条目**不替你跑**构建，§7 的读数都是历史件。

## 5. 使用方法

1. **先算两道算术题，再写 RTL**。
   槽数：每工作周期可用快槽 = N，需求 = 各消费者每次读次数之和；算出来是**零余量**（本项目 5 抽头对 N=5）就把"以后再加一次读要从哪个槽挤"写进模块头。
   RAM 代价：在同一组阵列上再加一个逻辑读口会不会让阵列翻倍（本项目探针 80 → 160 个 RAMB36，全片只有 140 ⇒ 封死，分时成了唯一出路）。
   完成后应看到：两个数字（槽数余量、加读口后的 tile 数）写在动手之前，且第二个数字超过全片可用 ⇒ 分时的理由成立。
2. **按方向分配组合逻辑预算**。同相派生下，慢域触发器在 `t=T_slow·n` 变化，快域最早能采它的沿是 `t=T_slow·n+T_fast` ⇒ **跨进快域的 Setup 预算是一个快周期，不是慢周期**。据此把地址/偏移算术全部在慢域算完并各打一拍，快域只留"本域寄存器 → 一个 mux → 存储器地址脚"；快→快只放一两级 mux、不放加法；快→慢最宽松。
   完成后应看到：跨过去的每一条线都是触发器到触发器（或到地址脚）的直线，快域里没有任何算术。
3. **同一份读所需的所有描述量，必须在同一个沿采集**（如"字号"与"字内选道"）。两者错开一个沿会让整列颜色对、位置偏一格，且**不报错、综合不告警**。
   完成后应看到：判据写法——让台架把其中一个量驱动成与另一个无关的独立图案，错了必然露；只测其中一个维度的判据抓不到。
4. **延迟常数要量出来并钉死，不要手推拍数**：端到端台架在候选平移量里搜**唯一**能全对的量并断言唯一（两个都对 ⇒ 判据没牙）；顶层写成一处定义、其它抽位由它推导；再用旧值回代自检，把旧延迟代回公式必须**原样**得到旧代码里的字面量。
   完成后应看到：一个唯一的量 + 一组由它推导的抽位；对不上的那一格就是"只有眼睛能看见"的真实错位。
5. **不要用整组 multicycle 豁免把红色关掉**：数据整个慢周期稳定常常是真的，但整组豁免会一并免掉同组里别的真实跨域路径（输出串行化器里往往就藏着一条慢→快路径，本仓那一层是 `rgb2dvi`，示例取值），换来的是一条时序全绿、显示随机花屏的位流。要么按具体寄存器名限定并接受"改名即失效"，要么按第 2 步把设计写成真能过一个快周期。
   完成后应看到：约束文件里没有整组 multicycle（本仓事实：全库 XDC 搜 `set_max_delay`/`set_multicycle_path` 零命中，示例取值）。
6. **违例先分诊"逻辑不够 vs 离得太远"**：看 `report_timing` 一条路径就够，别猜。逻辑级数很少而 route 占八成 ⇒ 不是深度问题，再砍逻辑是白费，方向是复制高扇出驱动器（`phys_opt_design` 的 fanout replication）、加一级贴着存储器的寄存、或 Pblock 圈住调度器与那批 RAM tile；含进位链的算术才是真深度问题，只能把算术搬回慢域。多份策略同红且起止点相同 ⇒ 是同一条锥，先当"同一张网表重掷"，连着三滚不中才动结构。
   完成后应看到：一条路径的 `Logic Levels` 与 route 占比被念出来，并给出"距离问题"还是"深度问题"的结论。
7. **改节拍要能一次性回退**：分时调度器一旦换采样沿或加一级寄存，抽头采集沿、valid 跟随链、搭车槽全都要动。把实验版整份留档（含槽位表与失败现象），回退到全绿的那版只补回确定的真错，工具侧旋钮一次只动一个。
   完成后应看到：一套"整份留档 + 一次只动一个旋钮"的记录，回退不需要临场猜。
8. 上板前 `md5sum`，**不信文件名**（构建会原地覆盖同名位流）；成套冻结与 md5 校验见 `skill/pitfalls/artifact-freeze-and-freshness/SKILL.md`（旧编号 S15）。

## 6. 判读与失败分叉

- 第 1 步：通过 = 槽数有余量或已把"从哪个槽挤"写进模块头，且加读口的 tile 代价已知。
  失败 = 算出零余量却没写挤槽方案 ⇒ 下一次加读必然重排节拍，判 `FAIL`（欠的是文档，不是逻辑）。
  读不到输入 = 拿不到 tile 数（没有资源层级表，或只有探针）⇒ `NOT_MEASURED`；⚠ 探针的绝对数只会乐观（本仓实测同一份模块探针 21 tile vs 真设计 80 ⇒ 探针低估了地址扇出），不许拿探针当上限。
- 第 2 步：通过 = 快域路径只有"寄存器 → mux → 地址脚"。
  失败 = 快域里出现加法/乘法 ⇒ 一个快周期塞不下，把算术搬回慢域。
  读不到输入 = 报告点不出这条路径的名字 ⇒ `NOT_MEASURED`，先确认两个时钟真同相（不同相就整条不适用）。
- 第 3 步：通过 = 独立图案激励下两个描述量同沿采集、无整列错位。
  失败 = 只测一个维度 ⇒ 这条判据结构上抓不到（错一个沿也不红），补激励而不是加断言。
- 第 4 步：通过 = 唯一量成立**且**用旧值回代能原样复现旧字面量。
  失败 = 两个候选量都全对 ⇒ 判据没牙，样本集或判据本身要改；回代对不上 ⇒ 那一格就是肉眼级错位。
  读不到输入 = 端到端台架没有已知图 ⇒ `NOT_MEASURED`，不许手推拍数顶替。
- 第 5 步：通过 = 没有整组豁免，或豁免按具体寄存器名限定并写明"改名即失效"。
  失败 = 用了整组 multicycle ⇒ 时序结论对该组内其它跨域路径不再成立，判 `FAIL`。
- 第 6 步：通过 = 每条违例都被归类为"逻辑不够"或"离得太远"，且动作与归类一致。
  失败 = 对着 route 占八成的路径继续砍逻辑 ⇒ 方向错，白费一轮。
  读不到输入 = 报告里的路径名与模块头注释的结构断言冲突（注释说"输入都打过一拍"而路径显示跨模块组合直驱一批 CE 脚）⇒ **信报告**，注释只是旧约定；这条不是 `NOT_MEASURED`，是文档过期。
- 第 7/8 步：通过 = 实验版留档、上板件按 md5 认。
  失败 = 只有"我以为的那一版"而没有留档 ⇒ 回退变猜，判 `FAIL`。

## 7. 已验证的效果

以下读数都出自历史台账（`report/log/ISSUES.md` #76 与 #105，另有 `report/log/OVERNIGHT_LOG.md` 的对应轮次）。本轮（技能包重构轮）**没有跑综合/实现、没有读新的时序报告、没有上板** ⇒ "现在重跑还能得到这些数"记 `【待验证】`。

- 算术题的量（#76）：帧缓存那一组在层级资源表里是 **80 个 RAMB36**，全设计 96 tile / 68.57 %，全片 140 ⇒ 再加一个逻辑读口实测 **80 → 160** ⇒ 直接出局；分时因此成为唯一出路。同节还记了探针只能量"地址那一段"、且同一份模块在探针里只落地 21 tile（低估地址扇出 ⇒ 绝对数只会乐观）。
- 快域放算术的代价（#76 记的第 14 次构建那一版）：`base+1`、`base+ROWW` 这类加法放在快域、再进 5:1 mux 打到 BRAM 地址脚，实测要 5.3 ns ⇒ **WNS −1.277、1400 个失败端点**（快域总共才 1855 个端点）；该族三次红 −1.277 / −0.485 / −0.327。同一条 mux→RAMB36 地址脚的路径读数：数据 3.844 ns 里布线 3.255 ns ⇒ **route 占 84.7 %**，与"离得太远而非逻辑不够"的分诊一致。
- `【未核实】`：旧卡把"`Logic Levels 2`"与这个 84.7 % 写成同一条路径的两个字段，而我在 #76 那一节只读到布线占比与 4 ns 预算的推导，没读到同一行的逻辑级数 ⇒ 该配对待核实。反向对照：同一台账更晚的一节把 `#105` 那条最差路径**改判**为 6 级逻辑 + 71 % 布线（瓶颈是距离/拥塞，不是算术锥体）⇒ 分诊必须在当版报告上做，旧结论不能引用。
- 延迟常数是量出来的（旧卡登记的那一笔，对应 `report/log/OVERNIGHT_LOG.md` 的对应轮次）：端到端台架在 0..20 的候选平移量里搜"唯一能让 152 个样本全对上的量"，搜到 1 个（量出的读口延迟 = 5）并断言只能有 1 个；顶层抽位改由它推导后，把旧值 2 代回公式原样得到旧代码里的 4 / (2) / 3 / 11，其中"右窗彩条"那一项算出来是 1 而代码里写的是 2 ⇒ 顺手抓出一处存在了很多版本的 1 像素错位（竖条纹图案肉眼看不出）。
- 不用 multicycle 的口径（对应轮次里明写过）：`set_multicycle_path` 要成立必须声明"数据整个慢周期稳定"这个前提，前提被后人改一拍，工具就不再有意见、芯片上才有现象；且整组豁免会连带免掉输出串行化器里那条真实的慢→快检查 ⇒ 本仓选择不加。
- 本条的动机**会消失**（#76 段二）：几何改成"每个源像素有 4 个慢拍、双线性正好要 4 个字"之后，同一节的结论是"不需要快钟、不需要 5 选 1、不需要第二个读口、一块 BRAM 都不多要（80→160 那个坑不存在）"，代价是显示统一延后一个源行（=2 个显示行）⇒ 第 1 步的算术题每次都必须重算，不能沿用上一版的结论。
