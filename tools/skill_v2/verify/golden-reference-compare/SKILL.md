# 黄金参考比对：来源盖章、按期望值豁免、空集不通过

## 适用场景

- 把设计/工具的实际输出与黄金参考（文本表、CSV、报告、样本流）逐条比对。
- 出现：全绿却查不出已知的差异；豁免名单一轮比一轮长；换台机器/换编辑器就整片红。
- 某个桶、某张表实际参与比较的条数是 0，但结论仍是绿。
- 需要为定点/浮点结果定容差，或需要在不同计数口径（样本、像素、周期）之间比数值。

## 使用方法

1. **参考件的来源与盖章**：参考件必须写明由谁、用哪条命令、在哪个版本生成，并随附一份指纹。
   指纹只覆盖**内容**——参与比对的字段值在规范化（剥时间戳与绝对路径、统一分隔符、按列取值）后计入；
   **行尾（CRLF/LF）、编码与 BOM、无关注释不参与**：按内容不按换行，否则换个环境就全红，
   团队下一步就是把指纹整条关掉。参考件与生成配方一起进版本库，只存参考件不存配方等于没有参考件。

2. **容差按物理量定，不按字符串定**：整数/枚举类要求逐位相等，容差为 0；
   定点类按量化步长给绝对容差（并写明位宽与小数位）；浮点类给绝对与相对两个容差、取其一即通过，
   并写明有效位来自哪里。每个容差旁边必须写"为什么是这个数"（量化噪声地板、编码增益、舍入方式）。
   推不出来的先标未核，别用一个"看起来差不多"的数占位。

3. **豁免名单必须按"被豁免的期望值"作键，不能按被测信号名**。
   按信号名豁免 = 该信号下所有用例全部买通，包括将来出现的真缺陷，等于把自检本身废掉。
   键要落到"哪一次比较"的粒度（用例 + 期望值 + 比对维度），并打印"本次豁免掉了哪一条比较"。

4. **豁免名单随检查器一起进版本库**，每次运行**打印实际命中条数**（命中的比较次数，不是名单长度）。
   命中 0 条的豁免是欠账：要么删掉，要么解释为什么这次没走到。命中数增长意味着尺子在退化。
   没有理由说明的豁免行不许合入。

5. **零样本分支不许真空通过**：某个桶参与比较的条数为 0 ⇒ 该桶给 `NOT_MEASURED`（见 `three-state-verdicts`），
   并打印是谁把它筛空的（过滤条件、解析列数、字段改名、表头漂移）。"没有差异"与"没有比较"必须能区分。

6. **比对维度要同现在**：两个不同单位的数相减得到的"绿"是假绿
   （一个按像素、一个按采样点；一个按周期、一个按纳秒；一个按帧、一个按场）。
   要求**同一单位把所有桶对平**：先换算到同一物理量与同一计数口径，再逐桶比，
   最后把各桶总量与参考总量对账——只看逐桶均值会漏掉两个方向相反、互相抵消的偏差。

7. **形状行的两个操作数必须来自不同来源**：如果"参考形状"与"实测形状"读自同一份文件或同一个变量，
   那是同一份数自比，恒等式永远绿。要求一侧来自设计实际输出（仿真/实现/上板读回），
   另一侧来自参考件或由规范推导，并分别打印两个操作数的出处与取法。

**先查什么**：手上这份参考件是哪一个版本、哪条命令生成的；字段定义与单位来自哪份一手资料
（接口规范/数据手册 ＞ 工具输出格式说明 ＞ 应用笔记 ＞ 记忆）。查到出处才允许写容差与豁免。
**先跟用户确认什么**：任何新增豁免、任何放宽容差、任何更换参考件——它们改的都是"什么叫正确"，
属于口径变更；以及是否允许为对齐单位而改写比对口径（会连带影响别的判据）。

## 失效条件

- 参考件与 DUT 同源（同一模型、同一脚本顺手生成两边）：比对退化成自证，设计错参考也错，全绿毫无意义。
- 指纹把行尾/编码算进去 ⇒ 换环境全红 ⇒ 团队关掉指纹 ⇒ 下一次真实内容变化也一起被放过。
- 豁免按信号名作键后，新用例静默继承同一豁免，覆盖面被无声扩大；征兆是豁免命中数大于新增用例数。
- 容差来自"上次差多少"（为了让它绿而放大）：噪声地板被抬高，真偏差永久隐身。
- 单位换算写在比对**之后**（先比出红、再补一句"其实是一个量"）：此时红绿已进结论，换算就是削足适履。
- 打印的是名单长度而非实际命中的比较次数，于是失效的豁免被读成仍在生效的豁免。
- 参考件更新没重跑：所有判据仍在拿旧参考比，绿是真的，结论是假的。

## 已验证效果

未量过，属建议。采用本条要求交付时给出三项读数：每桶实际比较次数、豁免命中次数（按比较计）、
参考件指纹及其覆盖范围说明（哪些字节参与、哪些不参与）。

## 来源

长自三类观察：豁免名单按被测信号作键、把别的用例买通了；零样本分支真空通过；
两个不同单位的数相减得到"绿"。对应坑清单 `ruler-fake-greens`、`tcl-and-probe-traps`。
配套见 `three-state-verdicts`、`checker-selftest`、`bench-expectations-first`。
