# 跨时钟域的四条通用规则与"按定义判"的定位口径

## 适用场景

- 日志里出现"跨域警告""异步时钟组""路径未约束"这类条目，数量不少，你说不清该修几条。
- 现象级：某位偶尔错、标志丢失或重复、队列假满假空、计数值跳成一个量不到的中间值，换个频率就复现不出来。
- 结构级：同一模块被两个时钟分别例化、复位来自别的域、外部接口（引脚、上位机侧、另一颗芯片）的采样钟与内部钟不同源。
- 哪一步用：写或评审任何跨越两个时钟域的一根网之前；采纳任何"加了个属性就算同步过"的改动之前。

## 使用方法

### 先查什么（一手资料优先级）

工具用户指南里"时钟域判定、自动约束、属性名及其生效范围"那几节，以及被用原语（异步队列、时钟合成、
同步器模板）的数据手册页 ＞ 应用笔记 ＞ 教程 ＞ 模型记忆。属性名与报告字段位置按你手上这一版工具
重新取一次形状基线，别凭记忆写字段名。

### 先跟用户确认什么

- 哪几路钟真是异步的、哪几路同源同频：这决定要不要建异步组，建错会静默放宽一大片路径。
- 是否允许改接口位宽与握手方式来消掉跨域，还是只能在现有接口上补机制（改接口名会连带影响按名的约束与检查）。
- 频率、深度这类决定"可算的界"的参数由谁定、什么时候定。

### 四条通用规则（先问形状，再问落点，最后才问属性）

1. **单域写、多域读**。一根被跨域消费的网只允许有一个驱动时钟域。两个域同时驱动同一网、或同一
   寄存器存在两个驱动版本，是"看起来偶尔对"的第一号来源。要多点消费就多打几份寄存器，不要在消费端合成。
2. **只传事件/标志，不传多位总线**。跨域传一位脉冲或一位电平标志（到接收域再还原成事件），不要把多位
   数据顺手打过去：多位量的各位翻转时刻不同，接收端采到的极可能既不是旧值也不是新值。量大就让数据留在
   源域，跨域只带一个"可以取了"的信号。
3. **多位量三选一：握手、异步存储转发、格雷码指针**。
   - 握手（请求/应答或电平翻转）：延迟换安全，吞吐按两个域里慢的那个算。
   - 异步队列（双口存储 + 两端指针各自同步）：容量与吞吐都走这条路，这是多位量的默认答案。
   - 格雷码只解决"指针必须跨域"这一步。为什么必要：二进制加到 2 的幂那一档时低位会连着翻多位，
     接收端采在这一刻就拿到中间组合，误差量级可达整表深度；格雷码相邻计数只差一位，采到的必然是
     前一个或后一个，误差被压到一个表元，而满/空判据本来就容得下这一格滞后。
     位宽与深度的关系：地址需要 A 位（深度 = 2^A）时，指针与其格雷码都要 A+1 位，多出的最高位专门
     用来区分满与空（回绕后地址相同、最高位不同）；格雷码必须在**源域、送出之前**编码，满/空判据
     必须在**各自消费端所在域**里生成。把二进制指针送出去再在对端编码，等于规则 2 没执行。
4. **同步链落在接收域，并带上归属属性**。同步器属于消费它的那个域：连续几级触发器必须都在接收域、
   同一物理区域，属性/例化约束只作用在这几级上。
   **属性只是放置指令，不是逻辑修复**：它只让工具把这几级摆得近一点，不会替你补缺失的同步级，也不会
   把多位总线变成安全量。加属性之后布局变了、时序读数跟着动，那是布局副作用，不是收益——别把"最差路径
   那一栏往好的方向动了"写成"跨域问题解决了"。

### 逐条判定被点名的警告（高自由度：按定义判，不追求全局零警告）

对每一条警告只问三个问题，答案来自网表与例化关系，不来自警告文本：

1. **驱动域是谁**：驱动那根网的寄存器实际挂在哪个钟网上（要穿过门控、使能、片内派生钟去追）。
2. **接收域是谁**：同样按实际钟网回答。
3. **两侧相同吗**：相同 ⇒ 假警，落档写清"哪两个实例、各自的钟是什么、因此同域"的证据；
   不同 ⇒ 真跨域，检查上面四条哪一条在覆盖它。没有机制覆盖就是欠账，按机制补，而不是加例外消音。

- 同名信号在不同实例里可能同域 ⇒ 假警：警告按名字聚类而不是按例化聚类。看到 N 条同名，先分实例再计数。
- **报告没点名的地方也可能真混域**：工具认不出的钟（门控出来的、片内派生的、根本没被约束的、被当成
  同源的两个物理输入）在它眼里不构成跨域。要按例化关系把每条跨模块边界的网自己列一张清单
  （例化名 / 驱动域 / 接收域 / 机制 / 约束 / 判定），清单条目数就是"判 N 项"的分母。
- 口径是"按定义判"，不是"全局零警告"。验收句写成：**真跨域条目数 = 有机制覆盖的条目数，且逐条对得上**。
  零警告既可能被假警凑出来，也可能被静默放宽的例外掩盖，两种都不是证据。

### 低自由度收尾（跑完应看到什么）

- 跨域清单一份，每条带 PASS/FAIL/NOT_MEASURED，结论行末位是判定词。
- 异步组与例外约束只出现在被判为真跨域的条目上；被放宽的路径数逐次可数。
- 同步链在**网表**里仍是连续几级、级间没有组合逻辑：源码看着对不算，优化可能合并、复制或插门。
- 任一项读不到就判 NOT_MEASURED，不许写"应该都同步过了"。

## 失效条件

- **工具的时钟模型不完整**：门控钟、片内派生钟、被约束成同源的异步输入会让"跨域"在工具眼里消失。
  征兆：某条你肉眼看着就该跨域的网，报告里连名字都没有。此时以自建清单为准。
- **同步级被优化改写**：等价寄存器合并、移位链抽取、高扇出复制、按位宽拆分，都能把同步器变成
  "不连续的两级"。征兆：网表里两级之间多了门，或某级被复制到别处。加属性不解决这类破坏，只能靠读网表。
- **用几级同步器同步脉冲**：接收钟周期长于脉冲宽度时事件整拍丢掉；要传事件就变电平或走握手。
- **只同步了标志、数据仍是多位**：同步器治不了多比特一致性。最阴的现象是收到一个值域里没定义过的数。
- **格雷码用错处**：只编码低位、漏掉回绕位、或在接收端才编码 ⇒ 依然多位同翻，且误差量级回到整表深度。
- **满/空判据所在域写反**：判据不在消费端生成就偶发假满假空；同步后的指针本就带一两拍滞后，
  深度与水位必须按这个滞后量留余量，否则会真溢出。
- **异步组与例外铺得过宽**：整片路径被当成不必计时之后，同步器最后一级到宽扇出逻辑这条**真该计时**的
  路径也一起消失，保持余量会好看得没有意义。
- 换工具版本或换目标平台：属性名、建议的同步级数、报告字段都可能不同，先重取形状基线再判。

## 已验证效果

未量过，属建议（本条没做过带/不带它的 A/B）。依据的观察类别：把"跨域警告条数清零"当目标，结果同名
假警被逐条消音、真混域一条没动；以及加了归属属性后时序读数变动被误记成收益。
变硬的可复跑形式：同一条构建命令在改动前后各出一次跨域清单，比三个数——真跨域条目数、有机制覆盖的
条目数、被判假警的条目数（后者每条须附"同域"的例化证据）；格雷码通路配变异对照（把编码改回二进制，
越界用例必须红），未配对照的判据要标注"未配对照"。

## 来源

长自"报告点名≠真混域、报告沉默≠真没事"这一类观察：同名信号在不同实例里其实同域却被逐条当真警处理；
以及工具识别不到的门控/派生钟造成的真跨域从未被点名。相邻条目：reset-and-clocking-plan（复位与钟的
域归属要先出名册）、width-and-overflow-audit（指针位宽与深度这类可算的界要断言）、constrain-io-and-clocks
（异步组与例外的建立顺序）、reduce-fanout-and-congestion（机制判据不等于结果判据）、
constraint-coverage-loss（放宽一片的静默代价）、three-state-verdicts（读不到判未测量）。
