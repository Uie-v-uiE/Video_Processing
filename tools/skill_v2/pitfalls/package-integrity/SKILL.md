# 交付包完整性

包的错误几乎都不是"内容写错"，而是**范围与来源**错：判定范围靠手抄、豁免靠邻居行、
读数靠工具自报。本条把每一处"靠"换成"现算并打印"。

## 适用场景

- 准备交出一个目录（源码 + 约束 + 脚本 + 报告 + 说明），或从中剪枝。
- 写了完整性检查器，要判断它绿得是否可信。
- 导出/打包动作跑完，交付物落在别处以远或需要复核。
- 不适用：只改单个源文件而不动目录结构与引用口径的轮次。

## 使用方法

动手前先查：交付要求里**必须随包的件类**（源、约束、脚本、报告、复现入口、凭据样例）与**明确不随包的件类**，
以及导出器的暂存目录在哪、它自己会不会清理。先跟用户确认：剪枝范围（哪些是内部过程件）、
是否允许删目录、凭据类文件是以脱敏样例随包还是以清单形式缺席。

判定的通用语言照旧：`PASS / FAIL / NOT_MEASURED`；结论行末位是判定词；空集、读不到、解析失败都是第三种。

### ① 死引用：文档点名的件不在包里

触发：改名/剪枝之后文档仍在引用旧名字；或检查器的判定范围是手抄的一批文件。
现象：评审按文档找不到件；或反过来——把纯过程记录里的历史路径当成"包不完整"，红一堆无关项。
排查：1) 读检查器**怎么得到待判文件集合**：现场遍历还是清单常量；后者先修；
2) 遍历现算待判集，并按"活文档 / 复现入口 / 过程记录"分类打印每类文件数；
3) 只在活文档与入口件上判死引用，打印红条数与每条"引用文本 + 所在文件"；
4) 对过程记录**不判但必须打印条数**，并在结论文里写出为什么不判（那些路径是当时那天的名字）；
5) 逐条读红项：是引用错了名字，还是件真的该随包。
根因分类：射程用快照；文档态没分层。
修法：判定范围一律遍历现算 + 深度/忽略规则显式；引用改到与盘上同名，或把件补进包。
预防：过程记录归档时打上当次的时间标记，让"它是历史陈述而不是复现入口"这件事可读出来而不是靠人记。

### ② 豁免写在邻居行，把整类文件买通

触发：检查器允许"这份不随包"这类声明，但只按文件或整篇判断，不要求写在被引用的那一行。
现象：一处豁免让整份文档的所有引用都免检；漏件被长期掩盖。
排查：1) 读豁免判定用的是行级还是文件级作用域；2) 让豁免词与引用文本**同行**跑一次，
确认只有那一条被免；3) 打印本次豁免命中的行数与每行内容；4) 跑变异对照：把引用改成孤零零一行（无豁免词），
判据必须变红——不变红说明豁免泄漏。
根因分类：豁免作用域过宽 + 词表不在检查器里。
修法：豁免词表进检查器（不散落在文档约定里），且只在"同一行含引用文本"时生效；命中行数必须打印。
预防：豁免清单条数设上限并在结论里出现；某类文件的豁免数突增就是有人在买通检查。

### ③ 本机绝对路径泄进交付件

触发：脚本、报告或说明里写死了"我机器上的那个位置"。
现象：换一台机器/换一个目录深度就跑不起来；或只是文档难看但不影响执行——两类处理不同。
排查：1) 遍历现算三类件：可执行件（会被运行的脚本/流程入口）、复现入口件（照着就能跑起来的说明）、
叙述件（当时的记录、日志摘录）；2) 对前两类搜绝对路径模式，命中即 `FAIL`，逐条读并改成相对/符号；
3) 对叙述件**只报数不改写**——那些路径是"当时读的是哪一份"的证据，改掉等于毁证据；
4) 允许带豁免标记，但标记必须含反例夹具（见第②条的同行规则与 `checker-selftest` 的做法）。
根因分类：三层件被当一层判；改写叙述件是过度修复。
修法：可执行件与入口件清零；叙述件保留并在检查结论里给出条数与理由。
预防：绝对路径模式进检查器词表；新脚本用包内相对定位，不引入机器依赖。

### ④ 导出器删了自己的输出目录，交付物是空的

触发：导出脚本先"清理目标目录"再写，但清理把输出目录本身删了，后续写入静默失败。
现象：脚本退出码 0、stdout 说成功，交付目录不存在或空；直到别人来取才发现。
排查：1) **不要读它的 stdout 当证据**；直接数盘上文件：遍历导出目标目录，打印文件数与目录是否存在；
2) 文件数为 0 或目录缺失时，去读该导出器自己的暂存/中间输出目录，件多半还在那里；
3) 从暂存目录按原始结构恢复到交付目录，再重跑第 1 步；
4) 读导出脚本里"清理"那一段，确认它删的是目录内容还是目录本身。
根因分类：工具自报状态 ≠ 盘上事实；清理语义过界。
修法：清理只清内容并保证重建目录；恢复后按**盘上文件数**验证，不用它的成功话术。
预防：交付目录的文件数成为一条门禁，地板非 0；导出后立刻跑这条门禁再宣布完成。

### ⑤ 空目录留在包里

触发：剪枝删掉了目录内容，目录本身还在。
现象：包看起来有结构但某些节点是空的；评审按目录找件落空；某些工具链对空目录行为不一致。
排查：1) 在所有剪枝动作**完成之后**统一遍历一次，打印每个空目录的路径；
2) 逐个读它是否被别处按目录名引用（引用了就要留占位或补件）；3) 无引用的才删除，删后再遍历确认计数为 0。
根因分类：剪枝与收尾分开做，收尾没跑。
修法：把"收空目录"作为剪枝流水线最后一步，前置条件是剪枝全部落盘。
预防：完整性检查里空目录数为一项，值应为 0；非 0 时报 `FAIL` 并列出路径。

### ⑥ 包内自洽检查核对数为 0，却被念成绿

触发：入口脚本按通配/约定去找凭据类或配置类文件，包里的件名与约定不一致。
现象：检查"一个都没找到"，于是"没有不一致"，被写成通过；换环境后入口脚本直接失败。
排查：1) 读那条检查的源码，找它"核对了几项"的计数变量；2) 让它自己打印核对数；
3) 核对数为 0 时判 `NOT_MEASURED`，禁止进入 `PASS`；4) 补一个正例夹具（放一个符合约定的件）跑一次，
确认它能从 0 变成 1，否则这条判据是死的。
根因分类：空集当通过；判据没配变异对照。
修法：判据统一三态并打印"判 N 项"，N=0 ⇒ 第三种判定。
预防：任何"扫/找"类检查都必须自带计数地板与一个能动过的正对照（见 `three-state-verdicts`）。

### ⑦ 指纹把行尾与编码算进去，合法差异误阻塞

触发：用整文件字节哈希做"是否同一版"的比对，而文件在不同机器间行尾（CRLF/LF）或编码（带 BOM）不同。
现象：内容一致的件被判成"不一致"，交付流程卡在无意义的红上；真改动反而被噪声淹没。
排查：1) 读指纹计算取的是什么：原始字节还是规范化后的内容；
2) 拿一个只差行尾的对照文件跑一次，若变红即确认指纹含格式；
3) 改成按内容哈希（统一换行、去 BOM、可选忽略首尾空白）后，重跑①的对照：应同指纹，且一处真实改动仍应不同；
4) 读"被忽略的差异"是否打印出来，避免用宽松把真改动一并放过。
根因分类：指纹定义与"是否同一版"的语义不对齐。
修法：内容哈希用于阻塞判定，字节哈希只用于存档与追溯，两者分别打印。
预防：任何哈希判据上线前先跑一组"只差行尾"的夹具；宽松化必须同时给出被豁免项计数。

### ⑧ "已推送到远端""板上就是这一版"这类声明

触发：结论里出现关于包外状态的陈述（远端仓库、板上、别人机器上的那份）。
现象：本地看着齐了，取回时缺件；或板上跑的其实是旧位流，现场演示与仓库不符。
排查：1) 读版本库实际记录：远端分支上该次提交是否可见、文件清单是否与本地一致（以库里读回为准，不以本地状态为准）；
2) 对板上/外部设备状态，跑一次**能读回身份**的动作（读版本标识类寄存器或部件回读），把读数写进结论；
3) 读回身份与预期不符时先怀疑没重载，而不是怀疑读数坏了；
4) 拿不到读回时，声明改写为 `NOT_MEASURED`，并在交付文档里注明未核。
根因分类：声明来自执行动作的返回，不来自事后读回。
修法：每个"已经完成"的外部状态都配一条读回命令与它的实际读数，写进 claims—evidence 对照。
预防：外部状态声明必须带"何处读的、读到什么、什么时候读的"；缺一律不计入完成项。

## 失效条件

- 遍历现算依赖能读到完整目录树：包被部分挂载、符号链接、被版本库忽略的件都会让遍历与真实交付集不同。
  征兆：每层计数与目录约定明显不符 ⇒ 先修射程再谈判定。
- "活文档 / 过程记录"的划分是**约定**，不是物理属性：约定改了（记录被当入口用）第①条的分层就失效，
  要重新打印每类文件数确认。
- 内容哈希的宽松化会把"只有空白差异但确实该红"的改动放过：它只适用于已知跨机器换行的件，不适用于生成物比对。
- 本条不判"内容对不对"，只判"件在不在、来源可不可读、读数是不是盘上事实"。内容质量靠评审与台架。

## 已验证效果

未量过，属建议（没做过带/不带本条的 A/B）。可复跑的读数集（缺任一项即 `NOT_MEASURED`）：
待判文件按三类的每类文件数；死引用红条数（应 0）；豁免命中行数（应有上界且逐条可列）；
绝对路径在可执行件/入口件中的命中数（应 0）与叙述件中的条数（只报数）；
交付目录盘上文件数与非 0 地板的比较；空目录数（应 0）；自洽检查的"判 N 项"中 N（N=0 不得为绿）；
行尾对照夹具的一对指纹（应相同）与真实改动对照（应不同）；外部状态读回值与预期值的差（应为空）。
