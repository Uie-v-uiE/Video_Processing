# 本包的验证记录（可复跑，不靠声明）

这份文件只回答一个问题：**这个技能包本身被检查过吗？怎么复跑？**
条目的"已验证效果"讲的是技能内容；这里讲的是**这个包作为交付物的自洽性**。

## 复跑命令（两条，都在包内，无外部依赖）

```bash
node _meta/check-selftest.mjs                 # 尺子自己的能红对照
node _meta/check-skill-package.mjs .          # 整包机器判据
node _meta/build-index.mjs . --check          # 索引是否与条目一致（只报差异）
```

三个工具的分工：`check-skill-package` 判内容形状，`check-selftest` 证明那把尺子**有牙**，
`build-index` 保证索引由条目现算（手写清单会随目录变深静默变窄）。

## 四道门落在哪里（新增条目时必须走完）

| 门 | 谁判 | 判什么 |
| --- | --- | --- |
| ① 格式 | `check-skill-package.mjs` | 五节齐、描述以「用于」开头且含触发条件、正文 ≤500 行且 ≤6000 字符、无绝对路径与专有名词、索引双向一致 |
| ② 可检索 | 人工（`_meta/authoring-standard.md` 第 2 条） | 只给症状能否命中这条；命不中 = `description` 写成了做法 |
| ③ 增益 | 条目自己的 `已验证效果` | 要么给可复跑形式，要么明写「未量过，属建议」；带具体读数必须声明"非普适" |
| ④ 陌生人演练 | 交付前的抽样演练 | 没参与的人照条目做一遍，卡住处改条目 |

门②与门④目前**没有机器判据**——这是本包已知的缺口，不写成已验证。
`_meta/distillation-process.md` 第二节把四道门各自的可自动化程度写明了，别把①的绿念成整包合格。

## 尺子的已知边界（不许反过来用）

- 长度按**去空白字符数**判：中文没有空格，按"词"数判等于没判（第一版就犯过这个维度错）。
- `失效条件` 只判"不是空话、长度 ≥12"，判不了"写得对不对"。
- `已验证效果` 的"非普适"声明按**测量标记**触发（带单位的量、千分位、"量到/实测"字样），
  不按数字个数——按数字个数会误伤"应为 1"这类处方句，正对照就会永远不动。
- 检查器自身的输出不落进被检查的树（`_meta/` 与 `fixtures/`、`_out/` 被跳过），
  否则它把自己扫进射程，形成自指。
