# 板级判活与读数

## 适用场景

- "命令返回成功"但没有任何读数能证明状态真的改了。
- 长时间批量测试中途失联，需要区分程序卡死、板子掉电、调试链断、主机侧脚本死。
- 演示前只有几十秒，需要一次动作就判定"活着 / 停了 / 读数读不回"。
- 只有眼睛可观察（画面、指示灯），而文档里正在把"看起来正常"当证据。

## 使用方法

本条是**低自由度**：判活动作固定成配方，每步写清前置与应看到的读数。

**先查什么**（一手资料优先：接口规范/数据手册 ＞ 应用笔记 ＞ 教程 ＞ 模型记忆）：在寄存器表里确认
哪些计数器与状态位**只读且读无副作用**，片上传感器（温度、电压）的读口位置与换算式，
心跳量的推进源是软件还是硬件。**先跟用户确认**：读操作会不会改变行为（读清、读触发中断的要先问）、
是否允许占用串口/调试链（可能和别的进程抢）、原始回显件落在哪里、允许留多大、批量测试跑完是否
必须复原现场。

1. **判活三件套**（三者都必须能被上位机一次性读回并留件）：
   - 心跳计数器：自由递增，由软件循环或硬件时基推进。判据 = 连续两次读数的差；差应等于
     "预期速率 × 间隔时长"。差为 0 ⇒ 卡死；差与间隔不成比例 ⇒ 被复位或重跑过。
   - 状态快照：当前模式、当前阶段、错误位、最近一次失败的原因码，**一次读回**，不靠多条命令拼。
   - 片上传感器：温度与电压。它把"程序停了"和"板子热停/供电异常"分开——只看前两件分不出来。
2. **一次读回并落件**：上位机用一条命令顺序取三件套，写成带时间戳的原始件（不加工、不改名、
   不复用同名）。每次判活都留件，屏上看过不算。
3. **可读回优先于屏幕观察**（本条核心）：屏幕只能证明"看起来对"，读数才能自证。
   某量现在没有读口，就明写"这条只能靠眼睛"，并把它**列为欠账**（下一版加只读计数器或状态位），
   不许在文档里用眼睛判据顶替读数。每条对外声明都要能指到一个读数或一个原始件，指不到就降级为"未量过"。
4. **控制台/串口的通用陷阱**（按配方走，别即兴）：
   - 命令按空白分词：含空格的路径、空参数、带分隔符的串会被拆成多条。用整条发送的转义方式，
     并先发一条能读回原样的命令验证分词。征兆：报"参数过多"、后半截被当成新命令。
   - 端口被别的进程占用：报错通常是"设备忙/打不开"。先列占用者再动手；关掉持有者（另一个会话、
     监视器、还没退出的脚本），不要在两个持有者之间盲重试。
   - "日志是 0 字节"证明不了任何事：**缓冲与路径是两回事，分开查**——先确认写的是不是这个文件、
     句柄是否还开着，再确认是否行缓冲没刷出（进程还活着时 0 字节完全正常）。
   - 无回显 ≠ 未执行：换一条能读状态的命令复核。给只读寄存器发写命令常常静默无效。
   - 回显被关闭、换行不统一、提示符吞字符，都会让读数丢掉；读数尽量走状态命令而不是走屏显文字。
5. **长时间批量测试的纪律**：
   - 每步留原始回显件（带序号与时间戳），失败必须能回溯到当时读数。
   - 每步记三件套的前后差值，差值为 0 的那一步单独标注。
   - 跑完把状态复原（模式、阈值、时钟与外设参数），并**核对复原成功**——核对靠读数，
     不靠"我发过复原命令"。
   - 失败先分类：设计问题 / 操作问题 / 环境问题（供电、温度、主机负载、别的进程抢端口）。
     **别急着把现场报告降级成"用户看错了"**：先证明那条分支可达（能复现，或能指出读数与用户描述
     矛盾在哪）。证明不了，现场报告的效力保留。

## 失效条件

- 调试链或板子供电任一不在 ⇒ 三件套全读不回；此时"读不到"既不判活也不判死，判 NOT_MEASURED。
  征兆：连静态寄存器都读不回来。
- 读口有副作用（读即清除、读触发中断、读推进状态机）⇒ "一次性读回"的配方会改变被测系统，
  必须改用镜像计数器或只读影子寄存器。
- 心跳计数器位宽太小会回卷 ⇒ 两次读数的差算出假象；用长位宽或同时记回卷次数。
- 应用侧（上位机脚本、驱动、加载流程）无法重建时，**不许写"板上已修"**，只能写"板上不可复验"。
- 征兆：文档里出现"应该没问题""看起来正常"却指不到任何读数编号或原始件名——这条已经被绕过了。

## 已验证效果

未量过，属建议——本包没做过带/不带本条的成对比跑。可复跑形式：一次批量测试 N 步，
判据 = 每步都有原始回显件且三件套读数齐（缺件数 0 记 PASS，>0 记 FAIL，跑不动记 NOT_MEASURED），
并在结论行打印"判 N 项"（N = 实际做的比较次数，不是通过数）。

## 来源

长自两类观察：命令返回成功而状态未改、只有屏显可看；串口被别的进程占住导致一整批测试空跑。
判定词与计数地板沿用 verify 类的 `three-state-verdicts`；探针与读数的自欺参见 pitfalls 类的
`tcl-and-probe-traps`；上板前置与禁区见 workflow 类的 `before-touching-hardware`；
读口从哪来见 `register-map-and-readback`。
