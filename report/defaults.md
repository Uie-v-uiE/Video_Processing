# 默认档（上电是什么状态，以及为什么是这一套）

这份文档回答评审最爱问的那句"你不上手，板子自己开机是什么样"。所有条目都是从 `src/host/ps/main.c` 的
初始化那一组 `static` 读出来的，不是从记忆或讲稿里抄的；**行号按 r87 那一版标**，改动之前请重新 grep。

## 一、上电默认（PS 侧唯一的真相）

| 项 | 默认 | 写在哪 | 屏上/回读怎么验 |
|---|---|---|---|
| 效果链各级 | 全关（`stage_sel = 0`） | `cur_sel` `main.c:170` | OSD 第 2 行 `PIPE:00000`；`[STAT] ctrl … stage=0x0` |
| 二值化阈值 | 80 | `cur_thr` `:171` | 第 2 行 `TH:80` |
| 片源 | C 初值是"不钉"（`cur_src=0`），但**开机自动播放会把它写成 1** | `cur_src` `:172` + autoplay 路径 `main.c:1594`（`sd_mount()` 成功就 `ctrl_set_src(1)`） | 插着卡正常开机时 `[STAT]` 该念 **`src=1`**（这一位是"PS 这一路有货"，不是"ETH"）；屏上 `SRC:` 那格念的是**仲裁后的有效源**，两者不是一回事，钉过才带 `*` |
| **缩放** | **手动 1.00×**（档号 4） | `cur_zsel=4` `:177`、`cur_zman=1` `:186` | 第 3 行 `ZOOM:1.00X` 且**不带** `(Auto)`/`(Fit)` |
| 呼吸开关位 | 1（发电机使能） | `cur_zoom=1` `:173` | 见下面第三节：这一位与 `zman` 并存是**对的** |
| 插值 | 双线性开 | `cur_bilin=1` `:190` | 第 3 行或 `[STAT] bilin=1` |
| OSD 叠层 | 开 | `cur_osd=1` `:191`（`gpio_o[20]` **反相**） | `osd off` 之后屏上五行字整层消失、画面逐位等于背景（`sim/tb_osd_lines.v` 的 T16 钉的就是这个） |
| 分割缝 | 正中 50%、蓝标记**画着** | `cur_split` `:145`（marker 位为 0 ⇒ 画） | `split show` 的 `pos=… marker=on` |
| Gamma 表 | 关（PL 逐位旁路） | `cur_gamma=0` `:287` | 第 2 行 `GAMMA:1.0` 之类，且画面逐位等于输入 |
| 发布电平 | 0（不往外推流） | `pub_lvl=0` `:193` | `[STAT] pub=0` |

开机时这一整套由 `ctrl_apply()` 一次写进 `axi_gpio_2`（`main.c:1544` 附近），紧接着做一次
**写图案再读回**的配对自检（`0x1FFu` 那一处）：位流里没有那个 GPIO 时不会编译报错，现象只是
"效果命令全都没反应"，所以这个自检值得留在开机路径上。

## 二、为什么把"缩放"的默认档从自动呼吸改成手动 1.00×（#118/#126 的收口）

1. **口径一致**：`demo_script.md`、`perf_report.md` 与 `lane23` 回读口径写的默认都是"手动 1.00×"，
   可上电给的是呼吸档 ⇒ 每次冷启动都要人先敲一次 `zoom 1.0` 才对得上（2026-09-29 早上那次冷跑串口电池，
   唯一一条红就是 `zman`：初值 0 ≠ 末值 1，其余十格逐字符相同）。
2. **第一眼看对**：评委自己按上电键时，"画面自己在缩放"容易被读成卡顿或漂移；静止画面 + OSD 才是可读的开场。
3. **效果该在第二幕**：呼吸是 `zoom auto` 一条命令就有的东西，当作演示动作比当作默认状态有说服力。

**这一位改的是真行为，不是显示**：`src/rtl/top/pl_video_top.v:984` 用
`zoom_run && !zman_pix && !zoom_fit_en` 生成"要不要标 `(Auto)`"，`:301` 把同一个 `zman_pix` 送进几何。
所以 `zman=1` 之后既不呼吸、屏上也不会残留 `(Auto)`。

## 三、看着矛盾其实对的三处

- `cur_zoom=1`（呼吸发电机使能）与 `cur_zman=1`（手动档）并存：前者是"会不会呼吸"的总开关，
  后者是"倍率由谁定"。手动档在前 ⇒ 总开关为 1 也不呼吸。`[STAT]` 会同时念 `zoom=1 … zman=1`，别把
  `zoom=1` 读成"现在在呼吸"。
- OSD 的位是**反相**的（`gpio_o[20]` = `osd_off`）：写 0 是画、写 1 是不画。位表在 `report/commands.md`，
  `ISSUES #112` 记着这条极性的来历。
- 分割蓝标记默认**画着**：它是演示"哪边是原图哪边是处理图"的指针；关掉它才是取证用的干净图。

- `frames=` 印的是 `sd_frame_total()` —— **片子的总帧数**，不是播放进度，也不是"自上次配置以来收了多少帧"。
  所以两次开机读到同一个 4398 是正常的，别拿它当心跳用（要看在喂多快，问 `sd`：那行有 `measured=`；r87b 起串口**不再自动打** `[SD] frame N:`）。
- `[STAT]` 只在**串口**上念，屏上 OSD 那五行是 PL 自己算的另一份；两者不一致时以屏上为准去查 PS 的写口
  （这正是 `lane23` 硬件回读存在的理由，见 `ISSUES` 里"为什么寄存器回读不算数"那段）。


## 四、怎么自己验默认档（三条独立证据，缺一就不算验过）

1. **屏上**：OSD 第 3 行显示 `ZOOM:1.00X`，不带 `(Auto)`。这一格是 PL 侧从自己的寄存器画出来的，
   装不出"PS 以为写了"的样子。
2. **串口**：`stat` 念 `zman=1 zsel=4`；`[BOOT]` 那几行没有 `CFG_DATA0` 配对失败的抱怨。
3. **硬件回读**：`lane23` 里的 `zman`/`zsel`/`zoom_code` 是 PL 真在用的那份（`ISSUES` 里"为什么寄存器回读
   不算数"那段解释了为什么还需要第 1 条）。

**冷启动这一格待复验**：默认档改了 PS 固件（`ps_app.elf`，r87 版 `d0b07f84a068`），
"冷上电跑串口电池 `zman` 不再红"这句要等这一轮上板跑过才成立；在那之前 `board/README.md` 里
"跑电池前先 `zoom 1.0`"那句操作规程保留。
