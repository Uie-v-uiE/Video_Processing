# PS 软件方案 vs PL 硬件方案对比

## 1. 数据面划分

| 职责 | 优化前（PS lwIP） | 优化后（PL 硬件） |
|------|-------------------|-------------------|
| 以太网 MAC/PHY | PS GEM0 + lwIP | **PL RGMII PHY2** |
| ARP/ICMP | 协议栈软件 | **硬件状态机** |
| UDP 收包 | RAW 回调 + memcpy | **硬件解析** |
| 帧重组 | PS 写 DDR[offset] | **PL frame_reasm → BRAM/DDR** |
| 效果/旋转/HDMI | PL（已硬件） | PL（不变） |
| 控制 | UART + GPIO | UART + GPIO（不变） |
| CPU 参与逐包 | **是** | **否** |

---

## 2. 旋转与窗口滤波

### 2.1 旧方案（PS 时代遗留 / 旁路）

**问题：** `angle≠0` 时强制旁路 blur/sobel。

**原因分析：**  
3×3 窗口需要「源图扫描顺序上的邻域」。若在**源图坐标系**取窗，逆映射后屏幕上相邻像素对应的源坐标可能相距很远，窗口内容错误 → 花屏。

点运算（灰度/二值/反色）只依赖当前像素，与邻域无关，故当时可保留。

```verilog
// 旧代码
wire by2 = ~en[2] | rotate_active;  // blur 强制关
wire by3 = ~en[3] | rotate_active;  // sobel 强制关
```

### 2.2 新方案（目标域处理）

**关键认识：**  
逆映射后，沿屏幕光栅扫描得到的像素流，**本身就是旋转后图像的光栅序**。  
在这条流上用屏幕坐标 (cx,cy) 建 3×3 行缓，窗口邻域在**目标域（显示域）**是合法的。

**流水线顺序：**
```
源像素(经逆映射) → 点运算 → 目标域 3×3 窗滤 → 输出
```

**结果：** 任意 0–359° 下 blur/sobel 与点运算可任意组合，无需旁路。

```verilog
// 新代码
wire by2 = ~en[2];  // 仅由使能决定
wire by3 = ~en[3];
```

### 2.3 三种可选方案对比

| 方案 | 描述 | 带宽/延迟 | 本工程 |
|------|------|-----------|--------|
| A. 旁路 | angle≠0 关窗滤 | 无额外 | 旧方案，已废弃 |
| B. 先旋转到帧缓再滤波 | 多一整帧缓冲 | +1 帧延迟 + 双份 BRAM | 7020 放不下 |
| C. **目标域窗滤** | 逆映射后在屏幕域取窗 | 行缓即可 | **现行方案** |

## 3. CPU 占用与延迟

| 指标 | PS lwIP | PL 硬件 |
|------|---------|---------|
| 中断/包 | 是（~220 包/帧 × 30fps） | 否 |
| memcpy | 每包 | 否 |
| Cache flush | 每帧 | 否 |
| CPU 占用 | 高（协议栈+拷贝） | **接近 0**（仅 UART） |
| 端到端延迟 | 毫秒级（中断+栈） | 微秒级（流水线） |

---

## 4. 为何仍保留 PS

- UART 命令解析更灵活  
- 效果使能、阈值、源选择经 AXI GPIO  
- `FILL` 诊断图可写 DDR  
- 控制面与数据面解耦，便于调试  

---

## 5. 迁移后的兼容性

- 上位机 **协议不变**：`[u32 LE offset][RGB565]`  
- 端口 **5001** 不变  
- **网线改插 PL 口**（不是 PS 口）  
- 串口命令语义不变（需 Vitis 下载 ELF）
