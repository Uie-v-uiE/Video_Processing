# 串口命令清单（照抄就能用）

> 波特率 **115200 8N1**，COM 号自己认（`board/uart_cap_once.ps1 -Port COM6` 或任意串口终端）。
> 每条命令以回车结束；大小写不敏感。这里是**当下这块 bit（r46，`build/frozen_r46_keys/`，bit `36568c71`）真能用的**，不是计划里的。
> 待接的（`rot` / `split` / `osd`）也列在最后，敲了会回一行"缺什么"，不会静默吞掉。

## 0. 板上两个按键（r46 之后的语义）

| 动作 | 效果 |
|---|---|
| KEY1 **短按**（W18） | 右窗旋转 **+1°**，在**松手瞬间**发（r46 起；以前是按下就发，于是每次长按都顺带转 1°） |
| KEY1 **长按 0.6 s** | 片源模式走一格。OSD 第一行 `Src:` 那一格画的是**屏幕上真的那一路**，词只有三个：`ETH` / `SD` / `TEST`（2026-09-25 用户定稿）；末尾出现 `*` 表示此刻是手动锁住的（没有 `*` 就是自动）。显示 ETH 时按一次 → `Src:SD*` |
| KEY2 短按/按住（V14） | 反向旋转，按下沿就发（连续转的手感要的就是早发），不占用长按 |
| LED1 | 按住 0.2 s 后**亮**（表示"正在计时"）；长按生效后**翻转**（每成功一次它翻一次） |
| LED0 | 1.5 Hz 心跳；发生过"拷贝超出消隐窗口"时变 6 Hz 快闪 |

> 为什么长按要留反馈：这四次现象（"长按没反应"、"切 SD 要按两次"、"看着像自己变成彗星图"）
> 全部来自同一件事 —— 模式变了但屏幕上没有任何东西跟着变。见 `report/ISSUES.md` #55。
>
> **为什么 `SRC=` 画的是"屏幕真的那一路"而不是"模式"**（r48 改的）：以前这行写意愿
> （AUTO/ETH/SD/TEST 四态），于是"显示 ETH 时写着 AUTO"这类事都会发生 ——
> 意愿没生效的状态下标签与屏幕必然不一致。现在标签由顶层的 `fb_vis` / `owner_eth` 推出来，
> 意愿只以一个 `*` 表示。机器判据故意造了"仲裁以为占着屏、mux 却选了图卡"这个组合，标签必须写 `CARD`。

## 1. 效果链 `pipe`：9 位 = 9 个算法，**最左边那一位是 bit0**

| 位 | 算法 | 属于哪一级 |
|---|---|---|
| 0 | 灰度 | 级1 颜色 |
| 1 | 反色 | 级1 颜色 |
| 2 | 3×3 模糊 | 级2 滤波 |
| 3 | 3×3 锐化 | 级2 滤波 |
| 4 | Sobel 边缘 | 级3 边缘 |
| 5 | 二值化（亮于阈值=白） | 级4 阈值 |
| 6 | 二值化判决反相（暗于阈值=白，只在 bit5=1 有意义） | 级4 阈值 |
| 7 | 腐蚀 | 级5 形态学 |
| 8 | 膨胀 | 级5 形态学 |

bit7 与 bit8 **同时为 1 时两个都不做**（开/闭运算要两遍 3×3 窗口，本设计只有一遍；见 `proc_morph.v` 文件头）。

**长度只有两种：5 位或 9 位，其余一律拒**（2026-09-25 r58 改的）。老代码只挡"超过 9 位"，
于是 `pipe 00001100`（8 位）被**静默当成 9 位前面补零**收下——命令收了、意思变了，敲的人只能试到
某个长度"看起来对了"。判据：`src/host/pipe_len_check.mjs`（从 main.c 抠原文用宿主 gcc 现编，
16 条用例 + 两条变异对照），板级那三条在 `board/cmd_battery_v81.txt` 里（含一条 `!sel=` 反例：
**拒了还写寄存器等于没拒**）。

**屏上 `Pipe:` 那一格不是这串 0/1**：它是五位、每位 0..3，含义是"这一级选了第几个算法"
（唯一出处 `src/rtl/video/osd_overlay.v` 第 114–125 行）。所以看到 `Pipe:00102` 不是打错字：
第 3 位是 Sobel、第 5 位是"这一级的第二个算法"=膨胀。想知道到底开着什么，敲 **`pipe show`**，
它按名字打印（`[PIPE] sel=008 生效: sharpen`）；名字表、`SEL_*` 位号、help 里那两句位序
必须与 RTL 的位定义表一致，这条一致性正是 `pipe_len_check.mjs` 的判据 A 在管的。

```
000000000   全关（原图）
100000000   灰度
110000000   灰度 + 反色
001000000   模糊
000100000   锐化          ← 看边缘比左窗"更脆"
000010000   Sobel
000001000   二值化
000001100   二值化（反相判决）
000001010   二值化 + 腐蚀   ← 白笔画变细、孤立白点消失
000001001   二值化 + 膨胀   ← 白笔画变粗、孤立黑点消失
100001001   灰度 + 二值化 + 膨胀
001010000   模糊 + Sobel   （= 老 5 位写法的 00110）
001110000   模糊 + 锐化 + Sobel（同级两个算法是**串联**的，两个都占自己的拍数）
```

阈值配合二值化用：`th 80`（0–255，默认 80）。

## 2. 片源

```
src auto     交还给按键环（= 回到自动，并把环也清回 AUTO）
src 0        钉住图卡（PL 自绘：会动的渐变底 + 彗星，自带帧号格）
src 1        钉住网络推流那一路（DDR）
src 2        钉住 SD 卡回放（DDR）并立刻开始播
stat         回读：en / thr / src / zoom / bilin / sd / frames / playing / sel / gm / mode
```
> **2026-09-25 r58 起 `src` 真的能钉住了**：以前它只写 PS 手里那 1 bit `src_sel`，
> 而"钉住哪一路"是 PL 里四态环、只有 KEY1 长按能改 ⇒ 命令打印一句"还要 mode 覆盖位"就没了下文
> （ISSUES #66：用户"发了流切不到 SD""长按要按几次"的根）。现在走 GPIO_0 `[24:23]`=模式码 + `[22]`=翻转位，
> 码与沿的先后由固件保证（两笔写），跨域在 `src_mode` 里做（码走一条与翻转位等长的延迟线）。
> **覆盖期间再按一次 KEY1 = 只交还控制权**，不会顺手多走一步；`src auto` 连环一起清。
> AUTO（`mode=0`）下屏幕归谁仍由仲裁决定：ETH 有流 → ETH；停流几百毫秒内自动交回 PS。
> ⚠ 钉在"锁网络"而当下没有流，屏幕会**冻在最后一帧** —— 这是"锁"的定义，不是坏了；
> 想知道为什么归某一路，读 `stat` 的 `mode=` 与 lane30 的 `why=`（lane30 的因果位见 ISSUES #57/#65）。

## 3. 画面与回放

```
zoom on / zoom off      右窗缩放开关（老写法 ZOOM1 / ZOOM0）
zoom 0.75               手动定档（r53 起）：八档里取最近的一档，收 `0.25/0.33/0.5/0.75/1.0/1.33/1.5/2`
                        与 `zoom auto` 交还呼吸。⚠ `zoom 1` 仍是 V7 的"开呼吸"（开关语义），
                        要 1.0 倍必须写 `zoom 1.0` —— 重叠已记 ISSUES #63，固件的拒绝消息自己会说
bilin on / bilin off    右窗双线性 ↔ 最近邻，现场对比用（老写法 BILIN1 / BILIN0）
th 120                  二值化阈值（老写法 TH120）
frame 1200              只显示 SD 的第 1200 帧（老写法 FRAME1200）
play / stop             SD 播放 开始 / 停止
sd                      重新挂载 SD（`XSdPs_CfgInitialize` 每个上电周期只成功一次，见 ISSUES #45）
fill                    PS 直接写一张四色诊断帧（查通路用）
autoplay 0 / 1          关/开上电自动播放（只影响下一次上电；老写法 AUTOPLAY0/1）
temp                    读一次片上温度（r54 起，读 PS 侧 XADC，PL 零改动）
temp th 60              改告警阈值（0..200 °C，默认 85）；`temp` 那行的 `over=` 跟着它走
gamma 1.8               明暗校正：PS 算 256 项曲线并逐项写进 PL（约 2.6 ms），只作用于**右窗**
gamma off               关掉（表保留，所以现场来回切很快）；也收 `gamma 180`（= γ×100）
help                    打印三套语法
```
> `temp` 那一行长这样：`[TEMP] degC=34.85 raw=0x9776 vccint=1003mv th=85C over=0 sane=1`。
> 两个不显眼但要紧的设计：**全程不用 float**（`xil_printf` 不认 `%f`），换算式与容差由
> `src/host/temp_formula_check.mjs` 独立核对（从 `main.c` 抠常数，与 BSP 浮点宏在全码段上比）；
> `sane=1` 是防"读回一个常数但看着很像数"（raw 全 0 会译成 −273.15 °C、全 F 译成 230.8 °C，
> 且 VCCINT 必须落在 0.8..1.3 V）。阈值可改是为了**能人为造出告警** —— 室温到不了 85 °C，
> 否则"接了但没亮过"与"根本没接"同形（八条判据在串口电池里，`--align` 先验对位）。
> `gamma` 为什么"只改右窗"就够用：本设计的语义一直是"左窗原图 / 右窗处理"，
> 所以 `gamma 1.8` 一开就是左右明暗直接对比 —— 不需要额外做"整屏 A/B 键"。
> 曲线本身（幂函数、端点 0/255、单调不降）由固件自检打印：`[GAMMA] g=1.80 mono_bad=0 first=0 last=255`；
> PL 侧"写进去什么就查什么"由台架 `sim/tb_v88_gamma`（八条，含"关着必须一动不动"的反例）钉。

## 4. 老写法（现有工具在用，都还有效）

```
SRC0 SRC1 TH80 ZOOM0 ZOOM1 BILIN0 BILIN1 FRAME12 AUTOPLAY0 AUTOPLAY1 SD PLAY STOP FILL STAT
00111     ← 5 位裸串是**老位序**：bit0 gray / bit1 binary / bit2 blur / bit3 sobel / bit4 invert
```
⚠ **5 位与 9 位的位序不同**（这是历史包袱：老工具的脚本里已经写死了 5 位串，不能断）。
换算法时的对照表：

| 想要的效果 | 老 5 位 | 新 9 位 |
|---|---|---|
| 模糊 + Sobel + 反色 | `00111` | `011010000` |
| 灰度 + 二值化 | `11000` | `100001000` |
| 只灰度 | `10000` | `100000000` |
| 只二值化 | `01000` | `000001000` |

新命令一律用 9 位；串口电池 `node src/host/uart_cmd_check.mjs` 里 `11000 → sel=021`、
`01010 → sel=030` 两条判据就是把这两个位序钉住的（写反了就红）。

## 5. 语法已经收、硬件还没接（敲了会告诉你缺什么）

```
rot 45 / rot +15 / rot auto / rot speed 1     缺 PL 的角度写入口（现在只有按键 +1°）
split 50 / split auto / split range 20 80 / split speed 2 / split swap
                                              缺"缝的执行者"：split_ctrl 已写好并单独验完
                                              （tb_v93 30 条），但**还没接线** ——
                                              可动的缝与当前"左右各 512、每半屏各画一整幅"
                                              的几何不相容，先要统一几何：**ISSUES #62**
osd on / osd off                              OSD 现在常显（V8-5 已把行内容改成四行，开关位仍缺）
```

**`zoom <倍率>` / `zoom auto` 从 r53 起不再是"待接"**：`zoom 1.5` 取最近档（八档表）并钉住呼吸，
`zoom auto` 交还给自动；回声里同时报 `[CTRL] zoom_step=<档> <档名> (手动|自动呼吸)`，
`[STAT]` 里也多了 `zsel=`/`zman=` 两项（串口电池的"末态必须等于初态"因此**覆盖**到这两个位）。

**好消息：这一段的解析器已经写好了**（V1 就把语法统一掉了，敲了会得到"缺什么"而不是静默吞），
所以接下去只差**PL 侧 + 一个寄存器写**。位预算在 `report/PLAN_V8_SPEC.md` §7a，r52 之后实况是这样：

| 位 | 现在有没有被用 | 说明 |
|---|---|---|
| `gpio_cfg1[8:0]` | **在用** | 九位算法选择字（`pipe ...` 命令） |
| `gpio_cfg1[28:26]` `zsel`、`[29]` `zman` | **r53 起在用** | V8-8 手动缩放：档号 0..7 = 0.25…2.00×，`zman=1` 才生效（0 = 自动呼吸）。与 `stage_sel` **同一个字、同一条 ASYNC_REG 链**（§7a 第三条规矩），所以 `cdc.rpt` 的配对集合没变；台架 `tb_v94_zoom_sel` 钉"表值 ↔ 档号"往返 |
| `gpio_cfg1[31:30]` | 空闲 | 留给 `split` 的 `range` 或 `sep_mode`（谁先来谁用） |
| `gpio_cfg1[20:9]` `split_x`、`[21]` `split_auto`、`[23:22]` `sep_mode` | **没人吃** | 留给 V8-4b。写进去不会有害，但也**不会有任何效果**，所以命令仍然明说"待接" |
| `gpio_cfg2 ch2 [13:8]` `gamma_disp` | **r52 起在用** | γ×10，只给 OSD 第一行 `Gamma:1.8` 那一格；PS 写 gamma 表时整字带过去（`main.c` 的 `gm_w` 是这个字唯一的真相） |
| `gpio_cfg2 ch2 [7:0]` | 空闲 | 计划放 `split` 的 `range` 两个端点（1/16 宽度单位，各 4 位） |
| `gpio_o[22:19]` | 空闲 | 计划放 `split speed`（4 位） |

`sep_mode` 是给用户报的"缝周围颜色条"留的开关：`=0` 时 `split_display` 那根硬编码蓝线**完全不画**
（那根线是**特性不是 bug**，但它现在与真正的对齐问题混在一起，看得见才好分开判）。

## 6. 三条最容易踩的坑

1. **`pipe` 生效在右窗**（左窗是原图，这是半屏对比的语义）。
2. `src`/`th`/`pipe` 之后**不必**重下发 bit；但换 **bit** 必须重下 elf（`bit/xsa/elf` 是一套，md5 说话）。
3. 想手工直接写寄存器（不发串口）：控制字在 `0x41200000`（老 32 位），
   九位算法字在 **`0x41220000`**（通道 2 在 **`+0x08`** = gamma 窗口，r47 起接上）——
   `xsdb` 里 `mwr -force 0x41220000 0x00000021` 就是"灰度+二值化"；
   gamma 窗口是 `{en[31], wr[30], data[29:22], idx[21:14]}`，
   手工写一项要**两次写**（先摆 idx/data、再把 wr 翻转），只写一次 PL 不会动 ——
   这不是坑，是协议（电平与边沿的区别），`gamma_lut.v` 头部写了为什么选翻转。
