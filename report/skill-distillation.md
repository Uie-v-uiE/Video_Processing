# 技能包的提炼过程

`skill/` 不是功能清单，也不是把 RTL 再抄一遍。它记录的是这个项目在工具、时序、验证和文档上踩过的坑，以及每条坑后来怎么被量出来、怎么被判据挡住。

## 1 包里有什么

当前包有 59 个条目，分八组：

| 组 | 条数 | 内容 |
|---|---:|---|
| `prompts/` | 8 | 提示词工作流：从算法描述推软硬件划分、从综合报告定位瓶颈、单轮改动闭环、对抗式评审、只读审查 |
| `templates/` | 4 | 工程骨架、接口契约、报告表单、脚本模板 |
| `scripts/` | 5 | 黄金比对、指标采集、寄存器映射检查、复现检查、契约生成 |
| `pitfalls/` | 24 | 判据假绿、CDC、约束覆盖、文档轮换、构建竞态、工具探针陷阱 |
| `runtime/` | 8 | 板上运行时事实：DDR 带宽、原子窗口回读、UDP 偏移重组、板级以太网/串口 |
| `references/` | 7 | 速查表：WNS 逻辑/走线、台架语法子集、报告字段图、判定行形状 |
| `zynq-video-rtl-debug/` | 1 | L0–L4 分层调试路径 |
| `frameworks/` | 2 | Vivado/板卡侧 `fpga-board-development` 与 PYNQ Overlay `pynq-overlay-development` |

每条 `SKILL.md` 按固定六节写：一句话用途、适用场景、不适用/失效条件、前置条件、使用方法、判读与失败分叉。赛题要求的四件事按下面读取：

- 适用范围：第 2 节；
- 使用方法：第 5 节；
- 失效条件：第 3 节；
- 已验证效果：第 6 节的完成判据与失败分叉。

条目的来源写在每条的出处/来源段和 `_meta/sources.md`。`frameworks/` 两条是通用框架技能，不混进本题的 57 条项目提炼；PYNQ 卡明确写“本项目未使用 PYNQ”，作为通用技能单独提交，不声称在本项目上板验证。原始评估记录和团队信息不随包；需要复现的验证过程在条目的第 6 节和 `_meta/entry-template.md` 的写法里。

## 2 从哪些事里总结

来源分四类。

**事故。** 检查脚本在等的判定行没有产出，却仍然报了通过；`catch` 存的是返回码，被误读成一次失败；`link` 命令的函数存在，但没有接进分派，板上敲命令回“不认”。这类事故写成“症状、原因、下次怎么提前发现”。

**反复出现的症状。** Tcl 查询返回空集合，被当成“对象不存在”，实际可能是查询写错了层；报告字段的位置随工具版本变化，解析脚本却按旧位置硬读。这类问题在不同轮次里重复出现，值得单独成条。

**量出来的差异。** 同一条路径在综合后和布线后的 WNS 不是一回事；同一份设计重跑一次，可能只差一行日期，也可能差出第三种结果。每条都要写清口径，否则“优化了 0.2 ns”可能只是布局摆动的噪声。

**外部资料。** AXI、RGMII、CDC 和时序约束的做法参考了厂商文档和公开的以太网栈实现；哪些采纳、哪些没有采纳、为什么，都留在条目里。

被证伪的判断不删。原来的判断、推翻它的那次运行和最后的结论并排保留，后来的人能看到“当时为什么那么想”，而不是只看到一个正确的答案。旧包里的 27 张扁平卡迁入分类目录时保留了原编号和出处，方便按症状回查。

## 3 怎么验证有效

验证口径是同一模型、同一上下文、同一工具版本，绕过技能包和使用技能包各跑一次。被控制的变量要列全；两次输入不同，读数就不能相减。

有些检查是确定性的：索引由目录生成，文本编码检查、行号引用检查同一输入跑两次应逐字节一致。有些检查只能做正反例：给一个已知坏的输入，判据必须红；给一个已知好的输入，判据必须绿。做不到这两点的判据，不写成“已验证”。

条目的第 6 节就是这条验证的记录：完成判据、失败分叉、读不到输入时的处理。原始评估记录和团队信息已经撤出提交包；它们不再作为可复核证据，条目正文和 `_meta/sources.md` 才是。

## 4 边界

**恒成立的方法。** 先有能红的判据再改代码；三态判定；读不到不等于通过；一条判据只回答一个问题；差分判据要成对。

**平台相关。** 7 系列的 IDELAY、BUFIO、ODDR 用法不能直接搬到 UltraScale+；AXI GPIO 控制面不能直接套到 MIO。每条技能写清“换平台要改哪几处”。

**工具相关。** Vivado 2025.2.1 的报告形状、xsim 的语法子集、Vitis 的组件 API 都可能在下一次升级时变化。条目里写明工具版本，并提醒“报告字段漂了就重新量形状”。

不写“适用于所有 AMD 器件”。跨板卡的迁移证据目前没有，就写“当前不具备迁移条件，需要第二块板或第二个可套用的子功能”。

## 5 和大模型协作

交付由一个主 agent 加若干只看文件、不共享上下文的子 agent 完成。每个子 agent 的产物落在自己的目录，主 agent 负责装配、复核和发布前检查。子 agent 的自述当待复核的断言处理，不因为“它说做完了”就采信。

原始轨迹留在 `report/collaboration/` 的登记卡和纠错记录里，引用时点名条目和可复核文件，不转述成“讨论后决定”。技能包的索引在 `skill/README.md`，59 个条目按症状和类别排好；这一章只讲方法，不重复列条目的名字。
