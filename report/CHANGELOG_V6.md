# 变更记录 · 第四版 V6.x（拖影 / 黑横纹 / 黑点 全过程）

本文是**逐版本的完整修改记录**：每一版写了什么、为什么写、用什么判据判定、
仿真与板级各是什么数、有没有回退。机理推导与测量方法学见
`report/V6_ROOT_CAUSE.md`，验收数据表见 `report/V6_BOARD_MEASUREMENT.md`，
工程流水线的通用经验见 `skill/` 与 `report/AI_COLLABORATION.md`。

约定：所有板级数字都是**同一块板（RK-ZYNQ7020-F，`xc7z020clg484-2`）、同一台 PC
（192.168.1.100 千兆直连 PL 口）、同一判据**（`--test frameid` 推流 → 停止 →
`rst -processor` 后 JTAG 回读两个 DDR bank → 逐 16bit 反解帧号）得到的，
不是肉眼观察，也不是不同批次的拼接。工具 Vivado/Vitis 2025.2.1。

## V6.0 —— 提交门限 + V-blank 原子换帧 + 拷贝在途深度

**改动**

| 文件 | 改了什么 |
|---|---|
| `src/rtl/eth/frame_reasm.v` | 提交条件由「累计字节数够」改成 `rows_hit==IMG_H` **且** 累计 `FRAME_BYTES`；修 `p_valid&&p_eof` 同拍的 off-by-one（`pkt_pay + (p_valid?1:0)`）；`stat_bad` 由每包一次改成每帧一次 |
| `src/rtl/top/pl_video_top.v` | 拷贝窗口从「全部消隐」收紧为「仅 V-blank + 尾部 64 像素保护」`disp_quiet`；新增 `copy_overrun` 观测位（`led[0]`：1.5 Hz 正常 / 6 Hz 曾越窗） |
| `src/rtl/video/frame_commit_lock.v` | 拷贝在 `allow` **上升沿**即启动（不等 vsync 边沿），窗口预算 +36%；`allow_rise` 用边沿脉冲而非电平 |
| `src/rtl/axi/axi_frame_writer_gated.v` | 在途 `MAX_OUT` 2→4（64 拍在途）、`SK=6`、`arlen=15` |

**判据 / 结果**

- 新增 `sim/tb_v6_cover_gate.v`（空洞帧被拒 / 完整帧提交 / `net_bad` 只在空洞时增长）、
  `sim/tb_v6_vblank_copy.v`、`sim/tb_v5_lock.v` —— PASS。
- 板级：拖影**没有消失**。⇒ 说明丢字发生在提交之前（写入链），不是显示链。
- 本版构建：WNS **+0.373 ns**，BRAM 130/140。

## V6.1 —— 入包 CDC 读侧节流 + 分包 8 字节对齐

**发现**：改变上位机速率（0.2 / 2 / 8 / 15 MB/s）时，回读到的坏字比例**几乎不变**，
且坏字掩码几乎全是 `1010` / `0101` ⇒ 不是带宽问题，是**每 N 拍才取一条**的确定性节流。
读 `eth_udp_video_top`：读侧写死「每 3 个 axi 周期取 1 条」= 66 MB/s，
而一个 1392 B 包在 125 MHz GMII 下是**连续线速**（125 MB/s）进来的 ⇒ 单包就能灌满 512 深缓冲。

**改动**

1. `src/rtl/eth/eth_udp_video_top.v`：CDC 读侧改成**每拍一条**（200 MB/s），
   并让 flush 标记永远给真实数据让路（`flush_pend` 排队，不再顶掉数据写）。
2. 上位机 `MTU_PAYLOAD` 1396 → **1392**：1396 不是 8 的倍数，会让每个 64bit 字的
   低 16bit 来自上一包（这一条当时只解决了当时的症状，**同一根因在 V6.4 才彻底修掉**）。

**结果**：单帧推流回读 **100% 落位**；但**连续推流**时最新帧只占 42~52% ⇒ 还剩一个与
「提交次数」相关的问题（进入 V6.2/V6.3）。本版起 `--test wordid` 被判定为不可用作验收判据。

## V6.2 —— 加深 CDC + 反压（**结论：方向错误，保留记录**）

**假设**：显示拷贝在消隐窗口内独占 HP0，入包写拿不到端口，打包器 512 字 FIFO 溢出被丢。
仿真 `sim/tb_v6_pingpong.v`（把拷贝等效成「每次提交后端口被独占 COPY_CYC 拍」）支持：
COPY_CYC=67200 时丢字**恰好从第 512 个字开始** ⇒ 于是加深缓冲。

**改动**：`dc_fifo` `ADDR_W` 9→13（512→8192 条，映射成真 BRAM）；打包器满时
`fifo_rd <= !fifo_empty && !sv_full` 反压 CDC。

**先失败了一次**：把打包器 FIFO 直接加深到 `FW=11` 触发
`ERROR: [DRC UTLZ-1] FDRE requires 176092, only 107000 compatible sites`
—— 打包器的 `q_addr/q_data` 被综合成**触发器**（512×96bit ≈ 4.9 万 FDRE），根本加不动。

**结果**：仿真 100%，**上板毫无改善**（42~52% 依旧）。本版构建 WNS +0.242 ns，
BRAM 138.5/140。**教训：深度只能推迟溢出，改不了「平均排空速率 < 到达速率」这件事。**

## V6.3 —— 入包写通道流水化（真正的根因修复）

**定位方法**（本版的关键不是代码而是测量）：把丢字率按**包内字节偏移**分带 ——
`src/host/ddr_stale.mjs`：

| 包内偏移 | 0–48 B | 48–96 | 96–192 | 192–384 | 384–768 | 768–1392 |
|---|---|---|---|---|---|---|
| bank0 丢字率 | **6.7%** | 54.8% | 59.5% | 59.5% | 59.9% | 60.3% |
| bank1 丢字率 | **5.7%** | 60.2% | 63.6% | 63.4% | 63.9% | 63.7% |

配套两个数：连续丢字带最长只有 15 个 16bit 字（**没有** ≥696 的整包段）；
18.6% 的 u32 里两个 16bit 属于不同帧。三条一起把机理唯一确定：
**每包的包尾被固定相位丢掉，粒度 16bit ⇒ 丢在 CDC 写侧门控 ⇒ 排空速率不足**
（长带=端口被完全占死；整包带=前端丢包；都不是）。

**根因**：`axi_frame_saver64` 的写状态机 `S_AW→S_W→S_B` **每写一个 64bit 字都要等 B 响应**
⇒ 在途深度恒为 1 ⇒ 吞吐 = 64bit ÷ HP0 往返延迟 ≈ 100 MHz/40 = **20 MB/s**，
对主机给的 15 MB/s 只有 1.3× 余量；显示拷贝一抢端口 RTT 涨到上百拍 ⇒ 平均 < 15 MB/s。
这同时解释了：1 fps 时 95.7%（窗口重叠少）、提交越密丢越多、单帧永远 100%、
以及 V6.2 为什么没用。

**改动**（单变量：只改写通道时序，`AWLEN=0` 与缓冲深度都不再动）

```verilog
localparam [3:0] OST = 4'd8;
wire beat = aw_wait || w_wait;
wire have = (rptr != wptr) && !beat && (outst < OST);
assign m_axi_awvalid = aw_wait;      // AW/W 同拍挂出，各自保持到被接收
assign m_axi_wvalid  = w_wait;
// B 只做 outst 计数回收；m_axi_bready 恒 1；计数只减不回绕（多回一个 B 也不会永久卡死）
```

吞吐上限由「往返延迟决定」变成「总线握手决定」：≤2 拍/字 ≈ **400 MB/s**，对 15 MB/s 有 26× 余量。
`idle` 仍要求 `outst==0` ⇒ 换 bank 依旧安全。

**仿真**（`tb_v6_pingpong`，扫端口被独占的拍数）

| 端口被独占 | V6.2 | **V6.3** |
|---|---|---|
| 0 | 100% | 100% |
| 67200（一个消隐窗口） | 95%，`firstmiss=512` | **100%** |
| 134400（两个窗口） | — | **100%** |
| 268800（四个窗口） | — | 74%（4608 字缓冲用满，符合预算） |

**板级**（本版构建 WNS **+0.675 ns**、WHS +0.053、0 违例；Registers 49.52%、BRAM 138.5/140）

| 推流 | 最新帧命中率 | 包内六带丢字率 | u32 内两 16bit 错帧 |
|---|---|---|---|
| 15 fps（A9 停） | 100.0% / 100.0% | 全 0.0% | 0/76800 |
| 30 fps（**A9 在跑**） | 100.0% / 100.0% | 全 0.0% | 0/76800 |
| 60 fps（18.4 MB/s） | 100.0% / 100.0% | 全 0.0% | 0/76800 |
| 15 fps（**A9 在跑**，交付工况） | 100.0% / 100.0% | 全 0.0% | 0/76800 |
| 修复前（V6.2） | 42~52% | 6.7% → 54~64% | 18.6% |

帧号跨度 = 相邻两帧 ⇒ 每个 bank 恰好一帧，乒乓切换本身不混帧。

## V6.4 —— `WSTRB` 按 16bit lane 生成（黑点根除）

**症状**：V6.3 之后推视频仍有**均匀散布的黑点**。

**A/B（同板同 bit 同会话）**

| 分包 | 最新帧命中率 | 每帧空洞（16bit 字） | 空洞内容 |
|---|---|---|---|
| 1396 B（本机多份历史 `video_sender.py` 的取值） | 99.9% | **222（111 处 × 2）** | `0x0000` ⇒ 黑点 |
| 1392 B | 100.0% | 0~2 | — |

**根因**：与速率无关，是**写选通**。1396 不是 8 的倍数 ⇒ 包边界落在 64bit 字中间 ⇒
打包器对同一个字被相邻两包各 `flush` 推送一次，而 `m_axi_wstrb` 恒 `8'hFF`
⇒ 第二次推送把自己没写的那两个 lane 填 0 覆盖过去。221 包里约 111 个跨界边界 ⇒ 111 处黑洞。

**改动**（单变量：只加掩码通路）

```verilog
reg [3:0] cur_keep, q_keep[0:(1<<FW)-1], keep_r;   // 每个 16bit lane 是否有效
// 新字：cur_keep <= 4'b0001<<wr_addr[1:0]；续字：对应位置 1；push_word 带上 keep
assign m_axi_wstrb = { {2{keep_r[3]}}, {2{keep_r[2]}}, {2{keep_r[1]}}, {2{keep_r[0]}} };
```

之后入包链**对分包长度不再敏感**。

**判据本身也被修了一次**：`tb_v6_ingress_integrity` 的 AXI 从机原来无条件整字写入、
**完全无视 `WSTRB`** ⇒ 这类覆盖 bug 在仿真里天生隐形（这就是第三版以来没人发现它的原因）。
改成按 `WSTRB` 做读-改-写并加 `+MISALIGN` 模式后：

| 1396 B +FULL（221 包整帧） | 修复前 | 修复后 |
|---|---|---|
| `words exact` | **38290/38400（差 110）** | 38400/38400 |
| `lanes_bad` | **220/153600** | 0 |
| `first bad word` | **174** = `00ae00ae_00000000`（应为 `00ae00ae_00ae00ae`，正是 `1396/8=174.5` 的跨界字） | — |
| `axi_wr` | 38510（=38400+110 次重复推送） | 38510（同样多，但不再互相覆盖） |

仿真的 110/220 与板上的 111/222 一一对应。

**板级验收**（v6.4 的 bit，故意仍用 1396：200 帧 @15fps）
两个 bank 命中率 **100.0%**、六带 **全 0.0%**、每帧空洞 **0**、帧号跨度 = 每 bank 一帧。

**本版构建**：WNS **+0.708 ns**、WHS +0.064、WPWS +0.264，115065 端点 0 违例；
Slice Registers 54588（51.30%）、BRAM 138.5/140（98.93%）、DSP48E1 用 13。
回归 **28/28 PASS**（在打包后的仓库目录里跑的，`sim/results/regression_v6.txt`）。

## 1. 尚未解决 / 已记账

| 项 | 状态 |
|---|---|
| 帧最后 4 字节偶发读到 0（`+0x4aff8`） | **未修**。8 次 bank 末帧读数中出现 4 次，15/30/60 fps 与两种分包都会；只影响 2 个像素且下一帧同地址覆盖 ⇒ 自愈、肉眼不可见；`+FULL` 不复现。怀疑帧尾 `wr_en` 与 `flush` 竞争。见 `report/V6_BOARD_MEASUREMENT.md` §4.1 |
| 右屏缩放细线闪烁 / 轻微偏移 | **不是数据问题**：`zoom_mapper` 是截断式最近邻（算了 `frac_x/frac_y` 但没用），1 像素细线在 1.0↔0.5 连续缩放里会周期性落进采样间隙。线宽改成 4 像素后闪烁消失，只剩位置偏移。→ 正在替换为 bicubic（`report/V6_ROOT_CAUSE.md` §8） |
| 主机完全不限速（`--no-pace`） | 允许丢包（覆盖门限会拒收空洞帧），不作为验收条件 |
| HP1 分离 / 突发写（AWLEN=15） | **不再必要**：V6.3 后握手决定吞吐，26× 余量；突发要处理 4KB 边界与 idle 语义（历史上 `axi_frame_saver_burst` 就是这两点挂死），风险大于收益 |
| JTAG 兜底启动 ≠ 交付态 | 正常交付应跑 FSBL/ELF；只有 FSBL 会写 SLCR `FPGA_FCM*` 一类寄存器。本文数字用的是 JTAG 启动路径（PL 通路与两者无关），但性能类结论应以 FSBL 启动为准 |
