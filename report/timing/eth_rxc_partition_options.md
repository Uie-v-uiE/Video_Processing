# `eth_rxc` 域的四种改法：逐条判断（只读核对，未动 RTL）

这份文档回答一个问题：**要让 `eth_rxc` 的余量变宽，值得动哪里**。四条候选逐条给
「前提 → 证据 → 判断 → 代价」，证据全部指回仓里的报告或源码行。这份文档**不改 RTL、不跑构建**，
所以每一条的"收益"都只写成**待量的数**，不写成结论；板上仍是 r118 那颗位流（`build/system.bit` md5 `cd04907e1369…`）。

## 1. 候选 A：把 512×100 位 LUTRAM 打包器移出 `eth_rxc` —— **前提为假，这条不成立**

- **先前写下的那条前提**：打包器 `axi_frame_saver64` 和收包链挤在同一颗 8 ns 时钟上，所以它是这个域过载的主要构成。
- **实测的连线**：`src/rtl/eth/eth_udp_video_top.v:355` 写的是 `.clk(axi_clk), .rst_n(axi_rst_n)`，
  而 `axi_clk` 是 HP0 的 100 MHz（同文件 `:5` 的时钟域注释：`gmii_rx_clk` 与 `gmii_tx_clk` 是同一根 125 MHz，
  `axi_clk` 是 100 MHz 的另一域）。**打包器本来就在 `clk_fpga_0`（100 MHz）那一侧，不在 `eth_rxc`。**
- **所以**：这条候选作废。它不是"更便宜的版本"，它是把域归属写错了 —— 本文件第 2 节连带把
  `docs/course/04` §7.4 与 `docs/course/10` 的 `eth_rxc` 行改正（那两处原先把打包器算进这个域）。
- **但同一个位置还有一条真的**：打包器的**写指针扇出**可能是那一侧最大的广播之一。
  先前记的读数是 `u_saver/wptr_reg[5]` 吃 1165 个负载，出处写的是 `build/roster_r118_after_fanout.rpt` 汇总表第 5 行——
  **那份名册现在不在盘上**（它当年没入库，属长期已知的那个洞），所以这个数字**当前无法复量、只能算待核**，
  不许当依据。复现它的办法是把同一支只读探针重跑一遍（`build/tcl/probe_timing_roster.tcl` 那一族）。
  若复量成立，可做的是**给它配复制驱动**，而这把刀已经在别的广播上被量过并否决过一次
  （#117：`eth_rxc` hold 0.050→0.035 被判红 ⇒ DECLINE），所以它属于"要单独一轮、带名册差分"的活，不是顺手改。

## 2. 候选 B：发侧协议栈从 RXC 域解耦（`verilog-ethernet` 那条的廉价版）—— **值得做，但要一整轮**

- **依据**：他工程里 MAC 之上没有任何逻辑去吃 RXC 的预算（`eth_mac_1g_rgmii_fifo.v` 三个时钟口
  `gtx_clk`/`logic_clk`/`rgmii_rx_clk`，包流在 `logic_clk` 消费，中间两只 `axis_async_fifo_adapter`）。
  本工程 `gmii_tx_clk` 与 `gmii_rx_clk` 是同一根 ⇒ **发侧 arp/icmp/udp 全压在收侧恢复钟上**，
  最差那条恰好就是发侧校验和（`u_icmp_tx`）。
- **廉价版**：不动协议，只动**时钟归属**。`rgmii_tx_clk` 本来就是 PL 的输出端口
  （`eth_udp_video_top.v:25`，直接接 `rgmii_txc`），所以可以由 PL 的 MMCM 另生一颗 125 MHz 驱动发侧，
  让 TX 协议栈有自己的 8 ns 预算，与收侧解耦。
- **代价与风险（这是"一整轮"而不是"顺手"的原因）**：
  1. 收发之间从此跨域。今天很多"发侧由收侧事件触发"的关系（ARP 请求→ARP 应答、ICMP echo→reply）
     都是同钟直连，拆开后**每一处都要缓冲**，这就是异步 FIFO 的工作量，省不掉，只是可以只做一条边。
  2. 新增跨域必须重新过 CDC 判据（`build/evidence_r75/cdc.rpt` 那一族、门禁第 6 项），
     以及 `report_methodology` 的 CDC-10/CDC-11 计数会动。
  3. 台架与上板复验要全跑：顶层 `tb_v98` + 单元 `tb_icmp_rx_len`/`tb_link_monitor` + `board_verify`。
- **预期收益**：**未量**。可参照的上界是同域里那条广播的读数（逻辑 0.904 ns + 布线 6.204 ns，§7.3 记的），
  以及"布线占比 58.4 %"这个结构事实——解耦把发侧移出后收侧端点数会明显下降，
  但**下降多少只能从一次真构建里读**，这里不给数字，只登记代价与判据。

## 3. 候选 C：#194 把 RGMII 收侧的捕获钟提前（BUFIO 或 MMCM 相移）—— **先量才能判**

- **现状**：#57 那一轮已经把 IDDR 的捕获钟从 BUFIO 改成共享 fabric BUFG，`BUFIO` 用量 1→0，
  skew 从 1.616 ns 降到 0.013–0.349 ns（`report/timing/` 那一族有记录），
  IDELAY 抽头从 15 调到 26；收侧输入窗后来在 r116 用带窗口径下扫到眼心 τ=31 并进了 r118。
- **所以 #194 现在的问题不是"要不要提前"，而是"提前之后眼心还在不在 τ=31"**：
  这一步要求一次**真构建 + 真输入窗扫描**，且 BUFIO 的快角 DCD 本机还没实测（#323 欠着）。
- **判断（后来按算术把它排到构建之前，并且就停在那里）**：这条是"物理侧"的刀，收益直接落在收侧那几条路径上，
  但**它的判据要连着 hold 与输入窗一起看**，单独看 WNS 会误判（规矩 35）。
  真正的封死条件不用跑构建也能读出来，写在被测模块自己的文件头里：
  `src/rtl/eth/rgmii_rx.v:19` 记着"数据侧没有出口：IDELAY 从 26 加到最大 **31 档只买到 0.43 ns**
  （实测斜率 ≈63 ps/tap）"，`:17` 记着这只 BUFG 的 `DCD = 5.008 ns、SCD = 0`，
  `:8-10` 记着当年 BUFIO→BUFG 那一步把采样沿往后推了 **1.683 ns**。
  把这三个数放在一起：可用档数 = 31 − 26 = 5 ⇒ 可补偿上限约 0.32–0.44 ns，
  而"提前捕获钟"想买的移动量级是 1.683 ns 那一档 ⇒ **5 档买不起**，
  这不是"收益没测出来"，是**器件档数把方向封死**。
  还有一条如实挂着：`:22-24` 记着每档实测值有三种互不一致的数（≈63 ps、≈88 ps、按 200 MHz 参考钟算的 156 ps），
  这一处**未定，不当结论用**（要翻案必须先把它量清楚）。
  ⇒ 结论：C 不进构建队列。要动它，动的不是 `IDELAY_VALUE`，而是整条钟树的相位（BD 里的 MMCM 参数 +
  重过 CDC 判据 + 台架 + 板级复验），那是另一个单变量，不叫 #194。

## 4. 候选 D：#259 补对外 I/O 约束 —— **它不买余量，但不补就是失实**

- **现状**：TMDS/LED/MDIO 这类对外引脚今天**没有任何输入/输出窗声明**；
  唯一红着的门禁项就来自这里（G1/H5 双红：6 个输出端口在 0…31 全档无解的不等式，角间差 3.411 ns ⇒ 器件边界）。
  源端窗口已经按 HDMI 规范 §4.2.4（TP1）取证过：管脚间实测 0.065/0.001 ns 对 4.000/0.300 ns 的界
  （`build/r119_window_check.mjs`），而把 `skew ≤ 0.20 Tcharacter` 当成捕获窗去绑，实测会把设计判成 −3.48/−4.90 ns —— 那是**量纲错**，不是 DUT 差。
- **判断**：这条**不改善 `eth_rxc` 内部余量**，它的价值是"声明与实测对齐"，
  以及让"对外时序"这一项从"未声明"变成"有界"。要做的量很小（改 XDC + 一次实现 + 一次 `report_io`），
  但**必须与 hold 一起看**，因为绑窗会立刻把某些路的 hold 拉紧。
  这是四子里唯一一条**该尽早做**的：理由不是收益，是不留失实。
- **做完了的三件事（读数都在盘上）**：
  ① **D1 窗量过并判 DECLINE**（第 6 节）；
  ② **D2 逐个定性**：`led`/`eth_mdc`/`eth_mdio` 走进 `build/check_io_timing_coverage.py` 的豁免表，
  理由各带行号出处（`rk_zynq7020.xdc:10-11`、`system_top.v:117`、`system_top.v:116`），
  尺子读数 `I3 bare_out_ports` 从 7 降到 4，剩下的四个全是屏那一路；
  ③ **D3 名字级对账闭合**：把归档的 `build/check_timing_verbose.rpt` 逐行数过之后，
  新增两条判据 `I7_verbose_selfreconcile` 与 `I10_names_vs_source`，真件都判绿
  （件 `build/evidence/1006_d3/io_debt_after_d3.txt`；`--self` 判 10 条 + 12 条对照全过）。
  顺带推翻一条先前写进文档的话：`checking no_output_delay (12)` 与 `There are 6 ports …` **不是两个单位**，
  而是同一个单位（每个端口位算一个、各点一行）差在射程——小标题数 HIGH+MEDIUM 两段，明细只给一段。


## 5. 建议顺序（每一条都要先立案才动手）

1. **D（#259 约束）**：最小、最不像"重构"，但它把一条长期"未声明"变成有界；代价 = 一次实现轮。
2. **B（发侧解耦）**：真正打"域过载"这一条的廉价版；代价 = 一整轮（跨域 + CDC 判据 + 台架 + 上板）。
3. **C（#194 捕获钟）**：与 B 抢同一批资源与预算，放 B 之后再单变量量。
4. **A（打包器移出域）**：**作废**，前提写错了；它剩下的可动点是写指针扇出，那要先复量 1165 这个数字。

每一条例子都遵守同一条纪律：**逐时钟名册差分**（`build/timing_roster_diff.sh`，八对 (时钟,类型) 要全配上），
本族没变好而别域变差就是**代价**，不是"没找到收益"。

**这条顺序走完之后的实际形状**（写在被引用的那份件里，不靠记忆）：
D 做了三件事（D1 量过并拒绝、D2 逐个定性、D3 名字级对账闭合，见第 4 节末与第 6 节）；
C 用器件档数把方向封死，**没进构建**（第 3 节）；
A 因前提为假作废（第 1 节）；
剩下唯一一条真正打"域过载"的是 **B**，它的前置那份只读跨域清单在
`report/timing/eth_tx_decoupling_inventory.md`——B 的动手门槛是那张表里"今天没有同步器、
只因两端同钟才安全"的那些点被逐条安排掉，而不是先把 RTL 改了。

## 6. D1 的实测结果（2026-10-05，判 DECLINE）

第 4 节那条 D 候选（TMDS 源端窗）已经量过一轮，结论写在这里以免下一份读者再去猜：

- **窗本身管用**：`VP_R119_TMDS_WINDOW=1` 的隔离构建里，`check_timing` 的 `no_output_delay` HIGH 缺口 **6 → 3**，
  并且**没有任何违例端点**（`build/evidence/1006d_tmdswindow_timing_summary.rpt`）。
- **代价在别的域**：同一轮的逐时钟名册差分（`build/evidence/1006d_roster_diff_vs_r118.txt`，八对全配上）
  `result=RED`：`eth_rxc/setup` 0.739→0.471（相对余量 9.24 %→5.89 %）、`clk_fpga_0/setup` 1.850→1.492（−19.4 %）、
  `sys_clk/hold` 0.222→0.121（−46 %）、`clk_fpga_0/hold` 与 `clkout0_1/hold` 各掉 5.7 %/6.8 %；
  唯一变好是 `clkout0_1/setup` +8.7 %。**RTL 一字未改**，这是"把 TMDS 纳入检查后工具重新布置"的连带。
- **所以默认构建不加载**：候选件与开关原样留着。这一条在尺子上留两个读数，别看混：
  我这一侧 `I3_output_covered bare_out_ports=4`（四个 BARE 输出**端口名**，就是屏那一路的
  `tmds_clk_p`/`tmds_clk_n`/`tmds_data_p`/`tmds_data_n`）；工具那一侧在未加载窗的构建里
  HIGH 缺口是 6 个**引脚名**（`led[0]`、`led[1]`、`tmds_clk_p`、`tmds_data_p[0..2]`），加载窗的那一轮降到 3
  （`led[0]`、`led[1]`、`tmds_clk_p`）。`led` 两个已经走带理由的豁免，所以尺子上的 4 与工具上的 3 不是同一个数，
  这句话本身就是"量过的债"的形状（件 `build/evidence/1006_d3/io_debt_after_d3.txt`）。
- **翻案的两个方向，每个都是另一个单变量**：给 `tmds_clk_p` 也配窗（现在那份只覆盖 `tmds_data_p/n`，
  剩下三个缺口正是 `led[0] led[1] tmds_clk_p`，与 `report/timing/debt_ledger.md` 的名单一致）；
  或把 ±4.000 ns 按板级走线失配**减掉**之后再绑。两条都要再来一轮名册差分才谈采纳。
