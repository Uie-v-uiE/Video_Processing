## 2. §3.3.4 优化目标

| 指南要求 | 落点与数字 |
|---|---|
| 取得**可测量**的性能表现并给出与基线的对比 | `report/PERF_REPORT.md`、`report/CHANGELOG_V7.md` 构建表：WNS −6.7 → +0.770；BRAM 98.93% → 64.64%；Reg 51.30% → 5.55%；推流命中率 15 fps×200 帧 198/198 帧完整、缺 0/76800 字 |
| 合理使用片上资源，**不以显著资源代价换有限收益** | 每一条资源增减都记账：#38 那一对收包逻辑 +267 LUT、BRAM **不涨**（厂商 `udp_rx` 的 FIFO 省下来正好抵）；R25 的并行译码省 85 LUT 但**没有**据此声称时序收益；UltraRAM 先把算式写对（9 块 vs 72 tile 同数量级）再谈实验，实验没收口就不写成结论 |
| 工程可由他人**从零复现** | `report/BUILD.md` §2/§3、`sim/run_sim.tcl`、`build/tcl/*.tcl`、`build/gates.sh`（一条命令读七项门禁）；目录名全 ASCII 正是为了这一条不被脚本卡住 |
| 把**判断依据**写进报告，而不只呈现结果 | `report/ISSUES.md` 每条都有"证据"段与**判据**段；`report/OVERNIGHT_LOG.md` 记的是决策与被否掉的推论；`report/VERSION_LINEAGE.md` 说明哪些代码来自厂商例程、哪些是自研 |
| 与大模型协作的经验提炼成**可复用技能包** | 同 §1 第 3 行；技能包里明确写了"从哪次失败总结出来的"与失效条件 |

## 4. 还没做到 / 待办（诚实清单）

1. **KU5P 未上板**：指南要求"作品须在板上跑通并提供实测输出"。Z7 满足；第二块板目前只有
   台架 + 门禁证据。要下的 bit 已备好：`ku5p/build/frozen_r26/ku5p_eth.bit`（md5 `14bd5752`，**只走 JTAG，绝不写 QSPI**）。
2. **SD 卡本地播放**（固件 + 显示通路复用）尚未收口 —— 需要人看屏幕，属白天项目前。
3. **UltraRAM 帧缓存实验没收口**：2025.2.1 拒绝 `ultramark`/`ultraram` 两种 `ram_style` 拼法并静默退回
   `auto`，量到的 BRAM 仍是 72 tile、URAM 0 ⇒ 结论"工具不会自己为该形状选 UltraRAM"是实测的，
   但"9 块 UltraRAM"目前只是算出来的。要真量需 UG901 的属性名或直接例化 `URAM1240`。
4. **`udp_rx_parser` 的三个统计脉冲没接可读寄存器**（`stat_drop_filt` 等）：端口过滤已进顶层，
   但"被过滤掉的包数"还不是可读数。接不接是独立小决定，没有顺手塞进 #38 那一笔。
5. **`bad` 会动这件事只有台架证据**（`tb_v795_rx_chain` 的 C2）。现场没有可靠的注错手段，
   所以板上只能报"改前是死的、改后有判据"，不报"板上见过它跳"。
