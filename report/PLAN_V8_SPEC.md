## 2. 动手前必须先定的 6 件事（不定就别开始写）

| # | 决策 | 选项 | 我的建议与代价 |
|---|---|---|---|
| **D1** | SD 到底是 **MJPEG** 还是**预转换裸帧**？ | ① 改口径为"SD 卡帧序列（PC 预转换 RGB565）"；② 真做 MJPEG 解码 | **选 ①**。②要在 PL 做 Huffman+IDCT+色度上采样（零厂商 IP 前提下是一个独立大项目），或在 PS 软解（standalone 无 libjpeg，512×300@30 也未必够）。现在这条路已经"整卡播完 + 30 fps 实测"，改成 MJPEG 等于推翻已交付的东西 |
| **D2** | 4 按键 → 2 按键怎么映射？ | ① 双键 + 短按/长按组合（0 硬件改动）；② 加编码器/矩阵键盘（要动硬件） | **用户 16:0x 答：板子上本来就是 4 个键（2 PS + 2 PL），都不用选**。PL 那两位（W18/V14）已在用；PS 那两位（MIO0/MIO12）要开 `PCW_GPIO_MIO_GPIO_ENABLE` 才读得到 ⇒ 并入 V8-2 那次重建，细节与已核事实见 §6a。**已知代价保留**：长按 KEY1 会顺带多转 1°（ISSUES #52 记过） |
| **D3** | 双线性：合入主线还是改口径？ | ① 3/5-slot 方案重试（横向 4 抽头从同一 64bit 字的 4 lane 白拿，只下一行需要读）；② 文档写"最邻近已实现，双线性组件完成、时序在收" | **先 ② 保交付，另开一晚做 ①**。①的代价是又一轮 250 MHz 时序对赌（已经红过三次），而且它**不改演示里任何一件事**，只改画质细节 |
| **D4** | Gamma LUT 怎么写进去？ | ① 新增 AXI-Lite 从设备（要重跑 BD + 全套门禁）；② 复用现有 32-bit AXI GPIO 做"地址+数据"两寄存器窗口（不动 BD） | **选 ②**。GPIO 32 bit 里 `en[4:0]`、`thr[15:8]`、`[19:16]` 已用，还有 `gpio_o[26:20]` + 高位可拼"索引+写通"；不动 BD 就不动地址约束，风险小一个量级。代价：写 256 项要 256 次 GPIO 写（PS 侧循环，微秒级，无所谓） |

| **D6** | 端到端时延测不测？ | ① 不测，OSD 不显示 Latency；② PL 打点"帧首包到达→commit"计数器（不改协议）；③ 协议加时间戳（要改上位机+收侧） | **选 ②**。③要动协议且评委现场不好复现；②只加一个计数 lane + 一行 OSD，且能给出"±1 帧"的诚实口径。在你自己的规矩下（没测过的数字不上文档）**选 ① 也比写 32ms 强** |
| **D7**（2026-09-24 晚用户定） | MIPI 与 KU5P 还留不留？ | ① 保留为"未来工作"；② **全部抛弃，只做 Z7 主线** | **选 ②：抛弃**。原话"目前是抛弃掉 mipi 和 ku5p 方面的所有内容专注完成现在这个项目"。影响：KU5P 的台架/文档/上板窗口全部退出 V8 的工作清单（已有内容留在历史提交与 `ku5p/` 目录里，不再投入）；MIPI 连"未来工作"也不写 |
| **D8**（2026-09-24 晚用户定） | 功能做完之后的收尾顺序 | — | **按用户给的次序**：① 做完 V8 全部功能（我这边的现象问题先记进 ISSUES，需要看的最后一次性列出交给用户）→ ② **深度优化一轮资源/功耗/时序** → ③ **按既有标准整体重写文档与学习文档** → ④ 上传为**新分支**版本 → ⑤ 与用户共同验证整体功能无问题 → ⑥ 再写一版**最终 main** 传 Git；过程中的一切提交就是记录（"现在的过程中的就作为记录传上去"）。⚠ **②③④⑤⑥ 的启动条件是用户明确说开始**：用户原话"在我验证和帮你看现象之后再明确告诉你开始写文档你再开始写" ⇒ 在那之前我只做功能与记录，不动文档重写、不推分支 |

**接口草图（照这个写就不用在实现时再决定一次）**：

```
video/split_ctrl.v
  #(PANE_W=512, DISP_W=1024)
  input  clk, rst_n, de, frame_start,
  input  [11:0] pos_px,        // 手工位置（像素，右窗内 0..DISP_W）
  input         auto_en, [3:0] speed, [3:0] lo_pct, [3:0] hi_pct,   // 百分比只当"端点"用
  input         swap,
  output [11:0] split_x_eff,   // 送给 split_display 的实际缝位
  output [11:0] shown_pct      // 给 OSD 的那个数（见下：除法一次一帧，逐位减）
```

* 扫描 = 自由运行计数器 + **取一位**当 enable + 三角波（先加后减），端点由 `lo/hi` 夹紧；
  **不许出现 `% 周期` 或 `/100` 的组合逻辑**（#58 那条 100 MHz 组合除法器就是死在这上面）。
* `shown_pct` = `split_x_eff * 100 / DISP_W` ⇒ 用**每帧一次的逐次除法**（24 拍移位减，纯寄存），

  缝位不动。
* 边界：`split_x_eff = 0` 与 `= DISP_W` 时不许越界读帧缓存（读坐标必须仍然夹在 `[0, IMG_W-1]`），

### 7c. V8-8 缩放因子与 OSD 的 `Zoom:`

`zoom_ctrl` 现在是 `INV_LO/INV_HI/STEP` 的三个常数在跑"呼吸缩放"，`inv_scale` 是 10 bit 的
**倒数尺度**。要显示 `0.75x` 这种数，就得有 ①一个用户可写的 `zfac`（同一个 10 bit 域）
②自动模式下由 `inv_scale` 反算一个 **定点两位小数**（商 + 余数逐位判，不除：`scale_x100 =
(1024*100 + inv/2) / inv` 这种形式**不能进 RTL**，改成查 8 档表：0.25/0.5/0.75/1.0/1.5/2.0/3.0/4.0
对应 8 个 `inv_scale` 值，OSD 显示"最近的那一档 + (Auto)"）。查表是合规做法，理由见 #58。

**V8-8 施工单（读码核对过的事实，动手时别再推一遍）**：
- 表值就是 `zoom_code` 那七个中点的**另一端**：`0.25/0.33/0.50/0.75/1.00/1.33/1.50/2.00` ↔
  `inv = 1023/776/512/341/256/192/171/128`（Q8 倒数尺度，`256/×100` 取整，一次算准写死成常数）。
  **⚠ 0.25× 那一档写 1023 不是 1024**：`inv_scale` 是 10 bit（Q8 的天花板就是 1023），
  写 1024 会**回绕成 0** —— 症状是"选 0.25× 结果画面变成一条线"，而且综合与仿真都不报错。
  `256/0.25 = 1024` 与 `1023` 差 0.02 %，档名照 0.25× 报是诚实的。台架 `tb_v94_zoom_sel` 的 T3
  拿"从倍率算出来的期望值（含 10 bit 夹取）"逐档对，就是为这一格准备的。
- **放大那一半（inv<256）硬件本来就吃得下**：`zoom_mapper` 是纯逆映射 `sx=(x−W/2)·inv/256+W/2`，
  inv 变小只是采样窗口收进画面内部 ⇒ `oob` 恒 0、不越界、不需要任何新逻辑；10 bit 也装得下 128。
  今天看不到的唯一原因是 `zoom_ctrl` 的参数把呼吸范围钉在 `INV_LO=256..INV_HI=512`（1.0x→0.5x）。
  ⇒ 所以 V8-8 只动 `zoom_ctrl`（加"手动档"），**不动 mapper、不动读口调度**。
- 呼吸的 `STEP=2`/帧 ⇒ 一档 0.75x（inv 341）到 1.0x（256）之间要走 43 帧 ≈ 0.7 秒。
  **换算方向要先弄对**：`inv` 是倒数尺度，源像素 `src = 中心 + 屏偏移 × inv / 256`，所以
  **源图里的**相邻采样点间距 = `inv/256` px（1.0x 时 1 px、0.5x 时 0.5 px）；而**屏幕**上相邻两像素
  对应的源位移 = `256/inv` px，`inv` 变 1 LSB 时它只动 `256·d(inv)/inv²` ≈ 1/(4·inv) px —— 越缩放越小。
  ⇒ "缩放时线会移位"在屏幕上看得见的那一半**不是 LSB 量化**，而是：① #54 那条整链错位（已修），
  ② 缩小以后屏幕上一条 1 px 的线跨过好几个源像素，最近邻取整会让那条线**逐帧挪动 1 个源像素**，
  在屏幕上表现为 2×/4× 的跳动。这一半只有亚像素插值能压（任务 #11 的双线性，代码在 tag
  `v7.8-bilinear-wip`）。另：`sin_rom`/`cos_rom` 是 **Q8**（`round(sin×256)`），45° 处 1/256 ≈ 0.4 %
  的模长误差在画面角上就是 ±0.2 px，同一类"看起来在抖"的来源。
- 手动档的位段按 §7a 用 `gpio_cfg1[28:26]`（`zsel[2:0]`），`[29]` 当"手动/自动"旗标，
  `[31:30]` 留空；`zoom_auto` 送给 OSD 的那一位必须跟着改成 `!manual`，否则屏上永远写 `(Auto)`。

### 7d. V8-5 OSD：用户指定的四行（原话照抄）

```
FPS:60  Src:ETH  1280x720
Pipe:11000  Th:80  Gamma:1.8
Rot:45°  Zoom:0.75x(Auto)
Split:50%(Auto)  Latency:32ms
```

* 容量：`MAX_CHARS` 从 10 加到 32，`N_LINES` 从 6 收到 4。SCALE=3 时 32 格 = 576 像素 < 1024 ✓
  四行高 4×(21+10) = 124 < 600 ✓ —— 尺寸不用动，动的只有字数与字模。
* `Pipe:` 那一格定成**五位、每位 0..3**（用户的 `11000` 就是五位，不能塞九位）：
  每位 = 该级"开了哪个算法"，`1 = 该级第一个、2 = 第二个、3 = 两个都开`，直接由 `stage_sel` 组合出来
  （`stage_sel` 已经在像素域、`effect_ctrl` 里有，OSD 只要多接这一口，**不新增跨域**）：

  | 位 | 级 | 1 = | 2 = | 3 = |
  |---|---|---|---|---|
  | 1 | 颜色 | 灰度 `[0]` | 反色 `[1]` | 两个都开 |
  | 2 | 滤波 | 3×3 模糊 `[2]` | 3×3 锐化 `[3]` | 两个都开 |
  | 3 | 边缘 | Sobel `[4]` | —（没有第二个） | — |
  | 4 | 阈值 | 二值化·亮于阈值 `[5]` | 二值化·暗于阈值 `[5]&[6]` | —（判决位不单独占格） |
  | 5 | 形态 | 腐蚀 `[7]` | 膨胀 `[8]` | 两位同时 = 1 表示"设成旁路了"（proc_pipeline 里写死的语义） |

  `Rot:` 一格**不需要任何换算**：`angle_ctrl` 的 `angle[8:0]` 就是**十进制度数 0..359**
  （KEY1 是 +1°、绕回 0），所以 OSD 直接三位十进制 + `°`；这也解释了用户报的"切模式顺带转 1°"
  —— 同一个按键既发长按事件也给 angle 加一，V8-5 之后如果还嫌别扭再单独分键（记在 #55 备注里）。
  `Zoom:` 用 8 档表（`inv_scale` 是 Q8 倒数尺度：256=1.0×、512=0.5× ⇒ `scale_x100 = 25600/inv`
  这种除法**不进 RTL**，查表：0.25/0.33/0.5/0.75/1.0/1.33/1.5/2.0 各对应一个 `inv_scale` 区间），
  `(Auto)` 后缀 = `zoom_en` 开着且用户在 V8-8 里没手写 `zsel`；
  `Split:` 的百分比同理走"每帧一次逐次除法"或 16 档表，见 §7b。
  用户例子里的 `Pipe:11000` = 灰度 + 模糊 ✓ 与老的 `00111` 记法（V7 的五位使能）不是一回事，
  文档里要写清楚"这一格换口径了"，否则拿老截图对不上；
  `sim/tb_osd_lines.v` 与 `sim/tb_v86_pipe_sel.v` 各加一条把这些语义钉住。
* 字模：现有 32 项字库只有大写与 12 个符号，**混排小写要新增 15 个**（a c e i l m n o r s t u x y，
  从这四行里逐字点出来的）+ 5 个符号（`:` `.` `%` `(` `)`），`°` 用 Latin-1 的 `0xDF` 码点映射。
  ⇒ 字库从 32 项扩到 64 项（`reg [4:0] font [0:63][0:6]`），`glyph_idx()` 保持 **case 并行译码**
  （V7.9.4 的教训：`if/else` 区间比较串成 27 级链，就是当时的全设计最差路径）。
* 每一格的取值来源都写在表里，谁不在表里就不许上屏：
  `FPS`←`fps_q`；`Src`←`src_eff={fb_vis,owner_eth_pix}`；`分辨率`←`IMG_W×IMG_H` **实参**
  （现在是 512×300；用户写的 1280×720 是示意值 —— 1 GbE 上裸 720p RGB565 要 1.06 Gb/s 装不下，
  所以这一格**只报真实几何**，要改口径由用户定）；`Pipe`←`effect_en[4:0]`；`Th`←`threshold`；
  `Gamma`←`gamma_disp`（7a 的那 6 位）；`Rot`←`angle` 查 8 档角度表；`Zoom`←`zfac`/查表；
  `Split`←`split_eff*100/PANE_W`（**除法用逐位减，或者干脆查 16 档百分比表**）；
  `Latency`←`frame_latency` 的 `q_tot` 拍数换算成 ms。
* **每个字段从哪儿来，先按"它在哪个域"分一遍**（免得又像 #57 那样接错宽度）：
  `threshold` / `effect_en` / `stage_sel` 已经是 `effect_ctrl` 同步到**像素域**的输出 ⇒ OSD 直接用；
  `gamma_disp`（新的 6 位）**并进 effect_ctrl 现有的那一条 18 位 ASYNC_REG 链**（变成 24 位）
  ⇒ 不新增跨域结构、`cdc.rpt` 的配对集合不会变 ⇒ 门禁不会因为它红；
  `split_x/split_auto/sep_mode/zsel` 与 `stage_sel` 同字同域 ⇒ 同一条链顺带过去；
  **只有 `Latency` 是新跨域**：`frame_latency` 在 axi 域，OSD 在像素域 ⇒
  先在 axi 域用**每帧一次的逐次除法**（24 拍移位减，纯寄存、不搭组合除法器，见 #58）算出 ms，
  再用"值稳定一整帧 + 翻转位过 3 级 ASYNC_REG"送进像素域（#36/#52 那一课），
  像素域 latch 一份给 OSD。台架判据：翻转一次 ⇒ 像素域必须恰好收到一次新值，
  且连续两帧之间 OSD 看到的数不变。
* `Latency:` 那一格有两条前置：① #59 的快照口必须真的自洽（板级判据 `torn=false`）；
  ② 拍数→ms 的换算**必须走"每帧一次的逐次除法"或者查表**，绝不许再来一个组合除法器（#58），
  而且它跨到像素域要用**翻转位 + 值稳定一整帧**的写法（#36/#52 那一课）。
  在 ① 未过之前，这一格钉成 `--`，不许把一个关系不成立的数画到屏上。
* **"屏上最多三位数（999），夹掉了怎么算"**（2026-09-25 自查，写下来免得被问住）：
  三类情形分清楚，别混成一句"不会发生"：
  ① 推流停了 / 屏幕归别人 / 本轮配对倒挂钳位 ⇒ `lat_sticky=1` 或 `snap_cross` 心跳 1 s 判 `hb_gone`
    ⇒ `lat_ok=0` ⇒ 屏上画 `--`（不是画一个过期的数）；
  ② 正常链路里 `tot` 是"等一个消隐窗口 + 搬一帧 + 等扫描轮到它"，上界由**显示侧**决定、与推流帧率无关 ⇒
    几十毫秒量级；
  ③ **但 ③ 是真的存在的残余**：如果搬运被长时间挡住（不是钳位、是真的等了很久），`lat_ms` 会是合法的
    四位数，OSD 三位画不下 ⇒ 静默夹成 999。这一条**机器侧看得见**：`health_read` 的 `tot_cyc/max_cyc`
    超过 99,900,000 就是"屏上那个 999 是夹出来的"，念数之前先看这两个口。
    要不要给屏上补一个 `≥` 记号，等演示口径定了一起决定（不在这一步偷偷加）。

## 7g. 屏上格式对用户原话的**四处有意偏差**（r58 之后；讲稿与答辩都要按这个说，别说成"照抄了")

实际屏上是这四类差别，每一条都是**主动选择**，不是漏做：
