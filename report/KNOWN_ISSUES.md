## 一、功能层面已确认、但这一版没修的缺陷

### 1. 帧头若干行的读侧绕回（`#98`）—— 顶层台架上唯一一条故意留红的判据

- **现象**：整屏逐像素判据里，帧头若干行会出现"读到上一帧尾巴"的绕回。判据号 `C5c`，
  红在 `build/` 里那份顶层台架报告中（每一轮都红，不掩盖）。
- **为什么现在是这样**：读侧绕回原本按"发请求那一拍"开窗，正确性依赖消隐期的长度恰好盖住延迟；
  改成按"数据写进环那一拍"开窗才是与消隐无关的口径（第一刀已落在 `r78`）。
- **复现**：`bash sim/run_one.sh tb_video_pipeline_top`，看 `C5c` 那一行。
- **为什么不修**：这一刀的改动落在读口调度上，会同时动数据通路 ⇒ 必须先给它一条"改前必须红、
  改后恰好绿这一条"的变异对照（本项目的规矩），而那条对照还没建。**留红是有意选择：
  宁可交付一条知道自己在哪红的尺子，也不交付一条被调绿的尺子。**

### 2. 旋转支上的双线性小数位（`#104`）—— **本轮（r94）已修**

- **改前的现象**：角度非 0 时 OSD 的 `bilin` 那一格显示"双线性开"，但旋转支取样的小数部分被丢掉，
  等效最近邻 ⇒ 屏幕上那一格名不副实。
- **改法**：`zoom_mapper.v` 旋转支把 `>>> 16` 之后的 `[15:8]` 接成小数。**纵向那一次
  `Y_disp = H/2 − Y_math` 的翻转必须连着 floor 一起改**（小数≠0 时 floor 多减一格、小数取 `256 − f`），
  只接小数不减那一格会在旋转态整体错一行 —— 画面上是沿角度方向的一条剪切。台账与判据形状见 `#162`。
  ⚠ **这一刀的"小数取 `256 − f`"后来被证明还是短的**：判"有没有小数"与算权重都只看了 8 位，
  小数落在 `(0, 1/256)` 时两头同时错 ⇒ 见本节末的 `#189`（r103 那一刀把它改成 16 位判 + `256 − ceil`）。
  读这一节时以 `#189` 的写法为准。
- **复现（两半都在盘上）**：改前的红 `build/r94_zoomfrac_console.txt`（结尾 VERDICT 行写 FAIL 行数=298；正文只贴前 80 行）；改后的绿
  `build/r94_zoomfrac_final.txt`（独立逐像素判据 128 次比较 0 失配；旋转态 99/99 个像素带非零小数）。
  重跑：`bash sim/run_one.sh tb_zoom_frac`。
- **当时为什么没修 / 现在动了什么**：位宽改动会进时序关键锥。这一轮确实动了它，所以时序那一侧的读数
  **只在 `build/` 的 `timing_summary` 里说**（见第二节第 1 条与 `report/OPTIMIZATION_LOG.md` 的 r94 段），
  本文不写"余量变好/变差了多少 ns"。眼睛判据（`rot 30` 前后边缘锯齿）**还没复验**，不进"已验证"那一栏。

### 3. 大角度旋转的角点出屏（`#93`）—— **本轮（r94）已修，代价写在下面**

- **改前的现象**：旋转角度大时画面对角线超出窗口 ⇒ 角点出屏，出现沿对角方向的宽彩条与左缘细线。
  原来这一条按"待定的产品决定"记录（语义是"旋转围绕视口中心、超出丢弃"）。
- **改法**：旋转真的在生效时，**实际生效的倍率被钳到 `zoom_fit` 那一档之内**（inv 越大画面越小 ⇒ 取较大的 inv）。
  钳制落在 `zoom_ctrl.v` 的 `inv_used` 那**一个**出口里（新增输入 `rotate_en`、输出 `rot_forced`），
  顶层只把 `rot_forced` 并进 OSD 的 `(Fit)` 标记 —— 于是 mapper、lane23、`status`、屏上档号四处说同一个数。
  为什么不在顶层再 mux 一次：`zoom_ctrl.v` 文件头自己立着这条规矩；我先在顶层写过一版，回退了，
  补丁留在 `build/r94_top_mux_superceded.patch` 当"走过的那条错路"的凭据。
- **代价（不美化，三条都量过）**：① 旋转态**不提供放大**，手动 1.33x/1.5x/2.0x 三档被拉回 fit，
  但用户那一档**不丢**（`inv_scale` 保持原值），关掉旋转立刻回去；② **0° 不钳**（`angle_ctrl.v` 明写 `rotate_active = (angle != 0)`）⇒ 这一钳的真实形状是"任何非 0 角度都在"，
  自动旋转逐 1° 也不例外；原文写成"0° 也在钳"是错的，已按 RTL 更正（账本 #162 追加更正）；
  ③ `zoom fit 0` **解不开**这一钳 —— 钳的是"旋转在不在生效"，不是 fit 开关（讲稿那句已改）。
- **复现**：`bash sim/run_one.sh tb_v94_zoom_sel` 看 T8a~T8f；把钳制关掉做变异对照时**恰好** T8b/T8c/T8e 红
  （`build/r94_rotfit_mutation.txt`），恢复后六条全绿（`build/r94_rotfit_after.txt`）。
  屏上"整幅到底在不在框内"由眼睛判，**这一条还没走眼睛复验**（配方：`rot auto` 起转到 45°/60°，看角点）。

## 二、性能与资源上没有做到的

1. **WNS 曾经为负，转正之后也不承诺它、更不为它写"提升 X ns"**。走势是实测的：r84/r85 全局 WNS **−0.094 ns**、失败 setup 端点 **16**；
   r86 把诊断计数器的使能改喂寄存过的事件之后，失败端点 **16 → 2**、TNS **−0.747 → −0.243**，
   但全设计 WNS 变成 **−0.135 ns**——最差的换成了同一片 `u_cdc` 邻域的兄弟路（写使能 → BRAM 的 `ENARDEN`，7 级）。
   r87 那天第一次全设计转正（**+0.152 ns、失败端点 0 / 50885**，`build/r87_timing_summary.rpt`）——
   但**这不叫余量**：同一条路在两次构建之间实测摆过 **0.4 ns**（放置抖动），
   **所以任何"WNS 提升 X ns"的说法在这颗器件这个规模上都不成立**，绝对值只认 `build/` 里那份 `timing_summary`，不认本文。
   杠杆这一栏就地更新：#121 点名的两条里，"算术侧那一刀"**已经落地**——但不是"把写使能寄存一拍"，
   而是把 `dc_fifo` 的满判据从"下一个写指针"改成"当前写指针"（与读侧对称，于是加法+格雷整条锥体
   不再挂在 `ENARDEN` 上；判据、变异对照与"顺带找回被提前一格丢掉的那个字"见 ISSUES **#139**）。
   **还欠的只剩物理那一侧**：这条路径 r87 实测 route 占 **66 %**，Pblock / 疏解绕线没做。
- **念 WHS 要先问是哪一个数，而且"哪一个最差"是跨版会换的**：本仓对 `eth_rxc` 故意加了 `set_clock_uncertainty -hold 0.800`（r79 起，只加严不放松，`src/constraints/rk_zynq7020.xdc`），
所以 **`eth_rxc` 那一格的余量是"按 0.8 ns 要求之后还剩这么多"**，不是"真实余量只有 0.0x"——凭据 
`build/clock_uncertainty.rpt`（报告里明写 `clock uncertainty 0.800`，约束确实生效）。**但这一格吃不吃这个口径要每版重看**：r92 的全设计最差 min 路径曾换到 `clk_fpga_0` 域
（`u_pl/u_lat/t_commit_reg[0] → max_cyc_reg[4]`，`Requirement: 0.000ns`、不带不确定度那一行）；
r94 实测全设计 WHS **+0.049 ns 又落回 `eth_rxc` 那一格**（`clk_fpga_0` 是 +0.060、`clkout0_1` +0.063，
`build/timing_summary.rpt` 的 Intra Clock Table）。⇒ **跨版比 WHS 之前，先确认比的是哪一格、那一格的尺子有没有动过**；而"哪一格最差"本身在两版之间就会换，所以它不是设计属性，别当趋势念。
2. **UltraRAM 换帧缓存这件事不成立也不宣称**。已核实的只有：`ram_style` 给 `ultramark`/`ultraram`
   都被综合判为无效值（`build/` 里那份 uram 探针输出）；**没核实**的是这颗器件有没有 URAM 站点
   —— 三次 Tcl 问法里**阳性对照没过，那个 0 不算结论**。对外只说帧缓存在 BRAM/分布式 RAM。
3. **端口过滤掉的包数还不是可读寄存器**。过滤逻辑进了顶层，三个统计脉冲没接出去 ⇒
   能演示"过滤生效"，不能读出"滤掉了多少"。
4. **`bad`（坏包计数）会动这件事只有台架证据**（入包链台架的 C2）。现场没有可靠的注错手段，
   所以板上只报"改前这个计数是死的、改后有判据"，**不报"板上见过它跳"**。

## 三、验证手段本身的边界（评委最常问、也最容易被含糊过去的一节）

| 边界 | 具体说法 |
|---|---|
| 只有一家仿真器 | 本机只有 **xsim**。早期可作第二意见的 ModelSim 已不在（许可证由新版 FlexNet 签发，自带客户端判 inconsistent）⇒ 凡是"两家仿真都过"的说法今天都不可复现。可复现的仿真路径只有 `sim/run_one.sh` 与 `build/gates.sh`。 |
| 仿真 ≠ 硬件的一类已知分歧 | 非打包数组的越界写：xsim 丢弃、硬件按地址位宽截断。`#103` 就是这么来的 ⇒ 本项目对这类问题**只用硬件读数收口，不用仿真通过收口**，并且专门有一条门禁判据检查"台架里有没有没被门住的越界读写"。 |
| 厂商原语的仿真模型是占位件 | `sim/prim/` 里是自建的行为级占位模型（`MMCME2_BASE`、`unisims_sim`）。跑 xsim 时看到的 OSERDESE2/BUFG 相关告警**来自占位件不是设计缺陷**，这是"仿真绿色"与"板上正确"之间必须说清的一段。 |
| 参考图不是自动生成的 | `data/golden/` 的对比图没有可一键重跑的生成脚本，只能人工比对 ⇒ 不说"与黄金参考逐像素一致"。 |
| 人眼判据是外部输入 | 屏幕上"有没有那条线"由队员判，智能体没有看屏幕的能力。凡是依赖人眼的结论，本仓库都记成"待眼睛"或"用户回报"，**不混进机器判据**。 |
| 位流与固件不入库 | 板子只走 JTAG（**不写 QSPI/SPI flash**：写了会把这台机器变成唯一能启动它的东西），所以 `bitstream/` 里那一份是**当场烧的那一版的副本**，靠 md5 认身份，不靠文件名。 |
| 首页数字与它点名的报告之间，曾经**没有对账层**（`#213`） | `README`/`README.en` 各有一行"全设计 setup WNS = 0.720 ns（板上这一版 r97）"并把 `build/timing_summary.rpt` 写成出处，而构建每轮都覆写那份报告 ⇒ 首页一定会烂。`metrics.csv` 有 D6 管，首页没有。现在 `metric_recheck.mjs` 复用同一批规则把首页那两行也判了（解析不到那一行、一行都没解析到、报告名不匹配，三种情况都判红，不许静默不判）。**它目前不进门禁**，是离线一跑：今天跑出来是 2 条真红（首页落后一轮），清它的动作排在 r99 门禁与刷板之后的文档刷新那一步 |
