## 0. 开机到"能演"：五步，缺一步就不要开始

| 步 | 做什么 | 怎么确认（不要"看起来好了"） |
|---|---|---|
| 1 | 板子 JTAG 上电，**三条按顺序**（先起 `hw_server`，否则第一句就是 `Invalid target`）：`xsdb build/tcl/ps_jtag_boot.tcl` → `xsdb build/tcl/program_pl.tcl` → `xsdb build/tcl/ps_app_reload.tcl` | 第一条打 `DDR_ECHO: 5A5AA5A5` + "PS BOOT STEP DONE"；第二条打 `PROGRAMMED xc7z020…`；第三条打 `CON: ok`。之后 LED0 以 **1.5 Hz** 跳（心跳），串口出现 `[BOOT]` 那一行 |
| 2 | 串口另开一个终端在 **COM6 115200 8N1**（或 `board/uart_cap_once.ps1 -Port COM6`） | 敲 `stat` 回一行 `[STAT] ctrl thr=… src=… zoom=… bilin=… zsel=… zman=… pub=…` |
| 3 | HDMI 接屏（1024×600） | 屏上有 OSD，`SRC:` 那一格写着 `TEST`（或 `SD`），图卡在**动**（移动块 + 帧号二值格） |
| 4 | PC 网卡 `192.168.1.100/24`，`ping 192.168.1.10` 通 | 通了再推流，否则第一幕会卡在这里 |

## 1. 三路片源与"谁在屏幕上"的仲裁（约 50 s）——本项目的"异常处理"最能看出来的一幕

**说什么**：三个片源（网络推流 / SD 卡回放 / 片内测试图卡）在无人干预下互相让位，
而且**屏幕左上角那一格写的就是屏上真的那一路**，不是"我希望是哪一路"。
本幕演可逆的那两跳（ETH ⇄ SD）；**不可逆的第三跳（SD → TEST）在第 9 幕**，原因写在下面。

```
src auto
play
```
推流：PC 上 `run_sender.bat`（或 `tools` 里那条 `video_sender`）。

**看到什么**：
* 推流一开始 → `SRC:` 变 `ETH`（没有 `*`，因为是自动让位来的），画面是推过去的视频；
* 串口 `[LINK]` 有节奏地报收到的帧率；
* **拔网线** → 屏幕立刻回到 SD 卡画面，`SRC:` 变 `SD`；
* **插回网线** → 又回到 `ETH`。本幕的两跳都是**可逆**的，所以放在最前面演。

**⚠ 本幕不演"拔掉 SD 卡"那第三跳 —— 挪到第 9 幕（最后一演）**，理由不是编排偏好而是硬件事实：
同一个上电周期里 SD 驱动不能第二次初始化成功，`sd remount` **救不回回放**
（2026-09-26 19:13 实测 `[SD] remount failed: XSdPs_CfgInitialize failed`，见 #94/#45）。
放在第 1 幕就意味着后面七幕没有 SD 这一路可用，而第 8 幕那句"回到初态"（拿首尾两条 `stat`
逐字段比）也必然对不上 —— `sd=` / `playing=` / `frames=` 三项都回不去。
**⇒ 顺序上的硬规矩：拔卡排在整场演示的最后，排在收尾 `stat` 之后。**

**演砸了怎么办**：`SRC:` 与屏上画面不一致 → 立刻 `src auto` 再看一次；仍不一致就是仲裁那一层的事，
**不要**改成手动锁源继续演（锁了就看不出"让位"了），跳过本幕去演第 2 幕。

## 2. 无极缩放 + 旋转（约 80 s）——标题里那一样

**说什么**：512×300 的源在 1024×600 的屏上从 0.25× 连续放到 2×，缩放和旋转是同一套逆映射，
倍率还能跟着角度自动收（旋转时整幅永远在屏内）。

```
zoom 0.25
zoom 2
zoom auto
rot speed 1
rot auto 1
zoom fit 1
```

**看到什么**：`zoom 0.25` 时画面只占中间一小块、四周是黑的；`zoom 2` 时只看到四分之一幅但**不糊**；
`rot auto 1` 之后画面开始转，**屏上 `ZOOM:` 那一格同步在变**（这一格是 PL 实际生效的倍率，不是设进去的档）；
`zoom fit 1` 之后转到 45° 也不会把角戳出屏幕。

**演砸了怎么办**：`rot auto 1` 会顺带把缩放切到 fit —— 不想要就先 `zoom fit 0`。
如果 `ZOOM:` 那一格不动而画面在动，说这句话不要藏（它是 #85 那条读回欠账的形状）。

## 3. 五级效果链（约 60 s）

```
pipe 000000000
pipe 000010000
pipe show
pipe 001000000
th 60
th 200
pipe 000000110
pipe 100001100
```

**看到什么**：屏上从"原图"当场变**边缘**（`pipe` 的第 5 个字符 = bit4 = Sobel）、变**二值**（bit5 + `th` 改判决阈值）、
变**腐蚀/膨胀**（bit7/bit8）；`pipe` 最左边那一个字符就是 bit0（`report/COMMANDS.md` 第 1 节的口径）；`pipe show` 按名字念出当前生效的是哪几个算法（`[PIPE] sel=008 生效: sharpen`）。
⚠ 屏上 `PIPE:` 那一格是**五位、每位 0..3**（每级选第几个算法），不是这串 0/1 —— 有人问就敲 `pipe show` 给他看。

**注意**：`pipe` **只认九位**（一位一级）。给五位的老串（`pipe 00001`）时寄存器**一个位都不写**，
串口回一行"等价的九位是：pipe …"让你照着重敲 —— 这不是挑剔，是 #66 之后屏上只有一套口径；
其它长度（例如八位）明确拒绝，拒了就不许改寄存器。bit7 与 bit8 同时为 1 时两个形态学**都不做**
（一遍 3×3 窗口做不了开/闭运算，屏上那一格也因此给 0 而不是 3）。

## 4. 同一帧的 A/B 对照（约 40 s）

```
split screen
split 50
split video
split marker 1
split show
```

**说什么**：一条缝把**同一个时钟、同一份源坐标**下的"原图"和"处理后的图"摆在同一屏上，
缝可以在屏幕里扫、也可以在画面里扫（后者跟着旋转一起走）。

**看到什么**：缝左右两侧内容严格是同一帧（拖动 `split 20`→`split 80` 时不出现"两边不同帧"的错位）；
`split marker 1` 会给缝本身画一条 2 px 标记线；`split video` 之后旋转，缝跟着画面一起转。

## 5. 双线性插值的 A/B（约 25 s）

```
zoom 2
bilin off
bilin on
bilin show
```

**说什么**：放大档的台阶是插值补掉的，而且**1:1 时插值按构造退化成最近邻**（所以老行为没被偷偷改掉）。

**看到什么**：`zoom 2` 下斜边在"硬台阶 ↔ 软过渡"之间**当场**切换；`bilin show` 念当前状态。
⚠ 这一条的"1.0 档两边一模一样"是 `tb_v101_fb_bilin` 判据 L5 逐位钉死的（4088 格），
现场只演"看得见的差别"。

## 6. Gamma（约 30 s）

```
gamma 1.8
gamma auto 100 300 20 2000
gamma manual
gamma show
```

**⚠ 参数单位**：`gamma auto` 的三个数都是 **γ×100 的正整数**（`100 300 20` = 1.00..3.00、一步 0.20，
最后一项才是毫秒）。写成 `gamma auto 1.0 3.0 0.2 2000` 会被**明确拒绝**
（`[GAMMA] auto 的 step 要的是 γ×100 的正整数（20 = 0.20）`，19:41 板上实测到就是这一句）。

**看到什么**：`gamma 1.8` 立刻压暗中间调；`gamma auto …` 在给定区间里来回扫（约 10 s 一轮），
屏上 `GAMMA:` 那一格的数字跟着走；`gamma manual` 停在当前值。
表是 PS 算好灌进 PL 的 256 项窗口，所以"算错曲线"与"接错线"各有各的凭据（`tb_v88_gamma` 八条）。

## 7. 自诊断与温度：把"数字"演出来（约 40 s）

```
stat
temp
temp th 60
rot show
split show
```

**说什么**：链路上丢了多少包、时延多少毫秒、片上多热 —— 都在板子**自己**报出来的数里，
不在我的嘴上。

**看到什么**：`temp` 回当前结温（`--` = 还没读到可信值）；`temp th 60` 之后过阈值时屏上那一格变色；

## 8. 收尾复位（约 20 s，但它是给评审看的那一句）

```
stat
pipe 000000000
th 80
zoom 1.0
zoom auto
zoom fit 0
rot auto 0
rot speed 0
bilin on
split screen
split marker 1
gamma off
temp
src auto
stat
```

**⚠ 这一份复位清单是被"排练"逼出来的，三条都是**：
* `th 80` —— 第 3 幕会 `th 60` / `th 200`；
* `zoom 1.0` —— 原来写的是 `zoom 1`，而 **`zoom 1` 是"缩放打开"**（`on|off` 就是 `1|0`），
  倍率必须写小数点形式；19:44 板上实测：写 `zoom 1` 跑完 `zsel` 还停在 7（=2.00x 档），
  写 `zoom 1.0` 才回到 4（=1.00x）；
* `zoom fit 0`、`rot speed 0` 与 **`split marker 1`** —— 第 2、4 幕各留下一个几何位，复位清单原来没写回去：
  `geom=` 从 `00400000` 一路变成 `40400400`。这里有一个**反逻辑的坑**，值得记下来：
  `cfg1[30]` 是 marker **off** 位（`main.c` 的 `SPLIT_MARKOFF_BIT`），开机默认 0 = 蓝线**画着**，
  所以"回到初态"要的是 `split marker 1`（把那个"关"字关掉），不是 `split marker 0` ——
  第一版清单写的正是 `marker 0`，被首尾 `stat` 的比对当场抓出来（回包也明明说 `marker=0`，
  而 `geom` 的位对不上：位与"人念的话"是两套，只有比对能发现）。

顺序也有讲究：`zoom 1.0` 之后才 `zoom auto`（前者把**手动档**放回 1.00x，后者把控制权交回呼吸；
反了就变成"手动停在 1.00x"，那是另一种状态）。
**每一项被某一幕改过的，都必须在这一幕里被写回去 —— 少一项就是没复位。**
首尾各一条 `stat` 不是给人看的：`src/host/demo_cmds.mjs --check` 就是拿这两条逐字段比对，
除 `pub=`（发布位每 100 ms 翻一次，本来就不该相等）以外必须全等。

**说什么**："板子被我放回了起点，而且这一步本身就是凭据" —— 把最后一行 `stat` 与第 0 步抄在纸上的那一行**逐个字段**念出来对。

**看到什么**：两行一致（`pub=` 与 `geom=` 允许不同：前者每翻一次发布就变，后者含 `rot auto` 那一位）。
不一致就是**状态没回去**，现场说清楚哪一项没回去比蒙混过去好得多。

## 9. 最后一演：拔掉 SD 卡（约 20 s + 恢复 90 s，**排在收尾 `stat` 之后**）

这一幕只有**手上动作**，没有串口命令 —— 所以它不进 `--emit` 那份排练脚本，也不参与首尾 `stat` 的对账
（对账在第 8 幕就已经判完了）。放在这里是**硬件事实**决定的，见第 1 幕那段"⚠"。

**说什么**："最后演一个更狠的：把卡直接拔掉。三件事同时发生 —— 画面 ≤0.5 秒换到片内图卡、
左上角那一格跟着改口、串口说清它是**为什么**让位的。"

**看到什么**：
* ≤0.5 秒内落到 `SRC:TEST`，图卡自己在动（移动块 + 帧号，一眼看得出是活的）；
* 串口出一行 `[SRC] PS 停心跳：片源不可信（拔卡 / 读错），画面交回仲裁`；
* **r71 之前**这一步是永久冻在最后一帧、而屏上还写着 `SD` —— 这一幕演的就是那件事被修好了
  （凭据：`tb_v102_src_life` 的 S12 钉住"PS 100 ms : PL 500 ms"的 1:5 比例，
  `board/README.md` 第 21 行，`build/evidence/r71_*.txt`）。

**演完之后怎么收场（这一段是给你自己的，不要对着评审念）**：
卡插回去 **不会** 恢复回放 —— `sd remount` 在同一个上电周期里救不回来
（`XSdPs_CfgInitialize` 不能第二次成功，#45/#94）。要恢复 SD 这一路，不必拔电源，
重跑 JTAG 三件套即可（`ps_jtag_boot` → `program_pl` → `ps_app_reload`，约 90 s；
凭据 `build/evidence/r71_after_recover.txt`：回来之后 `[SD] frame … 29.999 fps`）。
**如果明天只有一场演示**，这一幕演完就可以直接说"感谢观看"，不需要恢复；
**如果有第二场**，第二场之前必须重跑那三件套，否则第 1 幕的 `SRC:SD` 那一跳会演不出来。
