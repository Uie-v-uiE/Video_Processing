### 4b. BRAM 被谁吃掉了（`build/util_hier.rpt`，#31 实现后层次报告）

| 实例 | 模块 | RAMB36 | RAMB18 | LUT | FF |
|---|---|---|---|---|---|
| `u_pl/u_fb` | `frame_buffer_w64` | **80** | 0 | 169 | 4 |
| `u_eth/u_cdc` | `dc_fifo` | **9** | 0 | 52 | 126 |
| `u_pipe/u_blur` | `proc_box_blur` | 0 | 1 | 352 | 157 |
| `u_pipe/u_sobel` | `proc_sobel` | 0 | 1 | 228 | 81 |
| `system_top` 合计 | — | **89** | **3** | 7577 | 6026 |

89×36 + 3×18 = **90.5 个 tile**，与发布前检查里那个数一致；其中 **88 % 是显示帧缓存**：
512×300×16 b = 2.4576 Mb，80 片 BRAM36 给 2.88 Mb 容量（填充率 85 %，剩下的碎片是
64-bit 宽 + 乒乓两块拼出来的边界）。**换句话说：想再省 BRAM，只有"缩小帧缓存 / 降分辨率 /
改外存"三条路，都不是省字节的活**——所以这一项从 98.93 %（早期判为未通过的那一版）降到 64.64 %
之后就不再压了，余量留着给行缓与协议栈。

- 历史上这里写的"LUT 10621 / FF 20253 / BRAM 83 / DSP 13"是**另一个版本**（V6 时代，效果链与
  协议栈都还没收敛）的数，保留在这里只说明一件事：这份文档曾经长期失校。
- 历史明细（98.93 % → 64.64 % 怎么降下来的）见 `report/optimization_log.md`；
  逐实例的归属见上面 §4b（一张表就够，不用猜）。
- 资源侧的取舍口径是"**不为省资源牺牲功能**"：LUT/FF 都还有 80 % 以上余量，
  真正紧的是 BRAM 与 250 MHz 像素域的读口仲裁（双线性卡在这里，见 ISSUES #11/#39）。

## 6b. 2026-09-24 实测：交付率、抖动、以及"丢包会被记成什么"（bit `efc89779`）

一条命令可复跑：`node src/host/metrics.mjs --fps 30 --seconds 20 [--drop-every N] [--no-pace] --tag …`
（原始读数与表格在 `board/evidence_r41/metrics_*.json|.md`；下面每一行都对应一份 json）。

| 工况 | 发送 | 板端交付 | 验收门作废 | drop_words | CDC 灌满 | 平均帧间隔 | 由间隔算的 fps |
|---|---|---|---|---|---|---|---|
| 30 fps、限速 15 MB/s（演示工况） | 600 | 600.0 | **0** | **0** | 0 | 33.33 ms | **30.007** |
| 30 fps + 每 2000 包丢 1 | 600 | 599.7 | 66 | 0 | 0 | 37.45 ms | 26.7 |
| 30 fps + 每 200 包丢 1 | 600 | 597.0 | **597（全部）** | 0 | 0 | 没有一段可算 | — |
| 不限速，目标 60 fps | 600 | 600.0 | 0 | 0 | 0 | 16.66 ms | **60.0** |
| 不限速，目标 120 fps | 960 | 960.0 | 0 | 0 | 0 | 8.57 ms | **116.7** |
| **300 s 长跑**（30 fps、限速） | 9000 | 9000.0 | **0** | **0** | **0** | 33.34 ms | **29.99** |

读这几行要注意四件事（都是这份报告以前吃过口径亏的地方）：

1. **"交付"是 `bytes/307200` 反推的，"作废"是硬件计数器**，两者不是一回事：
   被作废的帧照样交付字节。所以平均帧间隔的分母必须是 `交付 − 作废` 再减 1（段数），
   第一版工具用"交付−1"，在"每 200 包丢 1"那一行算出了 `avg 22.4 ms < gap_min 6667 ms`
   这种算术上不可能的数 —— 现在工具会自己把这个矛盾印出来（`--selftest` 有两条钉住它）。
   另外 `gap_min/gap_max` 是本次 `--gapclr` 之后的极值，**只统计被接收的帧**。
2. **过载不是靠丢数据表现的**：不限速推到 116.7 fps（≈36 MB/s 有效载荷、287 Mbps）时
   `drop_words` 与 `cdc_episodes` 仍是 0 ⇒ 上限在**上位机与网线**，不在这条 PL 通路；
   这一版没有把 PL 顶到丢字的那一点，所以**不给"PL 能扛多少 fps"的数字**，只说"≥116.7 fps 未丢字"。
3. **"链路内时延"是两个不同的口径，别拿一个去替另一个**（2026-09-25 拆开写清楚）：
   - **(a) 一包进 PHY → 该帧被 commit**：本版本**仍然没有测**。协议里没有时间戳，PL 里也没有
     "帧首字节到达"这个打点 ⇒ 任何数字都是猜的。要测就得改协议或加一个计数器，那是下一版的事。
   - **(b) commit → 这一帧开始被扫描上屏（PL 内部）**：第 52 批起**有硬件打点**，就是屏幕上
     `Latency:` 那一格画的数，也是 `src/host/health_read.mjs` 的 lane27/lane24。口径三条必须一起念：
     ① **只有 PL 内部**，上位机编码、网线、交换机排队都不在里面 ⇒ 不许叫"端到端时延"；
     ② 单位是 axi 拍数（100 MHz ⇒ 1 拍 = 10 ns），换算集中在上位机那一个常量里；
     ③ 第三段"搬完→轮到它扫描"的分辨率 = **一个显示帧** ⇒ 报数天然带 **±1 帧**，
       所以它是"这一段等待落在哪个帧里"，不是一个精确的毫秒数。
     测量与判定条件：`frame_latency` 的三段（等消隐窗口 / 整帧搬运 / 等扫描）+ `q_*` 武装快照，
     台架 `sim/tb_v90_latency.v`，板级凭据在第 52 批的留档目录里（**这一格等那一轮读完才填数**）。
4. **丢包量化与算术一致**：一帧 221 个包，"每 2000 包丢 1"命中一帧的概率上限 221/2000 = 11.05 %，
   实测作废 66/597 = 11.06 %；"每 200 包丢 1"因为 221 > 200，每一帧至少被打一次 ⇒ 597/597 全作废。
   这两个数是对**验收门记账**的检验，不是对网络质量的检验。

长跑那一行的完整口径：9000 帧 / 1,989,000 个 UDP 包 / 5.02 分钟，
`drop_words`、`cdc_episodes`、`frames_bad` 三个计数器**全程增量为 0**，帧间隔
`min/avg/max = 20 / 33.34 / 51 ms`，墙钟交付 29.79 fps（≈9.15 MB/s = 73.2 Mbps 有效载荷）。
读数与表格在 `board/evidence_r41/metrics_r41_soak300.{md,json}`。

**SD 本地回放这一侧的速率**（同一块板、同一份素材 512×300 RGB565 @30 fps）：
固件自己按 100 帧窗口报速，整卡 4398 帧（9 个文件）连续播完并自动回绕，
窗口速率 29.2–30.0 fps、自开播起的累计值 ≈29.85 fps。
并发工况也测了：**30 fps 推流正在跑**的同时监听 165 s，SD 帧窗 `1804→4304→回绕→2306`
全程零失败（那次跑的是 SD 与 ETH 同时在的两条源；修根因之前这条工况必停在第 3584 帧。原始串口捕获已随上板捕获一起移出仓库，见提交 `58faa85`）。
凭据：`build/frozen_r32_sdfix/`（elf `c00b6553`，bit 仍 `efc89779`）。
口径边界：这些是**读取+发布**的速率，不是屏幕观感判据；"此刻屏幕上显示哪一路"仍属未确认项。

抖动（同一轮 30 fps 限速）：帧间隔 `min/avg/max = 22 / 33.33 / 45 ms`，
墙钟交付 27.2 fps（含发送端启动与 JTAG 读数开销）⇒ 报告里"交付率"一律用**间隔反推的 30.007**，
墙钟值单独列，不混用。

1. 数据面 PL 卸载后延迟确定，PS 仅控制。  
2. 右屏无极缩放与效果/旋转/选源可同时工作。  
3. 时序全局收敛；资源与功耗处于 XC7Z020 合理区间。  
4. 自写 FIFO + OSD 为可复用基础模块。  
5. 可后续升级：双线性插值、消隐期写帧缓减拖影。

### 10.3 带宽预算（为什么 V-blank 内拷贝一定够）
- 显示拷贝一帧 = 38400 拍（64bit），可用窗口 = 25 行 × 1344 = 33600 pix 周期
  = 67200 个 axi 周期 ⇒ 下限 **0.571 拍/周期 ≈ 457 MB/s**；实测 `copy_cycles ≤ 67200`
  （`copy_overrun` 标志从未置起，`led[0]` 保持 1.5 Hz 心跳）。

  缓冲（CDC 8192 + 打包器 512 = 4608 字）可吸收 **≈2.5 ms** 的端口完全独占。
