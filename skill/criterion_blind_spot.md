# S21 · 判据的"结构性红不了"：绿的那一格可能根本没给缺陷留地方站

## 触发
- 当一条**新写的**判据第一跑就绿，而它要判的缺陷是真实存在的（人眼已经看见、或别处已经量到）
- 当你选的档位上，缺陷显形需要的那个"背景/对比度/余量"结构上不存在：被检对象铺满整个域 ⇒
  一句"每行至多一段非黑"在这里是恒真式，可它看起来像一条通过了几何检验的硬判据
- 当扫描矩阵是按"方便的档位"取的，而不是照现象原话里的"当…时"取的；或诊断图案只有一种尺寸/频率
- 当差分判据只有单边（只问"要随圈内邻居变"，不问"不许随圈外回绕源变"），或正对照落在一个本来就不该动的格子上
  （平场里梯度类算子恒输出 0、探针幅度大到饱和 ⇒ 对照永远不动或两档同一个数）
- 当循环上界、例外分支、跳过条件用的是**被截断的字面量**或**被测信号自己** ⇒ 一整轮判据可以一次都没跑，屏幕照样打满 PASS
- 当**判据自己的标识**被容器截断：名字参数只有 100 字节而中文按 UTF-8 是 3 字节/字 ⇒ 超长部分从**左边**被削掉，那条判据在日志里的编号根本不是 `T8e`，"六条只数到五条"看起来像没跑到那一支（#162：新写判据一律 ASCII，并数一遍条数）
- 当那句"绿"建立在读回来的数据上，而数据可能是 X、空集、一份被两次运行交替写的日志、或一个初态本来就脏的 `初态 == 末态`
- 当"不许出现"那一类反例判据比较的是**正则的源串**（带着转义反斜杠），于是它找的是固件永远不会打的字面 ⇒ 几条反例一起空跑，"命令收了却不写寄存器"这类红结构上抓不到（#165：修活之后**当场**又抓到一条反例本身写错，因为固件的正确回声里就含那个串 —— 反例要钉到违例的**那一行**，不是钉到一个词）

## 不适用
- 判据红且能指出具体一格：那是真账，走"先量后修"；红了而硬件其实对是镜像面 [S20](bench_self_inflicted_reds.md)
- 纯组合逻辑的等价性检查：那里没有"激励维度"这件事
- 覆盖率已由独立机制证明充分（没有这种机制时，别拿本页当免检）
- 判据要判的本来就是恒真式（例如拿时序台架去验一个纯组合译码）：要换的是**判据类型**（改成逐格反解），加维度不会让它变红

## 动作
1. 写判据之前做"空位"检查（五分钟）：把缺陷的完整表现写成一个**可观察谓词**，再问"这一格的激励里，
   使该谓词可观察的那个背景/对比度/余量存在吗？"形状类判据就一句：被检对象与它应当区别于的东西，
   是否真的在同一个像素域里被分开？
2. 反例自造（最便宜、最有牙）：把被测对象的一个输入强行钉成"缺陷态"（force 一个内部寄存器、置一个控制位、
   盖一个黑块），看判据**能不能红**。不能红 = 这一格没给缺陷留地方 ⇒ 换激励维度，**别换阈值**。
   这与"新判据必须既能红又能绿"是同一句话的两半，"能红"那一半经常被跳过
3. 先问新判据**跑了几次**：给它配一条只打印一次的现场行，日志里没有那几行就是没跑，而不是"跑了且绿"；
   顺手检查循环边界字面量的容器位宽（装不下的上界会被截成 0，条件恒假）
4. 差分必须成对：`要随圈内邻居变`（抓旁路）+ `不随圈外回绕源变`（抓回绕）；只写前一半天生对
   "取或"型结构恒绿（回绕进来的那格与中心同值，夹不夹都一样）
5. 对照格定义成"在这一维上唯一会被这个改动影响的那一格"，写判据之前先算它会不会动；
   背景亮度与探针幅度都不许选到"所有必须变的对照一起哑"的那一档
6. 按现象的**自变量**给扫描矩阵补维（代价最大，所以最后做）：那句"只要…就在"本身就是维度声明，
   扫描集必须含那个自变量的非平凡值；维度不只是角度与倍率——激励的**栅格比例**（每两条显示行走一条源行时，
   窗口的中心行在成对两行里不是同一个源行）、图案频率、反压都是维度
7. 加固"读回再比"与例外：这类判据必须配一次**同一次采集里的 X/空集检查**加一条**覆盖地板**
   （被量到的样本数 > 阈值；地板与被检判据同生共死，样本数为 0 时那句绿不算通过）；
   采集窗口的代码要与注释对得上，只改阈值不算修；例外不许用被测信号当门（病灶恰好满足被跳过的条件时这一族从此修不红），
   例外只能由期望式子自己推出来，那一格仍照判，跳过数只是给人看的统计不是免检口
8. 加固凭据与不变量：凡"一个名字、一份文件、多次写"的凭据都要问"还有谁往这里写"——按校验和认源认的是
   "哪一份源码跑的"，钉不住"这一份文件是不是只有一跑写过"；见到还活着的仿真进程就退出并说清该杀谁（不自动杀）。
   `初态 == 末态` 型判据必须**同时**钉住"初态是已知的默认态"（跑之前先显式复位再读一次），
   否则它只在起点干净的那一次有牙，而那次往往没人看
9. 加固被测对象的形状：总线从机模型里至少一处主动把 `ready` 拉低过，否则这条通路只验了**不拥塞**
   （反压那一维结构上不可能红，而它报出的绿会被读成"通路已验证"）；除大色块外另备细线/棋盘/文字这类高频图案，
   两把尺子一起念；靠层次名成立的判据，改完结构就 grep 一次那些名字还在不在原位
10. 措辞分清"病"与"定义"：钉在病灶上的措辞在修好之后会红（这是好事，但要有心理准备），
    提前换成"定义 + 覆盖地板"，别到时候凭"红了就回退"的规矩把修复本身退掉

## 完成判据
- 一条能执行的裁决：输入 force 成缺陷态 ⇒ 判据必须红，撤掉 ⇒ 必须绿；两个方向缺一个，这一格判作废、去换维度而不是换阈值
- 数字关系：每一格先自报"被量到的样本数"并过覆盖地板（本工程那条是"有画面的行数 > 200"）；
  样本数不达标的绿不算通过，把地板调低更不算
- 正证尺子会分辨位置：不旋转那一格量到的首/末列区间要**正好等于几何应给的那一条带**，
  非单位倍率那几格量到的**画面带宽度**要等于"有效宽 × 倍率、按中心取整"，两侧留出可对证的背景 ⇒
  证明它不是恒输出、也不是恒绿
- 补维的回报能念出来：补维之后那句"没看见"意思是"在缺陷能站身的格子里也没看见"，
  与只跑恒真档位时的"在根本没有背景的格子里没看见"完全不是一回事；此时病灶从"台架没覆盖"移到
  "台架里没有的东西"（真实片源 / 物理层字流 / 面板采样）——那是一个**下一步该去哪里**的结论，比一条绿值钱

## 失效边界
- "空位"与被检对象同源时，加维度只会让两段一起错（背景本身由被测逻辑算错）⇒ 必须另找一条独立参照的尺子，两把一起念
- 覆盖地板被拿掉 ⇒ 本页全部作废（空集上的绿；同一形状在门禁侧的前科见 [S16](cdc_pair_baseline_gate.md)）
- 本页管"能不能红"，不管"有没有病"：结果为"补维之后仍不复现"不让这条失效，尺子的职责是前者
- 与 [S20](bench_self_inflicted_reds.md) 的分界：假红（期望值差常数倍、采样相位、起点没复位）在那页；
  本页只处理"绿得没牙"。上面登记的形状没有一条是阈值问题，全部是激励/扫描/例外/凭据/被测对象形状的问题
- 引用凭据要说清是哪一份：新判据的数在刷新冻结件之前只有实时日志可查，拿旧冻结件冒充新判据是另一条纪律的事

## 出处
同族两例（2026-09-30，r94）：**收尾解析只认两种判定形状**，`TB RESULT PASS|FAIL` 那一族被报成 "NO-VERDICT + FAIL 行数=0" ⇒ 红与"没数"在输出里长得一模一样（#163，配 `build/r94_verdict_ce.sh` 三条对照，第一版候选还被自己的"不许把没数当 PASS"那条打回）；**门禁在两份报告缺席时把空结果当合法的 0**，于是"20 项全判定"的绿依赖文件存在而从没人查过文件存在（#164），`run_one.sh` 判红仍 exit 0 让调用方的保护永不触发（#166）。
一条形状尺子在全域铺满的那几档全绿、补维之后才承认结构上不可能红（`report/log/ISSUES.md` #93）；登记的那一族"绿着错"来自同周的两轮（#97）与更早的"测量工具自己会造假"、"从机模型把被测对象伪装成死锁"（#34、#35）。
