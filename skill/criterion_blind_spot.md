# S21 · 判据的"结构性红不了"：绿的一格可能根本没有给缺陷留地方站

## 适用场景

一条**新写的**判据第一跑就绿，而它要判的那个缺陷是**真实存在**的（用户眼睛已经看见、或别处已经量到）。
这时要怀疑的不是硬件，而是这一格的**激励里没有缺陷可以显形的位置** ——
它和"假红"（见 `bench_self_inflicted_reds.md`）是同一族问题的镜像面：

| 情形 | 症状 | 该问的第一句话 |
|------|------|----------------|
| 假红 | 红了，硬件其实对 | 期望值是不是从被测代码抄的？采样相位对不对？ |
| **结构性绿** | **绿了，缺陷其实还在** | **这一格里，缺陷要显形需要的那个"空位"存在吗？** |

**不适用**：① 判据红且能指出具体一格（那是真账，走"先量后修"）；② 纯组合逻辑的等价性检查
（没有"激励维度"这件事）；③ 覆盖率已经由独立机制证明充分（本仓库还没有这种机制，所以别拿这条当免检）。

## 本仓库的现场（2026-09-27，ISSUES #93）

现象（用户报的，板上 r70/r75）：旋转到大角度 ⇒ 对角出现**一道宽彩条**；缩放只要不是 100 % ⇒
屏幕左缘**一条细线**画的是旋转前的内容。

给顶层台架加的尺子 C4 是**按形状**判的（不猜坐标）：一条旋转后的矩形被任何水平线切到，
只能切出**一段**连续区间 ⇒ "某一行的非黑段数 ≥ 2"就是那两道多出来的东西。
第一跑四个角度全绿（每档 780 行有画面、`多段行=0`）。**这一句绿是假的**，原因是倍率那一维选错了：

```
C4 idx=0..3  zoom=100%   有画面行=780  多段行=0     ← 结构上不可能红
```

1.00x 时画面**铺满整屏** ⇒ 屏上没有一列背景 ⇒ 多出来的细线/彩条**贴在**同一段非黑区间里 ⇒
段数仍然是 1。"每行一段"在这一格是恒真式，而它看起来像一条通过了几何检验的硬判据。

把尺子架到**看得见病**的那一格：0.50x 两侧各 256 列背景、0.25x 各 384 列 ——
背景带就是那条多出来的线的"舞台"，它一出现就必然是**第二段**。
（黑 ⇔ 画面外 这个等价关系不是假设，由 C0a3 先证明测试图卡 300×512 格里没有一格编码成全黑。）

## 照抄可用的方法：三条自查，按代价排序

1. **"空位"检查**（写判据之前，5 分钟）：把缺陷的完整表现写成一个**可观察谓词**，
   再问"这一格激励里，使该谓词可观察的那个背景/对比度/余量存在吗？"
   具体到形状类判据：*被检对象与它应当区别于的东西，是否真的在同一个像素域里被分开？*
2. **反例自造**（最便宜、最有牙）：在台架里把 DUT 的一个输入**强行**钉成"缺陷态"
   （本仓库做法：`force dut.angle`、`split_ctl_tb[13]`、盖一个黑块），
   看判据**能不能红**。不能红 = 这一格没给缺陷留地方，判据要换激励维度，别换阈值。
   这条与 S20 的"新判据必须能红也能绿"是同一句话的两半：**能红**那一半经常被跳过。
3. **扫描矩阵按"现象的自变量"补维**（代价最大，所以最后做）：
   用户那句"只要缩放到非 100 % 就在"本身就是**维度声明** —— 判据的扫描集必须含那个自变量的
   非平凡值。写判据时把现象原话里的"当 … 时"抄进注释，扫描矩阵照它取，而不是照"方便的档位"取。

## 已验证效果

- 1.00x 四档：`多段行=0`（已确认为**结构性绿**，见上）；90° 量的第 1 列/末列 = `[212..212]`/`[811..811]`
  正好等于几何应给的 600 列带 ⇒ 这把尺子**会**分辨位置，不是恒输出。
- 0.50x / 0.25x 八档（补维之后）：**也全是 `多段行=0`**，而带宽按定义收缩到位
  （不旋转 `256..767` = 512 列、`384..641` = 258 列 = 半宽 `512·256/1023` 按中心取整；
  90° `362..661` = 300 列、`438..587` = 150 列）⇒ **补维有回报**：现在这句"没看见"是
  "在缺陷能站身的格子里也没看见"，与只跑 1.00x 时那句"在根本没有背景的格子里没看见"
  完全不是一回事。
- ⚠ 本条的**结果是"没抓到"**，但它不因此作废：尺子的职责是"能不能红"，不是"有没有病"。
  补维之后仍不复现 ⇒ 病灶从"台架没覆盖"移到"台架里没有的东西"（真实片源 / PHY 字流 / 面板采样）
  —— 那是一个**下一步该去哪里**的结论，比一个"绿"值钱。
- 出处：`build/tb_v98_report.txt`（C4 那十二行），随 `build/refresh_evidence.sh 75` 进
  `build/evidence_r75/tb_v98_report.txt`。**在刷新之前这一条只有实时 `run.log` 可查**，
  念它的时候要说清是哪一份 —— 拿旧冻结件冒充新判据正是 S15 那一条防的事。

## 已经记下来的"绿着错"（按发现顺序；**编号会继续长，别把它当上限**）

第一组来自 `sim/tb_edge_rim.v` 那两轮（2026-09-27，ISSUES #97），第二组是从被合并的 S3
（原 `axi_stream_verify.md`）搬过来的三条"台架根本没在测你以为它在测的东西"。

1. **整轮判据可以一次都没跑，而屏幕打满 PASS**。`for (stage = 2'd0; stage < 2'd4; ...)` 里
   `stage` 是 `reg [1:0]`，于是字面量 `2'd4` **也被截成两位 = 0** ⇒ 条件恒假 ⇒ 四家差分判据
   全部跳过，`RESULT … PASS` 照样打印。**自查**：任何"新加的判据"，先问它**跑了几次**——
   给它加一条只打印一次的现场行（`D1 stage=…`），日志里没有那几行就是没跑，而不是"跑了且绿"。
   这一条是被"变异红不出来"抓到的，不是被思考抓到的。
2. **单边差分判据对某种算法结构上恒绿**。只问"边缘要随邻居变"，在 `blur/sharpen/sobel` 上能红；
   但形态学膨胀是 `any1`，回绕进来的那一格与中心同为暗 ⇒ 夹不夹都一样 ⇒ 关掉左夹照样绿。
   ⇒ 差分必须**成对**：`要随圈内邻居变`（抓旁路）+ `不随圈外回绕源变`（抓回绕）。
3. **正对照可以落在一个"本来就不该变"的格子上**。原来拿第 20 列当对照，而激励是平场，
   Sobel 对平场恒输出 0 ⇒ 对照永远不动 ⇒ 一旦判据红，说不清是被测对象坏还是激励坏。
   同类：背景选暗，腐蚀(`all1`)到处是 0，三条"必须变"的对照一起哑；锐化探针选大对比度，
   `5c−Σ4` 直接饱和到 0/31，两档跑出同一个数。
   ⇒ **对照格的定义 = "在这一维上唯一会被这个改动影响的那一格"**，写判据时先算它会不会动。

4. **绿建立在 X 上**：采集窗口写的是"第三、四帧"、代码留的却是**头两帧**（计数器每轮归零），
   而复位后第一帧的行缓存是 X ⇒ `X > 门限` 为假，"比较"一条都不算不符 —— R1~R5 可以整体假绿。
   ⇒ 凡是"读回一段数据再比"的判据，配一条**同一次采集里的 X/空集检查**（这里就是 R8），
   并且采集窗口的那几行代码要与注释对得上；只改阈值不算修。
5. **激励的"栅格形状"也是一个维度**：窗口级全部用 **1 行 = 1 源行**的栅格量，而设计喂链子的
   `y_in` 是**源行**、显示栅格每两条行走一条源行 ⇒ 窗口的"中心行"在成对两行里一次是 k−1、一次是 k。
   这个差别在 1× 激励里**无法表达**，于是"上沿旗标多夹了一次"错了整整一显示行而六条判据全绿。
   补上 ×2 那一格（R7）立刻红一条、位置精确到行 ⇒ 与 S21 同一课，但维度不是角度/倍率，是**栅格本身**。
6. **例外条件不许用被测信号当门。** `tb_v98` 的 C1h 旧写法是
   `if (dut.sy >= 299) 跳过; else if (与期望不符) 计数;` —— "跳过"这一支的判据正是**被验的那个坐标**。
   帧底那几行如果绕回没生效，`sy` 恰好还是 299 ⇒ 被自己跳掉，这一族从此**修不红**。
   ⇒ 例外只能由**期望式子自己**推出来（"我算出来这一格该是夹紧值"），并且那一格仍然照判；
   跳过数照数只是给人看的统计，不是免检口。同一族的另一处：C0e 那种"出界桶必须是不符集的子集"。
7. **判据把"病灶"当定义钉住，修好之后反而会红 —— 这是好事，但要有心理准备并改判据的措辞。**
   C1d-b 原来钉的是"帧头被跳过的那几格内容必须 == 43（=299 的低 8 位）"，那**正是病**（行环在帧头
   读到上一帧帧底、地址夹在末行）。读侧改成绕回之后，那几格的内容变成"本行自己要的那一源行" ⇒
   旧措辞立刻红。⇒ 写例外的时候，问一句"这句话描述的是**病**还是**定义**"：
   如果是病，修好之后它会红，那就提前把它换成定义 + 一条覆盖地板（这里是 `c1_ring_n > 1000`），
   别等到时候凭"红了就回退"的规矩把修复本身退掉。
8. **一份日志可以是两次跑的混合，而头部 md5 全都对。** `run_one.sh` 每次固定写
   `/tmp/kx/<tb>.run/run.log`；`TaskStop` 杀掉的是**包装的 bash**，它的 `xsim.exe/xsimk.exe` 还在跑，
   于是新旧两跑往同一个文件里交替写行。症状是**自相矛盾的计数**：
   `RESULT … nfail=3` 而 `grep -c "^FAIL " = 1`，同一份文件里既有旧措辞的判据行又有新措辞的。
   ⇒ "认 md5 不认文件名"钉的是"哪一份源跑的"，钉不住"这一份文件是不是只有一跑写过"。
   防法已经进脚本：`sim/run_one.sh` 见到活的 `xsim.exe` 就 **exit 3** 并说清该杀谁（不自动杀）。
   推广：**凡是"一个名字、一份文件、多次写"的凭据，都要问一句谁还会往这里写。**
9. **差量不变量（初态 == 末态）在"起点已经是被污染态"时会假绿。** `uart_cmd_check` 的收尾比对
   "电池不许改变板上状态"在 r75 上是 97/97 绿，r77 上却红在 `mode: 0 → 1`。读下去才发现
   命令组里最后一条会钉源的是 `src 1`，而复原用的 `src auto` 排在它**前面** —— 这个漏一直在，
   只是 r75 那一次板子的**初态本身就是上一次电池漏下的 mode=1**，于是"初 == 末"自动成立。
   ⇒ 凡是 `before == after` 型判据，必须**同时**钉住"`before` 是已知的默认态"（或跑之前先显式复位再读一次），
   否则它只在"干净起点"的那一次才有牙，而那次往往没人看。

10. **台架的从机模型太理想 ⇒ 反压这一维上结构性不可能红。** `ready` 从头到尾没被拉低过的 TB，
    验不出"FIFO 满时被挡住那一拍丢数据"这类缺陷，而且它报出来的绿会被读成"通路已验证"。
    自查：`grep` 你自己的台架，`ready` 有没有至少一处被主动写 0；一处都没有 ⇒ 这条通路只验了**不拥塞**。
    来源：ISSUES #35（从机模型把 DUT 伪装成死锁——看到 master"不排空"，先验 TB 从机的 B 通道：
    是不是只有一个 B 寄存器、是不是用组合 ready 握手、是不是拿上一拍的 AW 地址配这一拍的 W 数据）。
11. **诊断图案只有一种形状 ⇒ 现象没有落脚的地方。** 大色块图案对"细线跑错位置""一段多出来的带"
    结构上不敏感；必须另备细线/棋盘/文字这一类**高频**图案，两把尺子一起念。
    来源：ISSUES #34"测量工具自己会造假"，与 [S9](frameid_loss_signature.md) 的恒定图案误判同族。
12. **判据指向的对象会漂移。** TB 用**层次名**（`dut.u_xxx.sig`）引内部信号时，重命名/抽模块之后
    它可能静默地在测另一个东西——不报错、不告警、日志照绿。凡是靠层次名成立的判据，
    改完结构就 `grep` 一次那些名字还在不在原位。来源：`report/OVERNIGHT_LOG.md` R06。

**共同点**：十二条都不是阈值问题，全部是**激励/扫描/例外/出处/被测对象形状**的问题 ——
与本文件开头那句话一致：判据红不了，就改激励的维度，别改门限。

## 失效条件（这条经验什么时候不成立）

- **判据要判的本来就是恒真式**：例如用及时序台架验一个纯组合译码，加维度不会让它变红，
  要换的是**判据类型**（改成逐格反解），不是扫描范围。
- **"空位"与被检对象同源**：如果缺陷显形所需要的背景本身就是被测逻辑产生的
  （例如背景带由同一个 mapper 算错），那么加维度只会让两段一起错 ⇒ 必须另找独立参照
  （本仓库的做法：另用 C2 那条"逐列反解定义"的内容级尺子，两把一起念）。
- **覆盖地板判据被拿掉时，这条全部作废**：`C4a rows judged > 200` 与 C4b 必须同生共死 ——
  若一格的样本行数为 0，"多段行=0"就是空集上的绿（同一个形状在门禁侧的前科见
  [S16](cdc_pair_baseline_gate.md) 与 ISSUES #65）。**永远不许为了变绿调这个阈值。**
