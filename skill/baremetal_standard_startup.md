# S13 · 手工链接裸机 ARM 应用：改入口符号 = 改整条标准启动链

## 触发

- 当你**不用 IDE** 产出裸机镜像（手调交叉 gcc + 现成 BSP 静态库，因为交付要求"从零可复现"，而"在 IDE 里点新建工程"不是可复现步骤）。
- 当你改链接脚本里的 `ENTRY(...)` 符号 —— 哪怕只是"修一个 bug"的一行改名。
- 当链接脚本里出现过向量表段、boot 段、页表段、各模式栈符号这一类名字：它们**预期**有人把标准启动那几个 `.S` 链进来；没在镜像里就是缺件。
- 当症状彼此"互不相干"：第一条浮点指令陷 Undefined、板子"像自己重启了一遍"、`memcpy` 报对齐异常、复位一次就好、只在 MMU 关着时才出事。
- 当你准备在 0x0 摆自己的代码，或只补一条"设 CPACR"的土桩。

## 不适用

- 正常经 bootROM/FSBL 起、且不要求"纯 JTAG 就能跑"的固件（那份标准启动由 FSBL 带着）。
- 平台库不是 SDT 流程生成的、`USE_AMP` 多核、或应用跑在 DDR 里 —— 那几个 `.S` 的前提会变（见失效边界）。
- 软核或非 Cortex-A：向量表 / CPACR / VBAR 这套是 ARM 的。

## 动作

1. **查**镜像里有没有标准启动，三条命令就够（通用形态：符号表 + ELF 头 + 反汇编头 0x20 字节；本仓库把它们写进构建脚本的自检里）：

   ```bash
   arm-none-eabi-nm -n app.elf | grep -E "_boot|_vector_table|MMUTable|_start|IRQHandler"
   arm-none-eabi-readelf -h app.elf | grep Entry        # 入口必须等于 _boot
   arm-none-eabi-objdump -d --start-address=0 --stop-address=0x20 app.elf
   #   0x0 处必须是 b _boot；0x4 / 0x10 必须是 Undefined / DataAbort 的入口
   ```

2. **缺件就显式把那几个 `.S` 编进来**（异常向量、启动、页表各一份），编译开关与 BSP 自己一致（例如 `-DSDT`）；`-Wl,-u` 或 `KEEP` 不算"请回来"，让它们成为入口的下游最干净。
3. **把入口写回链接脚本**（`ENTRY(_boot)`），**不要用命令行 `-e`**：脚本里的 `ENTRY()` 会顶掉它，ELF 入口悄悄变成 0x0、一声不响。链接器的"入口"有两个来源且覆盖不报错 —— 这是本条要记的第一课。
4. **加两道等值哨兵，而不是存在性哨兵**：ELF 入口地址 == `_boot`；向量表符号必须在 0x0（复位后 VBAR 就是 0，表放别处等于没有表）。
5. **别在 0x0–0x1C 摆自己的代码**：`V=0` 时那正是异常向量区，于是每一次异常都变成一次"看起来很干净的重启"。
6. **顺手核 MMU 与对齐这条链**：MMU 关着时非对齐访问一定 fault（对齐豁免只在 MMU 开着时成立）；标准启动回来后由 BSP 的恒等映射打开 MMU，外设/PL 寄存器区间设成 device/uncached ⇒ 寄存器读写不会被缓存绕过。选择不链标准启动，就得自己承担 `-mno-unaligned-access` 与预编译库里 `memcpy` 半字快路径这一类雷。

## 完成判据

- 一次跑完的三条等值关系：反汇编 0x0 处的跳转目标 == ELF 入口 == `_boot` 的地址；`_vector_table` == 0x0；0x4/0x10 落在两个 handler 上。任一不满足就是红。
- 一个反例证明哨兵有用：把入口设成自己写的入口符号再链接，`--gc-sections` 会把没人引用的向量段整段裁掉 —— 此时"存在性"检查（符号表里有 `_boot`）**仍然绿**，等值检查必须红。
- 哨兵自己也要有测试：给它两个已知入口（0x0 与一个非零地址）各跑一次，必须一红一绿。栽过的坑是正则 `Entry point address:\s+0*([0-9a-f]+)` 遇到 `0xcc` 会把那个 0 吃掉、捕获为空 ⇒ 永远读成 0。
- 板级签名归零：发一条命令回来的是**整条启动横幅** ⇒ 就是"异常跑到 0x0"的现场，不要再去怀疑"板子自己复位了"。

## 失效边界

- 启动那几个 `.S` 依赖平台库的配置头（`-DSDT` 与内存配置文件）：老流程或改了编译开关 ⇒ 恒等映射与 errata 分支会不一致。
- 多核 / `USE_AMP`：启动代码按 CPU 亲和号决定谁往下跑，还会在单核 efuse 上复位另一核，不能照抄。
- 想让应用跑在 DDR 里：页表的 DDR 段属性来自 xparameters 里的地址与容量，与实机不符时开 MMU 后第一笔访存就炸，表现成"一个字节都没打出来"，比缺启动更难查。本仓库跑在 OCM ⇒ 这条路**未验证**。
- 别把异常初始化当成"异常已接管"：裸机库的默认 handler 只在库开了 DEBUG 时才打印；崩溃后可读的现场是几个 abort/undefined 地址全局 + pc/cpsr（例：本仓库 `board/pswhy.tcl` 就采这些）。想有打印就得自己注册 handler，别在文档里声称"handler 会打印"。
- 分界：本条只管"镜像里有没有整条标准启动"；"下位流后 PS 必须重起""重下才恢复"属板级连线与驱动状态那一类账（`skill/board_eth_uart.md`）。
