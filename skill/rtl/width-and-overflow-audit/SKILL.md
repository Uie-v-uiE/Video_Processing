# 位宽与可算的界：两侧夹逼、参数表达、别拿口头数当读数

## 适用场景

- 通路里有缩放、乘除、累加、平均、位移，或索引落在行/列/表边界上。
- 台架红过一条你解释不了的用例；怀疑是位宽/截断而不是逻辑。
- 深度、通道数、系数这些数字以字面量散落在源码与测试里，改一个参数就要重写一片判据。
- 有人（用户、评审、现场）报了一个数，要把它写进期望或结论。
- 哪一步用：写 RTL 里的每一个赋值时；写台架期望之前；改参数之前。

## 使用方法

### 先查什么（一手资料优先级）

接口规范/数据手册里那些**带单位的定义**：定点格式（几位整数几位小数、符号位在哪、饱和还是回绕）、
坐标口径（像素中心还是像素角、索引从 0 还是从 1、行优先还是列优先）、舍入与取整方向。
这些定义属于契约，必须由一手文档给出；文档没有就列为待定项去确认，不许用模型记忆补一个"通常是"。

### 先跟用户确认什么

- 数值契约：饱和/截断/回绕哪一种、舍入方向、坐标口径。这是"外观与算法结果"级决定，改一次就换一套判据。
- 参数范围：深度、通道数、系数的取值范围与是否可能变——它决定断言能不能只覆盖当前档。
- 口头报出的那个数是在哪儿、用什么口径、哪一拍看到的（先归因，再决定它进不进期望）。

### 一、能算出来的界，一律配断言（六类，缺一类就是欠账）

1. **缩放/乘除的截断**：乘积位宽 = 两操作数位宽之和；写明保留哪一段（高位还是低位、丢几位），
   断言"结果的低若干位为 0"或"移位量 == 参数"，而不是只断言最终值。
2. **索引的末行/末列越界**：上界 = 深度/行数（由参数给），断言索引严格小于上界；
   专门跑末行与"最后一行 + 1"两条用例——越界通常只在边界那一档现形。
3. **计数器溢出回绕**：先回答"回绕是不是设计意图"。是 ⇒ 断言回绕点与回绕后一拍的行为；
   不是 ⇒ 断言计数严格小于周期，并配饱和或使能关闭。
4. **累加宽度**：N 个 B 位项相加需要 B + ⌈log2 N⌉ 位；用这个式子写断言，让 N 一改判据跟着改。
5. **除法/取整方向**：向下取整、向零取整、四舍五入三者与软件参考必须逐位一致；
   负数与余数符号单独出用例——正数用例永远测不出这一类分歧。
6. **符号与混合位宽**：有符号数与无符号数混在一个表达式里会整体变成无符号，负数会变成一个巨大正值；
   截断赋值在有些语言里只是警告。断言写成显式位宽比较，禁止依赖隐式扩展。

### 二、判定用 RTL 自己的两侧夹逼，不在仿真外重算

- 形式：`值 ≥ 下界 且 值 ≤ 上界`，两侧界都由 RTL 里**同一个参数化表达式**算出，在台架内直接比较。
- 为什么不许离线重算：你在仿真外用另一套模型重算一遍，等于换了口径。真实过错的形状是
  "坐标口径不一致"——一侧按单元中心、一侧按索引算，两边都自洽，差分出来就是一条**根本不存在的违例**，
  然后整轮时间去修一个没坏的东西。夹逼判定把口径钉在 RTL 自己那一份上，界错了会一起错、立刻可见。
- 界本身也可能推错：所以每条夹逼都要有变异对照（人为把位宽削 1、把上界改成 深度−1，
  断言必须红）。没有对照的判据标注"未配对照"，它的绿证据力更低。

### 三、口头报出的一个数不是仪表读数

- "我看到 0.52"这类话只描述一次观看：没有口径、没有采样时刻、没有量程、不可复跑。
- 处理顺序：归因（哪个信号、哪一拍、什么坐标口径、什么单位）→ 复现成一条可跑读数 → 复现不了就
  明写"未复现"，并把该数只当线索放进待定项，绝不写进期望值或结论。
- 高危形状：口头数与你的口径单位不同相减；口头数是四舍五入后的显示值；口头数是另一档参数下看到的。

### 四、参数化：魔数变参数，断言用参数表达

- 深度、宽度、移位量、系数、边界索引全部进参数；源码里出现字面量界就算不合格。
- 断言里的界写成参数的函数式（例如 上界 = 深度 − 1、累加位宽 = B + ⌈log2 N⌉），
  这样改参数时判据自动跟着走，不需要人记得改测试。
- 参数范围要有检查：编译期或仿真起始时断言参数本身满足关系（深度是 2 的幂、位宽 ≥ 需要的位数），
  参数写错要第一时间炸，而不是让下游现象替你报错。

### 五、台架语言陷阱（X 会伪装成"设计错"）

- 未初始化的**数组/存储器元素默认是 X**，而**标量整数变量默认是 0**：同一个台架里两种默认值，
  你只初始化了标量，数组那一片读出来全是 X。
- X 参与比较：相等运算返回 X，`if` 条件里被当假走 else ⇒ 一条用例可能被记成"通过"也可能被记成"失败"，
  取决于你用的是哪个运算。判 X 要用专门的 X 检测，不要靠相等/不等。
- 未初始化期望 vs 未初始化实际输出，两种 X 会互相抵消成"看起来一致"。
- 结论：台架里每个数组/缓冲/黄金表都在起始显式初始化（填 0 或填一个不可能的哨兵值），
  并在报告里区分"X 造成的不匹配"与"数值造成的不匹配"——把前者算进设计错就是错账。

## 失效条件

- **界推错了，且两侧同源同错**：夹逼永远绿。只有变异对照能发现，所以对照不是可选项。
- **断言写了字面量而不是参数**：当前档绿，改深度后失效 ⇒ 假绿，且没人知道它失效了。
- **断言只在仿真里存在**：综合把它们剔掉，硬件上没有任何检查。仿真绿不等于硬件对，要写明覆盖边界。
- **夹逼的界来自不同口径**（一侧按契约、一侧按实现）：等价于把离线重算搬进了台架，仍然会造出假违例。
- **X 判据缺失**：未初始化被当 0 或当失败，红一片却分不清来源；此时先修台架，不要改设计。
- **口头数被直接当期望**：整轮在追一个不存在的偏差；征兆是判据"改到能过"而不是"算到能过"。
- 语言/工具混合（不同 HDL 或不同台架框架）时，默认值与 X 语义规则不同：换框架要重跑一次陷阱自查。

## 已验证效果

未量过，属建议（本条没做过带/不带它的 A/B）。依据的观察类别是：六处"能算出来的界"没有断言，
全部等到现场出现现象才被发现；以及一次在仿真外重算期望造成口径不一致，判出一条并不存在的违例。
变硬的可复跑形式：每条界一个断言，报告里给三个数——界总数、有断言的界数、带变异对照的断言数
（后两者与前者的比值就是这条的进度）；台架结论行末位带 PASS/FAIL/NOT_MEASURED，
X 造成与数值造成的不匹配分开计数。
