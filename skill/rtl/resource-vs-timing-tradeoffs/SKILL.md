# 用资源换时序：先算上限，带代价面，逐模块归因

## 适用场景

- 某条路径 setup 不收敛，你想说"那就把它挪进片内存储块/加一拍/复制一份"。
- 一次改动之后总量变了，但改动不止一处，收益说不清归谁。
- 上一次这类改动被判负，现在条件变了，你不确定该不该重开这条路。
- 资源已经很紧张（某类接近满），却还在按"随时能换"的假设规划。
- 哪一步用：任何"以面积/存储/布线资源为代价换时序"的候选改动，在**开构建之前**。

## 使用方法

### 先查什么（一手资料优先级）

器件/工具文档里这几页优先：每类存储资源的**容量与可用形态表**（单块位深、级联规则、按位宽拼块向上取整）、
时钟区域的物理划分与跨区代价、LUT 作为存储使用的条件与限制、复制/寄存器优化选项的适用前提 ＞
应用笔记 ＞ 教程 ＞ 模型记忆。别把"上次换了有效"当这一路的依据：瓶颈类型不同结论就不同。

### 先跟用户确认什么

- 这一轮的预算：允许用掉多少该类资源、允许哪个域余量变差、能接受几次完整构建的时间。
- 是否允许改接口的时序行为（多几拍延迟会改变对外可见的节奏与演示口径）。
- 换不动时的退路由谁定：降频、减功能、还是接受不收敛（这是取舍，不是技术事实）。

### 一、候选清单与各自的收益上限（先算后建）

每个候选在开构建前回答一句："这个改动能动的是路径延迟里的**哪一部分**，那部分最多值多少。"
读数来源是实现报告的延迟分解（时钟网络分量、逻辑分量、布线分量、扇出/拥塞迹象）。

| 候选 | 它真正改变的环节 | 收益上限的算法 |
|---|---|---|
| 行缓存/队列改存储块（片内存储块或 LUT 作存储） | 长走线与分散布线资源、扇出 | 只有当**布线分量占大头**时才有上限可算；上限 ≈ 该段布线延迟的可省部分 |
| 拆分组合锥、插入寄存（加拍） | 单周期内的逻辑分量 | 上限 = 被拆掉那段的逻辑延迟；同时多拍延迟要按接口预算核对 |
| 复制驱动降扇出 | 缓冲与高扇出网络的走线 | 上限 ≈ 缓冲/驱动替换掉的延迟；扇出本身不高时上限接近 0 |
| 查表替代算术（乘/累加折成表） | 逻辑级数 | 上限 = 算术链的逻辑延迟；代价是存储块/LUT 占用与读延迟 |
| 并行化（多实例换吞吐） | 单实例的组合深度 | 上限要看是深度受限还是吞吐受限，两者别混 |

硬规则：**预估上限 < 当前违例量 ⇒ 不开这一版构建**。收益上限没算出来 ⇒ 记 NOT_MEASURED，
这版构建只当"取数"用，不许当"改进"记账。

### 二、采纳前必须带代价面（三项齐了才算一个可采纳结论）

1. **被换进去那类资源的占用率**：改前 %、改后 %、余量绝对值（存储块要按位宽向上取整成块数，
   并算上控制逻辑与输出寄存器带来的额外占用）。
2. **别的域余量**：按全局名册读每个域的最差余量变化，不看单条路径。局部变好、别处变差的改动
   在这一步必须被拦住（同 global-timing-roster 的判法）。
3. **别的通路数量**：同一块存储/同一段布线资源被几处共用；这一改动挤掉了谁。写"共用处数 + 各自需求"。

代价面之外还有一项常被漏：**约束与检查的射程是否变了**。改层次名、换钟、重新源化会让按名的约束与
按名的检查静默失效，此时"时序变好"可能是覆盖面丢失的假象（见 constraint-coverage-loss）。

### 三、归因要逐模块给等式（部分收益不许写成全部）

- 格式：`本改动 = 该模块实测差值`，然后 `总量 = Σ各模块 + 未归因残差`，三者必须闭合。
- 示意（不是某次实测结论）：一次批量改动总量 −243，而你只拆了一个子模块、单独量到 −66，
  那么正确写法是"本改动贡献 −66，其余 −177 来自同批其他改动或未归因"，
  **不许**写成"本改动带来 −243"。差额必须给闭式，闭式写不出就是归因不明，结论降级。
- 同批混刀是最常见的归因破坏源：要么拆轮，要么逐刀各配读数（见 before-an-rtl-change 的单变量要求）。
- 每个数注明口径：同一份报告在改前/改后必须用同一条命令、同一工具版本、同一优化选项取；
  口径一变就写"不可比"，不做差分。

### 四、存储块接近满时不能假设还能换

- 余量必须实测，且实测要**在改动之前**取：接近满（按文档给的余量阈值判）时，换进去的代价是
  "放不下"或"为放得下把别处挤坏"，此时收益上限不再是延迟问题而是可行性问题。
- 检查三件事：按位宽拼块后的块数、共享同一存储的其它通路是否被挤掉、布局是否被推到跨区域（跨区反而更慢）。
- 接近满时的正确动作是先算能不能装、装完剩多少，再谈时序收益；顺序反了就是一版废构建。

### 五、量过并被判负的例子要写成"条件 + 重开条件"

不许写"这条路没用"。固定三段式：

```
量过：<候选> 在 <口径/版本/瓶颈类型/资源余量> 条件下，实测 <差值>，判定 <负/平/正>。
机制：<改动了路径的哪一部分>（机制是否动了，与结果是否赢，分开写）。
应重开条件：<瓶颈类型变成 X／该类资源余量变成 Y／拥塞被先缓解> 时应重新评估，不必重新发明。
```

"机制动了但结果没赢"是合法且常见的结论，它省下的是下一次重复试错的时间，不是采纳理由。

## 失效条件

- **没算上限就开构建**：整轮构建时间换回一个"改了但没量"。征兆：结论里只有差值没有上限估算。
- **只看被改那条路径**：别的域已经变差却被局部数字盖住；必须按名册逐域判。
- **把占用率当唯一代价**：忽略布线拥塞、功耗、跨区延迟、时钟树代价，以及约束射程变化。
- **口径漂移后仍做差分**：频率、优化选项、工具版本、器件任一不同，差值就不是同一把尺。
- **多刀混一轮**：总量归到单刀头上，写出来的收益是错的账，后续规划据此继续加码。
- **按"上次有效"套用**：瓶颈类型不同 ⇒ 同一候选从正收益变成负收益；先读延迟分解再选。
- 纯吞吐/纯功能问题不适用本条：本条只处理"以资源换时序"，行为错误不该用它解释。

## 已验证效果

未量过，属建议（本条是纪律清单，没做过带/不带它的 A/B）。依据的观察类别：一次"以片内存储块换 setup"
的改动量下来被判负；以及一次部分收益被写成总收益的归因错账（只动了一个子模块却领了整批改动带来的数）。
变硬的可复跑形式：每个候选一行，列"预估上限、实测差值、代价面三项（该类资源占用率前后、
其它域余量变化、共用通路数）"，缺任一项判 NOT_MEASURED；归因等式必须闭合，
残差超过约定阈值就标注"归因不明"并降级结论。

以及批量改动里部分收益被写成全部收益。相邻条目：fix-logic-depth（拆锥与插拍的上限先算）、

global-timing-roster（按域出名册）、constraint-coverage-loss（覆盖面丢失被当成收益）、
before-an-rtl-change（单变量与回滚前置）。
