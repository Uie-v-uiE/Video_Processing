# 工程骨架模板（目录树 + 逐目录职责 + 目录对照表）

## 1. 骨架目录树（把 `<项目根>` 换成你的仓库名，其余按需增删）

```
<项目根>/
├── README.md                     # 首页：项目做什么、三步复现、目录对照表（本文件第 5 节）
├── LICENSE                       # 开源许可（示例取值，需按自身工程替换：MIT）
├── src/
│   ├── rtl/                      # 可编程逻辑源码，按功能分子目录（top/ clocks/ video/ …）
│   │   └── <你的功能域>/         # 【填入】一个功能域一个目录，别按"新加的板级特性"建目录
│   ├── constraints/              # 全部约束文件 + 一份"哪份用在综合、哪份只用在实现"的顺序说明
│   ├── ps/                       # 处理器侧裸机/应用源码（没有处理系统就整目录删掉）
│   └── host/                     # 上位机/取证类小工具（脚本也放这，注明"不在演示主链路"）
├── sim/                          # 台架、判据、变异对照；一条判据一个可复跑入口
│   └── prim/                     # 仿真用的原语占位件（把仿真与综合的差异写进文件头）
├── build/                        # 构建入口 Tcl、门禁脚本、报告归档、每轮凭据目录
│   └── tcl/                      # 构建/下载脚本；README 里点名"哪个是入口、哪几个别用"
├── board/                        # 上板：操作卡、验收表、串口/日志捕获件
├── data/
│   ├── golden/                   # 黄金参考向量（必须有出处，见第 4 节）
│   └── measured/                 # 板上实测回读件（原始件，不手抄）
├── report/                       # 交付文档（给评审读的那一层）
│   └── log/                      # 追加式过程档案（问题账、过夜流水、版本谱系）
├── skill/                        # 技能包
│   ├── prompts/                  # 提示词工作流
│   ├── templates/                # 可抄模板（本文件所在层）
│   ├── pitfalls/                 # 技术踩坑（只作记录，不伪装成通用技能）
│   └── references/               # 外部来源与文档编号
└── <归档目录名>/                 # 【填入】每次采纳一键产物：见第 3 节命名式
```

## 2. 每个目录放什么（一句话口径，越界就重写）

| 目录 | 放什么 | 不放什么 |
|---|---|---|
| `src/rtl/` | 综合收进清单的 RTL；文件头写清端口、时序假设、被谁例化 | 只服务于某块板的临时探针（放 `build/` 或 `sim/`） |
| `src/constraints/` | 时钟与 I/O 约束；`set_...` 之外不写业务 | 任何"能跑但没人知道为什么"的历史约束（改名或删，并在文档留痕） |
| `src/ps/` | 处理器侧应用与寄存器访问层 | 用板级口吻汇报但未编译通过的源码 |
| `sim/` | 台架 + 每条判据的"该红条件"；变异对照入口 | 只在某次调试里手写的一次性比对 |
| `build/` | 构建入口、门禁脚本、报告归档、逐轮凭据 | 未成套的半份产物（缺报告的目录要标 `NOT_MEASURED`） |
| `board/` | 上板操作与验收表（每条：命令 → 该看见什么 → 看不见说明什么） | 机器判据冒充人眼结论 |
| `data/golden/` | 参考向量和它的生成方法 | 手抄的期望值 |
| `data/measured/` | 板上原始回读件（文件名带轮次与时间） | 事后补的"当时没记"的数 |
| `report/` | 交付文档：设计说明、性能读数、构建复现、已知限制 | 与 `data/` 里那张表重复的数字（只给指路） |
| `report/log/` | 过程档案；**只作过程留痕，不当结论引用** | 唯一的结论来源 |
| `skill/` | 可复用条目：每类一个目录，正文不出现本队专有名词（除非标"示例取值"） | 只有靠本队具体故障才成立的"经验"（那放 `pitfalls/`） |

## 3. 产物归档命名式（每采纳一次就产一份，不覆盖上一轮）

```
<归档目录前缀><轮次号>_<一句用途>/
├── MANIFEST.md5          # 三件套（位流 / 硬件定义 / 可执行文件）的 md5 + 工具版本
├── <逐域时序读数>        # 见 ../report-forms/timing-readout.md
├── <资源利用率读数>
├── <方法学与 CDC 读数>
└── <门禁逐条输出>        # 收尾必须含"判定 N 项、未判 M 项"
```

规则（每条都能判定做到没做到）：

1. 归档目录名含轮次号；同一轮的第二跑另加字母后缀，**不覆盖**上一份。
2. `MANIFEST.md5` 里的三行 md5 必须在产物生成之后、由脚本写入，不许手抄。
3. 若某份报告缺失，目录里放一行 `NOT_MEASURED: <缺哪份> <为什么>`；不许把空目录当"这一轮没问题"。
4. 被否决的轮次单独放 `rejected/` 前缀目录（示例取值），交付导出时按"被否决不进包"处理，但仓库里留着。

## 4. 输入数据与黄金参考的出处要求

- 每个 `data/golden/` 文件配一行生成方法（命令 + 输入 + 期望形状），否则比对结果无法复核。
- 未确认的数据不许进包：用 `【填入】` 占位并在 README 的"数据"一节写明缺什么。
- 仿真与硬件对不同步的已知差异（例如数组越界写在仿真里被丢弃、硬件按地址位宽截断）必须在
  `sim/` 的文件头写明，否则"台架绿"会被读成"硬件对"。

## 5. 目录对照表模板（采用了非推荐结构时**必须**填这张表并放进根 README）

依据条文（本地核对）：`report/log/CONTEST_CHECKLIST.md:120`（2026-10-01）引 §3.3.5.4 末句
"上表为推荐结构，非强制。采用其他组织方式的队伍须在 `README.md` 中给出目录对照说明"。

| 推荐目录（照条文抄，不转述） | 本仓库实际目录 | 为什么这样组织 | 评审复核某条数字时该走哪条路径 |
|---|---|---|---|
| 【填入】 | 【填入】 | 【填入：一句话，可判真假】 | 【填入：文档名 → 表行 → 凭据文件】 |
| 【填入】 | 【填入】 | 【填入】 | 【填入】 |

填写要求：

- 左列必须照抄条文里的目录名原文，不许意译。
- "为什么这样组织"一列禁止写"更清晰/更方便"这类不可判真假的话。
- 最后一列必须能由一个没参与过的人照着走到一份**具体文件**（含文件名，不含"见 build 目录"这种泛指）。

## 6. 骨架自检四条（新建仓库当天就跑，别等交付前）

| # | 判据 | 命令骨架 | 通过条件 |
|---|---|---|---|
| A1 | 文件/目录名纯 ASCII 小写 | `git ls-files \| grep -v '^[a-zA-Z0-9._/-]*$' \| wc -l`（大写与个别例外要在 README 里点名） | 非 ASCII 计数 = 0 |
| A2 | 没有仓库外绝对路径 | `grep -rn -e '<盘符>:' -e '/home/' src build sim board 2>/dev/null \| wc -l` | 交付文档与脚本内为 0 |
| A3 | 每个目录有"放什么"说明 | 根 README 含第 2 节那张表的实际填写版 | 表行数 = 顶层目录数 |
| A4 | 工具版本被写进清单 | `MANIFEST.md5` 或等价清单里有版本行 | 版本号非空且非 `【填入】` |

## 7. 与赛题条文的关系（哪些是硬要求）

- 文件名口径（本地核对：`report/log/CONTEST_CHECKLIST.md:21`，2026-10-01，引 §3.3.5.4 原文
  "小写字母、数字、下划线或连字符，不得出现中文、空格或特殊字符"）：中文只允许出现在文件正文里。
  该仓库对大写名（`README.md` 等）的处理方式记录在同一行里，属"文档化例外"，
  换队伍时要么照做要么全小写，别留第三种状态。
- 本文件不复制条文中那张推荐目录表的原文：条文在赛题指南里，本仓库未入库其副本 ⇒
  左列请直接从指南原文抄，`【填入】` 处不许凭记忆补。
