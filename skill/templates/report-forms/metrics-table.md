# 指标汇总表模板（表头照抄条文，不许改列名列序）

## 1. 表头（CSV 第一行，逐字照抄）

```csv
指标名称,类别,数值,单位,测量条件,测试次数或时长,证据文件
```

## 2. 每列的填写口径

| 列 | 必填？ | 填什么 | 常见错法 |
|---|---|---|---|
| 指标名称 | 必填 | 一个指标一行，名字与文档里念的那句一致 | 一行塞两个数（后续对账脚本会漏判） |
| 类别 | 必填 | 核心 / 资源 / 实测 / 口径 / 功能 / 自检 / 验收 / 未报 之一（按你的分类固定一套，全表统一） | 把"口径"写成"实测" |
| 数值 | 有条件必填 | 一个数字 + 必要的区间；**没有可复核读数时填 `—`**，并把类别写成"未报" | 用"约""量级"填空 |
| 单位 | 必填 | `ns`/`MHz`/`fps`/`个`/`W`/`℃`/`MB/s`；无量纲写 `—` 并在测量条件里说明 | 单位与列名混着写 |
| 测量条件 | 必填，六件齐全 | ①硬件型号 ②数值精度/定点位宽 ③输入规格（分辨率/帧率/负载） ④软件版本 ⑤FPGA 时钟频率 ⑥功耗模式 | 只写"实测"两个字 |
| 测试次数或时长 | 必填 | 次数（"一轮 600 帧"）、时长（"连续 300 s"）或"一次构建/一次布线后报告" | 空着（读者无法判断偶然性） |
| 证据文件 | 必填 | 具体文件路径（含文件名）；多份用顿号分隔 | "见 build 目录"这类泛指 |

绝不能空的列：`测量条件`、`证据文件`。
可以留 `—` 的列：`数值`、`单位`（前提是类别写"未报"，且测量条件里说明为什么没有）。

## 3. 三条填写规矩（可判真假）

1. **口径与实测分行**：算出来的负载（如 `宽 × 高 × 字节 × 帧率`）与板量到的读数不许共用一行；
   口径行在测量条件里明写"这是负载口径不是实测带宽"。
2. **逐轮走势写进测量条件，不另开一张表**：同一指标换过版本就在这一格里写"上一版是 X，
   差值来自某一次改动，出处是某两份报告相减"，且不得据此宣称收益（头条绝对值的跨构建移动只念不判）。
3. **文档里念到的每个数都必须能对回这张表**：首页/正文引用的数字逐个可被一支脚本重算
   （把这条写成一项门禁：脚本按"证据文件"列打开报告、读那一个字段、比对；读不到判红而不是判绿）。

## 5. 本模板示例取值的来源（不是让你照抄数字，是让你看形状）

- 表头与"未报也要占一行"的写法：`data/metrics.csv` 第一行与"端到端时延,未报,—,—,…"一行（本仓库，2026-10-04 06:23）。
- "测量条件里写清口径 vs 实测"：同文件"UDP 入口负载,口径,9.2,MB/s,…**这是负载口径不是实测带宽**…"一行。
- "逐轮走势写在测量条件里、不另开表"：同文件"Slice LUT 占用"一行（一串逐轮差值与各自的报告出处）。
- 六件测量条件齐全的例子：同文件"器件与工具链"一行（型号 + 速度等级 + 工具版本 + 可复现声明 + 指路）。
