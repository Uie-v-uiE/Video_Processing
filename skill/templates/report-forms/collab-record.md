# 大模型协作记录模板（一案一节，五栏齐全）

## 1. 单案模板（复制这一节，一案填一份）

```
## 例 N：<一句话症状>（问题账编号【填入】）

**提示词的最初形态**（照抄当时那句，含错别字与口语）：
> 【填入】

**模型给出的第一版解释/方案**：
【填入】

**它是错的还是对的？由哪一个读数判定**：
【填入：读数 + 出处文件路径；如果这版解释同时满足多条观察但仍是错的，写清是哪一条观察被我误读】

**换过取证方式之后结论怎么变**：
【填入：换了什么取证手段（原始字节 / 行回读 / 报告逐行 / 检查点复算），结论是否反过来】

**这一案沉淀成哪条规矩，落在哪个脚本/文件里**：
【填入：脚本路径 + 那条判据的名字；没有落成脚本就写"未落成"，并说明为什么】
```

## 2. 五栏的填写口径

| 栏 | 必填？ | 判真假的办法 |
|---|---|---|
| 提示词原文 | 必填 | 能在当日流水/问题账里按时间或编号对上 |
| 第一版回答 | 必填 | 原样摘录，不许美化成"我当时认为" |
| 推翻它的读数 | 必填 | 该读数有盘上文件；只写"感觉不对"不算 |
| 取证方式变化 | 必填 | 写出手段名（原始字节捕获 / 逐行回读 / 同树重滚） |
| 落成的规矩 | 必填 | 指向脚本里的具体判据；"下次注意"不算落成 |

## 3. 这张表里必须出现的三类内容（缺任一类就是宣传稿）

1. **被证伪的自我判断**：至少 N 条（N ≥ 3 或你实际的次数），且每条写明"错法是值得记的那种错"
   —— 例如把"我要求固件画出来的东西"当成缺陷、把巧合当成跟随、把自己的工具产物算到被测物头上。
2. **尺子自己的事故**：判据读的对象与它声称在判的对象不是同一个；判据标签被按字节截断；
   收尾解析把红报成"没判定"。这类要单列，别混进"设计缺陷"。
3. **失败与代价也要报**：模型给的数需要人逐条回读才能进台账；回读不出的降级为候选。
   两类事故（代理把两种越界混成一类 / 我用管道读状态）都要写出来。

## 4. 与问题账的交叉引用规矩

- 每个案子末尾给一个编号（问题账里的第几条），交付文档只摘要，**细节留在追加式档案里**。
- 追加式档案（问题账/过夜流水）里不许被"修改成迎合检查器"：检查器对这类档案只查路径存在性、
  不查行号，就是这个原因。
- 引用凭据要说清是哪一份：新判据的数在刷新冻结件之前只有实时日志可查，
  拿旧冻结件冒充新判据是另一条纪律的事。

## 5. 示例取值来源（看形状，不抄结论）

- 六案结构与"提示词原话 + 被哪个读数推翻 + 沉淀成哪条规矩"的四段式：`report/LLM_COLLAB.md`
  （本仓库，2026-10-02 02:16）例 1～例 6；其开头一段明写"里面每一次模型说错了都按当时的原话记下来，
  并注明是被哪一个读数推翻的；所有事实都能在 `report/log/ISSUES.md`（同一仓库、同一提交）里按编号查到原文"。
- 智能体工作流四件被固化的设计（只读评审代理 / 回读门槛 / 变异对照 / 门禁即文档）：同文件第 5 节。
- "模型与我的边界"（谁定义验收、谁提供现场观察、人在哪两处否决了方案）：同文件第 6 节。
- 更长的过程档案形状：`report/AI_COLLABORATION.md`（2026-10-02 03:07）与 `report/log/ISSUES.md`（追加式问题账）。
