## 1. 一句话用途

把读数填进四张固定表头的表，并让每个数旁边跟着它的出处。

## 2. 适用场景

- 当报告里开始出现数字，而没人能立刻说出"这个数出自哪份文件"时。
- 当首页/摘要/正文/表格四个地方各抄了一遍同一个数，其中一处已经过期时。
- 当时序/性能读数被按"全局最差那一条"汇报，其他时钟域或子系统没人念时。
- 当一轮优化做完，只留下"改后更好"，没有留下"哪些刀被证据否掉了"时。
- 当上板验收表里"通过"一栏既包含脚本读数又包含屏上现象，两者混在一起签字时。
- 当交付要求"大模型协作记录含提示词、回答、自我纠错轨迹"时。

## 3. 不适用 / 失效条件

- 还没有可信读数，只有估算：先按 `../script-template/` 把读数变成一条命令能算出来的东西；
  填进这张表只会把猜测格式化成"看起来像凭据"。
- 要设计实验本身（一次改动只测一件事、判据成对、机制证据）：用 `../../prompts/single-variable-ab/`。
- 只写内部周报、不给外部复核：第 1 节表头的"证据文件"列可以省，但"NA 不填 0"这条不许省。
- 指标口径与实测本来就是同一件事（同一个脚本读的同一个字段）：不要为它单开"口径行"，会造成两行打架。
- 交付文档结构完全不同（例如只交 PDF）：表头照抄，但"证据文件"列要换成能被评审打开的对象标识（页码 + 图号 + 报告名）。

## 4. 前置条件

- 每张表都要有"生成器"：一支脚本能从盘上报告把某些格子重新算出来（对应门禁里的"数字对账"这一项）。
- 已知并写进表的条件六件：硬件型号、数值精度、输入规格、软件版本、FPGA 时钟频率、功耗模式。
- 有一版基线读数与它的生成脚本名（差分只在两端同生成器时成立）。
- 归档目录规则：一轮一件、不覆盖上一轮；被否决的轮次单独前缀。
- 签字人（验收表）：谁看、在什么状态下看；机器判据不许替眼睛签字。

## 5. 使用方法（在陌生工程里实例化）

模板文件（同目录，一层深）：

| 文件 | 什么时候用它 |
|---|---|
| `metrics-table.md` | 建那张"唯一一张数字表"时（七列表头照抄条文） |
| `timing-readout.md` | 要交逐时钟域时序/资源读数、要做跨版本差分时 |
| `optimization-compare.md` | 要说清"改前/改后 + 唯一变量 + 没采纳的刀"时 |
| `acceptance-record.md` | 上板或整机验收、要把机器判据与人眼判据分开签时 |
| `collab-record.md` | 要交付"提示词/回答/被哪个读数推翻/落成哪条规矩"的协作记录时 |

槽位计数自检（命令 `grep -o '【填入' <文件> | wc -l`，实跑 2026-10-04）：`metrics-table.md` 24 ·
`timing-readout.md` 28 · `optimization-compare.md` 65 · `acceptance-record.md` 15 · `collab-record.md` 6 ·
本 `SKILL.md` 3。实例化到陌生工程后，目标文件里这些数应当归 0（第 5.1 节第 2 步就是这条检查）。

### 5.1 实例化步骤

1. 复制需要的表到你的文档目录并改名为纯英文小写：
   ```bash
   mkdir -p <你的仓库>/report
   cp <技能包>/skill/templates/report-forms/metrics-table.md <你的仓库>/report/metrics_table.md
   ```
   **完成后应看到**：目标文件存在；文件顶部四行元信息注释还在（用途/前置条件/产出物路径/失败时先看哪里）。
2. 按各文件"空表/主表"段落把 `【填入】` 换成你的槽位值；**计数并报出来**：
   ```bash
   grep -c '【填入】' <你的仓库>/report/metrics_table.md
   ```
   **完成后应看到**：填完之后这个数是 0（还留着的就是没填的槽）。
3. 给每张表配一支"重算脚本"（照 `../script-template/script-template.sh` 改），
   让表里每个数都能由脚本从盘上报告重新算出来。
   **完成后应看到**：脚本跑一次输出 `RESULT: ALL PASS（判定 N 项，未判 0 项）`；
   把某个格子故意改错 ⇒ 必须 `RESULT: 有红项`（这是这张表的反例）。
4. 在根 README 或正文里只留**指路**（"当前值见 `metrics.csv` 某行"），不把数值抄第二遍。
   **完成后应看到**：`grep -rn '<同一个数字>' .` 只在表与该行的凭据里出现，不在叙述段落里出现第二份。
5. 表头自检（照条文抄的那几列一字不差）：
   ```bash
   head -1 <你的仓库>/data/metrics.csv
   ```
   **完成后应看到**：`指标名称,类别,数值,单位,测量条件,测试次数或时长,证据文件`（顺序一致）。

### 5.2 哪些列可以留空、哪些绝不能空（照本条目四张表汇总）

| 表 | 可以留 `—`/`NA` 的列 | 绝不能空的列 |
|---|---|---|
| 指标汇总 | 数值、单位（类别写"未报"时） | 测量条件、证据文件 |
| 逐域花名册 | 该域无路径时的六个读数列（写 `NA`） | clock、period_ns、rel_margin 的分母口径、verdict |
| 优化前后对比 | 预期收益（写 `【未实测】`） | 唯一变量、其余域有无变差、出处两份路径 |
| 验收记录 | 人眼判据的"读数"（未判时写"未判"） | 由谁判、看到什么算通过、凭据路径、签核时间 |

## 6. 判读与失败分叉

- **通过**（表头一致、每个数有出处、NA 与 0 未混用、差值列写算式）：可以拿去给评审复核；下一步是配那支重算脚本进门禁。
- **失败：同一数字出现在两处且不一致**：先定"唯一权威来源"（指标表），把叙述段落改成指路；
  再让重算脚本判它（这一族错误的根因是"没有任何东西把报告与被测的树绑在一起"）。
- **失败：把 NA 当 0**：整行退回；这类表一旦混入"空集被读成合法 0"，全表的绿都不可信。
- **失败：只报全局最差一条**：补逐域行；没有逐域数据 ⇒ 标 `NOT_MEASURED` 并列为债，不许写"其余域没问题"。
- **读不到输入**（凭据文件不存在/版本对不上）：该行类别改"未报"、数值填 `—`、
  测量条件里写清缺哪件；不要用上一版的凭据顶替（认身份要认 md5 而不是认文件名）。
- **签核表出现"未判"行**：结论只能写"部分通过"；把未判行列进欠账清单并点名补它要跑的命令。

## 8. 提炼来源与边界

- 提炼来源：`data/metrics.csv`（口径行与实测行分行、逐轮差值写在测量条件里、"未报"也占一行）、
  `report/PERF_REPORT.md`（2026-10-01 08:06，"同一份数字抄在第二个地方就会漂移，所以这里只给指路、不复制数值"的时效声明）、
  `report/TIMING_GLOBAL.md`（逐域名册与"绝对差只念不判"）、`docs/timing/*.tsv`（列名与差分形状）、
  `board/ACCEPTANCE.md` 与 `board/VERIFY_r87.md`（按行记版本、未盖章明写）、`report/LLM_COLLAB.md`（协作记录五栏）、
  `src/host/metric_recheck.mjs` 与 `src/host/line_cite_check.mjs`（"文档里的每个数必须能对回报告""行号引用必须落在锚点上"两把尺子）。
- 迁移要改的：测量条件六件的具体值；逐域列名里的时钟对象名（改名后必须重取）；
  判定阈值（相对余量下限、噪声底）；验收表的"由谁看"必须换成你队伍里真实的人。
- 失效条件：项目没有任何脚本能重算表里的数（表会漂，此时先补脚本）；只有一个时钟域且从不跨版本比较
  （花名册退化成一行，可省差分列）。
- 边界：本条目只管"怎么填、填什么、哪个数旁边放什么"，不管实验设计、不管判定脚本本身、不管寄存器位域。
