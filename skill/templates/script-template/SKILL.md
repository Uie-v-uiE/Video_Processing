## 1. 一句话用途

一支自带反例、退出码分得清"红"与"没数"的判据脚本骨架。

## 2. 适用场景

- 当你已经手工跑过某条检查两三次，想把它变成"一条命令 + 一份留档"时。
- 当脚本在链里被调用，而它的退出码被读成"过/没过"两态、于是"什么都没判"被当成通过时。
- 当换一台机器就因为写死了绝对路径而全错（工具装在哪、仓库在哪）时。
- 当新增一项判据（例如给检查器加个子规则字母）而计数/射程模式没跟着改，导致新那一档永远不进射程时。
- 当交付要求"脚本打印工具版本并把版本写进归档清单"时。
- 当一次构建/一次回归的产物需要在综合后、布局后、布线后各留一份可复算检查点时。

## 3. 不适用 / 失效条件

- 你要的是报告表格的表头与填写口径：用 `../report-forms/`；本模板不产表格。
- 流程本身还没跑通过一次：先把流程走通再抽模板，否则抽出来的是想象中的步骤。
- 只需要"跑一条工具命令"而没有判定：那是构建脚本，不需要 `say()` 与反例；加进去只会得到一堆恒绿的行。
- 目标 shell 不是 bash（纯 PowerShell 环境）：本骨架的 `set -u`、`$(…)`、`local` 语义要重写，退出码与打印约定可以照搬。
- 判据读的文件正是脚本自己刚写的那份（自指）：必须先解决"谁写谁读"的顺序，别在模板上打补丁。

## 4. 前置条件

- bash 4+（`local`、`[[ ]]`-free 的 POSIX 风格判断、`mktemp -d`）。
- 待判定的三份报告/日志文件已存在且属于同一套产物（文件名走槽位，模板不假设具体名字）。
- 一个用作探测锚点的可执行文件名（`REQ_TOOL`）；`TOOL_BIN_DIR` 不设则从 `PATH` 找。
- 打印版本的命令（`VERSION_CMD`）；取不到就把版本行写成 `n/a` 并让"版本可解析"这条判据进 `--self` 的反例射程。
- 输出目录可写（归档目录名含轮次与时间戳，不覆盖上一轮）。
- 若在同一台机器上并行跑多个判定：先确认只有一个进程在写同一份日志（残留进程会把两跑的行混进同一文件，md5 也对得上）。

## 5. 使用方法（在陌生工程里实例化）

模板文件：`script-template.sh`（同目录，一层深，无二级引用）。

槽位计数自检（`grep -o '【填入】' | wc -l`，实跑 2026-10-04）：`script-template.sh` = 1 处正文提示；
本 `SKILL.md` = 1 处；另有 15 个环境变量槽位在 `SLOTS` 段（`TOOL_BIN_DIR REQ_TOOL VERSION_CMD REPORT_DIR
ARCHIVE ROUND R_TIMING R_RESOURCE R_STATUS DONE_TOKEN ROW_RE COL_WNS COL_EP MIN_PARSED SRC_DIR`），
外加一个可选旋钮 `STAGE`（设了才写检查点）。它们的默认值全为空 ⇒ 不填就跑不起来（这正是设计，见第 6 节 rc=3 分支）。

### 5.1 三步实例化

1. 复制并改名，填 SLOTS 段的十个槽位（**只改这一段**）：
   ```bash
   mkdir -p <你的仓库>/build/checks
   cp <技能包>/skill/templates/script-template/script-template.sh <你的仓库>/build/checks/my_gate.sh # 示例
   sed -n '33,50p' <你的仓库>/build/checks/my_gate.sh     # 看 SLOTS 段，逐行决定用环境变量还是改默认值 # 示例
   ```
   **完成后应看到**：`grep -c '【填入】' <你的仓库>/build/checks/my_gate.sh（示例）` 报出一个数（应当只剩判据行那一处提示，正文里不许留）。
2. 用环境变量跑一次（不改脚本也能跑，避免把机器路径写回文件）：
   ```bash
   REPORT_DIR=<报告目录> ROUND=<轮次号> REQ_TOOL=<可执行名> \
   VERSION_CMD='<工具> --version | head -1' \
   R_TIMING=<文件名> R_RESOURCE=<文件名> R_STATUS=<文件名> \
   DONE_TOKEN=<收尾标记> ROW_RE='<该读数行的正则>' COL_WNS=<列号> COL_EP=<列号> \
   bash <你的仓库>/build/checks/my_gate.sh > /tmp/g.txt 2>&1; echo "rc=$?" # 示例
   ```
   **完成后应看到**：`rc=` 是 0/1/2/3 之一；`/tmp/g.txt` 里有 `  <名> <实测> <判据> PASS|FAIL|n/a` 若干行 + 一行 `判定 N 项…` + 一行 `RESULT: …`。
   ⚠ 取退出码不许用管道（`… | tail -2; echo $?` 读的是 `tail` 的状态）——先重定向到文件再 `echo rc=$?`。
3. 跑反例：
   ```bash
   bash <你的仓库>/build/checks/my_gate.sh --self # 示例
   ```
   **完成后应看到**：`SELF: 全绿（7 条）`，退出码 0；任何一条 `FAIL 反例：…` 都说明这条判据没有牙。

### 5.2 加自己的判据时配套的三件（缺一件就是没加）

1. 一条 `say "<名字>" "<实测>" "<判据文本>" <1|0|NA>`；读不到就传 `NA`，不许传 0。
2. `--self` 里加一条反例：合成一份"该红"的读数喂进来，期望退出码与收尾行首词都要对上。
3. 如果这条判据靠"数行数/数条数"过日子，加一条**射程地板**（`MIN_PARSED` 或该判据自己的命中下限），
   否则"扫不到任何东西"也会报绿。

### 5.3 长流程的检查点段

设 `STAGE=<after_synth|after_place|after_route>` 再跑，会把三份读数拷进
`$OUT/checkpoints/<STAGE>_<文件名>`。用途与限制写在脚本第 4 段注释里：从检查点低成本复算后半流程；
跨构建比较前先确认两跑用的是同一个检查点、同一批种子/策略，否则差值没有意义。

## 6. 判读与失败分叉

- **rc=0（PASS）**：可以进采纳/冻结；把 `$OUT/manifest.txt`（含版本与逐件 md5）一起留档。
- **rc=1（FAIL）**：这是结论。逐行找 `FAIL`，按其"实测"列回到源文件；不许改阈值让它过——要改判据必须先说明为什么这条判据本身错了，并留一份改前红色的凭据。
- **rc=2（NOT_MEASURED）**：三种子情形分别是 `NO-VERDICT`（判定 0 项或射程不足）、`PARTIAL`（有 n/a 项）、其余缺凭据。
  下一步是**补输入**（等构建结束、把缺的报告生成出来、或把行正则修对），不是把它读成通过；下游冻结脚本按行首词自然拒绝这一版。
- **rc=3（前置不满足）**：读 `REFUSE:` 那一行点名的变量名与当前值；它发生在 `mkdir` 之前，所以盘上没有半截产物。
- **`--self` 有 FAIL 条**：先修尺子。特别是"rc 对但收尾行首词不对"这一族 ⇒ 说明状态与文案脱钩（下游按词判定会被绕过）。
- **`--self` 全绿但正式跑一直 n/a**：合成件的形状与真报告不同 ⇒ 把 fixture 换成真报告的**副本**（脱敏后）再验一次。

## 8. 提炼来源与边界

- 提炼来源：`build/gates.sh`（三态收尾、`say()`、带符号读数、射程地板注释）、`sim/run_one.sh`（退出码分态、单一进程写日志、provenance 在编译之前取）、`sim/mut_control.sh`（"改前必须红"的反例口径）、`report/LLM_COLLAB.md` 例 4/例 5/例 6（管道吃 rc、`ALL PASS` 里躺着两行 n/a、判据标签被按字节从左边截断）、`report/BUILD.md` 第 1 节（环境变量定位与第一步拒绝）、`docs/timing/README.md`（检查点复算与噪声底标定）。
- 迁移要改的四处：SLOTS 段全部槽位；`ROW_RE`/`COL_*` 换成你的报告行形状；`say()` 的名字列宽（非 ASCII 标签要短或改 ASCII）；反例集合（每条新判据配一条）。
- 失效条件：判定对象不是"从文件读数"而是"跑工具看返回码"时，本骨架要加进程管理与超时；当工具版本行不可解析且你允许它继续跑，退出码就失去意义（本模板选择不允许）。
- 边界：本模板管一支判定脚本的形状，不管目录骨架（`../project-skeleton/`）、不管读数往哪填（`../report-forms/`）、不管寄存器契约（`../interface-contract/`）。
