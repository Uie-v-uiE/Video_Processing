# 验收配方与眼睛判据（人判项怎么写才可重放）

## 适用场景

- 交付前要写"这条怎么算通过"，其中至少有一项要靠人眼看：画面有没有撕裂、切换是否可见、
  指示是否显眼、延迟跟不跟得上动作、外观取舍是否被接受。
- 现场演示：需要在几分钟内、在不熟悉的机器上把一串状态摆出来，并且事后能说清判过什么。
- 症状级触发：判据写完只有"正常/异常"没有"应看到什么"；换个人就复现不出来；
  同一个现象"每次都要凑巧才能看到"；演示靠临场手敲、敲错一步整段废掉。
- 不适用：能完全量化的项（那是台架判据的活，写成三态门禁更省人）；
  本条不替代对照表（声明—证据），它管"人怎么判、怎么留下判过的痕迹"。

## 使用方法

**动手前先查**：显示/输出通路在各层（源、处理链、板侧、上位机、屏）分别改了哪些像素或时序参数——
不查就会把某一层的处理当成"原始效果"来判；上游交付文档点名的验收项原文；平台手册里
观察通路的能力（截图、冻结、慢放、对比度设置）在什么状态下可用。
**先跟用户确认**（外观与演示是人的领域，不能替判）：验收项清单与优先级、
**演示动作顺序**（这一条随时可能被用户改，所以配方里它必须是一个可替换的列表而不是流程）、
观看条件（距离、环境亮度、单屏还是投屏）、由谁来判（判的人不能是写这行代码的人单独定案）。

每条判据写满五段（模板第 1 节即此形状，缺一段就不算写完）：

1. **前置条件**：平台状态、输入源、版本标识、观看条件，全部写成可核对的句子
   （"板子已刷入 <产物标识> 并读回身份一致"，不是"板子已经好了"）。
2. **命令序列**：一步一行，每行注明"跑完应看到什么"；序列要能被另一个人整段照抄。
3. **屏幕上应看到什么**：用**可数的特征**描述——几处、什么颜色、在第几帧、延迟多久、
   持续多长时间。避免"清晰/自然/流畅"这种只有判的人懂词义的词（要用就得给参照物）。
4. **每个不达标分别意味着什么**：分叉列表，"看到 A ⇒ 指向 <哪一层/哪一类原因>，下一步查 <什么>"。
   分叉要覆盖"什么都没看到"（链路断了）——那种情况记 `NOT_MEASURED`，不许记成通过。
5. **记录**：判定人 / 时刻 / 判定时的系统状态（版本、输入、观看条件）/ **原话**（判的人怎么说就怎么记）。

三件必须写清的事：

- **机判替代不了人判。** 机器能替你数帧、量延迟、测亮度、比对像素差；它替不了"这看起来能不能接受"。
  反过来，人也不能替机器给"通过"——人判项的结论只写"人已判 + 原话"，不写成客观读数。
  两者同列时，把可数特征（机）与观感取舍（人）分成两行，各配各的结论。
- **配方要能被另一个人复现。** 判据里凡出现"调到能看见为止"都算没写。
  需要把**两个相邻的像素级现象**放进**同一视野同时判**时，用这几招之一，并在配方里写明用哪一招：
  ① 把两处裁进同一张静止图并排显示并标号；② 找一个共同触发条件把两处冻结在同一时刻；
  ③ 在观察通路上做局部放大（同一帧内放大到能数清像素）；④ 让两处出现在同一动作的
  前后两帧、用慢放固定比较。每种都会引入失真（插值、缩放、时序被改变），失真方式必须写进配方，
  否则第二个人复现的是你的失真而不是现象。
- **演示动作顺序是变量。** 配方把顺序单列成一张可替换的列表（模板第 3 节），
  并保证**每一步都能独立进入、独立判定**。用户当天改顺序时只改那张列表，判据本体不动。

## 失效条件

- **判据词只有主观词**："自然""干净""没问题"。征兆：两个人判出相反结果而都自认有理——
  此时补可数特征与参照物，不要补"更严格的形容词"。
- **观察通路本身改了现象**：截图/缩放/慢放/串流都会改像素或时序，把工具产物当成了被观察对象。
  征兆：某现象只在放大时出现。配方必须写明失真方式，并至少有一条不经过观察工具的粗判。
- **前置条件写在人脑子里**：判过的人换了人就不成立。征兆：同一个配方在不同场次给出不同结论，
  而记录里没有系统状态那一栏。
- **把"没看到问题"记成通过**：屏幕暗、链路未通、输入未接、时间窗口错过，都属于"什么都没看到"
  ⇒ `NOT_MEASURED`。这是本条最贵的失效。
- **顺序写死**：配方把演示流程当固定脚本，用户临时改一步就得重写整条判据。
  征兆：判据里出现"第 3 步之后立刻…"却说不清为什么必须紧跟。
- **判的人与写的人同一人且无旁观记录**：外观项必须由非实现者共同判，或至少让用户当场说一句原话。

## 已验证效果

未量过，属建议：没量过"带配方/不带配方"在评审现场的一次通过率差异。可自查的 3 个读数都可复跑，
数值只在同一设计与同一批人手里成立、随设计变，**不可当普适结论引用**：

1. 每条人判项的五段完整率：缺任一段的条数应为 0（逐条查记录形状即可数）。
2. 陌生人复现演练：换一名没参与的人照配方跑一遍，能独立说出"应看到什么"并给出判定，目标 2/2 条；
   卡住处即配方缺陷，改配方不改人。
3. 记录四要素齐备率（人、时刻、系统状态、原话）：应为 100%；缺"原话"的项按 `NOT_MEASURED` 记账。
