# S30 判据的结论行必须打印"我判了几项、有几项没判"，否则"全绿"可以在主判据根本没跑的情况下成立

## 触发

你有一把聚合型判据（门禁脚本、CI 检查、审计表），它把 N 项小判据合成一句结论。
某天它打印了绿色的总结，而你发现其中几项**今天根本没有可判的对象**——
缺报告、缺凭据、目录里没有那个文件、上游没产出——脚本走的是"这条不判红"的分支。
于是"全绿"这句话的含义已经变了，但结论行一个字都没变。

## 不适用

- 单项判据（没有聚合结论行可写）。
- 那些"缺席本身就是错误"的检查：应当直接判红，而不是打 n/a——本卡只管**已经被你判定为可以不判**的那几项。
- 探索期的一次性脚本（还没有要被它长期守护的对象）。

## 动作

1. **把"不判"变成一等公民**：给红绿计数器之外再加一个 `NNA`（未判数）与一个 `NSAY`（判定数），
   每个 n/a 分支必须走一个会自增的打印函数，而不是散落的 `echo "n/a ..."`。
   散落的 echo 是根因：它写的时候很自然，读的时候没人计数。
2. **让结论行携带范围**，并且分三态，不是一态：
   - 有红项 → `有红项（判定 N 项）`，非零退出；
   - 无红项但有未判 → **`PARTIAL —— 判定 N 项全过，但有 M 项因缺凭据未判`**，非零退出；
   - 无红项且未判 = 0 → `ALL PASS（N 项全部判定）`，零退出。
3. **注意下游是 grep 行首**：如果"未判"那一档仍以 `ALL PASS` 开头，下游的
   `grep '^ALL PASS'` 会照样放行。所以那一档的行首必须换成别的词（这里用 `PARTIAL`），
   这样"只有全判定才允许冻结/发布"这条规则不用改下游就自动生效。
4. **给这条改动留一对对照**：同一份输入，改前打 `ALL PASS`、改后打 `PARTIAL … N 项 / M 项未判`，
   两份输出都留下来。否则你只是声称修好了尺子。

## 完成判据

结论行能被独立读出一个数字对（判定 N、未判 M），且存在一对"同一份输入、改前改后"的输出留档。
本仓库的实例：`build/gates.sh` 今天改前对同一份 r88 报告集打的是
`GATES: ALL PASS` / rc=0（`build/r88_gates_naive.txt`），改后打
`GATES: PARTIAL —— 判定 18 项全过，但有 2 项因缺凭据未判` / rc=1（`build/r88_gates_partial.txt`），
而那两项未判恰恰是**顶层台架与边缘条带**——本仓库最主要的两把机器尺子。
顺带同一族的另一条：每个检查器自己也要打印扫了多少文件（`扫了 353 个手写文件`），
数字变了就说明作用范围漂了。

## 失效边界

- 如果"未判"是**长期状态**（某项判据的凭据结构上就不存在），那么每次结论都是 PARTIAL，
  它会很快被忽略——那时该做的是删掉那一项或把它改成硬要求，而不是留着稀释结论。
- 三态改变了退出码，可能把**历史**重放也变成红（老目录缺新加的凭据文件）；
  上线前先跑一遍旧目录，确认"红的是真缺凭据"而不是"判据读错文件名"。
- 行首换词会让既有的 `grep` 逻辑反转——这是本卡第 3 条的目的，但也是它最容易伤到自己的地方：
  改完必须去看下游谁在读这行（这里是 `build/freeze_evidence.sh` 与 `build/refresh_evidence.sh`）。
