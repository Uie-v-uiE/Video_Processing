# 多字读回必须是"一组"：寄存器窗口的撕裂读数与原子快照口

## 适用场景

设计里有一组寄存器需要**通过同一个读口逐个读回**（本项目：AXI GPIO 的 lane 窗口，
`gpio_o[31:27]` 选 lane、另一个地址读数据），而这组数之间**存在恒等式或包含关系**
——例如"总时长 = 三段之和""计数 = 另两个字段之和""低 16 位与高 16 位同属一个量"。

**不适用**：
- 这组数之间没有任何关系（各自独立的计数器）⇒ 撕不撕裂无所谓；
- 它们更新极慢（比"逐 lane 读完一遍"还慢几个数量级）⇒ 风险可忽略，但仍值得写下判据；
- 只有 1 个字可读 ⇒ 没有"组"可言。

## 使用方法（照抄可用）

1. **先问"这组数之间有没有一条必须成立的式子"**，把它写成主机侧的一条判据。
   本项目写在 `src/host/health_read.mjs` 里：`tot ≥ c1 + c2`（时延三段），字段就叫 `torn`。
   这条判据的价值不在结果，而在**它能区分"硬件错"与"读法错"**（见下）。
2. **判红以后先怀疑读法**。硬件如果是在**同一个 always 块的同一拍**写这一组寄存器的，
   那么任何一次原子读必然自洽 ⇒ 违反恒等式只能是"我分几次读的"。
   复核方法很便宜：**连续读几组**，看式子是否**一会儿成立一会儿不成立**——
   真缺陷通常稳定复现，撕裂则随机。本项目实测 8 组里 3 组破功，且 `c2`（每轮都一样大的那段）
   反而最稳定，完全符合撕裂的形状。
3. **修在硬件里：给这一组加一个快照口。**要点三条：
   - 武装信号取自**读法本身**（本项目用"lane 选择指到这一组的第一个字" ⇒ `arm = (lane==25)`），
     这样任何按正常顺序的读取都自动得到快照，不需要新控制位、不动 BD；
   - 快照就是 `if (arm) begin q_a <= a; q_b <= b; ... end` —— **同一拍同时抄走**，
     于是快照组永远自洽，与抄的瞬间数据是否正在更新无关；
   - 读口导出的是快照，**live 值仍然留着给台架对账**（台架要逐周期验"值对不对"，
     板级要的是"一组自洽"，两件事不能互相顶替）。
4. **判据要按"读法"写，不是按"寄存器"写。**本项目补的是"任意相位武装都必须自洽"：
   在轮次正在进行时扫 600 个相位逐个武装并检查式子，同时打印**判到了多少个可信样本**
   （`trusted=600 violated=0`）。没有那句计数，这条判据会因为一个未初始化变量而空跑（见失效条件）。
5. **读回顺序是协议的一部分**（r52 加 lane24 时才看明白）：武装取自"lane 选择 == 这一组的第一个字"，
   所以**任何后加入这一组的口都必须排在那个第一个字之后**。先读它就会拿到**上一遍**武装的那一轮，
   与这一遍读到的其余成员不同源 ⇒ 判据恒红，而且红的是脚本自己。
   所以本项目的 lane 表把顺序写进注释，并在 `system_top` 的 mux 旁边写"读这一组必须 25→…"。
6. **让快照自己携带"这一组可不可信"**。如果某个成员是**多拍算出来的**（本项目：拍数换 ms 要 32 拍移位减），
   武装可能正好落在那 32 拍里，抄到的商还是上一轮的 ⇒ 快照必须连带抄一个 `pair_ok = ~除法在跑` 的位。
   主机侧看见 0 就**既不判红也不判绿**（本项目把它编在组内：lane24 = `{14'd0, pair_ok, 本轮sticky, ms[15:0]}`）。
   这比"多读几遍期望它错开"稳：撞上的概率 = 除法那 32 拍 ÷ 一轮的拍数（60 fps ⇒ 约 2×10⁻⁵，
   9 fps ⇒ 约 3×10⁻⁶），靠重复采样是碰不出来的，所以必须让硬件把这条信息送出来。

## 已验证效果

Zynq-7020 视频链路，2026-09-24（`report/ISSUES.md` #59，构建 r51）：

- 现象：板级第一次读到端到端时延，`c1 = 5.498 ms` 却 `tot = 5.324 ms`——`c1` 是 `tot` 的一段，
  这在物理上不可能。凭据 `build/lat_tearing_r50.txt`（8 组）与 `build/frozen_r50_lat/health_r50_lat.json`。
- 排除：先写下过一条"根因 = 一轮打点中途被新事件改写"，**读完整段 RTL 后作废**
  （收尾要求配对标志齐 ⇒ `t_commit ≤ t_start ≤ t_done ≤ cyc` 构造性成立）。
- 修完：`frame_latency` 加 `arm` + 五个 `q_*` 快照，`system_top` 用 lane 号武装，读口给快照。
- 台架：`sim/tb_v90_latency.v` 从 11 条加到含 T8b/T8c/T8d/T9/T10/T10b ——
  其中 T8c/T8d 是**对照式**判据（"再跑一轮，live 变了而快照一动不动"），少了 T8c 就分不清
  "快照有效"与"根本没在跑"。当晚受影响的 6 份台架（v90/v92/rotate_window/v84/v85/v86/v89）
  同时全绿；**全量 L1 与 r51 构建是同一批在做，数字以 `sim/xsim_l1_r51.log` 与冻结件为准**，
  写这份技能时全量还没跑完 ⇒ 这里不放总条数（不放没验的数字是本仓库的规矩）。
- **r51 上板后补记（当时留的"未验证"两条已核）**：`torn` 在 8 组读数里**全部为 false**，
  `c3_ms` 每轮都有值 ⇒ 快照口成立，凭据 `build/lat_snapshot_r51.txt`。
  第 5/6 条（读回顺序、`pair_ok`）是 r52 才加的口，板级凭据要等 r52 那一轮填，
  所以这里**不放 r52 的数字**（本仓库的规矩：没验过的数字不上文档）。

## 失效条件

- **恒等式本身不成立**（例如三段确实可能来自不同轮次的设计），那 `torn` 会永远为真，
  此时要么改口径要么把字段拆开，**不许把判据改成"看起来不成立也算对"**。
- 武装信号如果是**脉冲**而不是电平、且会跨时钟域 ⇒ 本方法只适用于"武装与数据同域"；
  跨域时要按翻转位那一套（`skill/pulse_toggle_cdc.md`），否则武装会被吃掉一半。
- 快照组如果又被别处（如 OSD）当"实时值"用，要清楚它的**新鲜度是一个读周期**而不是当前值。
- 主机侧如果按"第 i 遍的 A 口 配 第 i 遍的 B 口"来配对，**必须先确认每一口都读到了 i 个值**：
  少读一口会让两个数组错位，把第 0 遍的商配上第 1 遍的拍数 ⇒ **报出一个假红**。
  假红比不判更糟（它教人去关门禁），所以本项目那条判据在没有对齐保证时直接把
  `osd_ms_matches_tot` 报成 `null`（不判），并单独给出 `osd_ms_lanes_aligned` 说明为什么没判。
- 判据里任何"计数型"字段（判到了多少个样本）**必须初始化并打印出来**：
  本项目 `integer nchk` 忘了清零 ⇒ 条件是 X ⇒ 而 `if (!cond)` 在 X 时两个分支都不走 ⇒
  **一条什么都没判的判据报成 PASS**（`report/ISSUES.md` #60）。
