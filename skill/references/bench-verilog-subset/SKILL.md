## 1. 一句话用途

方言子集与打印窄面，一行一个出处。

## 2. 适用场景

- 当你看到 `syntax error near '`，而去改算术、改位宽都不消失——这类报错从不告诉你"你用了 SystemVerilog"时。
- 当你准备把一份看着很像能过的台架（尤其是按 SystemVerilog 习惯写的）交给按 Verilog-2001 编译的仿真流程时：
  类型转换 `xxx'()`、位宽转换 `{8'(...)}`、`fork…join_any`、**无参 function** 都在这一格；
  把 `edge`/`cover` 这类词当端口名或信号名同样落在这一格。
- 当判据行的非 ASCII 文字在日志里变成乱码，而同一个文件里直接打印的那句完好时。
- 当 `$display` 打出来的数字落在自己那一格之外、或行尾漂出空位——它读起来像对的时候。
- 当一个极值统计永远停在它的初值（哨兵值 `-1` 与无符号量比较那一族）时。
- 当你准备一轮改几百处（压注释、改措辞），或准备用 heredoc 里的脚本生成带转义的源码时。

## 3. 不适用 / 失效条件

- **本层不是判据**：任何结论都不能靠本页自称成立，只能靠 `evals/` 的记录或实测输出；本页写的是"这台工具现在怎么做"，不是"你该怎么判"。
- 失效（版本绑定）：本页记的是**工具行为**不是语言规范，全部在 Vivado/Vitis 2025.2.1（build 6403652）的 `xvlog`/`xsim` 上量到；
  换仿真器或换工具大版本时每一格都要用小台架重新量一遍，`$display` 那两条在别的仿真器里可能完全正常，换工具先重新量再引用
  （版本口径的真相源见 `skill/references/tool-version-drift/SKILL.md`）。
- 不适用：纯 SystemVerilog 工程——上面那些写法在那里合法且行为正确，照本页改反而会削弱表达。
- 不适用：报错在 elaboration 期且指向例化/位宽/多驱动——那是接线那一格（走端口与顶层接线检查），不是方言。
- 不适用：期望值算错、判据结构性红不了——归同族 S20 / S21（见 §8）。本页只覆盖"不报错但不照做"这一族。
- 分界：与 S19 的分界是组合块拿着旧值不放属于敏感表语义，不是方言；跨域结构问题在 S11 / S16。
- 失效：「打出来的数不动」也可能是激励根本没进那条路（声明了却没进位流）⇒ 先用可达性/端口检查确认信号活着。
- 不许越界：本页不给出"该把判据阈值改成多少"，也不替你判断某个报错到底该不该停手。

## 4. 前置条件

- 工具与版本：本条目在 Vivado/Vitis 2025.2.1（build 6403652）的 `xvlog`/`xsim` 下写成；页内数字来自那一支台架轮次（示例取值，需按自身工程替换）。
- 一份能落盘的编译日志：要在里面找 `syntax error near '` 与 `function must have at least one input` 这两个串。
- 一条对方言高危形态的扫描口子（§5 步骤 1 给的是形状，扫描根要换成你自己的仿真与 RTL 树，不要照抄本仓路径）。
- 批量文本手术时，仓库里那支"代码不变性"尺子要在盘上：`build/trim_comments.py`（本仓用法 `python build/trim_comments.py --check`，示例取值，需按自身工程替换）。
- 反例自证要一个几十行的小台架：同一段非 ASCII 文案按四种写法并排，外加 `od -c` 比字节。

## 5. 使用方法

先按症状在下表定位，再按对应动作做；表中"出处"列是本轮打开过的行，不是记忆。

| 症状 / 文本 | 落在哪一格 | 就地降级成什么写法 | 出处（本轮直读） |
|---|---|---|---|
| `syntax error near '`、改算术改位宽都不消失 | Verilog-2001 子集：类型/位宽转换 `xxx'()`、`{8'(...)}` | 用 `* 1.0` 把表达式拉成 real；取整直接赋给 `integer`，**不要再 +0.5**（real→integer 本身四舍五入，加 0.5 等于取两次整，实测会把精确周期顶出 ppm 级偏差，变成一个看起来正常的假时钟）；截位先取模再拼接 | 旧卡 S22 动作 1；台账 `report/log/OVERNIGHT_LOG.md` 第 3905–3906 行（`xvlog` 按 Verilog-2001 编，一天撞四次：`real'()`/`int'()`/`8'()`、`fork…join_any/disable fork`、无参 function、`task` 参数只给第一个写类型） |
| 台架可能挂死并拖垮整轮回归 | `fork…join_any disable fork` | 换成"固定时间窗 + 有界循环"，天然有上界 | 旧卡 S22 动作 1；同上第 3906 行 |
| 编译只说"语法"，指向一个函数名 | **无参 function** | 无参函数就地写进 `always` | 旧卡 S22 动作 1；同上第 3906 行 |
| 报错只指向"语法"，像是命名风格问题 | `edge`/`cover` 这类词被当端口名或信号名（撞保留字） | 换个带后缀的名字即可；**先怀疑方言与顺序，再怀疑算术** | 旧卡 S22 触发与动作 2 |
| 数据看起来慢一拍 | 激励与 DUT 抢同一拍的读（沿上读到旧值） | 激励必须在时钟沿**之后**隔一点时间给出 | 旧卡 S22 动作 2 |
| 前面几行按未声明处理 | 数组的初始化块排在它所依赖的 `wire` 声明之前 | 初始化块必须排在依赖的 `wire` 之后 | 旧卡 S22 动作 2 |
| 一句 `cannot find port` | 端口名/参数名凭模块手册的印象写 | 把例化里出现过的名字全列出来对一遍（命令写在表下"动作侧"第 0 条） | 旧卡 S22 动作 3 |
| 判据行的非 ASCII 文字变乱码，直接打印的那句完好 | 字面量进定宽向量/task 实参时**每字节最高位被清**，ASCII 幸存 | 判据标签字段**只写 ASCII**（形如 `C0a RULER`），要解释就写在同一条 `$display` 的字面量里，或紧跟一条直接 `$display` 的说明行 | 台账 `report/log/ISSUES.md` #68 的追加（本轮直读到第 1940 行）；`report/log/OVERNIGHT_LOG.md` 第 3898 行与第 3973 行 |
| 定宽字段超长时丢的是**头部** | 容量按字节数算，而非 ASCII 文字每字占多字节 | 装超长字符串前按字节算宽度 | 同上两处（第 3898 行、第 1940 行） |
| `%0s` 只剩乱码 | 三元式被折成较短操作数的位宽 | `%0s` 的位置不要放三元式 | 旧卡 S22 动作 4 |
| 整行参数对位被带歪、读起来像对的 | 不认识的格式符**不报错、只是不消费参数** | 格式符只用 `%0d / %0h / %0b / %s / %0t`；带符号的差值用 `%0d`（整数打印自带负号） | 台账 `report/log/OVERNIGHT_LOG.md` 第 3973 行与第 3975 行（本仓那一条实例是 `%+d` 不被认，全仓台架改 `%0d`） |
| 极值统计永远停在初值 | 哨兵值 `-1` 与无符号量比较时被统一成无符号 ⇒ 条件永不成立 | 把无符号那侧显式扩到比较位宽，或加一个"第一次"标志位代替哨兵 | 旧卡 S22 触发与动作 7 |
| 生成出来的源码报错落在**下一行**、或有"未声明标识符" | heredoc/模板语言把转义先吃了一遍；占位符残留在结果里 | 优先用编辑工具直写；一定要脚本生成时用 `chr(92)` 拼反斜杠；写完**立刻**编译/仿真一次，不要把三处改动攒到一起再验；占位符不许残留 | 旧卡 S22 动作 8 |

动作侧还有五条不属于"方言识别"的，但它们同住这一格：

1. 先按症状在上表定位，再做静态扫描：对方言高危形态做扫描，剔掉注释行后命中数为 0 才算绿
   （`grep -rnE "[A-Za-z_][A-Za-z0-9_]*'\(|join_any|disable fork" <仿真与 RTL 树> --include=*.v | grep -v '//'`）。
   完成后应看到：一行命中都没有；有命中就按上表的"降级写法"改，而不是去改算术。
2. 新台架第一跑先把自己打的每一行读一遍，确认每个数字落在它该在的那一格。
   完成后应看到：没有"数字打错位置"的行——它比"打不出来"更难发现，因为它读起来像对的。
3. 批量文本手术必须配一个"代码不变性"判据，而不是靠人眼看 diff：把基线与工作树各自剥掉注释再逐字比，
   代码动了一个字节就红（本仓库 `python build/trim_comments.py --check`）；没有它，"我只改了注释"这句话没有资格进提交信息。
   这类编辑搭在一次本来就要重新综合的构建上，省一轮专门验证。
   完成后应看到：不变性判据绿，且门禁脚本里没有任何一处在读被手术的那些行号。
4. 修要修根：写死在字符串里的"文件:行号"改成编译期行号宏，并加一条静态判据——输出里的每个 `文件:行号`
   必须指得回那一行，且不能是空行或纯注释；**不许**用"跑一遍把所有行号重数一遍"的脚本修（那只是把下一次失准的日期推后）。
   理由值得记住：**指错的出处比没有出处更坏**，它会让人去改一行无关的代码。
   完成后应看到：静态行号判据绿 + 阳性对照（随手把某个行号 +7）红。
5. 破坏范围先量再慌：受影响的文件数与"有没有判据在读它"各一条 `grep` 就够，再决定要不要停手。

## 6. 判读与失败分叉

- 步骤 1（静态扫描）：
  通过 = 剔掉注释行后命中数 = 0。
  失败 = 命中数 > 0 ⇒ `FAIL`，按 §5 表里那一行降级；这一格的红是方言红，不是算术红。
  读不到输入 = 扫描根给错、一条 `.v` 都没扫到 ⇒ `NOT_MEASURED`；**0 命中不等于绿**，先把扫到的文件数念出来。
- 步骤 2（编译日志动态那一半）：
  通过 = 日志里既没有 `syntax error near '` 也没有 `function must have at least one input`。
  失败 = 出现任一个 ⇒ `FAIL`，且这一行就是分诊标志，回去按 §5 表砍方言而不是改算术；
  注意无参 function 这一类**没法用一行 grep 抓**（合法写法的函数名那一行后面才接 `input`）。
  读不到输入 = 日志没落盘或 0 字节 ⇒ `NOT_MEASURED`，不许把"没看到报错"当"没有报错"。
- 步骤 3（反例自证）：
  通过 = 同一段非 ASCII 文案按 ① 直接 `$display` 字面量 ② 作为定宽向量 task 实参 ③ 先赋 `reg [8*N-1:0]` 再 `%0s` ④ `%0s` 打三元式
    打出来，②③④ 与 ① 不一致（`od -c` 显示每字节的最高位被清、ASCII 幸存）⇒ 病灶在"字面量→向量"那一步，本页规则生效。
  失败 = 四条一致 ⇒ 那是别的工具/别的版本，**删条目而不是硬套**。
  读不到输入 = 小台架没跑起来或 `od -c` 输出没留档 ⇒ `NOT_MEASURED`。
- 步骤 4/5（批量手术后追加两问）：
  通过 = 行号引用静态判据绿，且阳性对照（随手把某个行号 +7）红。
  失败 = 不变性判据红 ⇒ 那一轮不只是注释，按本仓口径这句"只改了注释"不能进提交信息。
  读不到输入 = 没有可比的基线件（工作树与参照不同源）⇒ `NOT_MEASURED`。
- 通用：本页任何一格若在你的工具上重测量不出同样症状，那一格对你就是 `NOT_MEASURED`，照抄会造出假事实。
