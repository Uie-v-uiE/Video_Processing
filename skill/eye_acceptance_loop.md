# S23 · 眼睛不在代理这一侧时，怎么把"看一眼"变成一条能判的观测

> 四段式：适用场景 / 使用方法 / 已验证效果 / 失效条件。
> 来源：2026-09-27 那一轮"`split` 二分 + 用户看屏"（`report/OVERNIGHT_LOG.md` §80 一、§81 五、§82），
> 以及同一天傍晚我自己写错的那句"已发"（`report/OVERNIGHT_LOG.md` §80 三、`report/AI_COLLABORATION.md` §6 第 4 笔）。

## 适用场景

- 症状只有眼睛能判：**一条线 / 一条带 / 闪烁 / 走样 / 颜色不对**，而你手里没有一条命令覆盖那一路。
- 分工是"**代理发命令、人看屏**"：代理通过串口或控制台一次一条地把命令打进去，人来报看见了什么。
  这种分工下，代理的每句话都是操作者唯一的线索 —— 一句没发出去的"已发"就会让他去找一个不存在的缺陷。
- 也用于**修完之后那一半**：台架判不到的那一路必须有人签（本工程图卡那一路 `fb_vis` 在顶层台架里恒为 1，
  所以 `board/HANDS_ON.md` 第 11 组明写"这一眼只能人来"）。
- **不适用**：① 任何能被一条命令判的症状 —— 先去造判据（[S20](bench_self_inflicted_reds.md)、
  [S21](criterion_blind_spot.md)），别占用人；② 画质好坏的主观收敛（本方法只判**归属**，不判审美）；
  ③ 命令通道本身不可用时（先修连线与串口，见 [S7](board_eth_uart.md)）。

## 使用方法

1. **先证明这一眼不可被机器替掉**，并把那句话写下来。做法：打开覆盖那一路的台架，找出它为什么不覆盖
   （本工程是台架喂的是 DDR 片源，图卡那一路根本没有面板级判据）。写不出这句，这一眼就只是形式主义，
   下一个人会拿它当免检。
2. **给这一眼一个配方，不是一个提问**。三样必须写死：**前置状态**（哪一路片源、哪一档倍率、标记线开没开）→
   **一次一条的命令** → **每一个"不"分别指向什么病灶**。形状照 `board/HANDS_ON.md` 第 11 组那张五行表抄：
   那一组只花 30 秒，却把"某条带属于哪一路"判死了。
3. **用一个能切换归属的旋钮做二分**，而不是问"有没有东西"。本工程的旋钮是 `split`：
   `split 100` = 整屏原图抽头、`split 0` = 整屏处理抽头、`split 50` = **一屏两条抽头同看**（最省事的一档，
   一次回答"跨不跨缝"）。然后**一次问不超过三条、每条只问一个事实**：
   ① 在不在？② 宽度跟不跟着倍率走？③ 颜色跟不跟着内容走？三个答案就把"哪一路 / 几何还是取值 /
   是不是我自己造出来的"分开了。
4. **先排除自己造出来的伪像，再下结论**。本工程两次都是自己产物冒充缺陷：2 px 标记线（所以配方里
   第一步之前要 `split show` 确认 `marker=off`）与"我说已发但那一条命令其实没发"。
   凡是"操作者看到的异常"与"代理刚刚动过的东西"在同一条边上，先关自己的那个开关。
5. **状态断言只从文件里读，不从记忆里读**。要说"我已经发了 X"，就去那一次的捕获里 grep 这一行：
   `board/uart_cap_once.ps1 -Port COM6 -Seconds 20`（一次性捕获）或 `board/uart_cmd_script.ps1`
   （按脚本批量发并留档）；成套复验是 `src/host/uart_cmd_check.mjs`。答"没发"就当场收回上一句并说明
   实际发了什么 —— 收回比面子便宜得多。
6. **看完立刻把这一眼换成可复跑的东西**。工程里的正确顺序是：眼睛报现象 → 加一条判据（`ISSUES #102`
   的眼睛 → 顶层 `C8a/C8b` 两路各判第 0 列、各带覆盖地板）→ 下一次同类问题不必再叫人。

## 已验证效果

- **一次二分把归属钉死**（`report/OVERNIGHT_LOG.md` §80 一）：`split 100` 左线在、顶带看不到；
  `split 0` 两条都看不到；`split 50` 一屏同看 ⇒ 顶带与左线**只在缝的左边 = 原图抽头**，右边缘与底边干净。
  病灶由此收敛到 `pix_raw → raw_line_delay → orig_skid → orig_disp` 这一段，排除了映射器、处理链、
  PS 写 DDR。**同一次还抓到台架自己的洞**：`tb_v98` 里 `split_ctl_tb = 19'd0` ⇒ 缝一直在 0%，
  三条"缝左右"的列号判的是**同一路** —— "尺子有，但它看着的是另一路"。
- **五档观察矩阵**（`report/ISSUES.md` #102）：2.0× / 1.0× / 0.75× / 0.50× / 0.25× 各自记"有没有、
  多宽、别的边怎样"，外加五条排除项（`SPLIT 0|100`、`BILIN OFF`、`SPLIT MARKER 0`、`SRC 0`、OSD 正常），
  **每一条排除都是一条串口命令**。用户那句"只要缩放到非 100 % 就在"因此变成了可判的宽度规律。
- **这一眼最后怎么关闭的**：`report/OVERNIGHT_LOG.md` §82 记下操作者原话第三句
  "左边和顶部的条块都消失了"，机器那一半是 `C8a/C8b` 各 1178 格、0 不符（`report/ISSUES.md` #102 第二刀）
  与模块台架 T7/T7k（把修复 revert 掉只红 T7）⇒ 眼睛与判据各签一半，谁也没替谁签。
- **写错一句的代价有账**：17:5x 声称 `pipe 000010000` 已发，而上一条调用只发了 `src 2` 与 `split 50` ⇒
  操作者如实回"画面没变化啊还是原图"（`report/OVERNIGHT_LOG.md` §80 三）。同一族第二次是一整轮
  以为在"无旋转"下测、实际跑在 339°，因为当时串口根本没有角度读数（`report/OVERNIGHT_LOG.md` §78 四；
  这条空档在 `board/HANDS_ON.md` 里以 #101 被引用了三回，而 `report/ISSUES.md:4694` 那段
  "#100 现场追加两条命令层空档"才是它的账本原文）⇒
  **代理的状态断言必须点名回读字段**，没有那个字段就先造它。同一段里还有一条更早的：
  一次 `SPLIT 20` 留下的标记线被当成操作者报的缺陷收下（同一个 #100，当场收回）——
  那正是使用方法第 4 条存在的原因。
- **反向也成立**：一个功能到底有没有在跑，最终要能让眼睛看出差别。`report/ISSUES.md` #104 给自己开的
  修法第三步就是"`bilin on/off` 在某个角度下必须**看得出差别**，看不出差别就是还没修好"——
  这是"判据必须能红也能绿"的视觉版，与 [S21](criterion_blind_spot.md) 同源。

## 失效条件

1. **那一路其实有面板级判据时，这一眼不该再要人**。先回去问"台架为什么不覆盖它"（本工程 SD/ETH 两路
   就有机器判据），能补判据就补判据；把可自动化的症状交给人眼，是在花别人的时间换自己的安心。
2. **没有可切换归属的 A/B 通道时，"看一眼"没有区分力**。本方法靠的是 `split` 这一类能选择抽头的旋钮；
   没有它就先造一个（哪怕是一次性的串口命令），否则"有没有线"这个问题会得到一个无法归因的答案。
3. **判据所看的那条边在这一档碰不到时，不算证据**。本工程 1.00× 那一档画面铺满整屏 ⇒ 屏上没有一列背景，
   多出来的线贴在同一个非黑段里（`report/ISSUES.md` #93 与 [S21](criterion_blind_spot.md) 是同一课），
   再叠上图卡自己那圈亮边框 ⇒ 左缘那一格根本没法用眼睛判。**换一档再看，比再看一次有用。**
4. **症状是时间类的**（几秒一次、只在看的时候闪）⇒ 一次"看一眼"必然漏。要的是带时间戳的连续捕获
   或一个计数器出口，不是第二双眼睛。
5. **眼睛只回答"在不在 / 在哪一路 / 跟不跟"，不回答"对不对"**。任何数值结论仍要走采集链
   （[S14](metrics_gap_sum.md)、[S9](frameid_loss_signature.md)）；把"看起来正常"写进报告就是本条要防的错。
6. **操作者不在场时不许自代签**。本仓库的口径写在 `report/AI_COLLABORATION.md` §5：
   凡是只有台架数、没有板上那一眼的结论，对外表述必须停在"通过 L1/门禁"这一档。
