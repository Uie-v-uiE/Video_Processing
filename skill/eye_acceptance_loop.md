# S23 · 眼睛在操作者那侧时，把"看一眼"变成一条能判、能归档的观测

## 触发
- 当你准备叫人来"看一眼"，而这一路你手里没有一条命令覆盖它时。
- 当症状只有眼睛能判：一条线 / 一条带 / 闪烁 / 走样 / 颜色不对。
- 当分工已经是"代理发命令、人看屏"，而代理的每句话成了操作者唯一的线索时。
- 当一个功能修完、但台架判不到那一路、必须有人签收最后那一半时。

## 不适用
- 任何能被一条命令判的症状 —— 先去造判据（见 [S20](bench_self_inflicted_reds.md)、
  [S21](criterion_blind_spot.md)），别占用人。
- 画质好坏的主观收敛：本方法只判**归属**，不判审美。
- 命令通道本身不可用时：先修连线与串口（见 [S7](board_eth_uart.md)）。
- 症状是时间类的（几秒一次、只在看的时候闪）：要的是带时间戳的连续捕获或一个计数器出口，不是第二双眼睛。

## 动作
1. **先证明这一眼不可被机器替掉**，并把"台架为什么不覆盖它"那句话写下来。写不出这句，这一眼就只是
   形式主义，下一个人会拿它当免检。
2. **给这一眼一个配方，不是一个提问**。三样写死：前置状态（哪一路片源、哪一档倍率、标记线开没开）→
   一次一条的命令 → 每一个"不"分别指向什么病灶。
3. **用一个能切换归属的旋钮做二分**，而不是问"有没有东西"。本工程的旋钮是一个 0/50/100 的分割量
   （0 = 整屏处理、100 = 整屏原图、50 = 一屏两条同看，最省事的一档，一次回答"跨不跨缝"）。然后**一次
   问不超过三条、每条只问一个事实**：①在不在？②宽度跟不跟着倍率走？③颜色跟不跟着内容走？三个答案
   就把"哪一路 / 几何还是取值 / 是不是我自己造出来的"分开。
4. **先排除自己造出来的伪像，再下结论**。凡是"操作者看到的异常"与"代理刚刚动过的东西"落在同一条边上，
   先关自己的那个开关（如确认标记线是 off）。
5. **状态断言只从捕获文件里读，不从记忆里读**。要说"我已经发了 X"，就去那一次的捕获里 grep 这一行
   （一次性捕获或按脚本批量发并留档）。答"没发"就当场收回上一句并说明实际发了什么——收回比面子便宜得多。
6. **看完立刻把这一眼换成可复跑的东西**：眼睛报现象 → 补一条判据 → 下一次同类问题不必再叫人。

## 完成判据
- 这一眼要么绑出一条可判的归属结论（"某条带属于哪一路"），要么被登记成"未验证"；不许写"看起来正常"。
- 每条排除项都是一条能发的命令，且它的实际发出**能从捕获文件里 grep 到**（反例：声称"已发"，
  而上一条调用其实只发了别的两行，操作者如实回"画面没变化"——这就是本条要防的）。
- 关闭一次眼睛验收要**两半都签**：操作者原话 + 机器判据的数字（各签一半，谁也没替谁签）。

## 失效边界
- 那一路其实有面板级判据时，这一眼不该再要人——把可自动化的症状交给人眼，是花别人的时间换自己的安心。
- 没有可切换归属的 A/B 通道时，"看一眼"没有区分力：先造一个旋钮（哪怕一次性命令），否则"有没有线"
  会得到一个无法归因的答案。
- 判据所看的那条边在这一档碰不到时不算证据（画面铺满整屏 ⇒ 屏上没有一列背景可对照）；
  **换一档再看，比再看一次有用**（与 [S21](criterion_blind_spot.md) 同源）。
- 眼睛只答"在不在 / 在哪一路 / 跟不跟"，任何数值结论仍要走采集链（[S14](metrics_gap_sum.md)、
  [S9](frameid_loss_signature.md)）。操作者不在场时不许自代签。
