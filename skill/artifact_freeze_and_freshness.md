# S15 · 交付单元是"一套产物"：门禁自报新鲜度，证据按 md5 成套冻结

## 触发

- 当你准备念门禁、抄报告里的数字，而实现可能还在跑（门禁读的是磁盘上现成的报告文件）。
- 当门禁结果与上一版**一字不差**、全绿得没有理由。
- 当你把"一个 bit"当成交付单元，而 xsa / elf / 综合与实现报告散在工作目录里、各自都会被下一次构建覆盖。
- 当有人需要回答"这个数是哪一次构建出来的"。
- 当你的证据文件名按"第 N 轮 / 第 N 次"命名，而 N 靠人临时数。

## 不适用

- 只跑一次、不留历史、也不需要复现的探索性实验。
- 产物由打包系统一次性生成并自带版本标识（无需自建新鲜度检查）。
- 只有一件产物的工程（没有"成套"可言）；但"是不是同一批"这个问题对任何多文件证据都还在。

## 动作

1. **让**门禁脚本自报"这套产物是不是同一批"：读报告前打印主控产物与报告的写入时间差，超过"一次构建的正常跨度"就 WARN（阈值按工程量：综合 ~4 min + 实现 ~8 min ⇒ 取 10 min 一档，换工程要重量）。
2. **给**检查器自己写判据，两跑：拿一套已知成套的产物跑 ⇒ 必须不响；把主控产物的时间戳改到 2 小时前再跑 ⇒ 必须响。两次都过才算这条告警是活的（例：`bash build/gates.sh <目录>`）。
3. **把**交付单元定义成"一套"：一条命令把 bit / xsa / elf / 综合与实现报告**一起**复制进一个新的冻结目录，复制后立刻自校验（例：`bash build/freeze_evidence.sh <号>`，判据是 `md5sum -c` 的 OK 行数等于该套文件数）。
4. **在**人读的 MANIFEST 里写四件事，缺一条就是给未来的自己埋雷：这一版改了什么（源码级）/ 门禁数字 + 复核命令 / 板级验到哪一条、哪几条**没验**（没验要写"没验"，不许靠沉默）/ 刻意没收的文件与原因。
5. **给**证据文件名带上不会撞车的身份：用时间与内容哈希，不用"第 N 轮"；脚本落盘前先列一遍目标目录。
6. **每次**改完固件都重新成套冻结一次，或在 MANIFEST 写明"本目录那份 elf 已被后续某次提交取代"（elf 与 bit 不同步是同一族的坑）。
7. **把**失败版本也成套留下，并明确标注"反例，不要拿去演示"。

## 完成判据

- 一条反例命令：把主控产物时间戳改旧 ⇒ 门禁输出里**必须**出现那一行 WARN；成套目录 ⇒ 必须没有。
- 一个数字关系：任意两个冻结目录各自 `md5sum -c` 都通过，而门禁念出的数字**互不相同** ⇒ "这个数是哪一套"有唯一答案。
- 一条硬约束：新鲜度报 WARN 时整轮**判红**（不许在可疑的成套关系上给绿），回退只能**按套**回退，不是"猜上一个 bit"。
- 交付前自问：MANIFEST 的"没验"那一栏是空的吗？空得可疑就说明有人在靠沉默。

## 失效边界

- mtime 会被复制、同步盘、checkout 改动 ⇒ mtime 只当"新鲜度提醒"，**身份认定永远用 md5**。
- 复制会把复制件的时间统一成"现在" ⇒ 冻结目录永远测不出偏差；这条判据只对正在写的工作目录有意义，别拿冻结件当"通过"的证据。
- 构建流程没写主控产物（例如只跑到 checkpoint）时报"没成套"是**真信号**，不要为了消警去改阈值。
- 分界：本条管产物与报告的成套性、新鲜度；"文档里念的当前版本对不对"是文档时效判据（`src/host/doc_currency_check.mjs`），机制不同、别混着修。
