# S22 · 仿真器的 Verilog-2001 方言子集：它不报错，但不按你写的做

## 触发
- 当你看到 `syntax error near '`，而去改算术、改位宽都不消失——这类报错从不告诉你"你用了 SystemVerilog"
- 当你准备把一份看着很像能过的台架（尤其是按 SystemVerilog 习惯写的）交给按 Verilog-2001 编译的仿真流程：
  类型转换 `xxx'()`、位宽转换 `{8'(...)}`、`fork…join_any`、**无参 function** 都在这一格；
  把 `edge`/`cover` 这类词当端口名或信号名同样落在这一格
- 当判据行的非 ASCII 文字在日志里变成乱码，而同一个文件里直接打印的那句完好
- 当 `$display` 打出来的数字落在自己那一格之外、或行尾漂出空位——它读起来像对的
- 当一个极值统计永远停在它的初值（哨兵值 `-1` 与无符号量比较那一族）
- 当你准备一轮改几百处（压注释、改措辞），或准备用 heredoc 里的脚本生成带转义的源码

## 不适用
- 换仿真器或换工具大版本：本页记的是**工具行为**不是语言规范，每条都要用小台架重新量一遍
- 纯 SystemVerilog 工程：上面那些写法在那里合法且行为正确，照本页改反而会削弱表达
- 报错在 elaboration 期且指向例化/位宽/多驱动：那是接线那一格（走端口与顶层接线检查），不是方言
- 期望值算错、判据结构性红不了：归 [S20](bench_self_inflicted_reds.md) / [S21](criterion_blind_spot.md)

## 动作
1. 先当语法砍、再谈算术：见到上面三种形态就地降级成 Verilog-2001 写法——用 `* 1.0` 把表达式拉成 real；
   取整直接赋给 `integer`，**不要再 +0.5**（real→integer 本身四舍五入，加 0.5 等于取两次整，
   实测会把精确周期顶出 ppm 级偏差，变成一个看起来正常的假时钟）；截位先取模再拼接；
   无参函数就地写进 `always`；`fork…join_any disable fork` 换成"固定时间窗 + 有界循环"，
   天然有上界，顺带把"台架挂死拖垮整轮回归"一起解决
2. 把保留字与声明顺序也算进这一格：**先怀疑方言与顺序，再怀疑算术**。
   `edge`/`cover` 这类词拿来当端口名或信号名会撞保留字，而报错只指向"语法"，容易让人去查命名风格
   （换个带后缀的名字即可）；激励必须在时钟沿**之后**隔一点时间给出，否则与 DUT 抢同一拍的读，
   症状是"数据看起来慢一拍"而真实原因是台架在沿上读到了旧值；数组的初始化块必须排在它所依赖的
   `wire` 声明之后，否则前面那几行按未声明处理
3. 别凭模块手册的印象写端口名与参数名：把例化里出现过的名字全列出来对一遍
   （`grep -oE "\.[A-Z][A-Z0-9_]+\s*\(" | sort -u`）——拼错的代价是一句 `cannot find port`
4. 判据的标签字段**只写 ASCII**（形如 `C0a RULER`），要解释就写在同一条 `$display` 的字面量里，
   或紧跟一条直接 `$display` 的说明行；`%0s` 的位置不要放三元式（整个三元式会被折成较短操作数的位宽，只剩乱码）；
   定宽向量装超长字符串时**保留尾部、丢掉头部**，而非 ASCII 文字每字占多字节 ⇒ 容量按字节数算
5. 格式符只用 `%0d / %0h / %0b / %s / %0t`；带符号的差值用 `%0d`（整数打印自带负号）——
   不认识的格式符**不报错、只是不消费参数**，于是后面所有参数的对位整体带歪
6. 新台架第一跑先把自己打的每一行读一遍，确认每个数字落在它该在的那一格；
   "数字打错位置"比"打不出来"更难发现，因为它读起来像对的
7. 别拿 `-1` 当哨兵去和无符号 net 比（比较会把两侧统一成无符号 ⇒ 条件永不成立）：
   把无符号那侧显式扩到比较位宽，或者加一个"第一次"标志位代替哨兵
8. 生成含转义的源码优先用编辑工具直写；一定要脚本生成时用 `chr(92)` 拼反斜杠（普通字符串里的转义会被
   模板语言先吃一遍，报错还会落在下一行），写完**立刻**编译/仿真一次，不要把三处改动攒到一起再验；
   占位符不许残留在生成结果里（它会以"未声明标识符"的面目出现）
9. 批量文本手术必须配一个"代码不变性"判据，而不是靠人眼看 diff：把基线与工作树各自剥掉注释再逐字比，
   代码动了一个字节就红（本仓库 `python build/trim_comments.py --check`）；没有它，"我只改了注释"
   这句话没有资格进提交信息。这类编辑搭在一次本来就要重新综合的构建上，省一轮专门验证
10. 修要修根：写死在字符串里的"文件:行号"改成编译期行号宏，并加一条静态判据——输出里的每个 `文件:行号`
    必须指得回那一行，且不能是空行或纯注释；**不许**用"跑一遍把所有行号重数一遍"的脚本修
    （那只是把下一次失准的日期推后）。理由值得记住：**指错的出处比没有出处更坏**，它会让人去改一行无关的代码。
    破坏范围先量再慌：受影响的文件数与"有没有判据在读它"各一条 `grep` 就够，再决定要不要停手

## 完成判据
- 一条命令出红/绿（静态那一半）：对方言高危形态做扫描，剔掉注释行后命中数为 0 才算绿
  （`grep -rnE "[A-Za-z_][A-Za-z0-9_]*'\(|join_any|disable fork" <仿真与 RTL 树> --include=*.v | grep -v '//'`）
- 一条日志出红/绿（动态那一半）：编译日志里出现 `syntax error near '` 或
  `function must have at least one input` ⇒ 红，且这一行就是分诊标志，回去按动作 1 砍方言而不是改算术
  （无参 function 这一类没法用一行 grep 抓：合法写法的函数名那一行后面才接 `input`）
- 反例自证（几十行的小台架，四种写法并排 + `od -c` 比字节）：同一段非 ASCII 文案分别按
  ① 直接 `$display` 字面量 ② 作为定宽向量 task 实参 ③ 先赋 `reg [8*N-1:0]` 再 `%0s` ④ `%0s` 打三元式
  打出来 ⇒ ②③④ 与 ① 不一致（每字节的最高位被清、ASCII 幸存）就说明病灶在"字面量→向量"那一步、本页规则生效；
  若四条一致，那是别的工具/别的版本，**删条目而不是硬套**
- 批量手术后追加两问：行号引用静态判据必须绿，且阳性对照（随手把某个行号 +7）必须红；
  同时确认门禁脚本里没有任何一处在读这些行号

## 失效边界
- 本页是版本绑定的工具行为：`$display` 那两条在别的仿真器里可能完全正常，换工具先重新量再引用
- 它只覆盖"不报错但不照做"这一族；会报错且报错指向例化/位宽/多驱动的，先走接线与端口检查那几条
- 与 [S19](combinational_block_misses_task_reads.md) 的分界：组合块拿着旧值不放是敏感表语义，不是方言；
  跨域结构问题在 [S11](pulse_toggle_cdc.md) / [S16](cdc_pair_baseline_gate.md)
- "打出来的数不动"也可能是激励根本没进那条路（声明了却没进位流）⇒ 先用可达性/端口检查确认信号活着
