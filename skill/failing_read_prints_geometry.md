# 让失败自己报出几何量：把"偶发/环境"类误判定成"定点数据缺陷"

## 适用场景

一个操作**在固定位置**失败（同一帧号、同一行号、同一序号、同一通道），但错误信息只有
一句"读失败 / 超时 / 不工作"。这类签名最容易被安到**时间**方向的因头上——并发挤的、
控制器忙、时钟被拉慢、时序不稳——因为这些解释**不需要任何新证据**就能自圆其说。

本技能就是用来打掉这一整类误判的：**在失败分支上打印失败者自己算出来的地址/索引/边界**，
让"数据位置错"与"时机错"一句话分开。

## 使用方法

失败分支上至少打这四类量，一条就够判：

1. **它试图访问的位置**（LBA / 指针 / 数组下标 / 寄存器地址）；
2. **这个位置是怎么来的**（上游的中间量，例如簇号、偏移、行号）；
3. **合法边界**（分区末尾、缓冲区容量、数组长度）—— 不要让人去查手册；
4. **一个当场算出的分类**，例如 `IN-RANGE` / `OUT-OF-RANGE`。

写成一行，失败时才打（成功路径零开销）：

```c
xil_printf("[SDRD!] lba=%u n=%u clus=%u part_end=%u %s (data_lba=%u spc=%u)\r\n", ...);
```

配套两条纪律：

- **判据自己要有反例**。加了检查，就要证明它能红：把缺陷改回去重下一版，看它是否报警
  （本项目是 `dir_selftest()` + 一次真实的"字节序改回去→挂载被拒"）。
- **定点性要先确认再归因**。同一帧号复现两次以上 + 一次定点跳帧（N 好 / N+1 坏），
  才允许写"偶发"或"竞态"。

## 已验证效果

ISSUES #50：SD 播放在第 3584 帧必失败，先前被记成"并发挤出来的读超时"，加了重试也不治。
一行 `[SDRD!]` 打出的现场是

```
lba=536959104  clus=16778886(=0x01000686)  part_end=62332928  OUT-OF-RANGE
```

三个数直接锁死因果链：目录项 `DIR_FirstClusterHi` 是 16 位**小端**字，代码按大端拼了两个字节；
把高字换回来是 `0x00010686 = 67206`，与"按文件长度推算的连续布局首簇 67205"只差 1；
再由 `clus_lba()` 精确复现出打印的那个 LBA。→ 卡从头到尾是好的，FAT 也是好的。
修完的板上凭据：155 s 串口连续抓取，帧窗 3500→4300 平稳跨过坏点，第一次整卡（4398 帧）播完并回绕。

**为什么这一招专治这一类**：字节序拼反的错误在数值小的字段上是**不可见**的（高字为 0 时怎么拼都是 0），
所以它"只在某个数据位置之后发作"——任何基于时间的假设都解释不了这种"位置选择性"，
而位置选择性正是数据缺陷的签名。

## 失效条件

- 失败**不定点**（同一操作在不同位置随机失败）⇒ 打印几何量仍然有用，但结论方向要换回时间/电源/时序。
- 打印本身要走那条已经坏掉的通路（例如打印前要先读同一个设备）⇒ 只能打到主机侧日志或预先攒在内存里事后导出。
- 现场量太多的行会被串口缓冲截断：本项目就因此误读过一次"证据"（乱码输出不算输出，**判据文件要整份读完**）。
- 边界值算错会让分类骗人（`part_end` 要从 MBR/BIOS 参数读，不要假设容量），
  所以打印时把边界**和它的来源量**（`data_lba`/`spc`）一起打出来，让人能复核分类。
