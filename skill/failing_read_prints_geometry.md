# S17 · 让失败分支自己报出几何量：把"定点数据缺陷"从"偶发/环境"里分出来

## 触发
- 当一个操作**在固定位置**反复失败（同一帧号、同一行号、同一序号、同一通道），而错误信息只有一句
  "读失败 / 超时 / 不工作"时。
- 当你正准备把这种失败解释成**时间方向**的因头（并发挤的、控制器忙、时钟被拉慢、时序不稳）时——
  这类解释不需要任何新证据就能自圆其说，正是本条要拦的。
- 当一个判据涉及"第几拍 / 第几格"，而你能推出好几套都说得通的解释时。

## 不适用
- 失败**不定点**（同一操作在不同位置随机失败）：打印几何量仍有用，但结论方向要换回时间 / 电源 / 时序。
- 打印本身要走那条已经坏掉的通路（例如打印前要先读同一个设备）：这时只能打到主机侧日志，
  或预先攒在内存里事后导出。
- 现象本身能被一条命令判（那不是"看一眼"的活，也不是本条；先去补判据，见
  [S21](criterion_blind_spot.md)）。

## 动作
1. **在失败分支上至少打四类量，一条就够判**：① 它试图访问的位置（LBA / 指针 / 数组下标 / 寄存器地址）；
   ② 这个位置**怎么来的**（上游中间量，如簇号、偏移、行号）；③ 合法边界（分区末尾、缓冲区容量、
   数组长度）—— 别让人去查手册；④ 一个当场算出的分类（`IN-RANGE` / `OUT-OF-RANGE`）。
2. **写成一行、只在失败时才打**（成功路径零开销）。把边界**和它的来源量**一起打出来，让人能复核那个
   分类，而不是只能信它。
3. **给判据自己配一个反例**：加了检查就要证明它能红——把缺陷改回去重下一版，看它是否报警
   （本仓库是一次真实的"字节序改回去 → 挂载被拒"）。
4. **定点性先确认再归因**：同一位置复现两次以上 + 一次定点跳帧（N 好 / N+1 坏）之后，才允许写
   "偶发"或"竞态"。
5. **RTL 台架里的同一招**：只要判据涉及"第几拍 / 第几格"，就让**被测对象自己报出它那一拍的坐标**——
   分层引用各模块内部那个对齐量、打印出来（本项目四处引用把"三个模块猜了三版"一句话裁决成"滞后 =
   3 个有效像素"）。有多套合理解释时，打印一次的代价远低于再猜一轮，而且打印结果能被下一个人复核，
   推断不行。

## 完成判据
- 那一行打印能**同时锁死因果链**：位置、来历、边界、分类四者自洽，且把打印值套回换算式能精确复现
  出访问位置（本项目反算出"按大端/小端拼字节的差 1"，直接指到字节序拼反）。
- 判据能红也能绿：缺陷改回去它必须报警。
- 反例：字节序拼反在数值小的字段上**不可见**（高字为 0 时怎么拼都是 0），所以它"只在某个数据位置
  之后才发作"——这种**位置选择性**任何基于时间的假设都解释不了，是数据缺陷的签名。

## 失效边界
- 现场量太多会被串口缓冲截断：乱码输出不算输出，**判据文件要整份读完**再下结论。
- 边界值算错会让分类骗人（边界要从分区/固件参数读，不要假设容量）——所以第 2 步把来源量一起打。
- 判据的**输出本身坏掉**时（如打印用了不支持的格式符，糊成一串），它的红与绿都不算证据（见
  [S20](bench_self_inflicted_reds.md)）。
- 与 [S9](frameid_loss_signature.md) 的分界：本条管"失败时打什么"，S9 管"整条流丢没丢字"的取证图案。
