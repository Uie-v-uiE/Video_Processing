# S5 · 与大模型协作的边界：判断必须能追溯到文件与数字

> 四要素：适用场景 / 使用方法 / 失效条件 / 来源。索引见 [README.md](README.md) 的 A 组。
> **四条可抄的提示词模板在 [SKILL.md](SKILL.md)**（要假设 / 要判据 / 要证据 / 要交代）。
> 本文件讲的是那四条**为什么长这样**，以及另外两条只在特定分工下才用到的模板。

## 适用场景

- 用大模型写 RTL、定位上板问题、整理交付材料，而且**要求每个结论能追溯到文件与数字**。
- 工程里已经有一批可跑的资产（台架、构建脚本、报告、回读工具）。
  **没有可执行判据时本工作流不成立**——那时模型说什么你都没有办法驳回，纪律就退化成仪式。
- 不适用：需要肉眼判定的画质问题（缩放走样、色彩、抖动），见失效条件 4。

## 使用方法

### 上下文的给法（一次给全，之后只给增量）

器件的**完整 part 号**、工具链**精确版本**、架构图路径、失败日志**原文**（不是你的转述）。
日志原文这一条不能省：模型对"我截了 20 行"的日志会补出它以为在中间的那 100 行。

### 两条额外模板（分工与验收）

3. 交叉阅读（只读角色，防止和构建抢 `sim_work`）：
   > 只读，不许改文件、不许跑仿真。给我 3 个候选根因，每个附**文件路径 + 行号 + 那几行的原文**。
   > 行号你不确定就写"不确定"，不要估。

   本仓库把这句话钉成了硬要求，因为一次交叉阅读里出现过"引用了一个不存在的行号"——
   估出来的行号看起来和读出来的一模一样，只有回原文才能分辨。
4. 验收它的结论（主代理侧）：
   > 逐条给出：结论 / 支撑它的文件与数字 / 你为了得到它跑了什么命令。
   > 我这边会**直读**同一份文件复核；对不上的那条降级为假设，不进报告。

### 三条被验证过有用的习惯

1. **要求可证伪**：让模型写"若假设成立应看到 X"，再把 X 变成一条能跑的判据。
   范例：把"拆分 impl-only 时钟组"写成判据——"若实现阶段时序数字发生变化，就说明原先
   'synth 阶段无约束'的假定是错 ⇒ 停下重查"，结果 `build/system.bit` 的 md5 与上一版
   **逐字节相同** ⇒ 改动中性被证明（`docs/log/OVERNIGHT_LOG.md` R07）。
2. **凡"综合器才知道"的问题，用最小实验回答，而不是问模型**：
   `sim/probes/` 下那几个探针（同一存储器的 5–6 种写法变体，回答"为什么 `ram_style` 被忽略"、
   "1W1R 与 1W2R 各吃多少 RAMB36"）。这些数字后来直接决定了架构（见 [S10](derived_clock_port_mux.md)）。
3. **数字不许采信转述**：每轮由主代理直读 `build/*.rpt`；子代理/模型给的数字一律先当假设。

RTL 侧的两条附带约束也是踩出来的：注释只写非显然的 WHY；禁止无端加流水"以防万一"；
禁止顺手加超时计数器（一处"加超时兜底"被明确否决，改用 CDC 排空本身当兜底条件）。

## 已验证效果（三条被推翻的记录，都有出处）

这套纪律在本仓库**推翻了 3 次模型（含我自己）的结论**，每次都留下可复核的数字：

1. **采纳 4 条中的 3 条、否决 1 条**：一条"`else if (idle) pack_base <= …` 在 `!cur_dirty`
   已成立时是死代码"被逐条件核对后否掉（`docs/log/OVERNIGHT_LOG.md` §7 R02）。
   ⇒ 说明这不是"模型说了算"，也不是"人说了算"，是**那段代码的结构说了算**。
2. **拔线实验推翻"断链 ⇒ PHY 停供 RXC"**：板上 `hb_gone` 恒 0，而 `stall_ms` 在断流 13 秒里
   只走 831→1117（**+20.5 计数/秒**而不是 1000/秒）⇒ RXC 被拉慢约 48 倍；第二次受控拔线独立
   量到 **49.3×**（`data/measured/board_measure_r09.md`）。"有没有沿"查不出拔线，只能判"沿够不够快"。
3. **自家收益表整张作废重来**：`2x2 盒 = 99 dB` 是"理想像坐标差半像素"造成的自证，
   修正后加**锚点 + 反向对照**双判据（带限图样恒等下最近邻实测 45.4 dB、故意用旧约定 30.0 dB），
   任一不满足就 `exit(1)`，整张表不许引用（`docs/log/CHANGELOG_V7.md` V7.7、`src/host/interp_study.mjs`）。

判据纪律本身有产物，不是口号：

- `sim/run_sim.tcl` 不再把"一个 PASS/FAIL 都没打印"的 `NO_ASSERT` 计为 pass（R13 第 3 条）
  ⇒ 否则一个**什么都不断言的台架可以永远绿**。
- 构建脚本不采信"工具自报成功"：`build/ps_app.mjs` 第一次报"链接成功"的镜像 `.text` 只有
  **80 字节**（`--gc-sections` 把 `main` 裁光了），现在强制检查 `_start`/`main` 与 `.text ≥ 20 KB`。
- 外部检索（数据手册、论文、同类开源工程）的**落地率如实记成 0**：真正改变设计决策的是探针数字
  （`docs/log/OVERNIGHT_LOG.md` §8）。 ⇒ 让模型去"查资料"之前先想清楚：这一步能不能换成一次本地测量。

## 失效条件

1. 只让模型"直接改 bit / 改 XDC 管脚"而没有原理图或 `docs/BOARD_PINS.md` 依据 ⇒ 立即停手。
2. 无仿真、无日志的纯猜测循环；以及把**未上板**的数据写成实测结论。
   本仓库的可执行出口就三个：`sim/run_sim.tcl`、`build/tcl/build_system_axigpio.tcl`、
   `build/tcl/ooc_newmods.tcl`——**最后者报的数字不是门禁**（它对输入一律加 3 ns）。
3. 转述的数字未经直读复核 ⇒ 本工作流要求"引用即给路径"，否则降级为假设。
   反面案例：一次"`fsm_encoding` 没用"的宣布，依据是几分钟后单独 `awk` 出来的一份 `cdc.rpt`
   —— 那是**上一版**的文件。同一件事的机器版判据见 [S16](cdc_pair_baseline_gate.md)
   的 #26/#27/#28 三连（写死阈值漏掉两次退化）。
4. 画质类问题（缩放走样、色彩、抖动）**不能由模型自己收敛**：这套判据只覆盖**数据完整性**
   （`docs/AI_COLLABORATION.md` 的"边界"一节：右屏细线闪烁最终确认是最近邻走样，与丢字无关）。
   需要人眼的那一半有它的操作规程，见 [S23](eye_acceptance_loop.md) —— 那一页管"怎么要这一眼、谁签"。
5. **"把 ISSUES 当检索索引"这件事依赖编号稳定**，而编号一直在往后追加、还会漂
   （旧笔记里的"19 条"指的是 `origin/v1-ps-ethernet:docs/ISSUES.md`，
   `docs/log/VERSION_LINEAGE.md` §V1；同一份文档里还出现过两个 #28）。
   ⇒ **引用任何编号前先 `grep -n "^### \|^## #" docs/log/ISSUES.md` 核对**，否则索引指向错的条目；
   跨版本引用 skill 编号（S1…S23）同理，见 README 开头那段"编号是对外接口"。
   **这一页故意不写"现在排到第几条"** —— 那个数每天都不一样，写下来就是给自己造一条会红的假凭据。
6. 提示词模板、模型与协作边界**没做过跨模型/跨工程的可比性实验** ⇒ 本文件只主张
   "这些纪律在本仓库抓出过上面那几条具体缺陷"，不主张通用效果（未验证）。
