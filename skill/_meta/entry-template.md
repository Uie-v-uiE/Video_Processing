## 每节填错的后果（写这一节的目的是：让人知道为什么不许省）

| 节 | 填错的后果 |
| --- | --- |
| frontmatter `description` | 概述了内部流程 → 智能体在"要不要载入本条"这一步就选错；写不出触发场景 → 索引一览表（README）无法生成"适用场景关键词" |
| 1 一句话用途 | 超过 30 字或与目录名不符 → 一览表列宽塌陷，门禁 G3/G7 判红 |
| 2 适用场景 | 写成"需要时"→ 陌生人 15 分钟内找不到入口，演练（P09 第 3 步）必然答不出 |
| 3 不适用 / 失效条件 | 缺 → 条目会被套到它不成立的平台，制造错误结论；这是评分点，也是本仓库翻过最多次的车 |
| 4 前置条件 | 缺输入文件 → 脚本把"读不到"当"通过"，等于交付一把没有牙的尺子 |
| 5 使用方法 | 步骤后面不写"应看到什么" → 执行人无法判断自己卡在哪，红项变成猜 |
| 6 判读与失败分叉 | 只写通过/失败两态 → "文件缺失/解析不到/空集合"会被当成绿，这是本仓库禁止事项里最严重的一类 |
| 7 已验证的效果 | 没有四要素（复跑命令+输入路径+期望输出+实际输出）却写"已验证" → 该文件按未完成处理；缺数据就写 `【待验证】`，不删节 |
| 8 提炼来源与边界 | 写成叙事 → 无法复核；边界不写 → 条目被误用，且"边界如何确定"这一评分项直接失分 |

## 长度与分层

- 单个 `SKILL.md` ≤500 行。超了就按"一层深"拆分：长内容放同目录的 `reference-*.md` / `tables/*.md`，
  正文留索引；**不做链式引用**（A 引 B 引 C 会让按需加载失效）。
- 参考页 >100 行必须有目录（标题级链接），因为评审与智能体都是按节取用。
