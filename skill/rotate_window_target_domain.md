# S2 · 邻域滤波必须做在逆映射**之后**的那条流上：源域里那个 3×3 根本不挨着

## 触发
- 当你准备让"任意角逆映射（旋转 / 缩放 / 透视这一类屏幕坐标 → 源坐标）"与"3×3 邻域滤波（blur / sharpen / Sobel / 形态学）"同时开时
- 当症状是"几何变换一开、滤波就花屏或冒出中间混叠值，把几何关掉又完全正常"时
- 当现有代码里有一条"某种几何模式下强制旁路窗滤"的捷径，你打算保留它时
- 当你准备用"在源域行缓存上换成屏幕坐标寻址"来修它时（这条路是错的，见失效边界）

## 不适用
- 点运算（灰度 / 二值 / 反色 / gamma）与邻域无关，任何域都兼容，不用重排
- 整行平移、整屏等比这类**邻域保持**的变换：两种顺序等价，别为此重构
- 做**前向**映射（源 → 屏幕去散布）而不是逆映射采样的通路：那条上没有规整的目标域光栅可谈，本条不适用

## 动作
1. 记住机理再排顺序：滤波若做在源图扫描序上，逆映射之后"屏幕邻域 ≠ 源图邻域"，滤的是一个根本不挨着的窗口。所以定死为：屏幕坐标 → 逆映射 → 读像素 → **在这条读出来的流上**建 3×3 → 输出。关键是承认"读出来的像素流本身就是目标图像的光栅序"——它把"滤波该挂在哪"从选择题变成事实题。
2. 行缓存的列坐标用目标域（屏幕）坐标寻址，深度必须 ≥ 有效行宽，而且深度由上层传进来、别在滤波器里写死（本仓库是一个由顶层传入的行宽参数，默认值与实传值不一致时就会踩失效边界 1）。
3. 删掉那条"几何模式强制旁路窗滤"的捷径，然后 grep 确认它真的删干净了：端口/信号还留在接口上 ≠ 功能还在，看它被**读**了几次（通用版在 S1）。
4. 越界填 0 放在效果链**之前**、黑边强制放在**之后**。反过来做，一个反色类点运算会把越界的 0 变成白，于是造出一个"看起来像丢帧"的现象。
5. 判据别只判"没花屏"，要判"滤波真的在跑"：在几何开启那一档把期望写成"**必须**出现中间混叠值"——不出现就说明窗滤被静默旁路了。反向判据的通用形态见 S21。
6. 顺手把资源算一遍：几何重排常常是**减逻辑**而不是加逻辑。把同一种几何限制在一路、删掉另一路多余的映射实例先问"哪一路能省"（本仓库那一轮 DSP48 13→9，LUT/寄存器/时序失败端点同向减少，最差负裕量反而变好）。

## 完成判据
- 台架里"几何开启"与"几何关闭"两档**都**要求看到"滤波在跑"，两档同时 PASS 才算；只有一档绿等于没判。本仓库入口 `bash sim/run_one.sh tb_rotate_window`。
- 一条便宜的自证：把顺序改回"先滤波、后映射"，那条反向判据必须**变红**。改回去它不红，说明判据恒真，本次 PASS 不算证据。

## 失效边界
- 行缓存深度 < 有效行宽时 3×3 的列会对不上，而且它**不报错**，只是列错——改分辨率必须连着改这里。
- "在源域行缓存上滤波、却改用屏幕坐标寻址"仍然是错的，只是更隐蔽：重构成立的充分条件是行缓存挂在逆映射**之后**的那条流上，不是"坐标换了"。
- 与未做几何的参考图逐像素比时，**金标也要先做同样的几何再滤波**，否则报出一堆假差异——那是比错的参照物，不是缺陷。
- 参考图本身不可一键重跑时，这条对比的证据等级只有"人工比对"，别写成"与参考图逐像素一致"。
- 想在几何开启态做双线性或更高档插值，先确认小数权重真的传出去了：本仓库旋转那一支把小数位钉成 0，于是"开插值"与"关"在非零角度是同一张画，而屏上那一格写着开（已记录未修）。通用形态是"开关的投影与硬件真的那一位不是同一位"，见 S20 第六签名。
- "哪一路做几何、哪一路不做"是产品决定，会随版本变 ⇒ 任何文档里念的几何行为都要用一条命令验一遍，读不到就按未验证处理。
- 相邻条目的分界：单口存储器被分时成多次访问、以及由此推出来的抽位与预算，见 S10；上板画面异常的分层定位见 S8；那一眼由人签见 S23。
