## 1. 一句话用途

推流的落位协议：按目标偏移写、提交要两条与门。

## 2. 适用场景

- 当 PC/上位机向 PL 推**原始帧**（视频、点云、矩阵），每帧远超一个 MTU、必须切包时。
- 当症状是"画面均匀黑点 / 拖影 / 最新一帧没上来"，而你手里没有一条命令能说清**丢在哪一级**时。
- 当你想让数据面彻底离开处理器（ARP / ICMP / UDP 全由 RTL 应答，PS 或 MCU 只做控制面）时。
- 当你准备沿用别人那句"载荷长度取 8 的倍数"的经验时。
- 当你改动手写协议栈的一小段、整链就收不到包、而且它不报原因时。

## 3. 不适用 / 失效条件

- 需要可靠、有序交付的场合：本方案丢包就是丢包，靠下一帧自愈。
- 走 SoC 自带 MAC + 协议栈（lwIP 那一类）的工程 —— 下面所有结论都建立在"不经过 CPU 缓存与协议栈"上。
- 稀疏载荷（一行只写几个字节；点云抽稀、稀疏矩阵那一类）：行覆盖门在那种形状上会误判 —— 它会把没写过的行也算进"覆盖" ⇒ 换成**包位图**，而不是把行门调松。
- 不重组 IP 分片 ⇒ 上位机必须自己控制包长不超过 MTU 余量。
- 片外时序没约束时（位对齐靠固定输入延迟抽头、收发方向被 false path 整条豁免），时序报告全绿只说明**片内**满足，片外只有板级证据 ⇒ 换板 / 换走线要重扫抽头。
- 器件换代时收发侧的原语（串联 / 延迟校准、输出的串化器那一类）整段作废，必须改写；本仓库从 7 系列换走就会踩这条。
- 相邻条目的分界：连线 / 绑源地址 / 串口重扫见 runtime 类 `board-eth-uart`（旧编号 S7）；上板不亮的分层定位见 `skill/zynq-video-rtl-debug/SKILL.md`（旧编号 S8）；"丢在哪一级"的图案协议与发完再读见 pitfalls 类 `frameid-loss-signature`（旧编号 S9）；跨域脉冲的写法见 pitfalls 类 `pulse-toggle-cdc`（旧编号 S11）。

## 4. 前置条件

- 工具与版本：本包写作环境 Vivado/Vitis 2025.2.1 + Zynq-7020（本仓示例取值，需按自身工程替换）；本条的机理与器件家族无关，只要求"手写 RX 链 + 按偏移落位"这个形状。
- 需要的输入：目标帧的几何量（宽 × 高 × 每像素字节 ⇒ 帧长常数与总行数）、存储字宽、上位机的包长、被例化的那条 RX 链的 RTL。
- 需要的台架/工具：一支单台架运行脚本（本仓 `bash sim/run_one.sh <tb名>`）与一支"拿综合日志当可达性 oracle"的脚本 `bash build/orphan_rtl.sh`（本仓示例取值，需按自身工程替换）。
- 需要的权限或硬件连接状态：判据主体在台架（不需要板子）；只有对齐边界那条要板级逐字比对（见 5.3 第 5 步与 §7）。

## 5. 使用方法

### 5.1 先定协议侧的五件事（按这个顺序做）

1. 包头带**绝对偏移**（该载荷在目标帧内的字节偏移，定长小端字段），接收侧把它换算成写地址 ⇒ **按偏移落位，绝不按到达顺序追加**。换算时先确认单位是"字节地址"还是"存储字索引"，两者差 log2(位宽 ÷ 8)；再顺手用偏移算出行号，用来记"本帧哪些源行被写过"。
2. 提交门写成**两条与门**：被写过的行数 == 总行数 **且** 帧内字节累计 == 帧长，并且本帧没有坏包。只看累计字节会把"丢一包 + 一包重复偏移"当成收满 ⇒ 空洞帧被提交。
3. 把"换页 / 切 bank"与"数据就绪"分成两件事，换页还要等跨域排空 —— 否则屏会在半帧上翻页。
4. 坏帧策略说死（丢弃、不重传、屏上保留上一帧），但事件必须落成**可数的寄存器**（作废帧计数、缺行峰值），而不是留成屏幕上一条没人能计数的黑纹。
5. 载荷长度是**板级量出来的**，不是随手取的：包边界若落在存储字中间，同一个字会被分两次推送、后一次覆盖前一次，于是每帧留下固定数量的小宽度空洞（洞里全 0 ⇒ 屏上均匀散布的黑点）。修法只有两种：把包长取成总线字宽的整数倍，或让写侧按字节写使能生成部分字写。本仓两条路都验过：1396 B → 1392 B，以及补上写使能后仍用 1396 B 复测。

完成后应看到：一行"按偏移落位"的写地址换算、两个提交与门各自可读、换页与就绪分开、坏帧有计数器、以及一个**由板级量出来**的包长（换板 / 换位宽 / 换 burst 语义都要重量一次这条对齐边界，别沿用别人那句"8 的倍数"）。

### 5.2 手写 RX 链再清这五处隐性假设（每一条都会静默改变行为）

6. 前导码 / 分界符状态机是一段隐性契约：动它的相位、计数器位宽或状态编码，整链就收不到包，而且它不会报"为什么没包" —— 现象与"对面没发"一模一样。
7. 邻居缓存（ARP）如果只存一个对端，同网段多主机时回复目标会漂；顺手确认它是否还接受广播目的地址。
8. "树里有这段代码 ≠ 板上有这个功能"：引用"某某检查已经做了"之前，先确认**被例化的那条链**上有它（本仓 `bash build/orphan_rtl.sh` 拿综合日志当可达性 oracle）。功能做了与它**可观测**也是两笔账 —— 被过滤器丢掉的包若没接成可读寄存器，板上看不到"丢了多少"。
9. 任何"看起来恒真 / 恒 0"的输入都要 grep 它的驱动：本仓的错误标志曾被硬接成常量 1，于是下游坏包计数**构造性为 0**，那一版所有关于坏包的遥测都是死数字。结论里要写清它靠哪一级证据。
10. 端口 / IP / 地址在几处各写了一份时，改一处不会报错、只会静默不通 ⇒ 集中成一处，或加一条对账脚本把它们比一遍。

完成后应看到：五处各自有一句"现在是怎么定的"，并且第 8、9 条能点名它靠的是可达性脚本还是驱动 grep。

### 5.3 激励与判据的写法

- 一条乱序 / 丢包 / 重复 / 帧跳变 / 坏包的激励必须证明"提交门真的在门"：丢过包的帧被拒绝、有洞的帧被计数、下一完整帧仍能提交。本仓的两支台架：`bash sim/run_one.sh tb_udp_reasm`、`bash sim/run_one.sh tb_v6_cover_gate`。
- 台架里"行覆盖"与"字节覆盖"必须**分开写**：合在一起就复现不出 5.1 第 2 条那个误判。
- 偏移字段本身坏了就写飞：链路层 FCS 有检查，但 UDP/IP 头里的 checksum 通常不参与判定 ⇒ "范围合法但数值错误"的偏移查不出来，只有越界那一类有计数。要防它得在应用层加 magic / CRC，别指望协议栈替你验。

完成后应看到：拒绝、计数、恢复三件事在同一份台架日志里各占一行，且两个覆盖量分别是两行。

## 6. 判读与失败分叉

| 检查 | 通过 | 失败 | 读不到输入 |
| --- | --- | --- | --- |
| 提交门激励（5.3 两支台架） | 丢过包的帧被拒绝、有洞的帧被计数、下一完整帧仍能提交 ⇒ 提交门在门 | 空洞帧被提交 ⇒ 回 5.1 第 2 条：是不是只看了累计字节；行门/字节门缺一 ⇒ 补两条与门 | 台架日志里没有判定行 ⇒ `NOT_MEASURED`，不等于"没有 FAIL 所以过" |
| 对齐边界那条判据 | 能**自己解释数字**：本仓修复前逐字比对 38290/38400、首个错字编号 174，而 174 正是"包长 ÷ 总线字宽"算出来的那个跨界字 | 数对不上机理 ⇒ 还没抓到根因，先别改包长；换板/换位宽后沿用旧包长 ⇒ 视同未验 | 拿不到逐字比对结果 ⇒ `NOT_MEASURED`（屏上"有黑点"不是这条判据的输入） |
| 可达性（5.2 第 8 条） | `bash build/orphan_rtl.sh` 显示该检查在**被例化的那条链**上 ⇒ 才允许引用"已经做了" | 报了"声明了但没进这一版位流" ⇒ 结论撤回，先去接线，别先改文档 | 综合日志不在 ⇒ `NOT_MEASURED`，不许以"树里有代码"替代 |
| 恒真/恒 0 输入（5.2 第 9 条） | grep 到它的驱动，且驱动不是常量 ⇒ 遥测数字是活的 | 驱动是常量 ⇒ 该路遥测构造性为 0，此前所有相关结论作废，结论里要写清靠哪一级证据 | 找不到驱动语句 ⇒ `NOT_MEASURED`，先确认读的是被综合的那份文件 |
| 换页 / 切 bank（5.1 第 3 条） | 屏只在整帧就绪且跨域排空后翻页 | 半帧上翻页 ⇒ "就绪"与"换页"被并成一件事，拆开 | 看不出翻在哪一帧 ⇒ `NOT_MEASURED`，先补可数的事件计数 |
| 坏帧遥测（5.1 第 4 条） | 作废帧计数、缺行峰值都可读 | 只有屏上一条黑纹、没有寄存器 ⇒ 事件没落成可数量 | 计数器读不出 ⇒ `NOT_MEASURED`（与 5.2 第 8 条"可观测是另一笔账"同族） |

三态只有 `PASS` / `FAIL` / `NOT_MEASURED`。
