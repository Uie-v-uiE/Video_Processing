# S9 · 用"自描述逐帧图案 + 相位分带"把"花屏"定位成"在哪一级丢数据"

## 触发
- 当数据流写进内存/DDR，肉眼只看到花屏 / 拖影 / 黑纹，而你还不知道**是不是在丢数据、丢在哪一级**时。
- 当任何"PC → 板卡 → 内存 → 显示/计算"链路要对**数据完整性**取证时（视频、点云、ADC 流、DMA 采集）。
- 当有人要用"加深缓冲"来修丢数据，而你还没证明瓶颈是深度还是排空速率时。

## 不适用
- 画质类问题（缩放走样、色彩、抖动）——本判据只判数据完整性，不判画质。
- 无法回读内存的平台（无 JTAG、无调试端口）：判据失效，只能退化为板内自检 + 计数寄存器。
- 载荷不是字宽整数倍时："包内相位"会与打包器的部分字状态混在一起，先解决对齐再用本判据。

## 动作
1. **图案必须逐帧变化**。让回读能对每个字反解出"它来自第几帧"（本项目把第 `w` 个字的每个 lane 写成
   `value = (w + n) & 0xffff`，`n` = 帧号，反解 `n_implied = (value − w) & 0xffff`）。**恒定图案只能验
   地址映射，结构上发现不了逐帧丢字**——用恒定图案会得到假的"100% 命中"（测量工具自己会造假）。
2. **先停流再回读**。一次回读要几秒，边推边读会让每个地址段读到不同时刻的帧，统计全废（症状：反解出的
   帧号跨度达几十帧）。把采集脚本按"发完再读"写死，而不是靠人记。
3. **把丢字按三个维度展开**（三个维度对应三种不同机理，缺一不可）：
   - 包内相位：丢字率 vs 字节偏移分带。呈**固定台阶** ⇒ 下游**平均排空速率**跟不上，加深缓冲无用。
   - 空间连续性：连续丢字带的长度分布、最长带。一条几百字长带 ⇒ 某窗口端口被完全占死；
     整包那么长 ⇒ 前端整包丢失。
   - 粒度：同一宽字内的两个窄字是否属于不同帧。高比例 ⇒ 丢在窄粒度（写侧门控 / CDC），不是整字丢弃。
4. **判"换帧是否原子"**：看每个 bank 的帧号跨度。健康 = 每个乒乓 buffer 恰好一帧；混进十几帧 = 提交/
   切换逻辑有问题。
5. **控制缓存这个变量**：从调试端口回读前先关/绕开 D-Cache，否则同一块内存三次读出三组数。

## 完成判据
- 一张带**数字**的分带表：最新帧占比、各相位带丢字率、最长连续丢字带、半字错帧比例——修复前后各一组，
  差得出来的才叫结论（本项目实测：修复前最新帧仅约 42~52%、包尾带丢 54~64%、半字错帧约 18.6%；
  根因是"每写一字就等 B 响应"把在途深度钉成 1；流水化后三档帧率全部 100.0%、各带 0.0%、半字错帧 0）。
- 判据能在仿真里复现同一签名（端口被独占 N 拍 ⇒ 丢字起始位置恰好等于打包器 FIFO 深度）。
- 换题目时只改两个常数（每帧字数、每包载荷），其余不动——这本身就是"方法可迁移"的检验。

## 失效边界
- 回读会把处理器停住 ⇒ 之后任何复测前必须重跑"引导→刷 PL→设源"三件套，否则量的是"PS 不跑"的工况。
- 脚本结尾固定打的那行"没读到有效图案"可能与同一轮的 100% **不矛盾**，只是文案位置错的假警报 ⇒
  判读看判据表，不看最后一行。
- 这套判据"看不见自己不覆盖的工况"：只出现在帧尾/边缘的残留，基线回读一次都不会出现 ⇒ 本判据没能给出
  板级区分力，相关修复的证据等级只到"机理 + 仿真双向判据"。
- 与 [S4](zynq_ddr_bandwidth.md) 的分界：S9 给"丢没丢、丢在哪一级"的**现象签名**；
  "在途深度 ÷ 往返延迟 = 吞吐"这笔**算术**的唯一住处在 S4，本页只给这组数不外推。
