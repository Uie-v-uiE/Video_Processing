# Skill：共享介质的发送仲裁 —— "全部空闲" + pending 记账 + 脉宽判据

> 四段式：适用场景 / 使用方法 / 已验证效果 / 失效条件。
> 来源：`report/ISSUES.md` #37（发现于 R23 的 KU5P 移植，修于 R24），判据 `sim/tb_ku5p_tx_arb.v`。

## 一、适用场景

两路以上的数据源共用**一个**输出多路选择器／一条介质（本工程：ARP / ICMP / UDP 共用 GMII 发送口），
并且满足下面任一条形状 —— 满足就值得按 bug 读一遍：

- 切换条件是**几个互相独立的 busy 标志用 OR 连起来**：`flag && (a_busy==0 || b_busy==0)`。
  它的语义是"**任一**空闲"，而想要的是"**全部**空闲" ⇒ 会在别人**帧中间**换源，
  剩下的一半字节就地作废（帧长、载荷、CRC 全错，且错得"看起来随机"）。
- 请求是**一拍宽**的脉冲（`arp_rx_flag`、`*_start_en`），而授权条件可能连续几拍都不成立
  ⇒ 脉冲会被整拍吃掉（表现成"要等对端超时才动"，最难查）。
- 授权之后靠"`*_done`"释放介质，但**没有区分是谁的 done** ⇒ 别人收尾那一拍会把你提前放掉。

## 二、使用方法（三条规则，按这个顺序查）

### 规则 1：切源只看"全部空闲"，而且要能"等"

```verilog
// 原（厂商 eth_ctrl）：任一空闲就切 ⇒ 帧中间换源
end else if ((arp_rx_flag && (udp_tx_busy == 1'b0)) ||
             (arp_rx_flag && (icmp_tx_busy == 1'b0))) begin
// 改：先记账，等全部空闲再兑现
end else if (arp_pend && (udp_tx_busy == 1'b0) && (icmp_tx_busy == 1'b0)) begin
```

### 规则 2：`&&` 单独用会丢请求 ⇒ 必须补 pending 位

`arp_rx_flag` 只有一拍。把它直接 AND 上"全部空闲"，那一拍不成立就**永久丢**这笔请求。
所以要一个记账位：

```verilog
reg arp_pend;                       // 声明与置位/清零放在**同一个 always**，见规则 3
...
if (arp_pend && (udp_tx_busy == 1'b0) && (icmp_tx_busy == 1'b0)) begin
    protocol_sw <= 2'b0;
    arp_tx_en   <= 1'b1;
    arp_pend    <= 1'b0;            // 与授权**同拍**清
end
if (arp_rx_flag) arp_pend <= 1'b1;  // 置位放块尾：同拍"兑现旧账+新请求"时新请求不会被吃掉
```

### 规则 3：跨 always 块用非阻塞信号互相清标志 = 默认晚一拍

第一版的错写法（在**另一个** always 里清账）：

```verilog
always @(...)                        // 块 A
    else if (arp_tx_en) arp_pend <= 1'b0;   // 读到的是**上一拍**的 arp_tx_en
```

后果：`arp_tx_en` 连高**两拍** ⇒ 发送状态机被重启一次 ⇒ 帧的第 0 字节发了两遍。
数字上只多一个字节，肉眼看不出，**只有"数每帧几个字节"的判据能抓到**。

### 规则 4（新写仲裁器时）：只认当前 owner 的 done

`ku5p/src/rtl/ku5p_tx_arb.v` 的形状：请求（脉冲）→ pending（电平）→ 空闲时按优先级 grant →
`owner` 寄存下来 → **只有 owner 的 `*_done` 能清 busy**。多路 done 混着来也不会提前放掉介质。

## 三、已验证效果（同一套激励喂四个变体，全部实测）

`sim/tb_ku5p_tx_arb.v`：T1–T4 验自研仲裁器，**V 组把同一批激励喂给厂商 `eth_ctrl` 做对照**。
标签约定 ARP=`A0+i`、ICMP=`C0+i`、UDP=`D0+i`，高 4 位就是来源，于是"帧内换源"可以直接数出来。
下面四行是**四个 eth_ctrl 变体**跑同一个台架的实测（变体在 `/tmp` 的副本上改，不动仓库；
第一行用 `git show HEAD:src/rtl/eth/eth_ctrl.v` 取原文）：

| eth_ctrl 变体 | `midbad`（帧在飞时别人的字节） | ARP 字节 | UDP 字节 | 结论 |
|------|---|---|---|---|
| 厂商原文（`\|\|`） | **3** | 12 | **7** | 换源 1 次 ⇒ 那帧 12 字节只剩 7，**截断** |
| 只改 `&&`、无 pending | 0 | **0** | 12 | 不换源了，但 **ARP 请求整笔丢掉** |
| `&&` + 跨 always 块清账 | 0 | **13** | 12 | 授权脉冲高两拍 ⇒ 第 0 字节发了两遍 |
| 本版（`&&` + 同块记账） | **0** | **12** | **12** | PASS（`flips=1` 是帧边界那一次，正常） |

判据写成三条一起看才算过：`midbad==0 && arp==12 && udp==12`。
**四个变体分别挂在不同的一条上** —— 这正是为什么要三条：
只判 `midbad` 会放走"丢请求"（第 2 行）和"多一字节"（第 3 行）；
只判字节总数会放走"帧中间插进别人的字节"（第 1 行的 UDP 是 7 不是 12，但 ARP 仍是 12）。

## 四、失效条件 / 不适用

- 需要**公平性**或**带宽配额**的仲裁（本方法只保证"不抢占 + 优先级固定"，UDP 大流量可以饿死后两级）；
- 带 backpressure 的总线（AXI/AHB）—— 那里的正确形状是 outstanding ID + ready 通道，不是这套 busy 位；
- 两条请求落在**同一帧的发送时间内**：本方法仍会让第二笔排队，但**已经在发的那路**如果没有
  busy 标志（厂商 ARP 就没有：`arp_tx_done` 在 `eth_ctrl` 里根本没被使用），第二笔会重启它。
  这是厂商原有行为，本条没动 —— 补法要加 `arp_tx_busy`，代价是"done 丢了就永久不再应答"，
  **活性风险需要上板验证**，所以只登记不盲改；
- 如果 `*_done` 可能永远不来（状态机被外部 abort），pending/busy 会卡住 ⇒ 那需要超时兜底，
  本工程没有这个场景（ARP/ICMP/UDP 三个发送状态机都是自走完）。
