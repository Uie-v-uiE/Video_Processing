---

## 1. 一句话用途

把一轮改动做成唯一变量的 A/B，并先证机制动了。

## 2. 适用场景

- 当你手上有 2 个以上想试的改动，而构建窗口只够跑一两轮时。
- 当两次构建之间出现数字移动（WNS、TNS、资源、吞吐），而你没量过噪声底时。
- 当改动是物理侧手段（复制、Pblock、实现指令）而工具是否真执行了这件事还没被读数证明时。
- 当某刀"预期收益"要靠跨构建比较才能说出来时（例如只有中间检查点可复算，全量构建要几十分钟）。
- 当采纳判据是"本域变好"而不含"其余域不许变差"时——这时按本模板补成对判据。
- 当回归在飞、需要把改动挡在采纳入口之外时（在飞的尺子不换、在飞时不动源码）。

## 3. 不适用 / 失效条件

- 本轮真的只有一个候选、且它已经有同变量的两跑凭据：直接判读，别再要一次设计。
- 改动跨域共享状态、跑一次的顺序会影响结果：一次基线不够，本模板要求至少两跑同序对照，做不到就退回先做顺序固化。
- 你要判的是"这版功能对不对"而不是"这一刀值不值"：那是判据/验收问题，用 `../criterion-before-code/`。
- 没有可复算的中间产物、也没有时间跑第二滚：此时任何跨构建差值都只能标 `NOT_MEASURED`，本模板给不出结论。
- 目的是复现别人的绝对数字（绝对值随器件批次/工具版本漂移）：单变量 A/B 只判相对移动，不判绝对值。

## 4. 前置条件

- 一个冻结基线：同一套产物的逐域读数（或逐指标读数）+ 生成它的脚本名（两端必须同生成器，混口径要先拒绝比较）。
- 中间检查点：已铺好布局或已布线的产物路径；有它才有"低成本复算"这一档。
- 噪声底：同树重跑一次得到的最大读数移动（单位与被判量一致）；没量过就先跑空白滚（不挂任何改动的那一滚）。
- 变量清单：本轮候选，每条写明"手段 + 影响的读数 + 代价面"。
- 工具执行入口与耗时预算（示例取值，需按自身工程替换；两处都有本仓库凭据：一滚"布局 + 布线 +  phys_opt"约 8–10 分钟，见 `build/r114_replication_ab.sh` 用法行写的"约 2 x 8~10 分钟"；整屏台架一次约 108 分钟，见 `data/metrics.csv`"整屏逐像素判据"行的"一次台架（约 108 分钟）"）。
- 权限：改动只落在副本树或单独的构建目录；源码目录在有构建/回归在飞时禁改。

## 5. 使用方法

### 5.1 提示词正文（整段复制，先填 5.2 的槽位）

```
你是我的 A/B 实验设计 agent。任务：把我给的这一轮改动压成"唯一变量的两跑对照"，
并规定判定顺序。你不许改我的源码，只输出实验设计与判据；执行由我做。

【本轮事实（全部由我填；我没给的数字不许补）】
- 基线件（逐域/逐指标读数 + 生成它的脚本）：【填入】
- 可复算的中间检查点路径：【填入】（没有写"无"）
- 噪声底（同树重跑的最大读数移动）：【填入】（没量过写【未实测】，并排在设计里第一件事就是量它）
- 候选改动清单（每条一行）：【填入】
- 每滚的耗时与可并行度：【填入】
- 每滚要产出的读数清单（报告文件名 / 字段名）：【填入】
- 采纳判据（谁变好、谁不许变差、代价上限）：【填入】
- 在飞的回归或构建（禁改窗口）：【填入】

第 0 步 · 先取证：A 节列你读过的文件与抄到的原文数字，B 节列假设（已确认/未确认）。
  缺基线件或缺读数清单 ⇒ 停下要文件，不要设计一个无法判定的实验。

第 1 步 · 变量归一（本模板的核心动作）：
  - 从候选清单里选出**一条**进 A/B，其余全部标 excluded(原因=与本轮不同变量)，写进台账不删。
  - 输出"两滚唯一差异"这一句，句式：A 滚 = 【共同流程】；B 滚 = 【共同流程】+ 【这一个变量】。
  - 若两个候选必须同轮（例如一个约束改动会让另一个的读数没意义）：明写依赖顺序，
    并给出"先跑哪一个、为什么"，禁止一次测两件事。
  - 自检一句：这个变量落上了没有独立读数？答不出 ⇒ 先补机制探针，再谈收益。

第 2 步 · 判定顺序写死（先证机制，再谈收益）：
  | 序 | 判据 | 通过条件 | 不过时的结论 |
  V1 两滚都完整跑完（各自一条收尾标记）。
  V2 变量真的落上：B 滚该开关/该选项的落地读数存在，A 滚明确"没加"（对照必须能区分两者）。
  V2b 机制动了（正对照）：B 滚的机制计数严格大于 A 滚（例：被复制出来的单元数、
      新增的实例数、该网扇出下降）。
  V2c 机制动了的第二个**独立来源**读数（不同文件、不同算法），与 V2b 不同源才算数。
  V3 收益侧：目标那一族/那一项的提升 >= 【填入】（阈值来自噪声底，不来自感觉）。
  V4 代价侧：其余每一域/每一项的差分全绿（任何一项从满足掉进违例、或相对余量掉过
      【填入】都判红）。
  V5 资源/代价侧：占用变化在【填入】界内，并写出归属（哪一处改动花掉的）。
  结论口径：V2b 或 V2c 任一不过 ⇒ verdict = MECHANISM_INERT（"这一刀没打到东西"），
  **禁止**把它写成"该手段的收益不成立"；机制过了才由 V3+V4+V5 决定 ADOPT / DECLINE。

第 3 步 · 头条数字的处理规则（必须逐句写进设计）：
  - 跨构建的绝对值移动**只念不判**：WNS/吞吐的绝对差不算收益也不算损失，除非同变量两跑都复现。
  - 判据必须成对：本域一条 + 至少一个相邻域一条；"本域涨了 0.4"这句话单独出现就是不合格产出。
  - 换主语要认出：最差路径从 A 族换到 B 族时，绝对差没有含义；改报"族计数/归属"这种噪声做不到的量。
  - 若噪声底【未实测】：本轮一律降级为 NOT_MEASURED，并先跑空白滚（不挂变量的那一滚）标定它。

第 4 步 · 低成本复算优先：
  - 若我有中间检查点：先做"从同一检查点重跑后半流程"的两滚（分钟级），用它判机制与方向；
    只有要采纳时才付全量构建的代价。
  - 检查点复算的两滚必须来自同一个检查点文件，且除该变量外流程一致；做不到就写"对照不合法"。
  - 归档命名按轮次分件、不覆盖上一轮；声明"跨构建比较前先确认布局是同一批种子/策略"。

第 5 步 · 输出契约（顺序写死）：
  1) 唯一变量那句（第 1 步的句式）+ 被剔除的候选与原因
  2) V1..V5 表格（含每条的通过条件与不过时的结论）
  3) 每滚产出清单：文件名 + 要读的字段 + 期望形状（读不到时的第三态）
  4) 判读脚本骨架：逐条打印"判据名 / 实测 / 判据文本 / PASS|FAIL"，收尾必须打印
     "判定 N 项、未判 M 项"，有未判时收尾换词（让下游冻结/采纳入口自动拒绝）
  5) 采纳入口与回滚动作：判负时刷回/切回基线的具体命令
  没有数据处写【未实测】；命令与选项必须来自我给的脚本或工具 help 原文，取不到写"未核实"；
  禁止"通常/一般来说"。

第 6 步 · 停止条件（任一命中就停下报我）：
  - 找不到能区分 A/B 的独立读数（机制无法证明）；
  - 需要的第二滚会覆盖上一轮凭据（命名/目录冲突）；
  - 噪声底缺失且全量构建时间不够再跑空白滚；
  - 同一判据连续 3 次不过——停下说明卡在哪，不许弱化判据。
```

### 5.2 槽位清单

| 槽位 | 该填什么值 |
|---|---|
| 基线件 | 上一版采纳的逐域/逐指标读数文件 + **生成它的脚本名**（两端同生成器才可比） |
| 可复算的中间检查点路径 | 已铺布局或已布线产物的真实路径；没有写"无" |
| 噪声底 | 同树重跑一次的最大读数移动（含单位）；没量过写 `【未实测】` |
| 候选改动清单 | 每条：手段 + 目标读数 + 预期代价；本模板只放一条进 A/B |
| 每滚耗时与可并行度 | 分钟数 + 是否独占工具窗口（同一时刻只允许一个进程写同一份日志） |
| 每滚要产出的读数清单 | 报告文件名 + 字段名（例如逐域 WNS/WHS/失败端点、占用、复制单元数） |
| 采纳判据阈值 | V3 的最小提升（由噪声底推）、V4 的相对余量下限、V5 的占用界 |
| 在飞的回归 | 正在跑的台架/构建名与禁改窗口 |

### 5.3 执行步骤

1. 填槽发出。**完成后应看到**：第 1) 项"唯一变量那句"里 A/B 流程逐字相同，只差一个变量。
2. 核对 V2 的对照设计。**完成后应看到**：A 滚明确"没加"，而不是"少了一步没跑"（缺步骤不是对照）。
3. 跑 B 之前先跑一次空白滚（若噪声底 `【未实测】`）。**完成后应看到**：噪声底数字或明确的 0（同树确定性时是逐位相同）。
4. 执行两滚（脚本按第 4) 项骨架打印逐条判定）。**完成后应看到**：`判定 N 项、未判 M 项` 那一行；M>0 时收尾词不同、采纳入口拒绝。
5. 读 verdict。**完成后应看到**：ADOPT / DECLINE / MECHANISM_INERT 三选一，且每条红都点名"谁变差了"。
6. 判负时执行回滚命令。**完成后应看到**：板上/产物身份回到基线 md5，且台账记了这条负结果（不删）。

## 6. 判读与失败分叉

- **ADOPT**（V1–V5 全绿）：进正式构建与采纳记录；同时把"其余域读数"一起写进报告，不只念本域。
- **DECLINE**（机制绿、收益或代价红）：保留两跑凭据不删，把该候选写 `declined(measured)`；下一步换刀或换维度，不许改阈值。
- **MECHANISM_INERT**（V2/V2b/V2c 任一红）：这一刀没打到东西 ⇒ 先核实手段本身（命令/选项/对象名是否在工具里真实存在，本仓库就栽过"把杠杆写给一条不存在的命令"），再重跑对照。
- **V4 一进一出**：本轮净移动记 0、归属写"未定"；把两件事拆成两轮（回到第 1 步重新归一变量）。
- **读不到输入**：某滚报告缺 ⇒ 该项 `NOT_MEASURED`；禁止用上一轮同名文件补数（身份不同套）。
- **两滚混进同一份日志**：先查是否只有唯一一个进程在写；有残留进程就拒绝启动并说明该杀谁（不自动杀，那一跑可能是别人要的凭据）。
- **3 次不过**：停下，列试过什么与卡在哪条判据，等裁决（本仓库口径：三次尝试用满就不再加试，改记工具账）。

## 8. 提炼来源与边界

- 提炼来源：`build/r114_replication_ab.sh`、`build/evidence/r117_repl3/B_console.txt`、`docs/timing/cut_ledger.tsv`、`docs/timing/README.md`、`docs/timing/ROUND_r116.md`、`docs/timing/ROUND_r117.md`（判负记录）、`report/TIMING_GLOBAL.md` 第 2/2b/3 节、`skill/pitfalls/ab-revert-control-run/SKILL.md`（2026-10-01 08:06，#113：新红先退回未改状态用同一版台架再跑）、`report/log/ISSUES.md` #223（单变量纪律与"同树重复滚 = 零散布"的结案）、#254、#288、#319/#320（选项名与目标网名未核实造成的假"没差别"）、#328（四格变差判负）。
- 迁移要点：V3/V4/V5 的三个阈值都要由你自己的噪声底推出来；把"复制单元数"这一类机制计数换成你手段的对应可数读数（要两个不同来源，规矩：一条形状行的两个操作数不许同源）。
- 失效边界：工具放置/布线不确定（跨构建同树重跑数字会漂）时，第 4 步的"检查点复算"只给方向不给结论，收益判定必须回到同变量双跑；当只有全量构建可用（无中间检查点）时，一轮只能验一条，模板第 1 步的"其余候选 excluded"就变成硬性。
- 边界：本模板不判定功能对错（见 `../criterion-before-code/`），也不重新划定架构侧（见 `../hw-sw-partition/`）。
