# 同相派生快时钟上的"分时读口"：给单口 BRAM 塞进 N 次读

适用：想把一个只有"1 读/1 写"的存储器（帧缓存、行缓存）在**不增加任何 RAM** 的前提下
供多个消费者使用，而片上正好有一个 N 倍于工作时钟、**同一个 PLL/MMCM 出来、同相**的时钟。
本项目用它把 512×300 RGB565 帧缓存的读口从"1 次/像素"扩到"5 次/像素"，实现右窗双线性插值
（`src/rtl/process/bilin/`，`report/CHANGELOG_V7.md` V7.8）。

## 一、先算两道算术题，再动手

1. **槽数够不够**：每工作周期可用快槽 = N。需求 = 各消费者每次读次数之和。
   本项目：右窗 4 抽头 + 左窗 1 = 5，N = 5 ⇒ **零余量**。零余量意味着"以后再加一次读"
   必须先回答"从哪个槽挤"，所以这句话要写在模块头上。
2. **RAM 会不会涨**：在**同一组阵列上再加一个逻辑读口**，7-series 的综合器会复制阵列。
   实测（对照实验在 `sim/probes/`）：80 → **160** 个 RAMB36，全片才 140 ⇒ 封死。
   ⇒ 唯一出路就是分时；分时只能靠快时钟。

## 二、预算规则（最容易算错的一条）

同相派生时钟下，慢域触发器在 `t=20n` 变化，快域**最早**能采它的沿是 `t=20n+4`
⇒ **"跨进快域"的 Setup 预算是一个快周期（4 ns），不是慢周期（20 ns）**。
反方向 `快→慢` 最坏约 `20-4=16 ns`，很宽松。

推论（本项目所有红色违例都归因到违反了它）：

| 位置 | 允许的组合逻辑 | 预算 |
|------|----------------|------|
| 慢域 → 慢域 | 随便（乘法、加法、mux） | 20 ns |
| 慢域 → 快域（含直接打到 BRAM 地址脚） | **只允许直线**：触发器输出 → 触发器输入 | 4 ns |
| 快域 → 快域 | 浅逻辑（一两级 mux；**不要加法**） | 4 ns |
| 快域 → 慢域 | 任意浅逻辑 | 16 ns |

所以正确写法是：**地址/偏移全部在慢域算完并各打一拍**（慢域有 20 ns），
快域只做"若干本域寄存器 → 一个 mux → 存储器地址脚"。
`bilin_lerp` 那 12 个乘法留在慢域两级流水里（快域 4 ns 塞不下，慢域本来就有预算）。

## 三、成对信号必须在**同一个沿**采集

字内选车道需要 (字号, 车道) 两个量。若字号在"周期起始沿"进快域、车道在"中间某个沿"进，
两者会差一个像素周期 ⇒ **整列颜色对、左右偏 1 格，且不报错、综合不告警**。
规则：**同一份读所需的所有描述量，同一个 `if (同一个沿)` 采**。
判据写法：台架把车道驱动成与字号**无关**的独立图案（本项目 `lane = i[1:0]^1`），
错了必然露；只对字号的判据抓不到。

## 四、延迟常数要"量"出来并钉住

改了读口，下游所有配准抽位（彩条链、效果链 `de/x/y`、合成器抽位、窗口/越界标志）都要跟着挪。
不要手推拍数，也不要留字面量：

1. 让端到端台架在 0..20 里**搜索唯一能全对的平移量**，并**断言唯一**
   （两个平移量都能对上 ⇒ 判据没牙）。本项目量到 `LAT=5`。
2. 顶层把它写成一个常数，其它抽位全部由它推导：
   `BAR_L_TAP = BUS_LAT-1`、`BAR_R_TAP = BUS_LAT-1-MAP_LAT`、`PIPE_TAP = BUS_LAT-1`、
   `SPLIT_TAP = BUS_LAT+LEFT_TAIL-1`。
3. **用旧值回代自检**：把 `RD_LAT=2` 代回这套公式，必须原样得到旧代码里的字面量。
   本项目这样得到了 4 / (1≠2) / 4(≠3) / 11 —— 于是顺手抓出两处存在很多版本的 1 像素错位
   （效果链 `PROC_LAT`、右窗彩条），都是"不会报错、只有眼睛能看见"的那类。

## 五、不要用 `set_multicycle_path` 把红色关掉

数据"整个慢周期稳定"这个前提常常是真的，但**整组时钟间的 multicycle 会一并豁免**
同组里别的真实跨域路径 —— 本项目 `rgb2dvi/tmds_serializer` 里就有 `clk_pix→clk_pix5x` 的路径，
豁免它们换来的是一条时序全绿、HDMI 随机花屏的 bit。
要么按**具体寄存器名**限定（`-from [get_cells -hier ...]`，改名即失效，得写校验），
要么按第二/三节把设计写成真的能过 4 ns。本项目选后者。

## 六、区分"逻辑不够"与"离得太远"

看 `report_timing` 的一条违例路径就够，别猜：

```
Data Path Delay  3.844ns (logic 0.589ns 15.3%  route 3.255ns 84.7%)
Logic Levels     2 (LUT6=2)
Source/Dest      u_sched/slot_reg[1] → u_fb/lo_reg_0_36/ADDRBWRADDR[14]
```

route 占八成 + 只有 2 级逻辑 ⇒ **不是深度问题**，再砍逻辑是白费，方向是：
- 让工具**复制高扇出驱动器**（`phys_opt_design` 的 fanout replication；
  用 `Performance_ExtraTimingOpt` 这类策略一次性打开，日志里能看到
  `Processed net ... Replicated 1 ...`）；
- 或加一级"贴着存储器的寄存"（注意：这会改变分时节拍，整张槽位表要重排 ⇒ 见第七节）；
- 或 Pblock 把调度器与那批 BRAM tile 圈在一起。
反例（本项目 build#14）：`base+ROWW` 在快域 ⇒ 2 级 LUT + 17 位进位链，逻辑就吃掉 2.6 ns，
那是真深度问题，只能按第二节把算术搬回慢域（−1.277 → −0.485）。

## 七、改节拍要能一次性回退

分时调度器一旦换节拍（加一级寄存、挪采样沿），抽头采集沿、vld 跟随链、左窗搭车槽全都要动。
本项目第三次尝试时两个台架同时变红（`err_bil=77`、`tb_tap_sched` 116 条错、左窗腿反而全对），
**当时已过半夜且没有板级复核** ⇒ 正确动作是：
1. 把实验版**整份留档**（含槽位表与失败现象），不是删掉；
2. `git checkout` 回"L1 全绿"的那一版，只单独补回确定的真错；
3. 换工具侧的旋钮（第六节），一次一个；
4. 兜底 bit 先冻结在 `build/frozen_*/` 并写 `MANIFEST.txt`（md5）。
   **注意**：`build/system.bit` 会被之后的构建**原地覆盖**——本项目发生过
   "02:32 恢复成已知可用版、02:54 又被失败构建盖掉"，文件名一模一样。
   ⇒ 上板前必须 `md5sum` 校验，而不是相信文件名。
