# S10 · 同相派生快时钟上的"分时读口"：给单口 BRAM 塞进 N 次读

## 适用场景

想把一个只有"1 读/1 写"的存储器（帧缓存、行缓存）在**不增加任何 RAM** 的前提下供多个消费者使用，
而片上正好有一个 N 倍于工作时钟、**同一个 PLL/MMCM 出来、同相**的时钟。
本项目用它把 512×300 RGB565 帧缓存的读口从"1 次/像素"扩到"5 次/像素"，实现右窗双线性插值
（`src/rtl/process/bilin/`，`docs/log/CHANGELOG_V7.md` V7.8）。

## 使用方法（下面第一到第七节就是用法本身，按顺序做）

## 一、先算两道算术题，再动手

1. **槽数够不够**：每工作周期可用快槽 = N。需求 = 各消费者每次读次数之和。
   本项目：右窗 4 抽头 + 左窗 1 = 5，N = 5 ⇒ **零余量**。零余量意味着"以后再加一次读"
   必须先回答"从哪个槽挤"，所以这句话要写在模块头上。
2. **RAM 会不会涨**：在**同一组阵列上再加一个逻辑读口**，7-series 的综合器会复制阵列。
   实测（对照实验在 `sim/probes/`）：80 → **160** 个 RAMB36，全片才 140 ⇒ 封死。
   ⇒ 唯一出路就是分时；分时只能靠快时钟。

## 二、预算规则（最容易算错的一条）

同相派生时钟下，慢域触发器在 `t=20n` 变化，快域**最早**能采它的沿是 `t=20n+4`
⇒ **"跨进快域"的 Setup 预算是一个快周期（4 ns），不是慢周期（20 ns）**。
反方向 `快→慢` 最坏约 `20-4=16 ns`，很宽松。

推论（本项目所有红色违例都归因到违反了它）：

| 位置 | 允许的组合逻辑 | 预算 |
|------|----------------|------|
| 慢域 → 慢域 | 随便（乘法、加法、mux） | 20 ns |
| 慢域 → 快域（含直接打到 BRAM 地址脚） | **只允许直线**：触发器输出 → 触发器输入 | 4 ns |
| 快域 → 快域 | 浅逻辑（一两级 mux；**不要加法**） | 4 ns |
| 快域 → 慢域 | 任意浅逻辑 | 16 ns |

所以正确写法是：**地址/偏移全部在慢域算完并各打一拍**（慢域有 20 ns），
快域只做"若干本域寄存器 → 一个 mux → 存储器地址脚"。
`bilin_lerp` 那 12 个乘法留在慢域两级流水里（快域 4 ns 塞不下，慢域本来就有预算）。

## 三、成对信号必须在**同一个沿**采集

字内选车道需要 (字号, 车道) 两个量。若字号在"周期起始沿"进快域、车道在"中间某个沿"进，
两者会差一个像素周期 ⇒ **整列颜色对、左右偏 1 格，且不报错、综合不告警**。
规则：**同一份读所需的所有描述量，同一个 `if (同一个沿)` 采**。
判据写法：台架把车道驱动成与字号**无关**的独立图案（本项目 `lane = i[1:0]^1`），
错了必然露；只对字号的判据抓不到。

## 四、延迟常数要"量"出来并钉住

改了读口，下游所有配准抽位（彩条链、效果链 `de/x/y`、合成器抽位、窗口/越界标志）都要跟着挪。
不要手推拍数，也不要留字面量：

1. 让端到端台架在 0..20 里**搜索唯一能全对的平移量**，并**断言唯一**
   （两个平移量都能对上 ⇒ 判据没牙）。`sim/tb_fb_rd5x.v` 量到的是通路端到端 `LAT_PIN = 6`，
   `fb_rd5x` 模块自己那一段是 5 个 `clk_pix`——**两个数量的是不同对象，别混着引用**。
2. 顶层把它写成**一处定义**，其它抽位由它推导。本仓库现在的写法是
   `PROC_LAT = u_pipe.LATENCY`（延迟只在处理链自己那里定义一次）、
   `MIX_D = 3 + 1 + 1 + u_pipe.LATENCY`、`LEFT_TAIL = PROC_LAT`（`src/rtl/top/pl_video_top.v`）。
   ⚠ 本节早期版本写的 `BUS_LAT / BAR_L_TAP / PIPE_TAP / SPLIT_TAP` 现在**只剩在
   `fb_rd5x.v` 的注释里**，顶层已经没有这些常数（改结构时被合掉了）。**规则照用，名字去 RTL 里现查**——
   这本身就是本页要防的那类错：文档点名的标识符漂移了，而它看起来仍然很确定。
3. **用旧值回代自检**：把 `RD_LAT=2` 代回这套公式，必须原样得到旧代码里的字面量。
   本项目这样得到了 4 / (1≠2) / 4(≠3) / 11 —— 于是顺手抓出两处存在很多版本的 1 像素错位
   （效果链 `PROC_LAT`、右窗彩条），都是"不会报错、只有眼睛能看见"的那类。

## 五、不要用 `set_multicycle_path` 把红色关掉

数据"整个慢周期稳定"这个前提常常是真的，但**整组时钟间的 multicycle 会一并豁免**
同组里别的真实跨域路径 —— 本项目 `rgb2dvi/tmds_serializer` 里就有 `clk_pix→clk_pix5x` 的路径，
豁免它们换来的是一条时序全绿、HDMI 随机花屏的 bit。
要么按**具体寄存器名**限定（`-from [get_cells -hier ...]`，改名即失效，得写校验），
要么按第二/三节把设计写成真的能过 4 ns。本项目选后者。

## 六、区分"逻辑不够"与"离得太远"

看 `report_timing` 的一条违例路径就够，别猜：

```
Data Path Delay  3.844ns (logic 0.589ns 15.3%  route 3.255ns 84.7%)
Logic Levels     2 (LUT6=2)
Source/Dest      u_sched/slot_reg[1] → u_fb/lo_reg_0_36/ADDRBWRADDR[14]
```

route 占八成 + 只有 2 级逻辑 ⇒ **不是深度问题**，再砍逻辑是白费，方向是：
- 让工具**复制高扇出驱动器**（`phys_opt_design` 的 fanout replication；
  用 `Performance_ExtraTimingOpt` 这类策略一次性打开，日志里能看到
  `Processed net ... Replicated 1 ...`）；
- 或加一级"贴着存储器的寄存"（注意：这会改变分时节拍，整张槽位表要重排 ⇒ 见第七节）；
- 或 Pblock 把调度器与那批 BRAM tile 圈在一起。
反例（本项目 build#14）：`base+ROWW` 在快域 ⇒ 2 级 LUT 外加一条 17 位进位链，
那是真深度问题，只能按第二节把算术搬回慢域。三版红的数字都留档：
**−1.277 / −0.485 / −0.327**（`docs/log/OVERNIGHT_LOG.md` R20、`docs/log/CHANGELOG_V7.md` 的 build 表），
最后是 `build/micro_rd/` 的三 MODE 探针量死后才放弃这条路（ISSUES #76）。

同一格判据救过一次"冤枉优化"（r81，ISSUES #105）：三档策略全红，量到的都是同一条锥 ——
终点 `u_lm/drop_words_reg[*]/CE`、起点 `u_cdc/wbin_reg[2]/C`，也就是一个**跨模块的组合输出直接驱动
32 个 CE 脚**。而那个模块自己的文件头注释写着"所有输入都是打过一拍的信号" ⇒
**报告里的路径名会读穿注释里的结构断言**。两条处置都值：

- 裕量掉在零附近（−0.062 / +0.066 这种量级）时，先把它当**同一张网表重掷**看待：
  反正改注释那一轮本来就要重新综合，等于免费再滚；连着三滚不中才动结构。
  反过来说，"三滚全红、数字一模一样"本身就是证据（两份 rpt 的 `Date` 行不同 ⇒ 不是把一份念了两遍）。
- **动结构的图纸要一次写全**：把丢字脉冲打在它出生的地方、跨模块只送一个 bit，
  并明确禁止"把 `full` 打一拍再用"这种看着等价的改法 —— 那会漏掉真正溢出的那一拍。
  三条采纳判据（台架逐笔一致 / 顶层台架全绿 / WNS>0 且失败端点 0）写在 ISSUES #105 里，
  任何一条不满足就回退，不留"看起来更好"的版本。

## 七、改节拍要能一次性回退

分时调度器一旦换节拍（加一级寄存、挪采样沿），抽头采集沿、vld 跟随链、左窗搭车槽全都要动。
本项目第三次尝试时两个台架同时变红（`err_bil=77`、`tb_tap_sched` 116 条错、左窗腿反而全对），
**当时已过半夜且没有板级复核** ⇒ 正确动作是：
1. 把实验版**整份留档**（含槽位表与失败现象），不是删掉；
2. `git checkout` 回"L1 全绿"的那一版，只单独补回确定的真错；
3. 换工具侧的旋钮（第六节），一次一个；
4. 兜底 bit 先冻结在 `build/frozen_*/` 并写 `MANIFEST.txt`（md5）。
   **注意**：`build/system.bit` 会被之后的构建**原地覆盖**——本项目发生过
   "02:32 恢复成已知可用版、02:54 又被失败构建盖掉"，文件名一模一样。
   ⇒ 上板前必须 `md5sum` 校验，而不是相信文件名。
     （成套冻结与新鲜度的完整规矩在 [S15](artifact_freeze_and_freshness.md)，本文件不复述。）

## 失效条件

- **两个时钟不是同一个 PLL/MMCM 出来、或不同相** ⇒ 第二节的预算表整个作废，
  那才是真正需要异步握手（FIFO / 格雷码 / 翻转位）的场合，硬套分时只会把错误推迟到硅片上。
- **N 次读里有任何一次需要加法** ⇒ 快域那 4 ns 塞不下（第三节表格的"只允许直线"），
  算术必须搬回慢域；本项目 build#14 就是拿 `base+ROWW` 在快域做，2 级 LUT 吃掉 2.6 ns。
- 存储器**再加一个逻辑读口不会翻倍**的器件（有真正双口 RAM、或换到 UltraScale+ 的原语）
  ⇒ 分时这一整套的动机消失，先量 RAM 代价再决定要不要走这条路（探针写法见第一节的
  `sim/probes/dpfb.v`：1W1R = 80 个 RAMB36、1W2R = 160，正好翻倍，这才是本条成立的前提）。
- 改像素时钟与快钟的**比例**（`CLKOUT0_DIVIDE_F` / `CLKOUT1_DIVIDE`）⇒ 整张槽位表与 `LAT`
  全部作废，必须重新量，不许沿用推导出来的抽位常数（复测量台架：`tb_fb_rd5x`、`tb_tap_sched`）。

## 已验证效果与来源

- **回代自检真的抓到过东西**：把 `RD_LAT=2` 代回这套公式，原样得到旧代码里的字面量，
  顺带抓出两处"存在很多版本、不会报错、只有眼睛能看见"的 1 像素错位（右窗彩条与效果链 `PROC_LAT`）。
- **算术题救了三版构建**：三版红的数字都留档 **−1.277 / −0.485 / −0.327**
  （`docs/log/OVERNIGHT_LOG.md` R20、`docs/log/CHANGELOG_V7.md` 的 build 表），最后是 `build/micro_rd/`
  的三 MODE 探针量死后才放弃那条路（`docs/log/ISSUES.md` #76）。
- **分时成立的前提是数出来的**：1W1R = 80、1W2R = 160 个 RAMB36（`sim/probes/dpfb.v`），
  而全片只有 140 ⇒ 没有这两个数，"必须分时"这条结论就没有资格。
- V7.8 那一夜的流水见 `docs/log/OVERNIGHT_LOG.md` 的 R19/R20 与 `docs/log/CHANGELOG_V7.md` V7.8；
  预算表与槽位表来自 `src/rtl/process/bilin/`，延迟量取与回代自检来自 `sim/tb_fb_rd5x.v` /
  `sim/tb_tap_sched.v`；两个失败版本（快域加法 −1.277、换节拍后两台架同时红）记在
  `docs/log/OVERNIGHT_LOG.md` 对应的 R 轮里。
