# Skill：跨域脉冲怎么过 —— 翻转式同步器 + 相位扫描判据

> 四段式：适用场景 / 使用方法 / 已验证效果 / 失效条件。
> 来源：`report/ISSUES.md` #36（登记于 R22，修于 R23），判据 `sim/tb_v79_abort_toggle.v`。

## 一、适用场景

一个域里**只存在 1~2 拍的脉冲**（看门狗到期、事件发生一次、计数清零），另一个域要"每次
都看到、且只看到一次"。本工程里的实例：`frame_commit_lock` 的 `copy_abort`（axi 100 MHz
上 1 拍 = 10 ns）被 `pl_video_top` 的 `eth_has_frame`（像素域 50 MHz）消费。

**不适用**：
- **电平**信号（链路 up/down、开关、模式）⇒ 用普通 3 级同步（`eth_link`/`src_sel` 那套），
  翻转式反而会多出一拍延迟且没有收益；
- 需要"每一次都不合并"的**连续多次**事件（翻转式是电平语义，两次事件间隔短于消费速度会合并）
  ⇒ 那种要用握手（`util/ps_publish.v` 的 `pend/consume` 就是这个形状）；
- 脉冲宽度 ≥ 目的域 2 个周期 ⇒ 裸采虽然难看但不会漏，先解决更值钱的。

## 二、使用方法（照抄可用的最小形状）

发送域（产生脉冲的地方）加一个翻转位，**与脉冲同源同域**：

```verilog
always @(posedge axi_clk or negedge axi_rst_n) begin
    if (!axi_rst_n) abort_tgl <= 1'b0;
    else if (copy_abort) abort_tgl <= ~abort_tgl;   // 一次事件 = 一次翻转
end
```

接收域用"3 级 + 异拍"，并把 `ASYNC_REG` 写给工具（否则它会把这些 FF 当普通寄存器优化散布，
亚稳概率反而上升）：

```verilog
(* ASYNC_REG = "TRUE" *) reg ab0, ab1, ab2;
always @(posedge clk_pix or negedge rst_pix_n) begin
    if (!rst_pix_n) {ab2,ab1,ab0} <= 3'b0;
    else            {ab2,ab1,ab0} <= {ab1, ab0, abort_tgl};
end
wire copy_abort_pix = ab1 ^ ab2;      // 每次事件恰好一拍
```

**判据必须配相位扫描**，否则测不出来。做法（`tb_v79_abort_toggle.v`）：
产生域与被消费域名义同相（本项目就是 MMCM 同相出来的 100/50 MHz），
把接收域的半周期临时改 1 ns（`always #(PZ)` + 一次性 `PZ=11` 再回 10）⇒ 得到 1..9 ns 的
相对偏移，每个相位跑 N 次事件，统计"真发生了几次 / 三种接法各看到几次"。
三种接法一起量：裸采、电平型 3 级、翻转式 —— 中间那一列的价值是**把"看起来正规的做法"
证伪**，不然读者会以为换个同步器链就算修好了。

## 三、已验证效果（30 次事件 × 10 个相位，`SIM DONE pass=40 fail=0`）

| 接法 | 合计 | 4 ns 相位 | 结论 |
|------|------|-----------|------|
| 裸采 | 27 / 30 | **0 / 3** | 不是"偶尔丢一个"，是**整体错位时一个都不到** |
| 电平型 3 级同步 | 27 / 30（与裸采**逐相位一致**） | 0 / 3 | **不是修法**，只是把漏看延后 3 拍 |
| 翻转 + 3 级 + 异拍 | **30 / 30** | 3 / 3 | 全相位正确 |

顺带被测量纠正的两条我自己的说法（都写回 ISSUES 了）：
① "约一半会漏"是估的，实测形态是"对齐全对、错开全丢"；
② "电平同步只会更糟"被台架否掉 —— 是"一样糟"。**结论没变，理由必须换成数字。**

**最重要的一条方法论**：0 ns（板上标称同相）这一档仿真里 3/3 全对 ⇒
这类 bug 的真实形态是"**仿真通过、硅片靠运气**"。所以这类问题的判据必须含"人为移相"，
只看默认相位等于没测。

## 四、失效条件

1. **两路时钟其实同相且脉冲与采样沿严格对齐**时，仿真看不到任何现象（见上）⇒
   不能拿"台架过了"当"没有 bug"，要拿"所有相位都对"当。
2. 事件频率接近目的域采样率时，翻转式会**合并**相邻事件（电平语义）。真需要逐次计数就要
   换成握手或计数器 + 格雷码，本工程目前不需要（abort 是毫秒级罕见事件）。
3. 目的域周期**小于**脉冲宽度时，翻转式仍然对，但裸采也可能一直是对的 —— 那时这条 skill
   的必要性下降，别为它多花一轮构建。
4. 工具版本换了要重看 `report_cdc` 的归类：本项目 R22 的实测是"补 ASYNC_REG 之后
   `clk_fpga_0→clkout0_1` 那行的未归类计数 13→0"，说明工具是按**写法**而不是按**意图**
   判定的；同样的写法在别的版本上数字可能不同，但"该写还是要写"。
5. 如果脉冲产生侧本身是**组合毛刺**产生的（不是寄存器输出），翻转位会被毛刺多翻一次 ⇒
   先确认翻转源是触发器（本工程 `copy_abort` 是寄存器 ✓）。

## 五、硬规矩：一个发射触发器只服务一组同步器（2026-09-25 r54 撞到）

"翻转位跨域"这件事，**发射触发器必须一对一**：同一个源域触发器的输出，不许同时接到
两组目的域寄存器的 D。原因不是亚稳态，而是工具判定：

- `report_cdc` 看到"一个 launch flop 扇出到多个目的时钟域寄存器"会报 **CDC-11 Critical
  "Fan-out from launch flop to destination clock"**，并把**整对**时钟从 Info/Warning 提成 Critical；
- 于是门禁第 6 项（`build/CDC_BASELINE.txt` 的**配对集合**不新增 Critical）当场红。

r54 实例（`build/gates_r54_build34_CDC_RED.txt` + `build/cdc_details.rpt`）：lane23 的心跳图省事
借用了 `sof_tgl`，而它已经喂着 `frame_latency` 的 `sof_sync_reg[0]` ⇒ details 里同一个
`u_pl/sof_tgl_reg/C` 出现在两条 CDC-11 行上（row 5 与 row 25），`clkout0_1→clk_fpga_0`
从"这一对项目里根本没有"变成 **27 端点 / 2 unsafe 的 Critical 行**。

- 正解：**给每条跨域一个自己的翻转触发器**（哪怕它与被借用的那个同源同拍，多 1 个 FF）：
  `z_hb_tog` 与 `sof_tgl` 都是"帧首翻转"，但各自只扇出一组 ⇒ 这一对退回
  19× CDC-15 Warning（准静态总线被 `bus_edge` 使能采样，是 `snap_cross` 的固有写法）
  + 2× CDC-3 Info，配对不再 Critical。
- 顺手记一条**别误读**：CDC-15「Clock enable controlled CDC structure」在本工程里是
  **期望中的 Warning**（它正是"总线只在边沿那拍被采"的证据），不要为了让它消失去改结构；
  真正要盯的是 CDC-10（同步器前有组合逻辑）与 CDC-11（本条）。
- 判据在哪：门禁第 6 项按配对集合判；`build/tcl/cdc_who.tcl` 回答"这一行是谁"。
  两者合起来才让"多加一条跨域"这件事有代价、有解释、不会被静默接受。
