# S11 · 只有一两拍宽的脉冲跨时钟域只能走翻转式同步器；电平型多级同步**不修**它

## 触发
- 当一个域里只存在一两拍宽的事件脉冲（看门狗到期、一次提交、一次清零），另一个域要"每次都看到、且只看到一次"时
- 当仿真全绿、上板靠运气，而工具的 CDC 报告一直把这条路径记成 unsafe 时
- 当你准备"给这条脉冲加一级/三级电平同步器"就当成修法时
- 当你新加一条跨域、打算顺手借用现成那个翻转位（同源同拍，看起来不花钱）时

## 不适用
- 电平类信号（链路 up/down、模式、开关）：用普通多级电平同步即可，翻转式只多一拍延迟、没有收益
- 需要"每一次都不合并"的密集事件：翻转同步本质是电平语义，事件间隔短于目的域消费速度就会合并，要用握手或计数器 + 格雷码
- 脉冲宽度已经 ≥ 目的域 2 个周期：裸采虽然难看但不会漏，先解决更值钱的那条

## 动作
1. 源域加一个翻转位，与脉冲**同源同域**，一次事件翻一次。
2. 目的域用"三级 + 异拍"还原脉冲：移位三级，输出取最后两级的异或 ⇒ 每次事件恰好一拍。
3. 给这条链的寄存器写上工具的异步约束属性（本仓库是 `ASYNC_REG`）。不写，工具会把这些触发器当普通寄存器优化散布，亚稳概率反而上升。
4. 判据必须带**人为移相**：两路时钟名义同相（同一颗 PLL/MMCM 出来的整数比）时，把接收域半周期临时挪开 1~9 ns 逐相扫，每个相位跑 N 次事件，统计"真发生了几次 / 每种接法各看到几次"。只看默认相位等于没测。
5. 三种接法一起量：裸采、电平型多级、翻转式。中间那一列的价值是**把"看起来正规的做法"证伪**，否则读者会以为换一条同步器链就算修好了。
6. 握手类/非整数比时钟的台架同理：把两个时钟做成非整数比，并给每次事件加随机相位——"恰好同相"那一格会掩盖全部问题。
7. 每条新跨域**自己起一个发射触发器**，哪怕它与已有的那个同源同拍（多花 1 个触发器）：一个发射触发器扇出到目的域的两组同步器，会被工具按"发射端扇出"判成 Critical，并把整对时钟从 Info/Warning 提级。

最小形状（可直接抄，名字换成你的）：

```verilog
always @(posedge src_clk or negedge src_rst_n)          // 源域：一次事件 = 一次翻转
    if (!src_rst_n) tgl <= 1'b0;  else if (evt) tgl <= ~tgl;
(* ASYNC_REG = "TRUE" *) reg s0, s1, s2;                // 目的域：三级 + 异拍
always @(posedge dst_clk or negedge dst_rst_n)
    if (!dst_rst_n) {s2,s1,s0} <= 3'b0;  else {s2,s1,s0} <= {s1,s0,tgl};
wire evt_in_dst = s1 ^ s2;                              // 每次事件恰好一拍
```

## 完成判据
- 相位扫描表必须同时给出这两件事才算数：翻转式在**所有测试相位**上 N/N 全对；裸采与电平型多级至少各有一个相位**归零**。只有第一句、没有第二句，说明这轮激励没打到要害（判据恒真）。（本仓库入口：`bash sim/run_one.sh tb_v79_abort_toggle`）
- 名义同相那一档在仿真里通常全对 ⇒ "台架过了"永远不等于"没有这个 bug"，只有"所有相位都对"才是判据。
- 工具侧可复核的那条：补上异步属性后，这一对的"未归类"端点数应归零（本仓库实测从 13 降到 0）。

## 失效边界
- 两路时钟真的同相、且脉冲与采样沿严格对齐时仿真看不到任何现象——这正是这类 bug 的真实形态："仿真通过、硅片靠运气"。
- 事件频率接近目的域采样率时翻转式会**合并**相邻事件，那时要换握手或计数器 + 格雷码。
- 目的域周期小于脉冲宽度时，翻转式仍然对，但裸采也可能一直是对的 ⇒ 本条的必要性下降，别为它多花一轮构建。
- 脉冲若由组合逻辑毛刺产生（不是寄存器输出），翻转位会被毛刺多翻一次 ⇒ 先确认翻转源是触发器。
- 换了工具版本要重看 CDC 报告的归类：它按**写法**判定而不是按**意图**，同写法在别的版本数字可能不同，但该写的属性还得写。别为了让某类 Warning 消失去改结构——有些 Warning 正是"总线只在事件那一拍被采"的证据；真正要盯的是"同步器前有组合逻辑"和"发射端扇出"这两类。
- 相邻条目的分界：跨域总线的"配对基线门禁"（unsafe 端点数也会漂，同一对配对的计数才是真相）见 S16；一拍宽请求在共享介质仲裁里的记账见 S12；同步器前面那段组合逻辑怎么被点名，也见 S16。
