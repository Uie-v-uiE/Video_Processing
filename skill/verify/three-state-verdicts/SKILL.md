# 三态判定与计数口径：每条判据的输出形状

## 适用场景

- 新写或改任何检查器、门禁跑批、比对器，需要规定它打印什么。
- 出现"扫描器一条都没抓到，结论却是通过"。
- 汇总脚本 grep 不到判定词，或者被明细行里的一句"FAIL 明细"骗了。
- `判 N 项` 的 N 对不上实际做过的比较；通过数下降被读成射程变窄。
- 日志过一遍管道/重定向后中文列变乱码，红伪装成崩溃。

## 使用方法

硬性规定（低自由度，逐条落到脚本里）：

1. 每条判据只有三态：`PASS / FAIL / NOT_MEASURED`。不设第四态，也不许用空串、缺字段、
   默认值来表达"没测"——"没测"必须显式打印。
2. **结论行最后一个字段才是判定词**，形状固定为 `判 N 项：<计数与说明> <判定词>`。
   行内其它位置出现的 `FAIL`（明细行、文件名、被检内容自带的字符串）都不参与判定；
   解析按**最后一个空白分隔字段**取，不按"整行里有没有 FAIL"取。
3. `判 N 项` 记的是**做了多少次比较**，不是通过了多少项。把"通过数下降"读成"射程变窄"
   是本包自己犯过的错：只有比较次数才反映射程，通过数只反映结果。
4. 空集、文件读不到、解析失败、格式不认识——一律 `NOT_MEASURED`，不许默认通过，
   也不许当"设计干净"。`NOT_MEASURED` 的退出码与 `FAIL` 分开（红=1、未测=2），
   这样"跑挂了"不会被误读成"判过了"。
5. **每层解析都要计数地板**：提取层、判据层、汇总层各自打印抓到的条数，
   抓到 N≥1 才算这一层扫到；N=0 时这一层只能给 `NOT_MEASURED`，并打印是谁筛空的
   （哪个输入、哪条过滤、列数不符）。地板值按被检对象的实际规模定，不许留 0 当默认。
6. **机器可读 token 保持 ASCII**：判定词、字段名、计数键都用 ASCII；中文只放在说明里，
   并且放在判定词之前或另起明细行。控制台/日志编码把中文判定变乱码时，
   解析抛异常会被当成崩溃，红就被伪装掉了。

可抄的输出示例（每个前缀是一条判据，最后一行是汇总）：

```text
[cfg-window] 提取条数=14 地板=1
[cfg-window] 期望 下界<=1024 上界<=4096 实测 min=512 max=1024
[cfg-window] 判 28 项：上下界各 14 次比较 差异=0 PASS
[golden-map] 提取条数=0 地板=1 原因=表头列数不符(期望 7 实测 6)
[golden-map] 判 0 项：本轮未做任何比较 NOT_MEASURED
overall 判 28 项：判据=2 比较=28 红=0 未测=1 FAIL
```

（汇总行末尾字段才是判定；上一行的 `PASS` 不参与折叠。这里红是因为有未测项被门禁降级拒绝。）

可抄的解析示例（bash）：

```bash
line=$(grep -m1 '^overall' run.log) || { echo "NOT_MEASURED"; exit 2; }
v=${line##* }                       # 取最后一个空白分隔字段
case "$v" in
  PASS) exit 0 ;;
  FAIL) exit 1 ;;
  *) echo "无法识别的判定词: [$v]"; exit 2 ;;
esac
```

跑完应看到：判定词永远是 ASCII 三态之一；每一层都有"提取条数/比较次数"两个数；
识别不了的情况走 `exit 2`，不走 0。

**先查什么**：解析器要先对**真实件**的形状核一遍（列数、表头、单位）再信它，不要按夹具写解析；
判定词形状以本包的尺子语言为准（见 `checker-selftest`）。
**先跟用户确认什么**：把某层从 `FAIL` 降级成 `NOT_MEASURED`、调整计数地板、
改动汇总折叠规则（未测是否拒绝）——这些都会改变放行口径，不是纯技术细节。

## 失效条件

- 判定词写在了行中而解析取了别的位置（例如把"详见 FAIL 明细"当结论）→ 汇总读空，脚本按 0 退出。
- 汇总用布尔折叠处理空列表（`all([])` 为真、`reduce(and)` 初值为真）：空集直接变通过，
  这是本族最安静的假绿。
- 计数键中途从"比较次数"换成"通过数"（或反之）→ 两轮的数不可比，趋势全是噪声。
- 编码：日志经管道或重定向换了编码，中文列成乱码，解析抛异常，你开始查设计而不是查尺子。
  征兆：红只在带中文的那一列出现，去掉中文就绿。
- 某条判据既不打印 PASS 也不打印 FAIL（异常被 catch 后静默跳过）→ 明细行数比预期少而结论仍绿。
- 本条对"判定词该判什么"保持中立：它只规定形状，不替你决定阈值。

## 已验证效果

未量过，属建议。采用这条时要求现场给出两个读数：每次运行的"比较次数"与"未测层数"，
以及一条被人为清空输入的注入确实让结论变成 `NOT_MEASURED`（而不是 `PASS`）。

## 来源

长自"没扫到被写成通过"这一族账——它是尺子类错误里最大的一族；也长自把"通过数下降"
误读成"射程变窄"的一次自我纠错，以及中文判定经控制台编码被伪装成崩溃的观察。
对应坑清单 `ruler-fake-greens`、`tcl-and-probe-traps`。配套见 `checker-selftest`、`mutation-controlled-coverage`。
