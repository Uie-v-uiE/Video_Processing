# 改代码前先建尺子：期望值从当前代码逐行推出

## 适用场景

- 要动 RTL / 台架 / 生成脚本，但手里只有"编译通过"这种弱读数，没有任何一条判据能红。
- 出现"改前红"：台架在干净树上就报红，你分不清是设计的问题还是你的期望写错了。
- 做行为保持的重构（拆模块、改名、插拍、重定时），需要证明"输出没变"而不是"我觉得没变"。
- 一轮改动结束后只有叙述式的结论，没有可复跑的对照。

## 使用方法

**先查什么**（一手资料优先级：设计源码与接口规范/数据手册 ＞ 应用笔记 ＞ 教程 ＞ 模型记忆）：

1. 当前代码本身——端口与参数定义、复位分支里的初值、状态机的出口条件、寄存器的读写宏。
   期望值只能从这些地方逐行推出来。
2. 越界/范围类判据的上下界来自规范（合法范围、编码表、位宽上限），不来自"大概"。
3. 旧版设计在未修改干净树上的实际输出。
   凭记忆写进判据的数字一律先标"未核"，查到出处才允许进入结论。

**先跟用户确认什么**：判据口径的改变（阈值、容差、把某项移出或移入门禁）——尤其是会把原本红的变绿；
是否允许为对照在源码里临时插桩、是否允许改台架的激励序列；跑整轮构建/仿真的时间预算。

**最小序列**（低自由度，按序执行）：

1. 在**未修改的干净树**上跑一遍台架，记下每条判据的读数与 `判 N 项`。
   理由：最便宜的对照就是旧设计本身，不需要另写参考模型；干净树绿了之后，后面任何红才能归因到本轮改动。
2. 逐条写期望，每条后面挂出处（代码位置或规范条目）。推不出处分的期望不许进判据，先挂"待定"。
3. 判据形状要**两端夹逼**：越界/范围类同时判上界与下界，只判一边会漏——
   只判"不超上限"时，负值、回绕、下溢全绿；比较"相等"时也要判偏差方向（谁大谁小），
   单向阈值会掩盖反向偏差。
4. 每条判据配一个**最小变异对照**：故意把边界挪一格、把一个期望值挪一位，跑，必须红；
   复原，必须绿。红不了说明这条判据是死的，按 `checker-selftest` 处理。
5. 然后才改设计。改完复跑，与步骤 1 的读数做差分；任何"由红变绿"都要能指到某一条具体改动。

**行为保持重构的专用判据**：

- 比对**输出字节流**（逐样本/逐字节的全文对照或差异行清单），不要比哈希摘要——
  摘要相同不代表内容相同：字段对调、行列转置、块序置换都可能得到同一份摘要，而内容已经错了。
- 再配一条**输入扰动对照**：换一条激励（换种子、换边界值、换长度），重构前后各跑一次，
  两次的差异集合都必须为空。只在一组输入上比字节流，会把"只在这组激励下才暴露的置换"买通。
- 重构不许顺手改期望。如果你不得不动判据文件，说明这不是行为保持，按功能改动重新走一遍上面五步。

## 失效条件

- 干净树本身是错的（旧设计的已知缺陷被当参考）：此时"改前绿"只证明一样、不证明对，
  必须先有一条来自规范的外部判据顶住。征兆：所有判据从立项起就没红过。
- 期望是从直觉或上次读数抄的，不是从代码推的 → 出现"改前红"。这类红绝大多数是期望猜错、DUT 无辜。
  征兆：同一处反复调期望，每调一次就绿一次。
- 台架输出自身不稳定（时间戳、绝对路径、随机种子、异步读回顺序混进输出流）→ 字节流对照永远红，
  会诱使你退回摘要比对，那正好是假绿。先做输出规范化（剥时间戳、排序）再比。
- 变异对照只在单一激励下才红：判据其实只覆盖一角，按 `mutation-controlled-coverage` 补组合。
- 计数把"通过数"当射程：改前改后的数不可比，见 `three-state-verdicts`。

## 已验证效果

未量过，属建议。落地这条时要求现场给出两个可复跑读数：干净树基线的 `判 N 项` 与每条判据的变异红/绿配对表。

## 来源

长自两类观察：反复"改前红"最后发现是期望猜错、DUT 一直是对的；行为保持重构用摘要比对被内容置换骗过。
对应坑清单条目 `ruler-fake-greens`、`tcl-and-probe-traps`。配套纪律见 `checker-selftest`、`three-state-verdicts`、`mutation-controlled-coverage`。
