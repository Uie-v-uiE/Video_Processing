# 变异对照下的覆盖率：射程按比较次数算

## 适用场景

- 要回答"这套尺子覆盖到了什么"，而不是"这轮跑了几条判据"。
- 出现：某个症状"修好"之后下一轮仍在；覆盖数字看着够，但说不清哪条规则管哪一处。
- 脚本用文件清单/后缀过滤决定遍历范围，没人能证明那个集合是全集。
- 两个维度各自都测过，但它们的组合从没被任何一条判据刺激过。

## 使用方法

1. **"检查过"不等于"集合完整"**。做法：沿"**这一轮哪些数字变了**"遍历所有出现处。
   本轮改动触碰过的量——判据条数、名字、阈值、单位口径、路径——都全文检索出它的每一处出现
   （文档、索引、跑批脚本、其它检查器的期望表），逐个问三句话：
   这条规则归谁管？谁负责改它？有没有机器判据覆盖到这一处？
   三问有一个答不上来就是射程外的洞，登记为欠账，不许当成已完成。

2. **射程计数器按比较次数**，不按判据条数、不按通过数（口径定义见 `three-state-verdicts`）。
   条数不变而比较次数下降 ⇒ 射程在收窄；征兆是某类对象突然不进集合
   （字段改名、表头漂移、目录层级变化都会这样收掉，而且不报错）。

3. **范围由 `find` 现算，不要手写文件清单**。手写清单会随目录变深静默变窄：新增子目录、
   改后缀、换个落盘位置，脚本只会少扫，然后绿。做法与最小形状：

   ```text
   find <根> -type f -name '<模式>' -print    # 现算，并打印进入集合的条数
   ```

   同时打印：进入集合的条数、显式排除的目录与排除理由、遍历对符号链接与隐藏目录的策略。
   数字要和"预期规模"对一眼（这个工程大概该有多少个这类文件），差得离谱就是过滤吃掉了东西。

4. **两个维度的覆盖必须在同一条判据里同现**。分别覆盖会留下从未被刺激的组合：
   维度甲单独测绿、维度乙单独测绿，而 (甲,乙) 的组合从没进过任何判据。
   做法：列出每条判据实际刺激的组合集合，与"关心的组合"做差集，差集非空就是洞；
   补的是**一条同时要求两维度成立**的判据，而不是再补两条单维度的。

5. **变异对照的构造**（低自由度）：对每个关心的维度注入一个最小、单点、可复原的缺陷，
   要求它让对应判据变红；一条变异只该红一条判据，需要连带红的把连带关系列成清单而不是削弱判据
   （见 `checker-selftest`）。注入必须一键复原，复原后复跑要绿。
   注在**被检数据**上，不要注在期望值上——改期望只能证明比较在跑，证明不了提取在跑。
   记不住红是怎么来的，就记不住眼前的绿值不值钱。

6. **"某症状消失了"要先怀疑尺子维度对不对得上**。症状在"修好"之后仍在 ⇒ 是尺子或归因错了，
   不是设计变好了。对照问题：这条判据的观测维度与症状所在维度是同一个吗？
   单位与计数口径是同一个吗（见 `golden-reference-compare`）？提取层真的读到这一类对象吗？
   三问都过了，才允许把"消失"写进结论。

7. **新增判据时同步更新所有引用判据条数的文案**，在同一次提交里：条数本身是被引数字，
   漏改就得到"文档 N 条 / 实跑 N+1 项"这种对不上；改完复跑门禁与索引一致性检查。

**先查什么**：这一轮改动的**一手范围**来自版本控制的差异清单与构建产物列表，
不是你记忆里"我改了哪几个文件"；判据的合法取值范围来自规范与源码（优先级见 `research-before-code`）。
**先跟用户确认什么**：扩大遍历范围会让旧欠账一起变红、把门禁染红；补新维度会把已有的绿改掉
——这些是口径变更不是纯增益；以及在真件里注入缺陷前必须确认能完整复原。

## 失效条件

- 用"跑了 N 条判据"当覆盖读数：每条都在扫空集也算覆盖，数字漂亮而射程为零。
- 计数口径中途换过（通过数与比较次数互换）：两轮的数不可比，任何趋势都是噪声。
- 排除列表写死目录名：真件换了目录就被排除出射程，红变绿，看起来"改善了"。
- 遍历依赖相对路径或当前工作目录：换机器上"少扫"，而少扫从不报错，只让结论变绿。
- 组合差集靠手算：判据一多必漏，漏掉的那一格正是缺陷的藏身处。
- 变异只注入在实现层或只注入在期望表上：提取层的缺陷全程没被刺激过，正对照永远绿。
- 把"这条判据从没红过"当成稳定可靠——它更可能是死的（见 `checker-selftest`）。

## 已验证效果

未量过，属建议。采用本条要求交付时给出三项读数：每个维度的实际比较次数、单点变异的红/绿配对表、
以及差集清单（哪些关心的组合至今没有任何判据刺激过），三项缺一即视为未量。

## 来源

长自四类观察：一个"永远绿"的判据掩盖了从未被刺激的维度组合；手写文件清单随目录变深静默变窄；
症状在"修好"之后仍在，最后发现是尺子维度对不上；新增判据后引用条数的文案没在同一提交里改。
对应坑清单 `ruler-fake-greens`、`constraint-coverage-loss`、`doc-rotation-damage`。
配套见 `checker-selftest`、`three-state-verdicts`、`golden-reference-compare`。
