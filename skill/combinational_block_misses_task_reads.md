# `always @(*)` 看不见"只在任务里读"的信号：组合块会拿着旧值不放

## 适用场景

一个纯组合的 `always @(*)`（字模表、mux、控制字解码、状态显示）里调了 `task`/`function`，
而某个信号**只在那个任务体内被读**。症状是：改这个信号的激励，输出**不动**——
不是差一拍，是**永远停在上一次的值**；仿真、综合、时序报告全绿。

写 RTL 的人很容易掉进去，因为代码看起来完全正确：

```verilog
task put_src;                       // ✗ 任务里直接读模块信号
    begin
        case (src_eff)  2'b11: puts("ETH", 3);  2'b10: puts("PS", 2);
                        default: puts("CARD", 4);  endcase
        if (mode != 2'b00) put("*");
    end
endtask

always @(*) begin                   // 块里只写了 put_src; —— @(*) 看不到 src_eff / mode
    at(0); puts("FPS:", 4); ...  put_src;  ...
end
```

## 为什么

Verilog-2001 的 `@(*)` 是把**这个块自己的表达式里读到的**量收集进敏感表；
它**不递归进被调用的 task**。于是 `src_eff` 变了、块不会被叫醒，`chars[]` 里留着上一次算的结果。
（`@*` 在 SystemVerilog 里也只到参数传递那一层，别指望工具替你补上。）

综合端看不出来：综合是**组合可达性**分析，它按方程建逻辑，不按事件队列 ⇒ 硬件里那条线是连着的，
于是仿真与硬件的行为不一致，而且不一致的方向是"仿真少算了一次更新"——屏上就是一次真实的错标签。

## 使用方法（三条，按优先级）

1. **把信号作为任务入参传进去**（本仓库采纳的写法）。这样读发生在块里，`@(*)` 看得见：

   ```verilog
   task put_src;  input [1:0] se;  input [1:0] md;  ...  endtask
   always @(*) begin ... put_src(src_eff, mode); ... end
   ```

2. 或者把**判断留在块里**、任务只做机械动作（`put(char)` / `puts(str,n)` 这种只读写参数的）。
   本仓库的排版任务就故意只有 `col`/`chars` 两个模块级副作用，其余全是入参。
3. 或者改用 `always_comb`（SystemVerilog）并让工具做全集分析——**不推荐**：本仓库是 Verilog-2001 口径，
   而且这条规则一旦被下一个人破一次，就又回到"看着对"的状态。

## 怎么把它变成判据（关键）

这类 bug 的特征是"**改了激励、输出不动**"，所以判据必须是**差分**的，不能只比一个状态：

```
先设 A → 读期望；再设 B → 读期望；两次都按整串比对。
```
如果实现看不见 B，第二次比对就会红。抽样比"一个代表状态"是抓不到的。

本仓库的落地：`sim/tb_osd_lines.v` 的 T3 段连比四种片源状态，其中一条故意造
"仲裁以为自己占着屏、mux 其实选了图卡"——**标签必须跟着屏幕走**。
这条判据在写出来的那一轮就抓住了上面的 bug（第一次跑：`src_eff=CARD` 而屏上仍是 `PS`）。

## 同族的另外两条"块不动"签名

- 信号在 `generate`/函数里读：函数同样不进敏感表 ⇒ 让调用方把值当参数传。
- 敏感表里少一个信号（`always @(a or b)` 忘了 c）：与上面同一种红法——差分激励。
