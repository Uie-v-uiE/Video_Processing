# S19 · `always @(*)` 不递归进被调用的任务：只在任务里读的信号会拿着旧值不放

## 触发
- 当你在一个纯组合块（字模表、mux、控制字解码、状态显示）里调了 `task`/`function`，而某个信号**只在那个任务体内被读**
- 当你改这个信号的激励，输出**完全不动**——不是差一拍，是永远停在上一次算好的值
- 当仿真、综合、时序报告、门禁全绿，而屏上或下游拿到一个陈旧的标签/内容
- 当你把"判断"写进了任务体（任务直接读模块级信号），只把机械动作留在块里
- 当你手写了 `always @(a or b)` 的敏感表，或者把值在函数/`generate` 里读

## 不适用
- 块里根本不调任务、只是敏感表少写了一个信号：症状一模一样，但修法是补敏感表，把任务改成入参不会有任何变化 ⇒ 先定位再选修法
- 综合之后的硬件也错（不只是仿真少算一次）：那说明那条线在网表里真没连上，属端口接线检查，不在本页
- 工具按 SystemVerilog 编、`always_comb` 做全集分析时看不到这现象——但别把修法写成"换关键字"（理由见动作 4）
- 带时钟沿的时序块不适用：本条只讲组合块敏感表的推导规则

## 动作
1. 先定位"这个名字到底在哪一行被读"：只在被调用的任务/函数里出现、块本体一次都不读 ⇒ 确诊。
   机理只有一句：Verilog-2001 的 `@(*)` 只把**本块自己的表达式里读到的**量收进敏感表，
   它不递归进被调用的任务（`@*` 在 SystemVerilog 里也只到实参那一层，工具不会替你补）；
   而综合是**组合可达性**分析，它按方程建逻辑、不按事件队列 ⇒ 于是"仿真少算一次更新、硬件照连"
2. 把信号作为任务的**入参**传进去：这样读发生在块里，`@(*)` 就看得见（本仓库采纳的写法；
   源码里那条"为什么必须是入参"的注释要留着给下一个人）
3. 或者把**判断留在块里**、任务只做机械动作：只读写参数的 `put(char)` / `puts(str,n)` 这类。
   排版类任务故意只留"列指针 + 字符数组"两个模块级副作用，其余全走参数
4. 不建议改成 `always_comb` 让工具做全集分析：口径是 Verilog-2001 的工程不提这个选项；
   更关键的是这条规则一旦被下一个人破一次，就回到"看着对"的状态
5. 把它变成**差分**判据（这一步才是重点）：这类 bug 的签名是"改了激励、输出不动"，
   所以判据不许只比一个状态——先设 A 读期望、再设 B 读期望，两次都按**整串**比对；
   多位的源选择信号要把它的全部取值都扫一遍，抽一个代表状态等于没有这条判据
6. 显示类标签与"mux 实际选中的那一路"必须被同一句判据钉住：故意造一个
   "仲裁以为自己占着输出、mux 其实选了另一路"的不一致态进台架（本仓库落在 `sim/tb_osd_lines.v` 的 T3，连比四种片源状态）
7. 同族两条一起扫：值在函数/`generate` 里读（函数同样不进敏感表 ⇒ 让调用方把值当参数传）、
   手写敏感表漏一个信号（与上面同一种红法，同样用差分激励抓）

## 完成判据
- 一条可执行的红/绿：台架对同一输出串逐状态整串比对 ⇒ 实现"看不见"后一个状态时，那一次比对必红。
  这条判据写出来那一轮就抓住了真 bug（片源已切、屏上标签还停在上一路），报的是"标签 ≠ 屏幕"而不是超时
- 反面对照（证明它不是恒红）：改成入参写法后所有状态应全绿；把入参退回任务内直读，必须立刻红
- 数字关系：**采样状态数 ≥ 该信号定义域的基数**（2 bit 源 ⇒ 至少 4 格），少一格就可能结构性红不了

## 失效边界
- 差分激励是唯一能生效的形状：只比一格给出的仍是假绿，而且会把注意力推向"综合也错了"这种更贵的假设
  （补维度这件事本身是 [S21](criterion_blind_spot.md) 的地盘）
- "改了激励输出不动"也可能是激励根本没进到那条路（声明了却没进位流、顶层没例化）⇒ 先确认信号活着再怀疑敏感表
- 本页只管"块不动"这一族：期望值本身算错、采样相位选错、起点没复位是 [S20](bench_self_inflicted_reds.md)
- 换关键字让症状消失不等于根因走掉：只要还有任务直读模块信号，这条规则就等着被破

## 出处
`docs/log/OVERNIGHT_LOG.md` §33 那一轮——判据写出来的第一次运行就把显示标签与 mux 实际选中的那一路钉在一起（实现见 `src/rtl/video/osd_overlay.v` 的入参写法与 `sim/tb_osd_lines.v` T3）。
