# 契约 ⇒ 主机侧三份产物（同源生成 + 自带能红的自测）

## 适用场景

- 改一条寄存器要同时改头文件、脚本常量、测试三处，时间长了两边漂移。
- 契约表新增一行，只有调用改了、测试没加，漏项靠人记。
- 地址区间重叠、复位值超位宽这类错误到上板才现形。
- 交接时对方要"能直接编译、能直接跑"的主机侧壳子，而现在手里只有一张表格。
- 同一个生成器两次跑出不同文件（把时间戳或绝对路径写进了产物）。

## 使用方法

在条目根目录执行（路径全相对）：

```bash
node scripts/gen.mjs --in <契约表.csv> --out <产物目录> [--stem <前缀>]
node scripts/gen.mjs --self        # 跑随包夹具与变异对照
```

契约形状（列名固定、一列一名）：`name,offset,width,access,policy,reset,doc`；
`access ∈ RW/RO/WO/self-clear`；`policy` 放单位或换算式（原样搬进产物、不参与计算）；
数值接受 `0x` / `0b` / 十进制。给了 `--out` 却没给 `--in` 时默认吃 `fixtures/contract.csv`；
什么参数都不给 ⇒ 打印用法并判未测（不猜你要往哪儿生成）。

跑完应看到（8 行夹具的实测读数）：

```
契约 contract.csv：行数=8 生成用例数=8 一致=PASS（判据：契约行数 = 生成用例数）
已生成 3 份：contract_regs.h, contract_regs.mjs, contract_regs_test.mjs
判 23 项 红=0 未测=0 PASS
```

退出码 **0 绿 / 1 红 / 2 未测**；判红时（重叠、复位越界、名字重复、access 非法、缺硬列）
**不落任何文件**，只打印每条红及其行号与区间——先改契约再重跑，不许绕过。

三份产物各自承担什么：

1. `<stem>_regs.h`：偏移/位宽/掩码/复位/方向宏 + `NAME_READ(base)` / `NAME_WRITE(base,v)`；
   **RO 故意不生成写宏**；末尾用 `GEN_ASSERT`（报错数组技巧）做**编译期**区间不重叠与复位不越界。
   产物只出偏移，基址由宿主传进 `base`。
2. `<stem>_regs.mjs`：`REGISTERS` 冻结数组 + `offsetOf / regOf / maskOf / resetOf / isWritable / isSelfClear / names`。
   **缺列的字段值是 `null` 而不是 0**——0 会把"没测到"洗成"通过"。
3. `<stem>_regs_test.mjs`：每寄存器一条用例（RW 写 A 读 A + 写 B 读 B；RO 写后两次读回相等；
   self-clear 读回应为 0；WO 天生标未测）。期望值出厂就是 `【待填：读回值】`，
   直跑 ⇒ 每条 `NOT_MEASURED` 且退出 2。接入方式：填期望，再实现 `io = { read(name), write(name, v) }`
   调 `runAll(io)`。

**先查什么**：契约每个值必须能指到一手资料（用户指南/数据手册里的寄存器表、接口规范里的命令规格），
优先级 一手规范 ＞ 应用笔记 ＞ 教程 ＞ 模型记忆。动手前先逐列核对偏移、位宽、方向、复位值、单位，
对不上先改表并在表里标红，**不许在生成物里打补丁**。
**先跟用户确认**：列形状是否已定（改形状影响所有已生成物）、产物落在哪个目录、是否允许覆盖既有文件、
基址与访问宽度由谁提供、子字节寄存器是否允许非字节对齐偏移。

## 失效条件

- 一致性判据只证**同源**，不证**对硬件**：行数相等、用例数相等，地址仍可能是抄错的。
  征兆是"全绿但板上读不回"——那一段只能靠板上读回，不在本工具射程内。
- 契约形状表达不了的特例（读即清的副作用、同一偏移按模式变义、需要位域 shift 的打包、窗口式间接寻址）
  ⇒ 不许往模板里塞分支。征兆：产物里出现"这一条特殊"的手工注释、或同一列出现两种单位。该改列，不是加分支。
- 幂等只在契约字节不变时成立：**改行顺序也会变 digest**，产物 diff 出满屏红是有意的（逼你确认变动来自契约）。
- 缺列时生成物写 `null`；下游代码把 `null` 当 0 用就又回到假绿。这条只在"读回口按三态处理"的前提下才安全。
- `width > 32` 直接判红：本工具不出 64 位与任意位域切分形状，别把它当位域生成器用。
- 编译期那两层断言**只有真编译过生成物才算数**。从没编译 ⇒ 那层是未测，不是通过。
- 判红时不落文件 ⇒ 上一版产物仍留在盘上。别把旧产物当新生成的用（比对完再决定是否删）。

## 已验证效果

`node scripts/gen.mjs --self` 实跑读数（本包内，退出码 0）：

```
S1 黄金一致（3 份产物逐字节比对随包 expected） 相符=3/3 生成退出码=0 PASS
S2 幂等（同一契约两次生成逐字节一致） 相符=3/3 PASS
S3 能红对照：两条 offset 改成重叠 ⇒ 必须红且只红这一条 退出码=1 红行=1 点名=STATUS/IE 未落盘=是 PASS
S4 能红对照：reset 超出 width ⇒ 必须红且只红一条 退出码=1 红行=1 越界条数=1 PASS
S5 缺列 ⇒ 用例照生成并标 NOT_MEASURED，且不编默认值 退出码=2 未测=5/5 reset:null=5/5 头文件标注=5/5 编造值=无 PASS
S6 测试骨架直接跑 ⇒ 8/8 条 NOT_MEASURED（不许假绿） 退出码=2 未测=8/8 用例数=8 PASS
S7 空契约（只有表头）⇒ NOT_MEASURED 而非通过 退出码=2 结论=判 0 项 红=0 未测=0 NOT_MEASURED PASS
S8 填期望 + 理想 io ⇒ 测到的全绿、只剩 WO 未测 退出码=2 比较=14 红=0 未测=1 PASS
S9 变异对照：模型丢掉 CTRL 的写 ⇒ 骨架必须判红 退出码=1 红=1 点名=CTRL PASS
判 27 项 红=0 未测=0 PASS
```

另把生成头文件拿 C99 编译器编了一次（通过），再做两个变异：`IE_OFFSET` 改 `0x06u` ⇒
`error: size of array 'gen_assert_cth_ov_…' is negative`；`DBG_RESET` 改 `0x0001FFFFu` ⇒
`error: size of array 'gen_assert_cth_rst_DBG' is negative`，退出码都是 1 ⇒ 编译期那两层真能红。
未量过：真实工程里"手工双改 vs 同源生成"的漏项差没量过，属建议。

## 来源

长自"主机侧代码与寄存器表双轨手工维护、改一处漏一处、交接时两边对不上"这一类反复出现的观察；
范式与列形状的讨论见 runtime 类的 `host-bindings-from-contract`；三态与"判 N 项 = 比较次数"
见 verify 类的 `three-state-verdicts`；自带 `--self` 与变异对照的纪律见 verify 类的 `checker-selftest`；
假绿形态（空集、把通过数当比较数）见 pitfalls 类的 `ruler-fake-greens`；三件套齐（件 + 夹具 + 自测）
的完整性要求见 pitfalls 类的 `package-integrity`；批量改口时把生成物手改坏的形态见 pitfalls 类的 `doc-rotation-damage`。
