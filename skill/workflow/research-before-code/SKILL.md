# 动手前的检索规范与出处记录

## 适用场景

- 你要在文档或约束里写下一个数字、一个引脚、一条属性，却答不出它来自哪份文档的哪一页。
- 模型（或你自己）"记得"某张表里的值，而这个值会决定约束、验收判据或对外结论。
- 出现带合规性含义的材料：建立/保持窗、掩码与屏蔽表、未公开的寄存器位定义——这些常在保密协议材料里。
- 某个报告字段或属性名第一次出现，形状靠猜。

## 使用方法

### 一手资料优先级（越靠前越有资格被当事实）

1. 厂商用户指南、数据手册、引脚表、接口规范——器件与板卡的权威定义。
2. 应用笔记、勘误表——结论正确但带适用条件（修订号、版本、封装）。
3. 第三方教程、博客、开源仓库——只当线索与旁证，不当出处。
4. 模型记忆——不是资料，是待核对的假设。

### 一条事实的记账形状（三件套齐了才算查过）

- **内容**：将写进文档的那一句，带单位与成立条件。
- **位置**：文档全名 + 版本或日期 + 章节号或表号 + 页码，并注明是文件页还是印刷页。
- **核对**：一条可复跑的动作，别人跑它能取到同一个值——文本型文档给抽取命令与关键词；
  在线文档给锚点标题；工具报告给"命令 + 取哪个字段"。

### 带合规性的窗口/掩码类表格

这类表格经常在保密协议材料里。此时：只能引用公开的二手转述，并显式标注「未核对原始表格」，
同时写清你据以推导的量及其公开出处。不许把协议材料的内容抄进仓库或交付文档；
不许把"我知道有这张表"写成"这条已核实"。

### 提问模板（向模型要事实时逐字可用）

```
就下面每一项结论，分三行输出：
  结论：<一句话，含单位与成立条件>
  出处：<文档全名> <版本/日期> · <章节号或表号> · <页码，注明文件页还是印刷页>
  核对：<一条能复跑的命令，或"取哪份产物的哪个字段">
没有出处的结论单独归到「假设」一节，不要混进事实。
查不到就写查不到，禁止用"通常/一般来说/大概"把空缺补成事实。
```

拿到答案后：抽查至少一个页码或表号是否真指向所述内容——模型给的页码可能是编的。
抽查不过，整批降级为假设，并回到一手文档重新核对。

### 查不到就标「未核实」

统一标记 + 一句"要核什么、去哪儿核"。含糊句子（"通常是某个频率"）视为没写。

### 先跟用户确认什么（查完之后，不是之前）

一手资料的可达性（有无访问协议材料的资格、要不要用镜像）、引用与转述的许可边界、
未核实项是否允许进入交付文档（默认：允许，但必须带标记）。顺序是：先只读检索，再问这三件，
最后才把事实写进约束或判据。

## 失效条件

- **扫描版或图片型文档检索不到文本**：检索"没有命中"不等于"文档里没有"。先确认抽取层能出字
  （拿一句你肉眼看得见的话做正对照），出不了字就改用读图并记页码，把这条判为未测量而非缺失。
- **在线文档的版本与你手上的工具/器件版本不一致**：页面默认显示最新版，属性名、表号、行为都可能已变；
  以随装文档为准，网页只当差异线索。
- **模型给的页码可能是编的**：所以抽查是硬步骤；跳过抽查等于把记忆当一手资料。
- **公开转述与协议材料不一致时**：以你能核对到的公开量为准，并承认结论带不确定性；
  不许悄悄用"内部知识"把差值补齐。
- **勘误与应用笔记只适用于某个修订号**：抄结论不抄条件，会把别人的修正当成自己的规格。
- 把文档里的示例当成文档里的规定：示例经常省略前置条件。

## 已验证效果

未量过，属建议。依据的观察类别：把模型记忆当事实写进文档，后来被厂商文档的实际页码与表号打脸；
以及涉密表格只能引公开二手转述、边界不写清就在交付审查里说不清来源。想变硬：给一份交付文档做
"声明—证据"对照（templates/claims-vs-evidence 一类），统计有位置且有核对命令的事实占比；
同一批结论跑两次核对，比较带记账形状与事后回查两种做法的耗时与出错数。
