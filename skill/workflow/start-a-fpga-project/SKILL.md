# 从题目到第一版位流

## 适用场景

- 目录里只有题目文本，agent 一上来就写顶层大模块，写完发现管脚和时钟全对不上。
- 现象级信号：第一次综合报成堆的未约束时钟/未分配管脚；"能编译但下不了板"；做到一半装不下。
- 哪一步用：接手工程的第一轮，或换一个工具版本/换一块板重来一遍时。

## 使用方法

### 先查四类事实（缺哪一类，后面就在哪一类返工）

1. **器件与开发板的硬约束**：可用资源上限（查找表/触发器/片内存储块/乘法器四个维度的数量级，
   取一手数据手册的表，不要取别人的"大概"）；板载时钟源有哪几路、各自引脚号与标称频率；
   复位与配置模式（调试端口加载 / 上电易失加载 / 板载非易失存储加载）；对外接口的电气与协议文档在哪。
2. **工具链的确切版本与调用方式**：版本号、许可证形态、命令行调用写法与产物目录。
   版本不同，报告的形状与属性名都不同——先拿一个最小设计跑一遍，把报告存成"形状基线"，
   之后所有探针都对着基线写，不凭记忆写字段名。
3. **题目要演示什么、评委要看什么**：一句话写下"演示时眼睛看哪三处"。这句话决定第一版数据通路做什么。
4. **已有哪些参考设计与例程，以及它们的许可证边界**：可否修改、可否再分发、是否必须署名。

### 再跟用户确认（写法与逐字模板见 confirm-with-user-first，一次不超过三个）

- 用哪块板、跑在哪台机器上，板载时钟引脚归属（哪一路归显示、哪一路归数据通路、哪一路可复用）。
- 是否允许写入/擦除板载非易失存储，还是只允许易失加载。
- 演示目标与验收顺序（先看什么，允许牺牲什么）。
- 是否有外部设备、上位机脚本、显示端要一起接线。

### 目录骨架的最小版本

源（按子系统分目录，不按时间）、约束、台架与激励、构建脚本（一条命令产出到一个带标签的目录）、
报告与证据件的落点约定、交付文档。六块就够起步；完整形态与命名约定用 templates/project-skeleton，
一轮内怎么推进用 one-round-work-loop。

### "第一次能跑通的综合"必须包含的四件（缺一件就是假绿）

- **一个顶层**：只有端口与例化；端口就是板级接口的镜像，不预留"以后可能用"的端口。
- **一个真实时钟**：板载晶振 → 时钟原语/倍频分频 → 一条被约束住、能被报告点名的时钟网。
  不要用一个仿真里自由运行的计数器钟充当——它综合后不是你以为的那张网。
- **一条真实数据通路**：有确定位宽、有握手或使能、含一个会溢出的计数或移位链。题目没定就先做
  "能产生可观测输出"的最小通路，装饰性功能一律不进第一版。
- **管脚约束**：时钟、复位、至少一个输出可见物（指示引脚或显示接口之一）。

跑一次完整综合与实现，只看两件事：有没有未约束时钟与未分配管脚的警告；资源用量是否在预算内。

低自由度收尾（跑完应看到什么）：构建命令一条、退出码为 0、位流文件存在且字节数非 0、
报告里未分配管脚计数为 0、未约束时钟端点计数为 0。任一项读不到就判未测量，不许写"应该能过"
（判据词与空集规则见 three-state-verdicts）。

## 失效条件

- **参考设计许可证不明**：不许直接抄进仓库。权属风险之外，还会把无法核对来历的版本拖进来。
  先只读它的结构做纸面推导，拿到许可或确认题目允许后再落盘。征兆：仓库里出现来历不明的约束或头文件。
- **把教程当规格**：教程的约束常按另一块板、另一个工具版本写（时钟频率、复位极性、引脚角色）。
  照抄的结果是约束返工，而且时序看着收敛、实际测的是别人的硬件。征兆：约束里的频率与原理图上
  晶振标称值不一致，或复位极性与板卡指南相反。
- **先写顶层大模块再补约束**：端口名与时钟域归属跟约束对不上，整片重写；顶层例化一改，
  点名该时钟的约束会静默失效，覆盖面收窄却看不出收益（见 constraint-coverage-loss 那一族）。
- 工具版本换了：本条"先看两类读数"仍成立，但任何按具体属性名/字段位置写的探针会红——先重取基线。
- 题目只要行为仿真、不出位流：本条的管脚约束与位流收尾不适用，改为"顶层 + 台架 + 一条比对判据"。

## 已验证效果

未量过，属建议。依据的观察类别是：前期没查器件资源上限与板载时钟归属，导致后期几乎全部返工；
以及工具版本没锁导致同一命令的报告形状与预期不符、判读连错几次。想把它变硬的做法：
拿一个空题目做 A/B，一支按上面四类事实先查再动手、一支直接写顶层，比较两支撑有第一版位流的
墙钟时间、返工次数与约束文件的改动行数。

## 来源

长自"前期事实没补齐、后期全是返工"这一类观察的三个具体形状：资源上限没查（做到一半装不下）、
时钟归属没查（两个子系统抢同一路钟、约束点名了不存在的时钟网）、工具版本没锁（同一条命令换版本后
字段不同）。相邻条目：reset-and-clocking-plan（时钟与复位归属要先定）、constrain-io-and-clocks
（约束的建立顺序）、templates/project-skeleton（骨架完整形态）、confirm-with-user-first（先问哪几件）。
