# 改 RTL 前的六项前置检查

低自由度清单：每项给"怎么验"和"读到什么算不过"。有一条不过就不要动手——先补齐，或把这一轮的口径改小。

## 适用场景

会改到综合入口以下任何东西的动作：RTL 源、约束文件、tcl 流程、生成脚本。
尤其适用于"只是重构、不改行为"的那一刀——它最需要第①和第⑥项，因为它最容易只带一个"看起来等价"的说辞。
不适用：只读报告、只加判据而完全不动源的轮次。

## 使用方法

**动手前先查**（优先级：厂商用户指南/数据手册/接口规范 ＞ 应用笔记 ＞ 教程 ＞ 模型记忆）：
本工具的工程模式与报告命令、目标平台的资源上限页、被改模块的接口契约（端口/时序/寄存器表）在文档里的位置。
**先跟用户确认**：会改变外观、演示口径、上位机可见接口（端口名、寄存器地址、协议字段）的改动；
需要新增工具、许可或外部依赖的动作；这一轮的边界是否就是这一刀。

六项：

**① 有没有对应台架/仿真判据，且它在未改的树上先红过。**
怎么验：现在就跑一次，看退出状态与结论行末位判定词。
读到什么算不过：没有判据；判据在未改树上已经是 `PASS`（说明它测不到这一刀）；
读数读不到或解析失败（记 `NOT_MEASURED`，不许当绿）。

**② 期望值是否从当前代码逐行推出来（不是猜）。**
怎么验：动手前把期望写成表——信号/表达式/位宽/边界值/符号与饱和行为，逐格指回源码里的式子；
数值型期望必须给出算式。
算不过：指不回源码；出现"大概/应该是/一般这样"；位宽或截断没有可算的界。

**③ 这一刀是否单变量。**
怎么验：把预想的 diff 写成一句话"只把 X 改成 Y，因为 Z"。
算不过：一句话里出现"并且/顺便/同时把另一处"。混刀要么拆轮，要么**逐刀各配判据、逐刀先红后绿**，
每刀各自有一个改前红；否则这一轮只能得到一个"归因不明"的结论。

**④ 有没有构建或台架正在跑同一批源。**
怎么验：查进程是否在册、日志是否还在增长、产物 mtime 是否推进（0 字节日志不算"在跑"的证据）。
算不过：任一在飞 ⇒ 等它结束，或换**隔离拷贝树**（并注意失效条件里的工具版本一条）。

**⑤ 回滚能力。**
怎么验：确认源改动可 revert；确认**产物（位流/报告/判据读数）也在版本控制里，或能被同一条命令复现**；
确认要覆盖的文件当前没有未提交的本地改动。
算不过：产物不在库里又不可复现 ⇒ "能回到某轮"只是空话；判据依赖的件已被同名覆盖。

**⑥ 这一刀会不会让已有的约束/检查射程静默变窄。**
怎么验：把所有"按名字点人"的地方列成清单——约束里的端口名/网表名/时钟名/实例名、
台架的层次路径与信号名、脚本里的过滤正则、报告提取的字段名、上位机侧的寄存器名——逐个对照新名字。
算不过：改了端口名、层次名、时钟名而清单上任何一处没同步。
最坏征兆是"检查器输出 0 条记录却被打成通过"：改名后过滤命中空集 ⇒ 全线空转 ⇒ 假绿。

过完六项再动手；改完按一轮节拍走"量—差分—落件—改口—提交"（见 `one-round-work-loop`，
它是节拍而非本条的前置依赖）。

## 失效条件

- **拷贝树与主树工具版本不同 ⇒ 结论不可迁移**：版本、补丁、器件支持包、约束语法任一不同，
  时序与资源读数就不是同一口径。差分只在同版本树之间做；跨版本要显式写"口径已变，不可比"，
  并把另一侧读数按 `NOT_MEASURED` 处理。征兆：两边报告表格字段顺序或标题不一样。
- **用"逻辑等价"的说辞跳过行为对比**：声称"改成了等价写法"不代替观测。行为保持的重构要比对
  **同一激励下的输出字节流**（逐字节 diff 出哪一位、哪一拍变了），**不是比哈希**——哈希相同只证明
  你比的是同一份文件，哈希不同也可能只是格式化差异。没有激励可跑时，明写"未做行为对比"，
  不许写"行为保持"。
- **①的先红本身可能红错了地方**：判据没配变异对照时，改前红可能来自期望错而不是 DUT。
  先复核②，再决定这一刀的判据是否可信。
- **⑥只覆盖按名点人的检查**：同一刀把数值阈值或容差顺手放宽，不算改名但同样让射程变窄，必须单列。

## 已验证效果

未量过，属建议（本条是前置清单，没做过带/不带这条的 A/B）。
可复跑的三个自查读数：未改树上判据的比较次数（`判 N 项`，N 应大于 0 且含至少一次改前红）、
产物在库文件数（应覆盖本轮全部点名件）、按名点名清单的命中数与改名后重新命中的差值（应为 0）。
