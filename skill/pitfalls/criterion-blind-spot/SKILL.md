---
name: criterion-blind-spot
description: 管"绿得没牙"这一类：当一条**新写的**判据第一跑就绿而它要判的缺陷真实存在（人眼已看见或别处已量到）、当你选的档位上缺陷显形所需的背景/对比度/余量结构上不存在（被检对象铺满整个域 ⇒ "每行至多一段非黑"在这里是恒真式）、当扫描矩阵按"方便的档位"取而不照现象原话的"当…时"取、当差分判据只有单边或正对照落在本来就不该动的格子上、当循环上界与例外分支用的是被截断的字面量或被测信号自己时用它。核心裁决是把输入 force 成缺陷态判据必须红、撤掉必须绿；缺任一半就换激励维度，**别换阈值**。
---

## 1. 一句话用途

先问这条判据能不能红。

## 2. 适用场景

- 当一条**新写的**判据第一跑就绿，而它要判的缺陷是真实存在的（人眼已经看见、或别处已经量到）。
- 当你选的档位上，缺陷显形需要的那个"背景/对比度/余量"结构上不存在：被检对象铺满整个域 ⇒ 一句"每行至多一段非黑"在这里是恒真式，可它看起来像一条通过了几何检验的硬判据。
- 当扫描矩阵是按"方便的档位"取的，而不是照现象原话里的"当…时"取的；或诊断图案只有一种尺寸/频率。
- 当差分判据只有单边（只问"要随圈内邻居变"，不问"不许随圈外回绕源变"），或正对照落在一个本来就不该动的格子上（平场里梯度类算子恒输出 0、探针幅度大到饱和 ⇒ 对照永远不动或两档同一个数）。
- 当循环上界、例外分支、跳过条件用的是**被截断的字面量**或**被测信号自己** ⇒ 一整轮判据可以一次都没跑，屏幕照样打满 PASS。
- 当**判据自己的标识**被容器截断：名字参数只有 100 字节而中文按 UTF-8 是 3 字节/字 ⇒ 超长部分从**左边**被削掉，那条判据在日志里的编号根本不是 `T8e`，"六条只数到五条"看起来像没跑到那一支（#162：新写判据一律 ASCII，并数一遍条数）。
- 当那句"绿"建立在读回来的数据上，而数据可能是 X、空集、一份被两次运行交替写的日志、或一个初态本来就脏的 `初态 == 末态`。
- 当"不许出现"那一类反例判据比较的是**正则的源串**（带着转义反斜杠），于是它找的是固件永远不会打的字面 ⇒ 几条反例一起空跑，"命令收了却不写寄存器"这类红结构上抓不到（#165：修活之后**当场**又抓到一条反例本身写错，因为固件的正确回声里就含那个串 —— 反例要钉到违例的**那一行**，不是钉到一个词）。

## 3. 不适用 / 失效条件

- 不适用：判据红且能指出具体一格——那是真账，走"先量后修"；红了而硬件其实对是镜像面，在旧编号 S20（`skill/references/bench-self-inflicted-reds/SKILL.md`）。
- 不适用：纯组合逻辑的等价性检查——那里没有"激励维度"这件事。
- 不适用：覆盖率已由独立机制证明充分（没有这种机制时，别拿本页当免检）。
- 不适用：判据要判的本来就是恒真式（例如拿时序台架去验一个纯组合译码）——要换的是**判据类型**（改成逐格反解），加维度不会让它变红。
- 失效：覆盖地板被拿掉 ⇒ 本页全部作废（空集上的绿；同一形状在门禁侧的前科见 `skill/pitfalls/cdc-pair-baseline-gate/SKILL.md`，旧编号 S16）。
- 失效边界：本页管"能不能红"，不管"有没有病"——结果为"补维之后仍不复现"不让这条失效，尺子的职责是前者。
- 失效：激励与被检对象同源时，加维度只会让两段一起错（背景本身由被测逻辑算错）⇒ 必须另找一条**独立参照**的尺子，两把一起念。
- 边界："引用凭据要说清是哪一份"不在本页管辖——新判据的数在刷新冻结件之前只有实时日志可查，拿旧冻结件冒充新判据是另一条纪律的事。

## 4. 前置条件

- 一个能**逐格 force 内部信号**的仿真环境（本包在 Vivado/Vitis 2025.2.1 下写成，版本真相源见 `skill/_meta/naming-and-format.md`）。
- 台架里每条判据有一行自己的现场打印（只打印一次的那种），并且条数能被日志数出来。
- 一个"被量到的样本数"的可打印计数器（覆盖地板要用），以及每条地板的**期望下限**（本仓那条是"有画面的行数 > 200"，示例取值，需按自身工程重定）。
- 一份现象原话（用户或眼睛的那句"只要…就在"），因为扫描矩阵的维度要从它推，而不是从"方便"推。
- 差分判据要能同时接"圈内邻居"与"圈外回绕源"两个激励；只接一个的台架先补线再谈判据。
- 不需要连板子；但"补维之后仍不复现"那一格的结论必须靠真实片源/物理层字流/面板采样，那一步本条只负责把结论搬过去，不替你跑。

## 5. 使用方法

1. 写判据之前做"空位"检查（五分钟）：把缺陷的完整表现写成一个**可观察谓词**，再问"这一格的激励里，使该谓词可观察的那个背景/对比度/余量存在吗？"形状类判据就一句：被检对象与它应当区别于的东西，是否真的在同一个像素域里被分开？
   完成后应看到：一句"这一格有没有让缺陷站身的地方"，而不是一个阈值。
2. **反例自造**（最便宜、最有牙）：把被测对象的一个输入强行钉成"缺陷态"（force 一个内部寄存器、置一个控制位、盖一个黑块），看判据**能不能红**。
   完成后应看到：力一给就红、力一撤就绿。不能红 = 这一格没给缺陷留地方 ⇒ **换激励维度，别换阈值**。这与"新判据必须既能红又能绿"是同一句话的两半，"能红"那一半经常被跳过。
3. 先问新判据**跑了几次**：给它配一条只打印一次的现场行。
   完成后应看到：日志里那几行按期望条数出现；没有那几行就是"没跑"，而不是"跑了且绿"。顺手检查循环边界字面量的容器位宽（装不下的上界会被截成 0，条件恒假；标签容器装不下会从左边削掉名字，见 #162）。
4. 差分必须**成对**：`要随圈内邻居变`（抓旁路）+ `不随圈外回绕源变`（抓回绕）。
   完成后应看到：两行独立的判定。只写前一半天生对"取或"型结构恒绿（回绕进来的那格与中心同值，夹不夹都一样）。
5. 对照格定义成"在这一维上**唯一**会被这个改动影响的那一格"，写判据之前先算它会不会动。
   完成后应看到：一个"这格必须变"的期望；背景亮度与探针幅度都不许选到"所有必须变的对照一起哑"的那一档。
6. 按现象的**自变量**给扫描矩阵补维（代价最大，所以最后做）：那句"只要…就在"本身就是维度声明，扫描集必须含那个自变量的非平凡值。
   完成后应看到：维度不只角度与倍率——激励的**栅格比例**（每两条显示行走一条源行时，窗口的中心行在成对两行里不是同一个源行）、图案频率、反压都是维度。
7. 加固"读回再比"与例外：这类判据必须配一次**同一次采集里的 X/空集检查**加一条**覆盖地板**（被量到的样本数 > 阈值；地板与被检判据同生共死，样本数为 0 时那句绿不算通过）。
   完成后应看到：地板行与判定行成对出现。采集窗口的代码要与注释对得上，**只改阈值不算修**；例外不许用被测信号当门（病灶恰好满足被跳过的条件时，这一族从此修不红），例外只能由期望式子自己推出来，那一格仍照判，跳过数只是给人看的统计、不是免检口。
8. 加固凭据与不变量：凡"一个名字、一份文件、多次写"的凭据都要问"还有谁往这里写"——按校验和认源认的是"哪一份源码跑的"，钉不住"这一份文件是不是只有一跑写过"；见到还活着的仿真进程就退出并说清该杀谁（**不自动杀**）。
   完成后应看到：`初态 == 末态` 型判据同时钉住"初态是已知的默认态"（跑之前先显式复位再读一次），否则它只在起点干净的那一次有牙，而那次往往没人看。
9. 加固被测对象的**形状**：总线从机模型里至少一处主动把 `ready` 拉低过。
   完成后应看到：反压那一维真的被走过；否则这条通路只验了**不拥塞**（反压结构上不可能红，而它报出的绿会被读成"通路已验证"）。除大色块外另备细线/棋盘/文字这类高频图案，两把尺子一起念；靠层次名成立的判据，改完结构就 grep 一次那些名字还在不在原位。
10. 措辞分清"病"与"定义"。
   完成后应看到：钉在病灶上的措辞在修好之后会红（这是好事，但要有心理准备）；提前换成"定义 + 覆盖地板"，别到时候凭"红了就回退"的规矩把修复本身退掉。

## 6. 判读与失败分叉

- 步骤 2 是可执行的**裁决**，其余步骤都向它交代：输入 force 成缺陷态 ⇒ 判据必须红，撤掉 ⇒ 必须绿；两个方向缺一个 ⇒ 这一格判作废、去换维度而不是换阈值。
- 步骤 1/6：通过 = 每一格都能说出"缺陷在这里有没有地方站"。失败 = 某档全绿而说不出背景/余量是否存在 ⇒ 该档的绿不算证据，补维或撤下该档的结论。读不到输入 = 现象原话没登记 ⇒ `NOT_MEASURED`，维度无从推起，先把那句"当…时"写下来。
- 步骤 3：通过 = 现场行按期望条数出现（条数对得上）。失败 = 条数少于一格 ⇒ 先怀疑容器截断（本仓 #162 的形状：名字参数 100 字节，中文 3 字节/字，从左边削 ⇒ 一整条判据在日志里没有可 grep 的编号）。读不到输入 = 日志里一条判定行都没有 ⇒ `NOT_MEASURED`，等价于"这一轮没判"，不许念成绿。
- 步骤 4：通过 = 两半各判一次且都能红。失败 = 只写了单边 ⇒ 该判据对"取或"型结构恒绿，判作废。读不到输入 = 第二激励接不进去（台架没有那个源）⇒ `NOT_MEASURED`，先补线。
- 步骤 5：通过 = 对照格在该维上确实动了。失败 = 对照永远不动 ⇒ 要么档位选哑（背景/幅度），要么正对照选错格子；这属于"平场里梯度算子恒 0"那一类，不是设计的问题。
- 步骤 7：通过 = 地板 > 阈值且 X/空集检查在同一次采集里做过。失败 = 样本数不达标的绿 ⇒ 判 `FAIL`，把地板调低更不算通过。读不到输入 = 拿不到样本数 ⇒ `NOT_MEASURED`，先给尺子加一行射程打印。
- 步骤 8：通过 = 没有别的写者、且初态是被显式复位后的已知值。失败 = 日志被两跑交替写、或 `初态 == 末态` 在脏起点上成立 ⇒ 该结论作废（同族见 `skill/pitfalls/who-else-writes-this-artifact/SKILL.md`）。
- 步骤 9：通过 = `ready` 至少被拉低过一次、高频图案那一把尺子也念过。失败 = 只有大色块 ⇒ "通路已验证"这句话不许写。
- "位置能不能分辨"这一类的正证（用来证明尺子不是恒输出、也不是恒绿）：不旋转那一格量到的首/末列区间要**正好等于几何应给的那一条带**，非单位倍率那几格量到的**画面带宽度**要等于"有效宽 × 倍率、按中心取整"，两侧留出可对证的背景。

## 7. 已验证的效果

以下全部是历史轮次的台账读数（`report/log/ISSUES.md` 的 #93、#97、#34、#35、#162、#163、#164、#165、#166 各节）。本轮（技能包重构轮）**没有跑任何台架、没有跑门禁、没有上板** ⇒ "现在重跑仍得同一组数"一律记 `【待验证】`。

- 形状尺子在全域铺满的那几档**全绿**、补维之后才承认结构上不可能红（#93）。补维后的十二格读数：`12 × PASS C4a` + `12 × PASS C4b`，多段行计数 `C4RUN` **一条都没打出来**（那正是它设计出来抓多段行的用法）；地板 `C4a`（这一格被量到的"有画面行"> 200）**先于** `C4b`（每一行至多一段非黑）判。
- 同一批读数证明这把尺子**会分辨位置**：inv 512 那格量到 `256..767`（512 列）、inv 1023 量到 `384..641`（258 列 = 半宽 512·256/1023 = 128.1 按中心取整的 128 + 129 + 1）；90° 三格 `212..811`(600)、`362..661`(300)、`438..587`(150) 是同一组数换了方向。⇒ "偏了几列"这类错它抓得住，所以下面的"没抓到"才有分量。
- 补维的回报能念出来（#93 的结论）：0.50x/0.25x 两排里背景带 `[0..255]`、`[0..383]` **一个非黑像素都没有** ⇒ 那句"只要缩放到非 100% 就在"在顶层台架这一版不成立；病灶从"台架没覆盖"移到"台架里没有的东西"（真实片源 / PHY 实际收到的字流 / 面板采样）——那是一个**下一步该去哪里**的结论，比一条绿值钱。
- 同族两例（2026-09-30，r94）：**收尾解析只认两种判定形状**，`TB RESULT PASS|FAIL` 那一族被报成 "NO-VERDICT + FAIL 行数=0" ⇒ 红与"没数"在输出里长得一模一样（#163，配 `build/r94_verdict_ce.sh` 三条对照，第一版候选还被自己的"不许把没数当 PASS"那条打回）；**门禁在两份报告缺席时把空结果当合法的 0**，于是"20 项全判定"的绿依赖文件存在而从没人查过文件存在（#164），`run_one.sh` 判红仍 exit 0 让调用方的保护永不触发（#166）。
- #164 的两跑对照（改前/改后同一目录）：改前那两项照旧打 `PASS`；改后打的是两行 `n/a … 这一项没门禁（空集合不是通过）`，收尾因 NNA≠0 变成 PARTIAL，而默认目录（两份报告都在）仍按数判、判定项数不变（20 项）、**阈值一个都没动**——动的只是"没数据时不许冒充有数据"。
- #165 的代价：8 条"不许出现"的判据因为比的是正则源串而**永久空跑**；修活之后当场抓出的第一条是反例本身写错（固件正确的回声里就含那个串 ⇒ 一条永红），处置是把反例钉到真正的违例行上、保留判据意图、改对维度。
- 更早的两条同族前科（#34、#35）：测量工具自己会造假（恒定图案看不见逐帧丢字、边推流边回读让每个地址段读到不同时刻的帧）；xsim 从机模型把 DUT 伪装成死锁（从机在 W 到达时用上一拍的 AW 地址、只有 1 个 B 寄存器、用组合 ready 做握手 ⇒ 数据错位 + 序号回绕 + 永久不排空）——两条都是"绿/红由尺子的形状决定"。
- `【未实测】`：本条目没有对"当前树"重跑任何一条判据；本条目也没有统计过"包里有多少判据缺地板"。
