description: 给"加一个开关/使能位"类功能（OSD 叠层、插值、调试输出、通道选择）交付两级证据：模块级要求关掉时输出逐位等于背景（背景不许取全黑），顶层级要求在引脚或最终产物上量一个只有这条链能产生的特征；用它防"端口加了但台架/顶层没接"的假绿、防"两个翻转位挂同一级扇出被 CDC 判据打回"、防"开关被做进数据通路多一级延迟"。
---

## 1. 一句话用途

开关要有两级证据：模块内与顶层接线。

## 2. 适用场景

- 当需求形如"给 X 加个开关/使能位"时：OSD 叠层、插值、调试输出、通道选择——改动小，但**最容易假绿**。
- 当你已经加了端口，却不确定顶层/台架是否真的接上时（本项目真发生过：端口加了但没接线，见 `report/log/ISSUES.md` #88）。
- 当一个控制位要跨时钟域、而你想把两个翻转位挂到同一级同步链上时（#65 的教训：会被 CDC 判据打回）。
- 当你打算"顺手加一级寄存器把使能打拍"时（那会把顶层所有延迟账牵进来，见第 3 节）。
- 当帮助文本/回显字段/文档命令表要跟着这个开关一起改版时。

## 3. 不适用 / 失效条件

- 不适用：纯组合的调试信号（只影响一个 LED）——没有接线可达性与延迟账要证。
- 失效：若开关被做进数据通路（多一级 mux / 一拍延迟），所有延迟对齐判据都会红——那不是开关，是改版；
  本条第 1 步存在的意义就是避开它。
- 失效：顶层判据若采样点在被控层**上游**，它对开关全盲 ⇒ 必须先确认采样点在下游。
- 不适用（证据等级不够）：只有模块级证据时，本条明确判"未证"——模块内逐位等价说明不了接线通。
- 边界：正对照缺席的判据不算判据（开着必须真有东西），否则"关掉 = 0"与"这层本来就没在画"是同一个读数。

## 4. 前置条件

- 一支能逐格扫描输出像素的**模块级**台架，并且背景激励可给成非全黑。
- 一支在**引脚/最终产物**上量特征的**顶层级**台架（或上板读数点），其采样点在被控层下游。
- 门禁里的 CDC 那一项可跑（本仓形式，只读核对判据文本即可，不需要为此重跑构建）。
- 固件产物（ELF/镜像）可 grep 字符串，用来证"不是链接失败的旧件"。
- 一份"这个开关牵动的延迟账"清单（本仓形式：混合深度、总延迟、行环这几处，示例取值，需按自身工程替换）。
- 本条目在 Vivado/Vitis 2025.2.1（build 6403652）下写成（版本真相源见 `skill/_meta/naming-and-format.md`）。

## 5. 使用方法

1. **不要新加一级寄存器**。把开关做成"已有的那个选择多一个输入"——本仓 `osd_en` 就并进
   `if (pixel_on)`，于是开/关的内容延迟逐拍相同，顶层所有延迟账（`MIX_D` / `LATENCY` / 行环）都不用动。
   完成后应看到：延迟相关的判据一条都没被牵动（它们应当仍绿）。
2. 跨域的准静态控制位**每一位一条独立同步链**（#65：两个翻转位挂同一级扇出会被 CDC 判据打回）。
   复位值选"与旧行为一致"的那一极（本仓 `osd_off` 复位 0 = 仍显示），这样"忘了初始化"不会改变观感。
   完成后应看到：CDC 那一项对新位给出独立链的记录，且上电默认观感与改前一致。
3. 立**模块级**判据：关掉 ⇒ 输出**逐位等于**背景/直通。背景**不许取全黑**
   （否则"等于背景"与"被清成 0"是同一个数，判据没有牙）。
   完成后应看到：同一份扫描里两个数——开着时"与背景不同的格数 > 0"（正对照），
   关掉时"那一数 = 0"，并且扫过的格子集合完全相同、样本数有地板。
4. 立**顶层级**判据：在**引脚/最终产物**上量一个只有这条链能产生的特征
   （本仓数 rose 字形格数：开着 > 1000、关掉 = 0）。
   完成后应看到：一个只有接线真的通才可能满足的读数（它判的是"接线真的通"）。
5. 帮助文本、回显字段、文档命令表**同一版改完**，并删掉那条已经走不到的"待接"提示。
   完成后应看到：产物里查得到新字符串，且文档里不再有过期提示。

## 6. 判读与失败分叉

- 步骤 1：
  通过 = 延迟类判据全部照旧。
  失败 = 有延迟对齐判据变红 ⇒ 开关被做进了数据通路（多一级 mux / 一拍），按第 3 节判 `FAIL` 并回到步骤 1 重写。
- 步骤 2：
  失败 = CDC 项打回 ⇒ 两个翻转位共用了链，拆成每位一条，不要靠放宽判据解决。
  读不到输入 = 看不出复位选的是哪一极 ⇒ `NOT_MEASURED`，先读复位分支代码再决定"与旧行为一致"是哪一极。
- 步骤 3（模块级）：
  通过 = 关掉逐位等于背景 **且** 开着与背景不同。
  失败 = 关掉时报的差异格 > 0 ⇒ 这层没真的消失；
  失败 = 背景用了全黑 ⇒ 判据恒真风险，判 `FAIL`，先把背景改成非全黑再念结论。
  读不到输入 = 扫到的格子数为 0 或少于地板 ⇒ `NOT_MEASURED`（样本不足时"= 0"没有意义）。
- 步骤 4（顶层级）：
  通过 = 那个"只有这条链能产生"的特征在开着时越线、关掉时归零。
  失败 = 开着也量不到 ⇒ 优先怀疑**接线没通**或采样点在上游（第 3 节），而不是先怀疑功能写错。
  读不到输入 = 顶层产物/引脚读数拿不到 ⇒ `NOT_MEASURED`，此时本条只成立一半，不许念"两级都过"。
- 步骤 5：
  失败 = 固件产物里查不到新字符串 ⇒ 那是链接失败的旧件，判 `FAIL`，先确认产物是这一版生成的。
- 两级的合取口径：两级判据都带**正对照**（开着必须有东西）才算完成；只有一级绿 = 未证。

## 7. 已验证的效果

- 本轮实跑（2026-10-04，**只读**打开两支台架核对判据形状，未起仿真）：
  1. 模块级：`sim/tb_osd_lines.v` 里这条判据现在挂 **T16**，期望是"en=1 与背景不同格 > 0"、
     "en=0 差异格 = 0"、"扫过格 > 5000"三件事在同一次扫描里成对量，且背景喂的是非全黑的
     `8'h12/8'h34/8'h56`（注释写明理由：全黑时"等于背景"与"被清成 0"是同一个数）；
  2. 顶层级：`sim/tb_v98_top_seam.v` 的 C12 拆成 `C12pre`（正对照：rose 格 ON > 1000 且扫过像素 > 200000）
     与 `C12a`（关掉 ⇒ rose 格必须 = 0），采样取的是叠层模块输出上的字形色；
  3. **标签勘正**：旧卡写的 `sim/tb_osd_lines.v` T13 是改号前的标签——该台架头注记录 2026-09-29 因为与
     "行宽"那条撞号才换号为 T16（源码里的局部变量名仍是 `t13_on` / `t13_off` 的旧写法），
     引用这条判据时按 T16 念，别按 T13 念。
- 本轮**没有**跑的：两支台架都要求起仿真（本轮禁止）⇒ "T16 与 C12/C12pre/C12a 现在同绿"记 `【待验证】`。
- 基线（更早轮次的历史事实，本轮未重演）：OSD 总开关的落地记在 `report/log/ISSUES.md` #112；
  "两个翻转位挂同一级扇出被打回"是 #65；"端口加了但顶层/台架没接"是 #88——三件事都出自台账，
  本轮只读核到台架里对应的判据确实存在，没有重跑上板与仿真。

## 8. 提炼来源与边界

- 来源证据：`report/log/ISSUES.md` #112（OSD 总开关）；`sim/tb_osd_lines.v` T13 与 `sim/tb_v98_top_seam.v` C12
  （两条标签的现状见第 7 节的勘正）；#65（每位一条独立同步链）、#88（接线不可达的真实事故）。
  旧卡编号 S26，本包对外仍按号引用。
- 不再适用的条件：你的工程有自动的"端口 → 顶层连线"可达性检查（例如拿综合日志当可达性 oracle），
  那时顶层级判据可以降级为抽查，但"背景不许取全黑"仍然成立。
- 迁移到新题目/新板卡要改的地方：
  1. "只有这条链能产生的特征"具体是什么（本仓是 rose 字形格数 > 1000 / = 0，示例取值，需按自身工程替换）；
  2. 模块级背景的取值（必须非全黑、且与叠层内容不同色）；
  3. 样本地板的数值（本仓 5000 格 / 200000 像素）；
  4. 复位极性的选择（哪一极等于"与旧行为一致"）；
  5. 顶层判据的采样点位置（必须在被控层下游）。
- 平台相关：与器件家族无关；与"能不能在最终产物上量到那一个特征"有关——
  没有可观测的最终产物（例如无可读回 framebuffer）时，顶层级只剩上板肉眼，证据等级要相应降级。
