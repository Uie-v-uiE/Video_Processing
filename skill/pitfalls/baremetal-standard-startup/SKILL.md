name: baremetal-standard-startup
description: 认出"手工链接的裸机 ARM 镜像里根本没有标准启动"这一类失效。当镜像由手调交叉 gcc + 现成 BSP 静态库产出、改动只是链接脚本里的 `ENTRY(...)` 换了个符号，症状却分散成第一条浮点指令陷 Undefined Instruction、板子像自己重启了一遍、`memcpy` 报对齐异常、复位一次就好、只在 MMU 关着时才出事，或 0x0 处读不到 `b _boot` 与两条异常入口向量时使用；也用于把"入口"这条容易静默失效的账变成等值判据。
---

## 1. 一句话用途

改入口符号 = 改整条标准启动链。

## 2. 适用场景

- 当你**不用 IDE** 产出裸机镜像（手调交叉 gcc + 现成 BSP 静态库，因为交付要求"从零可复现"，而"在 IDE 里点新建工程"不是可复现步骤）。
- 当你改链接脚本里的 `ENTRY(...)` 符号 —— 哪怕只是"修一个 bug"的一行改名。
- 当链接脚本里出现过向量表段、boot 段、页表段、各模式栈符号这一类名字：它们**预期**有人把标准启动那几个 `.S` 链进来；没在镜像里就是缺件。
- 当症状彼此"互不相干"：第一条浮点指令陷 Undefined、板子"像自己重启了一遍"、`memcpy` 报对齐异常、复位一次就好、只在 MMU 关着时才出事。
- 当你准备在 0x0 摆自己的代码，或只补一条"设 CPACR"的土桩。

## 3. 不适用 / 失效条件

- 正常经 bootROM/FSBL 起、且不要求"纯 JTAG 就能跑"的固件（那份标准启动由 FSBL 带着）。
- 平台库不是 SDT 流程生成的、`USE_AMP` 多核、或应用跑在 DDR 里 —— 那几个 `.S` 的前提会变（逐条见下面后三条）。
- 软核或非 Cortex-A：向量表 / CPACR / VBAR 这套是 ARM 的。
- 失效：启动那几个 `.S` 依赖平台库的配置头（`-DSDT` 与内存配置文件）—— 老流程或改了编译开关 ⇒ 恒等映射与 errata 分支会不一致。
- 失效：多核 / `USE_AMP` —— 启动代码按 CPU 亲和号决定谁往下跑，还会在单核 efuse 上复位另一核，不能照抄。
- 失效：想让应用跑在 DDR 里 —— 页表的 DDR 段属性来自 xparameters 里的地址与容量，与实机不符时开 MMU 后第一笔访存就炸，表现成"一个字节都没打出来"，比缺启动更难查。本仓库跑在 OCM ⇒ 这条路旧卡就写着**未验证**，本包同样记 `【待验证】`（缺一次 DDR 常驻的实跑件）。
- 分界：本条只管"镜像里有没有整条标准启动"；"下位流后 PS 必须重起""重下才恢复"属板级连线与驱动状态那一类账（本包 runtime 类 `board-eth-uart` 条目）。

## 4. 前置条件

- 工具与版本：本包写作环境是 Vivado/Vitis 2025.2.1 + Zynq-7020（本仓示例取值，需按自身工程替换）；本条判据本身只要求 ARM Cortex-A 裸机 + 手调交叉工具链，与 Vivado 版本无关。
- 需要的输入：一份已链接的镜像（本仓称 `app.elf`，示例取值）、链接脚本本体、BSP 静态库，以及标准启动那几个 `.S`（异常向量、启动、页表各一份）。
- 需要的工具：`arm-none-eabi-nm`、`arm-none-eabi-readelf`、`arm-none-eabi-objdump` 三件，能只读检查最终 ELF。
- 符号名账：`_boot`、`_vector_table`、`MMUTable`、`_start`、`IRQHandler` 是本仓 BSP 的符号名（示例取值，需按自身 BSP 的同名角色替换）；换名字时下面第 5.1 步的 grep 词表要一起换。
- 需要的权限或硬件连接状态：第 5.1–5.5 步全部离线（只看 ELF 与脚本），不需要板子；只有"板级签名归零"那一条要串口/JTAG 能读到横幅。

## 5. 使用方法

### 5.1 先查镜像里有没有标准启动（三条命令就够）

通用形态：符号表 + ELF 头 + 反汇编头 0x20 字节；本仓库把它们写进构建脚本的自检里。

```bash
arm-none-eabi-nm -n app.elf | grep -E "_boot|_vector_table|MMUTable|_start|IRQHandler"
arm-none-eabi-readelf -h app.elf | grep Entry        # 入口必须等于 _boot
arm-none-eabi-objdump -d --start-address=0 --stop-address=0x20 app.elf
#   0x0 处必须是 b _boot；0x4 / 0x10 必须是 Undefined / DataAbort 的入口
```

完成后应看到：符号表里那几个名字都在；`Entry point address:` 一行给出的地址等于 `_boot` 的地址；反汇编 0x0 是 `b _boot`，0x4 与 0x10 落在两个异常入口上。

### 5.2 缺件就显式把那几个 `.S` 编进来

异常向量、启动、页表各一份，编译开关与 BSP 自己一致（例如 `-DSDT`）。`-Wl,-u` 或 `KEEP` 不算"请回来"，**让它们成为入口的下游最干净**。

完成后应看到：5.1 的三条命令全部转绿，且不需要为向量段单独加 `KEEP`。

### 5.3 把入口写回链接脚本，不要用命令行 `-e`

`ENTRY(_boot)` 写在脚本里。脚本里的 `ENTRY()` 会顶掉命令行 `-e`，ELF 入口悄悄变成 0x0、一声不响。链接器的"入口"有两个来源且覆盖不报错 —— 这是本条要记的第一课。

完成后应看到：`readelf -h` 的入口地址非 0，且与脚本里 `ENTRY()` 指的符号同址。

### 5.4 加两道等值哨兵，而不是存在性哨兵

1. ELF 入口地址 == `_boot` 的地址；
2. 向量表符号必须在 0x0（复位后 VBAR 就是 0，表放别处等于没有表）。

完成后应看到：两条各打一行等式与左右值；等值不成立即判红。

### 5.5 别在 0x0–0x1C 摆自己的代码

`V=0` 时那正是异常向量区，于是每一次异常都变成一次"看起来很干净的重启"。

完成后应看到：链接映射里 0x0–0x1C 只住向量表。

### 5.6 顺手核 MMU 与对齐这条链

MMU 关着时非对齐访问一定 fault（对齐豁免只在 MMU 开着时成立）；标准启动回来后由 BSP 的恒等映射打开 MMU，外设/PL 寄存器区间设成 device/uncached ⇒ 寄存器读写不会被缓存绕过。选择不链标准启动，就得自己承担 `-mno-unaligned-access` 与预编译库里 `memcpy` 半字快路径这一类雷。

完成后应看到：要么链上了标准启动并由 BSP 开 MMU（外设段 device/uncached），要么显式带上 `-mno-unaligned-access` 并确认预编译库路径。

### 5.7 崩溃现场要可读，但别宣称"handler 会打印"

别把异常初始化当成"异常已接管"：裸机库的默认 handler 只在库开了 DEBUG 时才打印；崩溃后可读的现场是几个 abort/undefined 地址全局 + pc/cpsr（例：本仓库 `board/pswhy.tcl` 就采这些）。想有打印就得自己注册 handler。

完成后应看到：一份采集件里能读到 abort/undefined 地址全局与 pc/cpsr；文档里没有"handler 会自动打印"这类说法。

## 6. 判读与失败分叉

| 检查 | 通过 | 失败 | 读不到输入 |
| --- | --- | --- | --- |
| 5.1 三条命令 | 进 5.2 之前的绿灯状态；若本来就齐，只需重跑 5.4 哨兵 | 符号表里缺 `_boot`/`_vector_table`/`MMUTable` ⇒ 缺件，按 5.2 把 `.S` 链进来；入口不等于 `_boot` ⇒ 按 5.3 查两个入口来源谁在覆盖 | `nm`/`readelf` 报的不是空结果而是"文件不存在" ⇒ `NOT_MEASURED`：镜像没链接出来，先回构建侧；"grep 无输出"不等于"符号齐" |
| 5.4 等值哨兵（一次跑完三条关系） | 反汇编 0x0 处的跳转目标 == ELF 入口 == `_boot` 的地址；`_vector_table` == 0x0；0x4/0x10 落在两个 handler 上 ⇒ 绿 | 任一不满足就是红，按红的那一条分叉：入口红 ⇒ 回 5.3；表位置红 ⇒ 回 5.5/链接段布局 | 哨兵拿不到反汇编或符号地址 ⇒ `NOT_MEASURED`，不许把"读不到"记成"地址 0" |
| 反例：把入口设成自己写的入口符号再链接 | `--gc-sections` 会把没人引用的向量段整段裁掉 —— 此时"存在性"检查（符号表里有 `_boot`）**仍然绿**，等值检查必须红 | 等值检查也跟着绿 ⇒ 哨兵没牙，先修哨兵再谈结论 | 拿不到裁段后的镜像 ⇒ `NOT_MEASURED`：这一条反例必须真跑一次 |
| 哨兵自己的测试（两个已知入口：0x0 与一个非零地址） | 必须一红一绿 | 两跑同色 ⇒ 解析写错了。栽过的坑是正则 `Entry point address:\s+0*([0-9a-f]+)` 遇到 `0xcc` 会把那个 0 吃掉、捕获为空 ⇒ 永远读成 0 | 构造不出两个已知入口 ⇒ `NOT_MEASURED`，本条判据未成立 |
| 板级签名归零 | 发一条命令回来的是**一条命令的应答** ⇒ 启动链在位 | 回来的是**整条启动横幅** ⇒ 就是"异常跑到 0x0"的现场，不要再去怀疑"板子自己复位了" | 串口零字节 ⇒ 先按 runtime 类 `pl-load-verify` 与 `board-eth-uart` 排除加载与线材，再判本条 |

以下都是**旧卡登记的历史取证**（本条为迁移物，本轮任务禁止构建与上板，一次也没重跑）：

- 一个根因四个症状：`report/log/ISSUES.md` `#44` 登记 CPACR、向量表、各模式栈、MMU **一起没**（即"缺整条标准启动"这一类，不是四个独立 bug）。⇒ 台账有件；本轮复跑后的 §5.1 输出摘要 `【待验证】`（要跑的是 5.1 那三条命令并存档）。
- 症状起点：`report/log/ISSUES.md` `#42` 登记"第一条 VFP 指令陷成 Undefined Instruction"。⇒ 同上，本轮 `【待验证】`。
- 三条已观察到的机理（旧卡正文记录，未附输出件路径）：链接器入口的两个来源互相覆盖且不报错；哨兵正则把 `0xcc` 的 0 吃掉导致永远读成 0；"异常跑到 0x0"表现为整条启动横幅重打。⇒ 各自补一份运行件之前记 `【待验证】`。
- 崩溃现场采集：本仓 `board/pswhy.tcl` 采的是 abort/undefined 地址全局 + pc/cpsr（在树件，旧卡点名）。本轮未运行（需板子）⇒ `【待验证】`。

## 8. 提炼来源与边界

- 来源证据：`report/log/ISSUES.md` `#44`（一个根因四个症状）与 `#42`（第一条 VFP 指令陷成 Undefined Instruction）；采集件 `board/pswhy.tcl`；其余机理与判据形状来自本条迁移的旧卡（扁平卡 S13，退役后该文件不再存在）。
- 恒成立 / 平台相关 / 版本相关：等值哨兵优于存在性哨兵、"脚本 `ENTRY()` 覆盖命令行 `-e` 且不报错"、"别在 0x0–0x1C 摆代码"、"MMU 关着时非对齐必 fault" —— 恒成立（ARM Cortex-A 范围内）；`_boot`/`_vector_table`/`MMUTable` 这些符号名、`-DSDT` 开关、恒等映射与外设段 device/uncached 的写法是平台与 BSP 版本相关（换流程要重核 5.2/5.6）；`board/pswhy.tcl` 采的那几个全局名是本仓私有（示例取值，需按自身工程替换）。
- 不再适用的条件：改由 FSBL/bootROM 带标准启动且不要求纯 JTAG 可跑；改用非 Cortex-A 软核；启用 `USE_AMP` 多核；应用改驻 DDR；平台库不再由 SDT 流程生成。
- 迁移到新题目/新板卡要改的几处：① BSP 那几个 `.S` 的实际文件名与 `-DSDT` 一类编译开关；② `_boot` 等等值哨兵两侧的符号名；③ 向量表基址假设（复位后 VBAR 是否为 0）；④ 异常区范围（本条写 0x0–0x1C 是 ARM 的经典 8 个 4 字节向量，别的模式/表布局要重推）；⑤ 崩溃现场采集脚本换成目标工程自己的那一份，并按 5.7 决定要不要自己注册 handler。
