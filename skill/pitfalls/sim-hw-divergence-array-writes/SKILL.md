description: 用于"仿真全绿而板上有一根钉死位置的坏线"这一类：当屏上黑线与片源内容无关、与缩放无关、只在某一条通路上出现，或当行缓存 / 查找表 / 环形缓冲的边界列行为可疑而所有台架都绿时用它。签名是 xsim 对越界数组写静默丢掉、硬件按地址位截断（`addr mod 2**clog2(depth)`），于是仿真给"没有"、硬件给"别的格子"；动作是在台架里逐槽数未写位（必须配复位态对照）并数"`de` 有效而写地址 ≥ 深度"的拍数，两条判据都要改前红、改后绿，且屏上位置要由公式预测出来并被人眼证实。
---

## 1. 一句话用途

仿真给"没有"，硬件给"别的格子"。

## 2. 适用场景

- 当屏上有一根**钉在固定位置**的黑线/坏线：与片源内容无关、与缩放无关、只在某一条通路上出现，而**所有仿真都绿**时。
- 当某个存储型结构（行缓存、查找表、环形缓冲）的边界列行为可疑时——本仓实例：九条行缓存各自都差同一格没被写过。
- 当"关掉或打开链上任何一级它都还在"时：缺陷只落在中心抽头那一格（9 个采样里占 1 个），所以开模糊也不摊成三列——这种"跨级同格"的形状是本条的强信号。
- 当你正准备把"仿真里没有"念成"硬件里也没有"时。
- 当你新写了一条"越界计数 = 0 所以通过"的判据，而说不出这份激励是否真走到过行尾时。

## 3. 不适用 / 失效条件

- 不适用：线会随内容或缩放**移动** ⇒ 先怀疑坐标与标签的同级性（"标签与内容不同级"那一族），本条只管位置钉死。
- 不适用：仿真里能复现 ⇒ 那是普通逻辑错，不需要本条（本条的存在理由恰恰是仿真看不见）。
- 失效：器件/工具链不同，未初始化 RAM 的开机值不一定是 0（BRAM 可为 0/随机，LUTRAM 由 INIT 决定）⇒ "越界那一格在硬件里是纯黑"这一步必须重新量，不许沿用。
- 失效：台架若把消隐期的地址也喂成 0（而不是让它继续数），越界根本不会发生 ⇒ 判据是空转的。激励必须复刻真实栅格：有效列之后地址继续走到 `H_TOTAL-1`。
- 失效：分层引用指不到真数组时（数组改名、被复制成多份、或在另一个实例里），计数会恒 0——所以第 1 步的复位态对照不是可选项。

## 4. 前置条件

- 一个能直接例化被测数组的台架；本仓实例 `sim/tb_v103_pipe_bypass.v`（示例取值，需按自身工程替换）：它只喂效果链、按真实 1344/1024 的栅格时序跑。
- 仿真器允许**分层引用**读内部数组（本仓写法 `^dut.<路径>.mem[i]`），且你能在"复位态（一个像素都没喂）"和"喂完一帧"各读一次。
- 真实消隐形状：`H_ACTIVE < H_TOTAL`，且写地址在消隐期继续自增（否则本条的越界前提不存在）。
- 一个能把缺陷**机械复原**的手段：本仓做法是复制整棵树到临时目录、用 sed 复原修复前的那几行、**真源一个字节没动**，diff 行数不等于预期就拒绝继续（本仓 `sim/mut_control.sh`，示例取值）。⚠ 构建在飞时改源 = 静默重新综合，所以变异必须离开真源。
- 只读文本 + 仿真即可跑本条前 5 步；第 6 步（位置证实）要板子与串口，本条目不替你跑。

## 5. 使用方法

按这三问排，**别跳步**：

1. **这个数组的所有槽位都被写过吗？** 台架里逐槽查 X：`if (^dut.u_x.mem[i] === 1'bx) 计数`。
   完成后应看到：一个"未写槽数"。必须同时给**复位时的对照**（一个像素都没喂时它应数到全部槽）——否则那个 0 只是分层引用没指到真数组。
2. **有没有越界的写？** 数"`de` 有效而写地址 ≥ 深度"的拍数，按级分开数。
   完成后应看到：每级一个计数；任何一级非 0 就是本条的病，全 0 则先看第 4 步的地板再说"没有"。
3. **越界那一拍喂进去的是什么值？** 用 `addr mod 2**clog2(depth)` 算硬件里的真实落点，并记下那一拍的数据（消隐期数据通常是 0 ⇒ 硬件里就是纯黑；仿真里那个格子是 X 或旧值）。
   完成后应看到：一个**可以被打脸的预测列号**——这一步决定"为什么仿真看不见"，也给出屏幕上的位置。
4. **补取样地板**：数"激励确实走到行尾"的拍数（本仓形状 `de_in && x_in >= H_ACTIVE-1` 必须 > 0）。
   完成后应看到：地板行与计数行同屏出现，"计数 = 0"不再能被解释成"没走到那一列"。
5. **变异对照**：把被测对象复原成缺陷态重跑 ⇒ ①槽位完整性判据、②越界写计数判据**都必须红**；改回来都必须绿。
   完成后应看到：红的读数正落在第 3 步预测的那一格上。**判据有力的证据不是"它红了"，而是"它红在预测的位置上"。**
6. **上板证实位置**：摆一个已知位置的分割标记，让人眼念回相对位置（本仓实例：预测 `1343 mod 1024 = 319` ⇒ 读回应出现在显示列 320；标记摆在 317 ⇒ 念回"紧贴蓝线右侧"）。
   完成后应看到：预测被证实或被推翻——**预测能被打脸的判据才算有牙**。

## 6. 判读与失败分叉

- 第 1 步：通过 = 复位态数到"全部槽"，喂完一帧后未写槽数 = 0。
  失败 = 复位态也只数到很少几个 ⇒ 分层引用没指到真数组，判 `FAIL`（尺子坏），先修引用再谈结论。
  读不到输入 = 台架里没有那个数组名（改过名/换了实例层级）⇒ `NOT_MEASURED`，回第 1 步重新定位层次路径，不许改成"读不到就跳过"。
- 第 2 步：通过 = 各级越界计数 = 0 **且**第 4 步地板 > 0。
  失败 = 任一级 > 0 ⇒ 本条成立，记下第一 offender 的地址与数据值，进第 3 步。
  读不到输入 = 计数器一条都没打 ⇒ `NOT_MEASURED`，等于判据没跑，别念成绿。
- 第 3 步：通过 = 算出的落点列与屏上/人眼念回的位置一致。
  失败 = 位置对不上 ⇒ 你数的不是同一条通路（可能有第二处越界写或另有对齐补偿），回到"这条通路是谁写的"。
  读不到输入 = 没拿到消隐期的数据值 ⇒ `NOT_MEASURED`，"硬件里是纯黑"这一步就没有依据。
- 第 4 步：通过 = 地板 > 0。
  失败 = 地板 = 0 ⇒ 激励根本没走到行尾，第 2 步的 0 是空转，判 `FAIL` 并改激励（把地址在消隐期继续放）。
  地板 = 1 这种"过了但只发生过一次"的读数要单独记，不算好消息。
- 第 5 步：通过 = 缺陷态两条都红、修复态两条都绿，且红在预测那一格。
  失败 = 复原成缺陷态仍不红 ⇒ 这一格没给缺陷留地方，判据作废，换激励维度（**别换阈值**）。
  读不到输入 = 变异脚本拒绝执行（diff 行数不对）⇒ `NOT_MEASURED`，先确认复原的到底是哪几行。
- 第 6 步：通过 = 人眼念回的位置与预测一致 ⇒ 本条收口。
  失败 = 线还在/位置不同 ⇒ 根因认领不完整，回第 2 步把"每一级"的计数重新逐条对齐。
  读不到输入 = 没上板（只有机器侧证据）⇒ `NOT_MEASURED`：这类"只存在于仿真与硬件差别里"的事**必须过眼睛**，机器侧全绿不等于已证。

## 7. 已验证的效果

以下都是**历史轮次的台账读数**（本仓 `report/log/ISSUES.md` #103 那一节），本轮（技能包重构轮）**没有重跑台架、没有构建、没有上板**，所以下面不写成"本机实跑"。

- 缺陷态（修复前）的台架读数：`CACHE after A: total=1 first=1023 last=1023`，并按级给出 `blur / sharp / sobel / morph` 的 lb/mc 计数——**九条行缓存各自都差同一格（1023）没被写过**；同一次抓到的 burst 内容里那一格是干净的 `0000`（不是 X）。⇒ 这一条就是"每行末列那一槽永远没人写 + 每行首拍越界写"的直接观测。
- 硬件侧算术的证据（变异对照那一次，缺陷态复原）：`blur=11 sharp=11 sobel=11 morph=11 || first offender x_in=1343 -> HW slot 319 with din=0000` ⇒ 每一级都越界写、第一 offender 正是消隐末列 1343、被硬件截断到的槽位正是预测的 319、存进去的正是消隐值 0。台账同时记明：变异红的三条恰好是认领 #103 的三条，**这一刀没有顺带弄红别的判据**。
- 修复态读数：`C10a/C10d/C10f` 一起从红转绿（槽位完整性 + 越界计数 + 内容对齐同批转绿）。
- 眼睛那一半（2026-09-29 09:1x 用户回报原话）："osd 开关正常，黑线没了" ⇒ 显示列 320 那根线关闭，且台账特别记了一句"这是它的第一次屏上证据"。
- `【待验证】`：本轮没有重跑，故"现在这份树重跑 `sim/tb_v103_pipe_bypass.v` 仍得 `未写槽=0 / 越界=0`"未证；`【未实测】`：未初始化 RAM 的开机值只在这块板上按这一版工具链成立过，别的器件/家族没测。

## 8. 提炼来源与边界

- 台账出处（逐字保留）：`report/log/ISSUES.md` #103（显示列 320 的黑线）；台架 `sim/tb_v103_pipe_bypass.v` 的 C10d/C10f。
- 根因形状与修法（同一节台账内，本条只留结论）：坐标延迟线的第一跳写成 `xd[0] <= x_in` ⇒ 抽头 `xd[k]` 实际是 k+1 拍，而注释与抽头号按 k 拍口径 ⇒ 各级列标签比自己数据晚一整拍；修法是让 `xd[k]` 真的是 k 拍，并把四处右边界旗标的武装位从 `H_ACTIVE-2` 改回 `H_ACTIVE-1`；**没有改 LATENCY、没有改顶层任何补偿量**。
- 分界：本条只管"仿真看不见、硬件看得见"的**数组越界写/未写槽**这一族。同族但在别处的两笔不在本条：`de` 与自己数据差一拍（行首凭空多一格、末列发不出去）是另一条独立判据的事；假红那一类（期望值差常数倍、采样相位、起点没复位）在旧编号 S20（`bench-self-inflicted-reds`，本包 references 类别）。
- 迁移到新工程要改的几处：① 数组深度与地址位宽（决定 `2**clog2(depth)`）；② `H_ACTIVE/H_TOTAL` 与"消隐期地址是否继续走"；③ 分级计数与标签名（本仓 `C10d/C10f/C10fs` 这套命名是示例取值）；④ 分层引用语法（换仿真器要重写）；⑤ 变异对照脚本里"diff 行数"的那个期望值。
- 工具行为断言与来源行另见 `skill/pitfalls/_proposed-sources.md`（本目录不写 `_meta/`）。
- 平台相关：与器件家族无关的那一半是"xsim 静默丢越界写"；与器件有关的那一半是"硬件按地址位截断 + 未初始化值"，换板必重量。
