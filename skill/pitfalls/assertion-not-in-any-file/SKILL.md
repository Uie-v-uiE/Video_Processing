---
name: assertion-not-in-any-file
description: 用于验收"自己（或模型）刚写下的断言"：当一句话声称已验证/已改/已通过，但说不出复跑命令+输入文件+期望输出+实际输出摘要四件之一时用它；触发形状包括提交信息说改了而文件没变、引用了一行在任何文件里都不存在的判定文本、批量改口脚本把交付文档写坏、检查器所引的那句话被自己改写后该项静默空转、以及只读评审交回没有行号的发现。
---

## 1. 一句话用途

没有件的那句话，降级成假设。

## 2. 适用场景

- 当一句话里有"已验证/已通过/已修/补进了第 N 节"，而同一段里没有复跑命令、输入路径、期望输出、实际输出摘要这四件时。
- 当你想引用一行判定文本（`FAIL <某项>` 之类），而 `grep` 在任何文件里都找不到它时。
- 当批量替换/改口脚本报告成功，而目标文档的行数或某格内容变了样（本仓实测：首页被写成 0 行两次）。
- 当某个检查器所"引用为依据"的那句话被改写之后，那一项从红变成不再报（静默空转），或反之把不相干文件扫进射程制造远处的红。
- 当子任务/代理交回一批"发现"，其中若干条指不出 `file:line` 时。
- 当你把一次工具输出里"搜到了"当成"确认了"（例如把记忆里的选项名当成工具支持）。

## 3. 不适用 / 失效条件

- 不适用：对方（或你自己）明确写了"未验证/未实测"的条目——那已经是正确状态，不要二次加工。
- 不适用：有仪器凭据但一时没写进文档的场合；本条的动作是"补件或改口径"，不是"禁止下结论"。
- 失效：本条的形状依赖"存在可被 grep 的落盘件"；如果你们的凭据是截图/视频，判据要换成"能否指回那一份文件的哈希/时间戳"。
- 不许越界：不许为了让某句话过关去改检查器的正则或阈值（本仓硬规则）；要改的是被引用的那句话或脚本。
- 不适用：需求/主观审美讨论（没有可判件）。

## 4. 前置条件

- 仓库里可跑：`grep -rn`、`git status`、`git diff --numstat`、`git show HEAD:<路径>`。
- 至少两把尺子在门禁里：文档行号锚点检查与本仓 `src/host/line_cite_check.mjs`（D5）、数字对账 `src/host/metric_recheck.mjs`（D6）；换工程要换成你自己的（示例取值，需按自身工程替换）。
- 一份本轮/本步的输出目录（本仓形状 `build/evidence/<本轮>/`）。
- 做批量文档手术前：先 `cp` 备份 + 在拷贝上彩排 + 事后 `git status` 确认（本仓 #329 定的四步）。

## 5. 使用方法

按"症状 → 首查（≤2 分钟）→ 判别实验"三列查表；每行都在本仓有实例。

| 症状（观察者视角） | 首查 | 判别实验 |
|---|---|---|
| A. 提交信息/报告说"补了第 7 节"，文件里没有 | `git show --stat HEAD` 看那一轮真的动了哪些文件；再 `grep -n "<那句话>" <该文件>` | 把那次命令原样重跑一遍，看它的断言/退出码；本仓 #324：python 的 assert 挂了 ⇒ 文件其实没改 |
| B. 推理里引用了一行 `FAIL <某项>`，日志里没有 | `grep -rn "<那一行原文>" .` | 打开被点名的报告直读那一格；本仓流程账：`build/tb_v98_report.txt` 里那一行其实是 PASS |
| C. 批量改口脚本"成功"，文档却变样 | `wc -l <被改文档>` 与改前对比；`git status` | 先在拷贝上彩排：备份 → `--check` → 彩排跑 → 恢复 → `git status` 干净才允许真跑（本仓 #329/#330 就是这么救回来的） |
| D. 某项检查从红变"什么都不报" | 当场重跑那把尺子，数它 `判 N` 的 N 与红行数 | 故意把被引的那句话改坏，看尺子会不会红；不红就是它空转了（本仓 #325/#331：Markdown 粗体把正则挡掉，靠射程地板才没混过去） |
| E. 新造的临时文件让不相干的项目变红 | 看检查器的扫描集怎么定义的（本仓 D5 的 `DOC_DIRS` 递归扫 `skill/`、`board/`、`report/`） | 把快照落到不被扫的后缀（本仓改口为 `*.txt`）或直接靠 `git show HEAD:<path>` 当对照，删掉自造的旧行号 `.md`（#333） |
| F. 代理交回 N 条发现，其中几条没行号 | 逐条 `sed -n '<行>p' <文件>` 回读 | 指不出行号的降级为"下一步该量什么"，不写进结论（本仓 #125：16 条 ⇒ 8 进正文、4 降候选、其余不采信） |
| G. "搜到了"被当成"支持" | 打开权威件，逐字读那一行 | 让判定器把你用到的关键字/选项对回那份权威清单（本仓 #319 的形状：`help` 落件 + `present=0/1`） |

步骤与"完成后应看到"：

1. 对表里命中的那一行，先跑"首查"列的命令。完成后应看到：一个能证真或证伪的具体读数（不是"看起来对"）。
2. 跑"判别实验"列。完成后应看到：三态之一——证实、证伪、或读不到（读不到必须写 `NOT_MEASURED`）。
3. 若首查就发现被引对象不存在：立刻把那句话改口径（"未验证"），不要先去补证据链的解释。
4. 若命中 D/E 这类"尺子与文档互相依赖"：改**被引的那句话**或改**脚本**，两处一起改时先重跑尺子确认它抓到（本仓纪律：要求"抓到 N≥1"）。
5. 把本轮每条结论后面挂的件路径抄进日志时，用直读而不是记忆（本仓规矩：数字只认第一次直读）。
6. 收尾跑一次聚合判据，确认没有因为你的文档动作新增红项；红了就按"是我造的脏数据"分支先排查（#333 的形状：备份在 `build/evidence/`，红在门禁第 14/18 项）。

## 6. 判读与失败分叉

- 步骤 1：
  通过 = 首查读数与断言一致。
  失败 = 不一致 ⇒ `FAIL`，把该断言降级为假设并在报告里点名它错在哪一行。
  读不到输入 = 首查命令报错/无输出 ⇒ `NOT_MEASURED`，先确认文件路径与被覆盖风险（见 `who-else-writes-this-artifact`）。
- 步骤 2：
  通过 = 判别实验给出与断言同向的结论。
  失败 = 反向 ⇒ `FAIL`，并检查是否有第二处也依赖同一句被引文本（本仓 #333 里 D5 红会顺着基准件把 D1c 也拖红）。
  读不到输入 = 判别实验需要跑不了的东西（长构建/硬件）⇒ `NOT_MEASURED`，明写"需要谁做什么才能判"。
- 步骤 3：
  通过 = 文档里已无该假引用。
  失败 = 只删了引用没删结论 ⇒ `FAIL`，结论也要一并撤。
  读不到输入 = 找不到那句原文在哪 ⇒ `NOT_MEASURED`，先用 `git log -S"<原文>"` 定位它被写进哪一轮。
- 步骤 4：
  通过 = 尺子对被改坏的句子会红。
  失败 = 不红 ⇒ `FAIL`：判据没牙；先修尺子再谈文档（不许调阈值让它绿）。
  读不到输入 = 尺子跑不起来 ⇒ `NOT_MEASURED`，本轮不得声称该项已通过。
- 步骤 5：
  通过 = 每个数字都能指回一份件，且件里就有那个数。
  失败 = 指不回 ⇒ 改成 `【未实测】`。
  读不到输入 = 件被覆盖 ⇒ `NOT_MEASURED`，重跑那一步并成套冻结。
- 步骤 6：
  通过 = 聚合判据没有新增红。
  失败 = 新增红 ⇒ 先按"自造脏数据"排查自己本轮新建的文件（含临时备份/快照）。
  读不到输入 = 聚合判据读不到基准件 ⇒ `NOT_MEASURED`，本仓形状是该项打成 `n/a`（`build/gates.sh:194`）。

## 8. 提炼来源与边界

- 证据：`report/log/ISSUES.md` 上述编号小节；协作纪律本体在 `skill/prompts/round-work-loop/SKILL.md`（硬规则 1/2/3、禁止清单）与
  `skill/prompts/llm-fpga-debug-workflow/SKILL.md`（S5）、`skill/prompts/read-only-review-agent/SKILL.md`（S29）、`report/AI_COLLABORATION.md` 的自我纠错一节；
  本条不复制它们的内容，只给"按症状查表"那一半（分工按 P06 铁律 5：重复处删参考层、条目侧留链接）。
- 尺子形状：本仓 `src/host/line_cite_check.mjs` 的 `DOC_DIRS`（`skill`/`board`/`report` 递归）与"硬错只由四类决定"的口径。
- 工具行为断言的来源行见 `skill/pitfalls/_proposed-sources.md`。
- 停止适用的条件：当每句对外结论都由脚本自动生成（人/模型不手写结论句）时，本条被"生成器 + 件绑定"取代；
  但只要还有人写自由文本结论，A/B/D 三行就仍然有用。
- 迁移到新题目/新板卡要改的地方：
  1. 把表里"本仓尺子名"换成你自己的检查器名与它的扫描集（否则 E 行的失效条件判不了）；
  2. `file:line` 这一硬通货依赖你们的文档风格；若你们以"报告编号 + 段落"为凭据单位，F 行的回读动作要改；
  3. 与器件家族、板卡无关；与"是否有落盘件 + 是否能 grep"有关。
