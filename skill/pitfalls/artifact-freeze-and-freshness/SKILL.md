description: 判"这套交付产物是不是同一批、是不是过期"：当你在实现还在跑的时候就念门禁结论、当门禁数字与上一版一字不差而全绿得没有理由、当 bit / xsa / elf / 综合与实现报告散在工作目录而会被下一次构建原地覆盖、当你需要回答"这个数是哪一次构建出来的"、或当证据文件名按"第 N 轮 / 第 N 次"命名而 N 靠人临时数时用它。做法是门禁自报主控产物与报告的时间差（本仓阈值 10 分钟一档）、按 md5 把交付单元定义成"一套"并冻结后立刻自校验、在 MANIFEST 里写清哪几条**没验**。
---

## 1. 一句话用途

交付单元是"一套产物"，不是一件。

## 2. 适用场景

- 当你准备念门禁、抄报告里的数字，而实现可能还在跑（门禁读的是磁盘上**现成**的报告文件）。
- 当门禁结果与上一版**一字不差**、全绿得没有理由时——这通常意味着你念的是上一套产物。
- 当你把"一个 bit"当成交付单元，而 xsa / elf / 综合与实现报告散在工作目录里、各自都会被下一次构建覆盖时。
- 当有人需要回答"这个数是哪一次构建出来的"。
- 当你的证据文件名按"第 N 轮 / 第 N 次"命名，而 N 靠人临时数时。
- 当你改了固件（elf）而位流没动，或反过来——两份不同步时"当前版本"就没有唯一答案。

## 3. 不适用 / 失效条件

- 不适用：只跑一次、不留历史、也不需要复现的探索性实验。
- 不适用：产物由打包系统一次性生成并自带版本标识（无需自建新鲜度检查）。
- 不适用：只有一件产物的工程（没有"成套"可言）；但"是不是同一批"这个问题对任何多文件证据都还在。
- 失效：mtime 会被复制、同步盘、checkout 改动 ⇒ mtime 只当"新鲜度提醒"，**身份认定永远用 md5**；拿冻结件去测 mtime 偏差是本条最常见的误用。
- 失效：复制会把复制件的时间统一成"现在" ⇒ 冻结目录永远测不出偏差；这条判据只对**正在写的工作目录**有意义，别拿冻结件当"通过"的证据。
- 失效：构建流程没写主控产物（例如只跑到 checkpoint）时报"没成套"是**真信号**，不要为了消警去改阈值。
- 分界：本条管产物与报告的**成套性、新鲜度**；"文档里念的当前版本对不对"是另一把尺子（文档时效判据，本仓是 `src/host/doc_currency_check.mjs`，示例取值），机制不同、别混着修。

## 4. 前置条件

- 一个能一条命令跑出聚合结论的门禁脚本，且它读的是磁盘上的报告文件（本仓示例 `build/gates.sh`，示例取值，需按自身工程替换）。
- 一个"把交付件一起复制进新目录"的脚本（本仓示例 `build/freeze_evidence.sh`，示例取值）。
- `md5sum`（或等价校验和工具）+ `stat`；只读操作，不需要 Vivado/Vitis，也不需要连板子。
- 一个"一次构建的正常跨度"数字：本仓按综合 ~4 min + 实现 ~8 min ⇒ 取 10 分钟一档；**换工程必须重量这条阈值**。
- 一份人读的 MANIFEST 的落位约定（冻结目录里，不在条目里）。

## 5. 使用方法

1. **让**门禁脚本自报"这套产物是不是同一批"：读报告前打印主控产物（位流）与报告的写入时间差，超过"一次构建的正常跨度"就 WARN。
   完成后应看到：一行带两个时间戳与差值的告警行，且它只在可疑时出现。
2. **给**检查器自己写判据，两跑：拿一套已知成套的产物跑 ⇒ 必须**不响**；把主控产物的时间戳改到 2 小时前再跑 ⇒ 必须**响**。
   完成后应看到：两次结果相反。本仓形状 `bash build/gates.sh <目录>`（示例取值）。**两次都过才算这条告警是活的**；只做第一跑，你就交付了一条永远不会响的告警。
3. **把**交付单元定义成"一套"：一条命令把 bit / xsa / elf / 综合与实现报告**一起**复制进一个新的冻结目录，复制后立刻自校验。
   完成后应看到：`md5sum -c` 的 OK 行数**等于**该套文件数（本仓形状 `bash build/freeze_evidence.sh <号>`，示例取值）。
4. **在**人读的 MANIFEST 里写四件事，缺一条就是给未来的自己埋雷：这一版改了什么（源码级）/ 门禁数字 + 复核命令 / 板级验到哪一条、**哪几条没验**（没验要写"没验"，不许靠沉默）/ 刻意没收的文件与原因。
   完成后应看到："没验"那一栏有内容，或有明确理由为空。
5. **给**证据文件名带上不会撞车的身份：用**时间与内容哈希**，不用"第 N 轮"；脚本落盘前先列一遍目标目录。
   完成后应看到：新目录里没有同名文件被覆盖的记录。
6. **每次**改完固件都重新成套冻结一次，或在 MANIFEST 写明"本目录那份 elf 已被后续某次提交取代"（elf 与 bit 不同步是同一族的坑）。
   完成后应看到：任一冻结目录里 bit 与 elf 要么同批、要么有那句说明。
7. **把**失败版本也成套留下，并明确标注"反例，不要拿去演示"。
   完成后应看到：反例件与正式件在同一处清单里，各自带身份。

## 6. 判读与失败分叉

- 步骤 1：通过 = 时间差 ≤ 阈值且告警行不出现（或出现但内容与阈值自相矛盾地被解释过）。
  失败 = 念出"全绿"而告警行存在 ⇒ 你念的是上一套产物，判 `FAIL`，整轮判红。
  读不到输入 = 脚本找不到主控产物或报告 ⇒ `NOT_MEASURED`；**报"没成套"是真信号**，不要去改阈值消警。
- 步骤 2：通过 = 成套不响、改旧必响。
  失败 = 两种情形都不响 ⇒ 告警是死代码（本条最贵的失败），补成"必须响"的那一跑才算判据；
  失败 = 两种都响 ⇒ 阈值或操作数选错了对象（例：拿 stdout 重定向的日志文件当基准，它比报告落盘更晚 ⇒ 正确的报告永远被判旧）。
  读不到输入 = 没有可用的成套目录 ⇒ `NOT_MEASURED`，先做一次步骤 3。
- 步骤 3：通过 = OK 行数 = 该套文件数。
  失败 = OK 行数少于文件数 ⇒ 冻结未完成，别引用这套件。
  读不到输入 = 校验清单不存在（导出器可能删了自己的目标）⇒ `NOT_MEASURED`，按磁盘上的文件数数，不要读它的 stdout。
- 步骤 4：通过 = 四件事齐全，"没验"栏非空或有理由。
  失败 = "没验"栏空且板级只验了一两条 ⇒ 有人在靠沉默，判 `FAIL`。
- 步骤 5：通过 = 落盘前列目录、名字含时间或内容哈希。
  失败 = 出现"同名文件被覆盖" ⇒ 已经丢了一份历史证据；按 git 恢复该文件，并把那一次留在反例里。
- 步骤 6/7：通过 = elf/bit 同批或有写明；反例成套且带"不要拿去演示"的字。
  读不到输入 = 冻结集里没有对应件 ⇒ `NOT_MEASURED`，回步骤 3，不许用"上一版应该差不多"填数。
- 回退口径：新鲜度报 WARN 时整轮**判红**（不许在可疑的成套关系上给绿），回退只能**按套**回退，不是"猜上一个 bit"。
- 一条数字关系（自证）：任意两个冻结目录各自 `md5sum -c` 都通过，而门禁念出的数字**互不相同** ⇒ "这个数是哪一套"才有唯一答案。

## 7. 已验证的效果

以下读数全部出自 `report/log/OVERNIGHT_LOG.md` §20 那一轮（及其后一节的工具账），属**历史台账件**；本轮（技能包重构轮）没有重跑门禁、没有构建、没有冻结 ⇒ 不写"本机实跑"。

- 本条的起因（§20 记的"差点发生的错"）：那一轮构建**还在跑**的时候先念了一遍门禁，念到的是**上一版的旧报告、七项全绿、数字与上一版一字不差**——差一步就把上一版当成交付。这正是 §2 第二条场景的原型。
- 落地后的机制（同节）：门禁脚本从此先打印位流与实现报告的时间戳，相差超过 10 分钟就 WARN"可能不是同一套产物"。
- 登记的判据形状（同节写明）：拿已知成套的一套跑 ⇒ 不响；把位流的 mtime 改到 2 小时前再跑 ⇒ 必响。`【待验证】` 本轮未重跑这两跑，故"现在这两跑仍给出相反结果"未证。
- 同一天丢过一次证据并被追回（同节）：回归日志按"第 32 轮"起名，而中午 13:07 那一轮已经用过同一个名字 ⇒ **直接覆盖了一份历史证据**；随后用 `git checkout HEAD --` 恢复，本轮改叫 r33。这就是步骤 5 的代价样本。
- 后一节的工具账（同一份 OVERNIGHT_LOG）：把新鲜度写成"报告要比那份 stdout 重定向的日志新" ⇒ 工具打印收尾句的时间**晚于**报告落盘 ⇒ **正确的报告被判成旧、门禁被拒（rc=1）**；方向是安全的（宁可拒绝也不念旧数），错在操作数选错对象，改回"位流与报告相差 >10 分钟才算不是一套"。
- 一条真实"成套"的正读数（同一份 OVERNIGHT_LOG）：位流 03:36:21 与实现报告 03:37:00 ⇒ 差 39 秒 ⇒ 判为一套。
- `【未实测】`：MANIFEST"没验"那一栏的覆盖率从未被任何尺子数过；本条只把它写成纪律，没有"某一轮该栏确实非空"的凭据。

## 8. 提炼来源与边界

- 台账出处（逐字保留）：`report/log/OVERNIGHT_LOG.md` §20 —— 构建还在跑时念了一遍门禁，念到上一版的全绿；同一天还因"按轮次命名"覆盖掉一份历史证据。
- 脚本形状出处：`build/gates.sh`（新鲜度告警的落点）、`build/freeze_evidence.sh`（成套冻结与 `md5sum -c` 自校验）、文档时效那半件事归 `src/host/doc_currency_check.mjs`（三者都是本仓示例取值，换工程要重写）。
- 相关条目（同族但不同事）：产物被谁原地覆盖、两个进程写同一份日志 ⇒ `skill/pitfalls/who-else-writes-this-artifact/SKILL.md`；"聚合结论念出 ALL PASS 而输入其实缺席" ⇒ `skill/pitfalls/checker-ran-on-nothing/SKILL.md`；脚本 rc=0 而产物没变 ⇒ `skill/pitfalls/exit-zero-nothing-written/SKILL.md`。
- 不再适用的条件：交付物由单一打包系统生成且自带版本标识；或工程只有一件产物、无人问"这个数来自哪一跑"。
- 迁移到新题目/新板卡要改的地方：① 阈值（10 分钟按"综合 + 实现"的实际跨度重量，换工程不许沿用）；② 主控产物的种类（本仓是 bit/xsa/elf + 综合与实现报告；别的流程可能是镜像/压缩包/容器层）；③ 冻结目录与命名规则（用时间与内容哈希，不用轮次）；④ MANIFEST 的四件事模板。
- 工具行为断言与来源行另见 `skill/pitfalls/_proposed-sources.md`（本目录不写 `_meta/`）。
