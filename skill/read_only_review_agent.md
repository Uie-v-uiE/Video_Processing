# S29 让只读代理去做"通读找 bug"，但**只有能指出行号的才算发现**

## 触发
构建或长仿真占着机器（这里是一轮 12–15 分钟的实现、一趟 75–90 分钟的顶层台架），
你手里有一段不能碰 `src/rtl`、也不能再开一个仿真进程的时间，而你需要的是"整批代码里还有什么坑"。
这正是**只读评审**唯一能插进来的窗口；同时它也是最容易污染仓库的一种委托——
代理会读得很开心，然后顺手改文件、顺手跑脚本。

## 不适用
- 你要的是**结论**而不是候选（例如"这一族违例的成因"）：那需要测量，测量必须由主代理做，
  因为凭据要能被 `gates.sh` 与文档引用。
- 代码正在被构建读（`src/rtl`）：任何写入都会让 `rtl_md5` 与在跑的那一跑对不上（`docs/log/ISSUES.md` #123 的机制）。
- 评审对象是你自己十分钟前刚写的东西：那需要的是台架判据，不是第二双眼睛。

## 动作
1. **边界写在第一段**，而且要具体到不能解释：`禁止改文件、禁止跑仿真、禁止跑 src/host 下任何会碰 COM6/JTAG 的脚本`。
   只说"read-only"不够——本项目里 `src/host/metrics.mjs` 这类"看起来像检查器"的脚本会占串口并改写留档。
2. **把要查的缺陷族列成类**，不要问"有没有 bug"。本次五类：控制字位分配是否与 RTL 读者一致 /
   解析器的范围检查与错误路径 / 回读字段是不是硬件真值 / 会挂死或无限打印的错误路径 / 符号与位宽绕回。
   要求每条**必须带 `file:line`**，并自称 CONFIRMED 还是 CANDIDATE。
3. **主代理逐条回读**（这一步是本条的全部价值）：
   能在盘上指出那一行的才进文档；指不出来的降级为"下一步该量什么"，不写成发现。
   顺手挑一两条自己动手：要么改（若只动"会说谎的那一行"，如打印的符号位），
   要么写清"今晚不改的理由"（改控制字语义 = 动上位机契约；没有能红的判据；需要用户那一格）。
4. **别在评审轮里做行为改动**。本轮落地的那两条应该长成这样：一条打印格式、一条文档位表——
   都不改变正温度/正路径下的任何一个字节输出。

## 完成判据
一次可量化的复核收益，而不是一句"AI 帮我找到 bug"：
代理交回 16 条 ⇒ 主代理回读后 **8 条进正文（6 条 CONFIRMED + 2 条当场修掉）**、
4 条降为 CANDIDATE、其余不采信（它们把注释里的数字当事实，或与我已知的债重复）。
凭据在 `docs/log/ISSUES.md` #125。**失效**：代理读不到的东西仍然读不到——
它给不出时序收敛、板级观感、上位机协议这三类判断，那些只有测量与眼睛能给。

## 失效边界

上一节那句「失效」之外还有一条更常见的：**代理的结论数量不是成果**。第二轮把同一把尺子对准 RTL
（#127）时它交回 8 条，我逐条回读后只有 1 条是能指出行号的真缺陷、3 条是"先加探针再谈改"的候选；
如果把 8 条全记进台账，就等于让"扫过一遍"冒充"查清楚了"。

## 出处

`docs/log/ISSUES.md` #125（一夜"遍历代码"的最后一轮：只读评审 + 主线程逐条复核）与
#127（第二轮同法扫 RTL 的"越界写"那一族，八条里一条 CONFIRMED 真缺陷、四条 CANDIDATE 各欠一条机会计数探针）。
